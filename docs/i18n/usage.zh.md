# 使用方法

[← 返回 README](README.zh.md)

## 路径栏

笔记在仓库中的完整路径取代了视图标题栏中光秃秃的文件名 — 标题栏就是标签页下方、同时放着前进/后退按钮的那一条。

这一行上有两处可以点击，而 **文件夹名打开列表** 决定谁做什么：

| | 文件夹名 | 其后的分隔符 |
| --- | --- | --- |
| **开启**（默认） | 选中该文件夹以便编辑 | 打开该文件夹 |
| **关闭** | 打开该文件夹 | 进入该文件夹 |

“打开该文件夹”指的是在没有插件的 Obsidian 里点击该段所做的事。如果没有插件在那里监听，文件夹会在侧边栏的文件浏览器中显示出来 — 高亮，并展开以露出内容。

装有 [Folder notes](obsidian://show-plugin?id=folder-notes) 时，同样的点击会改为打开该文件夹的笔记。这是目前确认会接管标题栏路径的唯一一款文件夹笔记插件；[Folder Note](obsidian://show-plugin?id=folder-note-plugin) 与 [create folder notes with dropdown](obsidian://show-plugin?id=create-folder-notes-with-dropdown) 管理文件夹笔记，但并不监听路径上的点击，所以与它们同用时分隔符照常显示文件夹。参见[兼容性](../compatibility.md#verified-against)。

分隔符**只有在它前面的文件夹确实有文件夹笔记时**才带下划线，因此下划线是一个承诺：那里确实有东西可打开。无论有没有下划线，每个分隔符都可点击 — 没有下划线的那一个会在侧边栏中显示并展开它的文件夹，指针形状仍会提示这一点。下划线同时从文件夹名上移开：开启互换后，文件夹名打开的是列表，把它标成通往笔记的链接就成了谎言。

**重命名/移动模式会覆盖两者**，无论设置如何：有移动待定时，这一行上的任何东西都不会打开文件夹，因为打开就意味着放弃这次移动。文件夹名被选中以便编辑，分隔符则向下进入 — 两者都是挑选目的地的方式 — 并且下划线消失，以示打开已被暂停。

**仓库根目录**是唯一不属于路径分段的一段。它没有上级可用来列出同级项，因此改为打开[位置列表](#浏览仓库之外) — 你的其他仓库、主文件夹、文件系统根目录和已挂载的驱动器。

## 点击某一段：换成同级的另一个

点击文件夹名会在文本输入框中选中**该文件夹的名称**，并打开**上一层**文件夹 — 也就是它的上级 — 的列表。输入或挑选一项即可把这个文件夹换成同级的另一个，而它下面的一切原样保留，所以 `项目/2026/启动.md` → 点击 `2026` → 选择 `2025`，得到 `项目/2025/启动.md`。

点击**笔记的名称**对它自己的文件夹以同样方式起作用，并且选中的文件名**包含扩展名** — 重命名或改投一篇笔记通常也意味着要改扩展名。

点击文件夹时已经选中了一段，因此**再点一次**会把选区扩大到整行 — 该文件夹*以及*它下面的一切 — 这时输入就能一次性替换路径的其余部分。在导航模式和重命名/移动模式下表现一致。

这只有作为“打开输入框的那一次点击”的延续时才成立。一旦你开始使用这个输入框，它就和别的文本输入框一样：点击放置光标，双击取一个词，三击取整行。

无论哪种情况，路径的其余部分都留在输入框周围可见 — 前面是小块，后面是未选中的文本 — 所以完整路径不会从标题栏消失。输入以替换选区，或按 <kbd>End</kbd> / <kbd>→</kbd> 保留选区并从那里继续编辑。无论预填了什么，列表都会列出整个文件夹；只有你真正开始输入时它才开始筛选。

## 用分隔符向下进入

在 **文件夹名打开列表** 关闭时点击分隔符，会进入它前面的那个文件夹：列表列出*那个*文件夹的内容，路径的其余部分则以选中状态在输入框中打开。挑选一个文件夹会把它接到路径上，并立刻打开下一个列表，于是你可以一路点着往下走，不必离开标题行。

## 列表中的每一行都是真正的文件管理器行

列表里的每个文件和文件夹，表现都与它在文件浏览器中的那一行一致：

- **右键**可得同一个上下文菜单 — 文件夹上是 *新建笔记* / *新建文件夹*，文件上是 *在新标签页中打开* / *重命名…* / *删除* — 也包括其他插件加进文件菜单的项。
- 把条目**拖**到任何 Obsidian 接受文件的地方：拖进编辑器以插入链接，拖到文件浏览器的某个文件夹上以移动它，拖到标签栏上以打开它。

菜单文案来自 Obsidian 自己的译文，因此在任何语言下都与应用其余部分保持一致。

## 输入路径

- 点击路径前后的**空白处**会打开一个文本输入框，其中预填了完整路径并已全选 — 直接覆写，或就地编辑。（点击文件名本身只会选中文件名；见上文。）
- 在路径显示着的时候开始输入，会把末尾一段变成一个小输入框，带有限定于当前文件夹的实时自动补全。
- `/` 提交当前段并进入其中。
- 在空输入框中按 <kbd>Backspace</kbd> 会退回上级文件夹，并把它的名称重新打开、光标置于末尾。
- <kbd>Enter</kbd> 提交；<kbd>Esc</kbd> 或点击别处则取消，回到文件真正的路径。

输入框毫无修饰 — 没有方框，没有边框 — 因此读起来就是路径文本本身，并且会随输入自动伸长。

## 导航从不触碰打开的文件

在默认的（导航）模式下，当前打开的笔记**绝不会**被重命名或移动。

- 指向已有文件的路径会打开该文件。
- 尚不存在的路径会询问 *“创建新文件？”*。确认会创建缺少的上级文件夹和该文件；取消则什么也不做。

## <kbd>Ctrl</kbd> — 新标签页，以及复制而非移动

在从列表中挑选文件时，或在某个路径上按 <kbd>Enter</kbd> 时按住 <kbd>Ctrl</kbd>（macOS 上是 <kbd>Cmd</kbd>），会把结果送到**新标签页**而不是当前这个：

| | 直接操作 | 按住 <kbd>Ctrl</kbd> |
| --- | --- | --- |
| 挑选或输入一个已有文件 | 在此处打开 | 在新标签页中打开 |
| 输入一个不存在的路径 | 先询问，然后在此处打开 | 先询问，然后在新标签页中打开 |
| 在重命名/移动模式下提交路径 | 把笔记**移动**到那里 | 把它**复制**到那里，并在新标签页中打开副本 |

修饰键按 Obsidian 自己的规则读取，因此其行为与在链接或文件浏览器行上完全一致 — 中键点击同样表示“新标签页”，<kbd>Ctrl</kbd>+<kbd>Alt</kbd> 表示分屏，<kbd>Ctrl</kbd>+<kbd>Alt</kbd>+<kbd>Shift</kbd> 表示新窗口。

复制与移动一样拒绝覆盖 — 包括覆盖到笔记自身的路径，那里本就没有什么值得复制的。

## 浏览仓库之外

**此项默认关闭。** 请先在设置中开启 **访问外部文件** — 在仓库之外读写是这个插件所做的、而 Obsidian 自己不做的唯一一件事，所以它被设计成需要主动开启，而不是主动关闭。关闭时，仓库名只是在文件浏览器中显示你的仓库，这里的任何东西都不会望向它之外。

点击**仓库名称**（当 *显示仓库名称* 关闭时是 🏠 图标）打开的是位置列表，而不是内容：

- **你的其他仓库**，读自 Obsidian 自己的记录，最近打开的排在前面，各自带着 Obsidian 自己的仓库图标 — 也就是应用在仓库相关命令里用的那一个。已经打开的那个仓库改用一座房子：默认情况下这一行就从那里开始，它不是一个要去的地方。
- **主文件夹**，在自己的账户名下，以一个 `~` 标示。Lucide 没有波浪号，所以这一个由插件按 Lucide 自己的 24×24 网格、用同样的线宽绘制 — 它是这套图标缺失的一枚图标，而不是混在图标当中的一个文字字符。
- **文件系统根目录**，标为 `root` — 不作翻译，因为在任何系统上它都叫这个名字 — 而不用 `/`，那样在紧随其后的分隔符旁边会读成空空的一段。
- **已挂载的驱动器**，在判断成本低廉之处按类型配图标：网络共享、光盘、软盘和可移动介质各有其图标；其余一律用通用驱动器图标。在 Windows 上驱动器显示为 `C:` 并配通用图标 — 卷标和精确类型需要 WMI，这是刻意不去做的。

挑选另一个仓库**不会把 Obsidian 切换过去。** 你打开的一切照旧开着，只是路径栏开始在那边浏览。把它放在路径栏上、而不是交给侧边栏的仓库切换器，意义正在于此。

### 在外面时

路径**从你挑选的位置开始**，而不是从机器的目录结构开始 — 选了 `归档`，这一行读作 `归档 / 笔记 / …`，而不是 `/home/you/Vaults/归档/笔记/…`。起首那一段带着表明其身份的图标（仓库、主文件夹、驱动器），并且 <kbd>Backspace</kbd> 到此为止，不会继续往上走进文件系统的其余部分。当 *显示仓库名称* 关闭时，那一段就只剩图标 — 这项设置针对的是这一行的起首段，无论它指的是哪个仓库，而不只是你自己的那个。

只要路径栏指向仓库之外，它就一直**以错误色描边** — 与重命名模式所画的是同一个环。它标记的是一种持续状态，而非某个瞬间：只要它还在，Obsidian 自己的那套处理就都不适用于这一行所显示的内容，并且在你另行表态之前写入始终是锁定的。

除此之外，浏览与在仓库内一样：小块、分隔符、输入、自动补全、用 <kbd>Backspace</kbd> 退出。可见性规则同样适用，所以不受支持的扩展名仍需要 Obsidian 的 *检测所有类型文件*，点文件仍需要本插件的设置。

**右键和拖拽**在外面不起作用 — 那是文件浏览器自己的处理逻辑，它们需要一个仓库认识的文件。

### 写入仓库之外

一切写入操作**默认都是锁定的。** 只要这一行指向仓库之外，标题栏中重命名按钮旁就会出现一把**挂锁**；按下它会打开锁并变红，与这一行周围的描边相呼应。

许可授予的是**一个位置，而不是一个瞬间**：你在一个地方工作时会做的事，它都能挺过来 — 完成一次移动、点开输入框、打开一个文件 — 而当你从列表中挑选了另一个仓库、驱动器或根目录，当这一行回到仓库内的文件，或当你再次按下挂锁时，它就结束。因此在同一个文件夹里连着移动多次，只需按一次，而不是每个文件按一次。

挂锁打开后，路径栏在外面的表现与在里面一样：

| 操作 | 结果 |
| --- | --- |
| 输入一个不存在的名称，按 <kbd>Enter</kbd> | 与在仓库内相同的“要创建吗？”询问；缺少的上级文件夹也会被创建。不带扩展名的名称会变成 `.md`，与在仓库内完全一样 |
| 重命名/移动模式，输入新名称 | 重命名这一行所显示的文件。不带扩展名的名称会保留该文件原有的扩展名 — 在外面，一个文件夹里什么类型的文件都有，重命名不该悄悄把 `.png` 变成 `.md` |
| 重命名/移动模式，浏览到别处，选择**保留此名称** | 以它现有的名称移动过去 |
| 在以上任一操作中按住 <kbd>Ctrl</kbd> | 改为复制而非移动，并在新标签页中打开副本 |

处于锁定状态时，以上各项都不会发生，而是报告是什么挡住了它们。两种状态下都绝不会覆盖任何东西：已存在的目标会被拒绝，而这个拒绝来自文件系统本身（`COPYFILE_EXCL`，一次排他式创建），而不是某个可能输掉竞态的检查。跨文件系统的移动 — 从 U 盘、从网络共享 — 会退回到“先复制后删除”，并且只有在副本落地之后才会删除原件。

**有一件事挂锁并不解锁：把笔记移动到仓库*之外*。** `fileManager` 无法跨过那道边界跟踪文件，因此指向该笔记的每一个链接都会悄无声息地失效，而 Obsidian 只会看到它凭空消失。按住 <kbd>Ctrl</kbd> 会改为把它复制出去，这就完全没有那个问题，通知里也是这么说的。反方向 — 把外面的文件带*进*仓库 — 目前同样尚未接通。

### 打开外部文件

Obsidian 的编辑器只对仓库内的文件起作用，因此外部文件**无法**作为带链接、反向链接等等的真正笔记打开 — 这是应用的限制，不是本插件的限制。挑选一个外部文件会改为打开**预览**，在你另行表态之前是只读的：

| 类型 | 呈现方式 |
| --- | --- |
| `.md`、`.markdown` | 渲染后的 Markdown |
| 图片、音频、视频、PDF | 原生播放器/查看器 |
| 其他任何**文本**文件（`.json`、`.css`、`.log`、`.txt` …） | 原样的纯文本 |
| 没有查看器的二进制格式 | 交给 *在外部打开* |

查看器对一个文件有两种读法，而由于二者互斥，只会显示你将要**切换到**的那一种：

| | 作用 | 默认适用于 |
| --- | --- | --- |
| **以 Markdown 查看** | 把文件当作笔记渲染，只读 | `.md`、`.markdown` |
| **以文本编辑** | 源文本，可编辑 | 其余一切 |

在仓库之外，**以文本编辑** 同时也是解除只读的那一次按下 — 模式与许可是一个动作，而不是两个需要分别琢磨的按钮。**只要按下会解除只读**，它就带红色调，无论你是在原地准备编辑，还是径直从渲染视图过来；在仓库内没有什么可解锁的，所以它保持素净。**以 Markdown 查看** 覆着一层淡淡的强调色 — 与 Obsidian 给选中文本的色调相同 — 标明它是回去的路，而不是号召你行动。

由于按钮跟随的是*编辑*而非原始模式，一个在文本视图中处于只读的文件仍会给出 **以文本编辑**：正是这一按使其就绪。而永远无法写入的文件 — 被截断的，或读取失败的 — 则改为写着 **以文本查看**，因为按下所能给的就只有这些。

默认值取的是有用的那一面，而非字面的那一面：shell 脚本里的 `#` 是注释而不是标题，所以把 `.log` 当作 Markdown 渲染会把它悄悄吞掉。两种默认都可以按文件覆盖，而这个选择会进入该窗格的历史，因此前进/后退以及重新打开的工作区都会保留它 — 有大量笔记住在 `.txt` 文件里，也有大量 `.md` 文件读源码更省事。

**仓库内的文件可以直接编辑**，无需解锁：*以文本编辑* 是一个真正的编辑器，你输入它就写回。

**编辑状态会跨切换保留。** 切到 *以 Markdown 查看* 会将其挂起 — 静态渲染没有可输入之处，而实时预览需要 Obsidian 自己的编辑器，那只对仓库内的文件存在 — 因此在那边不会有任何东西声称你正在编辑。切回 *以文本编辑* 会从你停下的地方继续。

**仓库之外的文件以只读方式打开，而 *以文本编辑* 解除这一点。** 这一按就是整道门：在它发生之前，外面什么也不会被写入。之后文件会随你输入而保存，与仓库内的文件完全一样；状态行也从一把锁变成一支笔。这次解锁只覆盖那一个标签页里的那一个文件 — 转到另一个文件就重新上锁 — 而且它被刻意不存入标签页的历史，因此重新打开的工作区绝不会带着“已就绪的写入权限”回到某个你根本不记得打开过的系统文件上。

**被截断的文件无论如何都保持只读** — 保存屏幕上的内容会丢弃上限之外的一切，所以那个按钮根本不提供，而不是提供了再拒绝。读取失败的文件同理：除了一个空窗格，没有什么可写回。

如果写入失败 — 只读挂载、并非你所有的文件 — 系统自己的原因会以通知的形式显示出来。

超大文件会被截断显示，而状态行会直说，而不是留给你自己去发现 — 它与其他条件并列，而不是跟在按钮后面，因为它和其余各项一样是关于这个文件的事实。上限是对着真实渲染器量出来的，而不是猜的 — 把一兆字节的文本排布在一个窗格里会直接搞垮 Obsidian 的渲染进程，而 Markdown 每字节的开销是纯文本的数倍，所以二者有各自的上限；即便整个文件很小，单独一行过长时那一行也会被截短。

**状态行是标签，解释则是提示气泡。** 每一行都用尽可能少的字说明当下为真的事 — *仓库之外*、*没有适用于此文件类型的编辑器*、*已截断 — 文件过大* — 因为旁边的按钮已经说明了文件处于什么状态。把指针悬停上去就能得到那句话：为什么 Obsidian 无法把它当作笔记打开，这种文件类型本来会遭遇什么，截断让你失去了什么。

这同样适用于仓库**内**的文件。凡是 Obsidian 没有视图可用的扩展名，它都会径直交给桌面的默认应用程序 — 所以仓库里的一个 `.txt` 或 `.json` 会把你整个带出 Obsidian。现在这些也在同一个查看器中打开，带橙色描边，因为“在 Obsidian 里打开它”正是你的诉求 — 而作为仓库文件，它们在那里无需任何解锁即可编辑。没有查看器的二进制文件保持 Obsidian 原有的行为；那里没有什么可显示的。

预览**在你原本所在的标签页中**打开，因此前进/后退会把你带回原来的笔记；和别处一样，按住 <kbd>Ctrl</kbd> 可用新标签页。只要它开着，标题栏就继续显示这个外部文件的路径，你可以从那里继续浏览。

内容上方有一行低调的出口：

- **在“{vault}”中打开** — 当该文件属于你的另一个仓库时出现。把它交给 Obsidian 自己的 URI 处理器，由后者打开那个仓库的窗口并载入该笔记，作为一篇真正可编辑的笔记。当前这个窗口原封不动，不会在你脚下发生切换。
- **以 Markdown 查看** / **以文本编辑** — 两种读法；后者在仓库之外还会解除只读。
- **在外部打开** — 把文件交给桌面的默认应用程序，包括这个查看器无法显示的那些二进制格式。

除非你先按下 *以文本编辑*，否则仓库之外不会被写入任何东西。完整的说明见 README 的 [仓库之外](README.zh.md#仓库之外) 一节。

## 两种警示颜色

| | 何时 | 含义 |
| --- | --- | --- |
| 路径栏上的**红色**描边 | 这一行指向仓库之外 | Obsidian 无法把那里的东西当作笔记打开，并且在你打开挂锁之前，外面不会被写入任何东西。 |
| 路径栏上的**橙色**描边、列表中的橙色条目 | 该文件是 Obsidian 没有视图可用的文本类型 | 一个提醒。Obsidian 会把它交给桌面的默认应用程序；插件则改为显示它。 |

**二者相互独立，且可以同时成立** — 一个外部的 `.json` 既在仓库之外，*又*是 Obsidian 没有编辑器的类型。在查看器里它们呈现为各自独立的行，各自只陈述自己的那件事。而在路径栏上，两者都成立时红色胜出，因为两圈描边只会变成噪声。

橙色这一档是刻意收窄的。已注册的类型（Markdown、canvas、图片、PDF、音频、视频）会被妥善处理，什么也不加。二进制文件同样什么也不加 — 你不会不小心把一个 `.zip` 编辑成一团糟。剩下的恰好就是危险所在：被 **检测所有类型文件** 变得可见的 `.json`、`.css` 或 `.log`。

两者都会成立时红色胜出；同时出现两圈描边只会是噪声。

## 重命名/移动模式

标题栏最右侧的铅笔按钮 — 紧挨视图模式按钮，与原生按钮同样大小 — 切换重命名/移动模式。此时标题行会以强调色描边，与在文件浏览器中重命名时一模一样。同样的点击与按键，如今会经由 Obsidian 的 `fileManager.renameFile` 提交一次移动或重命名，因此指向该笔记的所有链接都会随之更新。

重命名期间：

- 当前文件名会被固定在每个文件夹的列表里，所以“移动笔记但不改名”只需一次点击。
- 目标文件夹中已被占用的名称会变灰，但仍可选中。
- 输入会实时按 Obsidian 自己的重命名规则校验 — 同样的字符集、同样的提示语、与在文件树中重命名时相同的红色气泡 — 因此非法或冲突的名称会在你输入时被标出，并且无法提交。
- 点击标题栏之外，或标题栏失去焦点，都会结束重命名模式。

## 一个键管两种重命名

重命名命令（默认 <kbd>F2</kbd>，或你重新绑定的按键）会在 Obsidian 的内联标题重命名与本插件“全路径已选中的标题路径栏”之间**交替**。若你关闭了 Obsidian 的内联标题，标题路径栏便成为唯一目标，于是这个键永远不会毫无作用。

这是通过包装 `workspace:edit-file-title` 命令实现的，而不是去抢按键，因此重新绑定快捷键和从命令面板执行命令都照常有效。

## 列表条目的着色

| 颜色 | 含义 |
| --- | --- |
| **紫色** | 一篇笔记（`.md`、`.markdown`）— Obsidian 会作为笔记打开的东西，从内容混杂的文件夹中挑出来 |
| **橙色** | Obsidian 没有视图可用的文本类型；参见[警示颜色](#两种警示颜色) |
| **暗淡** | 位于仓库之外，因此仓库自己的那套处理不适用 |
| **蓝色** | 你当前所在的笔记。浏览时是它自己的那一项；在重命名/移动模式下，*保留此名称* 这一项站在它的位置上 — 两者都是同一则笔记 |
| **灰显** | 仅限重命名/移动模式：该名称已被占用。仍可选中 — 选中会填入输入框，校验会在那里标出冲突 |

## 可见性规则

- 只有在 Obsidian 的 **检测所有类型文件** 设置开启时，扩展名不受支持的文件才会出现在列表中。
- 列表最多显示 100 项 — 这是 Obsidian 自己的上限。当某个文件夹超过此数时，最后一行会说明省略了多少项；继续输入以缩小范围。
- 只有在本插件的 **显示点文件** 设置开启时，点文件和点文件夹才会出现。
- **覆盖保护与是否可见无关，行为完全一致** — 隐藏的文件同样会阻止你覆盖它。

## 速查表

| 你想… | 这样做 |
| --- | --- |
| 打开一个文件夹（它的笔记，或显示它） | 点击那个文件夹**后面**的分隔符 |
| 把一个文件夹换成同级的另一个 | 点击该文件夹名，然后输入或挑选 |
| 重命名或改投这篇笔记 | 点击笔记名 — 含扩展名 |
| 浏览某个文件夹的内容 | 点击该文件夹名；列表列出的是它的上级，所以要点你想要的那个**下面**的文件夹 |
| 重打某个文件夹及其下的一切 | **双击**该文件夹名，然后输入 |
| 从某个文件夹起往下编辑路径 | 点击该文件夹名，再按 <kbd>End</kbd> 或 <kbd>→</kbd> 取消选中 |
| 输入路径跳到某个文件 | 点击文件名或空白处，输入，按 <kbd>Enter</kbd> |
| 改为在新标签页中打开文件 | 挑选时按 <kbd>Ctrl</kbd>，或按 <kbd>Ctrl</kbd>+<kbd>Enter</kbd> |
| 把笔记复制到某处而不是移动 | 铅笔，然后在挑选或提交目标时按 <kbd>Ctrl</kbd> |
| 在不存在的路径上创建笔记 | 输入路径，按 <kbd>Enter</kbd>，确认询问 |
| 输入时向下一级 | 输入 `/` |
| 输入时向上一级 | 在空输入框中按 <kbd>Backspace</kbd> |
| 移动或重命名当前打开的笔记 | 点击铅笔，然后照上面浏览或输入 |

| 跳到另一个仓库、主文件夹或驱动器 | 点击仓库名称 |
| 打开仓库之外的文件 | 仓库名称 → 挑选位置 → 浏览 → 挑选文件（在 *以文本编辑* 之前只读） |
| 取消任何操作 | 按 <kbd>Esc</kbd>，或点击标题栏之外 |

## 设置

| 设置 | 选项 | 默认 | 作用 |
| --- | --- | --- | --- |
| **对齐方式** | 左 / 居中 / 右 | 左 | 路径在标题行中的位置。*居中* 与 Obsidian 的经典样式一致。 |
| **分隔符** | 任意字符 | `/` | 绘制在各段之间的分隔符。文本框前面摆着六个一键预设（`/ > ▸ › \ •`）。 |
| **显示仓库名称** | 开 / 关 | 开 | 仓库本身是否作为路径的第一段。关闭后那一段会变成 🏠 图标而不是消失，因此路径起点仍是可点击的。 |
| **文件夹名打开列表** | 开 / 关 | 开 | 互换文件夹名与其后分隔符的作用 — 参见[上面的表](#路径栏)。装有 [Folder notes](obsidian://show-plugin?id=folder-notes) 时，分隔符打开文件夹笔记。在重命名/移动模式下始终不适用。 |
| **显示点文件** | 开 / 关 | 关 | 点文件和点文件夹是否列入列表。覆盖保护无论如何都适用。 |
| **访问外部文件** | 开 / 关 | **关** | 仓库名称是否打开位置列表。关闭时，插件中没有任何部分会望向本仓库之外。 |

## 替换图标

Lure 绘制三枚图标：仓库根目录图标（当 **显示仓库名称** 关闭时）、重命名/移动开关，以及守着“写入仓库之外”的挂锁。它们都可以从主题或 CSS 片段中替换 — 在同一条规则里设定替代字形并隐藏自带的那个：

```css
.lure-vault-icon {
	--lure-icon-glyph: "🏠";
	--lure-icon-svg: none;
}

.lure-rename-btn {
	--lure-icon-glyph: "✎";
	--lure-icon-svg: none;
}

/* 挂锁有两种状态；`.is-active` 是打开的那一种。 */
.lure-unlock-btn {
	--lure-icon-glyph: "🔒";
	--lure-icon-svg: none;
}

.lure-unlock-btn.is-active {
	--lure-icon-glyph: "🔓";
}
```

`--lure-icon-glyph` 接受任何在 CSS `content` 中合法的值，因此 `url(...)` 可用于图片，正如文本或表情字形一样。若想保留 Lucide 图标并把你的字形画在它旁边，就别动 `--lure-icon-svg`。
