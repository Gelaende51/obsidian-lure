# 使用方法

[← 返回 README](README.zh.md)

## 路径栏

笔记在仓库中的完整路径取代了视图标题栏中光秃秃的文件名 — 标题栏就是标签页下方、同时放着前进/后退按钮的那一条。

这一行上有两处可以点击，而 **文件夹名打开列表** 决定谁做什么：

| | 文件夹名 | 其后的分隔符 |
| --- | --- | --- |
| **开启**（默认） | 选中该文件夹以便编辑 | 打开该文件夹 |
| **关闭** | 打开该文件夹 | 进入该文件夹 |

“打开该文件夹”指的是在没有插件的 Obsidian 里点击该段所做的事。如果没有插件在那里监听，文件夹会在侧边栏的文件浏览器中显示出来 — 高亮，并展开以露出内容。

当文件夹里的笔记正是你已经在读的那一篇时，点击会转而显示该文件夹 — 因为屏幕上已经没有别的东西可打开了，这正是第二次按下一直以来的含义。

安装了 [Folder notes](obsidian://show-plugin?id=folder-notes) 后，同样的点击会转而打开那个文件夹的笔记，**不论深度**：这里的笔记是按该插件自己的约定解析的，而不是交给它去回答。那个插件只识别它标记过的文件夹，而在深度超过一层的路径上，这意味着没有一个被识别，所以过去打开顶层文件夹笔记的那次按下，在更深处就什么也不做了。另外两款文件夹笔记插件没有发布可读取的约定，也从不认领这一行，所以对它们而言，分隔符和以前一样只是显示文件夹。目前发现唯一认领标题路径的文件夹笔记插件就是它；[Folder Note](obsidian://show-plugin?id=folder-note-plugin) 和 [create folder notes with dropdown](obsidian://show-plugin?id=create-folder-notes-with-dropdown) 管理文件夹笔记，但不监听路径栏上的点击，所以对它们而言，分隔符照常显示文件夹。参见[兼容性](../compatibility.md#verified-against)。

只有**当分隔符前面的文件夹确实带有一篇文件夹笔记时，分隔符才会加下划线**，所以下划线是一个承诺：那里有东西可以打开 — 在运行 [Folder notes](obsidian://show-plugin?id=folder-notes) 时，任何深度都是如此，因为笔记是在这里解析的，而不是留给那个插件去标记。若运行的不是这个插件，就什么都不会加下划线，也什么都不会打开：分隔符只是显示文件夹，就像完全没有文件夹笔记插件时一样。无论哪种情况，每个分隔符都始终可以点击 — 没有下划线的那个会在侧边栏中显示并展开它的文件夹，指针光标依然会提示这一点。下划线同时也会从文件夹名上移开：开关打开时，文件夹名会打开列表，所以把它标记成通往笔记的链接就是在撒谎。

**重命名/移动模式会覆盖两者**，无论设置如何：有移动待定时，这一行上的任何东西都不会打开文件夹，因为打开就意味着放弃这次移动。文件夹名被选中以便编辑，分隔符则向下进入 — 两者都是挑选目的地的方式 — 并且下划线消失，以示打开已被暂停。

**仓库根目录**是唯一不属于路径分段的一段。它没有上级可用来列出同级项，因此改为打开[位置列表](#浏览仓库之外) — 你的其他仓库、主文件夹、文件系统根目录和已挂载的驱动器。

## 仓库自己的分隔符

紧跟在仓库名后面的分隔符代表的是仓库本身，而不是某个文件夹，所以它做着其他分隔符做不到的事：

| | 第一次点击 | 下一次点击 |
| --- | --- | --- |
| **装有启动页插件时**（Obsidian 打开时迎接你的一个页面） | 在当前面板中打开该页面 | 收起文件树 |
| **没有装时** | 收起文件树 | 精确恢复原先打开的内容 |

都是普通点击，不是双击：一旦页面已经打开，分隔符就没有别的可打开了，所以下一次按下就是收起 — 不论你隔了多久才按。

有启动页可打开时它是**带下划线**的，这与文件夹分隔符的承诺是一回事：那里有东西。收起是一个开关 — 下一次按下会恢复此前展开的那些文件夹，且仅限那些，所以你刚整理好的文件树不会因为瞥了一眼别处就丢失。

## 没有文件的面板

一个空标签页、图谱以及任何其他不指向文件的东西，都有自己的一行：仓库，然后是一段说明这个面板装着什么。

```
my-vault / :blank      一个新标签页
my-vault / :graph      图谱，本地的或全局的
my-vault / :<type>     其他任何不带文件的东西
```

**仓库根目录自己的列表**也会提供这些页面，就在其中实际存在的文件夹和笔记下方：在那里选择 `:graph` 或 `:search`，面板就会打开那个视图，正如选择笔记就会打开笔记一样。哪些页面存在是从 Obsidian 读取的，而不是写死在这里 — 所有不为了显示文件而存在的视图皆是如此，所以任何注册了视图的插件（主页标签、日历）都会出现，而本插件对它一无所知。需要文件的视图 — Markdown、PDF、图片、画布、数据库 — 不会被提供：它们没有东西可显示。

冒号才是关键 — 没有文件或文件夹能叫 `:graph`，所以这一行不会被误认成一个可以打开的路径。标签来自视图类型，而不是 Obsidian 自己的措辞，所以无论界面语言是什么，读起来都一样，并且结尾的 `-view` 会被去掉：一个主页标签插件把自己的视图注册为 `home-launcher-view`，这一行就写作 `:home-launcher`。

点击空白处，或标签本身，会**在仓库根目录处打开输入框**：输入路径，按 <kbd>Enter</kbd> 即可在当前这个面板中打开它，有着同样的补全、同样的列表，以及同样会提议创建尚不存在之物的红色输入框。空标签页正适合用来输入你想去的地方，这也正是它的用途。

这个标签只是标签，仅此而已：没有列表，不能拖动，不能重命名。侧边栏中的面板则完全不受影响 — 反向链接面板保留 Obsidian 给它的标题。

画布、PDF、图片和数据库都不需要这些。它们是文件，所以拥有普通的路径栏。

## 点击某一段：换成同级的另一个

点击文件夹名会在文本输入框中选中**该文件夹的名称**，并打开**上一层**文件夹 — 也就是它的上级 — 的列表。输入或挑选一项即可把这个文件夹换成同级的另一个，而它下面的一切原样保留，所以 `项目/2026/启动.md` → 点击 `2026` → 选择 `2025`，得到 `项目/2025/启动.md`。

点击**笔记的名称**对它所在的文件夹也是同样的道理，并且会选中**不含扩展名**的名称 — 重命名是最常见的操作，而如果连 `.md` 一起选中，直接输入覆盖过去就会意外改变文件类型。扩展名只需一次按键就能到达：<kbd>→</kbd> 可以到达它，扩大到整行的双击则会把它一并选中。

点击文件夹时已经选中了一段，因此**再点一次**会把选区扩大到整行 — 该文件夹*以及*它下面的一切 — 这时输入就能一次性替换路径的其余部分。在导航模式和重命名/移动模式下表现一致。

这只有作为“打开输入框的那一次点击”的延续时才成立。一旦你开始使用这个输入框，它就和别的文本输入框一样：点击放置光标，双击取一个词，三击取整行。

无论哪种情况，路径的其余部分都会在输入框周围保持可见 — 前面是若干小方块，后面是未选中的文字 — 所以完整路径永远不会从标题栏中消失。输入即可替换选区，或者按 <kbd>→</kbd> 保留它并从那里开始编辑。不论预填了什么，列表都会列出整个文件夹；只有当你真正开始输入时，它才会开始过滤。

## 用分隔符向下进入

在 **文件夹名打开列表** 关闭时点击分隔符，会进入它前面的那个文件夹：列表列出*那个*文件夹的内容，路径的其余部分则以选中状态在输入框中打开。挑选一个文件夹会把它接到路径上，并立刻打开下一个列表，于是你可以一路点着往下走，不必离开标题行。

## 列表在你所在之处打开

列表会在你当前所在的那一项上打开 — 也就是这条路径栏所属的那篇笔记，或者当点击文件夹列出其上级时，是那个文件夹 — 而不是第一行。在一个有两百篇笔记的文件夹里，第一行离你还远得很。

**在名称上滚动滚轮会打开它的列表并在其中移动。** 第一次滚动打开的列表，与按下名称打开的是同一个，此后每一次滚动都会把高亮移动一行，把你指向的内容精确地放入输入框，就跟方向键一样 — 这样不用键盘也能找到并选中一个同级项。往任意一端继续滚动到头，会把你的文字还给你。当一行的路径比面板还宽时，滚轮会改为横向滚动来回应，只要这种情况适用，它就优先于其他解读。

列表**高度取决于窗口允许多高**。Obsidian 的建议列表无论下方还剩多少空间，都封顶在 300 像素；而这个列表会一直延伸到窗口底部，止步于距边缘几像素处，只有当文件夹内容超出这个高度时才会滚动。它**不会比路径栏更宽**：放不下的名称会像路径栏本身那样被缩短，而当你指向它时会完整显示。

在列表中移动时，会**把你指向的内容放入输入框**，无论是通过方向键还是悬停 — 取代你正在编辑的那一段，路径的其余部分保持不变 — 所以你所在的那一行，也就是你会得到的路径。

路径的其余部分**只会显示到它在你所指向的内容下实际存在的程度**。假设你正待在某个文件夹中，你正在编辑的那一段后面跟着 `2026/note.md`，此时若指向一个恰好含有带 `note.md` 的 `2026` 的文件夹，就会完整显示；若只有 `2026` 而没有那篇笔记，就只显示 `2026`；若两者都没有，名称后面就什么都不显示，文件同样如此，因为文件下面不会有任何东西。**你自己输入的内容**在你输入的过程中会保留完整路径，无论目前输入了多少 — 一个才打了一半的名字还算不上一个决定。把一个名字定下来才算决定，从它出发到不了的部分就会在那一点被截断；你正在创建的那些文件夹，是你在它*之后*输入的那些，而按下 <kbd>Enter</kbd> 正是在那里创建它们。你已经输入的文字会被保留：**移出列表的任一端** — 从第一项往上，或从最后一项往下 — 就会放弃预览，把你的文字还回去，且不再高亮任何一项。输入框本身也是这个循环上的一站，就像列表里的任何一项一样，所以绕一圈会经过它，而不是直接从最后一行跳到第一行，从那里继续按下去又会绕到另一端。

把**指针移出列表**同样会把你的文字还回去 — 并把高亮交还给鼠标进来之前的那一项：你此前用方向键选中的那一项，会重新显示在输入框中，或者列表最初打开时所在的那一项，因为那是你所在之处。悬停是一种查看方式，而不是选择方式，所以指针在列表上扫过不会有任何代价。

列表本身在你移动时并不会改变 — 它始终按你输入的内容过滤，而不是按预览进输入框的内容 — 所以你脚下的这一项永远不会在下一次按键时被换掉。输入会照常替换预览并进行过滤。

**过滤依据的是你正在编辑的那一段**，而不是输入框里的全部内容。点击文件夹会把路径的其余部分留在你正在更改的名称后面，如果按整个内容过滤，就会去找一个名为 `2026/启动.md` 的子项而一无所获 — 不管你打的是什么，列表都会在你按下第一个字符时就关闭。**扩展名同样会被排除在外**，只要光标还在点号前面：点击笔记名称会选中主干部分，把 `.md` 留在后面，所以打一个字母就会让输入框变成 `a.md`，那不是你想要找的东西。把光标移到点号之后，扩展名就和其他字符一样参与过滤。一个确实什么都匹配不上的名字，仍然会关闭列表，因为空列表就是诚实的答案。

预览**只会替换那一段，路径的其余部分保持不动**：指向一个文件夹是在问“如果这一步换成那个会怎样”，而不是把整条路径都扔掉。移出列表会同时恢复你原有的文字*和*选区，所以下一次按键会替换的，正是你查看之前本该替换的东西。

## 列表中的每一行都是真正的文件管理器行

列表里的每个文件和文件夹，表现都与它在文件浏览器中的那一行一致：

- **右键点击**会弹出与文件浏览器完全相同的上下文菜单，逐项对应 — 包括其他插件添加的项目。文件夹提供*新建笔记*、*新建文件夹*、*新建画布*、*新建数据库*、*创建副本*、*移动文件夹到…*、*在文件夹中搜索*、*复制路径*、*在系统资源管理器中显示*、*重命名…*和*删除*；文件则提供与之对应的选项，包括*用默认应用打开*。
- **拖动**一个条目到 Obsidian 接受文件的任何地方：拖进编辑器中插入链接，拖到文件浏览器中的某个文件夹上以移动它，拖到标签栏上以打开它。

菜单文案来自 Obsidian 自己的译文，因此在任何语言下都与应用其余部分保持一致。

## 输入路径

- 点击路径栏前后的**空白处**会在整条路径上打开一个文本输入框，*同时在文件浏览器中显示该笔记*，这样文件树就会跟随面板变化，无需再多一步操作。它会**统计你的点击次数**：一次选中不含扩展名的路径，两次选中含扩展名的，三次选中系统认得的那种路径写法。点击**文件名**的计数方式相同，但从低一级开始，即文件名本身：一次选中不含扩展名的文件名，两次选中含扩展名的，三次扩大为*从你的仓库文件夹开始*的整条路径 — 这是链接或搜索想要的形式，而不是系统的形式。第四次点击才到达那种写法。
- **计数只属于打开该输入框的这一轮操作。** 一旦这一轮结束 — 你停顿了、打了字，或在文本中某处单击了一次 — 该输入框就变成一个普通的文本框，在其中双击会像在其他地方一样，选中指针所在的单词。可以直接覆盖选中内容输入，也可以就地编辑。（点击文件名本身只会选中文件名部分；见上文。）在同一空白处右键点击会**复制**同样的三种选区，对应二、三、四次按键 — 一个按钮显示它们，另一个按钮取用它们。**单次**右键点击会打开路径，选中全部内容，并提供可对其执行的操作：剪切、复制、粘贴、全选，措辞与 Obsidian 一致。
- **中键点击空白处**可粘贴覆盖路径：输入框会以*从仓库根目录开始*的整条路径打开，因此剪贴板内容会替换全部路径，落地后的内容处于选中状态。随后按 <kbd>Enter</kbd> 即可前往该处。
- **<kbd>Ctrl</kbd>+点击空白处**会在新标签页中再次打开这篇笔记，并在文件浏览器中闪烁提示，以免把第二个标签页误认成第一个。在**仓库名称**上，<kbd>Ctrl</kbd>+点击或中键点击会打开一个空白标签页，停在仓库根目录，并已展开列表 — 便于从头输入一条路径。
- 在路径栏显示时打字，会把末尾那一段转换成一个带实时自动补全的小输入框，范围限定在当前文件夹内。
- **可以输入以文件系统根目录起始的路径。** 在空输入框前输入 `/` 会打开这样一种路径，而不是补全某一级，此后的每个斜杠都属于它，`~` 代表你的主目录。当输入框中是这样的路径时，下拉列表显示的是系统而非仓库，行首那一段也会相应让位 — 输入框里的内容从根目录开始，也如实标明这一点。若关闭*访问外部文件*，列表会改为空白，因为 <kbd>Enter</kbd> 反正也不会接受这条路径。
- **页面可以直接输入，不必只靠选取。** `:graph`、`:search`，或你安装的插件注册的任何名字 — 这些正是[仓库根目录的列表](#没有文件的面板)所提供的标签。在任意位置输入冒号都会唤出它们，因为名称中不可能含有冒号，按 <kbd>Enter</kbd> 会在当前面板打开该视图。在**文件夹内部**输入 `:graph` 会打开该文件夹的关系图谱 — 即在其自身的搜索框中过滤为 `path:"that/folder"` 的关系图谱，就像是在那里手动输入的一样；在仓库根目录下则是完整的关系图谱。<kbd>Tab</kbd> 补全其名称的方式和补全文件夹名相同 — 并会带走输入框中其余的内容，因为页面不属于任何文件夹，其下也没有任何内容。点击这样一个面板上的标签，会打开已含有该内容的输入框。
- **<kbd>Tab</kbd> 将会写入的内容会随打字实时提供。** 只要所有以你已输入内容开头的子项还在继续保持一致，这段一致的部分就会显示在插入符之后并处于选中状态；一旦它们不再一致，就改为提示朝向其中第一项的那一步 — 或者朝向你用方向键选中的那一行，因为那正是 <kbd>Tab</kbd> 会前往的目标。覆盖输入一个名称时，其扩展名会保留在原处，并在其前方提供补全；刚进入的文件夹会提供它的第一级子项，因此不存在什么都不提供、而 <kbd>Tab</kbd> 却仍会写入内容的情况。输入与提示相符的字母，会被逐个吞掉；输入其他内容，提示就会消失。<kbd>Tab</kbd> 或 <kbd>End</kbd> 会整体接受它，<kbd>→</kbd> 会接受其中一个字母，<kbd>Backspace</kbd> 会把它整体收回而不影响你已输入的字母，且在你再次输入之前不会再给出提示 — 因此总有办法退出一个你并不想要的名字。按下 <kbd>Tab</kbd> 之后，下一步提示会立即给出，就像打完一个字母之后一样。下拉列表所过滤的依据是**你**输入的内容，而绝非已提供的那段提示。
- **提示不区分大小写。** 输入 `sch` 会提示 `Schemes`，按该名称本身的拼写显示；撤回该提示会把你输入的字母原样还给你。当 `Test` 与 `test` 同时存在时，会提示与你输入拼写方式相同的那个。
- 在输入框中，被提示的部分只是简单地处于**选中状态**。列表才是把它拼出来的地方：每一行都会把**与你输入内容相匹配的部分加粗**显示，无论匹配发生在名称中的哪个位置 — 输入 `kick` 能找到 `Weekly kickoff` 并如实标出。**以你输入内容开头的名称排在最前**，排在仅仅包含该内容的名称之前，并在边缘标有一条竖线：**蓝色**表示它们与你输入的内容相比还有更多共同部分，因此 <kbd>Tab</kbd> 对它们全都还有可补全的内容；**绿色**标在提示所走的那条分支上，也就是它们分道扬镳之处 — 以 `te` 匹配 `test1`、`test2`、`text1` 和 `text2` 为例，提示会是 `te`+`st`，因此两个 `test` 行是绿色的，两个 `text` 行保留普通竖线。每一行都会**给出 <kbd>Tab</kbd> 朝它前进那一步加下划线**，不只是当前被提示的那一行，且下划线会随提示变化而跟着移动。
- **打字会放开高亮所在的那一行。** 列表会在你当前所在的条目上打开，但你一开始打字，情况就变成了别处，而一个并非你亲自选定的高亮项，读起来却像是已经做出的选择。
- 提示始终只是摆在你面前的文本：你已输入的字母在你打字期间会保持你输入时的拼写方式，而接受提示会按文件夹的实际拼写重写该名称，因为路径必须与磁盘一致。`sk` + <kbd>Tab</kbd> 会到达 `Skyline`，而非 `skyline`。
- **输入框会染上它所指对象的颜色**，与下拉列表中对应行的颜色一致：紫色表示笔记，包括文件夹自身的笔记；橙色表示任何非笔记内容；蓝色表示你当前所在的笔记。取色所依据的那一行，是与你所输入内容完全同名的那一行；若没有，则是高亮的那一行；若还是没有，则是你的输入仍能指向的第一行。
- **一旦输入框中的内容找不到对应项，它就会变红** — 没有文件、没有文件夹，下拉列表中也没有任何一行仍指向它。此时按 <kbd>Enter</kbd> 会创建输入框中的内容，而不是打开它，红色正是在你提交之前发出的提示。它绝不会出现在网址上，因为网址本就不是要在本机上查找的位置。**变红的是整个**输入框，而不只是缺失的那一部分：文本框无法只给自己内容的一半上色。在重命名/移动模式下，输入框会保留自己那种红色，用于表示非法名称 — 在那里，找不到对应项的名字正是重点所在。名称**已被占用**这一情况会在你提交时被处理，届时会弹出对话框，询问该如何处理挡路的那个文件 — 参见[已被占用的名称](#已被占用的名称)：每一个朝 `Notes.md`输入的名字，途中都会经过一些本身可能就是文件的名字，因此如果逐字母标记就会对着谁都还没申请过的名字发出警告。
- `/` 会提交你正在输入的这一段，并进入其中，同时保留其之前的内容 — 与 <kbd>Tab</kbd> 进入某处时所做的事情相同。
- 在空输入框中按 <kbd>Backspace</kbd> 会退回到父文件夹，重新打开其名称，光标停在末尾。若输入框中只剩单独的扩展名，在其前方按 <kbd>Backspace</kbd> 效果相同 — 一个只剩 `.md` 的输入框并不指代任何东西 — 这个孤零零的扩展名也会随之消失。
- **在输入框打开时点击某个文件夹，会将其扩展为该文件夹之后的整条路径**，并选中该文件夹自身的名称 — 与从该行点击它会做的事情相同，且输入框中原有的内容都会保留。输入框中的内容在其打开期间就是该行的末尾部分，因此点击更靠上层的文件夹，交还的是这一次操作过程中所走过的路径，而不是笔记最初所在的那条路径。
- **在输入框最前端按方向键会把其前面的文件夹带入输入框**，仿佛整条路径就是一行文本。当插入符处于最开头时，<kbd>←</kbd> 会把那个文件夹带入输入框，并落在其名称末尾；<kbd>Ctrl</kbd>+<kbd>←</kbd> 落在其开头；<kbd>Home</kbd> 会一次性带入直到仓库根目录 — 或直到你所选定的位置（仓库之外）— 之间的每一个文件夹。按住 <kbd>Shift</kbd>，选区会随之延展覆盖被带入的部分。在 macOS 上，按词跳转是 <kbd>Option</kbd>+<kbd>←</kbd>，而 <kbd>Cmd</kbd>+<kbd>←</kbd> 相当于 <kbd>Home</kbd>。除了最前端之外，这些都是普通的文本编辑键。**下拉列表显示时，<kbd>Home</kbd>、<kbd>End</kbd>、<kbd>PgUp</kbd> 和 <kbd>PgDn</kbd> 归它所有** — 分别是第一行、最后一行、上一页、下一页，这里的“一页”指列表当前显示的内容，高亮行会保持其在屏幕上的位置 — 只有等列表关闭后，这些按键才会作用于文本；<kbd>Shift</kbd>+<kbd>Home</kbd> 在列表打开时同样会带入每一个文件夹。
- **列表跟随插入符。** 选中路径中不同的部分 — 拖选、点击进入，或用方向键移动 — 下拉列表就会列出*那个*文件夹的子项，而不是输入框最初打开时所在的那个。文件夹的判定依据是各个分段加上插入符之前输入框里的内容，因此在内容为 `2026/Notes.md` 的输入框中点入 `Notes.md`，列出的就是 `2026` 中的内容。指向某一行会将其写入插入符所在的那一段，而把指针移出列表则会把你的文本和选区原样还给你，与之前完全一致。
- **把选区从输入框中拖出去**，在别处松开，并不会关闭它。一次始于输入框内的按压，无论移动到多远，都仍属于这次编辑；只有*始于*输入框之外的按压，才算作点击到了别处。
- <kbd>Enter</kbd> 会提交 — 而当输入框完全没有指代任何东西时，比如在一个从来就没有可补全内容的空文件夹里，它会显示*未选择文件*，并保持打开，而不会像已经选定了什么那样直接关闭。<kbd>Esc</kbd> 或点击别处会取消并还原为文件的真实路径。按一次 <kbd>Esc</kbd> 就够了：它会关闭下拉列表、退出输入框，并把焦点交还给笔记，而不需要每一层都按一次。

输入框毫无修饰 — 没有方框，没有边框 — 因此读起来就是路径文本本身，并且会随输入自动伸长。

## 一行中的每个部分，逐个按钮说明

整行一览。右键那一列是**按一次**给你的结果；那个按钮还会计次，下面[它自己的表格](#右键一次两次三次)列出了第二次、第三次和第四次。这里假设**文件夹名打开列表**是开启的，也就是默认状态——关闭它时，文件夹名和分隔符会互换第一列的位置，正如[最上面的表格](#路径栏)所说。

| 按在哪里 | 单击 | 双击 | <kbd>Ctrl</kbd>+单击，或中键单击 | 右键 | 拖放东西到上面 |
| --- | --- | --- | --- | --- | --- |
| **仓库名** | 打开位置列表——其他仓库、主目录、文件系统根目录、已挂载的驱动器。默认关闭；关闭时改为在文件浏览器中显示该仓库 | 标记**整条绝对路径**。该列表打开时字段中已带有路径，且只标记了仓库自己的那一部分；再按一次会向外扩展标记其余部分。列表关闭时没有可扩展的对象 | 一个空标签页，停在仓库根目录，列表已经显示出来——可以从零开始输入路径的地方 | 仓库自己的右键菜单：对该段命名的仓库可以做什么 | **文件**移动到仓库根目录。**文本**在根目录打开字段，为它将成为的笔记命名 |
| **文件夹名** | 选中该文件夹以供编辑，其父级的内容列在下方 | 重新输入该文件夹及其下方的所有内容 | 在新标签页中打开该文件夹 | 该文件夹的右键菜单——与文件浏览器自身的菜单相同 | **文件**移动进该文件夹。**文本**在那里打开字段，为它将成为的笔记命名 |
| **分隔符** | 打开它前面的文件夹——如果有文件夹笔记插件在运行且存在文件夹笔记，则打开该笔记，否则在文件浏览器中显示并展开它 | 在有文件夹笔记插件运行且该文件夹尚无笔记时，**创建该文件夹的笔记**并跳转到它。如果已有笔记，这就只是单击的效果 | 如果已有文件夹笔记，则在新标签页中打开；否则打开一个停在该文件夹的标签页，列表显示出来 | 与文件夹名给出的相同的文件夹右键菜单——如果有文件夹笔记，则是该笔记的菜单 | 如果该文件夹有笔记，确认后追加到该笔记末尾 |
| **笔记的名称** | 打开名称以供编辑——文件夹仍以标签形式留在旁边——除扩展名外的部分都被标记 | 把扩展名也纳入标记 | 在新标签页中打开该笔记 | 该文件的右键菜单——与文件浏览器该行给出的相同 | 确认后追加到该笔记末尾 |
| **空白处** | 打开**整条路径**以供编辑，标记范围直到扩展名。文件夹会随之进入字段，这正是让此手势用于重新输入整条路径而非单个名称的原因 | 把扩展名也纳入标记 | <kbd>Ctrl</kbd>会在它自己的新标签页中再次打开该笔记，并在文件浏览器中闪烁提示，以免这个副本被误认为第一个。中键单击*不是*这个手势：它会覆盖路径进行粘贴 | 标记整条路径，并提供对已标记文本可以做的操作 | |

**第二次按下跟随第一次。**创建文件夹的笔记落在行中*打开*该文件夹的那一部分上——默认是分隔符，关闭互换后是文件夹名——与下划线标记的目标相同，也与单击已经请求文件夹笔记的目标相同。它只在有文件夹笔记插件运行时才会提供，因为文件夹笔记是一种约定而非文件系统本身的事实，并且只在该文件夹尚无笔记时才提供。它存放在哪里、叫什么名字，都读取自**Folder notes**插件自己的设置，所以把文件夹笔记放在文件夹旁边、或叫它`_index`的仓库，会得到相应的那种；文件本身始终是 Markdown，这正是该插件自己默认的创建命令所生成的格式，也是它在仓库设定的任何类型中查找到的格式。重命名/移动模式则完全不涉及这些——移动操作待定时，行上没有任何东西会打开文件夹。

**在名称上的点击会持续进行。**这四个层级与重命名键所经过的四个相同，顺序也一样：名称、带扩展名的名称、从仓库起的路径、从系统根起的路径。所以第三次点击到达仓库路径，第四次到达系统的——与<kbd>Tab</kbd>越过字段末尾给你的四样东西相同，也与右键*复制*而非选中的四样东西相同。

**悬停**是它自己的答案，从不改变任何东西：只要你指着一个被缩短的名称，它就会完整显示出来，行开头的图标则说明仓库位于何处。

## 右键：一次、两次、三次

行上的每个目标都会响应右键，你按几次决定了你得到什么。因为第二次按压可能还会到来，第一次会先等待约三分之一秒才行动——这是把三种手势放到一个按钮上的代价。

| 按在哪里 | 一次 | 两次 | 三次 |
| --- | --- | --- | --- |
| **仓库名** | 仓库的右键菜单：对该段命名的仓库可以做什么——包括*打开此仓库*，如果那个仓库不是你当前所在的仓库 | 复制仓库的名称 | 复制仓库所在的位置——第四次按下则复制打开的文件所在的位置 |
| **分隔符** | 该文件夹的菜单——如果有文件夹笔记插件在运行且该文件夹有笔记，则是该笔记的菜单 | | |
| **文件夹名** | 该文件夹的菜单 | 复制文件夹的名称 | 复制它及其右侧的一切 |
| **笔记的名称** | 该文件的菜单——与文件浏览器该行给出的相同 | 复制名称 | 连同扩展名一起复制 |
| **空白处** | | 复制从你的仓库文件夹起的路径，不带扩展名 | 同上，带扩展名 |

单击**仓库名**一次，会打开对该段所命名的对象可以做的操作。对于**你当前所在的仓库**：在新窗口中打开它、管理仓库、复制它所在的位置、复制它的 ID、在你的文件管理器中显示它。对于通过位置列表访问的**另一个仓库**，是同样的选项减去新窗口——那会打开*这个*仓库而不是那个——再加上唯一一件只有你不在其中的仓库才能提供的事：**打开此仓库**。它是按 ID 而非文件夹名向 Obsidian 命名的，因为两个仓库可能共用一个文件夹名。对于根本不是仓库的地方——你的主目录、一个挂载的驱动器——没有 ID 可复制，也没有东西可打开，菜单会通过不提供这些选项来说明这一点。

这不是 Obsidian 自己的三点菜单，那个菜单属于启动窗口，无法从正在运行的仓库内部打开——这些是同样的条目重新构建出来的，用的是 Obsidian 自己的措辞，取自它的命令，因此会以你的语言呈现。那个菜单里有三个条目故意**没有**放进来：*重命名仓库*、*移动仓库*和*从列表中移除*都作用于仓库自己的文件夹或 Obsidian 的仓库注册表，而对你正站在其中的仓库——文件已打开、监视器正在运行——做这些事正是仓库损坏的方式。打开仓库管理器（*打开另一个仓库*），在仓库关闭的状态下去做这些事。

**空白处**上的两种复制是按行原样书写的内容——链接或搜索想要的东西——而**仓库名**上的复制则是文件系统所知道的路径，这是 Obsidian 之外的任何东西想要的。那里每按一次都会扩大复制内容的用途：两次给出仓库的名称，三次给出仓库所在的位置，四次给出打开的文件所在的位置。Obsidian 自己在它的两个命令*从仓库文件夹*和*从系统根目录*中做出了同样的区分；这里面向外部的选项都落在路径本身之外的那一段上。

所有这些在仓库之外也同样有效，作用于相同的目标上。

每次复制都会在通知中说明，因为复制不会在屏幕上留下任何显示它已经发生的痕迹，而一次计数错误的按压不应该看起来像一次成功的按压。

## 修饰键：在别处打开它

笔记的名称和文件夹段的行为与它们在文件浏览器中的行一样。

| | 在笔记的名称上 | 在文件夹段上 |
| --- | --- | --- |
| 普通单击 | 编辑名称 | 浏览该文件夹 |
| <kbd>Ctrl</kbd> / 中键单击 | 在新标签页中打开该笔记 | 将该文件夹送到新标签页 |
| <kbd>Ctrl</kbd>+<kbd>Alt</kbd> | 拆分窗格 | 拆分窗格 |
| 拖动 | 该笔记，可拖到 Obsidian 能接受文件的任何地方 | 该文件夹，同样如此——包括标签栏 |

文件夹不是 Obsidian 能打开的东西，所以把一个文件夹送到标签页会做以下两件事之一：如果有文件夹笔记插件在运行且存在笔记，则打开其文件夹笔记；否则打开一个空标签页，其路径栏已经停在该文件夹中——只留给你输入名称。把一个文件夹段拖放到**标签栏**上会做同样的事，在你松手的位置打开一个新标签页——Obsidian 的标签栏本身只接受文件，所以从文件浏览器中拖出的文件夹在那里仍会被拒绝。

## Tab：先补全名字，再补全路径，然后扩大选中范围

<kbd>Tab</kbd> 的补全方式和 shell 一样：**按一次会把你输入的内容扩展到该文件夹里各个名字仍然一致的地方，在它们出现分歧的地方停下。** 输入 `Sk`，如果只有 `Sketches` 是这样开头的，这个词就直接补全了；输入 `Al`，如果 `Alpha-one`、`Alpha-two` 和 `Alpine` 都是这样开头的，你会得到 `Alp`，因为下一个字符是只有你才能回答的问题。

不输入任何内容再按一次，它会朝着某一个名字前进——列表中高亮的那一行，或者第一个——并在那个名字下一次出现分歧的地方停下：先是 `Alpha-`，然后是 `Alpha-one`。列表会以你当前所在的位置打开，所以在你自己的文件夹里，第一次按下会指向你正打开的那篇笔记，而不是排在最前面的那个。

**按一次绝不会替你在几个名字之间做出选择。** 一旦你输入的内容只剩下一个候选，或者你已经输入了某个文件夹的完整名字，且没有*别的文件夹*能继续扩展它，<kbd>Tab</kbd> 才会进入那个文件夹。如果有别的文件夹可以扩展——比如 `Schemes` 旁边还有 `Schemes2026`——<kbd>Tab</kbd> 会继续朝着更长的名字补全；<kbd>Enter</kbd> 和列表才是表示*就是这个*的动作。

一个**文件**从不会以这种方式挡住文件夹。一个文件夹旁边有一篇与它同名的笔记，那是文件夹笔记，不是路径上的分歧点，而 <kbd>Tab</kbd> 走的是文件夹——所以 `Projects` 旁边即使有 `Projects.md`，也照样会被进入，和其他文件夹一样。

由此还带来两件小事：填进输入框的内容会按文件夹本身的拼写方式来写，所以 `sk` 会变成 `Sketches`；而且只会替换正在输入的那个名字，所以路径右侧还有内容的话会被保留。

当输入时已经给出了一个候选名字，<kbd>Tab</kbd> **会精确地写出这个候选**：这个候选始终就是按下之后会写入的内容，列表里的下划线和绿线说的是同一件事，所以光标之后你看到的就是你会得到的。在名字们不再一致的地方，那就是朝着它们中第一个的一步——或者朝着你用方向键选中的那一行前进，<kbd>Tab</kbd> 走的是那一行而不是它旁边的那个——所以在按下之前，用方向键选到你想要的那个，或者输入越过分歧点。只有当候选只剩*一个*名字时，同一次按下才会进入它。

到达文件的名字**就是**第一级——不会有哪次按下只是把光标停在一个即将被标记的名字末尾而什么都没做。从这里开始，按下不再沿着路径移动，而是开始扩大被选中的范围：

1. 名字
2. 带扩展名的名字
3. 从你的仓库文件夹算起的路径
4. 从系统根目录算起的路径
5. 回到路径的开头**（按当前状态）**——停在行走开始的地方，第一段被标记，可以再走一遍

第四次点击可以直接到达同一个第四级。

扩大范围只会**扩大**。一个在输入框中已经完整的名字——无论是靠同一个键补全的，还是从列表里选出来的——会被整体标记，而不是先把扩展名去掉：第一级是给刚刚*到达*的名字用的，此时扩展名还不是话题所在。

这个阶梯是行走**到达**的地方，不是行走开始的地方。点击路径中间的某个文件夹，输入框会展开显示它下面的一切，并标记该文件夹的名字；此后每按一次 <kbd>Tab</kbd> 只会进入**一个**文件夹——标记下一个，并把其余路径留在它后面——只有当只剩文件名时，扩大范围才开始：

| 按下 | 面包屑 | 输入框 | 已标记 |
| --- | --- | --- | --- |
| 点击了 `a` | | `a/b/c/leaf.md` | `a` |
| <kbd>Tab</kbd> | `a` | `b/c/leaf.md` | `b` |
| <kbd>Tab</kbd> | `a › b` | `c/leaf.md` | `c` |
| <kbd>Tab</kbd> | `a › b › c` | `leaf.md` | `leaf` — 第一级 |
| <kbd>Tab</kbd> | `a › b › c` | `leaf.md` | `leaf.md` |

**一个已经确定填入的名字，不论你是怎么填入的，就是确定的。** 用 <kbd>Tab</kbd> 补全它、用 `/` 提交它、从列表中选出它，这三种方式最终都会让这一行停在同样的位置，保存同样的路径，所以做完这个动作之后再按下一步，无论你是怎么走到这里的，意义都一样。以前从列表里选一个文件夹会清空输入框，把用 <kbd>Tab</kbd> 到达同一个文件夹本该保留下来的路径丢掉。

**一段你还在书写的路径会整段跟着你。** 走进整段路径挂在其下的那个文件夹，并不是在断言剩下的部分已经存在——这正是路径提前于自身被输入的方式，它命名的那些文件夹正是 <kbd>Enter</kbd> 即将创建的。所以从 `Dokumente/plans/untitled.md` 走进 `Dokumente`，`plans/untitled.md` 会一直留在你面前，不管 `plans` 现在是否存在。你从零开始输入的路径同理：因为它没有从任何地方继承而来，所以也没有任何部分会被拿走。

**把某一段换成另一段，是另外一回事，这时路径只会跟到它真实存在的地方为止。** 把路径中间的某个文件夹换成同级的另一个——点击 `a`，输入另一个名字，按 <kbd>Tab</kbd>——它下面的一切都会跟着你，因为你原来所在的路径通常就是你想要的路径的大部分。不过只有那边真实存在的部分才会保留下来，这样输入框和旁边的列表就永远不会出现矛盾：留在你面前的始终是一条你真的能走下去的路径。以 `a/b/c/leaf.md` 为起点，点击 `a` 并标记其名字：

| 你填入的内容 | 面包屑 | 输入框 | 已标记 |
| --- | --- | --- | --- |
| `x`，完全没有 `b` | `x` | | 什么都没跟过来 |
| `y`，有 `b` 但里面没有 `c` | `y` | `b` | `b` |
| `z`，和 `a` 一路都完全一样 | `z` | `b/c/leaf.md` | `b` |

以这种方式单独留下的文件夹，仍然是一个可以走进去的文件夹：之后按下会进入它，而不是开始在它的名字上扩大选中范围。

如果一个名字在该文件夹里**完全**匹配不到任何东西，处理方式会不同，因为并没有因它而确定填入任何内容：按下会标记你输入的内容，方便你直接输入覆盖，而不会用别处的内容来回答。

整套机制是一个**循环，绕一圈不花任何代价**：最后一级之后再按一次，会把这一行交回路径的开头，文件夹们悉数还在，随时可以再走一遍。唯一会离开这一行的东西是绝对路径前缀，在停止显示它的那次按下时消失。

回来的是**你走出来的那条路径**，不是你出发时的那条。把行走过程半路分叉——从列表里选另一个同级项，朝另一个名字补全——这一圈就会收在你实际所在的地方；在它之前的四级描述的正是这同一条路径，而这一级以前才是那个描述过去的、格格不入的一级。

<kbd>Shift</kbd>+<kbd>Tab</kbd> 反方向关上同一个环：在路径开头，已经没有什么可以再交还，也没有更上层可去时，再按一次会跳到**最远**那一级——从系统根目录算起的路径——并从那里继续往内收窄。两个方向都不会走到死路。

它也不会在已经显示过的一级上白白花一次按下。第一级往下——不带扩展名的名字——阶梯就结束了，*同一次按下*会离开该文件夹：从系统根目录算起的路径、从你的仓库算起的路径、名字、不带扩展名的名字，然后是文件夹，每一步一次。

同样，不会在什么都没改变的一级上花一次按下：点击一篇笔记的名字时，它已经是不带扩展名显示的，这正是第一级要显示的内容，所以从这里开始，<kbd>Tab</kbd> 会从第二级起步。

每一级改变的是输入框里*实际的内容*，不只是高亮显示的部分——选中范围必须正好覆盖它所命名的文本，否则 <kbd>Enter</kbd> 提交的就会是和你看到被选中的内容不一样的东西。这个阶梯属于同一次编辑过程：点到别处，或者输入任何内容，下一次 <kbd>Tab</kbd> 就会重新开始补全名字。

### <kbd>Shift</kbd>+<kbd>Tab</kbd>：原路返回

<kbd>Shift</kbd>+<kbd>Tab</kbd> 按之前按下的顺序，每按一次收回一步：选中范围每次收窄一级，每次补全都被交还，每个文件夹都被退出——它的名字回到输入框里，让你可以编辑而不必重新输入。

**返回途中不会删除任何内容。** 一次补全被交还的方式，是把它添加的字符*标记*出来，正如前进时会标记它扩大过的部分——名字始终留在你面前，每再按一次都会多标记出一段：

| | 输入框 | 已标记 |
| --- | --- | --- |
| 已走入 | `Alpha-one` | |
| <kbd>Shift</kbd>+<kbd>Tab</kbd> | `Alpha-one` | `one` |
| <kbd>Shift</kbd>+<kbd>Tab</kbd> | `Alpha-one` | `ha-one` |
| <kbd>Shift</kbd>+<kbd>Tab</kbd> | `Alpha-one` | `Alpha-one` |

输入会替换掉被标记的部分，和其他地方一样。<kbd>Tab</kbd> 会精确地放回标记所交还的内容，所以退两步再走两步会让你回到原来的位置。

一旦整个名字都被标记，就没有什么是靠按下放在那里的了，下一次按下会*沿路径向上*：它会离开你当前所在的文件夹，就和在空输入框上按 <kbd>Backspace</kbd> 一样。这也不花任何代价——文件夹的名字会重新出现在输入框里，出现在原有内容**前面**，并被标记，这和点击那个文件夹会得到的文本完全一样。返回是一个方向，而不是撤销历史——但先标记名字意味着一次按下绝不会同时收回你写的内容，又把你带出你在其中写作的那个文件夹。

打开时**已经处于选中状态**的文本——文件夹点击留下的那种——正是 <kbd>Tab</kbd> 接下来要处理的名字：它会像其他情况一样被补全、被走入，输入会将其替换。只有聚焦命令会打开在阶梯本身的某一级上，因为它展示给你的是整条路径，而不是一个可以走进去的文件夹。

## 输入的内容不是一个路径

| 你输入的内容 | 会发生什么 |
| --- | --- |
| `https://…` | 如果启用了 Obsidian 的**网页查看器**核心插件，会在新标签页中打开；否则用你的桌面浏览器打开 |
| `obsidian://…` | 交给 Obsidian 自己的 URI 处理程序 |
| `file:///…` | 解码并打开：如果在你的仓库内，就作为真正的笔记打开；否则在查看器中打开 |
| `/home/you/a%20b.md` | 同上，适用于从浏览器或文件管理器复制出来的路径 |

只有明确的协议前缀才算数——一篇叫 `100%20` 的笔记依然只是一篇笔记。属于某个协议的 `/` 会保持原样，而不会被当作进入某个文件夹，所以网址也可以手动输入，而不仅限于粘贴。

## 一个供键盘使用的命令

**聚焦路径栏**会在笔记名字上打开输入框，并像 <kbd>F2</kbd> 一样在其中行走——名字、带扩展名的名字、从你的仓库算起的路径、从系统根目录算起的路径——之后再按一次会关闭输入框，把光标放回笔记中。它不会重命名：按 Enter 是导航，和其他任何输入框一样。它默认没有自己的快捷键，因为 Obsidian 的规范不鼓励插件擅自占用快捷键；本插件设置末尾的**热键**一行会打开*设置 → 热键*，只显示本插件的命令，你可以在那里绑定它。

## 导航从不触碰打开的文件

在默认的（导航）模式下，当前打开的笔记**绝不会**被重命名或移动。

- 一个能解析为已有文件的路径会打开该文件。
- 一个尚不存在的路径会被直接创建，连同所有缺失的父文件夹一起创建，然后打开。以这种方式创建的每个文件和文件夹都会在通知中说明——否则新建的文件夹在你去寻找它之前是看不见的——而 Obsidian 自带的回收站让不想要的文件只需一次按键就能撤回。
- **在仓库之外，它仍然会先询问。** 在外面，同样的打字失误会写入某个系统文件夹，那里既没有通知，Obsidian 的回收站也帮不上什么忙。

## <kbd>Ctrl</kbd> — 新标签页，以及复制而非移动

**在仓库内创建、移动或复制的笔记，会在文件浏览器中显示在它落脚的位置**，并短暂地用 Obsidian 的强调色标记出来——之后你会到目录树里去找它，所以它会直接呈现在你眼前，而不是被留在一个可能都没打开的文件夹里。复制操作同样会明确说明：副本会把原件留在原处，并在自己的窗格中打开副本，如果没有这句说明，很容易被误以为什么都没发生。

在从列表中挑选文件时，或在某个路径上按 <kbd>Enter</kbd> 时按住 <kbd>Ctrl</kbd>（macOS 上是 <kbd>Cmd</kbd>），会把结果送到**新标签页**而不是当前这个：

| | 直接操作 | 按住 <kbd>Ctrl</kbd> |
| --- | --- | --- |
| 挑选或输入一个已有文件 | 在此处打开 | 在新标签页中打开 |
| 输入一个不存在的路径 | 先询问，然后在此处打开 | 先询问，然后在新标签页中打开 |
| 在重命名/移动模式下提交路径 | 把笔记**移动**到那里 | 把它**复制**到那里，并在新标签页中打开副本 |

修饰键按 Obsidian 自己的规则读取，因此其行为与在链接或文件浏览器行上完全一致 — 中键点击同样表示“新标签页”，<kbd>Ctrl</kbd>+<kbd>Alt</kbd> 表示分屏，<kbd>Ctrl</kbd>+<kbd>Alt</kbd>+<kbd>Shift</kbd> 表示新窗口。

复制操作拒绝覆盖，和移动完全一样——包括覆盖到笔记自己的路径上，那种情况下并没有什么可以合理复制的东西。在仓库之外，这种拒绝同样会明确说出来。

所有这些在**列表打开时**和不打开时都同样有效：在某一行高亮时，修饰键作用于那一行；什么都没选中时，则作用于你输入的内容。

## 浏览仓库之外

**此项默认关闭。** 请先在设置中开启 **访问外部文件** — 在仓库之外读写是这个插件所做的、而 Obsidian 自己不做的唯一一件事，所以它被设计成需要主动开启，而不是主动关闭。关闭时，仓库名只是在文件浏览器中显示你的仓库，这里的任何东西都不会望向它之外。

点击**仓库名**（当 *显示仓库名称* 关闭时，则是 🏠 图标）会打开一个地点而非内容的下拉列表。它打开的输入框中装着**你所在的整条路径，完整写出**，并选中它开始的那个地点 — 所以挑选别的地方，或直接在选中内容上打字，只会替换那个开头部分，路径的其余部分仍留在你面前。**再按一次名称** — 相当于双击 — 选中范围就会扩展到整个名称，这样就能一次动作取得绝对路径，而不必手动划选。改变主意的话，<kbd>Esc</kbd> 会把这一行恢复原样。

在这里输入时，和别处一样会提示该地点名称的其余部分，<kbd>Tab</kbd> 会**代入那个地点** — 你正指向的那个，或者这个名称唯一能指代的那个。当仍有多个地点共享你已输入的内容时，按键会像别处一样停在分叉处。指向某个地点会显示**那个地点自己的路径**，全部选中，其后跟着你笔记的路径 — 但只到它在那边真正存在的深度为止 — 这正是挑选它会把你带到的地方。地点不是屏幕上路径里的一段，而是用来从头计算整条路径的起点，因此你原来所在之处不会有任何东西留在它前面。

可供选择的地点有：

- **你的其他仓库**，读自 Obsidian 自己的记录，最近打开的排在前面，各自带着 Obsidian 自己的仓库图标 — 也就是应用在仓库相关命令里用的那一个。已经打开的那个仓库改用一座房子：默认情况下这一行就从那里开始，它不是一个要去的地方。
- **主文件夹**，在自己的账户名下，以一个 `~` 标示。Lucide 没有波浪号，所以这一个由插件按 Lucide 自己的 24×24 网格、用同样的线宽绘制 — 它是这套图标缺失的一枚图标，而不是混在图标当中的一个文字字符。
- **文件系统根目录**，标为 `root` — 不作翻译，因为在任何系统上它都叫这个名字 — 而不用 `/`，那样在紧随其后的分隔符旁边会读成空空的一段。
- **已挂载的驱动器**，在判断成本低廉之处按类型配图标：网络共享、光盘、软盘和可移动介质各有其图标；其余一律用通用驱动器图标。在 Windows 上驱动器显示为 `C:` 并配通用图标 — 卷标和精确类型需要 WMI，这是刻意不去做的。

挑选另一个仓库**不会把 Obsidian 切换过去。** 你打开的一切照旧开着，只是路径栏开始在那边浏览。把它放在路径栏上、而不是交给侧边栏的仓库切换器，意义正在于此。

它落脚的位置也会**尽可能贴近你当前所在的笔记，只要那个地点真的延伸到那里**。

- 如果你挑选的地点*包含*这篇笔记 — 主文件夹，或者你的仓库所在之处 — 你会得到从那里算起的路径：打开 `takeaways.md` 时选 `~`，输入框会读作 `Vaults/your-vault/takeaways.md`。
- 如果它是与当前仓库并列的地点 — 另一个仓库、另一个驱动器 — 会尝试同样的相对路径，深入到它实际存在的程度。仓库之间常常近乎彼此的副本，跳去另一个仓库的理由通常正是那边同一篇笔记。

无论哪种情况，这一行都停留在你挑选的地点，并且**该路径的第一个文件夹会以选中状态打开** — 与点击一个文件夹得到的形状相同：当你跳到别处时最可能改动的那一段就在最前面，而路径的其余部分在你改动它时依然可见。绝不会预填任何磁盘上实际不存在的内容。

### 在外面时

路径**从你挑选的地点开始**，而不是从机器的目录布局开始 — 点击空白处或按下焦点键得到的输入框也是如此：它装着从那个地点算起的路径，而不是机器的绝对路径，其前置轨迹会收缩到那个地点本身，正如它在仓库内会收缩到仓库根目录一样 — 选择 `Archive` 后这一行会读作 `Archive / notes / …`，而不是 `/home/you/Vaults/Archive/notes/…`。开头那一段会带上表明其身份（仓库、主文件夹、驱动器）的图标，而 <kbd>Backspace</kbd> 会停在那里，不会继续走到文件系统的其余部分。当 *显示仓库名称* 关闭时，那一段就只剩图标 — 这个设置针对的是这一行的开头段，无论它命名的是哪个仓库，而不仅仅是你自己的那个。

只要路径栏指向仓库之外，它就一直**以错误色描边** — 与重命名模式所画的是同一个环。它标记的是一种持续状态，而非某个瞬间：只要它还在，Obsidian 自己的那套处理就都不适用于这一行所显示的内容，并且在你另行表态之前写入始终是锁定的。

除此之外，浏览与在仓库内一样：小块、分隔符、输入、自动补全、用 <kbd>Backspace</kbd> 退出。可见性规则同样适用，所以不受支持的扩展名仍需要 Obsidian 的 *检测所有类型文件*，点文件仍需要本插件的设置。

**在那边右键也能用**，不过是另一个菜单：文件浏览器自己的处理程序需要一个仓库认识的文件，而外面的条目则改由路径构建。它们提供打开（在此处、在右侧、在新窗口，或用你桌面的默认应用程序打开）、*复制路径*、*在系统文件管理器中显示*，以及 — 一旦挂锁打开后 — *新建笔记*、*新建文件夹*、*创建副本*、*重命名…* 和 *删除*。**拖拽**仍需要一个仓库文件，因此依然不可用。

同一个菜单也出现在查看器中打开的文件上，可通过右键，或从窗格自己的三点菜单调出，它会询问该视图标题栏中的那把挂锁。它不会询问别的：文件是被渲染还是以源码显示，对它能否被删除毫无影响，而一张图片或一份 PDF — 它们根本没有源码视图 — 与一篇笔记同样可以被删除。*删除* 意味着进入桌面的回收站，因此可以从那里撤销；没有回收站的系统会报告这一点，而不是直接销毁文件。

在仓库之外删除会把文件移到你的**系统回收站** — Windows 上的回收站，macOS 上的“废纸篓” — 绝不会直接解除链接。在这里没有 Obsidian 的回收站可供恢复，所以那种无法撤销的删除根本不会被提供：在没有回收站的平台上，尝试删除会转而报告失败。

### 写入仓库之外

一切写入操作**默认是锁定的**。只要这一行指向仓库之外，标题栏中原本放重命名切换的位置就会换成一把**红色挂锁** — 与这一行周围的环同色，理由也相同：它标记的是一种拒绝。这两者是同一个位置里的同一个控件，所以永远不会有“到底是哪一个在把关什么”的疑问。

三次按压，构成一个循环：

| 按压 | 得到什么 |
| --- | --- |
| 红色挂锁 | 允许在此写入。挂锁被替换为重命名/移动切换开关 |
| 切换开关 | 重命名/移动模式，与仓库内完全一样 |
| 再次按下切换开关 | 模式结束，挂锁重新关闭 — 许可不会比它为之开启的那件事活得更久 |

**重命名键同样会询问挂锁。** 在仓库之外按下它，会让挂锁一开一合地闪一下，而不是打开一个每次提交都会被拒绝的模式：拒绝发生在动作之前，而不是之后。按下挂锁，或者在半秒内再次按下重命名键 — 第二次按压恰好给予按钮所给予的许可，仅限于此地点，并随之打开重命名模式。

在仓库内没有挂锁：没有什么需要解锁，切换开关直接占用那个位置。

这份许可授予的是**一个地点，而非一个瞬间**：它会挺过你在这一个地方工作时所做的一切 — 完成一次移动、点击别处让输入框失焦、打开一个文件 — 并在你从下拉列表中挑选不同的仓库、驱动器或根目录时结束，或在这一行回到某个仓库文件时结束，或在第三次按压时结束。所以在同一个文件夹里连续移动多个文件只需按一次，而不是每个文件按一次。

挂锁打开后，路径栏在外面的表现与在里面一样：

| 操作 | 结果 |
| --- | --- |
| 输入一个不存在的名称，按 <kbd>Enter</kbd> | 与在仓库内相同的“要创建吗？”询问；缺少的上级文件夹也会被创建。不带扩展名的名称会变成 `.md`，与在仓库内完全一样 |
| 重命名/移动模式，输入新名称 | 重命名这一行所显示的文件。不带扩展名的名称会保留该文件原有的扩展名 — 在外面，一个文件夹里什么类型的文件都有，重命名不该悄悄把 `.png` 变成 `.md` |
| 重命名/移动模式，浏览到别处，选择**保留此名称** | 以它现有的名称移动过去 |
| 在以上任一操作中按住 <kbd>Ctrl</kbd> | 改为复制而非移动，并在新标签页中打开副本 |

处于锁定状态时，以上各项都不会发生，而是报告是什么挡住了它们。两种状态下都绝不会覆盖任何东西：已存在的目标会被拒绝，而这个拒绝来自文件系统本身（`COPYFILE_EXCL`，一次排他式创建），而不是某个可能输掉竞态的检查。跨文件系统的移动 — 从 U 盘、从网络共享 — 会退回到“先复制后删除”，并且只有在副本落地之后才会删除原件。

**把一篇笔记移*出*你的仓库会先询问。** `fileManager` 无法跟着文件跨越那道边界：每一条指向这篇笔记的链接都会停止解析，没有任何东西会更新它们，而且这篇笔记会从仓库的索引中消失。所以这个移动会作为一个决定被提出，而不是被拒绝或悄悄完成 — 一个对话框会说明这样做的代价，以及有多少笔记链接到你正在移动的这一篇。确认后它才会真正移动：先复制出去，再通过 Obsidian 自己的删除功能从仓库中移除，因此它可以像一篇被删除的笔记一样恢复；任一步骤失败，笔记都会留在原处。按住 <kbd>Ctrl</kbd> 仍然是改为复制出去，那样就没有上述任何问题。反过来 — 把外部文件带*入*仓库 — 目前尚未实现。

### 打开外部文件

浏览文件系统可以一路走回**你打开着的那个仓库** — 从根目录、从主文件夹、从你仓库所在的任何地方。以这种方式抵达的文件是一篇普通笔记，因此会照普通笔记打开：真正的编辑器、链接和反向链接，而这一行会弹回以仓库为根的路径栏。只有 Obsidian 没有视图的文件才会留在预览中，因为在那种情况下预览是更好的答案。当预览无论如何都在显示这样一篇笔记时 — 比如一个重新打开的工作区 — 它的顶行会提供**在*（仓库）*中打开**，与手动做出的提议相同。

Obsidian 的编辑器只对仓库内的文件起作用，因此外部文件**无法**作为带链接、反向链接等等的真正笔记打开 — 这是应用的限制，不是本插件的限制。挑选一个外部文件会改为打开**预览**，在你另行表态之前是只读的：

| 类型 | 显示为 |
| --- | --- |
| `.md`、`.markdown` | 渲染后的 Markdown |
| `.html`、`.htm`、`.xhtml` | 渲染后的页面 |
| 图片、音频、视频、PDF | 原生播放器/查看器 |
| 其他任何**文本**文件（`.json`、`.css`、`.log`、`.txt`……） | 逐字的纯文本 |
| 没有查看器的二进制格式（`.zip`、`.exe`……） | 交给 *用默认应用打开* |

查看器对一个文件有两种读法，而由于二者互斥，只会显示你将要**切换到**的那一种：

| | 作用 | 默认适用于 |
| --- | --- | --- |
| **以 Markdown 查看** | 将文件渲染为一篇笔记，只读 | `.md`、`.markdown` |
| **以页面显示** | 将文件渲染为其本身的页面，只读 | `.html`、`.htm`、`.xhtml` |
| **以文本编辑** | 源码，可编辑 | 其余所有类型 |

在仓库之外，**以文本编辑** 同时也是解除只读的那一次按下 — 模式与许可是一个动作，而不是两个需要分别琢磨的按钮。**只要按下会解除只读**，它就带红色调，无论你是在原地准备编辑，还是径直从渲染视图过来；在仓库内没有什么可解锁的，所以它保持素净。**以 Markdown 查看** 覆着一层淡淡的强调色 — 与 Obsidian 给选中文本的色调相同 — 标明它是回去的路，而不是号召你行动。

由于按钮跟随的是*编辑*而非原始模式，一个在文本视图中处于只读的文件仍会给出 **以文本编辑**：正是这一按使其就绪。而永远无法写入的文件 — 被截断的，或读取失败的 — 则改为写着 **以文本查看**，因为按下所能给的就只有这些。

默认值取的是有用的那一面，而非字面的那一面：shell 脚本里的 `#` 是注释而不是标题，所以把 `.log` 当作 Markdown 渲染会把它悄悄吞掉。两种默认都可以按文件覆盖，而这个选择会进入该窗格的历史，因此前进/后退以及重新打开的工作区都会保留它 — 有大量笔记住在 `.txt` 文件里，也有大量 `.md` 文件读源码更省事。

#### HTML 页面被允许做什么

什么都不允许。这个页面显示在一个**所有权限均被剥夺**的框架中 — 没有脚本、没有表单、没有导航、没有属于自己的源 — 并且有一条内容策略使它完全无法联网。这并非无谓的谨慎：以普通方式加载的本地页面会共享这个窗口的源，而这个窗口就是 Obsidian，所以一个下载的 HTML 文件中的脚本本会在你的应用内部运行，拥有你应用的权限范围。

由此付出的代价是页面能*做*的任何事；保留下来的是页面本身*是*什么。位于文件旁边的样式表和图片会被读入并带进这个框架，所以保存下来的页面看起来依然是它本来的样子。指向页面自身文件夹之外的引用，以及指向网络上某处的引用，会原样保留而单纯不会加载 — 一个本地文件无法悄悄告诉某台服务器你打开过它。

脚本是被**移除**而非仅仅被阻止的，这样你所见的页面与你可以切换到的源码之间只有一处明说的差异，而不是框架默默拒绝运行的种种。页面内的链接不起作用。当你想要真正的东西 — 脚本、网络，一应俱全 — *用默认应用打开* 会把它交给你的浏览器，那才是干这个的合适工具。

**仓库内的文件可以直接编辑**，无需解锁：*以文本编辑* 是一个真正的编辑器，你输入它就写回。

**编辑状态会跨切换保留。** 切到 *以 Markdown 查看* 会将其挂起 — 静态渲染没有可输入之处，而实时预览需要 Obsidian 自己的编辑器，那只对仓库内的文件存在 — 因此在那边不会有任何东西声称你正在编辑。切回 *以文本编辑* 会从你停下的地方继续。

**仓库之外的文件以只读方式打开，而 *以文本编辑* 解除这一点。** 这一按就是整道门：在它发生之前，外面什么也不会被写入。之后文件会随你输入而保存，与仓库内的文件完全一样；状态行也从一把锁变成一支笔。这次解锁只覆盖那一个标签页里的那一个文件 — 转到另一个文件就重新上锁 — 而且它被刻意不存入标签页的历史，因此重新打开的工作区绝不会带着“已就绪的写入权限”回到某个你根本不记得打开过的系统文件上。

**被截断的文件无论如何都保持只读** — 保存屏幕上的内容会丢弃上限之外的一切，所以那个按钮根本不提供，而不是提供了再拒绝。读取失败的文件同理：除了一个空窗格，没有什么可写回。

如果写入失败 — 只读挂载、并非你所有的文件 — 系统自己的原因会以通知的形式显示出来。

超大文件会被截断显示，而状态行会直说，而不是留给你自己去发现 — 它与其他条件并列，而不是跟在按钮后面，因为它和其余各项一样是关于这个文件的事实。上限是对着真实渲染器量出来的，而不是猜的 — 把一兆字节的文本排布在一个窗格里会直接搞垮 Obsidian 的渲染进程，而 Markdown 每字节的开销是纯文本的数倍，所以二者有各自的上限；即便整个文件很小，单独一行过长时那一行也会被截短。

**状态行是标签，解释则是提示气泡。** 每一行都用尽可能少的字说明当下为真的事 — *仓库之外*、*没有适用于此文件类型的编辑器*、*已截断 — 文件过大* — 因为旁边的按钮已经说明了文件处于什么状态。把指针悬停上去就能得到那句话：为什么 Obsidian 无法把它当作笔记打开，这种文件类型本来会遭遇什么，截断让你失去了什么。

这同样适用于仓库**内**的文件。凡是 Obsidian 没有视图可用的扩展名，它都会径直交给桌面的默认应用程序 — 所以仓库里的一个 `.txt` 或 `.json` 会把你整个带出 Obsidian。现在这些也在同一个查看器中打开，带橙色描边，因为“在 Obsidian 里打开它”正是你的诉求 — 而作为仓库文件，它们在那里无需任何解锁即可编辑。没有查看器的二进制文件保持 Obsidian 原有的行为；那里没有什么可显示的。

预览**在你原本所在的标签页中**打开，因此前进/后退会把你带回原来的笔记；和别处一样，按住 <kbd>Ctrl</kbd> 可用新标签页。只要它开着，标题栏就继续显示这个外部文件的路径，你可以从那里继续浏览。

内容上方有一行低调的出口：

- **在*（仓库）*中打开** — 当文件属于你的其他某个仓库时显示。把它交给 Obsidian 自己的 URI 处理程序，后者会打开那个仓库的窗口并带上这篇笔记，作为一篇真正可编辑的笔记。当前这个窗口保持原样不变；不会有任何东西在你脚下切换。
- **以 Markdown 查看** / **以页面显示** / **以文本编辑** — 这个文件所拥有的两种读法；最后一项在仓库之外还会解除只读。
- **用默认应用打开** — 把文件交给你桌面的默认应用程序，包括这个查看器无法显示的二进制格式。措辞与 Obsidian 自己针对同一动作的条目完全一致，因为这就是同一个动作。

查看器同样会响应**右键**：在文本编辑器内提供 *剪切* / *复制* / *粘贴* / *全选*，在其他任何地方则提供文件自己的菜单。标题栏中 Obsidian 的三点菜单也带着这个菜单 — 在仓库之外，否则它就只能提供 *向右拆分* 和 *向下拆分*。

除非你先按下 *以文本编辑*，否则仓库之外不会被写入任何东西。完整的说明见 README 的 [仓库之外](README.zh.md#仓库之外) 一节。

## 把文件拖放到路径中的某个文件夹上

路径中的每个文件夹都可以作为放置目标，所以**把笔记拖到某个文件夹上就会把它移动到那里**——从笔记到它上方任意文件夹的最短路径就在这里，因为目标本来就已经显示在屏幕上。可以从文件浏览器拖动，从下拉列表拖动，从表头中笔记自身的名称拖动，或者从 Obsidian 中任何能产生文件的地方拖动：这是应用自身的拖拽，所以悬停标签、光标和高亮显示都是文件浏览器绘制的那一套。

**仓库的名称也能接收放置**，因为它就是这一行最上方的文件夹——这是从这里把笔记放进仓库根目录的唯一手势。

**整个多选也能一起拖动**，并作为一个整体移动：如果其中任何一个无法被移动，整个放置都会被拒绝，而不是移动一部分、悄悄跳过其余部分。

链接会跟随笔记一起变化，与从文件浏览器移动或输入路径时完全一样。

**无法接受放置的文件夹不会有任何自己的表现**——没有*移入*标签，文件夹也不会高亮——而不是先表现出来再失败；Obsidian 自身对表头的回应，即*在此标签页中打开*，会代替它出现在那里。三种情况：

- 文件**已经在其中**的那个文件夹，因为它本来就在那里；
- 被拖到**它自身或它的子孙文件夹内部**的文件夹，这样会让它无处可来；
- 一个多选中同时包含**某个文件夹及其内部的内容**，因为移动该文件夹会把子项一并带走。

已经持有**同名文件**的文件夹会接受放置，并询问该如何处理挡路的那个文件，使用与输入或选取一个已被占用的名称时相同的对话框——见[已被占用的名称](#已被占用的名称)。这里的任何操作都不会覆盖文件。

只有**仓库内部**的文件夹才能接受放置。当这一行指向仓库之外时，它的各段都会拒绝接受，因为把笔记移出仓库会破坏指向它的每一个链接——这是一个值得用一次提问、而不是一个手势来做的决定。要有意这样做，仍然要通过输入路径，它会先询问，并告诉你会有多少笔记受到影响。

## 拖放文本或文件以写入内容

同样的目标既能接收文件，也能接收**内容**，两者的区分依据是你拖的是什么，而不是你放在哪里。

**放到这一行已经命名的某篇笔记上**——笔记自身的名称，或者某个其文件夹带有文件夹笔记的分隔符——你放下的内容会被追加到它的末尾，前面隔一个空行。它会先询问，因为这是写入一个已经存在的文件，而拖拽是一个不稳的手也可能不小心做出的动作。从编辑器中拖出的文本、从桌面拖来的文件、从本仓库拖出的笔记，都可以正常使用；文件会被当作文本读取，二进制文件则会被拒绝，而不是作为一屏乱码粘贴进去。

**放到一个位置——仓库名称或某个文件夹上**——还不会写入任何内容，因为还没有命名。输入框会在那里打开，装着你放下的内容，你输入的名称就是最终提交时用的名称：如果是新笔记，就*创建*一篇装着这段文本的笔记；如果是已有笔记，则会像上面一样询问。<kbd>Esc</kbd>，或点击别处，都会放弃整个操作。

**当一次拖拽最终会落地为内容时，这一行会显示蓝色光圈**，并在输入框正持有内容期间保持蓝色——同样的蓝色，表达同样的意思：接下来发生的事与你携带的文本有关。把文件从你自己的仓库拖到某个文件夹上，含义仍然是*把它移动到那里*，保留 Obsidian 自身的高亮，绝不会显示蓝色；那个手势本来就在先，内容让位于它。

## 当路径比面板更长时

名称是**被缩短，而不是被挤压**，缩短的顺序按你最不可能需要它的程度来排：

1. **首先是仓库名称**，一直缩到只剩图标。你知道自己在哪个仓库；图标一直在说明路径从哪里开始。
2. **然后是文件的扩展名**，如果你开启了它——几乎仓库里每个文件都有同样的三个字符。它是整体去掉，而不是被缩短：半个扩展名说明不了任何东西，不比没有扩展名强。
3. **然后是文件夹，最长的先来。** 最长的文件夹名会缩短到与次长的相同长度，再让两者一起缩短，依此类推，每个都在自己的下限处停下——所以一个非常长的文件夹会先让出它相对其他文件夹的全部多余部分，然后旁边一个短名称才会失去一个字母。
4. **文件自身的名称最后才被缩短**，并且会保留大约六个字符。这正是表头存在的意义所在。

空间是**连续地**被让出的，是按像素的几分之一让出，而不是一次一个字母：正在让步的名称会在像素处被截断，并在其 `…` 下淡出，所以缓慢拖动面板时，这一行会平滑地变窄，其后的任何内容都不会一步步地移动。在任何字母被删掉之前，先花掉的是分隔符周围的空隙——这是这一行唯一的间距，且完全不消耗信息——被缩短的名称会正好止于分隔符开始的地方，两者之间不留一段空白框。

**输入框会占满它所容纳的内容。** 打开一个输入框来输入路径，并不会把旁边的文件夹挤开：它的宽度与其中的文本相同，并随你输入而增长，所以其余的路径会保留输入框不需要的一切空间。只有当两者都容不下时，这一行才会滚动，此时输入框是唯一绝不让步的东西——它是正在被编辑的文本，而不是正在被适配的名称。

任何删减都不会超出让它与相邻项区分开所需的程度：同一文件夹下的 `Projects2025` 和 `Projects2026` 会被缩减为 `…025` 和 `…026`，而不是缩成一个会让它们变成同一个词的前缀；而 `Reports` 挨着 `Receipts` 时可以缩减为 `Rep…`。除此之外，每个名称都会保留**可读的宽度**——文件夹大约四个字母的宽度，文件名六个字母的宽度，这是按这一行实际所用字体测得的宽度，而不是按字符数计的。四个窄字母和四个宽字母代表的名称量并不相同，所以 `lilliliillil` 被允许比 `WWMMWWMMWWMM` 保留更多自身内容，而两者最终留在屏幕上的宽度是一样的。短名称完全不会被处理——一个被磨到只剩 `A…` 的名称虽然独一无二，却仍然无法阅读。**空格不计入这个宽度。** 用六个字符说明这是哪个文件，这六个字符都值得被读到，所以它们之间的空白会跟着一起被保留，且绝不会让一个空格紧贴在 `…` 旁边，因为那样它反正也看不见。

**名称会在相邻项彼此一致的地方被截断，如果哪里都不一致，就在中间截断。** 两个叫 `aaaa-common-one` 和 `aaaa-common-two` 的文件夹除了最后三个字符外完全相同，所以截掉尾部会保留有意义的那一半：它们会变成 `…one` 和 `…two`，这样既更短，又能区分两者。如果一致的部分在末尾——比如 `alpha-draft` 挨着 `beta-draft`——被去掉的就是末尾；如果两端都一致，留下的就是中间部分。一个没有相近邻居的名称会丢掉中间部分，因为一个名称的开头说明它是什么，结尾说明它是哪一个——对文件来说，就是它的扩展名：`annual…2026.md`。

短暂的共同部分不算数。`parallel structures` 恰好和旁边的 `Schemes` 结尾两个字母相同，但这并不是让两者都保持完整的理由——光是开头三个字符就已经能区分它们了。

不会有任何内容换到第二行。当即使最短的、如实呈现的名称也放不下时，这一行会**横向滚动**，停靠在文件所在的那一端——到那一步，已经没有可以再压缩的东西了，再截断只会隐藏内容，而不是缩短它。滚轮会在指针悬停于这一行的任意位置时使其滚动，两端都可以到达：滚动时这一行会对齐到起点，不论对齐设置是什么，因为内容如果在一个已经装不下它的框里居中，就会同时从左右两侧溢出——而那一半是完全无法滚动到的。

**指向一个被缩短的名称，它会完整地显示出来**，只要你的指针一直停留在上面，并且会滚动到左边缘，让恢复出来的全部内容都显示在屏幕上。**点击某个名称，它会保持展开**：输入框会打开，显示你点击的文件夹、其后提供的内容以及你输入的任何内容，并且在指针移开后仍然继续显示。你在滚动这一行或在其中输入时，各名称都会保持不动——如果一个原本用来阅读这一行的手势导致某个名称突然弹开，就会把它后面的所有内容都从你手下移走。

**开头那一段始终带有工具提示，其内容是绝对路径**——比如 `/home/you/Vaults/Notes`，或者这一行开始的任何地方。这是关于这一行、屏幕上任何东西都无法说明的唯一一件事：名称只告诉你*是哪个*仓库，从不说明它在哪里。不论是否有内容被缩短过，它都会一直存在。

关闭**显示仓库名称**后，名称并没有被移除，只是被收缩为零宽——所以指向图标，会像指向一个被这一行缩短过的名称一样，把名称原样还给你。

**显示文件扩展名**会把扩展名重新加回这一行的文件名上。关闭时——默认状态——这一行会按 Obsidian 给笔记命名的方式来命名，不带几乎仓库里每个文件都共有的 `.md`；打开时，它会按文件系统的方式命名，这在仓库里不止有笔记时会很有用。这也是当空间不足时，这一行第二个会被舍弃的内容，紧跟在仓库名称之后。
工具提示会给出其余信息：不只是名称，还有这一行在它之下显示的一切内容，形式如 `…/name/folder/note.md`，这样一次悬停就能同时回答"这是什么"和"它下面还有什么"两个问题。仓库图标在名称被关闭或被压缩掉时，也会用同样的方式命名它所属的仓库。

## 两种警示颜色

| | 情况 | 含义 |
| --- | --- | --- |
| 路径栏上的**红色**光圈 | 这一行指向仓库之外 | Obsidian 无法把那里的内容作为笔记打开，并且在你打开挂锁之前，那里的任何内容都不会被写入。 |
| 路径栏上的**橙色**光圈 | 该文件是 Obsidian 没有视图的文本类型 | 这是一种提醒。Obsidian 原本会把它交给你桌面的默认应用程序打开；而本插件会代为显示它。 |
| 打开的输入框中的**红色**文字 | 该路径下目前还没有任何内容 | 按下 <kbd>Enter</kbd> 会创建它，而不是打开它。与其说这是警告，不如说它在说明下一次按键会做什么——见[输入路径](#输入路径)。 |
| 用来代替重命名开关的**红色**挂锁 | 这一行指向仓库之外，且此处的写入功能仍处于锁定状态 | 与光圈同样的红色，出于同样的原因：它标记的是一次拒绝。按下它就会允许在此处写入，并把这个位置交还给开关——见[写入仓库之外](#写入仓库之外)。 |

**两种光圈是相互独立的，并且可以同时出现**——比如一个外部的 `.json` 文件，既在你的仓库之外，*又*是 Obsidian 没有编辑器的类型。在查看器中，这两点会分别显示为两行，各自只陈述自己那一项事实。在路径栏上，两者都适用时，红色胜出，因为同时显示两个光圈只会造成干扰。红色的*文字*则完全是另一回事：它说的是当前正在输入的内容，而不是这一行指向何处，所以它既可能出现在任意一种光圈内部，也可能哪个光圈都没有。

橙色这一档是故意收得很窄的。已注册的类型（Markdown、白板、图片、PDF、音频、视频）都能被正常处理，不会得到这个标记。二进制文件同样不会得到这个标记——你不会不小心把一个 `.zip` 编辑成一团乱码。剩下的正是真正的风险所在：一个因**显示所有文件类型**而变得可见的 `.json`、`.css` 或 `.log`。下拉列表的判定范围则故意更宽：在那里，任何不是笔记的东西都是橙色——见[列表条目的着色](#列表条目的着色)。

## 重命名/移动模式

表头最右侧的铅笔按钮——就在视图模式按钮旁边，尺寸与原生按钮相同——用于切换重命名/移动模式。在仓库之外，这个位置会显示一把红色挂锁，直到你按下它为止；见[写入仓库之外](#写入仓库之外)。此时表头这一行会用强调色描边，与在文件浏览器中重命名时完全一样。同样的点击和按键操作，现在会通过 Obsidian 的 `fileManager.renameFile` 提交一次移动或重命名，所以指向该笔记的所有链接都会随之更新。

重命名期间：

- 当前的文件名会被固定显示在每个文件夹的下拉列表中，所以在不改名的情况下移动一篇笔记只需一次点击。
- 目标文件夹中已被占用的名称会显示为**红色**——包括已经持有该名称的文件夹，以及同名文件——这样冲突在你做出选择之前就会显示出来。它们仍然可以被选中：见下文。
- 输入内容会实时按照 Obsidian 自身的重命名规则进行校验——相同的字符集、相同的提示信息、以及在文件树中重命名时会得到的同样的红色工具提示——所以非法名称在你输入时就会被标出，且无法被提交。
- 点击表头栏之外，或表头失去焦点，都会结束重命名模式。

### 已被占用的名称

将文件移动或重命名为一个已经存在的名称时，**会询问而不是直接拒绝。**会打开一个对话框，其中有两条可编辑的路径：一条是你的文件将去往何处，另一条是挡路的那个文件将去往何处——在它仍被占用期间显示为红色。每条路径也都按照路径栏绘制路径的方式来绘制，不同的部分会被着色，且最后才会被缩短，所以即使路径很长，也仍能看出发生了什么变化。

两个输入框都各有一个列表。第二个提供的是常见的解决方式：

- **互换位置**——挡路的文件会移动到你的文件原来所在的文件夹，并保留它自己的名称。
- **互换名称**——挡路的文件留在原地，改用你文件原来的名称。
- **互换整体**——挡路的文件会采用你文件原来的完整路径。
- 在其自身名称旁加上 `-1`、`-bak` 或 `-old`。
- 两个文件原本各自的名称。

第一个列表提供的选项包括：你的文件原本要去的位置、**保持原位**、在目标文件夹中使用它自己的名称，以及在旁边加上 `-1`、`-bak` 或 `-old`。任何路径已被占用的解决方式都会显示为灰色，无法选中。选中某一项**只会填入相应的输入框**——你仍然可以编辑它——**应用**会把两个文件都移动到位，包括所有链接；**取消**则什么都不会移动。从下拉列表中选中一个已被占用的名称，也会引发同样的询问，把一篇笔记拖到已经持有其同名文件的文件夹上时，也是一样。

## 一个键管两种重命名

重命名命令（默认是 <kbd>F2</kbd>，或你重新绑定的任何键）在 Obsidian 的内联标题重命名和本插件的路径栏之间**交替切换**。如果你关闭了 Obsidian 的内联标题，路径栏就成了唯一的目标，这个键因此永远不会落空。

在路径栏中，它打开的是**去掉扩展名的名称**——这几乎就是重命名时该编辑的部分，也正是点击名称时所选中的内容。再按一次，它会做<kbd>Tab</kbd>在那里会做的事：在名称上，那就是下一级——带扩展名的名称、从仓库文件夹算起的路径、从系统根目录算起的路径；已经输入了一些内容时，它会像<kbd>Tab</kbd>一样补全。

**循环在这个标题处闭合。** 按五次就转完一圈——内联标题、名称、带扩展名的名称、从仓库算起的路径、从系统根目录算起的路径——第六次又回到内联标题。这一次按键是唯一和<kbd>Tab</kbd>不同的地方，<kbd>Tab</kbd>会绕回路径的最前端；而第七次去的地方，正是<kbd>Tab</kbd>绕回后会去的地方：仓库根目录，输入框里是完整路径，第一个文件夹被选中。所以<kbd>Tab</kbd>能到达的每一步，这个键也都能到达。

**聚焦路径栏**命令在输入框内部做的是同一件事——<kbd>Tab</kbd>会做的事它都会做——而在<kbd>Tab</kbd>本该绕回的地方，它则会把光标交还给笔记。它的下一次按下才是那次绕回：仓库根目录，第一个文件夹被选中。

**在已经打开的输入框里**，这个键会把它原地变成重命名——保留文本、光标和选区——而**聚焦路径栏**则用同样的方式把重命名状态撤掉。在两次按键之间**按下或点击任何其他内容**都会让各自的循环重新开始，所以编辑过后的一次按键绝不会落在之前留下的某一级上。

在仓库之外这个键同样有效——那里没有内联标题，所以第一次按下会直接进入路径栏。

这是通过包装 `workspace:edit-file-title` 命令实现的，而不是去抢按键，因此重新绑定快捷键和从命令面板执行命令都照常有效。

## 列表条目的着色

| 颜色 | 含义 |
| --- | --- |
| **紫色** | 笔记（`.md`、`.markdown`）——Obsidian 会作为笔记打开的文件，从内容混杂的文件夹中挑出来的 |
| **橙色** | 不是笔记——任何 Obsidian 不会作为笔记打开的东西，从 PDF 到 `.txt`，以及与之相伴的 `:page` 条目。内容混杂的文件夹会被读取其中的笔记，而给其余所有内容统一用一种颜色，比只在少数几项上标出警示更直观；参见[警示颜色](#两种警示颜色) |
| **暗淡色** | 在仓库之外，因此仓库自身的处理方式不适用 |
| **蓝色**，加粗 | 你当前所在之处：这条路径栏对应的笔记，以及路径栏正停留的文件夹。在重命名/移动模式下，*保留此名称*这一条目占据了笔记原本的位置——无论哪种情况都是同一份笔记 |
| **红色** | 仅限重命名/移动模式：名称已被占用。仍可选中——选中它会询问该如何处理挡路的那个文件；参见[已被占用的名称](#已被占用的名称) |

**文件夹以粗体显示**，因此文件夹自身的笔记不需要专属颜色就能与其文件夹区分开：它和其他笔记一样是紫色的。**行边缘的一条竖线**标出与你所输入内容相符开头的名称：在进一步一致的地方为蓝色，在候选项所走的分支上为绿色；参见[输入路径](#输入路径)。

输入框对其所指的内容采用相同的着色方式——参见[输入路径](#输入路径)。

## 可见性规则

- 不受支持的扩展名的文件只有在 Obsidian 的**检测所有文件扩展名**设置开启时才会出现在列表中——**且仅限仓库内部**。在仓库外这条设置不适用：它控制的是仓库索引哪些内容，而外面的一切都不在仓库中，所以你笔记旁边的 `.txt` 无论如何都会被列出。
- 列表最多显示 1000 条，是 Obsidian 自身上限的十倍。当一个文件夹条目更多时，最后一行会说明省略了多少条；继续输入以缩小列表范围。
- 只有本插件的**显示点文件**设置开启时，点文件和点文件夹才会出现。
- **无论可见性如何，覆盖保护的效果都相同**——隐藏的文件同样会阻止你覆盖它。

## 速查表

**用引号括起来**的路径会为你自动去掉引号。Windows 的*复制为路径*给出的是 `"C:\Users\you\note.md"`，包含引号；而 shell 对带空格的路径也会这样处理；粘贴或直接输入都同样有效。只有双引号，且只在整体两端成对出现时才会被去掉——它不可能出现在真实的名称中，而撇号则完全可能。

| 你想要… | 这样做 |
| --- | --- |
| 打开一个文件夹（其笔记，或在文件管理器中显示） | 点击该文件夹**之后**的分隔符 |
| 给一个还没有文件夹笔记的文件夹创建一个 | **双击**同一个分隔符（需要文件夹笔记插件） |
| 把某个文件夹换成同级的另一个 | 点击该文件夹的名称，然后输入或选择 |
| 重命名或重定向笔记 | 点击笔记的名称——包括扩展名 |
| 浏览某个文件夹的内容 | 点击该文件夹的名称；列表显示的是它的父级内容，所以要点击你想要的文件夹**下面**的那一个 |
| 重新输入某个文件夹及其下所有内容 | **双击**该文件夹的名称，然后输入 |
| 从某个文件夹往下编辑路径 | 点击该文件夹的名称，再按<kbd>→</kbd>取消选中 |

## 设置

| 设置 | 选项 | 默认值 | 作用 |
| --- | --- | --- | --- |
| **语言** | Obsidian 默认，或 46 种语言中的任意一种 | Obsidian 默认 | 本插件自身文本所使用的语言。*Obsidian 默认*跟随外观设置中设定的语言，这也是几乎所有人想要的效果。这一行本身——它的名称、说明以及*Obsidian 默认*——无论选了哪种语言都保持英文，因为它是从一门你看不懂的语言里退出来的途径。希腊语和梵语在这里有翻译，却不在 Obsidian 自身的列表中，所以这项设置是到达它们的唯一途径。 |
| **对齐方式** | 左对齐 / 居中 / 右对齐 | 左对齐 | 路径栏在标题行中的位置。*居中*匹配 Obsidian 的经典外观。 |
| **分隔符** | 任意字符 | `/` | 在各段之间绘制的分隔符。文本输入框前有六个一键预设（`/ > ▸ › \ •`）。 |
| **显示仓库名称** | 开 / 关 | 开 | 仓库本身是否作为路径栏的第一段。关闭后，该段不会消失，而是变成一个 🏠 图标，让路径仍有一个可点击的起点。 |
| **文件夹名打开列表** | 开 / 关 | 开 | 交换文件夹名和其后分隔符的作用——参见[上表](#路径栏)。搭配[文件夹笔记](obsidian://show-plugin?id=folder-notes)使用时，分隔符会打开文件夹笔记。在重命名/移动模式下永不生效。 |
| **显示点文件** | 开 / 关 | 关 | 点文件和点文件夹是否会列在列表中。覆盖保护无论如何都会生效。 |
| **显示所有文件类型** | — | — | 并非本插件的设置，而是 Obsidian 的，之所以在此提及是因为它回答的是同一个问题：你的仓库只索引被告知要索引的文件类型，而只有被索引的内容才能被列出。到 Obsidian 的设置中找到它并开启，即可看到所有文件；此行旁边的按钮会打开该设置页面，并把这项设置滚动到可见位置并高亮闪烁，效果如同在设置自身的搜索框中点击它一样。在仓库之外它不适用，因为外面的任何内容本来就不会被索引。 |
| **显示文件扩展名** | 开 / 关 | 关 | 行中文件的名称是否带有扩展名。关闭时会省略——就像 Obsidian 在笔记标题上省略它一样。开启时，行中会按文件系统的方式命名文件。无论哪种情况，当行的空间不够时，扩展名都是继仓库名称之后第二个被省略的部分。 |
| **访问外部文件** | 开 / 关 | **关** | 仓库名称是否会打开位置列表。关闭时，本插件永远不会窥探此仓库之外的内容。 |
| **快捷键** | 按钮 | — | 打开 Obsidian 的*快捷键*页面并筛选出本插件，可在此为*聚焦路径栏*设置按键。 |

## 替换图标

Lure 会渲染三个图标：仓库根目录图标（当**显示仓库名称**关闭时）、重命名/移动切换按钮，以及在锁定写入仓库之外时占据其位置的挂锁。这些图标都可以通过主题或 CSS 代码片段替换——只需一条规则，设置替换字形并隐藏内置图标：

```css
.lure-vault-icon {
	--lure-icon-glyph: "🏠";
	--lure-icon-svg: none;
}

.lure-rename-btn {
	--lure-icon-glyph: "✎";
	--lure-icon-svg: none;
}

/* Only ever shown shut: opening it hands the slot to the rename toggle. */
.lure-unlock-btn {
	--lure-icon-glyph: "🔒";
	--lure-icon-svg: none;
}
```

`--lure-icon-glyph` 接受任何在 CSS `content` 中合法的值，因此 `url(...)` 可用于图片，正如文本或表情字形一样。若想保留 Lucide 图标并把你的字形画在它旁边，就别动 `--lure-icon-svg`。
