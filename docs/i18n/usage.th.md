## เส้นทางในแถบหัวเรื่อง

เส้นทางเต็มของโน้ตภายในห้องนิรภัยเข้าแทนที่ชื่อไฟล์เปล่า ๆ ในแถบหัวเรื่องของมุมมอง — แถวใต้แถวแท็บ ซึ่งเป็นแถวเดียวกับที่มีปุ่มย้อนกลับ/ไปข้างหน้า

มีสองสิ่งบนแถวนี้ที่คลิกได้ และ **ชื่อโฟลเดอร์เปิดรายการ** เป็นตัวกำหนดว่าอะไรทำอะไร:

| | ชื่อโฟลเดอร์ | ตัวคั่นที่ตามหลัง |
| --- | --- | --- |
| **เปิด** (ค่าเริ่มต้น) | เลือกโฟลเดอร์นั้นเพื่อแก้ไข | เปิดโฟลเดอร์ |
| **ปิด** | เปิดโฟลเดอร์ | ลงไปในโฟลเดอร์นั้น |

“เปิดโฟลเดอร์” หมายถึงสิ่งที่การคลิกส่วนนั้นทำใน Obsidian ล้วน ๆ หากไม่มีปลั๊กอินคอยดักฟังอยู่ตรงนั้น โฟลเดอร์จะถูกแสดงในแถบข้าง File explorer — ถูกไฮไลต์และกางออกเพื่อให้เห็นสิ่งที่อยู่ข้างใน

ในกรณีที่โน้ตของโฟลเดอร์นั้นคือโน้ตที่คุณกำลังอ่านอยู่แล้ว การคลิกจะแสดงโฟลเดอร์แทน — ไม่มีอะไรให้เปิดที่ยังไม่อยู่บนหน้าจอแล้ว ซึ่งเป็นความหมายที่การกดครั้งที่สองมีมาโดยตลอด

เมื่อติดตั้ง [Folder notes](obsidian://show-plugin?id=folder-notes) การคลิกเดียวกันจะเปิดโน้ตของโฟลเดอร์นั้นแทน **ในทุกความลึก**: โน้ตถูกหาคำตอบที่นี่ตามธรรมเนียมของปลั๊กอินนั้นเอง แทนที่จะปล่อยให้ปลั๊กอินนั้นเป็นผู้ตอบ ปลั๊กอินนั้นรู้จักเฉพาะโฟลเดอร์ที่ตัวมันทำเครื่องหมายไว้ ซึ่งบนเส้นทางที่ลึกกว่าหนึ่งชั้นจะไม่มีโฟลเดอร์ใดถูกทำเครื่องหมายเลย ดังนั้นการกดที่เคยเปิดโน้ตของโฟลเดอร์ระดับบนสุดจึงไม่ทำอะไรต่อในชั้นที่ลึกลงไป ปลั๊กอินโน้ตโฟลเดอร์อีกสองตัวไม่ได้เผยแพร่ธรรมเนียมใด ๆ ให้อ่าน และไม่เคยอ้างสิทธิ์แถวนี้ ดังนั้นกับปลั๊กอินเหล่านั้นตัวคั่นจะแสดงโฟลเดอร์เหมือนเดิม มีปลั๊กอินโน้ตโฟลเดอร์เพียงตัวเดียวที่พบว่าอ้างสิทธิ์เส้นทางในแถบหัวเรื่อง; [Folder Note](obsidian://show-plugin?id=folder-note-plugin) และ [create folder notes with dropdown](obsidian://show-plugin?id=create-folder-notes-with-dropdown) จัดการโน้ตโฟลเดอร์แต่ไม่ได้ดักฟังการคลิกบนเส้นทางในแถบหัวเรื่อง ดังนั้นกับปลั๊กอินเหล่านั้นตัวคั่นจะแสดงโฟลเดอร์ตามปกติ ดู [ความเข้ากันได้](../compatibility.md#verified-against)

ตัวคั่นจะ**ถูกขีดเส้นใต้ก็ต่อเมื่อโฟลเดอร์ก่อนหน้ามันมีโน้ตโฟลเดอร์จริง ๆ** ดังนั้นเส้นใต้จึงเป็นคำมั่นว่ามีบางอย่างให้เปิด — ในทุกความลึกเมื่อ [Folder notes](obsidian://show-plugin?id=folder-notes) ทำงานอยู่ เพราะโน้ตถูกหาคำตอบที่นี่แทนที่จะปล่อยให้ปลั๊กอินนั้นเป็นผู้ทำเครื่องหมาย ในกรณีที่ไม่ใช่ปลั๊กอินนั้นทำงานอยู่ จะไม่มีการขีดเส้นใต้และไม่มีอะไรเปิดขึ้น: ตัวคั่นจะแสดงโฟลเดอร์ เช่นเดียวกับตอนที่ไม่มีปลั๊กอินโน้ตโฟลเดอร์เลย ตัวคั่นทุกตัวยังคงคลิกได้ไม่ว่ากรณีใด — ตัวที่ไม่มีเส้นใต้จะแสดงและกางโฟลเดอร์ของมันในแถบข้าง ซึ่งเคอร์เซอร์รูปตัวชี้ยังคงบอกไว้ เส้นใต้จะย้ายออกจากชื่อโฟลเดอร์ในเวลาเดียวกัน: เมื่อเปิดการสลับไว้ ชื่อจะเปิดรายการ ดังนั้นการทำเครื่องหมายมันว่าเป็นลิงก์ไปยังโน้ตจะเป็นการโกหก

**โหมดเปลี่ยนชื่อ/ย้ายมีผลเหนือทั้งสองอย่าง** ไม่ว่าการตั้งค่าจะบอกอย่างไร: ไม่มีอะไรบนแถวนี้เปิดโฟลเดอร์ขณะที่การย้ายยังค้างอยู่ เพราะการเปิดจะเป็นการละทิ้งการย้าย ชื่อโฟลเดอร์จะถูกเลือกเพื่อแก้ไข ส่วนตัวคั่นจะลงไปข้างใน — ทั้งสองเป็นวิธีเลือกปลายทาง — และเส้นใต้จะหายไปเพื่อแสดงว่าการเปิดถูกระงับไว้

**รากของห้องนิรภัย** เป็นส่วนเดียวที่ไม่ใช่ส่วนของเส้นทาง มันไม่มีแม่ให้ไล่รายชื่อพี่น้อง จึงเปิด [รายการตำแหน่ง](#การเรียกดูนอกห้องนิรภัย) แทน — ห้องนิรภัยอื่น ๆ ของคุณ โฟลเดอร์ส่วนตัว รากของระบบไฟล์ และไดรฟ์ที่เมานต์ไว้

## ตัวคั่นเฉพาะของห้องนิรภัย

ตัวคั่นที่อยู่ทันทีหลังชื่อห้องนิรภัยแทนตัวห้องนิรภัยเอง ไม่ใช่แทนโฟลเดอร์ จึงทำในสิ่งที่ตัวคั่นอื่นทำไม่ได้:

| | คลิกครั้งแรก | คลิกครั้งถัดไป |
| --- | --- | --- |
| **เมื่อมีปลั๊กอินหน้าเริ่มต้น** (หน้าที่ต้อนรับคุณตอนเปิด Obsidian) | เปิดหน้านั้นในบานหน้าต่างนี้ | พับต้นไม้ไฟล์เก็บ |
| **เมื่อไม่มี** | พับต้นไม้ไฟล์เก็บ | คืนสิ่งที่เปิดอยู่เดิมกลับมาทุกอย่าง |

เป็นการคลิกธรรมดา ไม่ใช่การดับเบิลคลิก: เมื่อหน้าเปิดแล้ว ตัวคั่นก็ไม่มีอะไรเหลือให้เปิดอีก ดังนั้นการกดครั้งถัดไปจึงเป็นการพับ — ไม่ว่าคุณจะใช้เวลานานแค่ไหนกว่าจะกด

มันจะ**ถูกขีดเส้นใต้**เมื่อมีหน้าเริ่มต้นให้เปิด ซึ่งเป็นคำมั่นแบบเดียวกับที่ตัวคั่นของโฟลเดอร์ให้ไว้: มีบางอย่างอยู่ตรงนั้น การพับเป็นการสลับเปิด-ปิด — การกดครั้งถัดไปจะคืนโฟลเดอร์ที่เคยเปิดอยู่กลับมา และเฉพาะโฟลเดอร์เหล่านั้นเท่านั้น ดังนั้นต้นไม้ที่คุณจัดไว้จะไม่หายไปเพียงเพราะแวบไปดูอย่างอื่น

## บานหน้าต่างที่ไม่มีไฟล์

แท็บว่าง กราฟ และสิ่งอื่นใดที่ไม่มีชื่อไฟล์จะได้แถวของตัวเอง: ห้องนิรภัย ตามด้วยส่วนหนึ่งที่บอกว่าบานหน้าต่างนี้กำลังแสดงอะไรอยู่

```
my-vault / :blank      a new tab
my-vault / :graph      the graph, local or global
my-vault / :<type>     anything else with no file
```

**รายชื่อของรากห้องนิรภัยเอง** ก็เสนอหน้าเหล่านี้ด้วย ควบคู่ไปกับโฟลเดอร์และโน้ตที่มีอยู่จริงในนั้น: เลือก `:graph` หรือ `:search` ที่นั่น บานหน้าต่างจะเปิดมุมมองนั้น เหมือนกับการเลือกโน้ตแล้วเปิดโน้ต หน้าใดมีอยู่บ้างจะถูกอ่านจาก Obsidian แทนที่จะเขียนไว้ตายตัวที่นี่ — ทุกมุมมองที่ไม่ได้มีไว้แสดงไฟล์ ดังนั้นปลั๊กอินที่ลงทะเบียนมุมมองหนึ่งไว้ (แท็บหน้าแรก ปฏิทิน) จะปรากฏขึ้นโดยที่ปลั๊กอินนี้ไม่รู้อะไรเกี่ยวกับมันเลย มุมมองที่ต้องมีไฟล์ — Markdown, PDF, รูปภาพ, แคนวาส, เบส — จะไม่ถูกเสนอ: เพราะไม่มีอะไรให้พวกมันแสดง

เครื่องหมายโคลอนคือประเด็นสำคัญ — ไม่มีไฟล์หรือโฟลเดอร์ใดถูกเรียกว่า `:graph` ได้ ดังนั้นแถวนี้จะไม่ถูกเข้าใจผิดว่าเป็นเส้นทางที่เปิดได้ ป้ายชื่อมาจากประเภทของมุมมองแทนที่จะมาจากถ้อยคำของ Obsidian เอง จึงอ่านเหมือนเดิมไม่ว่าภาษาส่วนติดต่อจะเป็นภาษาใด และคำว่า `-view` ที่ต่อท้ายจะถูกตัดออก: ปลั๊กอินแท็บหน้าแรกลงทะเบียนมุมมองของตัวเองเป็น `home-launcher-view` และแถวนี้จะแสดงเป็น `:home-launcher`

การคลิกพื้นที่ว่าง หรือป้ายชื่อเอง **จะเปิดช่องที่รากของห้องนิรภัย**: พิมพ์เส้นทางแล้วกด <kbd>Enter</kbd> เพื่อเปิดมันในบานหน้าต่างเดียวกันนี้ ด้วยการเติมข้อความอัตโนมัติแบบเดียวกัน รายการแบบเดียวกัน และช่องสีแดงแบบเดียวกันที่เสนอให้สร้างสิ่งที่ยังไม่มีอยู่ แท็บว่างเป็นที่ที่เหมาะสำหรับพิมพ์บอกว่าคุณอยากไปที่ไหน ซึ่งนั่นคือสิ่งที่มันมีไว้ทำ

ป้ายชื่อก็เป็นเพียงป้ายชื่อ ไม่มีอะไรมากไปกว่านั้น: ไม่มีรายการ ไม่มีการลาก ไม่มีการเปลี่ยนชื่อ บานหน้าต่างในแถบข้างจะถูกปล่อยไว้ตามเดิมทั้งหมด — บานหน้าต่างลิงก์ย้อนกลับยังคงใช้ชื่อที่ Obsidian ตั้งให้

แคนวาส, PDF, รูปภาพ และเบสไม่ต้องการสิ่งเหล่านี้เลย เพราะเป็นไฟล์ จึงได้แถบเส้นทางแบบธรรมดา

## คลิกที่ส่วนหนึ่ง: สลับกับพี่น้อง

การคลิกชื่อโฟลเดอร์จะเลือก**ชื่อของโฟลเดอร์นั้น**ในช่องข้อความ และเปิดรายการของโฟลเดอร์**ที่สูงขึ้นไปหนึ่งชั้น** — โฟลเดอร์แม่ การพิมพ์หรือเลือกรายการจะสลับโฟลเดอร์นี้กับพี่น้อง และปล่อยทุกอย่างใต้มันไว้เหมือนเดิม ดังนั้น `Projects/2026/Kickoff.md` → คลิก `2026` → เลือก `2025` จะได้ `Projects/2025/Kickoff.md`

การคลิก**ชื่อของโน้ต**ทำงานแบบเดียวกันกับโฟลเดอร์ของมันเอง และเลือกชื่อ**โดยไม่รวมนามสกุล** — การเปลี่ยนชื่อเป็นการแก้ไขที่พบบ่อย และการพิมพ์ทับการเลือกที่รวม `.md` ไว้ด้วยเคยทำให้ประเภทไฟล์เปลี่ยนไปโดยไม่ตั้งใจ นามสกุลยังคงมองเห็นได้ห่างออกไปแค่การกดหนึ่งครั้ง: <kbd>→</kbd> จะไปถึงมัน และการดับเบิลคลิกที่ขยายไปทั้งแถวจะเอาไปทั้งหมด

การคลิกโฟลเดอร์ได้เลือกส่วนหนึ่งไปแล้ว ดังนั้น**การคลิกอีกครั้ง**จะขยายการเลือกเป็นทั้งบรรทัด — โฟลเดอร์นั้น*และ*ทุกอย่างใต้มัน — แล้วการพิมพ์จะแทนที่ส่วนที่เหลือของเส้นทางในคราวเดียว ทำงานเหมือนกันทั้งในโหมดนำทางและโหมดเปลี่ยนชื่อ/ย้าย

สิ่งนี้ใช้ได้เฉพาะในฐานะความต่อเนื่องของการคลิกที่เปิดช่องขึ้นมาเท่านั้น เมื่อคุณใช้ช่องนั้นแล้ว มันจะทำตัวเหมือนช่องข้อความอื่น ๆ: คลิกวางเคอร์เซอร์ ดับเบิลคลิกเลือกหนึ่งคำ คลิกสามครั้งเลือกทั้งบรรทัด

ไม่ว่ากรณีใด ส่วนที่เหลือของเส้นทางจะยังคงมองเห็นได้รอบ ๆ ช่อง เป็นชิปอยู่ก่อนหน้าและเป็นข้อความที่ไม่ถูกเลือกอยู่ข้างหลัง เส้นทางเต็มจึงไม่เคยหายไปจากแถวหัวเรื่อง พิมพ์เพื่อแทนที่ส่วนที่เลือก หรือกด <kbd>→</kbd> เพื่อเก็บมันไว้แล้วแก้ไขต่อจากตรงนั้น รายการจะแสดงทั้งโฟลเดอร์ไม่ว่าจะมีอะไรเติมไว้ล่วงหน้า มันจะเริ่มกรองก็ต่อเมื่อคุณเริ่มพิมพ์จริง ๆ เท่านั้น

## การลงไปด้วยตัวคั่น

การคลิกตัวคั่น (เมื่อ **ชื่อโฟลเดอร์เปิดรายการ** ปิดอยู่) จะลงไปในโฟลเดอร์ก่อนหน้ามัน: รายการจะแสดงสิ่งที่อยู่ใน*โฟลเดอร์นั้น* และส่วนที่เหลือของเส้นทางจะเปิดขึ้นในช่องโดยถูกเลือกไว้ การเลือกโฟลเดอร์จะต่อมันเข้ากับรอยเส้นทางและเปิดรายการถัดไปทันที คุณจึงคลิกไล่ลงไปตามต้นไม้ได้โดยไม่ต้องออกจากแถวหัวเรื่อง

## รายการเปิดตรงตำแหน่งที่คุณอยู่

ลิสต์จะเปิดที่รายการซึ่งคุณกำลังยืนอยู่ — โน้ตที่แถบนี้เป็นของมัน หรือเมื่อการคลิกโฟลเดอร์ได้แสดงรายชื่อของโฟลเดอร์แม่ ก็คือโฟลเดอร์นั้น — แทนที่จะเป็นแถวแรก ในโฟลเดอร์ที่มีสองร้อยโน้ต แถวแรกอยู่ไกลจากคุณมาก

**การหมุนล้อเมาส์เหนือชื่อจะเปิดลิสต์ของมันและไล่ดูไปตามนั้น** การหมุนครั้งแรกจะเปิดลิสต์เดียวกันกับที่กดชื่อจะเปิด และการหมุนทุกครั้งหลังจากนั้นจะเลื่อนไฮไลต์ไปหนึ่งแถว โดยใส่สิ่งที่คุณชี้อยู่ลงในช่องเหมือนกับการกดปุ่มลูกศร — ดังนั้นพี่น้องคนหนึ่งจึงหาเจอและเลือกได้โดยไม่ต้องใช้คีย์บอร์ด การหมุนออกที่ปลายด้านใดด้านหนึ่งจะคืนข้อความของคุณกลับมา แถวที่มีเส้นทางยาวกว่าบานหน้าต่างจะตอบสนองต่อการหมุนล้อด้วยการเลื่อนไปด้านข้างแทน ซึ่งเป็นการอ่านที่ชนะตราบเท่าที่ยังใช้ได้

ลิสต์จะ**สูงเท่าที่หน้าต่างจะยอมให้เป็น** Obsidian จำกัดลิสต์คำแนะนำของตัวเองไว้ที่ 300 พิกเซลไม่ว่าจะมีอะไรอยู่ข้างล่าง ส่วนลิสต์นี้จะยาวไปจนถึงขอบล่างของหน้าต่าง หยุดห่างจากขอบไม่กี่พิกเซล และจะเลื่อนก็ต่อเมื่อโฟลเดอร์มีมากกว่านั้น มัน**ไม่กว้างไปกว่าแถบเส้นทาง**: ชื่อที่ไม่พอดีจะถูกย่อแบบเดียวกับที่แถวย่อชื่อ และแสดงเต็มเมื่อคุณชี้ไปที่มัน

การเลื่อนผ่านลิสต์**จะใส่สิ่งที่คุณชี้อยู่ลงในช่อง** ไม่ว่าจะด้วยปุ่มลูกศรหรือการวางเมาส์ไว้เหนือ — แทนที่ส่วนที่คุณกำลังแก้ไขอยู่ โดยส่วนที่เหลือของเส้นทางยังคงอยู่เหมือนเดิม — ดังนั้นแถวที่คุณอยู่ก็คือเส้นทางที่คุณจะได้ด้วย

ส่วนที่เหลือของเส้นทางจะแสดง**เท่าที่มันมีอยู่จริงภายใต้สิ่งที่คุณกำลังชี้อยู่เท่านั้น** เมื่อยืนอยู่ในโฟลเดอร์หนึ่งโดยมี `2026/note.md` อยู่หลังส่วนที่คุณกำลังแก้ไข การชี้ไปที่โฟลเดอร์ที่มี `2026` ซึ่งมี `note.md` อยู่ข้างในจะแสดงทั้งหมด ส่วนโฟลเดอร์ที่มี `2026` แต่ไม่มีโน้ตจะแสดงแค่ `2026` และโฟลเดอร์ที่ไม่มีทั้งสองอย่างจะไม่แสดงอะไรเลยหลังชื่อ ไฟล์ก็เช่นกัน เพราะไม่มีอะไรอยู่ใต้ไฟล์ สิ่งที่**คุณพิมพ์เอง**จะคงเส้นทางทั้งหมดไว้ขณะที่คุณกำลังพิมพ์อยู่ ไม่ว่าจะพิมพ์ไปน้อยแค่ไหนแล้วก็ตาม — ชื่อที่พิมพ์ครึ่ง ๆ กลาง ๆ ยังไม่ใช่การตัดสินใจ การตั้งชื่อลงไปคือการตัดสินใจ และสิ่งที่ไปไม่ถึงจากชื่อนั้นจะถูกตัดออกตรงจุดนั้น โฟลเดอร์ที่คุณกำลังสร้างคือโฟลเดอร์ที่คุณพิมพ์*ต่อจาก*มัน ซึ่งเป็นจุดที่ <kbd>Enter</kbd> จะสร้างมันขึ้นมา ข้อความที่คุณพิมพ์ไว้จะถูกเก็บไว้: การเลื่อน**ออกจากปลายด้านใดด้านหนึ่งของลิสต์** — ขึ้นออกจากรายการแรก หรือลงออกจากรายการสุดท้าย — จะปล่อยมันไปและคืนข้อความของคุณกลับมา โดยไม่มีอะไรถูกไฮไลต์ ช่องนี้เป็นจุดหยุดหนึ่งบนวงแหวนเหมือนกับรายการใด ๆ ดังนั้นการวนรอบจะผ่านมันแทนที่จะกระโดดจากแถวสุดท้ายไปแถวแรก และการกดต่อจากตรงนั้นจะวนไปยังปลายอีกด้านหนึ่ง

การเอา**เมาส์ออกจากลิสต์**ก็คืนข้อความของคุณกลับมาเช่นกัน — และคืนไฮไลต์ให้กับสิ่งที่มีมันอยู่ก่อนที่เมาส์จะมาถึง: รายการที่คุณเคยกดลูกศรไปถึง ซึ่งจะแสดงในช่องอีกครั้ง หรือรายการที่ลิสต์เปิดขึ้นมาเพราะเป็นตำแหน่งที่คุณอยู่ การวางเมาส์ไว้เหนือเป็นวิธีการมองมากกว่าการเลือก ดังนั้นการกวาดเมาส์ผ่านลิสต์จึงไม่ทำให้คุณเสียอะไรเลย

ตัวลิสต์เองจะไม่เปลี่ยนแปลงขณะที่คุณเลื่อนผ่านมัน — มันยังคงกรองตามสิ่งที่คุณพิมพ์ ไม่ใช่ตามสิ่งที่ถูกแสดงตัวอย่างลงในช่อง — ดังนั้นรายการที่อยู่ใต้คุณจะไม่เปลี่ยนไปก่อนการกดครั้งถัดไป การพิมพ์จะแทนที่ตัวอย่างและกรองตามปกติ

**สิ่งที่มันใช้กรองคือส่วนที่คุณกำลังแก้ไข** ไม่ใช่ทุกอย่างในช่อง การคลิกโฟลเดอร์จะปล่อยส่วนที่เหลือของเส้นทางไว้ข้างหลังชื่อที่คุณกำลังเปลี่ยน ดังนั้นการกรองด้วยทั้งหมดจะเป็นการหาโฟลเดอร์ลูกที่ชื่อ `2026/Kickoff.md` และไม่พบอะไรเลย — ลิสต์จะปิดตัวลงตั้งแต่การกดปุ่มแรกไม่ว่าคุณจะพิมพ์อะไรก็ตาม **นามสกุลก็ถูกตัดออกเช่นกัน** ตราบเท่าที่เคอร์เซอร์ยังอยู่หน้าจุด: การคลิกชื่อโน้ตจะเลือกส่วนหลักและปล่อย `.md` ไว้ข้างหลัง ดังนั้นการพิมพ์ตัวอักษรหนึ่งตัวจะทำให้ช่องอ่านว่า `a.md` ซึ่งไม่ใช่สิ่งที่คุณกำลังหา วางเคอร์เซอร์ไว้หลังจุด แล้วนามสกุลจะถูกนับเหมือนสิ่งอื่น ๆ ชื่อที่ไม่ตรงกับอะไรเลยจริง ๆ ก็ยังคงปิดลิสต์ เพราะลิสต์ว่างเปล่าคือคำตอบที่ตรงไปตรงมา

ตัวอย่างจะ**สลับเฉพาะส่วนนั้นและปล่อยส่วนที่เหลือของเส้นทางไว้เหมือนเดิม**: การชี้ไปที่โฟลเดอร์เป็นการถามว่าถ้าขั้นนี้เป็นขั้นนั้นแทนล่ะ ไม่ใช่การทิ้งเส้นทางไปทั้งหมด การเลื่อนออกจากลิสต์จะคืนทั้งข้อความ*และ*การเลือกที่คุณมีอยู่ ดังนั้นการกดปุ่มครั้งถัดไปจะแทนที่สิ่งที่มันกำลังจะแทนที่ก่อนที่คุณจะมอง

## รายการในลิสต์คือแถวของตัวจัดการไฟล์จริง ๆ

ทุกไฟล์และทุกโฟลเดอร์ในรายการทำตัวเหมือนแถวของมันใน File explorer:

- **คลิกขวา** เพื่อเรียกเมนูบริบทเดียวกับที่ File explorer ให้ ครบทุกรายการ — รวมถึงรายการที่ปลั๊กอินอื่นเพิ่มเข้ามาด้วย โฟลเดอร์จะเสนอ *สร้างโน้ตใหม่*, *สร้างโฟลเดอร์ใหม่*, *สร้างแคนวาสใหม่*, *สร้างเบสใหม่*, *ทำสำเนา*, *ย้ายโฟลเดอร์ไปที่…*, *ค้นหาในโฟลเดอร์*, *คัดลอกเส้นทาง*, *แสดงในตัวจัดการระบบ*, *เปลี่ยนชื่อ…* และ *ลบ*; ไฟล์จะเสนอสิ่งที่เทียบเท่าของตัวเอง รวมถึง *เปิดด้วยแอปเริ่มต้น*
- **ลาก**รายการไปยังที่ใดก็ตามที่ Obsidian ยอมรับไฟล์: ลากลงในตัวแก้ไขเพื่อแทรกลิงก์ ลากไปยังโฟลเดอร์ใน File explorer เพื่อย้ายมัน ลากไปยังแถบแท็บเพื่อเปิดมัน

ถ้อยคำของเมนูมาจากคำแปลของ Obsidian เอง จึงเข้ากันกับส่วนอื่นของแอปในทุกภาษา

## การพิมพ์เส้นทาง

- การคลิก**พื้นที่ว่าง**ก่อนหรือหลังเส้นทางในแถบหัวเรื่อง เปิดช่องพิมพ์ข้อความบนเส้นทางทั้งหมด *และแสดงโน้ตนั้นในตัวจัดการไฟล์* ต้นไม้ไฟล์จึงตามแถบเนื้อหาไปโดยไม่ต้องออกท่าทางที่สอง ระบบจะ**นับจำนวนครั้งที่คุณกด**: หนึ่งครั้งเลือกเส้นทางโดยไม่รวมนามสกุล สองครั้งเลือกพร้อมนามสกุล สามครั้งเลือกเส้นทางแบบที่เครื่องรู้จัก การคลิกที่**ชื่อไฟล์**นับแบบเดียวกันแต่เริ่มต้นต่ำลงมาหนึ่งขั้น ที่ตัวชื่อเอง: หนึ่งครั้งเลือกโดยไม่รวมนามสกุล สองครั้งรวม และสามครั้งขยายไปยังเส้นทางทั้งหมด *นับจากโฟลเดอร์ห้องนิรภัยของคุณ* — รูปแบบที่ลิงก์หรือการค้นหาต้องการ ไม่ใช่แบบของเครื่อง การกดครั้งที่สี่จึงจะไปถึงแบบนั้น
- **การนับเป็นของช่วงที่เปิดช่องนี้ขึ้นมา** เมื่อช่วงนั้นหมดลง — คุณหยุดพัก พิมพ์ หรือคลิกครั้งเดียวที่ไหนสักแห่งในข้อความ — ช่องนี้ก็เป็นช่องข้อความธรรมดาเหมือนช่องอื่น ๆ และการดับเบิลคลิกในช่องจะเลือกคำที่อยู่ใต้ตัวชี้เหมือนที่อื่น ๆ พิมพ์ทับสิ่งที่ถูกเลือกไว้ หรือแก้ไขตรงจุดนั้นได้เลย (การคลิกที่ชื่อไฟล์เองจะเลือกเฉพาะชื่อไฟล์ ดูด้านบน) การคลิกขวาที่พื้นที่เดียวกัน**คัดลอก**สามแบบเดียวกันนี้ ที่การกดสอง สาม และสี่ครั้ง — ปุ่มหนึ่งแสดงมัน อีกปุ่มหนึ่งนำมันไป การกดขวา**ครั้งเดียว**เปิดเส้นทางโดยเลือกทั้งหมด และเสนอสิ่งที่ทำกับมันได้: ตัด คัดลอก วาง เลือกทั้งหมด ตามคำของ Obsidian เอง
- **คลิกกลางที่พื้นที่ว่าง**เพื่อวางทับเส้นทาง: ช่องจะเปิดขึ้นบนเส้นทางทั้งหมด *นับจากรากห้องนิรภัย* คลิปบอร์ดจึงแทนที่ทั้งหมด และสิ่งที่วางลงไปจะถูกเลือกไว้ จากนั้น <kbd>Enter</kbd> จะไปที่นั่น
- **<kbd>Ctrl</kbd>+คลิกที่พื้นที่ว่าง**เพื่อเปิดโน้ตนี้อีกครั้งในแท็บของตัวเอง โดยกะพริบในตัวจัดการไฟล์เพื่อไม่ให้แท็บที่สองถูกเข้าใจผิดว่าเป็นแท็บแรก ที่**ชื่อห้องนิรภัย** <kbd>Ctrl</kbd>+คลิกหรือคลิกกลางจะเปิดแท็บที่ไม่มีอะไรอยู่ ยืนอยู่ที่รากห้องนิรภัยโดยลิสต์แสดงอยู่แล้ว — ที่ที่จะพิมพ์เส้นทางขึ้นมาใหม่ตั้งแต่ต้น
- การพิมพ์ขณะที่เส้นทางในแถบหัวเรื่องกำลังแสดงอยู่ จะแปลงส่วนท้ายให้กลายเป็นช่องพิมพ์เล็ก ๆ ที่มีการเติมข้อความอัตโนมัติแบบสด จำกัดขอบเขตอยู่ในโฟลเดอร์ปัจจุบัน
- **พิมพ์เส้นทางจากรากของระบบไฟล์ได้เช่นกัน** `/` ที่นำหน้าช่องว่างเปล่าจะเปิดเส้นทางแบบนั้นแทนที่จะเติมขั้นหนึ่งให้ครบ ทุกเครื่องหมายทับหลังจากนั้นเป็นของมัน และ `~` คือโฟลเดอร์บ้านของคุณ ขณะที่ช่องนี้ถือเส้นทางแบบนั้นอยู่ ลิสต์จะแสดงรายการของเครื่องแทนที่จะเป็นห้องนิรภัย และส่วนเปิดของแถวจะหลบไป — สิ่งที่อยู่ในช่องเริ่มจากรากและบอกไว้อย่างนั้น เมื่อปิด *การเข้าถึงไฟล์ภายนอก* ลิสต์จะว่างเปล่าแทน เพราะ <kbd>Enter</kbd> จะปฏิเสธเส้นทางนั้นอยู่ดี
- **พิมพ์หน้าได้ ไม่ใช่แค่เลือกเอา** `:graph`, `:search` หรืออะไรก็ตามที่ปลั๊กอินของคุณลงทะเบียนไว้ — ป้ายชื่อที่[รายการของรากห้องนิรภัย](#บานหน้าต่างที่ไม่มีไฟล์)เสนอ การพิมพ์เครื่องหมายโคลอนที่ไหนก็ตามจะเรียกมันขึ้นมา เพราะไม่มีชื่อใดมีเครื่องหมายนี้ได้ และ <kbd>Enter</kbd> จะเปิดมุมมองนั้นในแถบเนื้อหานี้ `:graph` ที่พิมพ์**ภายในโฟลเดอร์**จะเปิดกราฟของโฟลเดอร์นั้น — กราฟที่ถูกกรองด้วย `path:"that/folder"` ในช่องค้นหาของตัวมันเอง เหมือนพิมพ์ไว้ที่นั่น ที่รากห้องนิรภัยมันคือกราฟทั้งหมด <kbd>Tab</kbd> เติมชื่อให้ครบเหมือนที่เติมชื่อโฟลเดอร์ให้ครบ — และพาสิ่งอื่นใดที่ช่องเคยถือไว้ไปด้วย เพราะหน้าไม่ได้อยู่ในโฟลเดอร์ใด และไม่มีอะไรอยู่ใต้หน้าได้ การคลิกป้ายชื่อบนแถบเนื้อหาแบบนั้นจะเปิดช่องขึ้นมาโดยถือมันไว้แล้ว
- **สิ่งที่ <kbd>Tab</kbd> จะเขียนถูกเสนอขึ้นขณะที่คุณพิมพ์** ที่ซึ่งลูกทุกตัวที่ขึ้นต้นด้วยสิ่งที่คุณพิมพ์ยังคงเห็นพ้องต่อไปสักพัก การเห็นพ้องนั้นปรากฏหลังเคอร์เซอร์ ถูกเลือกไว้ ที่ซึ่งพวกมันเลิกเห็นพ้อง ขั้นไปสู่ตัวแรกในกลุ่มนั้นจะปรากฏแทน — หรือไปสู่แถวที่คุณใช้ลูกศรเลื่อนไปถึง เพราะนั่นคือแถวที่ <kbd>Tab</kbd> จะมุ่งไป การพิมพ์ทับชื่อจะปล่อยนามสกุลของมันไว้และเสนอสิ่งที่จะเติมไว้ข้างหน้า และโฟลเดอร์ที่เพิ่งก้าวเข้าไปจะเสนอขั้นแรกของมัน จึงไม่มีสถานะใดที่ไม่มีอะไรถูกเสนอเลยแต่ <kbd>Tab</kbd> กลับเขียนบางอย่างขึ้นมา พิมพ์ตัวอักษรเหล่านั้นแล้วมันจะถูกกลืนไปทีละตัว พิมพ์อย่างอื่นแล้วมันจะหายไป <kbd>Tab</kbd> หรือ <kbd>End</kbd> รับมันไปทั้งหมด <kbd>→</kbd> รับไปทีละตัวอักษร <kbd>Backspace</kbd> คืนมันกลับไปโดยไม่แตะตัวอักษรที่คุณพิมพ์เอง และจะไม่มีอะไรถูกเสนออีกจนกว่าคุณจะพิมพ์ — จึงมีทางออกเสมอจากชื่อที่คุณไม่ต้องการ หลังจากกด <kbd>Tab</kbd> ครั้งหนึ่ง ขั้นถัดไปจะถูกเสนอทันที เหมือนหลังจากพิมพ์ตัวอักษรหนึ่งตัว สิ่งที่ลิสต์แสดงถูกกรองโดยสิ่งที่**คุณ**พิมพ์ ไม่ใช่โดยสิ่งที่ถูกเสนอ
- **ข้อเสนอไม่สนตัวพิมพ์เล็กใหญ่** `sch` เสนอ `Schemes` สะกดตามที่ชื่อนั้นสะกดไว้ การคืนข้อเสนอกลับจะคืนตัวอักษรของคุณตามที่คุณพิมพ์ไว้ ที่ซึ่งทั้ง `Test` และ `test` มีอยู่ ตัวที่สะกดตามที่คุณพิมพ์จะถูกเสนอ
- ในช่องนี้ส่วนที่ถูกเสนอเพียงแค่**ถูกเลือกไว้** ลิสต์คือที่ที่มันถูกสะกดออกมาให้ชัด: แต่ละแถวแสดงส่วนที่**ตรงกับสิ่งที่คุณพิมพ์เป็นตัวหนา** ไม่ว่าจะตรงตรงไหนในชื่อ — `kick` พบ `Weekly kickoff` และบอกไว้อย่างนั้น **ชื่อที่ขึ้นต้นด้วยสิ่งที่คุณพิมพ์มาก่อน** นำหน้าชื่อที่เพียงแค่มีมันอยู่ข้างใน และถูกทำเครื่องหมายด้วยเส้นที่ขอบของแถว: **สีน้ำเงิน**ที่ซึ่งพวกมันมีร่วมกันมากกว่าที่คุณพิมพ์ ดังนั้น <kbd>Tab</kbd> จึงมีอะไรจะเพิ่มให้กับพวกมันทั้งหมด และ**สีเขียว**บนกิ่งที่ข้อเสนอนำไปในจุดที่พวกมันแยกจากกัน — `te` กับ `test1`, `test2`, `text1` และ `text2` เสนอ `te`+`st` ดังนั้นสองแถว `test` จึงเป็นสีเขียว และสองแถว `text` ยังคงเส้นธรรมดา แต่ละแถว**ขีดเส้นใต้ขั้นที่ <kbd>Tab</kbd> จะก้าวไปหามัน** ไม่ใช่แค่แถวที่ถูกเสนอเท่านั้น และเส้นใต้นี้ตามข้อเสนอไปเมื่อมันเปลี่ยน
- **การพิมพ์ปล่อยแถวที่ถูกไฮไลต์ไป** ลิสต์เปิดขึ้นที่รายการที่คุณยืนอยู่ แต่ทันทีที่คุณพิมพ์ มันก็เป็นเรื่องของที่อื่นแล้ว และไฮไลต์ที่ไม่มีใครวางไว้จะถูกอ่านเป็นทางเลือกที่ทำไปแล้ว
- ข้อเสนอเป็นเพียงข้อความที่อยู่ตรงหน้าคุณเสมอ: ตัวอักษรที่คุณพิมพ์ยังคงสะกดตามที่คุณพิมพ์ไว้ขณะที่คุณพิมพ์ และการรับข้อเสนอจะเขียนชื่อใหม่ตามที่โฟลเดอร์สะกดไว้ เพราะเส้นทางต้องตรงกับดิสก์ `sk` + <kbd>Tab</kbd> ไปถึง `Skyline` ไม่ใช่ `skyline`
- **ช่องนี้สวมสีของสิ่งที่มันตั้งชื่อไว้** สีเดียวกับแถวของมันในลิสต์: สีม่วงสำหรับโน้ต รวมถึงโน้ตของโฟลเดอร์เอง สีส้มสำหรับสิ่งที่ไม่ใช่โน้ต สีน้ำเงินสำหรับโน้ตที่คุณอยู่ แถวที่มันรับสีมาคือแถวที่ชื่อตรงกับสิ่งที่คุณพิมพ์เป๊ะ หรือถ้าไม่มีก็แถวที่ถูกไฮไลต์ หรือถ้าไม่มีอีกก็แถวแรกที่การพิมพ์ของคุณยังนำไปถึง
- **ช่องนี้กลายเป็นสีแดงเมื่อไม่มีอะไรตอบรับสิ่งที่อยู่ในนั้น** — ไม่มีไฟล์ ไม่มีโฟลเดอร์ และไม่มีแถวในลิสต์ที่ยังนำไปถึงมัน จากจุดนั้น <kbd>Enter</kbd> จะสร้างสิ่งที่อยู่ในช่องขึ้นมาแทนที่จะเปิดมัน และสีแดงบอกไว้ก่อนที่คุณจะยืนยัน มันไม่ปรากฏขึ้นเลยสำหรับที่อยู่เว็บ ซึ่งไม่ใช่ที่ที่จะไปค้นหาบนเครื่องนี้ ช่องนี้ถูกให้สี**ทั้งหมด**แทนที่จะเป็นแค่ส่วนที่ขาดหายไป: ช่องข้อความไม่สามารถให้สีเพียงครึ่งหนึ่งของเนื้อหาตัวเองได้ ในโหมดย้าย/เปลี่ยนชื่อ ช่องนี้เก็บสีแดงของตัวเองไว้แทน สำหรับชื่อที่ผิดกฎ — ที่นั่น ชื่อที่ไม่มีอะไรตอบรับคือประเด็นเลย ที่ชื่อ**ถูกใช้ไปแล้ว**จะถูกจัดการเมื่อคุณยืนยัน ด้วยไดอะล็อกที่ถามว่าควรทำอย่างไรกับไฟล์ที่ขวางอยู่ — ดู [ชื่อที่ถูกใช้ไปแล้ว](#ชื่อที่ถูกใช้ไปแล้ว): ทุกชื่อที่พิมพ์ไปยัง `Notes.md` ผ่านชื่อที่อาจเป็นไฟล์ของตัวมันเอง การตั้งค่าสถานะทีละตัวอักษรจึงเตือนเกี่ยวกับชื่อที่ยังไม่มีใครถามหาด้วยซ้ำ
- `/` ยืนยันส่วนที่คุณกำลังพิมพ์และลงไปในนั้น โดยเก็บสิ่งที่อยู่ข้างหลังไว้ — สิ่งเดียวกับที่ <kbd>Tab</kbd> ทำเมื่อมันก้าวเข้าไป
- <kbd>Backspace</kbd> ในช่องพิมพ์ที่ว่างเปล่าจะถอยกลับออกไปยังโฟลเดอร์แม่ เปิดชื่อของมันขึ้นมาใหม่โดยเคอร์เซอร์อยู่ท้ายสุด <kbd>Backspace</kbd> หน้านามสกุลที่เหลืออยู่ตามลำพังก็ทำแบบเดียวกัน — ช่องที่มีแค่ `.md` ไม่ได้ตั้งชื่ออะไรเลย — และนามสกุลเดี่ยวนั้นก็หายไปด้วย
- **การคลิกโฟลเดอร์ขณะที่ช่องเปิดอยู่จะขยายช่องให้เป็นเส้นทางทั้งหมดหลังโฟลเดอร์นั้น** โดยชื่อของโฟลเดอร์เองถูกเลือกไว้ — สิ่งเดียวกับที่การคลิกมันจากแถวจะทำ และทุกอย่างที่ช่องเคยถือไว้ยังคงอยู่ สิ่งที่อยู่ในช่องคือส่วนท้ายของแถวขณะที่มันเปิดอยู่ ดังนั้นโฟลเดอร์ที่ถูกคลิกสูงขึ้นไปจะคืนเส้นทางที่ช่วงนี้เดินผ่านมา ไม่ใช่เส้นทางที่โน้ตเริ่มต้นไว้
- **การเลื่อนลูกศรออกจากหน้าช่องจะดึงโฟลเดอร์ก่อนหน้ามันเข้ามา** ราวกับว่าเส้นทางทั้งหมดเป็นข้อความบรรทัดเดียว เมื่อเคอร์เซอร์อยู่ที่จุดเริ่มต้นสุด <kbd>←</kbd> จะดึงโฟลเดอร์นั้นเข้ามาในช่องและไปจบที่ท้ายชื่อของมัน <kbd>Ctrl</kbd>+<kbd>←</kbd> ไปจบที่ต้นของมัน และ <kbd>Home</kbd> ดึงทุกโฟลเดอร์จนถึงรากห้องนิรภัยเข้ามาทีเดียว — หรือจนถึงที่ที่คุณเลือกไว้ นอกห้องนิรภัย กดค้าง <kbd>Shift</kbd> แล้วการเลือกจะขยายครอบคลุมสิ่งที่ดึงเข้ามา บน macOS การกระโดดคำคือ <kbd>Option</kbd>+<kbd>←</kbd> และ <kbd>Cmd</kbd>+<kbd>←</kbd> คือ <kbd>Home</kbd> ที่ไหนก็ตามนอกจากหน้าช่อง ปุ่มเหล่านี้เป็นปุ่มข้อความธรรมดา **ขณะที่ลิสต์กำลังแสดงอยู่ <kbd>Home</kbd>, <kbd>End</kbd>, <kbd>PgUp</kbd> และ <kbd>PgDn</kbd> เป็นของมัน** — แถวแรก แถวสุดท้าย เลื่อนขึ้นหนึ่งหน้า เลื่อนลงหนึ่งหน้า โดยหนึ่งหน้าคือสิ่งที่ลิสต์แสดงอยู่ และแถวที่ถูกไฮไลต์ยังคงตำแหน่งของมันบนหน้าจอ — และไปถึงข้อความก็ต่อเมื่อลิสต์ปิดไปแล้ว <kbd>Shift</kbd>+<kbd>Home</kbd> ดึงทุกโฟลเดอร์เข้ามาแม้ขณะที่ลิสต์เปิดอยู่เช่นกัน
- **ลิสต์ตามเคอร์เซอร์ไป** เลือกส่วนอื่นของเส้นทาง — ลากผ่านมัน คลิกเข้าไปในมัน หรือเลื่อนลูกศรไปตามมัน — แล้วลิสต์จะแสดงลูกของโฟลเดอร์*นั้น* ไม่ใช่โฟลเดอร์ที่ช่องถูกเปิดขึ้นมาด้วย โฟลเดอร์ถูกนับจากชิปบวกกับส่วนของช่องที่อยู่หน้าเคอร์เซอร์ ดังนั้นการคลิกเข้าไปใน `Notes.md` ในช่องที่มี `2026/Notes.md` จะแสดงสิ่งที่อยู่ใน `2026` การชี้ที่แถวจะเขียนมันลงในส่วนที่เคอร์เซอร์อยู่ และการยกตัวชี้ออกจากลิสต์จะคืนข้อความและการเลือกของคุณกลับมา เหมือนเดิมทุกประการ
- **การกวาดการเลือกออกจากช่อง**แล้วปล่อยที่อื่นไม่ปิดช่อง การกดที่เริ่มต้นในช่องเป็นของการแก้ไขไม่ว่าจะเดินทางไปไกลแค่ไหน มีเพียงการกดที่*เริ่มต้น*จากข้างนอกเท่านั้นที่เป็นการคลิกออกไป
- <kbd>Enter</kbd> ยืนยัน — และเมื่อช่องไม่ได้ตั้งชื่ออะไรเลย เช่นในโฟลเดอร์ว่างเปล่าที่ไม่เคยมีอะไรให้เติมให้ครบ มันจะบอกว่า *No file selected* และยังคงเปิดอยู่แทนที่จะปิดราวกับว่ามีบางอย่างถูกเลือกไปแล้ว <kbd>Esc</kbd> หรือคลิกที่อื่นจะยกเลิกกลับไปยังเส้นทางจริงของไฟล์ กด <kbd>Esc</kbd> ครั้งเดียวก็พอ: มันปิดลิสต์ ออกจากช่อง และคืนโฟกัสให้โน้ต แทนที่จะต้องกดทีละครั้งต่อชั้น

ช่องนี้ไม่มีกรอบ — ไม่มีกล่อง ไม่มีเส้นขอบ — จึงอ่านได้เหมือนตัวข้อความเส้นทางเอง และขยายตัวเองขณะที่คุณพิมพ์

## ทุกส่วนของแถว ปุ่มต่อปุ่ม

แถวทั้งหมดในภาพเดียว คอลัมน์คลิกขวาคือสิ่งที่การกด **หนึ่ง**
ครั้งให้คุณ ปุ่มนั้นยังนับจำนวนการกดด้วย และ[ตารางของมันเอง](#คลิกขวา-หนึ่งครั้ง-สองครั้ง-สามครั้ง)
ด้านล่างมีการกดครั้งที่สอง สาม และสี่ ตารางนี้สมมติว่า **ชื่อโฟลเดอร์เปิดรายการ**
เปิดอยู่ ซึ่งเป็นค่าเริ่มต้น — เมื่อปิดไว้ ชื่อโฟลเดอร์และตัวคั่นจะสลับคอลัมน์แรก
ตามที่[ตารางด้านบน](#เส้นทางในแถบหัวเรื่อง)บอกไว้

| กดที่ตรงไหน | คลิก | ดับเบิลคลิก | <kbd>Ctrl</kbd>+คลิก หรือคลิกกลาง | คลิกขวา | ลากบางอย่างมาวางบนมัน |
| --- | --- | --- | --- | --- | --- |
| **ชื่อห้องนิรภัย** | เปิดรายการตำแหน่ง — ห้องนิรภัยอื่น, โฮม, รากของระบบไฟล์, ไดรฟ์ที่เชื่อมต่อ ปิดไว้เป็นค่าเริ่มต้น เมื่อปิด จะเปิดห้องนิรภัยนั้นใน File Explorer แทน | ทำเครื่องหมาย **เส้นทางแบบสัมบูรณ์ทั้งหมด** รายการนั้นเปิดขึ้นโดยมีเส้นทางอยู่ในฟิลด์แล้ว และทำเครื่องหมายเฉพาะส่วนของห้องนิรภัยเอง การกดครั้งที่สองจะขยายไปทำเครื่องหมายส่วนที่เหลือ ไม่มีอะไรให้ขยายเมื่อรายการปิดไว้ | แท็บที่ไม่มีอะไรอยู่ ยืนอยู่ที่รากของห้องนิรภัยโดยแสดงรายการไว้แล้ว — ที่ให้พิมพ์เส้นทางจากศูนย์ | เมนูคลิกขวาของห้องนิรภัยเอง: สิ่งที่ทำกับห้องนิรภัยที่ส่วนนั้นเป็นชื่ออยู่ | **ไฟล์** ย้ายไปที่รากของห้องนิรภัย **ข้อความ** เปิดฟิลด์ที่ราก เพื่อตั้งชื่อโน้ตที่มันควรจะเป็น |
| **ชื่อโฟลเดอร์** | เลือกโฟลเดอร์นั้นเพื่อแก้ไข โดยแสดงเนื้อหาของโฟลเดอร์แม่ไว้ด้านล่าง | พิมพ์ใหม่ทั้งโฟลเดอร์นั้นและทุกอย่างที่อยู่ด้านล่างมัน | เปิดโฟลเดอร์นั้นในแท็บใหม่ | เมนูคลิกขวาของโฟลเดอร์นั้น — เมนูของ File Explorer เอง | **ไฟล์** ย้ายเข้าไปในโฟลเดอร์นั้น **ข้อความ** เปิดฟิลด์ที่นั่น เพื่อตั้งชื่อโน้ตที่มันควรจะเป็น |
| **ตัวคั่น** | เปิดโฟลเดอร์ก่อนหน้ามัน — โน้ตของโฟลเดอร์นั้น ในที่ที่มีปลั๊กอินโฟลเดอร์โน้ตทำงานอยู่และมีอยู่แล้ว ไม่เช่นนั้นจะแสดงและขยายมันใน File Explorer | **สร้างโน้ตของโฟลเดอร์นั้น** และไปที่นั่น ในที่ที่มีปลั๊กอินโฟลเดอร์โน้ตทำงานอยู่และโฟลเดอร์ยังไม่มี ในที่ที่มีอยู่แล้ว นี่ก็เป็นแค่การกดครั้งเดียวอีกครั้ง | โน้ตของโฟลเดอร์ในแท็บใหม่ ในที่ที่มีอยู่แล้ว ไม่เช่นนั้นก็เป็นแท็บที่ยืนอยู่ที่โฟลเดอร์นั้นโดยแสดงรายการไว้ | เมนูคลิกขวาของโฟลเดอร์เดียวกับที่ชื่อให้ — เมนูของโน้ตของโฟลเดอร์นั้น ในที่ที่มันมีอยู่ | ไปยังตอนท้ายของโน้ตของโฟลเดอร์นั้น ในที่ที่มันมีอยู่ เมื่อคุณยืนยัน |
| **ชื่อโน้ต** | เปิดชื่อเพื่อแก้ไข — โฟลเดอร์ต่าง ๆ จะยังคงอยู่เป็นชิปข้าง ๆ — โดยทำเครื่องหมายทุกอย่างยกเว้นส่วนขยาย | นำส่วนขยายเข้ามาในเครื่องหมายด้วย | เปิดโน้ตในแท็บใหม่ | เมนูคลิกขวาของไฟล์ — เมนูเดียวกับที่แถวของ File Explorer ให้ | ไปยังตอนท้ายของโน้ตนี้ เมื่อคุณยืนยัน |
| **พื้นที่ว่าง** | เปิด **เส้นทางทั้งหมด** เพื่อแก้ไข ทำเครื่องหมายไปจนถึงส่วนขยาย โฟลเดอร์ต่าง ๆ เข้ามาในฟิลด์ไปพร้อมกัน ซึ่งเป็นสิ่งที่ทำให้นี่เป็นวิธีสำหรับพิมพ์เส้นทางใหม่ทั้งเส้น มากกว่าแค่ชื่อ | นำส่วนขยายเข้ามาในเครื่องหมายด้วย | <kbd>Ctrl</kbd> เปิดโน้ตนี้อีกครั้งในแท็บของมันเอง โดยกระพริบใน File Explorer เพื่อไม่ให้สับสนสำเนากับตัวแรก คลิกกลาง *ไม่ใช่* การกระทำนั้น: มันวางทับเส้นทาง | ทำเครื่องหมายเส้นทางทั้งหมดและเสนอสิ่งที่ทำได้กับข้อความที่ทำเครื่องหมายไว้ | |

**การกดครั้งที่สองตามการกดครั้งแรก** การสร้างโน้ตของโฟลเดอร์อยู่บนส่วนใดก็ตามของแถวที่*เปิด*โฟลเดอร์นั้น ซึ่งเป็นตัวคั่นตามค่าเริ่มต้น
และเป็นชื่อโฟลเดอร์เมื่อสลับปิดไว้ — เป้าหมายเดียวกับที่เส้นใต้แสดง
และเป้าหมายเดียวกับที่การกดครั้งเดียวก็ขอโน้ตของโฟลเดอร์อยู่แล้ว
มันถูกเสนอให้เฉพาะในขณะที่มีปลั๊กอินโฟลเดอร์โน้ตทำงานอยู่ เพราะโน้ตของโฟลเดอร์เป็นข้อตกลง
ไม่ใช่ข้อเท็จจริงเกี่ยวกับระบบไฟล์ และเฉพาะในที่ที่โฟลเดอร์ยังไม่มี
ที่ที่มันอยู่และชื่อที่มันถูกเรียกจะถูกอ่านจากการตั้งค่าของ **Folder
notes** เอง ดังนั้นห้องนิรภัยที่เก็บโน้ตของโฟลเดอร์ไว้ข้างโฟลเดอร์
หรือเรียกมันว่า `_index` จะได้แบบนั้น ตัวไฟล์เองเป็น Markdown เสมอ
ซึ่งเป็นสิ่งที่คำสั่งสร้างค่าเริ่มต้นของปลั๊กอินนั้นสร้าง และเป็นสิ่งที่มันพบ
ไม่ว่าห้องนิรภัยจะถูกตั้งให้ใช้ประเภทใด โหมดเปลี่ยนชื่อ/ย้ายไม่เกี่ยวข้องเลย —
ไม่มีอะไรบนแถวเปิดโฟลเดอร์ในขณะที่การย้ายกำลังรอดำเนินการ

**การคลิกที่ชื่อยังคงดำเนินต่อไป** สี่ขั้นเป็นสี่ขั้นเดียวกับที่ปุ่มเปลี่ยนชื่อเดินผ่าน
ในลำดับเดียวกัน: ชื่อ, ชื่อพร้อมส่วนขยาย, เส้นทางจากห้องนิรภัย,
เส้นทางจากรากของระบบ ดังนั้นการคลิกครั้งที่สามจะไปถึงเส้นทางของห้องนิรภัย
และครั้งที่สี่ไปถึงเส้นทางของเครื่อง — สี่สิ่งเดียวกับที่
<kbd>Tab</kbd> ผ่านจุดสิ้นสุดของฟิลด์ให้คุณ และสี่สิ่งเดียวกับที่ปุ่ม
ขวา*คัดลอก*แทนที่จะเลือก

**การชี้เมาส์ค้าง** เป็นคำตอบของตัวมันเองและไม่เปลี่ยนแปลงอะไรเลย: ชื่อที่ถูกย่อ
จะกลับมาเต็มตราบใดที่คุณชี้ไปที่มัน และไอคอนที่จุดเริ่มต้นของแถวจะบอกว่า
ห้องนิรภัยอยู่ที่ไหน

## คลิกขวา: หนึ่งครั้ง สองครั้ง สามครั้ง

ทุกเป้าหมายบนแถวตอบสนองต่อการคลิกขวา และจำนวนครั้งที่คุณกดเป็นตัวกำหนดว่าคุณจะได้อะไร เพราะการกดครั้งที่สองอาจกำลังจะมา การกดครั้งแรกจะรอประมาณหนึ่งในสามวินาทีก่อนที่จะลงมือ — นั่นคือค่าใช้จ่ายของการรวมสามท่าทางไว้ในปุ่มเดียว

| กดที่ตรงไหน | ครั้งเดียว | สองครั้ง | สามครั้ง |
| --- | --- | --- | --- |
| **ชื่อห้องนิรภัย** | เมนูคลิกขวาของห้องนิรภัย: สิ่งที่ทำได้กับห้องนิรภัยที่ส่วนนั้นเป็นชื่ออยู่ — รวมถึง *เปิดห้องนิรภัยนี้* ในที่ที่ห้องนิรภัยนั้นไม่ใช่ห้องที่คุณอยู่ | คัดลอกชื่อของห้องนิรภัย | คัดลอกที่ที่ห้องนิรภัยอยู่ — และการกดครั้งที่สี่ ที่ที่ไฟล์ที่เปิดอยู่อยู่ |
| **ตัวคั่น** | เมนูของโฟลเดอร์นั้น — เมนูของโน้ตของโฟลเดอร์นั้น ในที่ที่มีปลั๊กอินโฟลเดอร์โน้ตทำงานอยู่และโฟลเดอร์มีอยู่ | | |
| **ชื่อโฟลเดอร์** | เมนูของโฟลเดอร์นั้น | คัดลอกชื่อของโฟลเดอร์ | คัดลอกมันและทุกอย่างที่อยู่ทางขวาของมัน |
| **ชื่อโน้ต** | เมนูของไฟล์ — เมนูเดียวกับที่แถวของ File Explorer ให้ | คัดลอกชื่อ | คัดลอกมันพร้อมส่วนขยาย |
| **พื้นที่ว่าง** | | คัดลอกเส้นทางจากโฟลเดอร์ห้องนิรภัยของคุณ โดยไม่มีส่วนขยาย | เหมือนกัน แต่มีส่วนขยาย |

การกดครั้งเดียวบน **ชื่อห้องนิรภัย** เปิดสิ่งที่ทำได้กับสิ่งที่ส่วนนั้นเป็นชื่ออยู่
สำหรับ **ห้องนิรภัยที่คุณอยู่**: เปิดในหน้าต่างใหม่, จัดการห้องนิรภัย,
คัดลอกที่ที่มันอยู่, คัดลอก ID ของมัน, แสดงในตัวจัดการไฟล์ของคุณ
สำหรับ **ห้องนิรภัยอื่น** ที่เข้าถึงผ่านรายการตำแหน่ง เหมือนกันแต่ไม่มีหน้าต่างใหม่ —
ซึ่งจะเปิดห้องนิรภัย*นี้* ไม่ใช่ห้องนั้น — บวกกับสิ่งเดียวที่มีเฉพาะห้องนิรภัยที่คุณไม่ได้อยู่เท่านั้นที่เสนอได้:
**เปิดห้องนิรภัยนี้** มันถูกเรียกให้ Obsidian รู้จักด้วย ID ของมัน มากกว่าชื่อโฟลเดอร์
เนื่องจากห้องนิรภัยสองห้องอาจใช้ชื่อร่วมกันได้ สำหรับที่ที่ไม่ใช่ห้องนิรภัยเลย — โฟลเดอร์โฮมของคุณ,
ไดรฟ์ที่เชื่อมต่อ — ไม่มี ID ให้คัดลอกและไม่มีอะไรให้เปิด และเมนูก็บอกแบบนั้น
โดยไม่เสนอตัวเลือกเหล่านั้น

นี่ไม่ใช่เมนูจุดสามจุดของ Obsidian เอง ซึ่งเป็นของหน้าต่างเริ่มต้น
และไม่สามารถเปิดได้จากภายในห้องนิรภัยที่กำลังทำงานอยู่ — นี่คือรายการเดียวกัน
ที่ถูกสร้างขึ้นใหม่ ด้วยคำพูดของ Obsidian เอง นำมาจากคำสั่งของมันเพื่อให้มันมาถึง
ในภาษาของคุณ สามรายการของเมนูนั้นถูก**ตัดออก**โดยตั้งใจ:
*rename vault*, *move vault* และ *remove from list* ทั้งหมดกระทำกับโฟลเดอร์ของห้องนิรภัยเอง
หรือกับรีจิสทรีของห้องนิรภัยของ Obsidian และการทำแบบนั้นกับห้องนิรภัยที่คุณ
กำลังยืนอยู่ — โดยที่ไฟล์ของมันเปิดอยู่และตัวเฝ้าดูของมันกำลังทำงาน — คือวิธีที่ห้องนิรภัย
พัง เปิดตัวจัดการห้องนิรภัย (*Open another vault*) และทำสิ่งเหล่านั้นที่นั่น ที่ที่
ห้องนิรภัยถูกปิดอยู่

การคัดลอกสองแบบบน **พื้นที่ว่าง** คือแถวตามที่มันถูกเขียนไว้ — สิ่งที่ลิงก์
หรือการค้นหาต้องการ — และแบบที่อยู่บน **ชื่อห้องนิรภัย** คือเส้นทางที่ระบบไฟล์รู้จัก
ซึ่งเป็นสิ่งที่อะไรก็ตามนอก Obsidian ต้องการ การกดแต่ละครั้งที่นั่น
ขยายว่าสำเนานั้นใช้ทำอะไรได้: สองครั้งให้ชื่อของห้องนิรภัย สามครั้งให้ที่ที่
ห้องนิรภัยอยู่ สี่ครั้งให้ที่ที่ไฟล์ที่เปิดอยู่อยู่ Obsidian แยกความแตกต่างเดียวกันนี้
ในสองคำสั่งของมันเอง คือ *from vault folder* และ *from system root* ที่นี่
แบบที่หันหน้าออกไปข้างนอกอยู่บนส่วนที่ตัวมันเองอยู่นอกเส้นทาง

ทั้งหมดนี้ทำงานได้นอกห้องนิรภัยด้วย บนเป้าหมายเดียวกัน

การคัดลอกทุกครั้งจะบอกไว้ในการแจ้งเตือน เพราะการคัดลอกไม่ทิ้งอะไรไว้บนหน้าจอ
ให้เห็นว่ามันเกิดขึ้นแล้ว และการกดที่นับผิดไม่ควรดูเหมือนการกดที่สำเร็จ

## ตัวปรับ: เปิดมันที่อื่น

ชื่อของโน้ตและส่วนของโฟลเดอร์มีพฤติกรรมเหมือนแถวของมันใน File Explorer

| | บนชื่อของโน้ต | บนส่วนของโฟลเดอร์ |
| --- | --- | --- |
| คลิกธรรมดา | แก้ไขชื่อ | เรียกดูโฟลเดอร์นั้น |
| <kbd>Ctrl</kbd> / คลิกกลาง | เปิดโน้ตในแท็บใหม่ | ส่งโฟลเดอร์ไปยังแท็บใหม่ |
| <kbd>Ctrl</kbd>+<kbd>Alt</kbd> | แยกหน้าจอ | แยกหน้าจอ |
| ลาก | โน้ต ไปยังที่ใดก็ตามที่ Obsidian รับไฟล์ | โฟลเดอร์ เช่นเดียวกัน — รวมถึงแถบแท็บด้วย |

โฟลเดอร์ไม่ใช่สิ่งที่ Obsidian สามารถเปิดได้ ดังนั้นการส่งมันไปยังแท็บจะทำอย่างใดอย่างหนึ่งจากสองอย่าง:
เปิดโน้ตของโฟลเดอร์ ในที่ที่มีปลั๊กอินโฟลเดอร์โน้ตทำงานอยู่และมีอยู่แล้ว
หรือเปิดแท็บเปล่าที่แถบเส้นทางของมันยืนอยู่ในโฟลเดอร์นั้นแล้ว —
เหลือไว้ให้คุณพิมพ์แค่ชื่อ การวางส่วนของโฟลเดอร์บน **แถบแท็บ** ก็ทำแบบเดียวกัน
ในแท็บใหม่ที่ที่คุณปล่อยมัน — แถบแท็บของ Obsidian รับแค่ไฟล์ด้วยตัวมันเอง
ดังนั้นโฟลเดอร์ที่ถูกลากออกจาก File Explorer ก็ยังถูกปฏิเสธที่นั่นด้วย

## Tab: เติมชื่อให้เต็ม แล้วเติมเส้นทาง แล้วขยายส่วนที่เลือก

<kbd>Tab</kbd> เติมคำแบบเดียวกับ shell: **การกดหนึ่งครั้งจะขยายสิ่งที่คุณพิมพ์ไปให้ไกลที่สุดเท่าที่ชื่อในโฟลเดอร์นั้นยังตรงกัน และหยุดตรงจุดที่เริ่มต่างกัน** พิมพ์ `Sk` ในที่ที่มีแต่ `Sketches` ที่ขึ้นต้นแบบนั้น คำก็จะเสร็จสมบูรณ์ทันที พิมพ์ `Al` ในที่ที่ `Alpha-one`, `Alpha-two` และ `Alpine` ต่างก็ขึ้นต้นแบบนั้นทั้งหมด คุณจะได้ `Alp` เพราะตัวอักษรถัดไปเป็นคำถามที่มีแต่คุณเท่านั้นที่ตอบได้

กดอีกครั้งโดยไม่พิมพ์อะไรเพิ่ม มันจะเดินเข้าหาชื่อหนึ่งชื่อ — แถวที่รายการไฮไลต์ไว้ หรือแถวแรก — โดยหยุดตรงจุดคลุมเครือถัดไปของชื่อนั้น: `Alpha-` แล้วจึง `Alpha-one` รายการจะเปิดขึ้นตรงตำแหน่งที่คุณอยู่แล้ว ดังนั้นในโฟลเดอร์ของคุณเอง การกดครั้งแรกจะมุ่งไปที่โน้ตที่คุณเปิดอยู่ ไม่ใช่ไปที่อะไรก็ตามที่เรียงมาก่อนตามลำดับ

**การกดหนึ่งครั้งไม่เคยเลือกระหว่างชื่อให้คุณ** <kbd>Tab</kbd> จะก้าวเข้าไปในโฟลเดอร์ก็ต่อเมื่อสิ่งที่คุณพิมพ์เหลือผู้สมัครเพียงหนึ่งเดียว หรือเมื่อคุณพิมพ์ชื่อเต็มของโฟลเดอร์นั้นแล้วและไม่มี*โฟลเดอร์อื่น*ใดที่ขยายจากมัน ในกรณีที่มี — `Schemes` กับ `Schemes2026` ที่อยู่เคียงกัน — <kbd>Tab</kbd> จะเติมต่อไปเรื่อย ๆ ไปทางชื่อที่ยาวกว่า ส่วน <kbd>Enter</kbd> และการเลือกจากรายการต่างหากที่หมายถึง *อันนี้แหละ*

**ไฟล์** ไม่เคยหน่วงโฟลเดอร์ไว้แบบนั้น โฟลเดอร์ที่มีชื่อเดียวกับโน้ตของตัวเองอยู่ข้าง ๆ คือโน้ตประจำโฟลเดอร์ ไม่ใช่จุดแยกในเส้นทาง และ <kbd>Tab</kbd> เดินผ่านโฟลเดอร์ — ดังนั้น `Projects` ที่มี `Projects.md` อยู่ข้าง ๆ ก็ถูกก้าวเข้าไปเหมือนโฟลเดอร์อื่น ๆ ทั่วไป

มีเรื่องเล็ก ๆ สองอย่างที่ตามมา: สิ่งที่ปรากฏในช่องจะสะกดตามที่โฟลเดอร์สะกดไว้ ดังนั้น `sk` จะกลายเป็น `Sketches` และมีเพียงชื่อที่กำลังพิมพ์อยู่เท่านั้นที่ถูกแทนที่ ดังนั้นเส้นทางที่มีส่วนต่อทางขวามือมากกว่านั้นจะยังคงอยู่

เมื่อมีชื่อถูกเสนอให้ระหว่างที่คุณพิมพ์ <kbd>Tab</kbd> **จะเขียนตามข้อเสนอนั้นเป๊ะ ๆ**: ข้อเสนอคือสิ่งที่การกดจะเขียนเสมอ และเส้นขีดเส้นใต้กับเส้นสีเขียวในรายการก็บอกสิ่งเดียวกัน ดังนั้นสิ่งที่คุณเห็นหลังเคอร์เซอร์คือสิ่งที่คุณจะได้รับ ในจุดที่ชื่อเริ่มไม่ตรงกัน นั่นคือก้าวไปทางชื่อแรกในบรรดาชื่อเหล่านั้น — หรือไปทางแถวที่คุณเลื่อนลูกศรไปหา ซึ่ง <kbd>Tab</kbd> จะเลือกแถวนั้นแทนที่จะเป็นแถวข้าง ๆ — ดังนั้นให้เลื่อนลูกศรไปยังแถวที่คุณต้องการ หรือพิมพ์ผ่านจุดแยกนั้นไป ก่อนที่คุณจะกด มีแต่ในกรณีที่ข้อเสนอเหลือชื่อเพียง*หนึ่งเดียว*เท่านั้นที่การกดครั้งเดียวกันจะก้าวเข้าไปในชื่อนั้น

การมาถึงชื่อไฟล์**คือ**ขั้นแรก — ไม่มีการกดใดถูกใช้ไปเพื่อจอดเคอร์เซอร์ไว้ที่ท้ายชื่อที่กำลังจะถูกทำเครื่องหมาย จากจุดนั้นการกดจะหยุดเคลื่อนไปตามเส้นทางและเริ่มขยายส่วนที่ถูกเลือกแทน:

1. ชื่อ
2. ชื่อพร้อมนามสกุล
3. เส้นทางจากโฟลเดอร์ห้องนิรภัยของคุณ
4. เส้นทางจากรากของระบบ
5. กลับสู่จุดเริ่มต้นของเส้นทาง**ตามที่เป็นอยู่ในตอนนี้** — ยืนอยู่ตรงจุดที่การเดินเริ่มต้น ส่วนแรกถูกทำเครื่องหมายไว้ พร้อมที่จะเดินอีกครั้ง

การคลิกครั้งที่สี่จะไปถึงขั้นที่สี่นั้นได้โดยตรง

การขยายจะขยายเสมอ **ไม่เคยหด** ชื่อที่สมบูรณ์อยู่แล้วในช่อง — ที่เติมเต็มด้วยปุ่มเดียวกัน หรือเลือกมาจากรายการ — จะถูกทำเครื่องหมายทั้งชื่อ แทนที่จะถูกดึงนามสกุลออกก่อน: ขั้นแรกมีไว้สำหรับชื่อที่การเดินเพิ่ง*มาถึง* ซึ่งนามสกุลยังไม่ใช่ประเด็น

บันไดคือจุดที่การเดิน**มาถึง** ไม่ใช่จุดที่มันเริ่มต้น คลิกโฟลเดอร์กลางเส้นทาง ช่องจะเปิดขึ้นพร้อมทุกอย่างที่อยู่ใต้โฟลเดอร์นั้นโดยมีชื่อของโฟลเดอร์นั้นถูกทำเครื่องหมาย จากนั้น <kbd>Tab</kbd> แต่ละครั้งจะพา**หนึ่ง**โฟลเดอร์ — ทำเครื่องหมายโฟลเดอร์ถัดไป โดยเก็บส่วนที่เหลือของเส้นทางไว้ข้างหลัง — และเมื่อเหลือแค่ชื่อไฟล์เท่านั้นการขยายจึงจะเริ่มขึ้น:

| กด | ชิป | ช่อง | ถูกทำเครื่องหมาย |
| --- | --- | --- | --- |
| คลิก `a` | | `a/b/c/leaf.md` | `a` |
| <kbd>Tab</kbd> | `a` | `b/c/leaf.md` | `b` |
| <kbd>Tab</kbd> | `a › b` | `c/leaf.md` | `c` |
| <kbd>Tab</kbd> | `a › b › c` | `leaf.md` | `leaf` — ขั้นแรก |
| <kbd>Tab</kbd> | `a › b › c` | `leaf.md` | `leaf.md` |

**ชื่อที่ถูกใส่เข้าไปแล้วก็คือใส่เข้าไปแล้ว ไม่ว่าคุณจะใส่มันด้วยวิธีไหน** การเติมให้เต็มด้วย <kbd>Tab</kbd> การยืนยันด้วย `/` และการเลือกจากรายการ ล้วนทิ้งแถวไว้ในตำแหน่งเดียวกันโดยถือเส้นทางเดียวกัน ดังนั้นการกดหลังจากท่าทางนั้นจึงหมายถึงสิ่งเดียวกันไม่ว่าคุณจะมาทางไหน การเลือกโฟลเดอร์จากรายการเคยทำให้ช่องว่างเปล่าแทน ซึ่งทิ้งเส้นทางที่การไปถึงโฟลเดอร์เดียวกันด้วย <kbd>Tab</kbd> จะเก็บไว้

**เส้นทางที่คุณยังเขียนไม่เสร็จจะติดตามมาทั้งหมด** การก้าวเข้าไปในโฟลเดอร์ที่ส่วนที่เหลือของเส้นทางแขวนอยู่ ไม่ใช่การอ้างว่าส่วนที่เหลือนั้นมีอยู่จริง — มันคือวิธีที่เส้นทางถูกพิมพ์ล่วงหน้าก่อนตัวมันเอง และโฟลเดอร์ที่มันตั้งชื่อไว้ก็คือโฟลเดอร์ที่ <kbd>Enter</kbd> กำลังจะสร้างขึ้น ดังนั้นการเดินลงจาก `Dokumente/plans/untitled.md` เข้าสู่ `Dokumente` จะเก็บ `plans/untitled.md` ไว้ข้างหน้าคุณ ไม่ว่า `plans` จะมีอยู่แล้วหรือยัง เช่นเดียวกันกับเส้นทางที่คุณพิมพ์ขึ้นจากความว่างเปล่า: ไม่มีส่วนใดของมันที่สืบทอดมาจากที่ไหน ดังนั้นจึงไม่มีส่วนใดถูกดึงออกไป

**การสลับขั้นหนึ่งเป็นอีกขั้นเป็นอีกเรื่องหนึ่ง และตอนนั้นเส้นทางจะติดตามมาเท่าที่มันมีอยู่จริงเท่านั้น** สลับโฟลเดอร์กลางเส้นทางไปเป็นพี่น้องของมัน — คลิก `a` พิมพ์ชื่ออื่น กด <kbd>Tab</kbd> — และทุกอย่างที่อยู่ใต้มันจะติดตามมาด้วย เพราะเส้นทางที่คุณอยู่มักเป็นส่วนใหญ่ของเส้นทางที่คุณต้องการอยู่แล้ว แต่มีแต่สิ่งที่มีอยู่จริงตรงนั้นเท่านั้นที่จะรอดจากการย้าย ดังนั้นช่องกับรายการข้าง ๆ จึงไม่มีวันขัดแย้งกัน: สิ่งที่เหลืออยู่ตรงหน้าคุณคือเส้นทางที่คุณเดินได้จริง เริ่มจาก `a/b/c/leaf.md` โดยคลิก `a` และชื่อของมันถูกทำเครื่องหมาย:

| สิ่งที่คุณใส่เข้าไป | ชิป | ช่อง | ถูกทำเครื่องหมาย |
| --- | --- | --- | --- |
| `x` ซึ่งไม่มี `b` เลย | `x` | | ไม่มีอะไรติดตามมา |
| `y` ซึ่งมี `b` แต่ไม่มี `c` อยู่ในนั้น | `y` | `b` | `b` |
| `z` ซึ่งเป็นฝาแฝดของ `a` ตลอดทาง | `z` | `b/c/leaf.md` | `b` |

โฟลเดอร์ที่ถูกทิ้งไว้ให้ยืนอยู่คนเดียวแบบนั้นก็ยังคงเป็นโฟลเดอร์ที่เดินเข้าไปได้: การกดหลังจากนั้นจะก้าวเข้าไป แทนที่จะเริ่มขยายส่วนที่เลือกไว้เหนือชื่อของมัน

ชื่อที่**ไม่มี**สิ่งใดในโฟลเดอร์ตรงกันเลยจะถูกตอบสนองต่างออกไป เพราะไม่มีอะไรถูกใส่เข้าไปด้วยมัน: การกดจะทำเครื่องหมายสิ่งที่คุณพิมพ์ พร้อมให้คุณพิมพ์ทับมัน แทนที่จะตอบสนองด้วยที่อื่น

ทั้งหมดนี้เป็น**วง และไม่มีต้นทุนใดในการวนไปรอบ ๆ**: การกดหลังจากขั้นสุดท้ายจะส่งแถวกลับไปที่จุดเริ่มต้นของเส้นทาง พร้อมทั้งโฟลเดอร์ทั้งหมด พร้อมที่จะวนอีกครั้ง สิ่งเดียวที่จะออกจากแถวไปเลยคือคำนำหน้าแบบสัมบูรณ์ ในการกดที่หยุดแสดงมัน

สิ่งที่กลับมาคือ**เส้นทางที่คุณสร้างขึ้น** ไม่ใช่เส้นทางที่คุณเริ่มต้นจาก แยกทางเดินกลางคัน — เลือกพี่น้องอีกตัวจากรายการ เติมไปทางชื่ออื่น — แล้ววงจะปิดลงตรงจุดที่คุณอยู่จริง ๆ ขั้นทั้งสี่ก่อนหน้านั้นล้วนอธิบายเส้นทางเดียวกันนั้น และขั้นนี้เองที่เคยเป็นขั้นแปลกที่อธิบายอดีต

<kbd>Shift</kbd>+<kbd>Tab</kbd> ปิดวงเดียวกันในทิศทางย้อนกลับ: ที่จุดเริ่มต้นของเส้นทาง ที่ไม่มีอะไรเหลือให้คืนกลับ และไม่มีที่ใดสูงขึ้นไปอีก การกดครั้งถัดไปจะวนไปที่ขั้น**ไกลสุด** — เส้นทางจากรากของระบบ — และเดินหน้าแคบลงจากตรงนั้นต่อไป ไม่มีทิศทางใดตันเลย

มันยังไม่เสียการกดใด ๆ ไปกับขั้นที่มันแสดงไปแล้วด้วย ต่ำกว่าขั้นสุดท้าย — ชื่อที่ไม่มีนามสกุล — บันไดก็จบลง และ*การกดเดียวกันนั้นเอง*จะออกจากโฟลเดอร์: เส้นทางจากรากของระบบ เส้นทางจากห้องนิรภัยของคุณ ชื่อ ชื่อที่ไม่มีนามสกุล แล้วจึงโฟลเดอร์ ทีละก้าว

ไม่มีการกดใดถูกใช้ไปกับขั้นที่ไม่เปลี่ยนแปลงอะไรเลยด้วย: การคลิกชื่อโน้ตจะแสดงมันโดยไม่มีนามสกุลอยู่แล้ว ซึ่งเป็นสิ่งที่ขั้นแรกแสดง ดังนั้นจากตรงนั้น <kbd>Tab</kbd> จะเริ่มที่ขั้นที่สอง

แต่ละขั้นเปลี่ยนสิ่งที่*อยู่ใน*ช่อง ไม่ใช่แค่สิ่งที่ถูกไฮไลต์ — การเลือกต้องอยู่เหนือข้อความที่มันตั้งชื่อไว้ ไม่เช่นนั้น <kbd>Enter</kbd> จะยืนยันสิ่งอื่นที่ไม่ใช่สิ่งที่คุณเห็นว่าถูกเลือกอยู่ บันไดนี้เป็นของหนึ่งช่วงการแก้ไข: คลิกออกไปที่อื่น หรือพิมพ์อะไรก็ตาม แล้ว <kbd>Tab</kbd> ครั้งถัดไปจะเติมชื่ออีกครั้ง

### <kbd>Shift</kbd>+<kbd>Tab</kbd>: ถนนเดิมแต่ย้อนกลับ

<kbd>Shift</kbd>+<kbd>Tab</kbd> จะถอยกลับหนึ่งก้าวต่อการกดหนึ่งครั้ง ตามลำดับที่กดไว้: การเลือกจะแคบลงทีละขั้น การเติมแต่ละครั้งจะถูกคืนกลับ และแต่ละโฟลเดอร์จะถูกก้าวออกมา — ชื่อของมันกลับเข้าไปในช่องเพื่อให้คุณแก้ไขได้แทนที่จะต้องพิมพ์ใหม่

**ไม่มีอะไรถูกลบระหว่างทางกลับ** การเติมจะถูกคืนกลับด้วยการ*ทำเครื่องหมาย*ตัวอักษรที่มันเพิ่มเข้าไป เหมือนกับการเดินไปข้างหน้าที่ทำเครื่องหมายสิ่งที่มันขยายไปทับ — ชื่อยังคงอยู่ตรงหน้าคุณ และการกดแต่ละครั้งถัดไปจะทำเครื่องหมายเพิ่มอีกหนึ่งก้าว:

| | ช่อง | ถูกทำเครื่องหมาย |
| --- | --- | --- |
| เดินเข้ามา | `Alpha-one` | |
| <kbd>Shift</kbd>+<kbd>Tab</kbd> | `Alpha-one` | `one` |
| <kbd>Shift</kbd>+<kbd>Tab</kbd> | `Alpha-one` | `ha-one` |
| <kbd>Shift</kbd>+<kbd>Tab</kbd> | `Alpha-one` | `Alpha-one` |

การพิมพ์จะแทนที่ส่วนที่ถูกทำเครื่องหมาย เหมือนกับที่อื่น ๆ <kbd>Tab</kbd> จะใส่กลับเข้าไปตรงกับสิ่งที่เครื่องหมายคืนกลับมาเป๊ะ ๆ ดังนั้นการเดินออกสองก้าวแล้วเดินเข้าอีกสองก้าวจะพาคุณกลับไปที่เดิม

เมื่อชื่อทั้งหมดถูกทำเครื่องหมายแล้ว ก็ไม่เหลืออะไรที่การกดใส่ไว้ตรงนั้นอีก และการกดครั้งถัดไปจะเดิน*ขึ้นตามเส้นทาง*: มันจะออกจากโฟลเดอร์ที่คุณยืนอยู่ เหมือนกับ <kbd>Backspace</kbd> บนช่องว่างเปล่า นั่นก็ไม่มีต้นทุนเช่นกัน — ชื่อของโฟลเดอร์จะกลับเข้ามาในช่อง**นำหน้า**สิ่งที่มีอยู่ในนั้น โดยถูกทำเครื่องหมายไว้ ซึ่งเป็นข้อความเดียวกับที่การคลิกโฟลเดอร์นั้นจะให้คุณ ย้อนกลับเป็นทิศทางหนึ่ง ไม่ใช่ประวัติการยกเลิก — แต่การทำเครื่องหมายชื่อไว้ก่อนหมายความว่าการกดครั้งเดียวจะไม่มีวันทั้งคืนสิ่งที่คุณเขียนกลับและพาคุณออกจากโฟลเดอร์ที่คุณเขียนมันไว้ในเวลาเดียวกัน

ข้อความที่เปิดขึ้นมา**โดยถูกเลือกไว้แล้ว** — สิ่งที่การคลิกโฟลเดอร์ทิ้งไว้เบื้องหลัง — คือชื่อที่ <kbd>Tab</kbd> จะทำงานต่อไป: มันถูกเติมและถูกก้าวเข้าไปเหมือนกับอย่างอื่น และการพิมพ์จะแทนที่มัน มีเพียงคำสั่งโฟกัสเท่านั้นที่เปิดขึ้นบนขั้นหนึ่งของบันไดเอง เพราะมันกำลังแสดงเส้นทางทั้งหมดให้คุณดู ไม่ใช่โฟลเดอร์ให้เดินเข้าไป

## การพิมพ์สิ่งที่ไม่ใช่เส้นทาง

| สิ่งที่คุณพิมพ์ | สิ่งที่เกิดขึ้น |
| --- | --- |
| `https://…` | เปิดในแท็บใหม่ใน**Web viewer**ของ Obsidian หากคุณเปิดปลั๊กอินหลักนั้นไว้ มิฉะนั้นจะเปิดในเบราว์เซอร์บนเดสก์ท็อปของคุณ |
| `obsidian://…` | ส่งให้ URI handler ของ Obsidian เอง |
| `file:///…` | ถูกถอดรหัสและเปิดขึ้น: เป็นโน้ตจริงหากอยู่ในห้องนิรภัยของคุณ หรือใน viewer หากไม่ใช่ |
| `/home/you/a%20b.md` | เช่นเดียวกัน สำหรับเส้นทางที่วางมาจากเบราว์เซอร์หรือตัวจัดการไฟล์ |

มีแต่ scheme ที่ระบุชัดเจนเท่านั้นที่นับ — โน้ตที่ชื่อ `100%20` ก็ยังคงเป็นโน้ต `/` ที่เป็นส่วนหนึ่งของ scheme จะคงเป็นตัวอักษรจริง แทนที่จะลงไปในโฟลเดอร์ ดังนั้น URL จึงพิมพ์ด้วยมือได้ ไม่ใช่แค่วางเท่านั้น

## คำสั่งสำหรับแป้นพิมพ์

**โฟกัสแถบพาธ** เปิดช่องขึ้นบนชื่อของโน้ตและเดินไปแบบเดียวกับที่ <kbd>F2</kbd> ทำ — ชื่อ ชื่อพร้อมนามสกุล เส้นทางจากห้องนิรภัยของคุณ เส้นทางจากรากของระบบ — และการกดหลังจากนั้นจะปิดช่องและวางเคอร์เซอร์กลับเข้าไปในโน้ต มันไม่ได้เปลี่ยนชื่อ: Enter นำทาง เหมือนกับช่องอื่นใดทั่วไป มันไม่มีปุ่มลัดของตัวเองมาให้แต่แรก เพราะแนวทางของ Obsidian ไม่สนับสนุนให้ปลั๊กอินจองปุ่มลัดไว้เอง — แถว **Hotkeys** ที่ท้ายการตั้งค่าของปลั๊กอินนี้จะเปิด *การตั้งค่า → Hotkeys* โดยแสดงเฉพาะคำสั่งของมัน คุณจึงตั้งปุ่มลัดได้ที่นั่น

## การนำทางไม่เคยแตะไฟล์ที่เปิดอยู่

ในโหมดค่าเริ่มต้น (นำทาง) โน้ตที่เปิดอยู่จะ**ไม่ถูก**เปลี่ยนชื่อหรือย้ายเลย

- เส้นทางที่ชี้ไปยังไฟล์ที่มีอยู่แล้วจะเปิดไฟล์นั้น
- เส้นทางที่ยังไม่มีอยู่จะถูกสร้างขึ้นทันที พร้อมทั้งโฟลเดอร์แม่ที่ขาดหายไป แล้วเปิดขึ้นมา ไฟล์และโฟลเดอร์ทุกอันที่ถูกสร้างแบบนี้จะบอกไว้ในการแจ้งเตือน — โฟลเดอร์ใหม่ไม่เช่นนั้นจะมองไม่เห็นจนกว่าคุณจะไปตามหามัน — และถังขยะของ Obsidian เองทำให้อันที่ไม่ต้องการยกเลิกได้ด้วยการกดปุ่มเดียว
- **นอกห้องนิรภัยมันจะถามก่อนเสมอ** ที่นั่นการพิมพ์ผิดแบบเดียวกันจะเขียนลงในโฟลเดอร์ของระบบ ซึ่งทั้งการแจ้งเตือนและถังขยะของ Obsidian ไม่ได้ช่วยปลอบใจอะไรมากนัก

## <kbd>Ctrl</kbd> — แท็บใหม่ และคัดลอกแทนการย้าย

โน้ตที่**ถูกสร้าง ย้าย หรือคัดลอกภายในห้องนิรภัยจะถูกแสดงตรงจุดที่มันไปลง**ใน File Explorer โดยถูกทำเครื่องหมายไว้ชั่วครู่ด้วยสีเน้นของ Obsidian — ต้นไม้ไฟล์คือที่ที่คุณมองหามันในภายหลัง มันจึงถูกวางไว้ตรงหน้าคุณแทนที่จะถูกทิ้งไว้ในโฟลเดอร์ที่อาจไม่ได้เปิดอยู่ด้วยซ้ำ การทำสำเนาก็บอกไว้เช่นกัน: สำเนาจะทิ้งต้นฉบับไว้ที่เดิมและเปิดสำเนาขึ้นในแผงของตัวเอง ซึ่งถ้าไม่มีคำบอกไว้ก็ง่ายที่จะเข้าใจผิดว่าไม่มีอะไรเกิดขึ้นเลย

การกด <kbd>Ctrl</kbd> ค้างไว้ (<kbd>Cmd</kbd> บน macOS) ขณะเลือกไฟล์จากรายการ หรือขณะกด <kbd>Enter</kbd> บนเส้นทาง จะส่งผลลัพธ์ไปยัง**แท็บใหม่**แทนแท็บนี้:

| | ปกติ | พร้อม <kbd>Ctrl</kbd> |
| --- | --- | --- |
| เลือกหรือพิมพ์ไฟล์ที่มีอยู่ | เปิดที่นี่ | เปิดในแท็บใหม่ |
| พิมพ์เส้นทางที่ยังไม่มี | ถาม แล้วเปิดที่นี่ | ถาม แล้วเปิดในแท็บใหม่ |
| ยืนยันเส้นทางในโหมดเปลี่ยนชื่อ/ย้าย | **ย้าย**โน้ตไปที่นั่น | **คัดลอก**ไปที่นั่นและเปิดสำเนาในแท็บใหม่ |

ปุ่มปรับถูกอ่านด้วยกฎของ Obsidian เอง มันจึงทำตัวเหมือนกับบนลิงก์หรือบนแถวของ File explorer ทุกประการ — คลิกกลางก็หมายถึง "แท็บใหม่" เช่นกัน <kbd>Ctrl</kbd>+<kbd>Alt</kbd> หมายถึงแยกบาน และ <kbd>Ctrl</kbd>+<kbd>Alt</kbd>+<kbd>Shift</kbd> หมายถึงหน้าต่างใหม่

การคัดลอกปฏิเสธที่จะเขียนทับ เหมือนกับการย้ายทุกประการ — รวมถึงทับเส้นทางของโน้ตเอง ซึ่งไม่มีอะไรให้คัดลอกอย่างสมเหตุสมผล นอกห้องนิรภัยการปฏิเสธนั้นก็ถูกบอกออกมาดัง ๆ เช่นกัน

ทั้งหมดนี้ทำงาน**ขณะที่รายการเปิดอยู่**ได้เช่นเดียวกับตอนที่ไม่เปิด: บนแถวที่ถูกไฮไลต์ ปุ่มปรับจะใช้กับแถวนั้น และเมื่อไม่ได้ยืนอยู่บนอะไรเลย มันจะใช้กับสิ่งที่คุณพิมพ์ไว้

## การเรียกดูนอกห้องนิรภัย

**สิ่งนี้ปิดอยู่โดยค่าเริ่มต้น** ให้เปิด **การเข้าถึงไฟล์ภายนอก** ในการตั้งค่าก่อน — การอ่านและเขียนนอกห้องนิรภัยเป็นสิ่งเดียวที่ปลั๊กอินนี้ทำแต่ Obsidian เองไม่ทำ จึงเป็นสิ่งที่ต้องเลือกเข้าไป ไม่ใช่สิ่งที่ต้องเลือกออก เมื่อปิดอยู่ ชื่อห้องนิรภัยจะเพียงแสดงห้องนิรภัยของคุณใน File explorer และไม่มีอะไรที่นี่มองเลยออกไปกว่านั้น

การคลิก **ชื่อห้องนิรภัย** (หรือไอคอน 🏠 เมื่อ *แสดงชื่อห้องนิรภัย* ปิดอยู่) จะเปิดลิสต์ของสถานที่แทนที่จะเป็นเนื้อหา ช่องที่เปิดขึ้นมาจะเก็บ **เส้นทางทั้งหมดที่คุณอยู่ เขียนออกมาเต็ม ๆ** โดยจุดที่มันเริ่มต้นถูกเลือกไว้ — การเลือกที่อื่น หรือพิมพ์ทับส่วนที่ถูกเลือก จึงสลับเฉพาะส่วนหน้านั้นและปล่อยส่วนที่เหลือของเส้นทางไว้ตรงหน้าคุณ **กดที่ชื่อเป็นครั้งที่สอง** — ดับเบิลคลิก — แล้วเครื่องหมายจะขยายครอบทั้งหมด ซึ่งเป็นวิธีที่เส้นทางแบบสัมบูรณ์ถูกยึดในท่าทางเดียวแทนที่จะกวาดด้วยมือ เปลี่ยนใจแล้วกด <kbd>Esc</kbd> แถวจะกลับไปเป็นอย่างที่เคยเป็น

การพิมพ์ที่นี่จะได้รับส่วนที่เหลือของชื่อสถานที่เสนอให้เหมือนที่อื่น ๆ และ <kbd>Tab</kbd> **ยึดสถานที่นั้นเข้ามา** — สถานที่ที่คุณกำลังชี้อยู่ หรือสถานที่ที่ชื่อนั้นหมายถึงได้เพียงที่เดียว ในกรณีที่หลายสถานที่ยังใช้ร่วมกับสิ่งที่คุณพิมพ์ไว้ การกดจะหยุดอยู่ที่จุดแยก เหมือนที่อื่น ๆ ทุกแห่ง การชี้ที่สถานที่หนึ่งจะแสดง **เส้นทางของสถานที่นั้นเอง** โดยทั้งหมดถูกเลือกไว้ ตามด้วยเส้นทางของโน้ตคุณเท่าที่มันไปถึงจริง ๆ ที่นั่น — ซึ่งเป็นสิ่งที่การเลือกมันจะพาคุณไปเจอพอดี สถานที่ไม่ใช่ก้าวหนึ่งภายในเส้นทางบนจอ แต่เป็นจุดให้นับเส้นทางทั้งหมดจากตรงนั้น ไม่มีสิ่งใดของที่ที่คุณเคยอยู่หลงเหลืออยู่ตรงหน้ามัน

สถานที่ที่มีให้เลือก:

- **ห้องนิรภัยอื่น ๆ ของคุณ** อ่านมาจากทะเบียนของ Obsidian เอง เรียงห้องที่เปิดล่าสุดก่อน แต่ละห้องอยู่ใต้ไอคอนห้องนิรภัยของ Obsidian เอง — ไอคอนที่แอปใช้กับคำสั่งเกี่ยวกับห้องนิรภัย ห้องนิรภัยที่คุณเปิดอยู่แล้วจะได้รูปบ้านแทน: มันคือจุดที่แถวนี้เริ่มต้นโดยค่าเริ่มต้น ไม่ใช่ที่ที่จะไป
- **โฟลเดอร์ส่วนตัว** อยู่ใต้ชื่อบัญชีของคุณเอง ทำเครื่องหมายด้วย `~` Lucide ไม่มีทิลเดอ ไอคอนนี้จึงถูกวาดโดยปลั๊กอินเองบนตาราง 24×24 ของ Lucide ด้วยความหนาเส้นเดียวกัน — เป็นไอคอนที่ชุดนั้นขาดไป ไม่ใช่ตัวอักษรข้อความที่มานั่งปนอยู่ในหมู่ไอคอน
- **รากของระบบไฟล์** ป้ายว่า `root` — ไม่แปล เพราะนั่นคือชื่อของมันในทุกระบบ — แทนที่จะเป็น `/` ซึ่งจะอ่านเหมือนก้าวเปล่าข้างตัวคั่นที่ตามมา
- **ไดรฟ์ที่เมานต์ไว้** พร้อมไอคอนตามชนิดในกรณีที่ตรวจได้ง่าย: การแชร์ผ่านเครือข่าย แผ่นออปติคัล ฟลอปปี และสื่อถอดได้จะมีไอคอนของตัวเอง ที่เหลือได้ไอคอนไดรฟ์ทั่วไป บน Windows ไดรฟ์จะแสดงเป็น `C:` พร้อมไอคอนทั่วไป — ชื่อโวลุมและชนิดที่แม่นยำต้องใช้ WMI ซึ่งจงใจไม่ทำ

การเลือกห้องนิรภัยอื่น **ไม่ได้สลับ Obsidian ไปยังห้องนั้น** ทุกอย่างที่คุณเปิดไว้ยังเปิดอยู่ เส้นทางเพียงเริ่มเรียกดูที่นั่น นี่คือเหตุผลทั้งหมดของการมีมันอยู่บนแถบเส้นทางแทนที่จะปล่อยให้เป็นเรื่องของตัวสลับห้องนิรภัยในแถบข้าง

มันยังลงจอด **ใกล้กับโน้ตที่คุณอยู่มากที่สุดเท่าที่สถานที่นั้นจะไปถึงได้จริง**

- ถ้าสถานที่ที่คุณเลือก *มี* โน้ตนั้นอยู่ — โฟลเดอร์ส่วนตัว หรือที่ใดก็ตามที่ห้องนิรภัยของคุณอาศัยอยู่ — คุณจะได้เส้นทางของมันจากตรงนั้น: เลือก `~` ขณะที่ `takeaways.md` เปิดอยู่ ช่องจะอ่านว่า `Vaults/your-vault/takeaways.md`
- ถ้าเป็นสถานที่ข้าง ๆ ที่นี้ — ห้องนิรภัยอื่น ไดรฟ์อื่น — เส้นทางสัมพัทธ์เดียวกันจะถูกลอง ลึกเท่าที่มันมีอยู่จริง ห้องนิรภัยมักเป็นสำเนาใกล้เคียงกันของกันและกัน และเหตุผลที่กระโดดไปที่หนึ่งมักเป็นโน้ตเดียวกันที่นั่น

ไม่ว่าทางไหน แถวจะอยู่ที่สถานที่ที่คุณเลือก และ **โฟลเดอร์แรกของเส้นทางนั้นจะเปิดขึ้นแบบถูกเลือก** รูปแบบเดียวกับที่การคลิกโฟลเดอร์หนึ่งให้: ก้าวที่คุณมีแนวโน้มจะเปลี่ยนมากที่สุดเมื่อกระโดดไปที่อื่น คือก้าวที่ใกล้ด้านบนที่สุด และส่วนที่เหลือของเส้นทางยังคงมองเห็นได้ขณะที่คุณเปลี่ยนมัน ไม่มีอะไรถูกใส่ไว้ล่วงหน้าโดยที่ไม่มีอยู่จริงบนดิสก์

### ขณะที่คุณอยู่ข้างนอก

เส้นทาง**เริ่มต้นที่สถานที่ที่คุณเลือก** ไม่ใช่ที่โครงสร้างไดเรกทอรีของเครื่อง — และช่องที่คุณได้จากการคลิกพื้นที่ว่างหรือกดปุ่มโฟกัสก็เช่นกัน: มันเก็บเส้นทางจากสถานที่นั้น ไม่ใช่เส้นทางสัมบูรณ์ของเครื่อง โดยทางที่ผ่านมาถูกยุบลงเหลือแค่ตัวสถานที่เองพอดีเหมือนที่มันยุบลงเหลือรากห้องนิรภัยข้างใน — เลือก `Archive` แล้วแถวจะอ่านว่า `Archive / notes / …` ไม่ใช่ `/home/you/Vaults/Archive/notes/…` ส่วนนำหน้าจะมีไอคอนตามชนิดของมัน (ห้องนิรภัย โฟลเดอร์ส่วนตัว ไดรฟ์) และ <kbd>Backspace</kbd> จะหยุดอยู่ตรงนั้นแทนที่จะเดินต่อขึ้นไปในส่วนที่เหลือของระบบไฟล์ เมื่อ *แสดงชื่อห้องนิรภัย* ปิดอยู่ ส่วนนั้นจะเป็นเพียงไอคอนเดี่ยว ๆ — การตั้งค่านี้เกี่ยวกับส่วนเปิดของแถว ไม่ว่ามันจะตั้งชื่อห้องนิรภัยใด ไม่ใช่แค่ของคุณเอง

แถบเส้นทางจะ**ถูกล้อมกรอบด้วยสีของข้อผิดพลาด** — วงแหวนเดียวกับที่โหมดเปลี่ยนชื่อวาด — ตราบเท่าที่มันชี้ออกไปนอกห้องนิรภัยของคุณ มันบ่งบอกสภาวะที่ดำรงอยู่ ไม่ใช่ชั่วขณะ: ตราบใดที่มันยังอยู่ ไม่มีการจัดการใด ๆ ของ Obsidian เองที่ใช้กับสิ่งที่แถวนี้กำลังแสดง และการเขียนถูกล็อกไว้จนกว่าคุณจะบอกเป็นอย่างอื่น

นอกจากนั้นการเรียกดูทำงานเหมือนอยู่ข้างใน: ชิ้นส่วน ตัวคั่น การพิมพ์ การเติมอัตโนมัติ <kbd>Backspace</kbd> เพื่อถอยออกหนึ่งก้าว กฎการมองเห็นเดียวกันก็ใช้ด้วย นามสกุลที่ไม่รองรับจึงยังต้องพึ่ง *แสดงผลไฟล์ทุกนามสกุล* ของ Obsidian และไฟล์ที่ขึ้นต้นด้วยจุดก็ยังต้องพึ่งการตั้งค่าของปลั๊กอินนี้

**คลิกขวาก็ใช้ได้ที่ข้างนอกนั้นด้วย** แม้จะเป็นเมนูที่ต่างออกไป: ตัวจัดการของ File Explorer เองต้องการไฟล์ที่ห้องนิรภัยรู้จัก รายการนอกจึงถูกสร้างขึ้นจากเส้นทางแทน มันเสนอการเปิด (ที่นี่ ทางขวา ในหน้าต่างใหม่ หรือในแอปเริ่มต้นของเดสก์ท็อป) *คัดลอกเส้นทาง* *แสดงในตัวจัดการไฟล์ของระบบ* และ — เมื่อแม่กุญแจเปิดอยู่ — *โน้ตใหม่* *โฟลเดอร์ใหม่* *สร้างสำเนา* *เปลี่ยนชื่อ…* และ *ลบ* **การลาก** ยังคงต้องการไฟล์ในห้องนิรภัยและยังใช้ไม่ได้

เมนูเดียวกันนี้อยู่บนไฟล์ที่เปิดในตัวแสดงด้วย โดยคลิกขวาหรือจากจุดสามจุดของบานเอง และมันจะถามแม่กุญแจในหัวเรื่องของมุมมองนั้น มันไม่ถามอะไรอื่นอีก: ไม่ว่าไฟล์จะถูกเรนเดอร์หรือแสดงเป็นต้นฉบับก็ไม่มีผลต่อว่ามันลบได้หรือไม่ และรูปภาพหรือ PDF — ซึ่งไม่มีมุมมองต้นฉบับเลย — ก็ลบได้เหมือนโน้ตทุกประการ *ลบ* หมายถึงถังขยะของเดสก์ท็อป จึงเรียกคืนจากตรงนั้นได้ ระบบที่ไม่มีถังขยะจะรายงานเช่นนั้นแทนที่จะทำลายไฟล์

การลบนอกห้องนิรภัยจะย้ายไฟล์ไปยัง**ถังขยะของระบบ** — Recycle Bin บน Windows, Trash บน macOS — ไม่ใช่การ unlink ข้างนอกนี้ไม่มีถังขยะของ Obsidian ให้กู้คืน การลบที่ไม่สามารถยกเลิกได้จึงไม่ถูกเสนอเลย: ในแพลตฟอร์มที่ไม่มีถังขยะ ความพยายามนั้นจะรายงานความล้มเหลวแทน

### การเขียนนอกห้องนิรภัย

ทุกอย่างที่เขียนจะ **ถูกล็อกโดยค่าเริ่มต้น** ตราบเท่าที่แถวชี้ออกไปนอกห้องนิรภัยของคุณ ตำแหน่งของสวิตช์เปลี่ยนชื่อในหัวเรื่องจะถูกแทนที่ด้วย **แม่กุญแจสีแดง** — สีเดียวกับวงแหวนรอบแถว และด้วยเหตุผลเดียวกัน: มันบ่งบอกการปฏิเสธ ทั้งสองเป็นตัวควบคุมเดียวในช่องเดียว จึงไม่มีคำถามเลยว่าตัวไหนกันตัวไหน

สามการกด ในวงจร:

| การกด | สิ่งที่คุณได้ |
| --- | --- |
| แม่กุญแจสีแดง | การเขียนที่นี่ได้รับอนุญาต แม่กุญแจถูกแทนที่ด้วยสวิตช์เปลี่ยนชื่อ/ย้าย |
| สวิตช์ | โหมดเปลี่ยนชื่อ/ย้าย เหมือนกับข้างในห้องนิรภัยทุกประการ |
| สวิตช์อีกครั้ง | โหมดสิ้นสุดและแม่กุญแจปิดลงอีกครั้ง — สิทธิ์ไม่คงอยู่นานกว่าสิ่งที่มันถูกเปิดขึ้นมาเพื่อ |

**ปุ่มเปลี่ยนชื่อก็ถามแม่กุญแจด้วย** นอกห้องนิรภัยของคุณ การกดมันจะทำให้แม่กุญแจกะพริบเปิดแล้วปิดแทนที่จะเปิดโหมดที่การยืนยันทุกครั้งจะถูกปฏิเสธ: การปฏิเสธมาถึงก่อนงานแทนที่จะมาทีหลัง กดที่แม่กุญแจ หรือกดปุ่มเปลี่ยนชื่ออีกครั้งภายในครึ่งวินาที — การกดครั้งที่สองจะให้สิทธิ์เท่ากับที่ปุ่มให้พอดี สำหรับสถานที่นี้ และเปิดโหมดเปลี่ยนชื่อไปพร้อมกัน

ข้างในห้องนิรภัยของคุณไม่มีแม่กุญแจ: ไม่มีอะไรให้ปลด และสวิตช์ก็ครองช่องนั้นเพียงตัวเดียว

สิทธิ์นี้ถูกให้ **แก่สถานที่หนึ่ง ไม่ใช่แก่ชั่วขณะหนึ่ง**: มันอยู่รอดผ่านทุกอย่างที่คุณจะทำขณะทำงานที่หนึ่งเดียว — จบการย้าย คลิกออกจากช่องป้อนข้อมูล เปิดไฟล์ — และจบลงเมื่อคุณเลือกห้องนิรภัย ไดรฟ์ หรือรากอื่นจากลิสต์ เมื่อแถวกลับไปยังไฟล์ในห้องนิรภัย หรือเมื่อกดครั้งที่สามนั้น ดังนั้นชุดการย้ายภายในโฟลเดอร์เดียวจึงใช้การกดเพียงครั้งเดียว ไม่ใช่ครั้งละไฟล์

เมื่อแม่กุญแจเปิดอยู่ แถบเส้นทางจะทำตัวที่ข้างนอกเหมือนที่ทำข้างใน:

| ท่าทาง | ผลลัพธ์ |
| --- | --- |
| พิมพ์ชื่อที่ยังไม่มี แล้ว <kbd>Enter</kbd> | คำถาม “สร้างเลยไหม” แบบเดียวกับข้างใน โฟลเดอร์แม่ที่ขาดไปก็ถูกสร้างด้วย ชื่อที่ไม่มีนามสกุลจะกลายเป็น `.md` เหมือนกับข้างในทุกประการ |
| โหมดเปลี่ยนชื่อ/ย้าย พิมพ์ชื่อใหม่ | เปลี่ยนชื่อไฟล์ที่แถวกำลังแสดงอยู่ ชื่อที่ไม่มีนามสกุลจะคงนามสกุลเดิมของไฟล์ไว้ — ข้างนอกนี้โฟลเดอร์หนึ่งเก็บไฟล์ได้ทุกชนิด และการเปลี่ยนชื่อไม่ควรแอบเปลี่ยน `.png` ให้เป็น `.md` |
| โหมดเปลี่ยนชื่อ/ย้าย เรียกดูที่อื่น แล้วเลือก **คงชื่อนี้ไว้** | ย้ายมันไปที่นั่นภายใต้ชื่อที่มันมีอยู่แล้ว |
| กด <kbd>Ctrl</kbd> ค้างไว้กับกรณีใดก็ได้ | คัดลอกแทนการย้าย และเปิดสำเนาในแท็บใหม่ |

เมื่อถูกล็อก ทุกอย่างข้างต้นจะรายงานว่าอะไรขวางอยู่แทนที่จะเกิดขึ้น ไม่มีอะไรถูกเขียนทับเลยในทั้งสองสถานะ: เป้าหมายที่มีอยู่แล้วจะถูกปฏิเสธ และการปฏิเสธนั้นเป็นของระบบไฟล์เอง (`COPYFILE_EXCL` การสร้างแบบผูกขาด) ไม่ใช่การตรวจสอบที่อาจแพ้การแข่งขัน การย้ายข้ามระบบไฟล์ — ออกจากแฟลชไดรฟ์ ออกจากการแชร์ผ่านเครือข่าย — จะถอยไปใช้วิธีคัดลอกแล้วลบ และต้นฉบับจะถูกลบก็ต่อเมื่อสำเนาลงที่เรียบร้อยแล้ว

**การย้ายโน้ต *ออกจาก* ห้องนิรภัยของคุณจะถามก่อน** `fileManager` ตามไฟล์ข้ามพรมแดนนั้นไม่ได้: ทุกลิงก์ที่ชี้ไปยังโน้ตนั้นจะหยุดแก้ไข ไม่มีอะไรอัปเดตมัน และโน้ตจะออกจากดัชนีของห้องนิรภัย ดังนั้นการย้ายจึงถูกเสนอเป็นการตัดสินใจแทนที่จะถูกปฏิเสธหรือทำอย่างเงียบ ๆ — กล่องโต้ตอบจะบอกว่ามันมีต้นทุนอะไรและมีกี่โน้ตที่ลิงก์มายังตัวที่คุณกำลังย้าย ยืนยันแล้วมันจะย้ายจริง ๆ: คัดลอกออกไป แล้วลบออกจากห้องนิรภัยผ่านการลบของ Obsidian เอง จึงกู้คืนได้เหมือนโน้ตที่ถูกลบทุกประการ และความล้มเหลวในขั้นตอนใดก็จะทิ้งโน้ตไว้ที่เดิม การกด <kbd>Ctrl</kbd> ค้างไว้ยังคงคัดลอกมันออกไปแทน ซึ่งไม่มีปัญหานั้นเลย การไปทางตรงข้าม — นำไฟล์ภายนอกเข้ามา*ใน*ห้องนิรภัย — ยังไม่ถูกเชื่อมต่อไว้

### การเปิดไฟล์ภายนอก

การเรียกดูระบบไฟล์สามารถเดินย้อนกลับ**เข้าไปในห้องนิรภัยที่คุณเปิดอยู่** — จากราก จากโฟลเดอร์ส่วนตัว จากที่ใดก็ตามที่ห้องนิรภัยของคุณอาศัยอยู่ ไฟล์ที่ไปถึงด้วยวิธีนั้นคือโน้ตธรรมดา จึงเปิดขึ้นเป็นเช่นนั้น: ตัวแก้ไขจริง ลิงก์และลิงก์ย้อนกลับ และแถวจะสแนปกลับไปยังเส้นทางที่มีรากเป็นห้องนิรภัย มีเพียงไฟล์ที่ Obsidian ไม่มีมุมมองให้เท่านั้นที่ยังอยู่ในตัวอย่าง เพราะข้างนอกนั้นตัวอย่างเป็นคำตอบที่ดีกว่า ในกรณีที่ตัวอย่างกำลังแสดงโน้ตแบบนั้นอยู่แล้ว — พื้นที่ทำงานที่เปิดใหม่ เช่น — บรรทัดบนสุดของมันจะเสนอ **เปิดใน *(ห้องนิรภัย)*** ซึ่งเป็นข้อเสนอเดียวกับที่ทำด้วยมือ

ตัวแก้ไขของ Obsidian ทำงานเฉพาะกับไฟล์ในห้องนิรภัย ไฟล์ภายนอกจึง**เปิดไม่ได้**ในฐานะโน้ตจริงที่มีลิงก์ ลิงก์ย้อนกลับ และอื่น ๆ — นั่นเป็นข้อจำกัดของแอป ไม่ใช่ของปลั๊กอินนี้ การเลือกไฟล์หนึ่งจะเปิด**ตัวอย่าง**แทน อ่านได้อย่างเดียวจนกว่าคุณจะบอกเป็นอย่างอื่น:

| ชนิด | แสดงเป็น |
| --- | --- |
| `.md`, `.markdown` | Markdown ที่เรนเดอร์แล้ว |
| `.html`, `.htm`, `.xhtml` | หน้าเว็บที่เรนเดอร์แล้ว |
| รูปภาพ เสียง วิดีโอ PDF | ตัวเล่น/ตัวแสดงดั้งเดิม |
| ไฟล์**ข้อความ**อื่น ๆ (`.json`, `.css`, `.log`, `.txt`, …) | ข้อความล้วนตามต้นฉบับ |
| รูปแบบไบนารีที่ไม่มีตัวแสดง (`.zip`, `.exe`, …) | ส่งให้ *เปิดในแอปเริ่มต้น* |

ตัวแสดงมีสองวิธีอ่านไฟล์หนึ่ง และเนื่องจากทั้งสองตัดกันเอง จึงแสดงเฉพาะวิธีที่คุณจะ**สลับไป**เท่านั้น:

| | สิ่งที่มันทำ | ค่าเริ่มต้นสำหรับ |
| --- | --- | --- |
| **ดูแบบ Markdown** | เรนเดอร์ไฟล์เป็นโน้ต แบบอ่านอย่างเดียว | `.md`, `.markdown` |
| **ดูเป็นหน้าเว็บ** | เรนเดอร์ไฟล์เป็นหน้าเว็บตามที่มันเป็น แบบอ่านอย่างเดียว | `.html`, `.htm`, `.xhtml` |
| **แก้ไขแบบข้อความ** | ต้นฉบับ แก้ไขได้ | อื่น ๆ ทั้งหมด |

นอกห้องนิรภัย **แก้ไขแบบข้อความ** ยังเป็นการกดที่ปลดสถานะอ่านอย่างเดียวด้วย — โหมดและสิทธิ์เป็นท่าทางเดียว ไม่ใช่สองปุ่มให้ต้องคิด มันจะย้อมสีแดง**ทุกครั้งที่การกดมันจะปลดสถานะอ่านอย่างเดียว** ไม่ว่าคุณจะกำลังเตรียมการแก้ไขในที่ หรือมาตรงจากมุมมองที่เรนเดอร์แล้ว ข้างในห้องนิรภัยไม่มีอะไรให้ปลด มันจึงคงเรียบธรรมดา ส่วน **ดูแบบ Markdown** จะได้สีเน้นอ่อน ๆ — เฉดเดียวกับที่ Obsidian ให้กับข้อความที่ถูกเลือก — เป็นการทำเครื่องหมายว่ามันคือทางกลับ ไม่ใช่การเรียกให้ลงมือ

เนื่องจากปุ่มติดตาม*การแก้ไข*ไม่ใช่โหมดดิบ ๆ ไฟล์ที่นั่งอยู่ในสถานะอ่านอย่างเดียวในมุมมองข้อความจึงยังเสนอ **แก้ไขแบบข้อความ**: นั่นคือการกดที่เตรียมมันไว้ ไฟล์ที่ไม่มีวันพิมพ์ลงไปได้ — ถูกตัดทอน หรืออ่านไม่ได้ — จะบอกว่า **ดูแบบข้อความ** แทน เพราะนั่นคือทั้งหมดที่การกดนี้ให้ได้

ค่าเริ่มต้นถูกเลือกให้เป็นประโยชน์แทนที่จะตรงตามตัวอักษร: `#` ในสคริปต์เชลล์เป็นคอมเมนต์ ไม่ใช่หัวข้อ การเรนเดอร์ `.log` เป็น Markdown จึงจะกลืนมันไปอย่างเงียบ ๆ ค่าเริ่มต้นทั้งสองแทนที่ได้เป็นรายไฟล์ และตัวเลือกนั้นจะเข้าไปในประวัติของบาน ปุ่มย้อนกลับ/ไปข้างหน้าและพื้นที่ทำงานที่เปิดใหม่จึงคงมันไว้ — โน้ตจำนวนมากอยู่ในไฟล์ `.txt` และไฟล์ `.md` จำนวนมากก็อ่านง่ายกว่าในรูปต้นฉบับ

#### หน้า HTML ได้รับอนุญาตให้ทำอะไรได้บ้าง

ไม่มีอะไรเลย หน้านั้นถูกแสดงในเฟรมที่**ถูกตัดสิทธิ์ทุกอย่างออก** — ไม่มีสคริปต์ ไม่มีฟอร์ม ไม่มีการนำทาง ไม่มีออริจินของตัวเอง — และมีนโยบายเนื้อหาที่ไม่ให้มันเข้าถึงเครือข่ายเลย นั่นไม่ใช่ความระมัดระวังเพื่อความระมัดระวังเฉย ๆ: หน้าไฟล์ในเครื่องที่โหลดด้วยวิธีปกติจะใช้ออริจินร่วมกับหน้าต่างนี้ และหน้าต่างนี้คือ Obsidian สคริปต์ในไฟล์ HTML ที่ดาวน์โหลดมาจึงจะทำงานอยู่ภายในแอปของคุณด้วยขอบเขตของแอปคุณเอง

สิ่งที่ต้องแลกไปคือทุกอย่างที่หน้านั้น*ทำ* สิ่งที่ยังคงอยู่คือทุกอย่างที่หน้านั้น*เป็น* สไตล์ชีตและรูปภาพที่อยู่ข้าง ๆ ไฟล์จะถูกอ่านเข้ามาและนำเข้าไปในเฟรม หน้าที่บันทึกไว้จึงยังคงหน้าตาเหมือนเดิม การอ้างอิงที่ชี้ออกไปนอกโฟลเดอร์ของหน้าเอง และการอ้างอิงไปยังที่ใดที่หนึ่งบนเว็บ จะถูกปล่อยไว้ตามที่เขียนไว้เป๊ะ ๆ และเพียงแค่ไม่โหลด — ไฟล์ในเครื่องไม่สามารถแอบบอกเซิร์ฟเวอร์ว่าคุณเปิดมันได้

สคริปต์ถูก**เอาออก**แทนที่จะแค่ถูกบล็อก เพื่อให้หน้าที่คุณเห็นกับต้นฉบับที่คุณสลับไปดูได้ต่างกันในทางเดียวที่ระบุไว้ชัดเจน แทนที่จะต่างกันในสิ่งที่เฟรมปฏิเสธจะรันอย่างเงียบ ๆ ลิงก์ภายในหน้าไม่ทำอะไรเลย เมื่อคุณต้องการของจริง — สคริปต์ เครือข่าย และทั้งหมด — *เปิดในแอปเริ่มต้น* จะส่งมันให้เบราว์เซอร์ของคุณ ซึ่งเป็นเครื่องมือที่ถูกต้องสำหรับสิ่งนั้น

**ไฟล์ในห้องนิรภัยของคุณแก้ไขได้ทันที** โดยไม่ต้องปลดล็อก: *แก้ไขแบบข้อความ* เป็นตัวแก้ไขจริง ๆ และเขียนกลับขณะที่คุณพิมพ์

**การแก้ไขถูกจำไว้ข้ามการสลับ** การไปที่ *ดูแบบ Markdown* จะระงับมันไว้ — การเรนเดอร์แบบนิ่งไม่มีที่ให้พิมพ์ และ Live Preview ต้องใช้ตัวแก้ไขของ Obsidian เอง ซึ่งมีเฉพาะสำหรับไฟล์ในห้องนิรภัย — จึงไม่มีอะไรอ้างว่าคุณกำลังแก้ไขอยู่ขณะอยู่ตรงนั้น การกลับไปที่ *แก้ไขแบบข้อความ* จะรับช่วงต่อจากจุดที่คุณค้างไว้

**ไฟล์นอกห้องนิรภัยเปิดขึ้นแบบอ่านอย่างเดียว และ *แก้ไขแบบข้อความ* เป็นตัวปลดสิ่งนั้น** การกดนั้นคือประตูทั้งบาน: จนกว่ามันจะเกิดขึ้น จะไม่มีอะไรข้างนอกนั้นถูกเขียน หลังจากนั้นไฟล์จะบันทึกขณะที่คุณพิมพ์ เหมือนไฟล์ในห้องนิรภัยทุกประการ และบรรทัดสถานะจะเปลี่ยนจากกุญแจเป็นดินสอ การปลดล็อกครอบคลุมไฟล์นั้นไฟล์เดียวในแท็บนั้นแท็บเดียว — การนำทางไปยังไฟล์อื่นจะล็อกใหม่ และมันถูกจงใจไม่เก็บไว้ในประวัติของแท็บ พื้นที่ทำงานที่เปิดใหม่จึงไม่มีวันกลับมาพร้อมกับการเขียนที่เตรียมพร้อมไว้แล้วบนไฟล์ระบบที่คุณจำไม่ได้ว่าเคยเปิด

**ไฟล์ที่ถูกตัดทอนยังคงอ่านอย่างเดียวไม่ว่าอย่างไร** — การบันทึกสิ่งที่อยู่บนจอจะทิ้งทุกอย่างที่เลยเพดานไป ปุ่มจึงไม่ถูกเสนอเลยแทนที่จะเสนอแล้วปฏิเสธ เช่นเดียวกันกับไฟล์ที่อ่านไม่สำเร็จ: ไม่มีอะไรให้เขียนกลับนอกจากบานเปล่า ๆ

หากการเขียนล้มเหลว — จุดเมานต์แบบอ่านอย่างเดียว ไฟล์ที่ไม่ใช่ของคุณ — เหตุผลของระบบเองจะแสดงในคำแจ้งเตือน

ไฟล์ที่ใหญ่มากจะถูกแสดงแบบตัดทอน และบรรทัดสถานะก็บอกไว้แทนที่จะปล่อยให้คุณค้นพบเอง — อยู่ข้างเงื่อนไขอื่น ๆ ไม่ใช่ต่อท้ายปุ่ม เพราะมันก็เป็นข้อเท็จจริงเกี่ยวกับไฟล์เหมือนข้ออื่น เพดานถูกวัดกับตัวเรนเดอร์จริงแทนที่จะเดา — การจัดวางข้อความหนึ่งเมกะไบต์ในบานเดียวฆ่ากระบวนการเรนเดอร์ของ Obsidian ทันที และ Markdown มีต้นทุนต่อไบต์หลายเท่าของข้อความล้วน ทั้งสองจึงมีขีดจำกัดแยกกัน และบรรทัดเดี่ยวที่ยาวมหาศาลก็ถูกย่อแม้ตัวไฟล์โดยรวมจะเล็ก

**บรรทัดสถานะคือป้ายกำกับ ส่วนคำอธิบายคือทูลทิป** แต่ละบรรทัดบอกสิ่งที่เป็นจริงด้วยคำน้อยที่สุดเท่าที่จำเป็น — *นอกห้องนิรภัย*, *ไม่มีตัวแก้ไขสำหรับไฟล์ชนิดนี้*, *ตัดทอน — ไฟล์ใหญ่เกินไป* — เพราะปุ่มที่อยู่ข้าง ๆ บอกอยู่แล้วว่าไฟล์อยู่ในสถานะใด การเอาเมาส์ไปวางบนบรรทัดหนึ่งจะให้ประโยคเต็ม: ทำไม Obsidian ถึงเปิดมันเป็นโน้ตไม่ได้ มิฉะนั้นจะเกิดอะไรขึ้นกับไฟล์ชนิดนี้ การตัดทอนทำให้คุณเสียอะไรไป

สิ่งนี้ใช้กับไฟล์**ในห้องนิรภัย**ของคุณด้วย Obsidian ส่งนามสกุลใดก็ตามที่มันไม่มีมุมมองให้ ตรงไปยังแอปเริ่มต้นของเดสก์ท็อป — `.txt` หรือ `.json` ในห้องนิรภัยของคุณจึงจะออกจาก Obsidian ไปเลย ตอนนี้ไฟล์เหล่านั้นเปิดในตัวแสดงเดียวกัน พร้อมวงแหวนสีส้ม เพราะ “เปิดมันใน Obsidian” คือสิ่งที่คุณขอ — และเมื่อเป็นไฟล์ในห้องนิรภัย มันก็แก้ไขได้ตรงนั้นโดยไม่ต้องปลดล็อกใด ๆ ไฟล์ไบนารีที่ไม่มีตัวแสดงยังคงพฤติกรรมของ Obsidian ไว้ ไม่มีอะไรให้แสดง

ตัวอย่างเปิดขึ้น**ในแท็บที่คุณอยู่** ปุ่มย้อนกลับ/ไปข้างหน้าจึงพาคุณกลับไปยังโน้ตที่คุณมา กด <kbd>Ctrl</kbd> ค้างไว้เพื่อเปิดแท็บใหม่เหมือนที่อื่น ๆ แถบหัวเรื่องยังคงแสดงเส้นทางของไฟล์ภายนอกตราบที่มันเปิดอยู่ คุณจึงเรียกดูต่อจากตรงนั้นได้

บรรทัดเงียบ ๆ เหนือเนื้อหาเสนอทางออกไว้ให้:

- **เปิดใน *(ห้องนิรภัย)*** — แสดงเมื่อไฟล์นั้นเป็นของห้องนิรภัยอื่นของคุณ ส่งมันให้ตัวจัดการ URI ของ Obsidian เอง ซึ่งจะเปิดหน้าต่างของห้องนิรภัยนั้นพร้อมโน้ตอยู่ในนั้น ในฐานะโน้ตจริงที่แก้ไขได้ หน้าต่างนี้จะถูกปล่อยไว้เหมือนเดิมทุกประการ ไม่มีอะไรสลับใต้ตัวคุณ
- **ดูแบบ Markdown** / **ดูเป็นหน้าเว็บ** / **แก้ไขแบบข้อความ** — สองวิธีอ่านที่ไฟล์นี้มี วิธีสุดท้ายยังปลดสถานะอ่านอย่างเดียวนอกห้องนิรภัยด้วย
- **เปิดในแอปเริ่มต้น** — ส่งไฟล์ให้แอปเริ่มต้นของเดสก์ท็อปคุณ รวมถึงรูปแบบไบนารีที่ตัวแสดงนี้แสดงไม่ได้ ใช้คำเดียวกับรายการของ Obsidian เองสำหรับการกระทำเดียวกัน เพราะมันคือการกระทำเดียวกัน

ตัวแสดงยังตอบสนอง**การคลิกขวา**ด้วย: ภายในตัวแก้ไขข้อความด้วย *ตัด* / *คัดลอก* / *วาง* / *เลือกทั้งหมด* และที่อื่นด้วยเมนูของไฟล์เอง เมนูจุดสามจุดของ Obsidian ในหัวเรื่องก็มีเมนูนั้นเช่นกัน — นอกห้องนิรภัยมันจะไม่มีอะไรให้นอกจาก *แบ่งขวา* และ *แบ่งลง*

ไม่มีอะไรนอกห้องนิรภัยของคุณถูกเขียน เว้นแต่คุณจะกด *แก้ไขแบบข้อความ* ก่อน ดูหัวข้อ [นอกห้องนิรภัย](README.th.md#นอกห้องนิรภัย) ใน README สำหรับการเปิดเผยฉบับเต็ม

## การลากไฟล์วางบนโฟลเดอร์ในเส้นทาง

ทุกโฟลเดอร์ในแถวเป็นเป้าหมายที่รับการวางได้ ดังนั้น **โน้ตที่ถูกลากไปวางบนโฟลเดอร์จะย้ายไปที่นั่น**
เส้นทางที่สั้นที่สุดในการทำแบบนี้คือระหว่างโน้ตกับโฟลเดอร์ใด ๆ ที่อยู่เหนือมัน
เพราะปลายทางอยู่บนหน้าจออยู่แล้ว ลากจากตัวจัดการไฟล์ จากลิสต์ จากชื่อของโน้ตเองในแถบหัวเรื่อง
หรือจากที่ไหนก็ตามใน Obsidian ที่สร้างไฟล์ขึ้นมาได้: มันคือการลากของแอปเอง
ดังนั้นป้ายบอกเมื่อชี้ค้าง เคอร์เซอร์ และการไฮไลต์ล้วนเป็นสิ่งที่ตัวจัดการไฟล์วาดขึ้นเอง

**ชื่อของห้องนิรภัยก็รับการวางได้เช่นกัน** เพราะมันคือโฟลเดอร์บนสุดของแถว
เป็นท่าเดียวที่จะนำโน้ตไปไว้ที่รากของห้องนิรภัยได้จากตรงนี้

**สามารถลากทั้งชุดที่เลือกไว้ได้พร้อมกัน** และมันจะย้ายไปพร้อมกันเป็นชุดเดียว
ถ้ามีไฟล์ใดในชุดนั้นย้ายไม่ได้ การวางจะถูกปฏิเสธทั้งหมด แทนที่จะย้ายบางไฟล์แล้วข้ามที่เหลือไปเงียบ ๆ

ลิงก์จะตามโน้ตไปด้วย เหมือนกับตอนย้ายจากตัวจัดการไฟล์หรือด้วยการพิมพ์เส้นทาง

โฟลเดอร์ที่ **รับการวางนี้ไม่ได้จะไม่แสดงอะไรของตัวเองเลย** — ไม่มีป้าย *ย้ายเข้าไปใน*
ไม่มีการไฮไลต์บนโฟลเดอร์ — แทนที่จะเสนอสิ่งที่จะล้มเหลวในภายหลัง
คำตอบของ Obsidian เองสำหรับแถบหัวเรื่อง คือ *เปิดในแท็บนี้* จะปรากฏอยู่ตรงนั้นแทน มีสามกรณี:

- โฟลเดอร์ที่ไฟล์นั้น **อยู่ในนั้นอยู่แล้ว** เพราะมันอยู่ที่นั่นแล้ว
- โฟลเดอร์ที่ถูกวางลง **ในตัวมันเองหรือในลูกหลานของมันเอง**
  ซึ่งจะทำให้มันไม่มีที่มาให้กลับไปได้
- ชุดที่เลือกไว้ซึ่งมี **ทั้งโฟลเดอร์และสิ่งที่อยู่ข้างในโฟลเดอร์นั้น**
  เพราะการย้ายโฟลเดอร์จะพาลูกไปด้วย

โฟลเดอร์ที่มี **ไฟล์ชื่อเดียวกัน** อยู่แล้วจะรับการวางและถามว่าจะจัดการกับไฟล์ที่ขวางทางนั้นอย่างไร
ด้วยไดอะล็อกเดียวกับตอนพิมพ์หรือเลือกชื่อที่ถูกใช้ไปแล้ว — ดู [ชื่อที่ถูกใช้ไปแล้ว](#ชื่อที่ถูกใช้ไปแล้ว)
ไม่มีอะไรในนี้ที่จะเขียนทับ

มีเพียงโฟลเดอร์ **ภายในห้องนิรภัยของคุณ** เท่านั้นที่รับการวาง ขณะที่แถวชี้ไปนอกห้องนิรภัย
ส่วนต่าง ๆ ของมันจะปฏิเสธการวาง เพราะการนำโน้ตออกจากห้องนิรภัยจะทำลายลิงก์ทุกอันที่ชี้มาที่มัน
เป็นการตัดสินใจที่ควรค่าแก่การถามมากกว่าแค่ท่าทางเดียว วิธีทำแบบนั้นอย่างตั้งใจยังคงเป็นการพิมพ์เส้นทาง
ซึ่งจะถามก่อนและบอกคุณว่ามีโน้ตกี่ฉบับที่จะได้รับผลกระทบ

## การลากข้อความหรือไฟล์เพื่อเขียนลงไป

เป้าหมายเดียวกันนี้รับ **เนื้อหา** ได้เช่นเดียวกับไฟล์ และทั้งสองแบบจะถูกแยกออกจากกัน
โดยดูจากสิ่งที่คุณกำลังลาก ไม่ใช่จากตำแหน่งที่คุณปล่อย

**บนโน้ตที่แถวระบุชื่ออยู่แล้ว** — ชื่อของโน้ตเอง หรือตัวคั่นที่โฟลเดอร์ของมันมีโน้ตประจำโฟลเดอร์ —
สิ่งที่คุณวางจะไปต่อท้ายมัน หลังบรรทัดว่างหนึ่งบรรทัด มันจะถามก่อน
เพราะนี่คือการเขียนลงในไฟล์ที่มีอยู่แล้ว และการลากเป็นท่าทางที่มือไม่มั่นคงอาจทำโดยไม่ตั้งใจได้
ข้อความจากตัวแก้ไข ไฟล์จากเดสก์ท็อปของคุณ และโน้ตที่ลากออกมาจากห้องนิรภัยนี้ ล้วนใช้ได้ทั้งหมด
ไฟล์จะถูกอ่านเป็นข้อความ และไฟล์แบบไบนารีจะถูกปฏิเสธ แทนที่จะถูกวางลงเป็นข้อความไร้ความหมายเต็มหน้าจอ

**บนที่ใดที่หนึ่ง — ชื่อห้องนิรภัยหรือโฟลเดอร์** — ยังไม่มีการเขียนอะไรลงไป เพราะยังไม่มีการตั้งชื่อ
ฟิลด์จะเปิดขึ้นตรงนั้นพร้อมสิ่งที่คุณวางอยู่ในตัว และชื่อที่คุณพิมพ์คือสิ่งที่ยืนยันมัน:
โน้ตใหม่จะถูก *สร้างขึ้น* พร้อมเนื้อหานั้น ส่วนโน้ตที่มีอยู่แล้วจะถูกถามเหมือนข้างต้นทุกประการ
<kbd>Esc</kbd> หรือคลิกที่อื่น จะปล่อยทุกอย่างทิ้งไป

**แถวจะเรืองแสงสีฟ้า** ขณะที่การลากซึ่งจะกลายเป็นเนื้อหาอยู่เหนือมัน
และคงเป็นสีฟ้าต่อไปขณะที่ฟิลด์กำลังถือเนื้อหานั้นอยู่ — สีฟ้าเดียวกัน สื่อความหมายเดียวกัน:
สิ่งที่จะเกิดขึ้นต่อไปเกี่ยวกับข้อความที่คุณกำลังถืออยู่ ไฟล์ที่ลากออกมาจากห้องนิรภัยของคุณเอง
ไปวางบนโฟลเดอร์ยังคงหมายถึง *ย้ายไปที่นั่น* คงการไฮไลต์ของ Obsidian เอง
และไม่เคยเรืองแสงสีฟ้า ท่าทางนั้นมีอยู่ก่อนแล้ว และเนื้อหาก็ถอยห่างจากมัน

## เมื่อเส้นทางยาวกว่าพื้นที่แถบ

ชื่อจะ **ถูกย่อลงมากกว่าจะถูกบีบอัด** ตามลำดับของสิ่งที่คุณมีแนวโน้มจะต้องการน้อยที่สุด:

1. **ชื่อห้องนิรภัยก่อน** จนเหลือแค่ไอคอนของมัน คุณรู้อยู่แล้วว่ากำลังอยู่ในห้องนิรภัยไหน
   ไอคอนยังคงบอกอยู่ว่าเส้นทางเริ่มต้นที่ไหน
2. **จากนั้นนามสกุลไฟล์** ถ้าคุณเปิดใช้งานไว้ — ตัวอักษรสามตัวเดียวกันในเกือบทุกไฟล์ในห้องนิรภัย
   มันจะแสดงทั้งหมดแทนที่จะถูกย่อ: นามสกุลครึ่งเดียวไม่บอกอะไรเลยที่การไม่มีนามสกุลบอกไม่ได้อยู่แล้ว
3. **จากนั้นโฟลเดอร์ ยาวที่สุดก่อน** ชื่อโฟลเดอร์ที่ยาวที่สุดจะถูกย่อลงมาเท่ากับความยาวของชื่อที่ยาวรองลงมา
   จากนั้นทั้งสองก็ถูกย่อไปพร้อมกัน และเป็นเช่นนี้ต่อไป แต่ละอันจะหยุดที่ขั้นต่ำของตัวเอง
   ดังนั้นโฟลเดอร์ที่ยาวมากอันหนึ่งจะสละทุกอย่างที่มีเหนือกว่าอันอื่นก่อนที่ชื่อสั้น ๆ ข้าง ๆ มัน
   จะเสียแม้แต่ตัวอักษรเดียว
4. **ชื่อของไฟล์เองเป็นลำดับสุดท้าย** และมันจะคงไว้ประมาณหกตัวอักษร นี่คือสิ่งที่แถบหัวเรื่องมีไว้เพื่อสิ่งนี้

พื้นที่จะถูกสละ **อย่างต่อเนื่อง** เป็นเศษเสี้ยวของพิกเซลแทนที่จะเป็นทีละตัวอักษร:
ชื่อที่กำลังยอมสละพื้นที่จะถูกตัดที่พิกเซลและจางหายไปใต้ `…` ของมัน
ดังนั้นเมื่อพื้นที่ถูกลากให้แคบลงช้า ๆ แถวจะแคบลงอย่างราบรื่น และไม่มีอะไรหลังจากนั้นขยับเป็นขั้น ๆ
ก่อนที่ตัวอักษรใดจะหายไป พื้นที่ว่างรอบตัวคั่นจะถูกใช้ไปก่อน — มันเป็นระยะห่างเดียวของแถว
และไม่มีต้นทุนด้านข้อมูลเลย — และชื่อที่ถูกย่อจะจบลงตรงที่ตัวคั่นเริ่มต้น
โดยไม่มีแถบกล่องว่างเปล่าคั่นระหว่างทั้งสอง

**ฟิลด์จะเก็บสิ่งที่มันถืออยู่ไว้** การเปิดฟิลด์เพื่อพิมพ์เส้นทางจะไม่บีบโฟลเดอร์ข้าง ๆ ให้พ้นทาง:
มันจะกว้างเท่ากับข้อความในตัวมันและขยายขึ้นเมื่อคุณพิมพ์ ดังนั้นเส้นทางที่ตามหลังจะคงทุกอย่าง
ที่ฟิลด์ไม่ต้องการไว้ เมื่อพื้นที่ไม่พอสำหรับทั้งสองอย่างเท่านั้นแถวจึงจะเลื่อน
และเมื่อนั้นฟิลด์คือสิ่งเดียวที่ไม่มีวันยอมสละพื้นที่ — มันคือข้อความที่กำลังถูกแก้ไข ไม่ใช่ชื่อที่กำลังถูกจัดให้พอดี

ไม่มีอะไรถูกตัดเกินกว่าจุดที่ทำให้มันต่างจากเพื่อนบ้าน: `Projects2025` และ `Projects2026`
ในโฟลเดอร์เดียวกันจะลดลงเหลือ `…025` และ `…026` แทนที่จะเป็นคำนำหน้าที่จะทำให้ทั้งสองกลายเป็นคำเดียวกัน
ในขณะที่ `Reports` ข้าง ๆ `Receipts` สามารถลดลงเหลือ `Rep…` ได้ นอกจากนี้ทุกชื่อยังคง **ความกว้างที่อ่านได้**
— ประมาณค่าตัวอักษรสี่ตัวสำหรับโฟลเดอร์และหกตัวสำหรับชื่อไฟล์ วัดจากฟอนต์ที่แถวถูกวาดขึ้นจริง ๆ
มากกว่าจะนับตัวอักษร ตัวอักษรแคบสี่ตัวและตัวอักษรกว้างสี่ตัวไม่ใช่ปริมาณชื่อเท่ากัน
ดังนั้น `lilliliillil` จึงได้รับอนุญาตให้คงตัวเองไว้ได้มากกว่า `WWMMWWMMWWMM`
และสิ่งที่เหลืออยู่บนหน้าจอจะมีขนาดเท่ากันไม่ว่ากรณีใด ชื่อสั้น ๆ จะถูกปล่อยไว้เฉย ๆ ทั้งหมด
— ชื่อที่ถูกบดลงจนเหลือ `A…` นั้นไม่ซ้ำใครแต่ก็ยังอ่านไม่ออกอยู่ดี **ช่องว่างไม่นับรวมด้วย**
หกตัวอักษรที่บอกว่าไฟล์นี้คือไฟล์ไหนคือหกตัวอักษรที่ควรค่าแก่การอ่าน ดังนั้นช่องว่างระหว่างตัวอักษร
จึงไปด้วยฟรี ๆ และไม่มีช่องว่างใดถูกทิ้งไว้ติดกับ `…` ซึ่งจะมองไม่เห็นอยู่แล้ว

**ชื่อจะถูกตัดตรงจุดที่เพื่อนบ้านเห็นตรงกัน และตรงกลางเมื่อไม่เห็นตรงกันเลย** โฟลเดอร์สองชื่อ
คือ `aaaa-common-one` และ `aaaa-common-two` มีทุกอย่างเหมือนกันยกเว้นตัวอักษรสามตัวสุดท้าย
ดังนั้นการตัดส่วนท้ายจึงคงส่วนที่ไม่บอกอะไรไว้: มันลดลงเหลือ `…one` และ `…two` แทน
ซึ่งสั้นกว่า *และ* บอกความแตกต่างได้ด้วย ที่ใดที่ความเหมือนอยู่ที่ท้าย — `alpha-draft`
ข้าง ๆ `beta-draft` — ท้ายคือส่วนที่หายไป ที่ใดที่ความเหมือนอยู่ทั้งสองปลาย
สิ่งที่เหลือคือตรงกลาง ชื่อที่ไม่มีเพื่อนบ้านใกล้เคียงจะเสียส่วนตรงกลางไป เพราะชื่อเริ่มต้นด้วยว่ามันคืออะไร
และจบลงด้วยว่ามันเป็นตัวไหน — สำหรับไฟล์ คือนามสกุลของมัน: `annual…2026.md`

ความเหมือนกันแค่ช่วงสั้น ๆ ไม่นับ `parallel structures` บังเอิญลงท้ายด้วยตัวอักษรสองตัวเดียวกัน
กับ `Schemes` ข้าง ๆ มัน และนั่นไม่ใช่เหตุผลที่จะคงทั้งสองไว้เต็ม ๆ — แค่สามตัวอักษรจากด้านหน้า
ก็บอกความแตกต่างได้แล้ว

ไม่มีอะไรตกไปบรรทัดที่สอง เมื่อแม้แต่ชื่อที่ตรงไปตรงมาสั้นที่สุดก็ยังไม่พอดี แถวจะ **เลื่อนไปด้านข้าง**
จอดอยู่ที่ปลายด้านที่ไฟล์อยู่ — ณ จุดนั้นไม่มีอะไรเหลือให้บีบอัดอีกแล้ว
และการตัดต่อไปจะเป็นการซ่อนมากกว่าการย่อ ล้อเลื่อนจะเลื่อนมันไปตามตำแหน่งของตัวชี้ที่อยู่เหนือแถว
และสามารถไปถึงปลายทั้งสองด้านได้: ขณะที่มันเลื่อน แถวจะจัดตำแหน่งไปที่จุดเริ่มต้นของมัน
ไม่ว่าการตั้งค่าการจัดตำแหน่งจะระบุอย่างไร เพราะเนื้อหาที่จัดกึ่งกลางในกล่องที่มันล้นออกมา
จะล้นออกไปทั้งด้านซ้ายและด้านขวา — และครึ่งนั้นไม่สามารถเลื่อนไปถึงได้เลย

**ชี้ไปที่ชื่อที่ถูกย่อและมันจะกลับมาเต็ม ๆ** ตราบเท่าที่คุณยังชี้อยู่ที่มัน เลื่อนไปที่ขอบซ้าย
เพื่อให้ทุกส่วนที่กลับมาปรากฏบนหน้าจอ **คลิกที่หนึ่งและมันจะคงอยู่**: ฟิลด์จะเปิดขึ้นแสดงโฟลเดอร์
ที่คุณคลิก สิ่งที่เสนอต่อจากมัน และสิ่งที่คุณพิมพ์ และมันจะแสดงต่อไปแม้ตัวชี้จะเลื่อนออกไปแล้ว
ชื่อจะอยู่กับที่ขณะที่คุณกำลังเลื่อนแถวหรือพิมพ์ลงในมัน — ชื่อหนึ่งเปิดขึ้นเองภายใต้ท่าทาง
ที่ตั้งใจจะอ่านแถวจะเลื่อนทุกอย่างที่อยู่หลังมันออกไปจากใต้ตัวคุณ

**ส่วนแรกสุดจะมีคำแนะนำเครื่องมือติดอยู่เสมอ และมันคือเส้นทางแบบสัมบูรณ์** —
`/home/you/Vaults/Notes` หรือที่ใดก็ตามที่แถวเริ่มต้น นั่นคือสิ่งเดียวเกี่ยวกับแถว
ที่ไม่มีอะไรบนหน้าจอบอกได้: ชื่อบอกคุณว่าเป็นห้องนิรภัย *ไหน* ไม่เคยบอกว่ามันอยู่ที่ไหน
มันอยู่ตรงนั้นไม่ว่าจะมีอะไรถูกย่อลงหรือไม่ก็ตาม

เมื่อ **แสดงชื่อห้องนิรภัย** ปิดอยู่ ชื่อจะไม่ถูกลบออก เพียงแค่ถูกลดขนาดให้เหลือศูนย์
ดังนั้นการชี้ไปที่ไอคอนจะทำให้มันกลับมาแบบเดียวกันกับการชี้ไปที่ชื่อที่แถวต้องย่อลง

**แสดงนามสกุลไฟล์** จะใส่นามสกุลกลับเข้าไปในชื่อไฟล์ของแถว เมื่อปิด — ค่าเริ่มต้น — แถวจะตั้งชื่อโน้ต
แบบเดียวกับที่ Obsidian ตั้งชื่อให้ โดยไม่มี `.md` ที่เกือบทุกไฟล์ในห้องนิรภัยมีร่วมกัน
เมื่อเปิด มันจะตั้งชื่อแบบเดียวกับที่ระบบไฟล์ทำ ซึ่งเป็นสิ่งที่คุณต้องการเมื่อห้องนิรภัยมีมากกว่าแค่โน้ต
มันยังเป็นสิ่งที่สองที่แถวสละเมื่อพื้นที่ไม่พอ ต่อจากชื่อห้องนิรภัยทันที
คำแนะนำเครื่องมือจะให้ส่วนที่เหลือแก่คุณ: ไม่ใช่แค่ชื่อ แต่ทุกอย่างที่แถวแสดงอยู่ใต้มัน
ในรูปแบบ `…/name/folder/note.md` ดังนั้นการชี้ค้างครั้งเดียวจะตอบทั้ง "นี่คืออะไร"
และ "มันอยู่ใต้อะไร" ไอคอนห้องนิรภัยจะตั้งชื่อห้องนิรภัยของมันแบบเดียวกัน
เมื่อชื่อถูกปิดไว้หรือถูกบีบจนหายไป

| แม่กุญแจสี **แดง** แทนที่ปุ่มสลับเปลี่ยนชื่อ | แถวชี้ไปนอกห้องนิรภัยของคุณและการเขียนที่นั่นยังคงถูกล็อกอยู่ | สีแดงเดียวกับวงแหวน ด้วยเหตุผลเดียวกัน: มันบ่งชี้การปฏิเสธ การกดมันจะอนุญาตให้เขียนที่นี่ได้และคืนช่องนี้ให้กับปุ่มสลับ — ดู [การเขียนนอกห้องนิรภัย](#การเขียนนอกห้องนิรภัย) |

**วงแหวนทั้งสองเป็นอิสระจากกัน และทั้งคู่สามารถเกิดขึ้นพร้อมกันได้** — ไฟล์ `.json` ภายนอกอยู่นอกห้องนิรภัยของคุณ *และ* เป็นชนิดที่ Obsidian ไม่มีตัวแก้ไขด้วย ในตัวแสดงผล ทั้งสองจะปรากฏเป็นบรรทัดแยกกัน แต่ละบรรทัดระบุเพียงข้อเท็จจริงของตัวเอง บนแถบเส้นทาง สีแดงจะชนะเมื่อทั้งสองอย่างเข้าเงื่อนไข เพราะวงแหวนสองอันจะเป็นแค่สัญญาณรบกวน ข้อความสีแดงเป็นสิ่งที่สามที่แยกจากกันโดยสิ้นเชิง: มันเกี่ยวกับสิ่งที่กำลังถูกพิมพ์ ไม่ใช่เกี่ยวกับที่ที่แถวชี้ไป ดังนั้นมันสามารถปรากฏภายในวงแหวนใดวงแหวนหนึ่งหรือไม่มีเลยก็ได้

ระดับสีส้มถูกจำกัดไว้อย่างตั้งใจ ชนิดไฟล์ที่ลงทะเบียนไว้แล้ว (Markdown, canvas, รูปภาพ, PDF, เสียง, วิดีโอ) ถูกจัดการอย่างเหมาะสมและไม่ได้รับสีอะไร ไฟล์ไบนารีก็ไม่ได้รับสีอะไรเช่นกัน — คุณจะไม่แก้ไข `.zip` จนกลายเป็นความยุ่งเหยิงโดยไม่ตั้งใจ สิ่งที่เหลืออยู่คือความเสี่ยงพอดี: ไฟล์ `.json`, `.css` หรือ `.log` ที่ **แสดงไฟล์ทุกประเภท** ทำให้มองเห็นได้ ลิสต์กว้างกว่านั้นโดยตั้งใจ: ที่นั่น ทุกอย่างที่ไม่ใช่โน้ตจะเป็นสีส้ม — ดู [รายการในลิสต์ถูกไล่สีอย่างไร](#รายการในลิสต์ถูกไล่สีอย่างไร)

## โหมดย้าย/เปลี่ยนชื่อ

ปุ่มดินสอที่ขวาสุดของแถบหัวเรื่อง — ข้าง ๆ ปุ่มโหมดมุมมอง ขนาดเท่ากับปุ่มดั้งเดิม — สลับโหมดย้าย/เปลี่ยนชื่อ นอกห้องนิรภัยของคุณ แม่กุญแจสีแดงจะยืนอยู่แทนที่จนกว่าคุณจะกดมัน ดู [การเขียนนอกห้องนิรภัย](#การเขียนนอกห้องนิรภัย) แถวหัวเรื่องจะถูกใส่กรอบด้วยสีเน้น เหมือนกับการเปลี่ยนชื่อในตัวจัดการไฟล์ทุกประการ การคลิกและการกดปุ่มแบบเดียวกันตอนนี้จะยืนยันการย้ายหรือเปลี่ยนชื่อผ่าน `fileManager.renameFile` ของ Obsidian ดังนั้นลิงก์ทั้งหมดที่ไปยังโน้ตจะตามไปด้วย

ขณะเปลี่ยนชื่อ:

- ชื่อไฟล์ปัจจุบันถูกปักไว้ในลิสต์ของทุกโฟลเดอร์ ดังนั้นการย้ายโน้ตโดยไม่เปลี่ยนชื่อจึงเป็นการคลิกเพียงครั้งเดียว
- ชื่อที่ถูกใช้ไปแล้วในโฟลเดอร์เป้าหมายจะเป็นสี **แดง** — โฟลเดอร์ที่มีชื่อนั้นอยู่แล้ว และไฟล์ชื่อนั้น — ดังนั้นการชนกันจะแสดงก่อนที่คุณจะเลือก ยังคงเลือกได้อยู่: ดูด้านล่าง
- อินพุตจะถูกตรวจสอบสดตามกฎการเปลี่ยนชื่อของ Obsidian เอง — ชุดตัวอักษรเดียวกัน ข้อความเดียวกัน คำแนะนำเครื่องมือสีแดงเดียวกับที่คุณได้เมื่อเปลี่ยนชื่อในแผนผังไฟล์ — ดังนั้นชื่อที่ไม่ถูกต้องจะถูกทำเครื่องหมายขณะที่คุณพิมพ์ และไม่สามารถยืนยันได้
- การคลิกนอกแถบหัวเรื่อง หรือแถบหัวเรื่องเสียโฟกัส จะจบโหมดเปลี่ยนชื่อ

### ชื่อที่ถูกใช้ไปแล้ว

การย้ายหรือเปลี่ยนชื่อไปเป็นชื่อที่มีอยู่แล้ว **จะถามแทนที่จะปฏิเสธ**
ไดอะล็อกจะเปิดขึ้นพร้อมเส้นทางสองเส้นที่คุณสามารถแก้ไขได้: ไฟล์ของคุณจะไปที่ไหน
และไฟล์ที่ขวางทางจะไปที่ไหน — เป็นสีแดงตราบเท่าที่ยังถูกใช้อยู่ แต่ละเส้นทางยังถูกวาด
แบบเดียวกับที่แถบเส้นทางวาด โดยส่วนที่ต่างกันจะถูกลงสีและถูกย่อเป็นลำดับสุดท้าย
ดังนั้นเส้นทางที่ยาวก็ยังแสดงสิ่งที่เปลี่ยนแปลงอยู่

ทั้งสองฟิลด์มีลิสต์ ฟิลด์ที่สองมีทางออกทั่วไป:

- **สลับตำแหน่ง** — มันไปยังโฟลเดอร์เดิมของไฟล์คุณ ภายใต้ชื่อของมันเอง
- **สลับชื่อ** — มันอยู่ที่เดิมและรับชื่อเดิมของไฟล์คุณ
- **สลับทั้งสอง** — มันรับเส้นทางเดิมของไฟล์คุณ
- `-1`, `-bak` และ `-old` ต่อท้ายชื่อของมันเอง
- ชื่อทั้งสองที่ไฟล์ทั้งสองเคยมี

ลิสต์แรกเสนอที่ที่ไฟล์คุณกำลังจะไป **อยู่ที่เดิม** ชื่อของมันเองในโฟลเดอร์เป้าหมาย
และ `-1`, `-bak` และ `-old` ต่อท้าย ทางออกที่เส้นทางถูกใช้ไปแล้วจะถูกทำเป็นสีจางและเลือกไม่ได้
การเลือกอันหนึ่งจะ **แค่เติมลงในฟิลด์** — คุณยังแก้ไขมันได้อยู่ — และ **ยืนยัน** จะย้ายทั้งคู่
ลิงก์และทุกอย่าง; **ยกเลิก** จะไม่ย้ายอะไรเลย การเลือกชื่อที่ถูกใช้ไปแล้วจากลิสต์จะถามแบบเดียวกัน
และการวางโน้ตลงบนโฟลเดอร์ที่มีชื่อนั้นอยู่แล้วก็เช่นกัน

## ปุ่มเดียวสำหรับการเปลี่ยนชื่อทั้งสองแบบ

คำสั่งเปลี่ยนชื่อ (<kbd>F2</kbd> โดยค่าเริ่มต้น หรือปุ่มใดก็ตามที่คุณผูกไว้แทน) จะ**สลับ**ระหว่างการเปลี่ยนชื่อแบบ inline title ของ Obsidian กับแถบพาธในหัวเรื่องของปลั๊กอินนี้ ถ้าคุณปิด inline title ของ Obsidian ไว้ แถบพาธในหัวเรื่องจะกลายเป็นเป้าหมายเดียว ปุ่มนี้จึงไม่มีวันไร้ผล

ในแถบพาธ มันจะเปิดที่**ชื่อโดยไม่มีนามสกุล** — ซึ่งเป็นสิ่งที่การเปลี่ยนชื่อเกือบทุกครั้งต้องการแก้ไข และเป็นสิ่งเดียวกับที่การคลิกชื่อจะเลือกไว้ กดอีกครั้งแล้วมันจะทำสิ่งเดียวกับที่ <kbd>Tab</kbd> จะทำตรงนั้น: บนชื่อ นั่นคือขั้นถัดไป — ชื่อพร้อมนามสกุล เส้นทางจากโฟลเดอร์ห้องนิรภัยของคุณ เส้นทางจากรากของระบบ; เมื่อมีการพิมพ์บางอย่างไว้ มันจะเติมให้สมบูรณ์เหมือนที่ <kbd>Tab</kbd> ทำ

**วงจรปิดที่หัวเรื่อง** การกดห้าครั้งพาคุณวนครบรอบ — inline title, ชื่อ, ชื่อพร้อมนามสกุล, เส้นทางจากห้องนิรภัยของคุณ, เส้นทางจากรากของระบบ — และครั้งที่หกคือ inline title อีกครั้ง การกดครั้งนั้นเป็นครั้งเดียวที่ต่างจาก <kbd>Tab</kbd> ซึ่งจะวนกลับไปด้านหน้าของเส้นทางแทน — และครั้งที่เจ็ดไปยังจุดเดียวกับที่รอบของ <kbd>Tab</kbd> ไป: รากของห้องนิรภัย โดยมีเส้นทางทั้งหมดอยู่ในช่องและโฟลเดอร์แรกถูกทำเครื่องหมายไว้ ดังนั้นทุกขั้นที่ <kbd>Tab</kbd> ไปถึง ปุ่มนี้ก็ไปถึงเช่นกัน

คำสั่ง **โฟกัสแถบพาธ** ทำสิ่งเดียวกันภายในช่อง — ไม่ว่า <kbd>Tab</kbd> จะทำอะไร — และตรงจุดที่ <kbd>Tab</kbd> จะวนรอบ มันจะส่งเคอร์เซอร์กลับไปที่โน้ตแทน การกดครั้งถัดไปของมันคือรอบนั้น: รากของห้องนิรภัย โดยมีโฟลเดอร์แรกถูกทำเครื่องหมายไว้

**ในช่องที่เปิดอยู่แล้ว** ปุ่มนี้จะเปลี่ยนมันให้เป็นการเปลี่ยนชื่อตรงจุดที่มันอยู่ — โดยคงข้อความ ตำแหน่งเคอร์เซอร์ และการเลือกไว้ — และ **โฟกัสแถบพาธ** จะนำการเปลี่ยนชื่อกลับออกจากมันด้วยวิธีเดียวกัน **สิ่งอื่นใด** ที่ถูกกดหรือคลิกระหว่างการกดจะเริ่มวงจรใดวงจรหนึ่งใหม่ ดังนั้นการกดหลังจากที่คุณกำลังแก้ไขอยู่จะไม่มีวันตกอยู่ที่ขั้นเดิมที่เหลือจากก่อนหน้า

นอกห้องนิรภัย ปุ่มนี้ก็ทำงานเช่นกัน — ที่นั่นไม่มี inline title ดังนั้นการกดครั้งแรกจะไปที่แถบพาธโดยตรง

สิ่งนี้ทำงานโดยการห่อคำสั่ง `workspace:edit-file-title` แทนที่จะแย่งปุ่มไป การผูกทางลัดใหม่และการเรียกคำสั่งจากพาเลตต์จึงทำงานได้เหมือนเดิมทั้งคู่

## รายการในลิสต์ถูกไล่สีอย่างไร

| สี | หมายถึง |
| --- | --- |
| **สีม่วง** | โน้ต (`.md`, `.markdown`) — สิ่งที่ Obsidian จะเปิดในฐานะโน้ต ถูกคัดออกมาจากโฟลเดอร์ที่มีเนื้อหาปะปนกัน |
| **สีส้ม** | ไม่ใช่โน้ต — สิ่งใดก็ตามที่ Obsidian จะไม่เปิดในฐานะโน้ต ตั้งแต่ PDF ไปจนถึง `.txt` และรายการ `:page` ที่มากับมัน โฟลเดอร์ที่มีเนื้อหาปะปนกันจะถูกอ่านเพื่อหาโน้ตในนั้น และการใช้สีเดียวสำหรับทุกอย่างที่เหลือบอกได้เร็วกว่าการเตือนแค่บางรายการ ดู [สองสีของคำเตือน](#สองสีของคำเตือน) |
| **สีจาง** | นอกห้องนิรภัยของคุณ ดังนั้นการจัดการแบบห้องนิรภัยจึงไม่มีผล |
| **สีฟ้า** ตัวหนา | ตำแหน่งที่คุณอยู่แล้ว: โน้ตของแถบนี้เอง และโฟลเดอร์ที่แถบพาธยืนอยู่ ในโหมดเปลี่ยนชื่อ/ย้าย รายการ *คงชื่อนี้ไว้* จะยืนแทนที่โน้ต — เป็นโน้ตเดียวกันไม่ว่ากรณีใด |
| **สีแดง** | เฉพาะโหมดเปลี่ยนชื่อ/ย้ายเท่านั้น: ชื่อนี้ถูกใช้ไปแล้ว ยังคงเลือกได้ — การเลือกจะถามว่าจะทำอย่างไรกับไฟล์ที่ขวางอยู่ ดู [ชื่อที่ถูกใช้แล้ว](#ชื่อที่ถูกใช้ไปแล้ว) |

**โฟลเดอร์เป็นตัวหนา** ดังนั้นโน้ตของโฟลเดอร์เองจึงไม่ต้องมีสีเฉพาะเพื่อแยกตัวออกจากโฟลเดอร์: มันเป็นสีม่วงเหมือนโน้ตอื่น ๆ **เส้นที่ขอบของแถว** ทำเครื่องหมายชื่อที่ขึ้นต้นด้วยสิ่งที่คุณพิมพ์ — สีฟ้าเมื่อตรงกันมากขึ้นไปอีก สีเขียวบนกิ่งที่ข้อเสนอเลือกไป ดู [การพิมพ์เส้นทาง](#การพิมพ์เส้นทาง)

ช่องนี้ใช้สีเดียวกันสำหรับสิ่งที่มันตั้งชื่อ — ดู [การพิมพ์เส้นทาง](#การพิมพ์เส้นทาง)

## กฎการมองเห็น

- ไฟล์ที่มีนามสกุลไม่รองรับจะปรากฏในลิสต์ก็ต่อเมื่อการตั้งค่า **Detect all file extensions** ของ Obsidian เปิดอยู่ — **ภายในห้องนิรภัย** เท่านั้น นอกห้องนิรภัย การตั้งค่านี้ไม่มีผล: มันควบคุมว่าห้องนิรภัยจัดทำดัชนีอะไร และไม่มีอะไรข้างนอกนั้นอยู่ในห้องนิรภัยเลย ดังนั้น `.txt` ที่อยู่ข้างโน้ตของคุณจึงถูกแสดงในลิสต์เสมอ
- ลิสต์แสดงได้สูงสุด 1,000 รายการ มากกว่าขีดจำกัดของ Obsidian เองสิบเท่า เมื่อโฟลเดอร์มีมากกว่านั้น แถวสุดท้ายจะบอกว่ามีกี่รายการที่ถูกตัดออกไป พิมพ์ต่อเพื่อจำกัดรายการให้แคบลง
- ไฟล์ที่ซ่อนอยู่และโฟลเดอร์ที่ซ่อนอยู่จะปรากฏก็ต่อเมื่อการตั้งค่า **แสดงไฟล์ที่ซ่อนอยู่** ของปลั๊กอินนี้เปิดอยู่
- **การป้องกันการเขียนทับทำงานเหมือนกันไม่ว่าจะมองเห็นหรือไม่** — ไฟล์ที่ซ่อนอยู่ก็ยังคงกันไม่ให้คุณเขียนทับมันอยู่ดี

## การเปลี่ยนไอคอน

Lure วาดไอคอนสามแบบ: ไอคอนรากของห้องนิรภัย (เมื่อ **แสดงชื่อห้องนิรภัย** ปิดอยู่) ปุ่มสลับเปลี่ยนชื่อ/ย้าย และกุญแจที่ยืนแทนที่มันขณะที่การเขียนนอกห้องนิรภัยถูกล็อกอยู่ ทั้งหมดสามารถสลับได้จากธีมหรือ CSS snippet — ตั้งค่าสัญลักษณ์ทดแทนและซ่อนสัญลักษณ์ที่มากับปลั๊กอินในกฎเดียว:

```css
.lure-vault-icon {
	--lure-icon-glyph: "🏠";
	--lure-icon-svg: none;
}

.lure-rename-btn {
	--lure-icon-glyph: "✎";
	--lure-icon-svg: none;
}

/* Only ever shown shut: opening it hands the slot to the rename toggle. */
.lure-unlock-btn {
	--lure-icon-glyph: "🔒";
	--lure-icon-svg: none;
}
```

`--lure-icon-glyph` รับอะไรก็ได้ที่ใช้ได้ใน `content` ของ CSS ดังนั้น `url(...)` จึงใช้กับรูปภาพได้ดีพอ ๆ กับสัญลักษณ์ข้อความหรืออีโมจิ ปล่อย `--lure-icon-svg` ไว้อย่างนั้นหากต้องการคงไอคอน Lucide ไว้และวาดสัญลักษณ์ของคุณไว้ข้าง ๆ
