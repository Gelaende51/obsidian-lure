# 使い方

[← README に戻る](README.ja.md)

> **このガイドは Lure 1.0 について書かれています。** その後に加わった八つの節 — <kbd>Tab</kbd> による補完、右クリックの回数、ノートを行内のフォルダーへドラッグすること、パスがペインより長いときの挙動など — は今のところ[英語版ガイド](../usage.md)にしかありません。

## パス表示

ノートの保管庫内での完全なパスが、ビューヘッダー — タブ列の下にあり、戻る／進むボタンも並ぶバー — の素のファイル名を置き換えます。

この行でクリックできるものは二つあり、どちらが何をするかは **フォルダ名で一覧を開く** が決めます:

| | フォルダ名 | その後ろの区切り文字 |
| --- | --- | --- |
| **オン**（既定） | そのフォルダを編集対象として選択 | フォルダを開く |
| **オフ** | フォルダを開く | そのフォルダへ下る |

「フォルダを開く」とは、プラグインのない Obsidian でその要素をクリックしたときの動作を指します。そこを見張るプラグインがなければ、フォルダはサイドバーのファイルエクスプローラーで表示されます — ハイライトされ、中身が見えるように展開されます。

[Folder notes](obsidian://show-plugin?id=folder-notes) が入っていると、同じクリックが代わりにそのフォルダのノートを開きます。ヘッダーのパスを横取りすることが確認できた唯一のフォルダノート系プラグインです。[Folder Note](obsidian://show-plugin?id=folder-note-plugin) と [create folder notes with dropdown](obsidian://show-plugin?id=create-folder-notes-with-dropdown) はフォルダノートを扱いますが、パスのクリックは見ていないので、これらと併用すると区切り文字は従来どおりフォルダを表示します。[互換性](../compatibility.md#verified-against)を参照してください。

区切り文字に下線が付くのは、**その手前のフォルダに実際にフォルダノートがあるときだけ**です。つまり下線は「開くものがある」という約束です。下線の有無にかかわらず、どの区切り文字もクリックできます — 下線のないものはサイドバーでそのフォルダを表示して展開し、そのことはポインタの形が示し続けます。下線は同時にフォルダ名から外れます: 入れ替えがオンならフォルダ名は一覧を開くので、それをノートへのリンクとして印を付けるのは嘘になるからです。

**名前変更／移動モードは設定に関係なく両方を上書きします**: 移動が保留のあいだ、この行のどれもフォルダを開きません。開けば移動を捨てることになるからです。フォルダ名は編集対象として選択され、区切り文字は下ります — どちらも行き先を指す手段です — そして開く動作が止まっていることを示すために下線は消えます。

**保管庫のルート**は、パスの要素ではない唯一の要素です。同階層を並べるための親がないので、代わりに[場所の一覧](#保管庫の外を見る)を開きます — ほかの保管庫、ホーム、ファイルシステムのルート、マウント済みドライブです。

## 要素をクリックする：同階層の別のものに差し替える

フォルダ名をクリックすると、**そのフォルダの名前**がテキスト入力欄で選択され、**一つ上**のフォルダ — その親 — の一覧が開きます。入力するか項目を選ぶと、このフォルダが同階層の別のものに差し替わり、その下はそのまま残ります。つまり `プロジェクト/2026/キックオフ.md` → `2026` をクリック → `2025` を選ぶ、で `プロジェクト/2025/キックオフ.md` になります。

**ノートの名前**をクリックした場合も自分のフォルダに対して同じように働き、ファイル名を**拡張子ごと**選択します — ノートの名前を変えたり差し替えたりするときは、たいてい拡張子も変えるからです。

フォルダのクリックで既に一つの要素が選択されているので、**もう一度クリック**すると選択が行全体 — そのフォルダ*と*その下すべて — に広がり、入力すればパスの残りをまとめて置き換えられます。ナビゲーションでも名前変更／移動モードでも同じです。

これは入力欄を開いたクリックの続きとしてのみ効きます。いったん入力欄を使い始めれば、あとはほかのテキスト入力欄と同じです: クリックでキャレットを置き、ダブルクリックで単語、トリプルクリックで行を選びます。

いずれの場合もパスの残りは入力欄の周りに見えたままです — 前はチップ、後ろは未選択のテキスト — なのでヘッダーから完全なパスが消えることはありません。入力して選択を置き換えるか、<kbd>End</kbd> / <kbd>→</kbd> を押して選択を保ったままそこから編集してください。一覧はあらかじめ入っている内容にかかわらずフォルダ全体を並べ、実際に入力し始めて初めて絞り込みを始めます。

## 区切り文字で下る

（**フォルダ名で一覧を開く** がオフのとき）区切り文字をクリックすると、その手前のフォルダへ下ります: 一覧には*その*フォルダの中身が並び、パスの残りは選択された状態で入力欄に開きます。フォルダを選ぶとそれがパスに足され、すぐ次の一覧が開くので、ヘッダー行を離れずにツリーをクリックで下っていけます。

## 一覧の行は本物のファイルマネージャーの行

一覧のすべてのファイルとフォルダは、ファイルエクスプローラーでのその行と同じようにふるまいます:

- **右クリック**で同じコンテキストメニューが出ます — フォルダなら *新規ノート* / *新規フォルダ*、ファイルなら *新規タブに開く* / *リネーム…* / *削除* — ほかのプラグインがファイルメニューに足した項目も含みます。
- Obsidian がファイルを受け付ける場所へ項目を**ドラッグ**できます: エディタへ入れてリンクを挿入、ファイルエクスプローラーのフォルダへ落として移動、タブバーへ落として開く。

メニューの文言は Obsidian 自身の訳文から来るので、どの言語でもアプリの他の部分と一致します。

## パスを入力する

- パスの前後の**空いている部分**をクリックすると、パス全体があらかじめ入り、すべて選択された状態のテキスト入力欄が開きます — 上書きするか、その場で編集してください。（ファイル名そのものをクリックするとファイル名だけが選択されます。上を参照。）
- パスが出ているときに入力を始めると、末尾の要素が、現在のフォルダに限定した即時補完付きの小さな入力欄になります。
- `/` は現在の要素を確定してその中へ下ります。
- 空の入力欄での <kbd>Backspace</kbd> は親フォルダへ戻り、その名前をカーソルを末尾に置いて開き直します。
- <kbd>Enter</kbd> で確定、<kbd>Esc</kbd> かどこか別の場所のクリックで取り消してファイルの本当のパスに戻ります。

入力欄には装飾がありません — 枠も境界線もない — のでパスの文字列そのものとして読め、入力に合わせて自動的に伸びます。

## ナビゲーションは開いているファイルに触れない

既定（ナビゲーション）モードでは、開いているノートの名前が変わったり移動したりすることは**決してありません**。

- 既存のファイルに解決するパスは、そのファイルを開きます。
- まだ存在しないパスは *「新しいファイルを作成しますか？」* と尋ねます。確定すれば足りない親フォルダとファイルが作られ、取り消せば何も起きません。

## <kbd>Ctrl</kbd> — 新規タブ、そして移動ではなくコピー

一覧からファイルを選ぶとき、またはパスで <kbd>Enter</kbd> を押すときに <kbd>Ctrl</kbd>（macOS では <kbd>Cmd</kbd>）を押していると、結果はこのタブではなく**新規タブ**へ送られます:

| | そのまま | <kbd>Ctrl</kbd> あり |
| --- | --- | --- |
| 既存のファイルを選ぶか入力する | ここで開く | 新規タブで開く |
| 存在しないパスを入力する | 確認のうえ、ここで開く | 確認のうえ、新規タブで開く |
| 名前変更／移動モードでパスを確定する | ノートをそこへ**移動** | そこへ**コピー**し、コピーを新規タブで開く |

修飾キーは Obsidian 自身のルールで読まれるので、リンクやファイルエクスプローラーの行の上と全く同じにふるまいます — 中クリックも「新規タブ」、<kbd>Ctrl</kbd>+<kbd>Alt</kbd> は分割、<kbd>Ctrl</kbd>+<kbd>Alt</kbd>+<kbd>Shift</kbd> は新規ウィンドウです。

コピーも移動と同じく上書きを拒みます — ノート自身のパスに対しても同じで、そこにはコピーする意味のあるものがありません。

## 保管庫の外を見る

**これは既定でオフです。** まず設定で **外部ファイルへのアクセス** をオンにしてください — 保管庫の外を読み書きすることは、このプラグインが行うことのうち Obsidian 自身が行わない唯一のものなので、オフにするものではなくオンにするものにしてあります。オフのあいだ、保管庫名は単に保管庫をファイルエクスプローラーで表示するだけで、ここにあるものがその先を見ることはありません。

**保管庫名**（*保管庫名を表示* がオフのときは 🏠 アイコン）をクリックすると、中身ではなく場所の一覧が開きます:

- **ほかの保管庫**。Obsidian 自身の記録から読み、最近開いた順に、それぞれ Obsidian 自身の保管庫アイコンの下に並びます — アプリが保管庫コマンドに使っているアイコンです。すでに開いている保管庫だけは家のアイコンになります: そこは既定でこの行が始まる場所であって、行き先ではないからです。
- **ホーム**。自分のアカウント名の下に、`~` の印付きで並びます。Lucide にチルダはないので、これはプラグインが Lucide 自身の 24×24 グリッドに同じ線幅で描いています — アイコンの列に紛れ込んだ文字ではなく、セットに欠けているアイコンとしてです。
- **ファイルシステムのルート**。`root` と表示します — どのシステムでもそう呼ばれるので訳しません — `/` にしないのは、後ろに続く区切り文字の隣で空の一段のように読めてしまうからです。
- **マウント済みドライブ**。種類の判定が安く済むところでは種類ごとのアイコンが付きます: ネットワーク共有、光学ディスク、フロッピー、リムーバブルメディアはそれぞれ専用のもの、それ以外は汎用のドライブです。Windows ではドライブは汎用アイコン付きの `C:` として出ます — ボリューム名や正確な種類には WMI が要るので、あえて行っていません。

ほかの保管庫を選んでも **Obsidian がそちらに切り替わることはありません。** 開いているものはすべて開いたままで、パスの表示がそこを見始めるだけです。サイドバーの保管庫切り替えに任せず、パスバーに置いてある意味はまさにそこにあります。

### 外にいるあいだ

パスは**選んだ場所から始まり**、マシンのディレクトリ構成からは始まりません — `アーカイブ` を選べば行は `アーカイブ / ノート / …` であって `/home/you/Vaults/アーカイブ/ノート/…` ではありません。先頭の要素にはそれが何か（保管庫、ホーム、ドライブ）を示すアイコンが付き、<kbd>Backspace</kbd> はそこで止まり、ファイルシステムの残りへ上っていくことはありません。*保管庫名を表示* がオフなら、その要素はアイコンだけになります — この設定は、どの保管庫を指していようと行の先頭の要素についてのものであって、自分の保管庫に限った話ではありません。

パスバーは、保管庫の外を指しているあいだずっと**エラー色で囲まれます** — 名前変更モードが描くのと同じ枠です。これは瞬間ではなく継続する状態を示します: それが出ているあいだ、行が示しているものに Obsidian 自身の扱いは一切適用されず、あなたがそう言うまで書き込みはロックされたままです。

それ以外、閲覧は中にいるときと同じように働きます: チップ、区切り文字、入力、補完、外へ出るための <kbd>Backspace</kbd>。表示のルールも同じなので、対応していない拡張子には引き続き Obsidian の *すべてのファイル拡張子を認識* が要り、ドットファイルには引き続きこのプラグインの設定が要ります。

**右クリックとドラッグ**は外では働きません — あれはファイルエクスプローラー自身の処理で、保管庫が知っているファイルを必要とするからです。

### 保管庫の外に書き込む

書き込むものはすべて**既定でロックされています。** 行が保管庫の外を指しているあいだ、ヘッダーの名前変更ボタンの隣に**南京錠**が現れます。押すと錠が開き、行を囲む枠に合わせて赤くなります。

許可は**瞬間にではなく場所に**与えられます: 一つの場所で作業するあいだにすることには耐えます — 移動を終える、入力欄の外をクリックする、ファイルを開く — そして一覧から別の保管庫・ドライブ・ルートを選んだとき、行が保管庫内のファイルに戻ったとき、あるいは南京錠をもう一度押したときに終わります。ですから一つのフォルダの中で移動を続けても、押すのは一度きりで、ファイルごとではありません。

南京錠が開いていれば、パスバーは外でも中と同じようにふるまいます:

| 操作 | 結果 |
| --- | --- |
| 存在しない名前を入力して <kbd>Enter</kbd> | 中と同じ「作成しますか？」の確認。足りない親フォルダも作られます。拡張子のない名前は、中とまったく同じく `.md` になります |
| 名前変更／移動モードで新しい名前を入力 | 行が示しているファイルの名前を変えます。拡張子のない名前はそのファイルの拡張子を保ちます — 外ではフォルダにあらゆる種類のファイルが入っており、名前変更が黙って `.png` を `.md` に変えてしまってはいけないからです |
| 名前変更／移動モードで別の場所へ移り、**この名前のまま**を選ぶ | 今の名前のままそこへ移動します |
| どちらでも <kbd>Ctrl</kbd> を押しながら | 移動ではなくコピーし、コピーを新規タブで開きます |

ロックされていれば、これらはどれも実行される代わりに何が妨げているかを知らせます。どちらの状態でも何かが上書きされることはありません: すでに存在する行き先は拒否され、その拒否は競合に負けうるチェックではなくファイルシステム自身のもの（`COPYFILE_EXCL`、排他的な作成）です。ファイルシステムをまたぐ移動 — USB メモリから、ネットワーク共有から — はコピーしてから削除する方式に切り替わり、コピーが着いてから初めて元が消されます。

**南京錠が解除しないものが一つあります: ノートを保管庫の*外*へ移動すること。** `fileManager` はその境界を越えてファイルを追えないので、そのノートを指すリンクはどれも黙って壊れ、Obsidian からはただ消えたように見えます。<kbd>Ctrl</kbd> を押しながらなら代わりに外へコピーでき、そちらにはその問題がまったくありません。通知もそう伝えます。逆方向 — 外のファイルを保管庫の*中*へ取り込むこと — もまだつないでいません。

### 外部ファイルを開く

Obsidian のエディタは保管庫の中のファイルにしか働かないので、外部ファイルをリンクやバックリンクを備えた本物のノートとして開くことは**できません** — これはアプリの制限であって、このプラグインの制限ではありません。選ぶと代わりに**プレビュー**が開き、あなたがそう言うまで読み取り専用です:

| 種類 | 表示 |
| --- | --- |
| `.md`、`.markdown` | 描画された Markdown |
| 画像・音声・動画・PDF | 標準のプレイヤー／ビューア |
| そのほかの**テキスト**ファイル（`.json`、`.css`、`.log`、`.txt` …） | そのままのプレーンテキスト |
| ビューアのないバイナリ形式 | *外部で開く* に渡す |

ビューアはファイルの読み方を二通り持っており、互いに排他なので、**切り替える先**のほうだけが表示されます:

| | 何をするか | 既定になる対象 |
| --- | --- | --- |
| **Markdown として表示** | ファイルをノートとして描画、読み取り専用 | `.md`、`.markdown` |
| **テキストとして編集** | ソースを編集可能に | それ以外すべて |

保管庫の外では、**テキストとして編集** は読み取り専用を解除する操作でもあります — モードと許可を、二つのボタンで考えるのではなく一つの操作にまとめてあります。**押せば読み取り専用が解除される状況ならいつでも**赤みを帯びます。その場で編集を構えるときも、描画表示から直接来たときも同じです。保管庫の中では解除するものがないので、そこでは普通の見た目のままです。**Markdown として表示** は薄いアクセント色に染まります — Obsidian が選択テキストに与えるのと同じ色合いです — 行動を促すものではなく戻り道であることを示しています。

ボタンが素のモードではなく*編集*を追っているので、テキスト表示で読み取り専用のまま置かれているファイルにも **テキストとして編集** が出ます: それが編集を構える操作だからです。決して書き込めないファイル — 省略表示のもの、読めなかったもの — には代わりに **テキストとして表示** と出ます。押して得られるのはそれだけだからです。

既定は字面どおりではなく役に立つ側に倒してあります: シェルスクリプトの `#` は見出しではなくコメントなので、`.log` を Markdown として描画すればそれを黙って飲み込んでしまいます。どちらの既定もファイルごとに上書きでき、その選択はリーフの履歴に入るので、戻る／進むも、開き直したワークスペースも覚えています — `.txt` に住むノートはいくらでもあり、ソースで読むほうが楽な `.md` もいくらでもあります。

**保管庫の中のファイルは解除なしですぐ編集できます**: *テキストとして編集* は本物のエディタで、入力に応じて書き戻します。

**編集は切り替えをまたいで覚えられます。** *Markdown として表示* へ行くと編集は中断します — 静的な描画には入力する先がなく、Live Preview は保管庫の中のファイルにしか存在しない Obsidian 自身のエディタを必要とします — なので、そこにいるあいだ編集中だと主張するものはありません。*テキストとして編集* に戻れば続きから再開します。

**保管庫の外のファイルは読み取り専用で開き、*テキストとして編集* がそれを解除します。** その一押しが門のすべてです: それが起きるまで、外には何も書かれません。押したあとは保管庫の中のファイルとまったく同じく、入力に応じて保存され、状態行は錠から鉛筆に変わります。解除が及ぶのはそのタブのそのファイル一つだけ — 別のファイルへ移れば再びロックされます — そしてこれは意図的にタブの履歴に保存されないので、開き直したワークスペースが、開いた覚えのないシステムファイルに書き込みを構えた状態で戻ってくることはありません。

**省略表示のファイルはどのみち読み取り専用のままです** — 画面にあるものを保存すれば上限より先がすべて失われるので、ボタンは出したうえで拒むのではなく、そもそも出しません。読めなかったファイルも同じです: 空のペインのほか、書き戻すものがありません。

書き込みが失敗したら — 読み取り専用のマウント、自分のものでないファイル — システム自身の理由が通知で示されます。

とても大きなファイルは省略して表示し、状態行がそれを伝えます。自分で気づかせるのではなく、ボタンの後ろではなくほかの条件と並べて — ほかと同じくファイルについての事実だからです。上限は推測ではなく実際のレンダラーに対して測ってあります — 1 メガバイトのテキストを一つのペインに組めば Obsidian のレンダラープロセスは丸ごと落ちますし、Markdown は 1 バイトあたりプレーンテキストの数倍かかるので、二つには別々の上限があり、ファイル全体が小さくても一行が巨大ならその行は短くされます。

**状態行はラベルであり、説明はツールチップです。** 各行は必要なだけの語数で事実だけを述べます — *保管庫の外*、*このファイル形式のエディタがありません*、*省略表示 — ファイルが大きすぎます* — 隣のボタンがファイルの状態をすでに語っているからです。ポインタを重ねればその一文が出ます: なぜ Obsidian がノートとして開けないのか、この形式は本来どう扱われるのか、省略で何を失うのか。

これは保管庫の**中**のファイルにも当てはまります。Obsidian はビューを持たない拡張子をそのままデスクトップの既定アプリに渡します — つまり保管庫の中の `.txt` や `.json` は Obsidian から出ていってしまいます。それらも今は同じビューアで、オレンジの枠付きで開きます。「Obsidian で開く」があなたの求めたことだからです — そして保管庫のファイルなので、そこでは何の解除もなしに編集できます。ビューアのないバイナリファイルは Obsidian の動作のままです。表示するものがありません。

プレビューは**いたタブの中で**開くので、戻る／進むで元のノートに帰れます。ほかと同じく <kbd>Ctrl</kbd> で新規タブです。開いているあいだヘッダーバーは外部ファイルのパスを表示し続けるので、そこから閲覧を続けられます。

内容の上の控えめな行が、出口を差し出します:

- **{vault} で開く** — そのファイルがほかの保管庫のものであるときに出ます。Obsidian 自身の URI ハンドラに渡し、その保管庫のウィンドウをノートを開いた状態で立ち上げます。本物の編集できるノートとしてです。このウィンドウはそのまま残り、足元で何かが切り替わることはありません。
- **Markdown として表示** / **テキストとして編集** — 二つの読み方。後者は保管庫の外では読み取り専用も解除します。
- **外部で開く** — このビューアが表示できないバイナリ形式も含め、ファイルをデスクトップの既定アプリに渡します。

先に *テキストとして編集* を押さないかぎり、保管庫の外には何も書かれません。全面的な説明は README の [保管庫の外](README.ja.md#保管庫の外) の節を参照してください。

## 二つの警告色

| | いつ | 意味 |
| --- | --- | --- |
| パスバーの**赤**い枠 | 行が保管庫の外を指している | Obsidian はそこにあるものをノートとして開けず、南京錠を開くまで外には何も書かれません。 |
| パスバーの**オレンジ**の枠、一覧のオレンジの項目 | Obsidian にビューがないテキスト形式のファイル | 注意喚起です。Obsidian ならデスクトップの既定アプリに渡すところを、プラグインが代わりに表示します。 |

**この二つは独立していて、同時に成り立ちます** — 外部の `.json` は保管庫の外にあり、*かつ* Obsidian にエディタのない形式です。ビューアでは別々の行として現れ、それぞれ自分の事実だけを述べます。パスバーでは両方あてはまる場合に赤が勝ちます。枠が二重になっても雑音にしかならないからです。

オレンジの層はあえて狭くしてあります。登録済みの形式（Markdown、canvas、画像、PDF、音声、動画）はきちんと扱われるので何も付きません。バイナリファイルにも何も付きません — うっかり `.zip` を編集して壊すことはないからです。残るのはまさに危ないところだけ: **すべてのファイル拡張子を認識** によって見えるようになった `.json`、`.css`、`.log` です。

両方あてはまるところでは赤が勝ちます。枠が二重になっても雑音にしかなりません。

## 名前変更／移動モード

ヘッダーのいちばん右の鉛筆ボタン — 表示モードのボタンの隣、標準のボタンと同じ大きさ — が名前変更／移動モードを切り替えます。ヘッダー行はそのときアクセント色で囲まれます。ファイルエクスプローラーで名前を変えるときとまったく同じです。同じクリックとキー操作が、今度は Obsidian の `fileManager.renameFile` を通して移動や名前変更を確定するので、そのノートへのリンクはすべて付いてきます。

名前変更のあいだ:

- 現在のファイル名がどのフォルダの一覧にも留められるので、名前を変えずにノートを移すのはクリック一回です。
- 行き先のフォルダで既に使われている名前は薄くなりますが、それでも選べます。
- 入力は Obsidian 自身の名前変更ルールに対して即時に検証されます — 同じ文字集合、同じメッセージ、ファイルツリーで名前を変えるときと同じ赤いツールチップ — なので、使えない名前や衝突する名前は入力中に指摘され、確定できません。
- ヘッダーバーの外をクリックするか、ヘッダーがフォーカスを失うと、名前変更モードは終わります。

## 二つの名前変更を一つのキーで

名前変更コマンド（既定では <kbd>F2</kbd>、割り当てを変えていればそのキー）は、Obsidian のインラインタイトルでの名前変更と、パス全体を選択した状態のこのプラグインのヘッダーのパスバーとを**交互に**切り替えます。Obsidian のインラインタイトルをオフにしていれば、ヘッダーのパスバーが唯一の行き先になるので、このキーが何もしないことはありません。

これはキーを奪うのではなく `workspace:edit-file-title` コマンドを包むことで実現しているので、ホットキーの割り当て変更も、パレットからのコマンド実行も、変わらず働きます。

## 一覧の行の色分け

| 色 | 意味 |
| --- | --- |
| **紫** | ノート（`.md`、`.markdown`）— Obsidian がノートとして開くもの。中身の混じったフォルダから拾い出されます |
| **オレンジ** | Obsidian にビューのないテキスト形式。[警告色](#二つの警告色)を参照 |
| **淡色** | 保管庫の外なので、保管庫自身の扱いが当てはまりません |
| **青** | いま開いているノート。閲覧中はそのノート自身の項目で、名前変更／移動モードでは *この名前のまま* の項目がその位置に立ちます — どちらも同じノートです |
| **灰色** | 名前変更／移動モードのみ: その名前は使われています。それでも選べます — 選ぶと入力欄に入り、そこで検証が衝突を指摘します |

## 表示のルール

- 対応していない拡張子のファイルが一覧に出るのは、Obsidian の **すべてのファイル拡張子を認識** 設定がオンのときだけです。
- 一覧に出るのは最大 100 件 — Obsidian 自身の上限です。フォルダにそれ以上あるときは、最後の行が何件省かれたかを伝えます。入力を続けて絞り込んでください。
- ドットファイルとドットフォルダが出るのは、このプラグインの **ドットファイルを表示** 設定がオンのときだけです。
- **上書き防止は表示・非表示にかかわらず同じように働きます** — 隠れているファイルも、上書きは依然として止めます。

## チートシート

| したいこと | 操作 |
| --- | --- |
| フォルダを開く（そのノート、または表示） | そのフォルダの**後ろの**区切り文字をクリック |
| フォルダを同階層の別のものに差し替える | そのフォルダ名をクリックし、入力するか選ぶ |
| ノートの名前を変える・差し替える | ノートの名前をクリック — 拡張子込み |
| フォルダの中身を見る | そのフォルダ名をクリック。一覧は親を並べるので、目当てのフォルダの**一つ下**のフォルダをクリック |
| フォルダとその下すべてを打ち直す | そのフォルダ名を**ダブルクリック**して入力 |
| あるフォルダ以下のパスを編集する | そのフォルダ名をクリックし、<kbd>End</kbd> か <kbd>→</kbd> で選択を解除 |
| パスを打ってファイルへ飛ぶ | ファイル名か空いている部分をクリックし、入力して <kbd>Enter</kbd> |
| 代わりに新規タブで開く | 選ぶときに <kbd>Ctrl</kbd>、または <kbd>Ctrl</kbd>+<kbd>Enter</kbd> |
| 移動ではなくノートをどこかへコピーする | 鉛筆、そして行き先を選ぶ／確定するときに <kbd>Ctrl</kbd> |
| 存在しないパスにノートを作る | パスを入力して <kbd>Enter</kbd>、確認に応じる |
| 入力中に一階層下る | `/` を入力 |
| 入力中に一階層上る | 空の入力欄で <kbd>Backspace</kbd> |
| 開いているノートを移動・名前変更する | 鉛筆をクリックし、上のように見るか入力する |
| 名前を変えずに移動する | 鉛筆 → 行き先フォルダへ入る → 留められた現在のファイル名を選ぶ |

| 何であれ取り消す | <kbd>Esc</kbd>、またはヘッダーバーの外をクリック |

| 設定 | 選択肢 | 既定 | 内容 |
| --- | --- | --- | --- |

| **フォルダ名で一覧を開く** | オン / オフ | オン | フォルダ名とその後ろの区切り文字の役割を入れ替えます — [上の表](#パス表示)を参照。[Folder notes](obsidian://show-plugin?id=folder-notes) があれば区切り文字がフォルダノートを開きます。名前変更／移動モードでは適用されません。 |
| **ドットファイルを表示** | オン / オフ | オフ | ドットファイルとドットフォルダを一覧に並べるか。上書き防止はどちらでも働きます。 |

## アイコンを差し替える

Lure は三つのアイコンを描きます: 保管庫ルートのアイコン（**保管庫名を表示** がオフのとき）、名前変更／移動の切り替え、そして保管庫の外への書き込みを守る南京錠です。どれもテーマや CSS スニペットから差し替えられます — 置き換える字と同梱アイコンの非表示を、一つのルールで指定してください:

```css
.lure-vault-icon {
	--lure-icon-glyph: "🏠";
	--lure-icon-svg: none;
}

.lure-rename-btn {
	--lure-icon-glyph: "✎";
	--lure-icon-svg: none;
}

/* 南京錠には二つの状態があり、`.is-active` が開いているほうです。 */
.lure-unlock-btn {
	--lure-icon-glyph: "🔒";
	--lure-icon-svg: none;
}

.lure-unlock-btn.is-active {
	--lure-icon-glyph: "🔓";
}
```

`--lure-icon-glyph` は CSS の `content` に使えるものなら何でも取るので、テキストや絵文字だけでなく `url(...)` で画像も指定できます。Lucide のアイコンを残して自分の字をその隣に描きたいときは、`--lure-icon-svg` はそのままにしてください。
