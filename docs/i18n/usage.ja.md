# 使い方

[← README に戻る](README.ja.md)

## パス表示

ノートの保管庫内での完全なパスが、ビューヘッダー — タブ列の下にあり、戻る／進むボタンも並ぶバー — の素のファイル名を置き換えます。

この行でクリックできるものは二つあり、どちらが何をするかは **フォルダ名で一覧を開く** が決めます:

| | フォルダ名 | その後ろの区切り文字 |
| --- | --- | --- |
| **オン**（既定） | そのフォルダを編集対象として選択 | フォルダを開く |
| **オフ** | フォルダを開く | そのフォルダへ下る |

「フォルダを開く」とは、プラグインのない Obsidian でその要素をクリックしたときの動作を指します。そこを見張るプラグインがなければ、フォルダはサイドバーのファイルエクスプローラーで表示されます — ハイライトされ、中身が見えるように展開されます。

そのフォルダのノートが今読んでいるノートそのものである場合、クリックは代わりにフォルダを表示します — 画面にまだ出ていないものを開く先はなく、これは二回目の押下が常に意味してきたことです。

[Folder notes](obsidian://show-plugin?id=folder-notes) を導入していれば、同じクリックで代わりにそのフォルダのノートが開きます、**どんな深さでも**: ノートはそのプラグイン自身の慣習からここで解決され、そのプラグインに答えを委ねることはありません。そのプラグインは自身がマークしたフォルダしか認識せず、一つより深いパスではそれに当たるものがないため、以前はトップレベルのフォルダのノートを開いた押下も、それより深い階層では何もしませんでした。ほかの二つのフォルダノートプラグインは読み取れる慣習を公開せず、この行を扱おうともしないので、それらの場合、区切り文字は以前どおりフォルダを表示します。ヘッダーのパスを扱うと分かったフォルダノートプラグインはこの一つだけです。[Folder Note](obsidian://show-plugin?id=folder-note-plugin) と [create folder notes with dropdown](obsidian://show-plugin?id=create-folder-notes-with-dropdown) はフォルダノートを管理しますが、パス表示のクリックを見張らないため、それらの場合も区切り文字はいつもどおりフォルダを表示します。[互換性](../compatibility.md#verified-against)を参照してください。

区切り文字に**下線が付くのは、その手前のフォルダに実際にフォルダノートがあるときだけ**なので、下線は開けるものがそこにあるという約束です — [Folder notes](obsidian://show-plugin?id=folder-notes) が動いていればどの深さでも、ノートはそのプラグインにマークを委ねずここで解決されるからです。そのプラグインが動いていない場合、何も下線は付かず何も開きません: フォルダノートプラグインが一切ない場合と同じく、区切り文字はフォルダを表示します。どちらにしても区切り文字は常にクリックでき — 下線のないものはサイドバーでそのフォルダを表示・展開し、それはポインターカーソルが今でも示すとおりです。下線はフォルダ名からも同時に外れます: 切り替えがオンのときは、名前が一覧を開くので、それをノートへのリンクとしてマークするのは偽りになるからです。

**名前変更／移動モードは設定に関係なく両方を上書きします**: 移動が保留のあいだ、この行のどれもフォルダを開きません。開けば移動を捨てることになるからです。フォルダ名は編集対象として選択され、区切り文字は下ります — どちらも行き先を指す手段です — そして開く動作が止まっていることを示すために下線は消えます。

**保管庫のルート**は、パスの要素ではない唯一の要素です。同階層を並べるための親がないので、代わりに[場所の一覧](#保管庫の外を見る)を開きます — ほかの保管庫、ホーム、ファイルシステムのルート、マウント済みドライブです。

## 保管庫自身の区切り文字

保管庫名のすぐ後ろの区切り文字はフォルダではなく保管庫そのものを表すので、
ほかのどの区切り文字にもできないことをします:

| | 一回目のクリック | 次のクリック |
| --- | --- | --- |
| **スタートページ用プラグインがある場合**（Obsidian を開いたときに迎えてくれるページ） | そのページをこのペインで開く | ファイルツリーをたたむ |
| **ない場合** | ファイルツリーをたたむ | 開いていたものをそのまま元に戻す |

普通のクリックであり、ダブルクリックではありません: ページが一度開けば、
区切り文字にはもう開くものが残っていないので、次の押下はたたむ動作になります —
どれだけ間をおいても同じです。

開くべきスタートページがあるときは**下線が付き**、これはフォルダの区切り文字が
する約束と同じです: そこに何かがある、というものです。たたむ動作はトグルで —
次の押下は開いていたフォルダだけを元どおりに復元するので、整えておいたツリーが
ほかのものをちらっと見ただけで失われることはありません。

## ファイルを持たないペイン

空のタブ、グラフ、そしてファイルを名乗らないそのほかのものには、
専用の行が与えられます: 保管庫、そしてそのペインが何を保持しているかを示す要素が一つ。

```
my-vault / :blank      新規タブ
my-vault / :graph      グラフ（ローカルまたはグローバル）
my-vault / :<type>     ファイルを持たないそのほかのもの
```

**保管庫ルート自身の一覧**もこれらのページを提供します。実際にそこにある
フォルダやノートの下に並びます: そこで `:graph` や `:search` を選ぶと、
ノートを選んだときにノートが開くのとまったく同じように、そのビューがペインで開きます。
どんなページが存在するかは、ここに書き留めるのではなく Obsidian から読み取られます —
ファイルを表示するために存在するのではないすべてのビューが対象なので、
ビューを登録するプラグイン（ホームタブ、カレンダー）は、このプラグインが
それについて何も知らないまま現れます。ファイルを必要とするビュー —
Markdown、PDF、画像、キャンバス、ベース — は提供されません: そこには表示するものがないからです。

コロンが要点です — `:graph` という名前のファイルやフォルダは存在しえないので、
この行が開けそうなパスと見間違えられることはありません。ラベルは Obsidian 自身の
文言ではなくビューの種類から来るので、インターフェースの言語が何であれ同じように
読め、末尾の `-view` は取り除かれます: ホームタブ用プラグインが自身のビューを
`home-launcher-view` として登録すれば、行は `:home-launcher` と表示されます。

空白部分、またはラベル自体をクリックすると、**保管庫ルートで入力欄が開きます**:
パスを入力して <kbd>Enter</kbd> を押せば、まさにこのペインでそれが開きます。
補完も、一覧も、まだないものを作ろうと申し出る赤い入力欄も同じです。
空のタブは行きたい場所を入力するのにちょうどよい場所であり、それがまさにその用途です。

ラベルはラベルであり、それ以上のものではありません: 一覧もドラッグも
名前変更もありません。サイドバーのペインはまったく手を加えられません —
バックリンクのペインは Obsidian が与えるタイトルのままです。

キャンバス、PDF、画像、ベースはこうしたものを一切必要としません。
それらはファイルなので、普通のパスバーを得ます。

## 要素をクリックする：同階層の別のものに差し替える

フォルダ名をクリックすると、**そのフォルダの名前**がテキスト入力欄で選択され、**一つ上**のフォルダ — その親 — の一覧が開きます。入力するか項目を選ぶと、このフォルダが同階層の別のものに差し替わり、その下はそのまま残ります。つまり `プロジェクト/2026/キックオフ.md` → `2026` をクリック → `2025` を選ぶ、で `プロジェクト/2025/キックオフ.md` になります。

**ノートの名前**をクリックしても、そのノート自身のフォルダに対して同じように働き、名前は**拡張子を除いて**選択されます — 名前変更がよくある編集であり、`.md` を含んだ選択範囲にそのまま上書き入力すると、うっかりファイルの種類を変えてしまっていたからです。拡張子はキー一つ分先に見えたままです: <kbd>→</kbd> でそこに届き、行全体に選択を広げるダブルクリックはその全部を取り込みます。

フォルダのクリックで既に一つの要素が選択されているので、**もう一度クリック**すると選択が行全体 — そのフォルダ*と*その下すべて — に広がり、入力すればパスの残りをまとめて置き換えられます。ナビゲーションでも名前変更／移動モードでも同じです。

これは入力欄を開いたクリックの続きとしてのみ効きます。いったん入力欄を使い始めれば、あとはほかのテキスト入力欄と同じです: クリックでキャレットを置き、ダブルクリックで単語、トリプルクリックで行を選びます。

どちらの場合も、パスの残りは入力欄の周りに見えたままです。手前はチップとして、後ろは未選択のテキストとして残るので、完全なパスがヘッダーから消えることはありません。入力すれば選択範囲を置き換え、<kbd>→</kbd> を押せば選択範囲を保ったままそこから編集できます。一覧はあらかじめ何が入っているかにかかわらずフォルダ全体を並べます。実際に入力を始めて初めて絞り込みが始まります。

## 区切り文字で下る

（**フォルダ名で一覧を開く** がオフのとき）区切り文字をクリックすると、その手前のフォルダへ下ります: 一覧には*その*フォルダの中身が並び、パスの残りは選択された状態で入力欄に開きます。フォルダを選ぶとそれがパスに足され、すぐ次の一覧が開くので、ヘッダー行を離れずにツリーをクリックで下っていけます。

## 一覧はあなたのいる場所で開く

一覧は、最初の行ではなく、あなたが今いる項目 — このバーが属するノート、
あるいはフォルダのクリックでその親を並べているときはそのフォルダ — の位置で開きます。
二百件のノートが入ったフォルダでは、最初の行はあなたのいる場所からほど遠いのです。

**名前の上でホイールを回すと一覧が開き、その中を進みます。** 最初の一回転は名前を
押したときと同じ一覧を開き、それ以降の一回転ごとにハイライトが一行動き、
矢印キーのときとまったく同じように、指している項目が入力欄に入ります —
そのためキーボードなしでも同階層の別のものを見つけて選べます。どちらかの端を
越えて回すと、あなたのテキストが戻ります。ペインより長いパスを持つ行は、
それが当てはまるあいだは横スクロールでホイールに応じます。こちらが優先されます。

一覧の高さは**ウィンドウが許すかぎり**です。Obsidian は下に何があろうと候補一覧を
300 ピクセルに制限しますが、この一覧はウィンドウの下端まで伸び、端の少し手前で
止まり、フォルダの中身がそれを超える場合にだけスクロールします。**幅はパスバーを
超えません**: 収まらない名前は行が短縮されるのと同じ方法で短くされ、指すと
全体が表示されます。

一覧の中を移動すると、矢印キーでもホバーでも、**指している項目が入力欄に入ります** —
編集していた要素の代わりに、パスの残りはそのまま残ります — なので、
今いる行がそのまま得られるパスでもあります。

パスの残りは、**指しているものの下に実際に存在する分だけ**表示されます。
編集している要素の後ろに `2026/note.md` を持つあるフォルダにいるとして、
`2026` を持ち、その中に `note.md` もあるフォルダを指せばその全部が表示され、
`2026` はあるがノートがないものは `2026` だけを表示し、どちらもないものは
名前の後ろに何も表示せず、ファイルの場合も同様です。下には何もないからです。
**あなたが入力したもの**は、まだどれだけしか入力していなくても、入力している
あいだは常に完全なパスを保ちます — 途中まで打った名前はまだ決定ではありません。
名前を確定させることは決定であり、そこから届かないものはその時点で切り捨てられます。
今作ろうとしているフォルダは、その*後ろ*に入力するものであり、そこが
<kbd>Enter</kbd> がそれらを作る場所です。
入力していたテキストは保たれます: **一覧のどちらかの端を越えて**動くと —
最初の項目より上、または最後の項目より下 — それを手放してあなたのテキストが
戻り、何もハイライトされません。入力欄も一覧の輪の中の一つの停留所なので、
一周は最後の行から最初の行へ飛ぶのではなくそこを通り過ぎ、そこから続けて
押せばもう一方の端へと回り込みます。

**ポインターを一覧から外す**とテキストも戻ります — そして、マウスが来る前に
ハイライトを持っていたものにハイライトを返します: 矢印で移動していた項目が
入力欄に再び表示されるか、あるいは今いる場所であるがゆえに一覧が開いた項目です。
ホバーは選ぶ手段ではなく見る手段なので、一覧の上をポインターでなぞっても
何も失いません。

一覧そのものは、その中を移動しているあいだは変わりません — 入力欄にプレビュー
されたものではなく、あなたが入力したものによる絞り込みを保ち続けます —
なので、あなたのいる項目が次の押下の下で動くことはありません。入力すれば
プレビューを置き換え、いつもどおり絞り込みます。

**絞り込みの対象は編集している要素であり**、入力欄全体ではありません。
フォルダをクリックすると、変更中の名前の後ろにパスの残りが残るので、
全体で絞り込めば `2026/Kickoff.md` という名の子を探すことになり、
何も見つかりません — 何を入力しても一覧は最初のキー入力で閉じてしまいます。
**拡張子も同様に除外されます**。キャレットがドットの手前にあるあいだは:
ノートの名前をクリックすると本体部分が選択され、後ろに `.md` が残るので、
一文字入力すると入力欄は `a.md` になってしまい、それは求めているものでは
ありません。キャレットをドットの後ろに置けば、拡張子もほかと同じように
扱われます。本当に何にも一致しない名前は、それでも一覧を閉じます。
空の一覧が正直な答えだからです。

プレビューは**その一つの要素だけを差し替え、パスの残りはそのままにします**:
フォルダを指すことは、この段がそれだったらどうかと問うものであり、
パスを丸ごと捨てることではありません。一覧から外れると、テキスト*と*
持っていた選択範囲の両方が復元されるので、次のキー入力は、見る前に
置き換えるはずだったものを置き換えます。

## 一覧の行は本物のファイルマネージャーの行

一覧のすべてのファイルとフォルダは、ファイルエクスプローラーでのその行と同じようにふるまいます:

- **右クリック**で、ファイルエクスプローラーが出すのと同じコンテキストメニューが、項目一つ一つまで — ほかのプラグインが追加するものも含めて — 出ます。フォルダには *新規ノート*、*新規フォルダ*、*新規キャンバス*、*新規ベース*、*コピーを作成*、*フォルダの移動先…*、*フォルダ内を検索*、*パスをコピー*、*システムのエクスプローラーで表示*、*名前を変更…*、*削除* が用意され、ファイルにはそれに相当するもの、*既定のアプリで開く* を含めて用意されます。
- Obsidian がファイルを受け付けるどこへでも項目を**ドラッグ**できます: エディタへドラッグしてリンクを挿入する、ファイルエクスプローラーのフォルダへドラッグして移動する、タブバーへドラッグして開く、といった具合です。

メニューの文言は Obsidian 自身の訳文から来るので、どの言語でもアプリの他の部分と一致します。

## パスを入力する

- パス表示の前後にある**空白部分**をクリックすると、パス全体に対するテキスト入力が開き、*同時にファイルエクスプローラーでもそのノートを表示*するので、二度手間なくツリーがペインに追従します。これはクリックした**回数を数えて**います：一回は拡張子を除いたパスを選択、二回で拡張子込みで選択、三回でマシンが知っているパスを選択します。**ファイル名**をクリックした場合も同じように数えますが、一段低い位置、名前そのものから始まります：一回は拡張子を除いた名前を選択、二回で拡張子込み、三回でパス全体に広がります — これは*保管庫フォルダから*の形式で、マシンの形式ではなく、リンクや検索が求める形です。四回目でそこに到達します。
- **この回数のカウントは、その入力欄を開いた一連の操作に属します。** 一度途切れると — 一時停止した、何か入力した、テキスト内のどこかを一回クリックした — その入力欄は他と同じ普通のテキストフィールドになり、その中でダブルクリックすればどこでもそうであるようにポインタ下の単語を選択します。選択されているものの上に上書き入力するか、その場で編集してください。（ファイル名自体をクリックするとファイル名だけが選択されます。上記参照。）同じ空白部分を右クリックすると、二回、三回、四回のクリックに対応するその同じ三つを**コピー**します — 片方のボタンがそれらを見せ、もう片方がそれらを取ります。**一回**の右クリックはパス全体が選択された状態で入力欄を開き、それに対して何ができるかを提示します：切り取り、コピー、貼り付け、すべて選択、Obsidian自身の言葉で言えば。
- **空白部分を中クリック**すると、パスの上に貼り付けられます：入力欄は*保管庫のルートから*のパス全体で開くので、クリップボードの内容がそのすべてを置き換え、収まった部分が選択されます。その後<kbd>Enter</kbd>でそこへ移動します。
- **空白部分を<kbd>Ctrl</kbd>+クリック**すると、このノートを別のタブでもう一度開き、ファイルエクスプローラーで点滅表示するので、二つ目のタブが一つ目と間違われません。**保管庫名**の上で<kbd>Ctrl</kbd>+クリックまたは中クリックすると、何も持たない、保管庫のルートに立つタブが開き、一覧がすでに表示されています — ゼロからパスを入力する場所です。
- パス表示が出ている状態で入力すると、末尾の要素が現在のフォルダに絞られたライブ補完付きの小さな入力欄に変わります。
- **ファイルシステムのルートからのパスも入力できます。** 空の入力欄の先頭に`/`を置くと、一段を補完するのではなく一つを開き、それに続くすべてのスラッシュはそれに属し、`~`はホームフォルダを表します。入力欄がそのようなパスを保持している間、一覧は保管庫ではなくマシンを表示し、行の先頭要素は退きます — 入力欄にあるものはルートから始まり、そう告げています。*外部ファイルへのアクセス*が無効な場合、一覧は代わりに空になります。どうせ<kbd>Enter</kbd>がそのパスを拒否するからです。
- **ページも選択するだけでなく入力できます。** `:graph`、`:search`、あるいはあなたのプラグインが登録している何でも — [保管庫ルートの一覧](#ファイルを持たないペイン)が提示するラベルです。どこでもコロンを入力するとそれらが呼び出されます。名前にコロンを含むことはできないからです。そして<kbd>Enter</kbd>でこのペインにそのビューが開きます。**フォルダの中で**入力した`:graph`はそのフォルダのグラフを開きます — 自身の検索ボックスにそこで入力したかのように`path:"that/folder"`で絞り込まれたグラフです。保管庫のルートではグラフ全体になります。<kbd>Tab</kbd>はフォルダの名前を補完するのと同じように名前を補完します — そして入力欄が保持していた他のものも一緒に持ち去ります。ページはどのフォルダにも属さず、その下に何も存在しないからです。そのようなページ上でラベルをクリックすると、それを保持した状態で入力欄が開きます。
- **<kbd>Tab</kbd>が書き込むはずの内容は、入力中に提示されます。** 入力した内容で始まるすべての子がしばらく一致し続ける場合、その一致部分はキャレットの後ろに選択済みの状態で表示されます。一致しなくなる場所では、それらの最初のものへの一歩が表示されます — あるいは矢印キーで移動した行への一歩です。それが<kbd>Tab</kbd>が向かう先だからです。名前の上に上書き入力すると拡張子はそのまま残り、その前に提示が表示され、たった今踏み入れたフォルダはその最初の一歩を提示します。つまり何も提示されない状態はなく、<kbd>Tab</kbd>は常に何かを書き込みます。それらの文字を入力すると一文字ずつ吸収され、それ以外の何かを入力すると消えます。<kbd>Tab</kbd>または<kbd>End</kbd>はそれを丸ごと取り、<kbd>→</kbd>はその一文字を取り、<kbd>Backspace</kbd>はあなたが入力した文字には触れずにそれを取り消し、入力するまで何も再び提示されません — つまり望まなかった名前から抜け出す道は常にあります。<kbd>Tab</kbd>を押した後は、入力した文字の後と同様に次の一歩がすぐに提示されます。一覧が表示するものは**あなたが**入力したものによって絞り込まれ、提示されたものによって絞り込まれることは決してありません。
- **提示は大文字小文字を区別しません。** `sch`は名前の表記通りに`Schemes`を提示します。その提示を取り消すと、あなたが入力した通りの文字が戻ります。`Test`と`test`の両方が存在する場合、あなたが入力した表記のものが提示されます。
- 入力欄では提示部分は単純に**選択状態**になります。それが詳しく示されるのは一覧の方です：各行は、名前のどこで一致したかにかかわらず、**あなたが入力した内容に一致した部分を太字で**示します — `kick`は`Weekly kickoff`を見つけ、そう示します。**あなたが入力した内容で始まる名前が先に来ます**。それを含むだけの名前より前に、そして端に線が引かれて示されます：あなたが入力した以上に共通する部分がある場合は**青**、つまり<kbd>Tab</kbd>がそれらすべてに対して何か追加できるものがある場合、そして分岐する枝には**緑**、提示がそちらへ向かう場合 — `te`に対して`test1`、`test2`、`text1`、`text2`があれば`te`+`st`が提示されるので、二つの`test`行は緑になり、二つの`text`行は普通の線のままです。それぞれの行は**<kbd>Tab</kbd>がそれへ向かって取る一歩に下線を引きます**。提示されているものだけではなく、そして下線は提示が変わるのに追従します。
- **入力すると、ハイライトされた行から手が離れます。** 一覧はあなたが立っている項目で開きますが、入力した瞬間それは別の場所についてのものになり、誰も置いたわけではないハイライトが、すでに選ばれた選択として読まれてしまいます。
- 提示はあくまで目の前のテキストにすぎません：入力中、あなたが入力した文字はあなたが入力した通りの表記のままであり、提示を受け入れるとフォルダの表記通りに名前が書き換えられます。パスはディスクと一致しなければならないからです。`sk` + <kbd>Tab</kbd>は`skyline`ではなく`Skyline`に到達します。
- **入力欄はそれが指すものの色をまといます**。一覧内のその行と同じ色です：ノートなら紫、フォルダ自身のノートも含みます、ノートでないものなら橙、あなたが今いるノートなら青。色の由来となる行は、あなたが入力した内容と正確に一致する名前の行、それがなければハイライトされた行、それもなければあなたの入力が今なお導く最初の行です。
- **入力欄は、そこにある内容に何も応えるものがなくなると赤くなります** — ファイルもフォルダもなく、一覧のどの行もそこへ導かなくなった状態です。そこから<kbd>Enter</kbd>を押すと、入力欄の内容を開くのではなく作成し、赤色はそれをコミットする前に告げています。ウェブアドレスに対しては決して現れません。それはこのマシン上で探すべき場所ではないからです。欠けている部分だけでなく**入力欄全体**が色付けされます。テキストフィールドは自身の内容の半分だけを色付けすることはできないからです。名前変更／移動モードでは、入力欄は不正な名前に対して独自の赤を保持します — そこでは、何も応えない名前であることこそが本題です。名前が**すでに使われている**ことは、コミットした時点で扱われ、邪魔になっているファイルをどうするかを尋ねるダイアログが表示されます — [使用済みの名前](#使われている名前)を参照してください：`Notes.md`に向かって入力されるすべての名前は、それ自体がファイルであり得る名前を経由するので、一文字ごとにそれを警告することは、誰も求めていなかった名前について警告することになります。
- `/`は入力中の要素をコミットしてその中へ下ります。その後ろにあるものはそのまま保持されます — <kbd>Tab</kbd>が踏み入る際にすることと同じです。
- 空の入力欄で<kbd>Backspace</kbd>を押すと親フォルダへ一段戻り、その名前をカーソルを末尾に置いた状態で再び開きます。拡張子だけが単独で残っている場合の<kbd>Backspace</kbd>も同様です — `.md`だけを保持する入力欄は何も指していません — その単独の拡張子も一緒に消えます。
- **入力欄が開いている状態でフォルダをクリックすると、そのフォルダの後のパス全体に広がり**、フォルダ自身の名前が選択されます — その行からクリックした場合と同じことが起こり、入力欄が保持していたものはすべて保たれます。入力欄の内容は開いている間は行の末尾部分なので、さらに上のフォルダをクリックすると、ノートが始まったパスではなく、そのセッションがたどってきたパスが返ってきます。
- **入力欄の先頭より前へ矢印キーで移動すると、その前のフォルダが取り込まれます**。パス全体が一行のテキストであるかのようにです。キャレットが先頭にある状態で、<kbd>←</kbd>はそのフォルダを入力欄に取り込み、その名前の末尾に着地します。<kbd>Ctrl</kbd>+<kbd>←</kbd>はその先頭に着地し、<kbd>Home</kbd>は保管庫のルートまで — あるいは保管庫の外で選んだ場所まで — すべてのフォルダを一度に取り込みます。<kbd>Shift</kbd>を押したままだと、選択範囲が取り込まれた部分に広がります。macOSでは単語単位の移動は<kbd>Option</kbd>+<kbd>←</kbd>で、<kbd>Cmd</kbd>+<kbd>←</kbd>が<kbd>Home</kbd>になります。先頭以外の場所ではこれらは普通のテキストキーです。**一覧が表示されている間、<kbd>Home</kbd>、<kbd>End</kbd>、<kbd>PgUp</kbd>、<kbd>PgDn</kbd>はそれに属します** — 最初の行、最後の行、一ページ上、一ページ下、ページとは一覧が表示している範囲を指し、ハイライトされた行は画面上の位置を保ちます — そしてそれが閉じてから初めてテキストに届きます。<kbd>Shift</kbd>+<kbd>Home</kbd>は一覧が開いている状態でもすべてのフォルダを取り込みます。
- **一覧はキャレットに追従します。** パスの別の部分を選び出す — ドラッグして選択する、その中をクリックする、あるいは矢印キーで移動する — と、一覧は入力欄が開かれたフォルダではなく*その*フォルダの子を表示します。フォルダは、チップとキャレットより前にある入力欄の内容から数えられます。つまり`2026/Notes.md`を保持する入力欄で`Notes.md`の中をクリックすると、`2026`の中身が一覧表示されます。行を指し示すとそれがキャレットのある要素に書き込まれ、ポインタを一覧から離すと、テキストと選択範囲がそのままの状態で戻ってきます。
- **入力欄から選択範囲をドラッグして**別の場所で手を離しても、それは閉じません。入力欄内で始まった押下は、どこまで移動しても編集に属します。外で*始まる*押下だけがクリックとして離脱扱いになります。
- <kbd>Enter</kbd>はコミットします — そして入力欄が何も指していない場合、たとえば補完すべきものが元からない空のフォルダの場合、*ファイルが選択されていません*と表示され、何かが選ばれたかのように閉じるのではなく開いたままになります。<kbd>Esc</kbd>または他の場所をクリックすると、ファイルの実際のパスに戻ってキャンセルされます。<kbd>Esc</kbd>を一回押せば十分です：一覧を閉じ、入力欄を離れ、フォーカスをノートに戻します。階層ごとに一回押す必要はありません。

入力欄には装飾がありません — 枠も境界線もない — のでパスの文字列そのものとして読め、入力に合わせて自動的に伸びます。

## 行の各部分を、ボタンごとに

行全体を一目で見渡す表。右クリックの列は**一回**押したときの結果で、そのボタンは押した回数も数えており、[専用の表](#右クリック一回二回三回)を下に置いて二回目、三回目、四回目を示す。この表は**フォルダ名で一覧を開く**がオンであることを前提にしている（これが既定値）。オフにすると、[冒頭の表](#パス表示)にある通り、フォルダ名と区切り文字が最初の列で入れ替わる。

| どこを押すか | クリック | ダブルクリック | <kbd>Ctrl</kbd>+クリック、または中クリック | 右クリック | 何かをドロップする |
| --- | --- | --- | --- | --- | --- |
| **Vault 名** | 場所の一覧を開く — 他の Vault、ホーム、ファイルシステムのルート、マウントされたドライブ。既定ではオフで、オフのときはファイルエクスプローラーで Vault を表示する | **絶対パス全体**を選択する。その一覧はすでにパスが入力欄に入った状態で開き、Vault 自身の部分だけが選択されている。もう一度押すと残りにも広がる。一覧がオフのときは広げる対象がない | 何も持たない新規タブが、一覧を表示した状態で Vault のルートに立つ — ゼロからパスを入力する場所 | Vault 自身のコンテキストメニュー — その要素の名前を持つ Vault に対してできること | **ファイル**は Vault のルートに移動する。**テキスト**はルートで入力欄を開き、そのノートに付ける名前を入力させる |
| **フォルダ名** | そのフォルダを編集用に選択し、その親の中身を下に一覧表示する | そのフォルダとその下すべてを再入力する | そのフォルダを新規タブで開く | そのフォルダのコンテキストメニュー — ファイルエクスプローラー自身のもの | **ファイル**はそのフォルダに移動する。**テキスト**はそこで入力欄を開き、そのノートに付ける名前を入力させる |
| **区切り文字** | その前のフォルダを開く — フォルダノートプラグインが動作していてそれが存在すればそのフォルダノートを、そうでなければファイルエクスプローラーでそれを表示して展開する | フォルダノートプラグインが動作していてそのフォルダにまだノートがない場合、**そのフォルダのノートを作成**して移動する。すでに存在する場合は、これは単に一回押したのと同じになる | それが存在する場合は新規タブでそのフォルダノートを開く。存在しない場合は一覧を表示した状態でそのフォルダに立つタブを開く | 名前が示すのと同じフォルダのコンテキストメニュー — それがあればそのフォルダノートのもの | 確認すると、そのフォルダにノートがあれば、そのノートの末尾に追加する |
| **ノートの名前** | 名前を編集用に開く — フォルダはその横にチップとして残る — 拡張子を除くすべてが選択されている | 拡張子も選択に含める | そのノートを新規タブで開く | ファイルのコンテキストメニュー — ファイルエクスプローラーの行が出すのと同じもの | 確認すると、このノートの末尾に追加する |
| **空白部分** | **パス全体**を編集用に開き、拡張子まで選択する。フォルダも一緒に入力欄に入るので、これが名前ではなくパスを再入力するための操作になっている | 拡張子も選択に含める | <kbd>Ctrl</kbd>はこのノートを専用の新規タブでもう一度開き、ファイルエクスプローラーで点滅させて、コピーが最初のものと混同されないようにする。中クリックはこの操作*ではない* — パスの上に貼り付ける | パス全体を選択し、選択したテキストに対してできることを提示する | |

**二回目の押下は一回目に続く。** フォルダのノートを作成する操作は、そのフォルダを*開く*行の部分に置かれている — これは既定では区切り文字で、差し替えがオフのときはフォルダ名であり、下線が示すのと同じ対象で、一回押すだけですでにそのフォルダノートを求めているのと同じ対象である。これが提示されるのは、フォルダノートプラグインが動作しているあいだだけである。フォルダノートはファイルシステム上の事実というより慣習だからであり、また、そのフォルダにまだノートがない場合に限られる。それがどこに置かれ、何と呼ばれるかは**フォルダノート**自身の設定から読み取られる。そのため、フォルダの横にフォルダノートを置く Vault や、それを`_index`と呼ぶ Vault では、それに応じたものが作られる。ファイル自体は常に Markdown であり、これはそのプラグイン自身の既定の作成コマンドが作るものであり、また Vault がどの種類に設定されていても見つけ出すものである。名前変更／移動モードはこれには一切関係しない — 移動が保留中のときは、行のどこもフォルダを開かない。

**名前へのクリックは続いていく。** 四つの段階は、名前変更キーがたどるのと同じ四つで、同じ順序である — 名前、拡張子付きの名前、Vault からのパス、システムのルートからのパス。したがって三回目のクリックは Vault のパスに達し、四回目はマシンのパスに達する — これは<kbd>Tab</kbd>で入力欄の末尾を過ぎたときに得られるのと同じ四つであり、右のボタンが選択の代わりに*コピー*するのと同じ四つでもある。

**ホバー**はそれ自体で完結する反応であり、何も変えることはない — 短縮された名前は、指し示しているあいだだけ全体で戻ってくる。行の先頭にあるアイコンは Vault がどこにあるかを示す。

## 右クリック：一回、二回、三回

行のすべての対象は右クリックに応じ、何回押すかによって得られるものが決まる。二回目がまだ来るかもしれないため、一回目は動作するまで約三分の一秒待つ — 一つのボタンに三つの操作を載せることの代償である。

| どこを押すか | 一回 | 二回 | 三回 |
| --- | --- | --- | --- |
| **Vault 名** | Vault のコンテキストメニュー — その要素の名前を持つ Vault に対してできること。そのVault が今いる Vault でない場合は*この Vault を開く*を含む | Vault の名前をコピーする | Vault の場所をコピーする — そして四回目は、開いているファイルの場所 |
| **区切り文字** | そのフォルダのメニュー — フォルダノートプラグインが動作していてそのフォルダにノートがあれば、そのフォルダノートのもの | | |
| **フォルダ名** | そのフォルダのメニュー | フォルダの名前をコピーする | それとその右側すべてをコピーする |
| **ノートの名前** | ファイルのメニュー — ファイルエクスプローラーの行が出すのと同じもの | 名前をコピーする | 拡張子付きでコピーする |
| **空白部分** | | Vault フォルダからのパスを、拡張子なしでコピーする | 同じものを、拡張子付きで |

**Vault 名**への一回の押下は、その要素が名前としているものに対してできることを開く。**今いる Vault**については：新規ウィンドウで開く、Vault を管理する、その場所をコピーする、その ID をコピーする、ファイルマネージャーで表示する。場所の一覧を通じて到達した**別の Vault**については、新規ウィンドウ（これは*この* Vault を開いてしまい、その Vault ではないため）を除いた同じもの、それに加えて、今いない Vault だけが提示できる一つのもの — **この Vault を開く**。これはフォルダ名ではなく ID によって Obsidian に登録されている。二つの Vault が一つのフォルダ名を共有することがあるためである。Vault ではまったくない場所 — ホームフォルダや、マウントされたドライブ — については、コピーする ID も開くものもなく、メニューはそれらを提示しないことでそれを示す。

これは Obsidian 自身の三点メニューではない。それはスターターウィンドウに属していて、動作中の Vault の内部から開くことはできない。ここにあるのは、同じ項目を Obsidian 自身の表記で再構築したもので、そのコマンドから取り出しているため、あなたの言語で表示される。そのメニューの項目のうち三つは意図的に**ここに含まれていない** — *Vault の名前を変更*、*Vault を移動*、*リストから削除*はいずれも Vault 自身のフォルダ、または Obsidian の Vault 登録に対して作用するものであり、今立っている Vault — ファイルが開かれ、監視が動いている状態 — に対してそれを行うことは、Vault を壊す原因になる。Vault マネージャー（*別の Vault を開く*）を開いて、Vault が閉じられた状態でそれらを行うこと。

**空白部分**にある二つのコピーは、行に書かれている通りのもの — リンクや検索が求めるもの — であり、**Vault 名**にあるものは、ファイルシステムが知っているパス、つまり Obsidian の外部にあるものが求めるものである。そこでの押下はそれぞれ、コピーが役立つ範囲を広げていく — 二回で Vault の名前、三回で Vault の場所、四回で開いているファイルの場所。Obsidian は自身の二つのコマンド、*Vault フォルダから*と*システムのルートから*で同じ区別をしている。ここでは、外部向けのものが、パスそのものの外にある要素に置かれている。

これらはすべて、保管庫の外でも、同じ対象に対して機能する。

すべてのコピーは通知でそのことを知らせる。コピーは画面上に何も残さないため、それが起きたことを示すものがなく、数え間違えた押下が成功した押下のように見えてはならないからである。

## 修飾キー：別の場所で開く

ノートの名前とフォルダの要素は、ファイルエクスプローラーでの行と同じように振る舞う。

| | ノートの名前で | フォルダの要素で |
| --- | --- | --- |
| 通常クリック | 名前を編集する | そのフォルダを見る |
| <kbd>Ctrl</kbd> / 中クリック | ノートを新規タブで開く | フォルダを新規タブに送る |
| <kbd>Ctrl</kbd>+<kbd>Alt</kbd> | 分割 | 分割 |
| ドラッグ | ノートを、Obsidian がファイルを受け取るあらゆる場所へ | フォルダを、同様に — タブバーも含めて |

フォルダは Obsidian が開けるものではないため、それをタブに送ると二つのうちどちらかが起こる — フォルダノートプラグインが動作していてそれがあればそのフォルダノートを開くか、パス表示がすでにそのフォルダに立った状態の空のタブを開き、あとは名前を入力するだけにする。フォルダの要素を**タブバー**にドロップしても同じことが、手を離した場所の新規タブで起こる — Obsidian のタブバーはそれ自体ではファイルしか受け取らないため、ファイルエクスプローラーからドラッグされたフォルダはそこでも同じように拒否される。

## Tab：まず名前、次にパス、そして選択範囲を広げる

<kbd>Tab</kbd> はシェルと同じように補完します：**一回押すごとに、そのフォルダ内の名前が一致する範囲まで入力を延長し、食い違う所で止まります。** `Sketches` しかそう始まらない所で `Sk` と打てば単語は完成し、`Alpha-one`・`Alpha-two`・`Alpine` がどれもそうである所で `Al` と打てば `Alp` になります — 次の文字はあなたにしか答えられない問いだからです。

何も入力せずにもう一度押すと、一つの名前――一覧でハイライトされている行、あるいは最初の行――に向かって進み、その名前の次の食い違いで止まります：`Alpha-`、それから `Alpha-one`。一覧は今いる場所を起点に開くので、自分のフォルダの中では一回目の押下は何かのソート順で先頭に来るものではなく、いま開いているノートへ向かいます。

**一回押しても、名前同士のどちらかをあなたの代わりに選ぶことは決してありません。** 入力した内容が候補を一つに絞った時点で、あるいはフォルダの名前を全部入力し終えて他のどんな*フォルダ*もそれを延長しない時点で、<kbd>Tab</kbd> はそのフォルダへ入ります。`Schemes2026` の隣の `Schemes` のように他が延長する場合、<kbd>Tab</kbd> は長い方の名前へ向けて補完を続けます；*これだ*という意思表示は <kbd>Enter</kbd> と一覧のほうです。

**ファイル**がそのようにフォルダを足止めすることは決してありません。自分と同じ名前のノートの隣にあるフォルダはフォルダノートであって、パスの分岐点ではないので、<kbd>Tab</kbd> はフォルダを渡り歩きます — したがって `Projects.md` が隣にある `Projects` も他と同様に中へ入られます。

これに伴う小さな点が二つ：フィールドに収まるのはそのフォルダの綴り方に沿ったものなので、`sk` は `Sketches` になります；そして置き換えられるのは入力中の名前だけなので、その右にまだ続きがあるパスはそれを保持します。

入力中に候補として名前が示されているとき、<kbd>Tab</kbd> は**その候補をそのまま書き込みます**：候補は常に押した場合に書き込まれる内容そのものであり、一覧の下線と緑の線も同じことを示しているので、キャレットの後ろに見えているものがそのまま得られます。名前同士が一致しなくなる所は、それらのうち最初のもの――あるいは矢印キーで移動した行、これが隣の行より優先されて <kbd>Tab</kbd> によって選ばれます――へ向かう一歩です。だから、押す前に欲しいものへ矢印キーで移動するか、分岐点を越えて入力してください。候補が名前を*一つ*に絞る所でだけ、同じ押下がその中へ入ります。

ファイルの名前に到達することが最初の段**そのもの**です――これからマークしようとする名前の末尾にキャレットを置くためだけに一回押されることはありません。そこから先は、押すたびにパスを進むのではなく、選択範囲を広げ始めます：

1. 名前
2. 拡張子込みの名前
3. 保管庫フォルダからのパス
4. システムのルートからのパス
5. **その時点での**パスの先頭へ戻る――歩き始めた場所に立ち、最初の要素がマークされ、再び歩き出す準備が整った状態

四回目のクリックは同じ四段目へ直接到達します。

広げる動作は常に**広げる**だけです。フィールドの中ですでに全体として仕上がっている名前――同じキーで補完されたか、一覧から選ばれたもの――は、まず拡張子を取り戻すのではなく、丸ごとマークされます：最初の段は歩みがちょうど*到達した*名前のためのものであり、そこでは拡張子はまだ話題になっていません。

このはしごは歩みが**到達する**場所であって、始まる場所ではありません。パスの途中にあるフォルダをクリックすると、フィールドはそのフォルダより下すべてを開き、そのフォルダの名前をマークします；そこから <kbd>Tab</kbd> を押すたびに**一つ**のフォルダへ進み――次のフォルダをマークし、残りのパスはその後ろに保ったまま――ファイル名しか残っていない時点で初めて広げる動作が始まります：

| 押下 | パンくず | フィールド | マーク |
| --- | --- | --- | --- |
| `a` をクリック | | `a/b/c/leaf.md` | `a` |
| <kbd>Tab</kbd> | `a` | `b/c/leaf.md` | `b` |
| <kbd>Tab</kbd> | `a › b` | `c/leaf.md` | `c` |
| <kbd>Tab</kbd> | `a › b › c` | `leaf.md` | `leaf` — 最初の段 |
| <kbd>Tab</kbd> | `a › b › c` | `leaf.md` | `leaf.md` |

**確定した名前は、どう確定しようと確定したままです。** <kbd>Tab</kbd> で補完すること、`/` で確定すること、一覧から選ぶこと――どれも行を同じ場所に同じパスを保持したまま残すので、その仕草の後の押下は、どの経路で来ても同じ意味を持ちます。かつては一覧からフォルダを選ぶとフィールドが空になり、<kbd>Tab</kbd> で同じフォルダに到達すれば保持されていたはずのパスを捨てていました。

**まだ書きかけのパスは丸ごとついてきます。** 残りのパスがぶら下がっているまさにそのフォルダへ入ることは、残りが存在するという主張ではありません――それはパスが自分自身より先に入力される仕組みであり、そこで名指されたフォルダは <kbd>Enter</kbd> がまさに作ろうとしているフォルダです。ですから `Dokumente/plans/untitled.md` を歩んで `Dokumente` へ入っても、`plans` がまだ存在するかどうかにかかわらず `plans/untitled.md` は目の前に保たれます。何もない所から入力したパスについても同じです：どこからも継承されていないので、何も取り去られません。

**一つの段を別のものに差し替えるのは話が別で、そのときパスはそこに本当に存在する分だけしかついてきません。** パスの途中のフォルダを同階層の別のものに差し替える――`a` をクリックし、別の名前を入力し、<kbd>Tab</kbd> を押す――と、その下のすべてがついてきます。今いたパスは、たいてい欲しいパスの大部分だからです。ただし、そちらに実在するものだけが移動を生き延びるので、フィールドとその隣の一覧が食い違うことは決してありません：目の前に残るのは実際に歩けるパスです。`a/b/c/leaf.md` から始め、`a` をクリックしてその名前がマークされている状態で：

| 確定した内容 | パンくず | フィールド | マーク |
| --- | --- | --- | --- |
| `x`、`b` すら全くない | `x` | | 何もついてこなかった |
| `y`、`b` はあるが中に `c` はない | `y` | `b` | `b` |
| `z`、`a` の末端までそっくりな双子 | `z` | `b/c/leaf.md` | `b` |

そのように単独で残されたフォルダも、依然として歩いて入れるフォルダです：その後の押下はその名前の上で選択を広げ始めるのではなく、中へ入ります。

フォルダの中に一致するものが**何もない**名前には違う応じ方をします。何もそれによって確定していないからです：押下は入力した内容をマークし、上書き入力できる状態にします――どこか別の場所で応じるのではなく。

これ全体は一つの**循環であり、一周するのに何も失いません**：最後の段の後の押下は、フォルダも含めてパスの先頭に行を戻し、再び一周する準備を整えます。行から失われるものが唯一あるとすれば、それは絶対パスの接頭部だけで、それが表示されなくなる押下のときです。

戻ってくるのは**あなたが組み立てたパス**であって、出発点だったパスではありません。歩みの途中で分岐する――一覧から別の兄弟を選ぶ、別の名前へ向けて補完する――と、一周はあなたが実際にいる場所で閉じます；その手前の四段は同じそのパスを表しており、この段はかつて過去を表す変則的な段でした。

<kbd>Shift</kbd>+<kbd>Tab</kbd> は同じ輪を逆回りに閉じます：パスの先頭で、返すものも上がる先もなくなったとき、次の押下は**最も遠い**段――システムのルートからのパス――へと循環し、そこから再び狭め始めます。どちらの方向にも行き止まりはありません。

すでに示した段に押下を費やすこともありません。最後の段――拡張子のない名前――より下ではしごは終わり、*同じ押下*でフォルダを出ます：システムのルートからのパス、保管庫からのパス、名前、拡張子のない名前、そしてフォルダ、一段ずつです。

何も変わらない段にも押下は費やされません：ノートの名前をクリックした時点ですでに拡張子なしで表示されており、それは最初の段が示すものと同じなので、そこから <kbd>Tab</kbd> は二段目から始まります。

各段はハイライトされる部分だけでなく、フィールドの*中身*そのものを変えます――選択範囲はそれが名指すテキストの上になければ、<kbd>Enter</kbd> は見えている選択とは違う何かを確定してしまうからです。このはしごは一つの編集セッションに属します：どこかをクリックするか、何かを入力すれば、次の <kbd>Tab</kbd> はまた名前の補完から始まります。

### <kbd>Shift</kbd>+<kbd>Tab</kbd>：同じ道を逆に

<kbd>Shift</kbd>+<kbd>Tab</kbd> は押すたびに、押された順番通りに一歩ずつ戻します：選択範囲は一段ずつ狭まり、補完は一つずつ返され、フォルダは一つずつ出ていきます――その名前はフィールドに戻ってきて、打ち直すのではなく編集できるようになります。

**戻る道すがら何も削除されません。** 補完は、それが加えた文字を*マークする*ことで返されます――進む方向が広げた部分をマークするのと全く同じです――名前は目の前に残り、さらに押すたびにもう一段分がマークされます：

| | フィールド | マーク |
| --- | --- | --- |
| 歩いて入った | `Alpha-one` | |
| <kbd>Shift</kbd>+<kbd>Tab</kbd> | `Alpha-one` | `one` |
| <kbd>Shift</kbd>+<kbd>Tab</kbd> | `Alpha-one` | `ha-one` |
| <kbd>Shift</kbd>+<kbd>Tab</kbd> | `Alpha-one` | `Alpha-one` |

入力するとマークされた部分が置き換わるのは、他の場所と同じです。<kbd>Tab</kbd> はマークが返したものをそのまま元に戻すので、二歩外へ出て二歩また入れば元いた場所に戻ります。

名前全体がマークされると、押下が置いたものはもう何も残っていないので、次の押下は*パスを上へ*進みます：空のフィールドで <kbd>Backspace</kbd> を押すのと全く同じように、今いるフォルダを出ます。それにも何も失われません――そのフォルダの名前は、中にあった内容の**前に**マークされた状態で戻ってきます。これはそのフォルダをクリックした場合に得られるのと同じテキストです。「戻る」は取り消し履歴ではなく方向です――ただし先に名前をマークすることで、一回の押下が書いた内容を取り消すことと、書いていたフォルダから出ることを同時に行ってしまうことはありません。

**すでに選択された状態で**開くテキスト――フォルダのクリックが残していくもの――は、次に <kbd>Tab</kbd> が処理する名前です：他のものと同様に補完され、中へ入られ、入力すれば置き換わります。フォーカスコマンドだけがはしごそのものの一段目で開きます。歩くべきフォルダではなく、パス全体をあなたに見せているからです。

## パスではないものを入力する

| 入力するもの | 起こること |
| --- | --- |
| `https://…` | そのコアプラグインを有効にしていれば Obsidian の**ウェブビューア**の新規タブで開く；そうでなければデスクトップのブラウザで開く |
| `obsidian://…` | Obsidian 自身の URI ハンドラーに渡される |
| `file:///…` | デコードされて開かれる：保管庫の中にあれば本物のノートとして、そうでなければビューアで |
| `/home/you/a%20b.md` | 同様に、ブラウザやファイルマネージャーから貼り付けたパスに対して |

明示的なスキームだけがそう扱われます――`100%20` という名前のノートは依然としてノートです。スキームに属する `/` はフォルダへ下ることなくそのまま文字として扱われるので、URL は貼り付けだけでなく手で入力することもできます。

## キーボードのためのコマンド

**パスバーにフォーカス**は、ノートの名前でフィールドを開き、<kbd>F2</kbd> と同じように歩きます――名前、拡張子込みの名前、保管庫からのパス、システムのルートからのパス――そしてその後の押下でフィールドを閉じ、カーソルをノートへ戻します。名前は変更しません：他のどのフィールドとも同様に、Enter はナビゲーションです。標準では専用のキーは割り当てられていません。Obsidian のガイドラインがプラグインによるキーの占有を推奨していないためです；このプラグインの設定の末尾にある「**ホットキー**」の行は、このプラグインのコマンドだけを表示した状態で*設定 → ホットキー*を開くので、そこで割り当てられます。

## ナビゲーションは開いているファイルに触れない

既定（ナビゲーション）モードでは、開いているノートの名前が変わったり移動したりすることは**決してありません**。

- 既存のファイルに解決するパスは、それを開きます。
- まだ存在しないパスは、足りない親フォルダもろとも単純に作成され、開かれます。この方法で作られたファイルやフォルダは必ず通知でそう知らせます――さもなければ新しいフォルダは、あなたが探しに行くまで見えないままです――そして Obsidian 自身のごみ箱のおかげで、望まないものはキー一つで元に戻せます。
- **保管庫の外では、それでも先に確認します。** そこでは同じ誤字がシステムフォルダに書き込んでしまい、通知も Obsidian のごみ箱もあまり慰めにはなりません。

## <kbd>Ctrl</kbd> — 新規タブ、そして移動ではなくコピー

保管庫の中で**作成・移動・コピーされたノートは、着地した場所がファイルエクスプローラーに表示され**、Obsidian のアクセントカラーで一瞬マークされます――ツリーは後でそれを探す場所なので、開いていないかもしれないフォルダの中に置き去りにするのではなく、目の前に示されます。複製についても同様です：コピーは元のものをそのまま残し、コピーを自分のペインで開きます。何も言わなければ、何も起きなかったと読み違えやすいからです。

一覧からファイルを選ぶとき、またはパスで <kbd>Enter</kbd> を押すときに <kbd>Ctrl</kbd>（macOS では <kbd>Cmd</kbd>）を押していると、結果はこのタブではなく**新規タブ**へ送られます:

| | そのまま | <kbd>Ctrl</kbd> あり |
| --- | --- | --- |
| 既存のファイルを選ぶか入力する | ここで開く | 新規タブで開く |
| 存在しないパスを入力する | 確認のうえ、ここで開く | 確認のうえ、新規タブで開く |
| 名前変更／移動モードでパスを確定する | ノートをそこへ**移動** | そこへ**コピー**し、コピーを新規タブで開く |

修飾キーは Obsidian 自身のルールで読まれるので、リンクやファイルエクスプローラーの行の上と全く同じにふるまいます — 中クリックも「新規タブ」、<kbd>Ctrl</kbd>+<kbd>Alt</kbd> は分割、<kbd>Ctrl</kbd>+<kbd>Alt</kbd>+<kbd>Shift</kbd> は新規ウィンドウです。

コピーは、移動と全く同様に上書きを拒みます――ノート自身のパスへのコピーも含めて、そこにはコピーする意味のあるものが何もありません。保管庫の外でも、その拒否ははっきり伝えられます。

これらすべては、一覧が開いていても開いていなくても**同じように**動作します：ハイライトされた行の上では修飾キーはその行に適用され、何も選ばれていない状態では入力した内容に適用されます。

## 保管庫の外を見る

**これは既定でオフです。** まず設定で **外部ファイルへのアクセス** をオンにしてください — 保管庫の外を読み書きすることは、このプラグインが行うことのうち Obsidian 自身が行わない唯一のものなので、オフにするものではなくオンにするものにしてあります。オフのあいだ、保管庫名は単に保管庫をファイルエクスプローラーで表示するだけで、ここにあるものがその先を見ることはありません。

**保管庫名**（*保管庫名を表示* がオフのときは 🏠 アイコン）をクリックすると、内容ではなく場所の一覧が開きます。開くフィールドには**あなたがいたパス全体がそのまま書き出され**、その始まりの場所が選択された状態になります — なので、別の場所を選ぶか選択部分を打ち替えるかすると、その先頭部分だけが差し替わり、残りのパスは目の前に残ります。**名前をもう一度押す** — ダブルクリック — と選択範囲がその全体に広がります。手で全部をなぞる代わりに、こうして一つの操作で絶対パスを取り出せます。気が変わったら <kbd>Esc</kbd> で行を元通りに戻せます。

ここでの入力にも、ほかと同じくその場所の名前の続きが差し出され、<kbd>Tab</kbd> で**その場所を確定**します — 指し示している場所、あるいはその名前が意味しうる唯一の場所です。入力したものをまだ複数の場所が共有しているときは、ほかの場所と同じくその分かれ目で止まります。ある場所を指すと、**その場所自身のパス**が全選択の状態で示され、続けてあなたのノートのパスが実際にそちらで通じるところまでだけ示されます — それは選べばまさに着地する先そのものです。場所は画面上のパスの中の一段ではなく、そこからパス全体を数え直す起点なので、いた場所の痕跡はその手前に何も残りません。

用意されている場所:

- **ほかの保管庫**。Obsidian 自身の記録から読み、最近開いた順に、それぞれ Obsidian 自身の保管庫アイコンの下に並びます — アプリが保管庫コマンドに使っているアイコンです。すでに開いている保管庫だけは家のアイコンになります: そこは既定でこの行が始まる場所であって、行き先ではないからです。
- **ホーム**。自分のアカウント名の下に、`~` の印付きで並びます。Lucide にチルダはないので、これはプラグインが Lucide 自身の 24×24 グリッドに同じ線幅で描いています — アイコンの列に紛れ込んだ文字ではなく、セットに欠けているアイコンとしてです。
- **ファイルシステムのルート**。`root` と表示します — どのシステムでもそう呼ばれるので訳しません — `/` にしないのは、後ろに続く区切り文字の隣で空の一段のように読めてしまうからです。
- **マウント済みドライブ**。種類の判定が安く済むところでは種類ごとのアイコンが付きます: ネットワーク共有、光学ディスク、フロッピー、リムーバブルメディアはそれぞれ専用のもの、それ以外は汎用のドライブです。Windows ではドライブは汎用アイコン付きの `C:` として出ます — ボリューム名や正確な種類には WMI が要るので、あえて行っていません。

ほかの保管庫を選んでも **Obsidian がそちらに切り替わることはありません。** 開いているものはすべて開いたままで、パスの表示がそこを見始めるだけです。サイドバーの保管庫切り替えに任せず、パスバーに置いてある意味はまさにそこにあります。

さらに、**その場所が実際に届く範囲でいまのノートにできるだけ近い場所**に着地します。

- 選んだ場所がそのノートを*含んでいる*なら — ホーム、あるいはあなたの保管庫たちが住んでいる場所 — そこからのパスが得られます: `takeaways.md` を開いた状態で `~` を選ぶと、フィールドは `Vaults/your-vault/takeaways.md` になります。
- それがこの隣にある場所なら — 別の保管庫、別のドライブ — 同じ相対パスが、実際に存在する深さまで試されます。保管庫どうしは互いにほぼ複製であることが多く、あるものへ飛ぶ理由はたいてい向こうにある同じノートだからです。

どちらの場合も、行は選んだ場所にとどまり、**そのパスの最初のフォルダが選択された状態で開きます** — フォルダをクリックしたときと同じ形です: どこかへ飛んだときに変えたくなる可能性が一番高い一段は一番上に近い一段で、それを変えているあいだも残りのパスは見えたままです。ディスク上に実在しないものが前もって埋められることは決してありません。

### 外にいるあいだ

パスは**選んだ場所から始まり**、マシンのディレクトリ構造からは始まりません — 空白部分をクリックするか、フォーカスキーを押して得られるフィールドも同じです: 中で保管庫のルートに畳まれるのとまったく同じように、その道のりはその場所自身に畳まれた状態で、その場所からのパスを保持し、マシンの絶対パスは保持しません — `Archive` を選べば行は `/home/you/Vaults/Archive/notes/…` ではなく `Archive / notes / …` になります。先頭の要素にはそれが何であるか（保管庫、ホーム、ドライブ）を表すアイコンが付き、<kbd>Backspace</kbd> はそこで止まり、ファイルシステムの残りへとさらに上へは歩いていきません。*保管庫名を表示* がオフのときは、その要素はアイコンだけになります — この設定は、どの保管庫を指していようと行の先頭要素についてのものであって、自分自身の保管庫だけのものではありません。

パスバーは、保管庫の外を指しているあいだずっと**エラー色で囲まれます** — 名前変更モードが描くのと同じ枠です。これは瞬間ではなく継続する状態を示します: それが出ているあいだ、行が示しているものに Obsidian 自身の扱いは一切適用されず、あなたがそう言うまで書き込みはロックされたままです。

それ以外、閲覧は中にいるときと同じように働きます: チップ、区切り文字、入力、補完、外へ出るための <kbd>Backspace</kbd>。表示のルールも同じなので、対応していない拡張子には引き続き Obsidian の *すべてのファイル拡張子を認識* が要り、ドットファイルには引き続きこのプラグインの設定が要ります。

**外でも右クリックは使えます**が、別のメニューになります: ファイルエクスプローラー自身の処理は保管庫が知っているファイルを必要とするので、外の項目はパスから組み立てられます。開く（ここで、右で、新規ウィンドウで、あるいはデスクトップの既定アプリで）、*パスをコピー*、*システムのエクスプローラーで表示*、そして — 南京錠が開いていれば — *新規ノート*、*新規フォルダ*、*コピーを作成*、*名前を変更…*、*削除* を差し出します。**ドラッグ**は引き続き保管庫のファイルを必要とし、使えないままです。

同じメニューはビューアで開いているファイルにもあり、右クリックか、あるいはペイン自身の三点メニューから出せます。そしてそのビューのヘッダーにある南京錠に尋ねます。それ以外は何も尋ねません: ファイルが描画されているかソースとして表示されているかは、削除できるかどうかとは関係がなく、ソース表示を持たない画像や PDF もノートと同じように削除できます。*削除* はデスクトップのごみ箱行きを意味するので、そこから元に戻せます。ごみ箱のないシステムでは、破棄する代わりにそう報告します。

保管庫の外での削除はファイルを**システムのごみ箱** — Windows ならごみ箱、macOS ならゴミ箱 — へ移すだけで、リンク解除にはなりません。外には元に戻せる Obsidian のごみ箱がないので、元に戻せない削除はそもそも差し出されません: ごみ箱のないプラットフォームでは、試みが失敗として報告されます。

### 保管庫の外に書き込む

書き込むものはすべて**既定でロック**されています。行が保管庫の外を指しているあいだ、ヘッダーの名前変更トグルの場所には**赤い南京錠**が入ります — 行を囲む枠と同じ色で、理由も同じです: それは拒否を示しています。この二つは一つのスロットに入る一つのコントロールなので、どちらが何を制限しているのか迷うことはありません。

三回の押下が一巡します:

| 押下 | 得られるもの |
| --- | --- |
| 赤い南京錠 | ここでの書き込みが許可されます。南京錠は名前変更／移動トグルに置き換わります |
| トグル | 名前変更／移動モード。保管庫の中とまったく同じです |
| もう一度トグル | モードが終わり、南京錠が再び閉じます — 許可はそれが開かれた対象より長くは生きません |

**名前変更キーも南京錠に尋ねます。** 保管庫の外でこれを押すと、どのコミットも拒まれるモードを開く代わりに、南京錠が開いてまた閉じる様子を一瞬見せます: 作業の後ではなく前に拒否が届くわけです。南京錠を押すか、名前変更キーを 0.5 秒以内にもう一度押してください — 二回目の押下はボタンが与えるのとまったく同じ許可をこの場所に与え、それとともに名前変更モードを開きます。

保管庫の中には南京錠がありません: 解除するものが何もないので、トグルが単にそのスロットを占めています。

許可は**瞬間ではなく場所に対して**与えられます: 一つの場所で作業しているあいだに行うことすべて — 移動を終える、入力欄の外をクリックする、ファイルを開く — をまたいで生き続け、ドロップダウンから別の保管庫、ドライブ、ルートを選んだとき、行が保管庫のファイルに戻ったとき、あるいは三回目の押下で終わります。なので一つのフォルダの中で連続して移動するなら、必要なのはファイルごとの押下ではなく一回の押下だけです。

南京錠が開いていれば、パスバーは外でも中と同じようにふるまいます:

| 操作 | 結果 |
| --- | --- |
| 存在しない名前を入力して <kbd>Enter</kbd> | 中と同じ「作成しますか？」の確認。足りない親フォルダも作られます。拡張子のない名前は、中とまったく同じく `.md` になります |
| 名前変更／移動モードで新しい名前を入力 | 行が示しているファイルの名前を変えます。拡張子のない名前はそのファイルの拡張子を保ちます — 外ではフォルダにあらゆる種類のファイルが入っており、名前変更が黙って `.png` を `.md` に変えてしまってはいけないからです |
| 名前変更／移動モードで別の場所へ移り、**この名前のまま**を選ぶ | 今の名前のままそこへ移動します |
| どちらでも <kbd>Ctrl</kbd> を押しながら | 移動ではなくコピーし、コピーを新規タブで開きます |

ロックされていれば、これらはどれも実行される代わりに何が妨げているかを知らせます。どちらの状態でも何かが上書きされることはありません: すでに存在する行き先は拒否され、その拒否は競合に負けうるチェックではなくファイルシステム自身のもの（`COPYFILE_EXCL`、排他的な作成）です。ファイルシステムをまたぐ移動 — USB メモリから、ネットワーク共有から — はコピーしてから削除する方式に切り替わり、コピーが着いてから初めて元が消されます。

**ノートを保管庫の*外へ*移動するときは、まず確認します。** `fileManager` はその境界をまたいでファイルを追うことができません: そのノートを指すすべてのリンクは解決できなくなり、何もそれらを更新せず、そのノートは保管庫の索引から外れます。なので、この移動は拒否されるでも黙って実行されるでもなく、判断として差し出されます — ダイアログが、それが何を犠牲にするかと、あなたが移動しようとしているノートに何本のリンクがあるかを示します。確認すれば実際に移動します: 外へコピーしたのち、Obsidian 自身の削除を通して保管庫から取り除かれるので、削除されたノートとまったく同じように復元でき、どちらかの段階で失敗すればノートは元の場所に残ります。<kbd>Ctrl</kbd> を押していれば代わりにコピーするだけで、こうした問題は一切ありません。逆方向 — 外部ファイルを保管庫に*取り込む*こと — はまだ実装されていません。

### 外部ファイルを開く

ファイルシステムを見て回っていると、**開いている保管庫の中へ**戻ってくることがあります — ルートから、ホームから、あなたの保管庫たちが住んでいるどこかから。そうやって辿り着いたファイルは普通のノートなので、ノートとして開きます: 本物のエディタ、リンクとバックリンク、そして行は保管庫を起点としたパス表示に戻ります。プレビューにとどまるのは、Obsidian がビューを持たないファイルだけです。外ではプレビューのほうが優れた答えだからです。そうしたノートがすでにプレビューで表示されているとき — 開き直したワークスペースなど — その一番上の行が **《保管庫名》で開く** を差し出します。これは手でする場合と同じ提案です。

Obsidian のエディタは保管庫の中のファイルにしか働かないので、外部ファイルをリンクやバックリンクを備えた本物のノートとして開くことは**できません** — これはアプリの制限であって、このプラグインの制限ではありません。選ぶと代わりに**プレビュー**が開き、あなたがそう言うまで読み取り専用です:

| 種類 | 表示のされ方 |
| --- | --- |
| `.md`、`.markdown` | 描画された Markdown |
| `.html`、`.htm`、`.xhtml` | 描画されたページ |
| 画像、音声、動画、PDF | ネイティブのプレーヤー／ビューア |
| そのほかの**テキスト**ファイル（`.json`、`.css`、`.log`、`.txt`、…） | そのままのプレーンテキスト |
| ビューアのないバイナリ形式（`.zip`、`.exe`、…） | *既定のアプリで開く* に渡されます |

ビューアはファイルの読み方を二通り持っており、互いに排他なので、**切り替える先**のほうだけが表示されます:

| | すること | 既定になる形式 |
| --- | --- | --- |
| **Markdown として表示** | ファイルをノートとして描画、読み取り専用 | `.md`、`.markdown` |
| **ページとして表示** | ファイルをそのもののページとして描画、読み取り専用 | `.html`、`.htm`、`.xhtml` |
| **テキストとして編集** | ソース、編集可能 | それ以外すべて |

保管庫の外では、**テキストとして編集** は読み取り専用を解除する操作でもあります — モードと許可を、二つのボタンで考えるのではなく一つの操作にまとめてあります。**押せば読み取り専用が解除される状況ならいつでも**赤みを帯びます。その場で編集を構えるときも、描画表示から直接来たときも同じです。保管庫の中では解除するものがないので、そこでは普通の見た目のままです。**Markdown として表示** は薄いアクセント色に染まります — Obsidian が選択テキストに与えるのと同じ色合いです — 行動を促すものではなく戻り道であることを示しています。

ボタンが素のモードではなく*編集*を追っているので、テキスト表示で読み取り専用のまま置かれているファイルにも **テキストとして編集** が出ます: それが編集を構える操作だからです。決して書き込めないファイル — 省略表示のもの、読めなかったもの — には代わりに **テキストとして表示** と出ます。押して得られるのはそれだけだからです。

既定は字面どおりではなく役に立つ側に倒してあります: シェルスクリプトの `#` は見出しではなくコメントなので、`.log` を Markdown として描画すればそれを黙って飲み込んでしまいます。どちらの既定もファイルごとに上書きでき、その選択はリーフの履歴に入るので、戻る／進むも、開き直したワークスペースも覚えています — `.txt` に住むノートはいくらでもあり、ソースで読むほうが楽な `.md` もいくらでもあります。

#### HTML ページに許されていること

何もありません。ページは**あらゆる権限を与えられずに**フレームの中で表示されます —
スクリプトなし、フォームなし、ナビゲーションなし、自身のオリジンなし — そして
コンテンツポリシーはネットワークへのアクセスを一切許しません。これは念のための
用心ではありません: ローカルのページを普通の方法で読み込めば、このウィンドウの
オリジンを共有してしまい、このウィンドウは Obsidian そのものなので、ダウンロード
した HTML ファイルの中のスクリプトがあなたのアプリの中で、あなたのアプリの権限で
動いてしまうことになります。

その代償はページが*する*ことのすべてであり、保たれるのはページが*そのもの*で
あることのすべてです。ファイルの隣にあるスタイルシートや画像は読み込まれて
フレームに持ち込まれるので、保存されたページは相変わらず自分自身のように
見えます。ページ自身のフォルダの外を指す参照や、ウェブ上のどこかを指す参照は
書かれたとおりのまま残され、単に読み込まれません — ローカルのファイルが、
あなたがそれを開いたことをサーバーへこっそり伝えることはできません。

スクリプトは単に阻止されるのではなく**取り除かれます**。そうすることで、
目にするページと切り替え先のソースの違いが、フレームが黙って実行を拒んだ
何かによるものではなく、はっきり述べられた一点だけの違いになります。
ページの中のリンクは何もしません。本物のもの — スクリプトもネットワークも
すべて — が欲しくなったら、*既定のアプリで開く* がそれをあなたのブラウザに
渡します。そちらこそがそのための正しい道具だからです。

**保管庫の中のファイルは解除なしですぐ編集できます**: *テキストとして編集* は本物のエディタで、入力に応じて書き戻します。

**編集は切り替えをまたいで覚えられます。** *Markdown として表示* へ行くと編集は中断します — 静的な描画には入力する先がなく、Live Preview は保管庫の中のファイルにしか存在しない Obsidian 自身のエディタを必要とします — なので、そこにいるあいだ編集中だと主張するものはありません。*テキストとして編集* に戻れば続きから再開します。

**保管庫の外のファイルは読み取り専用で開き、*テキストとして編集* がそれを解除します。** その一押しが門のすべてです: それが起きるまで、外には何も書かれません。押したあとは保管庫の中のファイルとまったく同じく、入力に応じて保存され、状態行は錠から鉛筆に変わります。解除が及ぶのはそのタブのそのファイル一つだけ — 別のファイルへ移れば再びロックされます — そしてこれは意図的にタブの履歴に保存されないので、開き直したワークスペースが、開いた覚えのないシステムファイルに書き込みを構えた状態で戻ってくることはありません。

**省略表示のファイルはどのみち読み取り専用のままです** — 画面にあるものを保存すれば上限より先がすべて失われるので、ボタンは出したうえで拒むのではなく、そもそも出しません。読めなかったファイルも同じです: 空のペインのほか、書き戻すものがありません。

書き込みが失敗したら — 読み取り専用のマウント、自分のものでないファイル — システム自身の理由が通知で示されます。

とても大きなファイルは省略して表示し、状態行がそれを伝えます。自分で気づかせるのではなく、ボタンの後ろではなくほかの条件と並べて — ほかと同じくファイルについての事実だからです。上限は推測ではなく実際のレンダラーに対して測ってあります — 1 メガバイトのテキストを一つのペインに組めば Obsidian のレンダラープロセスは丸ごと落ちますし、Markdown は 1 バイトあたりプレーンテキストの数倍かかるので、二つには別々の上限があり、ファイル全体が小さくても一行が巨大ならその行は短くされます。

**状態行はラベルであり、説明はツールチップです。** 各線は必要なだけの語数で事実だけを述べます — *保管庫の外*、*このファイル形式のエディタがありません*、*省略表示 — ファイルが大きすぎます* — 隣のボタンがファイルの状態をすでに語っているからです。ポインタを重ねればその一文が出ます: なぜ Obsidian がノートとして開けないのか、この形式は本来どう扱われるのか、省略で何を失うのか。

これは保管庫の**中**のファイルにも当てはまります。Obsidian はビューを持たない拡張子をそのままデスクトップの既定アプリに渡します — つまり保管庫の中の `.txt` や `.json` は Obsidian から出ていってしまいます。それらも今は同じビューアで、オレンジの枠付きで開きます。「Obsidian で開く」があなたの求めたことだからです — そして保管庫のファイルなので、そこでは何の解除もなしに編集できます。ビューアのないバイナリファイルは Obsidian の動作のままです。表示するものがありません。

プレビューは**いたタブの中で**開くので、戻る／進むで元のノートに帰れます。ほかと同じく <kbd>Ctrl</kbd> で新規タブです。開いているあいだヘッダーバーは外部ファイルのパスを表示し続けるので、そこから閲覧を続けられます。

内容の上の控えめな行が、出口を差し出します:

- **《保管庫名》で開く** — ファイルがほかの保管庫の一つに属しているときに表示されます。Obsidian 自身の URI ハンドラに渡し、そのノートを入れた状態でその保管庫のウィンドウを、本物の編集可能なノートとして開きます。このウィンドウは元のままで、あなたの足元で何かが切り替わることはありません。
- **Markdown として表示** ／ **ページとして表示** ／ **テキストとして編集** — このファイルが持つ二通りの読み方です。最後のものは保管庫の外での読み取り専用も解除します。
- **既定のアプリで開く** — ファイルをデスクトップの既定アプリに渡します。このビューアが表示できないバイナリ形式も含めてです。同じ操作を表す Obsidian 自身の項目とまったく同じ表記になっています。同じ操作だからです。

ビューアは**右クリック**にも応じます: テキストエディタの中では *切り取り* ／ *コピー* ／ *貼り付け* ／ *すべて選択*、それ以外の場所ではそのファイル自身のメニューです。ヘッダーにある Obsidian の三点メニューもそのメニューを備えます — 保管庫の外では、そうでなければ *右に分割* と *下に分割* しか出せないところです。

先に *テキストとして編集* を押さないかぎり、保管庫の外には何も書かれません。全面的な説明は README の [保管庫の外](README.ja.md#保管庫の外) の節を参照してください。

## パス内のフォルダにファイルをドロップする

行にあるすべてのフォルダはドロップ先になる。つまり **ノートをドラッグしてフォルダに落とすと、そこへ移動する** ——ノートとその上にあるどのフォルダとの間も、行き先がすでに画面上にある分、最短の経路になる。File Explorerから、一覧から、ヘッダーのノート自身の名前から、あるいはObsidian内のファイルを生成するどこからでもドラッグできる。これはアプリ自体のドラッグなので、ホバー時のラベル、カーソル、ハイライトはFile Explorerが描くものと同じになる。

**保管庫の名前もドロップを受け付ける**。行の一番上にあるフォルダだからで、ここからノートを保管庫のルートに置ける唯一の操作になる。

**複数選択したものもまとめてドラッグでき**、ひとまとまりとして移動する。もしどれか一つでも移動できないものがあれば、一部だけ移動して残りを黙って飛ばすのではなく、ドロップそのものが拒否される。

リンクはノートに追従する。File Explorerから移動したときや、パスを入力して移動したときとまったく同じように。

**ドロップを受け付けられないフォルダは、何も提示しない**——*ここに移動*というラベルもフォルダのハイライトも出ない——失敗するとわかっているものを提示するくらいなら、何も出さないほうがいい。代わりにそこに立つのは、Obsidian自身がヘッダーに用意している答え、*このタブで開く*だ。三つのケースがある：

- ファイルが **すでに入っている** フォルダ——すでにそこにあるから；
- **自分自身、または自分の子孫の中に** ドロップされたフォルダ——それでは元いた場所がなくなってしまうから；
- **フォルダとその中身の両方** を含む選択——フォルダを移動すれば中身も一緒についてくるから。

すでに **同じ名前のファイル** を持つフォルダはドロップを受け付け、行く手を阻むファイルをどうするか尋ねる。入力または選択した名前がすでに使われている場合と同じダイアログだ——[使われている名前](#使われている名前)を参照。ここでは何も上書きされない。

**保管庫の中にある** フォルダだけがドロップを受け付ける。行が保管庫の外を指している間、その要素は拒否する。ノートを保管庫の外に出すと、そこへのすべてのリンクが壊れるからだ——身振り一つで済ませるより、問いを立てる価値のある決断だ。あえてそれを行う方法は、今もパスを入力することだ。それなら先に確認を求め、何件のノートが影響を受けるかを教えてくれる。

## テキストやファイルをドロップして書き込む

同じドロップ先は **内容** も受け付ける。ファイルと内容の違いは、ドロップする場所ではなく、ドラッグしているものが何かで判断される。

**行がすでに名前を示しているノートの上** ——ノート自身の名前、あるいはフォルダノートを持つフォルダを指す区切り文字——にドロップすると、ドロップした内容は空行を挟んでその末尾に追加される。まず確認を求める。すでにあるファイルに書き込む操作であり、ドラッグは不安定な手が偶然にでも行える身振りだからだ。エディタから出したテキスト、デスクトップから出したファイル、この保管庫の外に出したノート、いずれも機能する。ファイルはテキストとして読み込まれ、バイナリファイルは意味不明な文字の羅列として貼り付けられるくらいなら拒否される。

**場所——保管庫名やフォルダの上** ——にドロップした場合、まだ何も名付けられていないので、何も書き込まれない。フィールドがそこに開き、ドロップした内容を保持する。入力する名前がそれを確定させる：新規ノートはそのテキストを持つ状態で *作られ*、既存のノートには上と全く同じように尋ねられる。<kbd>Esc</kbd>、あるいは他の場所をクリックすると、すべてが手放される。

**内容として着地するドラッグがその上にある間、行は青く縁取られ**、フィールドが内容を保持している間も青いままだ。同じ青が、同じことを伝えている：この先起きることは、あなたが運んでいるテキストに関するものだ、と。自分の保管庫から出したファイルをフォルダにドラッグする場合、それは今も *そこに移動する* という意味であり、Obsidian自身のハイライトを保ち、決して青くはならない。その身振りは先にあったもので、内容はそれに一歩譲る。

## パスがペインより長いとき

名前は詰めるのではなく **短縮される**。最も必要とされない順に：

1. **まず保管庫名**を、アイコンだけになるまで。今いる保管庫がどれかはわかっているので、アイコンはパスがどこから始まるかを伝え続ける。
2. **次にファイルの拡張子**、表示がオンになっている場合——保管庫内のほぼすべてのファイルに共通する同じ三文字。これは短縮されずまるごと消える：拡張子の半分は、拡張子なしと同じく何も伝えない。
3. **次にフォルダ、最も長いものから。** 最も長いフォルダ名は、次に長いものの長さまで縮まり、続いて両方一緒に縮み、それを繰り返す。それぞれに下限があるので、非常に長いフォルダ名が持ち分をすべて他に譲り渡してから、隣の短い名前が一文字失う。
4. **最後にファイル自身の名前**。これはおよそ六文字を保つ。ヘッダーはこのためにある。

余白は **文字単位ではなく、一ピクセルの何分の一という単位で連続的に** 手放される：譲る名前はそのピクセルで切り詰められ、`…`の下に消えていく。だからペインをゆっくりドラッグすると行は滑らかに狭まり、それ以降の部分は段階的には動かない。どの文字が消える前にも、まず区切り文字周りの余白が使われる——それは行における唯一の余白であり、情報を何も犠牲にしない——そして短縮された名前は区切り文字が始まるところで終わり、両者の間に空の帯は残らない。

**フィールドは保持している内容の分だけ場所を取る。** パスを入力するために一つ開いても、隣のフォルダを押しのけたりはしない：フィールドは中のテキストと同じ幅を持ち、入力するにつれて広がる。だから軌跡はフィールドが必要としないものすべてを保つ。両方に十分な余地がない場合に限って行はスクロールする。そしてフィールドだけは決して譲らない一つのものになる——それは編集中のテキストであって、収まるよう調整される名前ではないからだ。

隣と見分けがつく限界を超えて切られることはない：`Projects2025`と`Projects2026`が同じフォルダにある場合、二つを同じ言葉にしてしまう先頭一致ではなく、`…025`と`…026`に落ち着く。一方`Reports`は隣の`Receipts`と並ぶと`Rep…`まで削れる。それに加え、すべての名前は **読める幅** を保つ——フォルダなら四文字分、ファイル名なら六文字分ほど。これは実際に行が描かれるフォントで測られ、文字数で数えられるわけではない。細い文字四つと太い文字四つは同じ量の名前ではない。だから`lilliliillil`は`WWMMWWMMWWMM`より多くの文字を残すことが許され、画面に残るものはどちらも同じ大きさになる。短い名前はそのまま手をつけられない——`A…`まで削られた名前は一意ではあっても読めないままだ。**空白はこの幅に含まれない。** どのファイルかを伝える六文字は、読む価値のある六文字であり、その間の空白は無料で付いてくる。空白が`…`にぴったりくっついて、見えなくなってしまうことは決してない。

**名前は隣同士が一致する部分で切られ、どこにも一致がなければ真ん中で切られる。** `aaaa-common-one`と`aaaa-common-two`という二つのフォルダは末尾三文字を除いてすべて同じなので、末尾を切り落とすことで何も伝えない部分を残す：それぞれ`…one`と`…two`になり、これは短い *上に* 見分けもつく。一致が末尾にある場合——`alpha-draft`と`beta-draft`が並ぶ場合——消えるのは末尾だ。両端に一致がある場合、残るのは真ん中になる。近くに似た名前がない場合、真ん中が失われる。名前は自分が何であるかで始まり、どれであるかで終わるからだ——ファイルの場合、それは拡張子だ：`annual…2026.md`。

短い共通部分は勘定に入らない。`parallel structures`はたまたま隣の`Schemes`と同じ二文字で終わるが、それはどちらかをまるごと残す理由にはならない——先頭三文字だけですでに見分けがつく。

二行目に折り返されることはない。最も短い正直な名前でも収まらない場合、行は **横にスクロールする**。ファイルがある末尾に寄せて止まる——その時点で圧縮できるものはもう何もなく、これ以上切ることは短縮ではなく隠蔽になってしまう。ホイールは、ポインタが行の上にある限りどこでもスクロールでき、両端に到達できる：スクロール中、行は配置設定が何であれ、その始点に揃う。それは、はみ出した箱の中で中央揃えされたコンテンツは左右両方にこぼれ、その半分にはそもそもスクロールでたどり着けないからだ。

**短縮された名前を指すと、指している間だけ全体が戻ってくる**。左端までスクロールされ、戻ってきたもの全体が画面に収まる。**クリックするとそのまま留まる**：フィールドが開き、クリックしたフォルダ、その後に提示されるもの、そして入力したものが表示され、ポインタが離れた後もそれらを表示し続ける。行をスクロールしている間や、そこに入力している間は名前はそのままだ——行を読もうとしている身振りの下で何かが勝手に開くと、それ以降のものが足元から動いてしまう。

**先頭の要素には常にツールチップがあり、それは絶対パスだ**——`/home/you/Vaults/Notes`、あるいは行がどこから始まっていようとそこが示される。それは画面上の他の何によっても伝えられない唯一のものだ：名前は *どの* 保管庫かを伝えるが、それがどこにあるかは決して伝えない。何かを短縮する必要があったかどうかにかかわらず、これは常にそこにある。

**保管庫名を表示** をオフにしても名前は削除されるのではなく、幅がゼロに保たれているだけだ——だからアイコンを指すと、行が短縮せざるを得なかった名前を指したときとまったく同じように、名前が戻ってくる。

**拡張子を表示** は、行のファイル名に拡張子を戻す。オフのとき——これが既定——行は、保管庫内のほぼすべてのファイルに共通する`.md`なしで、Obsidianがタイトルとして表示するのと同じ形でノートを名付ける。オンにすると、ファイルシステムが名付けるのと同じ形になる。これは保管庫がノート以外のものも含む場合に望ましい。これはまた、余白が足りなくなったときに行が二番目に手放すもので、保管庫名のすぐ後に続く。
ツールチップは残りを教えてくれる：名前だけでなく、その下に行が示すものすべてを`…/name/folder/note.md`として示し、一度のホバーで「これは何か」と「その下に何があるか」の両方に答える。保管庫のアイコンも、名前がオフになっているか、詰められて消えてしまっているとき、同じ形で自分の保管庫を名乗る。

## 二つの警告色

| | いつ | 何を意味するか |
| --- | --- | --- |
| パスバーの **赤い** 縁取り | 行が保管庫の外を指している | Obsidianはそこにあるものをノートとして開けず、南京錠を開けるまでそこには何も書き込まれない。 |
| パスバーの **オレンジの** 縁取り | ファイルがObsidianにビューを持たないテキスト形式である | 注意喚起。Obsidianはそれをデスクトップの既定アプリに渡すところだが、代わりにこのプラグインが表示する。 |
| 開いたフィールドの **赤い** テキスト | そのパスにはまだ何もない | <kbd>Enter</kbd>はそれを開くのではなく作る。警告というより、次のキー入力が何をするかの説明だ——[パスを入力する](#パスを入力する)を参照。 |
| 名前変更トグルの代わりにある **赤い** 南京錠 | 行が保管庫の外を指していて、そこへの書き込みがまだロックされている | 縁取りと同じ赤で、理由も同じ：拒否を示している。押すとここへの書き込みが許可され、スロットがトグルに戻る——[保管庫の外に書き込む](#保管庫の外に書き込む)を参照。 |

**二つの縁取りは独立していて、両方同時に成り立つこともある**——外部の`.json`は保管庫の外にあり *かつ* Obsidianがエディタを持たない形式でもありうる。ビューアではこれらは別々の行として現れ、それぞれが自分の事実だけを述べる。パスバーでは、両方が当てはまる場合は赤が優先される。二つの縁取りがあっても雑音にしかならないからだ。赤い *テキスト* はまったく別の三つ目のものだ：それは行が何を指しているかではなく、入力中の内容についてのものなので、どちらの縁取りの中にも、あるいはどちらの中にも現れうる。

オレンジの階層は意図的に狭い。登録済みの形式（Markdown、canvas、画像、PDF、音声、動画）は適切に扱われ、何も表示されない。バイナリファイルにも何も表示されない——うっかり`.zip`を編集して台無しにすることはないからだ。残るのはまさにその危険な領域だ：**すべてのファイルの種類を表示** によって見えるようになった`.json`、`.css`、`.log`だ。一覧のほうは意図的に対象が広い：そこでは、ノートでないものはすべてオレンジになる——[一覧の行の色分け](#一覧の行の色分け)を参照。

## 名前変更／移動モード

ヘッダーの右端にある鉛筆ボタン——表示モードボタンの隣、Obsidian標準のボタンと同じサイズ——が名前変更／移動モードを切り替える。保管庫の外では、押すまで代わりに赤い南京錠が立っている。[保管庫の外に書き込む](#保管庫の外に書き込む)を参照。このときヘッダー行は、File Explorerでの名前変更とまったく同じように、アクセントカラーで縁取られる。同じクリックやキー操作が、Obsidianの`fileManager.renameFile`を通じて移動や名前変更を確定するので、ノートへのすべてのリンクが追従する。

名前変更のあいだ:

- 現在のファイル名がすべてのフォルダの一覧に固定表示されるので、ノートを名前を変えずに移動するのはワンクリックで済む。
- 移動先フォルダですでに使われている名前は **赤** で示される——その名前を持つフォルダ、その名前を持つファイル——選ぶ前に衝突がわかるようになっている。それでも選ぶことはできる：詳細は下記を参照。
- 入力はObsidian自身の名前変更ルールに照らしてその場で検証される——同じ使用可能文字、同じメッセージ、ファイルツリーで名前を変更するときに出るのと同じ赤いツールチップだ。だから許されない名前は入力しているそばから示され、確定できない。
- ヘッダーバーの外をクリックするか、ヘッダーがフォーカスを失うと、名前変更モードは終了する。

### 使われている名前

すでに存在する名前へ移動または名前変更しようとすると、**拒否ではなく確認が入る。** 編集可能な二つのパスを示すダイアログが開く：あなたのファイルの行き先と、行く手を阻んでいるファイルの行き先だ——後者はまだ使われている間は赤で示される。どちらのパスも、パスバーがパスを描くのと同じ方法で描かれる。異なる部分に色がつき、最後に短縮されるので、長いパスでも何が変わるのかがわかる。

両方のフィールドに一覧がある。二つ目のフィールドには、よくある解決策が並ぶ：

- **場所を入れ替える** ——それはあなたのファイルの元のフォルダに、自分自身の名前のまま移る。
- **名前を入れ替える** ——それはそこに留まり、あなたのファイルの元の名前を引き継ぐ。
- **両方を入れ替える** ——それはあなたのファイルの元のパスを引き継ぐ。
- 自分自身の名前の横に付く`-1`、`-bak`、`-old`。
- 両ファイルがもともと持っていた二つの名前。

一つ目の一覧には、あなたのファイルが行くはずだった場所、**そこに留まる**、移動先フォルダでの自分自身の名前、そしてその横に付く`-1`、`-bak`、`-old`が並ぶ。パスがすでに使われている解決策はグレー表示になり、選べない。どれかを選んでも **フィールドが埋まるだけ** で——まだ編集できる——**適用** を押すと両方が、リンクも含めて移動する。**キャンセル** は何も移動しない。一覧から使われている名前を選ぶ場合も同じ確認が入り、すでにその名前を持つフォルダにノートをドロップした場合も同様だ。

## 二つの名前変更を一つのキーで

名前変更コマンド（デフォルトでは<kbd>F2</kbd>、割り当て変更後ならそのキー）は、Obsidianのインライトタイトルの名前変更と、このプラグインのヘッダーパスバーとの間を**交互に**切り替えます。Obsidianのインラインタイトルをオフにしている場合、ヘッダーパスバーが唯一の対象になるので、このキーが何もしないことはありません。

パスバーでは**拡張子を除いた名前**が開きます — 名前変更でほぼ常に編集するのはそこであり、名前をクリックしたときに選択されるのも同じ部分です。もう一度押すと、そこで<kbd>Tab</kbd>が行うことと同じことをします：名前の上では次の段へ進みます — 拡張子付きの名前、保管庫フォルダからのパス、システムのルートからのパス。何か入力してある場合は、<kbd>Tab</kbd>と同様にそれを補完します。

**この一巡は見出しで閉じます。**五回押すと一巡します — インラインタイトル、名前、拡張子付きの名前、保管庫からのパス、システムのルートからのパス — そして六回目でまたインラインタイトルに戻ります。この押下だけが<kbd>Tab</kbd>と異なる点で、<kbd>Tab</kbd>のほうはパスの先頭に戻ります — そして七回目は<kbd>Tab</kbd>が戻る先と同じところに行きます：保管庫のルートで、フィールドにはパス全体が入り、最初のフォルダが選択された状態です。つまり<kbd>Tab</kbd>が到達するすべての段に、このキーも到達します。

**パスバーにフォーカス**コマンドはフィールド内で同じことを行います — <kbd>Tab</kbd>が行うことと同じことを — そして<kbd>Tab</kbd>が一巡する場面では、代わりにカーソルをノートへ返します。その次の押下が一巡です：保管庫のルート、最初のフォルダが選択された状態です。

**すでに開いているフィールドでは**、このキーはその場のまま名前変更に切り替えます — テキストもキャレットも選択範囲も保ったまま — そして**パスバーにフォーカス**は同じやり方でその名前変更を解除します。押下の間に**それ以外の何か**を押したりクリックしたりすると、どちらの一巡も最初からやり直しになるので、編集していた後に押しても、前回の途中の段に着地することはありません。

保管庫の外でもこのキーは働きます — そこにはインラインタイトルがないので、最初の押下でそのままパスバーに行きます。

これはキーを奪うのではなく `workspace:edit-file-title` コマンドを包むことで実現しているので、ホットキーの割り当て変更も、パレットからのコマンド実行も、変わらず働きます。

## 一覧の行の色分け

| 色 | 意味 |
| --- | --- |
| **紫** | ノート（`.md`、`.markdown`）— 混在した内容のフォルダの中から、Obsidianがノートとして開くものを選び出したもの |
| **オレンジ** | ノートではないもの — PDFから`.txt`まで、Obsidianがノートとして開かないもの全部、それに伴う`:page`の項目も含む。混在した内容のフォルダはその中のノートを読み取るためのもので、それ以外すべてを一色にすることで、一部だけに注意色を付けるより速く伝わります。[警告色](#二つの警告色)を参照 |
| **淡色** | 保管庫の外なので、保管庫自体の扱いは適用されない |
| **青、太字** | すでにいる場所：このバー自身のノート、そしてパスバーが立っているフォルダ。名前変更／移動モードでは、*この名前を保つ*という項目がノートの位置に代わりに入りますが、どちらにしても同じノートです |
| **赤** | 名前変更／移動モードのみ：その名前は使用中です。それでも選択可能で、選ぶと邪魔なファイルをどうするか尋ねられます。[使用中の名前](#使われている名前)を参照 |

**フォルダは太字**なので、フォルダ自身のノートは自分のフォルダと区別するために特別な色を必要としません：他のノートと同じ紫のままです。**行の端に沿った縦線**は、入力した文字で始まる名前を示します — さらに先まで一致する場合は青、候補が分岐する側では緑になります。[パスを入力する](#パスを入力する)を参照。

フィールドも、それが指すものに対して同じ色を取ります — [パスを入力する](#パスを入力する)を参照。

## 表示のルール

- 未対応の拡張子を持つファイルは、Obsidianの**すべてのファイルタイプを検出**設定がオンのときだけ一覧に表示されます — **保管庫の内側では**。外側ではこの設定は適用されません：この設定は保管庫が何を索引化するかを決めるものであり、外にあるものは保管庫に含まれないので、ノートの隣にある`.txt`はどちらの設定でも一覧に出ます。
- 一覧は最大1,000件を表示し、これはObsidian自身の上限の十倍です。フォルダにそれ以上ある場合、最後の行に何件省略されたかが表示されます。入力を続けて絞り込んでください。
- ドットファイルとドットフォルダは、このプラグインの**ドットファイルを表示**設定がオンのときだけ表示されます。
- **上書き保護は表示に関わらず同じように働きます** — 非表示のファイルでも、上書きは防止されます。

## チートシート

**引用符で囲まれた**パスは自動で外されます。Windowsの*パスとしてコピー*は`"C:\Users\you\note.md"`のように引用符付きで渡し、シェルもスペースを含むパスに対して同じことをします。貼り付けても入力しても、どちらでも動作します。対象になるのはダブルクォートのみで、しかも全体を挟む対のときだけです — これは実際の名前には現れませんが、アポストロフィは十分に現れ得ます。

| したいこと | すること |
| --- | --- |
| フォルダを開く（そのノート、または表示） | そのフォルダの**後ろの**区切り文字をクリック |
| フォルダにまだないフォルダノートを与える | 同じ区切り文字を**ダブルクリック**（フォルダノート用プラグインが必要） |
| フォルダを同階層の別のものに差し替える | そのフォルダの名前をクリックし、入力または選択 |
| ノートの名前変更、または対象の切り替え | ノートの名前をクリック — 拡張子も含めて |
| フォルダの内容を見る | そのフォルダの名前をクリック。一覧はその親フォルダを表示するので、見たいフォルダの**下の**フォルダをクリックしてください |
| フォルダとその下すべてを打ち直す | そのフォルダの名前を**ダブルクリック**して入力 |
| フォルダから下のパスを編集する | そのフォルダの名前をクリックし、<kbd>→</kbd>で選択を外す |
| パスを入力してファイルへ移動 | ファイル名または空白部分をクリックして入力、<kbd>Enter</kbd> |
| 代わりに新規タブでファイルを開く | 選ぶときに<kbd>Ctrl</kbd>、または<kbd>Ctrl</kbd>+<kbd>Enter</kbd> |
| ノートを移動せずにどこかへコピーする | 鉛筆アイコン、その後対象を選ぶか確定するときに<kbd>Ctrl</kbd> |
| 存在しないパスにノートを作成する | パスを入力する — 一覧の何とも一致しなくなると、フィールドが**赤く**なります — その後<kbd>Enter</kbd>。保管庫の内側ではすぐに作成され、外側では先に確認を求められます |
| 入力したパスが既に存在するか確かめる | 色を見てください：それが指す行の色を取り、赤なら<kbd>Enter</kbd>で作成されることを意味します |
| 入力しながら一段下る | `/`を入力 |
| 入力しながら一段上る | 空の入力欄で<kbd>Backspace</kbd> |
| フィールドの前にあるフォルダをフィールドに取り込む | 先頭で<kbd>←</kbd>で一つ；<kbd>Shift</kbd>+<kbd>Home</kbd>、または一覧が閉じている状態での<kbd>Home</kbd>で全部 |
| 開いているノートを移動、または名前変更する | 鉛筆をクリックし、上記のように参照または入力 |
| 使用中の名前に移動する | それでも確定する：邪魔なファイルと位置を入れ替える、名前を入れ替える、両方入れ替える、または邪魔なファイルに別の名前を与える、いずれかを選べるダイアログが出ます |
| 名前を変えずに移動する | 鉛筆 → 対象フォルダの中をクリック → 固定されている現在のファイル名を選ぶ |
| その場で名前変更する | <kbd>F2</kbd>を二回（最初はインラインタイトルへ、二回目でヘッダーへ） |
| 別の保管庫、ホーム、またはドライブへ移動する | 保管庫名をクリック |
| 保管庫の外からファイルを開く | 保管庫名 → 場所を選択 → 参照 → ファイルを選ぶ（*テキストとして編集*するまでは読み取り専用） |
| 入力中の名前を補完する | <kbd>Tab</kbd>、または提示されているものについては<kbd>End</kbd>；<kbd>→</kbd>はその一文字分を取り込む |
| 一つに絞られたら、その中に入る | もう一度<kbd>Tab</kbd> |
| 一段戻る、またはフォルダを出る | <kbd>Shift</kbd>+<kbd>Tab</kbd> |
| パス全体、またはシステムパスを取得する | 末尾を過ぎて<kbd>Tab</kbd>、または四回クリック |
| 名前、パス、またはシステムパスをコピーする | 二回右クリック；システムパスの場合は空白部分を三回 |
| この保管庫について保管庫マネージャーが提供するものにアクセスする | 行の先頭のアイコンを右クリック |
| 保管庫のIDをコピーする | 行の先頭のアイコンを右クリック |
| 参照していた別の保管庫を開く | 行の先頭にあるその名前を右クリック |
| 行でファイルの拡張子を見る | 設定で**拡張子を表示**をオンにする |
| フォルダの要素を新規タブで開く | <kbd>Ctrl</kbd>を押しながらクリックか中クリック、またはタブバーへドラッグ |
| キーボードからパスバーに到達する | Hotkeysで*パスバーにフォーカス*を割り当てる |
| ウェブアドレスや`obsidian://`リンクを開く | バーに入力して<kbd>Enter</kbd>を押す |
| 何かをキャンセルする | <kbd>Esc</kbd>、またはヘッダーバーの外をクリック |
| 確定する前に候補を試してみる | 一覧を矢印キーかマウスホバーで巡る；先頭を過ぎて<kbd>↑</kbd>を押すと入力していたテキストが戻る |
| ノートを上位のフォルダへ移動する | 行の中のそのフォルダへドラッグ |
| テキストの断片を新規ノートとして保存する | テキストをフォルダへドラッグし、名前を入力、<kbd>Enter</kbd> |
| テキストの断片を今読んでいるノートに追加する | ノートの名前へドラッグし、確認する |
| 短縮されたフォルダ名を全部見る | ホバーする、またはペインを広げる |
| 保管庫自体がどこにあるか確かめる | 行の先頭のアイコンにホバー |
| ノートを保管庫の外に出す | 鉛筆 → 外を参照 → ダイアログで確認（リンクは切れます） |
| 保管庫の外への書き込みを許可する | ヘッダーの**赤い錠アイコン**をクリック；名前変更トグルがその場所に代わって現れます |
| もう一度ロックする | 錠アイコンが戻るまでトグルをクリック — 一回で入り、一回で出る |
| 保管庫の外のファイルを削除する | 錠を開けてから、そのファイルを右クリック：*削除*はシステムのごみ箱へ移動します |

## 設定

| 設定 | 選択肢 | デフォルト | 内容 |
| --- | --- | --- | --- |
| **Language** | Obsidianのデフォルト、または46言語のいずれか | Obsidianのデフォルト | このプラグイン自身のテキストがどの言語で表示されるか。*Obsidianのデフォルト*は外観設定で設定した言語に従い、ほとんどの人が望むのはこれです。この行自体 — その名前、説明、そして*Obsidianのデフォルト*という表記 — は、どれを選んでも英語のままです。読めない言語から戻る道になるからです。ギリシャ語とサンスクリット語はここで翻訳されていますが、Obsidian自身のリストには存在しないので、この設定が唯一それらに到達する方法です。 |
| **Alignment** | 左／中央／右 | 左 | パス表示がヘッダー行のどこに位置するか。*中央*はObsidianの従来の見た目と一致します。 |
| **Delimiter** | 任意の文字 | `/` | 要素の間に描かれる区切り記号。ワンクリックで選べる六つのプリセット（`/ > ▸ › \ •`）がテキストフィールドの前にあります。 |
| **Show vault name** | オン／オフ | オン | 保管庫自体が最初のパス表示要素になるかどうか。オフにすると、その要素は消えるのではなく🏠アイコンになるので、パスはそれでもクリックできる何かから始まります。 |
| **Folder name opens the dropdown** | オン／オフ | オン | フォルダ名とその後ろの区切り文字が行うことを入れ替えます — [上の表](#パス表示)を参照。[Folder notes](obsidian://show-plugin?id=folder-notes)があると、区切り文字がフォルダノートを開きます。名前変更／移動モードでは決して適用されません。 |
| **Show dot files** | オン／オフ | オフ | ドットファイルとドットフォルダを一覧に表示するかどうか。上書き保護はどちらでも適用されます。 |
| **Show all file types** | — | — | このプラグインの設定ではなくObsidianのものですが、同じ疑問に答えるのでここで触れます：あなたの保管庫は指示されたファイルタイプしか索引化せず、索引化されたものしか一覧に表示できません。Obsidianの設定でこれを探し、オンにするとすべてのファイルが見えるようになります。行の横のボタンは、設定自身の検索でクリックしたときと同じように、その設定までスクロールして点滅させながらそのページを開きます。保管庫の外ではこの設定は適用されません。そこにあるものはそもそも索引化されないからです。 |
| **Show file extensions** | オン／オフ | オフ | 行に表示されるファイル名に拡張子を含めるかどうか。オフでは省かれます — Obsidianがノートのタイトルで拡張子を省くのと同じです。オンでは、行はファイルシステムと同じ形でファイルの名前を示します。どちらにしても、行の幅が足りなくなったとき、拡張子は保管庫名の直後、二番目に切り落とされます。 |
| **Access external files** | オン／オフ | **オフ** | 保管庫名が場所の一覧を開くかどうか。オフでは、このプラグインは保管庫の外を一切見ません。 |
| **Hotkeys** | ボタン | — | このプラグインで絞り込まれたObsidianの*Hotkeys*を開きます。そこで*パスバーにフォーカス*にキーを割り当てられます。 |

## アイコンを差し替える

Lureは三つのアイコンを描画します：保管庫ルートのアイコン（**Show vault name**がオフのとき）、名前変更／移動トグル、そして保管庫の外への書き込みがロックされている間その場所に立つ錠アイコンです。どれもテーマやCSSスニペットから差し替えられます — 差し替え用の字形を指定し、一つのルールで内蔵アイコンを隠します：

```css
.lure-vault-icon {
	--lure-icon-glyph: "🏠";
	--lure-icon-svg: none;
}

.lure-rename-btn {
	--lure-icon-glyph: "✎";
	--lure-icon-svg: none;
}

/* Only ever shown shut: opening it hands the slot to the rename toggle. */
.lure-unlock-btn {
	--lure-icon-glyph: "🔒";
	--lure-icon-svg: none;
}
```

`--lure-icon-glyph` は CSS の `content` に使えるものなら何でも取るので、テキストや絵文字だけでなく `url(...)` で画像も指定できます。Lucide のアイコンを残して自分の字をその隣に描きたいときは、`--lure-icon-svg` はそのままにしてください。
