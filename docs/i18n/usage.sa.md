## शीर्षपट्टिकायां मार्गः

कोशस्य अन्तः टिप्पण्याः पूर्णमार्गः दृश्यशीर्षपट्टिकायां स्थितं नग्नं सञ्चिकानाम प्रतिस्थापयति — पिधानपङ्क्तेः अधस्तात् या पङ्क्तिः, यस्यां पश्चात्-अग्रे-गमनस्य कुञ्जिके अपि स्तः।

अस्यां पङ्क्तौ द्वे वस्तुनी नोदनीये स्तः, **पुटनाम सूचीं उद्घाटयति** इति च निर्णयति कतरत् किं करोति:

| | पुटनाम | तदनन्तरः विभाजकः |
| --- | --- | --- |
| **सक्रियम्** (पूर्वनिर्धारितम्) | तत् पुटं सम्पादनार्थं वृणोति | पुटम् उद्घाटयति |
| **निष्क्रियम्** | पुटम् उद्घाटयति | तस्मिन् पुटे अवतरति |

„पुटम् उद्घाटयति“ इत्यस्य अर्थः — शुद्धे Obsidian इत्यत्र तस्मिन् खण्डे नोदनं यत् करोति, तदेव। तत्र श्रवणशीलं किमपि प्लगिन् न चेत्, पुटं पार्श्वपट्टिकायां File explorer इत्यत्र दर्श्यते — उद्दीपितं, अन्तर्गतं दर्शयितुं विस्तारितं च।

[Folder notes](obsidian://show-plugin?id=folder-notes) संस्थापिते सति तदेव नोदनं तस्य पुटस्य टिप्पणीम् उद्घाटयति। शीर्षपट्टिकायाः मार्गं गृह्णाति इति ज्ञातं तदेकमेव पुटटिप्पणी-प्लगिन्; [Folder Note](obsidian://show-plugin?id=folder-note-plugin) [create folder notes with dropdown](obsidian://show-plugin?id=create-folder-notes-with-dropdown) च पुटटिप्पणीः प्रबन्धयतः किन्तु मार्गे नोदनं न शृणुतः, अतः ताभ्यां सह विभाजकः यथापूर्वं पुटं दर्शयति। [संगतिं](../compatibility.md#verified-against) पश्यतु।

विभाजकस्य अधः रेखा **तदैव भवति यदा तस्मात् पूर्वस्य पुटस्य वस्तुतः पुटटिप्पणी अस्ति**, अतः सा रेखा उद्घाटनीयं किञ्चित् अस्ति इति प्रतिज्ञा। तथापि प्रत्येकः विभाजकः नोदनीयः एव तिष्ठति — रेखारहितः स्वकीयं पुटं पार्श्वपट्टिकायां दर्शयति विस्तारयति च, यत् सूचकः अद्यापि सूचयति। रेखा तस्मिन्नेव क्षणे पुटनाम्नः अपगच्छति: विनिमये सक्रिये सति नाम सूचीम् उद्घाटयति, अतः तत् टिप्पण्याः सम्बन्धः इति चिह्नितुम् असत्यं भवेत्।

**पुनर्नामकरण/स्थानान्तरण-अवस्था उभयम् अतिक्रामति**, संयोजनं यत्किमपि वदतु: स्थानान्तरणं यावत् अपूर्णं तावत् पङ्क्तौ किमपि पुटं न उद्घाटयति, यतः उद्घाटनेन स्थानान्तरणं त्यक्तं भवेत्। पुटनामानि सम्पादनार्थं वृण्यन्ते, विभाजकाः च अवतरन्ति — उभयम् अपि गन्तव्यचयनस्य उपायः — उद्घाटनं स्थगितम् इति दर्शयितुं रेखा च अन्तर्धीयते।

**कोशमूलम्** एकमेव खण्डं यत् मार्गखण्डं नास्ति। सहजान् गणयितुं तस्य जनकः नास्ति, अतः तत् प्रत्युत [स्थानसूचीम्](#कोशात्-बहिः-अवलोकनम्) उद्घाटयति — भवतः अन्ये कोशाः, निजपुटम्, सञ्चिकाव्यवस्थायाः मूलम्, संयोजिताः चालकाः च।

## खण्डे नोदनम्: तस्य सहजेन विनिमयः

पुटनाम्नि नोदनेन पाठक्षेत्रे **तस्यैव पुटस्य नाम** वृतं भवति, **एकस्तरम् उपरि** स्थितस्य पुटस्य — तस्य जनकस्य — सूची च उद्घाट्यते। लेखनेन प्रविष्टिचयनेन वा इदं पुटं सहजेन विनिमीयते, तस्य अधःस्थं सर्वं च अस्पृष्टं तिष्ठति, अतः `Projects/2026/Kickoff.md` → `2026` इत्यत्र नोदनम् → `2025` चयनम् इत्यनेन भवते `Projects/2025/Kickoff.md` लभ्यते।

**टिप्पण्याः नाम्नि** नोदनं तस्याः स्वकीयस्य पुटस्य प्रति तथैव कार्यं करोति, सञ्चिकानाम च **विस्तारसहितम्** वृणोति — टिप्पण्याः पुनर्नामकरणं वा अन्यत्र निर्देशनं वा प्रायः तस्यापि परिवर्तनं सूचयति।

पुटे नोदनेन पूर्वमेव एकं खण्डं वृतम्, अतः **अपरम् एकं नोदनम्** चयनं समग्रपङ्क्तौ विस्तारयति — तत् पुटं *तस्य* अधःस्थं सर्वं च — ततः लेखनेन मार्गस्य शेषः एकवारमेव प्रतिस्थाप्यते। सञ्चरणे पुनर्नामकरण/स्थानान्तरण-अवस्थायां च समानम् एव कार्यं करोति।

एतत् केवलं तस्य नोदनस्य अनुवृत्तिरूपेण एव प्रवर्तते यत् क्षेत्रम् उद्घाटितवत्। यदा एकवारं क्षेत्रम् उपयुक्तं, तदा तत् अन्यपाठक्षेत्रवत् एव आचरति: नोदनं सूचकं स्थापयति, द्विनोदनं पदं गृह्णाति, त्रिनोदनं पङ्क्तिं गृह्णाति।

यथाकथञ्चित् मार्गस्य शेषः क्षेत्रस्य परितः दृश्यः तिष्ठति — तस्मात् पूर्वं खण्डकरूपेण, तस्मात् परं च अवृतपाठरूपेण — अतः पूर्णमार्गः शीर्षात् कदापि न अन्तर्धीयते। चयनं प्रतिस्थापयितुं लिखतु, अथवा तत् रक्षित्वा ततः सम्पादयितुं <kbd>End</kbd> / <kbd>→</kbd> नुदतु। पूर्वं यत्किमपि पूरितम् अस्तु, सूची समग्रं पुटं दर्शयति; गालनं तु तदैव आरभते यदा वस्तुतः लिखति।

## विभाजकेन अवतरणम्

विभाजके नोदनं (**पुटनाम सूचीं उद्घाटयति** इत्यस्मिन् निष्क्रिये सति) तस्मात् पूर्वस्मिन् पुटे अवतरति: सूची *तस्यैव* पुटस्य अन्तर्गतं दर्शयति, मार्गस्य शेषः च क्षेत्रे वृतः सन् उद्घाट्यते। पुटस्य चयनं तत् मार्गपदचिह्ने योजयति, तत्क्षणमेव च अग्रिमां सूचीम् उद्घाटयति, अतः शीर्षपङ्क्तिं न त्यक्त्वा वृक्षे अधः नोदनैः गन्तुं शक्यते।

## सूचीप्रविष्टयः वास्तविकाः सञ्चिकाप्रबन्धकपङ्क्तयः सन्ति

सूच्यां प्रत्येका सञ्चिका पुटं च File explorer इत्यत्र स्वकीयपङ्क्तिवत् आचरति:

- **दक्षिणनोदनेन** तदेव सन्दर्भसूचिकं लभ्यते — पुटे *New note* / *New folder*, सञ्चिकायां *Open in new tab* / *Rename…* / *Delete* — अन्यैः प्लगिन्-द्वारा सञ्चिकासूचिकेषु योजिताः प्रविष्टयः अपि सहिताः।
- यत्र कुत्रापि Obsidian सञ्चिकां स्वीकरोति तत्र प्रविष्टिम् **आकर्षयतु**: सम्बन्धं निवेशयितुं सम्पादके अन्तः, स्थानान्तरयितुं File explorer इत्यत्र पुटस्य उपरि, उद्घाटयितुं पिधानपट्टिकायाः उपरि।

सूचिकापदानि Obsidian इत्यस्य स्वकीयानुवादेभ्यः आगच्छन्ति, अतः प्रत्येकस्यां भाषायां तानि अनुप्रयोगस्य शेषभागेन सह मिलन्ति।

## मार्गस्य लेखनम्

- खण्डकेभ्यः पूर्वं परं वा स्थितं **रिक्तस्थानं** नुदन् पूर्णमार्गेण पूरितं समग्रतया वृतं च पाठक्षेत्रम् उद्घाटयति — तस्य उपरि लिखतु, अथवा तत्रैव सम्पादयतु। (सञ्चिकानाम्नि एव नोदनेन केवलं सञ्चिकानाम वृतं भवति; उपरि पश्यतु।)
- खण्डकपदचिह्ने दृश्यमाने सति लेखनम् अन्तिमं खण्डं वर्तमानपुटे सीमितेन जीवत्-स्वयंपूरणेन युक्तं लघुक्षेत्रं करोति।
- `/` वर्तमानखण्डं दृढीकरोति, तस्मिन् च अवतरति।
- रिक्तक्षेत्रे <kbd>Backspace</kbd> एकपदं पश्चात् जनकपुटं प्रति नयति, तस्य नाम च अन्ते सूचकेन सह पुनः उद्घाटयति।
- <kbd>Enter</kbd> दृढीकरोति; <kbd>Esc</kbd> अन्यत्र नोदनं वा निरस्यति सञ्चिकायाः वास्तविकं मार्गं च प्रत्यानयति।

क्षेत्रम् अलङ्काररहितम् — न मञ्जूषा, न सीमा — अतः तत् मार्गपाठ इव एव पठ्यते, लिखतः सतः स्वयमेव च वर्धते।

## सञ्चरणं कदापि उद्घाटितां सञ्चिकां न स्पृशति

पूर्वनिर्धारितायाम् (सञ्चरण-) अवस्थायाम् उद्घाटितायाः टिप्पण्याः नाम **कदापि** न परिवर्त्यते, सा च न स्थानान्तर्यते।

- विद्यमानया सञ्चिकया सह मिलन् मार्गः तां सञ्चिकाम् उद्घाटयति।
- अद्यापि अविद्यमानः मार्गः *„नवीना सञ्चिका रच्यताम्?“* इति पृच्छति। दृढीकरणेन अनुपस्थितानि जनकपुटानि सञ्चिका च रच्यन्ते; निरसनेन किमपि न भवति।

## <kbd>Ctrl</kbd> — नवीनं पिधानं, स्थानान्तरणस्य स्थाने प्रतिलिपिः च

सूच्याः सञ्चिकां वृण्वन् सन्, अथवा मार्गे <kbd>Enter</kbd> नुदन् सन्, <kbd>Ctrl</kbd> (macOS इत्यत्र <kbd>Cmd</kbd>) धारयन् फलम् अस्य पिधानस्य स्थाने **नवीने पिधाने** प्रेषयति:

| | सामान्यम् | <kbd>Ctrl</kbd> सहितम् |
| --- | --- | --- |
| विद्यमानायाः सञ्चिकायाः चयनं लेखनं वा | अत्रैव उद्घाट्यते | नवीने पिधाने उद्घाट्यते |
| अविद्यमानस्य मार्गस्य लेखनम् | पृच्छति, ततः अत्र उद्घाटयति | पृच्छति, ततः नवीने पिधाने उद्घाटयति |
| पुनर्नामकरण/स्थानान्तरण-अवस्थायां मार्गस्य दृढीकरणम् | टिप्पणीं तत्र **स्थानान्तरयति** | तत्र तस्याः **प्रतिलिपिं** करोति, प्रतिलिपिं च नवीने पिधाने उद्घाटयति |

परिवर्तककुञ्जी Obsidian इत्यस्य स्वकीयनियमेन पठ्यते, अतः सा सम्बन्धे वा File explorer इत्यस्य पङ्क्तौ वा यथा आचरति तथैव आचरति — मध्यनोदनम् अपि „नवीनं पिधानम्“ इति सूचयति, <kbd>Ctrl</kbd>+<kbd>Alt</kbd> विभाजनं सूचयति, <kbd>Ctrl</kbd>+<kbd>Alt</kbd>+<kbd>Shift</kbd> च नवीनं गवाक्षम्।

प्रतिलिपिः स्थानान्तरणम् इव एव अधिलेखनं निराकरोति — टिप्पण्याः स्वकीयमार्गे अपि, यत्र प्रतिलिपिकरणाय युक्तं किमपि नास्ति।

## कोशात् बहिः अवलोकनम्

**एतत् पूर्वनिर्धारितरूपेण निष्क्रियम्।** प्रथमं संयोजनेषु **बाह्यसञ्चिकासु प्रवेशः** इति सक्रियं करोतु — कोशात् बहिः पठनं लेखनं च तदेकमेव यत् इदं प्लगिन् करोति परं स्वयं Obsidian न करोति, अतः तस्मात् बहिर्गमनस्य स्थाने तस्मिन् प्रवेशः क्रियते। निष्क्रिये सति कोशनाम केवलं भवतः कोशं File explorer इत्यत्र दर्शयति, अत्र च किमपि तस्मात् परं न पश्यति।

**कोशनाम्नि** (अथवा *कोशनाम प्रदर्श्यताम्* इत्यस्मिन् निष्क्रिये सति 🏠 इति चिह्ने) नोदनम् अन्तर्गतस्य स्थाने स्थानानां सूचीम् उद्घाटयति:

- **भवतः अन्ये कोशाः**, Obsidian इत्यस्य स्वकीयात् पञ्जिकातः पठिताः, नवीनतमम् उद्घाटितः प्रथमम्, प्रत्येकः Obsidian इत्यस्य स्वकीयस्य कोशचिह्नस्य अधः — यत् अनुप्रयोगः स्वयं कोशादेशार्थं प्रयुङ्क्ते। यः कोशः पूर्वमेव उद्घाटितः अस्ति, सः गृहचिह्नं लभते: पङ्क्तिः पूर्वनिर्धारितरूपेण यस्मात् आरभते तत् स्थानम्, न तु गन्तव्यम्।
- **निजपुटम्**, भवतः स्वकीयस्य खातस्य नाम्नः अधः, `~` इत्यनेन चिह्नितम्। Lucide इत्यत्र तिर्यक्चिह्नं नास्ति, अतः एतत् प्लगिन् स्वयमेव Lucide इत्यस्य स्वकीये २४×२४ जाले तस्यैव रेखास्थौल्येन लिखति — सङ्ग्रहे यत् चिह्नं न्यूनं तत्, न तु चिह्नानां मध्ये उपविष्टः पाठवर्णः।
- **सञ्चिकाव्यवस्थायाः मूलम्**, `root` इति नामाङ्कितम् — अननूदितम्, यतः प्रत्येकस्यां व्यवस्थायां तस्य नाम तदेव — न तु `/`, यत् अनुगामिनः विभाजकस्य पार्श्वे रिक्तपदम् इव पठ्येत।
- **संयोजिताः चालकाः**, यत्र निर्धारणं सुलभं तत्र प्रकारानुसारं चिह्नैः सह: जालसाझेदारीणि, प्रकाशिकचक्राणि, नम्यचक्राणि निष्कासनीयमाध्यमानि च स्वकीयानि लभन्ते; अन्यत् सर्वं सामान्यचालकं लभते। Windows इत्यत्र चालकाः सामान्यचिह्नेन सह `C:` इति दृश्यन्ते — आयतननामानि सूक्ष्मप्रकाराः च WMI अपेक्षन्ते, यत् बुद्ध्या न कृतम्।

अन्यस्य कोशस्य चयनं **Obsidian तत्र न परिवर्तयति।** यत्किमपि उद्घाटितम् अस्ति तत् उद्घाटितमेव तिष्ठति; मार्गः केवलं तत्र अवलोकनम् आरभते। पार्श्वपट्टिकायाः कोशपरिवर्तकाय समर्पणस्य स्थाने मार्गपट्टिकायां तस्य स्थापनस्य सम्पूर्णः आशयः एषः एव।

### यावत् भवान् बहिः अस्ति

मार्गः **भवता वृतात् स्थानात् आरभते**, न तु यन्त्रस्य निर्देशिकाविन्यासात् — `Archive` वृणोतु, पङ्क्तिः च `Archive / notes / …` इति पठ्यते, न तु `/home/भवान्/Vaults/Archive/notes/…` इति। अग्रिमं खण्डं यत् अस्ति तस्य चिह्नं वहति (कोशः, निजपुटम्, चालकः), <kbd>Backspace</kbd> च सञ्चिकाव्यवस्थायाः शेषभागे उपरि न गत्वा तत्रैव तिष्ठति। *कोशनाम प्रदर्श्यताम्* इत्यस्मिन् निष्क्रिये सति तत् खण्डं केवलं चिह्नमेव — इदं संयोजनं पङ्क्तेः आरम्भखण्डं प्रति निर्दिशति, तत् यं कमपि कोशं नामयतु, न केवलं भवतः स्वकीयम्।

मार्गपट्टिका यावत् भवतः कोशात् बहिः निर्दिशति तावत् **दोषवर्णेन परिवृता** भवति — तदेव वलयं यत् पुनर्नामकरणावस्था लिखति। तत् क्षणं न किन्तु स्थायिनीं स्थितिं सूचयति: यावत् तत् वर्तते तावत् पङ्क्तिः यत् दर्शयति तस्मिन् Obsidian इत्यस्य स्वकीयेषु प्रबन्धेषु किमपि न प्रवर्तते, यावत् च भवान् अन्यथा न वदति तावत् लेखनं निरुद्धं तिष्ठति।

अन्यथा अवलोकनम् अन्तः इव एव कार्यं करोति: खण्डकाः, विभाजकाः, लेखनम्, स्वयंपूरणम्, एकपदं बहिर्गन्तुं <kbd>Backspace</kbd>। तान्येव दृश्यतानियमानि अपि प्रवर्तन्ते, अतः असमर्थितविस्ताराः अद्यापि Obsidian इत्यस्य *Show all file types* अपेक्षन्ते, बिन्दुना आरभमाणाः सञ्चिकाः च अद्यापि अस्य प्लगिन् इत्यस्य संयोजनम् अपेक्षन्ते।

सूचीप्रविष्टिषु **दक्षिणनोदनम् आकर्षणं च** तत्र बहिः न कार्यं कुरुतः — तानि File explorer इत्यस्य स्वकीयानि प्रबन्धकानि, तेभ्यश्च कोशेन ज्ञाता सञ्चिका अपेक्षिता।

### कोशात् बहिः लेखनम्

यत्किमपि लिखति तत् सर्वं **पूर्वनिर्धारितरूपेण निरुद्धम्**। यावत् पङ्क्तिः भवतः कोशात् बहिः निर्दिशति तावत् शीर्षे पुनर्नामकरणकुञ्ज्याः पार्श्वे **तालकः** प्रादुर्भवति; तस्य नोदनेन तालकः उद्घाट्यते सः च रक्तः भवति, पङ्क्तेः परितः स्थितेन वलयेन सह मेलनम्।

अनुज्ञा **स्थानाय दीयते, न तु क्षणाय**: एकस्मिन् स्थाने कार्यं कुर्वन् भवान् यत्किमपि कुर्यात् तत् सर्वं सा अतिजीवति — स्थानान्तरणस्य समापनम्, क्षेत्रात् बहिः नोदनम्, सञ्चिकायाः उद्घाटनम् — समाप्यते च यदा भवान् सूच्याः अन्यं कोशं चालकं मूलं वा वृणोति, यदा पङ्क्तिः कोशसञ्चिकां प्रति प्रत्यागच्छति, अथवा यदा भवान् पुनः तालकं नुदति। एवं च एकस्मिन् पुटे अन्तः क्रमशः स्थानान्तरणानि एकं नोदनम् अपेक्षन्ते, न तु प्रतिसञ्चिकम् एकैकम्।

तालके उद्घाटिते सति मार्गपट्टिका तत्र बहिः अन्तः इव एव आचरति:

| क्रिया | फलम् |
| --- | --- |
| अविद्यमानं नाम लिखतु, <kbd>Enter</kbd> | अन्तः इव एव „एषा रच्यताम्?“ इति प्रश्नः; अनुपस्थितानि जनकपुटानि अपि रच्यन्ते। विस्ताररहितं नाम `.md` भवति, अन्तः इव एव |
| पुनर्नामकरण/स्थानान्तरण-अवस्था, नवीनं नाम लिखतु | पङ्क्तिः यां सञ्चिकां दर्शयति तस्याः नाम परिवर्तयति। विस्ताररहितं नाम सञ्चिकायाः स्वकीयं विस्तारं रक्षति — अत्र बहिः एकं पुटं सर्वप्रकारकाः सञ्चिकाः धारयति, पुनर्नामकरणेन च `.png` तूष्णीं `.md` न भवितव्यम् |
| पुनर्नामकरण/स्थानान्तरण-अवस्था, अन्यत्र अवलोकयतु, **इदमेव नाम रक्ष्यताम्** इति वृणोतु | यत् नाम पूर्वमेव अस्ति तेनैव तां तत्र स्थानान्तरयति |
| उभयत्र <kbd>Ctrl</kbd> धारयतु | स्थानान्तरणस्य स्थाने प्रतिलिपिं करोति, प्रतिलिपिं च नवीने पिधाने उद्घाटयति |

निरुद्धे सति तानि सर्वाणि घटनस्य स्थाने किं तानि निरुणद्धि इति निवेदयन्ति। उभयस्यामपि स्थितौ किमपि कदापि न अधिलिख्यते: पूर्वमेव विद्यमानं लक्ष्यं निराक्रियते, तत् निराकरणं च स्पर्धायां पराजेतुं शक्नुवती परीक्षा नास्ति अपि तु सञ्चिकाव्यवस्थायाः स्वकीयम् (`COPYFILE_EXCL`, अनन्या रचना)। सञ्चिकाव्यवस्थयोः मध्ये स्थानान्तरणम् — USB इत्यस्मात्, जालसाझेदारीतः — प्रतिलिपिं-ततः-लोपम् इति उपायं प्रति अवतरति, मूलं च प्रतिलिपौ स्थिते सति एव अपनीयते।

**एकं यत् तालकः न उद्घाटयति: टिप्पण्याः भवतः कोशात् *बहिः* स्थानान्तरणम्।** `fileManager` तां सीमाम् अतिक्रम्य सञ्चिकाम् अनुगन्तुं न शक्नोति, अतः टिप्पणीं प्रति निर्दिशन् प्रत्येकः सम्बन्धः तूष्णीं भग्नः भवेत्, Obsidian च केवलं तस्याः अन्तर्धानं पश्येत्। <kbd>Ctrl</kbd> धारणं प्रत्युत तस्याः प्रतिलिपिं तत्र नयति, यस्मिन् सा समस्या नास्ति, सूचना च तदेव वदति। विपरीता दिशा — बाह्यसञ्चिकायाः कोशे *अन्तः* आनयनम् — साऽपि अद्यापि न संयोजिता।

### बाह्यसञ्चिकायाः उद्घाटनम्

Obsidian इत्यस्य सम्पादकः केवलं कोशस्य अन्तःस्थासु सञ्चिकासु एव कार्यं करोति, अतः बाह्यसञ्चिका सम्बन्धैः प्रतिसम्बन्धैः शेषैः च सह वास्तविकटिप्पणीरूपेण **उद्घाटयितुं न शक्यते** — एषा अनुप्रयोगस्य सीमा, न तु अस्य प्लगिन् इत्यस्य। एकां वृण्वन् प्रत्युत **पूर्वावलोकनम्** उद्घाटयति, यावत् भवान् अन्यथा न वदति तावत् केवलपठनार्थम्:

| प्रकारः | यथा दर्श्यते |
| --- | --- |
| `.md`, `.markdown` | अङ्कितं Markdown |
| चित्राणि, श्रव्यम्, दृश्यम्, PDF | स्वकीयः वादकः/दर्शकः |
| अन्या काचित् **पाठ**सञ्चिका (`.json`, `.css`, `.log`, `.txt`, …) | यथावत् सामान्यपाठः |
| दर्शकरहिताः द्विचक्रीयाः प्रारूपाः (`.zip`, `.exe`, …) | *बहिः उद्घाट्यताम्* इत्यस्मै समर्प्यन्ते |

दर्शकस्य समीपे सञ्चिकायाः द्वौ पाठौ स्तः, तौ च परस्परं वारयतः इति यं प्रति भवान् **गच्छेत्** तदेव दर्श्यते:

| | किं करोति | कस्य कृते पूर्वनिर्धारितम् |
| --- | --- | --- |
| **Markdown रूपेण पश्यतु** | सञ्चिकां टिप्पणीरूपेण अङ्कयति, केवलपठनार्थम् | `.md`, `.markdown` |
| **पाठरूपेण सम्पादयतु** | स्रोतः, सम्पादनीयः | अन्यत् सर्वम् |

कोशात् बहिः **पाठरूपेण सम्पादयतु** तदेव नोदनम् अपि यत् केवलपठनस्थितिम् अपनयति — अवस्था अनुज्ञा च द्वे विचारणीये कुञ्ज्यौ न किन्तु एका एव क्रिया। **यदा कदापि तस्य नोदनं केवलपठनम् अपनयेत्** तदा तत् रक्तवर्णं भवति, भवान् तत्रैव सम्पादनं सज्जीकरोतु वा साक्षात् अङ्कितदृश्यात् आगच्छतु वा; कोशस्य अन्तः उद्घाटनीयं किमपि नास्ति, अतः तत् साधारणम् एव तिष्ठति। **Markdown रूपेण पश्यतु** इति लघुम् उद्दीपनवर्णम् आप्नोति — तमेव वर्णं यं Obsidian वृतपाठाय ददाति — येन तत् कर्मणे आह्वानं न किन्तु प्रत्यागमनमार्गः इति चिह्न्यते।

यतः कुञ्जी अपरिष्कृताम् अवस्थां न किन्तु *सम्पादनम्* अनुसरति, अतः पाठदृश्ये केवलपठनस्थितौ स्थिता सञ्चिका अपि **पाठरूपेण सम्पादयतु** इति प्रयच्छति: तदेव नोदनं यत् तत् सज्जीकरोति। यस्यां कदापि लेखितुं न शक्यते — संक्षिप्ता, अपठनीया वा — सा प्रत्युत **पाठरूपेण पश्यतु** इति वदति, यतः नोदनं तावदेव दातुं शक्नोति।

पूर्वनिर्धारितानि शब्दशः न किन्तु उपयोगिरूपेण वृतानि: shell-लिपौ `#` इति टिप्पणी, न तु शीर्षकम्, अतः `.log` इत्यस्य Markdown रूपेण अङ्कनं तत् तूष्णीं ग्रसेत्। उभयम् अपि पूर्वनिर्धारितं प्रतिसञ्चिकं व्यत्येतुं शक्यते, चयनं च पर्णस्य इतिहासे प्रविशति, अतः पश्चात्/अग्रे पुनरुद्घाटितं कार्यक्षेत्रं च तत् रक्षतः — बह्व्यः टिप्पण्यः `.txt` सञ्चिकासु वसन्ति, बह्व्यः `.md` सञ्चिकाश्च स्रोतरूपेण सुखेन पठ्यन्ते।

**भवतः कोशस्य अन्तःस्थाः सञ्चिकाः तत्क्षणमेव सम्पादनीयाः**, किमपि उद्घाटनं विना: *पाठरूपेण सम्पादयतु* इति वास्तविकः सम्पादकः, लिखतः सतः च प्रतिलिखति।

**सम्पादनं परिवर्तनम् अतिक्रम्य अपि स्मर्यते।** *Markdown रूपेण पश्यतु* इत्यत्र गमनं तत् स्थगयति — स्थिरे अङ्कने लेखनस्थानं नास्ति, Live Preview च Obsidian इत्यस्य स्वकीयं सम्पादकम् अपेक्षते, यः केवलं कोशस्य अन्तःस्थासु सञ्चिकासु एव वर्तते — अतः यावत् भवान् तत्र अस्ति तावत् किमपि सम्पादनं क्रियते इति न वदति। *पाठरूपेण सम्पादयतु* इत्यत्र प्रत्यागमनं यत्र भवान् विरतः ततः एव अनुवर्तते।

**कोशात् बहिःस्थाः सञ्चिकाः केवलपठनार्थम् उद्घाट्यन्ते, *पाठरूपेण सम्पादयतु* इति च तत् अपनयति।** तदेव नोदनं समग्रं द्वारम्: यावत् तत् न भवति तावत् तत्र बहिः किमपि न लिख्यते। ततः परं सञ्चिका लिखतः सतः रक्ष्यते, कोशस्य अन्तःस्थेव एव; स्थितिपङ्क्तिः च तालकात् लेखनीं प्रति परिवर्तते। तत् उद्घाटनं तस्मिन् एकस्मिन् पिधाने तां एकां सञ्चिकाम् एव आवृणोति — अन्यां सञ्चिकां प्रति गमनं पुनः निरुणद्धि, बुद्ध्या च तत् पिधानस्य इतिहासे न रक्ष्यते, अतः पुनरुद्घाटितं कार्यक्षेत्रं कदापि तया व्यवस्थासञ्चिकया सह न प्रत्यागच्छति यस्याः उद्घाटनं भवतः न स्मरति, यत्र च लेखनं पूर्वमेव सज्जम्।

**संक्षिप्ताः सञ्चिकाः यथाकथञ्चित् केवलपठनार्थम् एव तिष्ठन्ति** — पटले यत् अस्ति तस्य रक्षणेन सीमायाः परं यत्किमपि तत् सर्वं त्यक्तं भवेत्, अतः कुञ्जी प्रदाय निराकरणस्य स्थाने सर्वथैव न प्रदीयते। या सञ्चिका पठितुं न शक्ता तस्यापि तदेव: रिक्तात् फलकात् अन्यत् प्रतिलेखनीयं किमपि नास्ति।

यदि लेखनं विफलं भवति — केवलपठनार्थं संयोजितम्, भवतः न भवति सा सञ्चिका — तर्हि व्यवस्थायाः स्वकीयं कारणं सूचनायां दर्श्यते।

अतिविशालाः सञ्चिकाः संक्षिप्तरूपेण दर्श्यन्ते, स्थितिपङ्क्तिः च भवान् स्वयं जानीयात् इति न त्यक्त्वा तदेव वदति — कुञ्जीनाम् अनन्तरं न किन्तु अन्यासां स्थितीनां पार्श्वे, यतः एतदपि अन्यानि इव सञ्चिकाविषये तथ्यम्। सीमाः अनुमानेन न किन्तु जीवता अङ्कयित्रा सह मीयन्ते — एकस्मिन् फलके एकस्य मेगाबैट्-पाठस्य विन्यासः Obsidian इत्यस्य अङ्कनप्रक्रियां तत्क्षणमेव हन्ति, Markdown च सामान्यपाठात् प्रतिबैट् बहुगुणम् अधिकं व्ययं करोति, अतः तयोः पृथक् सीमे स्तः, एका विशाला पङ्क्तिः च सञ्चिका समग्रतया लघ्वी सत्यपि संक्षिप्यते।

**स्थितिपङ्क्तयः नामाङ्काः सन्ति, व्याख्या च सङ्केतः।** प्रत्येका पङ्क्तिः यावद्भिः पदैः शक्यते तावद्भिरेव किं सत्यम् इति वदति — *कोशात् बहिः*, *अस्य सञ्चिकाप्रकारस्य कृते सम्पादकः नास्ति*, *संक्षिप्तम् — सञ्चिका अतिविशाला* — यतः तासां पार्श्वे स्थिताः कुञ्ज्यः पूर्वमेव वदन्ति सञ्चिका कस्यां स्थितौ अस्ति इति। एकस्याः उपरि सूचकं नयन् वाक्यं लभते: कथं Obsidian तां टिप्पणीरूपेण उद्घाटयितुं न शक्नोति, अन्यथा अस्य सञ्चिकाप्रकारस्य किं भवेत्, संक्षेपेण भवतः किं नश्यति।

एतत् भवतः कोशस्य **अन्तःस्थासु** सञ्चिकासु अपि प्रवर्तते। यस्य कस्यापि विस्तारस्य कृते दृश्यं नास्ति तम् Obsidian साक्षात् उपकल्पस्य पूर्वनिर्धारिताय अनुप्रयोगाय समर्पयति — अतः भवतः कोशे स्थिता `.txt` `.json` वा Obsidian सर्वथा त्यजेत्। ताः इदानीं तस्मिन्नेव दर्शके नारङ्गवलयेन सह उद्घाट्यन्ते, यतः „तत् Obsidian इत्यत्र उद्घाटय“ इति एव भवता याचितम् — कोशसञ्चिकाः च सन्ति इति ताः तत्र किमपि उद्घाटनं विना सम्पादनीयाः। दर्शकरहिताः द्विचक्रीयाः सञ्चिकाः Obsidian इत्यस्य आचरणं रक्षन्ति; दर्शनीयं किमपि नास्ति।

पूर्वावलोकनं **यस्मिन् पिधाने भवान् आसीत् तस्मिन्नेव** उद्घाट्यते, अतः पश्चात्/अग्रे भवन्तं तां टिप्पणीं प्रति प्रत्यानयतः यस्याः सकाशात् भवान् आगतः; अन्यत्र इव नवीनाय पिधानाय <kbd>Ctrl</kbd> धारयतु। यावत् बाह्यसञ्चिका उद्घाटिता अस्ति तावत् शीर्षपट्टिका तस्याः मार्गं दर्शयति एव, अतः ततः एव अवलोकनम् अनुवर्तितुं शक्यते।

अन्तर्गतस्य उपरि स्थिता शान्ता पङ्क्तिः निर्गममार्गान् प्रयच्छति:

- **_(कोशः)_ इत्यत्र उद्घाटयतु** — यदा सञ्चिका भवतः अन्येषु कोशेषु कस्यचित् भवति तदा दृश्यते। तां Obsidian इत्यस्य स्वकीयाय URI-प्रबन्धकाय समर्पयति, यः तस्य कोशस्य गवाक्षं टिप्पण्या सह वास्तविकसम्पादनीयटिप्पणीरूपेण उद्घाटयति। इदं गवाक्षं यथा आसीत् तथैव तिष्ठति; भवतः अधः किमपि न परिवर्तते।
- **Markdown रूपेण पश्यतु** / **पाठरूपेण सम्पादयतु** — द्वौ पाठौ; द्वितीयः कोशात् बहिः केवलपठनस्थितिम् अपि अपनयति।
- **बहिः उद्घाट्यताम्** — सञ्चिकां भवतः उपकल्पस्य पूर्वनिर्धारिताय अनुप्रयोगाय समर्पयति, ये द्विचक्रीयाः प्रारूपाः एषः दर्शकः दर्शयितुं न शक्नोति तान् अपि सहितान्।

यावत् भवान् प्रथमं *पाठरूपेण सम्पादयतु* इति न नुदति तावत् भवतः कोशात् बहिः किमपि न लिख्यते। पूर्णप्रकटीकरणाय README इत्यस्य [कोशात् बहिः](README.sa.md#कोशात्-बहिः) इति खण्डं पश्यतु।

## स्थानान्तरण/पुनर्नामकरण-अवस्था

शीर्षस्य अत्यन्तदक्षिणे स्थिता लेखनीकुञ्जी — दृश्यावस्थाकुञ्ज्याः पार्श्वे, स्वकीयकुञ्जीभिः समानपरिमाणा — स्थानान्तरण/पुनर्नामकरण-अवस्थां परिवर्तयति। ततः शीर्षपङ्क्तिः उद्दीपनवर्णेन परिवृता भवति, File explorer इत्यत्र पुनर्नामकरणम् इव एव। तान्येव नोदनानि कुञ्ज्यश्च इदानीं Obsidian इत्यस्य `fileManager.renameFile` द्वारा स्थानान्तरणं पुनर्नामकरणं वा दृढीकुर्वन्ति, अतः टिप्पणीं प्रति सर्वे सम्बन्धाः अनुगच्छन्ति।

पुनर्नामकरणकाले:

- वर्तमानं सञ्चिकानाम प्रत्येकस्य पुटस्य सूच्यां संलग्नम् अस्ति, अतः टिप्पणीं पुनः न नामयित्वा स्थानान्तरयितुम् एकमेव नोदनं पर्याप्तम्।
- लक्ष्यपुटे पूर्वमेव गृहीतानि नामानि धूसराणि भवन्ति किन्तु अद्यापि वरणीयानि।
- यत् लिख्यते तत् Obsidian इत्यस्य स्वकीयैः पुनर्नामकरणनियमैः सह जीवत् परीक्ष्यते — तान्येव वर्णसमूहाः, तान्येव सन्देशाः, सञ्चिकावृक्षे पुनर्नामकरणकाले यः रक्तः सङ्केतः लभ्यते सः एव — अतः अनुचितं विरुद्धं वा नाम लिखतः सतः एव चिह्न्यते, दृढीकर्तुं च न शक्यते।
- शीर्षपट्टिकायाः बहिः नोदनं, शीर्षस्य केन्द्रनाशः वा, पुनर्नामकरणावस्थां समापयति।

## द्वयोः पुनर्नामकरणयोः कृते एका कुञ्जी

## दृश्यतानियमाः

- असमर्थितविस्तारयुक्ताः सञ्चिकाः सूचीषु तदैव दृश्यन्ते यदा Obsidian इत्यस्य **Show all file types** इति संयोजनं सक्रियम् अस्ति।
- सूची अधिकतमं १०० प्रविष्टीः दर्शयति — Obsidian इत्यस्य स्वकीया सीमा। यदा पुटे ततः अधिकाः सन्ति तदा अन्तिमा पङ्क्तिः कति त्यक्ताः इति वदति; सूचीं सङ्कोचयितुं लेखनम् अनुवर्तताम्।
- बिन्दुना आरभमाणाः सञ्चिकाः पुटानि च तदैव दृश्यन्ते यदा अस्य प्लगिन् इत्यस्य **गुप्तसञ्चिकाः प्रदर्श्यन्ताम्** इति संयोजनं सक्रियम् अस्ति।
- **अधिलेखनात् रक्षा दृश्यताम् अनपेक्ष्य समानम् एव कार्यं करोति** — गुप्ता सञ्चिका अपि भवन्तं तस्याः अधिलेखनात् निरुणद्धि।

## चिह्नानां प्रतिस्थापनम्

Lure त्रीणि चिह्नानि लिखति: कोशमूलस्य चिह्नम् (**कोशनाम प्रदर्श्यताम्** इत्यस्मिन् निष्क्रिये सति), पुनर्नामकरण/स्थानान्तरण-कुञ्जी, कोशात् बहिः लेखनं नियन्त्रयन् तालकश्च। सर्वाणि विषयात् CSS-खण्डात् वा परिवर्तयितुं शक्यन्ते — प्रतिस्थापकं चिह्नं निर्दिशतु, सह आगतं च एकस्मिन्नेव नियमे गोपयतु:

```css
.lure-vault-icon {
	--lure-icon-glyph: "🏠";
	--lure-icon-svg: none;
}

.lure-rename-btn {
	--lure-icon-glyph: "✎";
	--lure-icon-svg: none;
}

/* तालकस्य द्वे स्थिती स्तः; `.is-active` इति उद्घाटिता। */
.lure-unlock-btn {
	--lure-icon-glyph: "🔒";
	--lure-icon-svg: none;
}

.lure-unlock-btn.is-active {
	--lure-icon-glyph: "🔓";
}
```

`--lure-icon-glyph` इति CSS इत्यस्य `content` इत्यत्र यत्किमपि वैधं तत् सर्वं स्वीकरोति, अतः `url(...)` इति चित्रस्य कृते अपि पाठचिह्नस्य इमोजी-चिह्नस्य वा इव कार्यं करोति। Lucide इत्यस्य चिह्नं रक्षित्वा स्वकीयं चिह्नं तस्य पार्श्वे लेखितुम् `--lure-icon-svg` इति अस्पृष्टं त्यजतु।
