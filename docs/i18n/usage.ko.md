# 사용법

[← README로 돌아가기](README.ko.md)

## 경로 표시줄

노트의 보관함 안 전체 경로가 뷰 헤더 — 탭 줄 아래에 있고 뒤로/앞으로 버튼도 함께 있는 막대 — 의 밋밋한 파일 이름을 대신합니다.

이 줄에서 클릭할 수 있는 것은 둘이며, 어느 쪽이 무엇을 할지는 **폴더 이름으로 목록 열기**가 정합니다:

| | 폴더 이름 | 그 뒤의 구분자 |
| --- | --- | --- |
| **켬**(기본값) | 그 폴더를 편집 대상으로 선택 | 폴더를 엽니다 |
| **끔** | 폴더를 엽니다 | 그 폴더로 내려갑니다 |

"폴더를 엽니다"는 플러그인 없는 Obsidian에서 그 항목을 클릭했을 때의 동작을 뜻합니다. 거기를 듣고 있는 플러그인이 없으면 폴더는 사이드바의 파일 탐색기에서 표시됩니다 — 강조되고, 내용이 보이도록 펼쳐집니다.

[Folder notes](obsidian://show-plugin?id=folder-notes)가 설치되어 있으면 같은 클릭이 대신 그 폴더의 노트를 엽니다. 헤더의 경로를 가로채는 것이 확인된 유일한 폴더 노트 플러그인입니다. [Folder Note](obsidian://show-plugin?id=folder-note-plugin)와 [create folder notes with dropdown](obsidian://show-plugin?id=create-folder-notes-with-dropdown)은 폴더 노트를 다루지만 경로의 클릭은 듣지 않으므로, 이들과 함께 쓰면 구분자는 여느 때처럼 폴더를 표시합니다. [호환성](../compatibility.md#verified-against)을 참고하세요.

구분자에 밑줄이 붙는 것은 **그 앞의 폴더에 실제로 폴더 노트가 있을 때뿐**이므로, 밑줄은 열 것이 있다는 약속입니다. 밑줄이 있든 없든 모든 구분자는 클릭할 수 있습니다 — 밑줄 없는 것은 사이드바에서 그 폴더를 표시하고 펼치며, 포인터 모양이 그 점을 계속 알려 줍니다. 밑줄은 동시에 폴더 이름에서 떨어집니다: 맞바꾸기가 켜져 있으면 이름이 목록을 여니, 그것을 노트로 가는 링크라고 표시하는 건 거짓이 되기 때문입니다.

**이름 바꾸기/이동 모드는 설정과 무관하게 둘 다 덮어씁니다**: 이동이 진행 중인 동안에는 이 줄의 어느 것도 폴더를 열지 않습니다. 열면 이동을 버리는 셈이기 때문입니다. 폴더 이름은 편집 대상으로 선택되고 구분자는 내려갑니다 — 둘 다 목적지를 고르는 방법입니다 — 그리고 여는 동작이 멈춰 있음을 보이려고 밑줄이 사라집니다.

**보관함 루트**는 경로의 항목이 아닌 유일한 항목입니다. 같은 층을 나열할 상위 폴더가 없으므로 대신 [위치 목록](#보관함-밖-둘러보기)을 엽니다 — 다른 보관함들, 홈, 파일 시스템 루트, 마운트된 드라이브입니다.

## 항목 클릭: 같은 층의 다른 것으로 바꾸기

폴더 이름을 클릭하면 **그 폴더의 이름**이 텍스트 입력란에서 선택되고 **한 단계 위** 폴더 — 그 상위 — 의 목록이 열립니다. 입력하거나 항목을 고르면 이 폴더가 같은 층의 다른 것으로 바뀌고 그 아래는 그대로 남으므로, `프로젝트/2026/킥오프.md` → `2026` 클릭 → `2025` 선택이면 `프로젝트/2025/킥오프.md`가 됩니다.

**노트 이름**을 클릭해도 자기 폴더에 대해 같은 방식으로 동작하며, 파일 이름을 **확장자까지 포함해** 선택합니다 — 노트의 이름을 바꾸거나 다른 곳을 가리키게 할 때는 대개 확장자도 함께 바꾸기 때문입니다.

폴더를 클릭하면서 이미 한 항목이 선택되었으므로 **한 번 더 클릭**하면 선택이 줄 전체 — 그 폴더*와* 그 아래 전부 — 로 넓어지고, 그때 입력하면 경로의 나머지를 한 번에 바꿉니다. 탐색 모드와 이름 바꾸기/이동 모드에서 똑같이 동작합니다.

이는 입력란을 연 클릭의 연장으로서만 적용됩니다. 입력란을 한 번 쓰기 시작하면 여느 텍스트 입력란처럼 동작합니다: 클릭은 캐럿을 놓고, 더블클릭은 단어를, 트리플클릭은 줄을 잡습니다.

어느 쪽이든 경로의 나머지는 입력란 둘레에 계속 보입니다 — 앞은 칩으로, 뒤는 선택되지 않은 텍스트로 — 그래서 전체 경로가 헤더에서 사라지는 일은 없습니다. 입력해 선택을 바꾸거나, <kbd>End</kbd> / <kbd>→</kbd>를 눌러 선택을 유지한 채 거기서부터 편집하세요. 목록은 미리 채워진 내용과 상관없이 폴더 전체를 보여 주며, 실제로 입력을 시작해야 비로소 걸러 냅니다.

## 구분자로 내려가기

(**폴더 이름으로 목록 열기**가 꺼져 있을 때) 구분자를 클릭하면 그 앞의 폴더로 내려갑니다: 목록에는 *그* 폴더의 내용이 나오고, 경로의 나머지는 입력란에 선택된 채로 열립니다. 폴더를 고르면 경로에 덧붙고 곧바로 다음 목록이 열리므로, 헤더 줄을 떠나지 않고 트리를 클릭으로 내려갈 수 있습니다.

## 목록의 각 줄은 진짜 파일 관리자 줄

목록의 모든 파일과 폴더는 파일 탐색기에서의 그 줄처럼 동작합니다:

- 같은 컨텍스트 메뉴를 보려면 **오른쪽 클릭** — 폴더에는 *새 노트* / *새 폴더*, 파일에는 *새 탭에서 열기* / *이름 변경…* / *삭제* — 다른 플러그인이 파일 메뉴에 더한 항목까지 포함해서입니다.
- Obsidian이 파일을 받는 곳이면 어디로든 항목을 **끌어** 놓을 수 있습니다: 편집기 안으로 놓아 링크를 넣고, 파일 탐색기의 폴더 위로 놓아 옮기고, 탭 줄 위로 놓아 엽니다.

메뉴 문구는 Obsidian 자체 번역에서 오므로 어느 언어에서든 앱의 나머지 부분과 맞아떨어집니다.

## 경로 입력하기

- 경로 앞이나 뒤의 **빈 공간**을 클릭하면 전체 경로가 미리 채워지고 모두 선택된 텍스트 입력란이 열립니다 — 덮어쓰거나 그 자리에서 편집하세요. (파일 이름 자체를 클릭하면 파일 이름만 선택됩니다. 위를 보세요.)
- 경로가 보이는 상태에서 입력을 시작하면 마지막 항목이, 현재 폴더로 범위를 좁힌 실시간 자동 완성이 붙은 작은 입력란으로 바뀝니다.
- `/`는 현재 항목을 확정하고 그 안으로 내려갑니다.
- 빈 입력란에서의 <kbd>Backspace</kbd>는 상위 폴더로 되돌아 나가며, 커서를 끝에 두고 그 이름을 다시 엽니다.
- <kbd>Enter</kbd>는 확정하고, <kbd>Esc</kbd>나 다른 곳 클릭은 취소하여 파일의 실제 경로로 돌아갑니다.

입력란에는 꾸밈이 없습니다 — 상자도 테두리도 없습니다 — 그래서 경로 글자 자체로 읽히며, 입력에 따라 저절로 늘어납니다.

## 탐색은 열린 파일을 건드리지 않는다

기본(탐색) 모드에서는 열려 있는 노트의 이름이 바뀌거나 옮겨지는 일이 **절대** 없습니다.

- 이미 있는 파일로 이어지는 경로는 그 파일을 엽니다.
- 아직 없는 경로는 *"새 파일을 만들까요?"* 하고 묻습니다. 확인하면 없는 상위 폴더와 파일이 만들어지고, 취소하면 아무 일도 일어나지 않습니다.

## <kbd>Ctrl</kbd> — 새 탭, 그리고 이동 대신 복사

목록에서 파일을 고르거나 경로에서 <kbd>Enter</kbd>를 누를 때 <kbd>Ctrl</kbd>(macOS에서는 <kbd>Cmd</kbd>)을 누르고 있으면, 결과가 이 탭이 아니라 **새 탭**으로 갑니다:

| | 그냥 | <kbd>Ctrl</kbd>과 함께 |
| --- | --- | --- |
| 이미 있는 파일을 고르거나 입력 | 여기서 열림 | 새 탭에서 열림 |
| 없는 경로를 입력 | 묻고 나서 여기서 엶 | 묻고 나서 새 탭에서 엶 |
| 이름 바꾸기/이동 모드에서 경로 확정 | 노트를 그곳으로 **이동** | 그곳으로 **복사**하고 사본을 새 탭에서 엶 |

수정 키는 Obsidian 자체 규칙으로 읽히므로 링크나 파일 탐색기 줄 위에서와 똑같이 동작합니다 — 가운데 클릭도 "새 탭"이고, <kbd>Ctrl</kbd>+<kbd>Alt</kbd>는 분할, <kbd>Ctrl</kbd>+<kbd>Alt</kbd>+<kbd>Shift</kbd>는 새 창입니다.

복사도 이동과 똑같이 덮어쓰기를 거부합니다 — 노트 자신의 경로에 대해서도 마찬가지이며, 거기엔 복사할 만한 것이 없습니다.

## 보관함 밖 둘러보기

**이것은 기본으로 꺼져 있습니다.** 먼저 설정에서 **외부 파일 접근**을 켜세요 — 보관함 밖을 읽고 쓰는 것은 이 플러그인이 하는 일 가운데 Obsidian 자신은 하지 않는 유일한 것이므로, 끄는 것이 아니라 켜는 쪽으로 두었습니다. 꺼져 있으면 보관함 이름은 그저 보관함을 파일 탐색기에서 표시할 뿐이고, 여기 있는 어떤 것도 그 너머를 보지 않습니다.

**보관함 이름**(*보관함 이름 표시*가 꺼져 있으면 🏠 아이콘)을 클릭하면 내용이 아니라 장소의 목록이 열립니다:

- **다른 보관함들**. Obsidian 자체 기록에서 읽어 최근에 연 순서로, 각각 Obsidian 자신의 보관함 아이콘 아래에 놓입니다 — 앱이 보관함 명령에 쓰는 그 아이콘입니다. 이미 열려 있는 보관함만은 대신 집 모양을 답니다: 그곳은 기본적으로 이 줄이 시작하는 자리이지 갈 곳이 아니기 때문입니다.
- **홈**. 자기 계정 이름 아래에 `~` 표시와 함께 놓입니다. Lucide에는 물결표가 없어서 이것은 플러그인이 Lucide 자신의 24×24 격자에 같은 획으로 그립니다 — 아이콘 사이에 끼어든 글자가 아니라, 그 모음에 빠져 있는 아이콘으로서입니다.
- **파일 시스템 루트**. `root`라고 적습니다 — 어느 시스템에서든 그 이름이므로 번역하지 않습니다 — `/`로 하지 않는 것은, 뒤따르는 구분자 옆에서 빈 한 단계처럼 읽히기 때문입니다.
- **마운트된 드라이브**. 종류를 알아내는 비용이 싼 곳에서는 종류별 아이콘이 붙습니다: 네트워크 공유, 광학 디스크, 플로피, 이동식 매체는 각자의 것을, 나머지는 일반 드라이브를 받습니다. Windows에서는 드라이브가 일반 아이콘과 함께 `C:`로 나옵니다 — 볼륨 이름과 정확한 종류에는 WMI가 필요한데, 일부러 쓰지 않습니다.

다른 보관함을 골라도 **Obsidian이 그리로 바뀌지는 않습니다.** 열어 둔 것은 모두 그대로 열려 있고, 경로 표시줄이 그곳을 둘러보기 시작할 뿐입니다. 사이드바의 보관함 전환기에 맡기지 않고 경로 표시줄에 둔 이유가 바로 그것입니다.

### 밖에 있는 동안

경로는 기계의 디렉터리 구조가 아니라 **고른 위치에서 시작합니다** — `보관` 을 고르면 줄은 `/home/you/Vaults/보관/노트/…`가 아니라 `보관 / 노트 / …`로 읽힙니다. 맨 앞 항목에는 그것이 무엇인지(보관함, 홈, 드라이브)를 나타내는 아이콘이 붙고, <kbd>Backspace</kbd>는 파일 시스템의 나머지로 계속 올라가지 않고 거기서 멈춥니다. *보관함 이름 표시*가 꺼져 있으면 그 항목은 아이콘만 남습니다 — 이 설정은 어느 보관함을 가리키든 줄의 첫 항목에 관한 것이지, 자기 보관함에 한정된 이야기가 아닙니다.

경로 표시줄은 보관함 밖을 가리키는 동안 내내 **오류 색으로 테두리가 그려집니다** — 이름 바꾸기 모드가 그리는 것과 같은 테두리입니다. 이는 한순간이 아니라 지속되는 상태를 나타냅니다: 그것이 떠 있는 동안 줄이 보여 주는 것에는 Obsidian 자신의 처리가 하나도 적용되지 않고, 당신이 달리 말하기 전까지 쓰기는 잠겨 있습니다.

그 밖에는 둘러보기가 안에서와 똑같이 동작합니다: 칩, 구분자, 입력, 자동 완성, 밖으로 나가는 <kbd>Backspace</kbd>. 표시 규칙도 같으므로, 지원하지 않는 확장자에는 여전히 Obsidian의 *모든 파일 확장명 인식*이, 숨김 파일에는 여전히 이 플러그인의 설정이 필요합니다.

**오른쪽 클릭과 끌기**는 밖에서 동작하지 않습니다 — 그것들은 파일 탐색기 자신의 처리이고, 보관함이 아는 파일을 필요로 하기 때문입니다.

### 보관함 밖에 쓰기

쓰는 것은 모두 **기본으로 잠겨 있습니다.** 줄이 보관함 밖을 가리키는 동안 헤더의 이름 바꾸기 버튼 옆에 **자물쇠**가 나타납니다. 누르면 자물쇠가 열리고, 줄을 두른 테두리에 맞춰 빨갛게 바뀝니다.

권한은 **한순간이 아니라 한 장소에** 주어집니다: 한곳에서 일하는 동안 할 법한 일들을 모두 견딥니다 — 이동을 마치기, 입력란 바깥을 클릭하기, 파일 열기 — 그리고 목록에서 다른 보관함·드라이브·루트를 고를 때, 줄이 보관함 안 파일로 돌아올 때, 또는 자물쇠를 다시 누를 때 끝납니다. 그래서 한 폴더 안에서 이동을 잇달아 해도 누르는 건 한 번이지 파일마다 한 번이 아닙니다.

자물쇠가 열려 있으면 경로 표시줄은 밖에서도 안에서처럼 동작합니다:

| 동작 | 결과 |
| --- | --- |
| 없는 이름을 입력하고 <kbd>Enter</kbd> | 안에서와 같은 "만들까요?" 확인. 없는 상위 폴더도 함께 만들어집니다. 확장자 없는 이름은 안에서와 똑같이 `.md`가 됩니다 |
| 이름 바꾸기/이동 모드에서 새 이름 입력 | 줄이 보여 주는 파일의 이름을 바꿉니다. 확장자 없는 이름은 그 파일의 확장자를 지킵니다 — 밖에서는 한 폴더에 온갖 종류의 파일이 있고, 이름 바꾸기가 조용히 `.png`를 `.md`로 만들어서는 안 되기 때문입니다 |
| 이름 바꾸기/이동 모드에서 다른 곳을 둘러보고 **이 이름 유지** 선택 | 지금 이름 그대로 그곳으로 옮깁니다 |
| 둘 중 어느 쪽에서든 <kbd>Ctrl</kbd> 누르기 | 옮기는 대신 복사하고, 사본을 새 탭에서 엽니다 |

잠겨 있으면 이들 모두 실행되는 대신 무엇이 막고 있는지 알립니다. 어느 상태에서도 무언가가 덮어써지는 일은 없습니다: 이미 있는 대상은 거부되며, 그 거부는 경합에 질 수 있는 검사가 아니라 파일 시스템 자신의 것(`COPYFILE_EXCL`, 배타적 생성)입니다. 파일 시스템을 넘는 이동 — USB 메모리에서, 네트워크 공유에서 — 은 복사한 뒤 지우는 방식으로 물러나며, 사본이 도착한 뒤에야 원본이 지워집니다.

**자물쇠가 풀지 않는 것이 하나 있습니다: 노트를 보관함 *밖으로* 옮기는 일.** `fileManager`는 그 경계 너머로 파일을 따라갈 수 없으므로, 그 노트를 가리키는 링크는 모두 조용히 끊기고 Obsidian에는 그저 사라진 것으로 보입니다. <kbd>Ctrl</kbd>을 누른 채라면 대신 밖으로 복사되며 그런 문제가 전혀 없고, 알림도 그렇게 말합니다. 반대 방향 — 밖의 파일을 보관함 *안으로* 들이는 것 — 도 아직 연결하지 않았습니다.

### 외부 파일 열기

Obsidian의 편집기는 보관함 안의 파일에만 동작하므로, 외부 파일을 링크와 백링크를 갖춘 진짜 노트로 여는 것은 **불가능합니다** — 이는 앱의 한계이지 이 플러그인의 한계가 아닙니다. 하나를 고르면 대신 **미리 보기**가 열리며, 당신이 달리 말하기 전까지 읽기 전용입니다:

| 종류 | 표시 방식 |
| --- | --- |
| `.md`, `.markdown` | 렌더링된 Markdown |
| 이미지, 오디오, 비디오, PDF | 기본 재생기/뷰어 |
| 그 밖의 모든 **텍스트** 파일(`.json`, `.css`, `.log`, `.txt`, …) | 있는 그대로의 일반 텍스트 |
| 뷰어가 없는 바이너리 형식 | *외부에서 열기*로 넘김 |

뷰어는 파일을 읽는 방식을 둘 가지고 있고, 서로 배타적이므로 **바꿔 갈** 쪽만 보여 줍니다:

| | 하는 일 | 기본값인 대상 |
| --- | --- | --- |
| **Markdown으로 보기** | 파일을 노트처럼 렌더링, 읽기 전용 | `.md`, `.markdown` |
| **텍스트로 편집** | 원본을 편집 가능하게 | 그 밖의 모든 것 |

보관함 밖에서는 **텍스트로 편집**이 읽기 전용을 푸는 누름이기도 합니다 — 모드와 권한을 따져 볼 버튼 둘이 아니라 한 동작으로 묶었습니다. **누르면 읽기 전용이 풀리는 상황이라면 언제나** 붉은빛이 돕니다. 그 자리에서 편집을 준비하든, 렌더링된 보기에서 곧장 왔든 마찬가지입니다. 보관함 안에서는 풀 것이 없으므로 거기서는 평범한 모습입니다. **Markdown으로 보기**는 옅은 강조색이 깔립니다 — Obsidian이 선택된 텍스트에 주는 것과 같은 색조입니다 — 행동을 부르는 것이 아니라 돌아가는 길임을 나타냅니다.

버튼이 원시 모드가 아니라 *편집*을 따라가므로, 텍스트 보기에서 읽기 전용으로 놓인 파일에도 여전히 **텍스트로 편집**이 나옵니다: 그것이 편집을 준비시키는 누름이기 때문입니다. 결코 쓸 수 없는 파일 — 잘렸거나 읽지 못한 — 은 대신 **텍스트로 보기**라고 말합니다. 누름이 줄 수 있는 것이 그뿐이기 때문입니다.

기본값은 글자 그대로가 아니라 쓸모 있는 쪽으로 잡았습니다: 셸 스크립트의 `#`는 제목이 아니라 주석이므로, `.log`를 Markdown으로 렌더링하면 그것을 조용히 삼켜 버립니다. 두 기본값 모두 파일마다 덮어쓸 수 있고 그 선택은 탭의 기록에 들어가므로, 뒤로/앞으로도 다시 연 작업 공간도 그것을 지킵니다 — 노트가 `.txt`에 사는 경우도 많고, 원본으로 읽는 편이 나은 `.md`도 많습니다.

**보관함 안의 파일은 아무 잠금 해제 없이 바로 편집할 수 있습니다**: *텍스트로 편집*은 진짜 편집기이며 입력에 따라 되씁니다.

**편집은 전환을 넘어 기억됩니다.** *Markdown으로 보기*로 가면 편집이 중단됩니다 — 정적인 렌더링에는 입력할 곳이 없고, Live Preview는 보관함 안 파일에만 존재하는 Obsidian 자신의 편집기를 필요로 합니다 — 그래서 거기 있는 동안 편집 중이라고 주장하는 것은 없습니다. *텍스트로 편집*으로 돌아오면 멈춘 자리에서 이어집니다.

**보관함 밖의 파일은 읽기 전용으로 열리고, *텍스트로 편집*이 그것을 풉니다.** 그 한 번의 누름이 문 전체입니다: 그 일이 있기 전까지 밖에는 아무것도 쓰이지 않습니다. 그 뒤로는 보관함 안의 파일과 똑같이 입력에 따라 저장되고, 상태 줄은 자물쇠에서 연필로 바뀝니다. 잠금 해제는 그 탭의 그 파일 하나에만 미칩니다 — 다른 파일로 옮기면 다시 잠깁니다 — 그리고 이는 일부러 탭의 기록에 저장되지 않으므로, 다시 연 작업 공간이 연 기억도 없는 시스템 파일에 쓰기가 준비된 채로 돌아오는 일은 없습니다.

**잘린 파일은 어떤 경우에도 읽기 전용으로 남습니다** — 화면에 있는 것을 저장하면 한계 너머가 모두 버려지므로, 버튼을 내놓고 거절하는 대신 아예 내놓지 않습니다. 읽지 못한 파일도 마찬가지입니다: 빈 창 말고는 되쓸 것이 없습니다.

쓰기가 실패하면 — 읽기 전용 마운트, 자기 것이 아닌 파일 — 시스템 자신의 이유가 알림으로 표시됩니다.

아주 큰 파일은 잘라서 보여 주고, 상태 줄이 그것을 알려 줍니다. 알아서 알아차리게 두는 대신, 그리고 버튼 뒤가 아니라 다른 조건들과 나란히 — 그것도 나머지와 같은 파일에 관한 사실이기 때문입니다. 한계는 어림잡은 값이 아니라 실제 렌더러에 대고 잰 값입니다 — 1메가바이트의 텍스트를 한 창에 배치하면 Obsidian의 렌더러 프로세스가 통째로 죽고, Markdown은 바이트당 일반 텍스트의 몇 배가 들므로 둘의 한계는 따로이며, 파일 전체가 작아도 한 줄이 거대하면 그 줄은 짧아집니다.

**상태 줄은 표시이고, 설명은 툴팁입니다.** 각 줄은 필요한 만큼의 낱말로 사실만 말합니다 — *보관함 외부*, *이 파일 형식용 편집기 없음*, *잘림 — 파일이 너무 큼* — 옆의 버튼들이 파일이 어떤 상태인지 이미 말해 주기 때문입니다. 위에 포인터를 올리면 문장이 나옵니다: 왜 Obsidian이 노트로 열 수 없는지, 이 형식이라면 본래 어떻게 되는지, 잘림이 무엇을 앗아 가는지.

이는 보관함 **안의** 파일에도 적용됩니다. Obsidian은 보기를 갖지 않은 확장자를 곧장 데스크톱 기본 애플리케이션에 넘깁니다 — 그러니 보관함 안의 `.txt`나 `.json`은 Obsidian을 아예 떠나 버립니다. 이제 그런 것들도 같은 뷰어에서, 주황 테두리와 함께 열립니다. "Obsidian에서 열기"가 당신이 요청한 것이기 때문입니다 — 그리고 보관함 파일이므로 아무 잠금 해제 없이 거기서 편집할 수 있습니다. 뷰어가 없는 바이너리 파일은 Obsidian의 동작을 그대로 둡니다. 보여 줄 것이 없기 때문입니다.

미리 보기는 **있던 탭에서** 열리므로 뒤로/앞으로가 오던 노트로 데려다줍니다. 다른 곳과 마찬가지로 새 탭을 원하면 <kbd>Ctrl</kbd>을 누르세요. 열려 있는 동안 헤더 막대는 외부 파일의 경로를 계속 보여 주므로 거기서부터 계속 둘러볼 수 있습니다.

내용 위의 조용한 줄이 나가는 길을 내놓습니다:

- **{vault}에서 열기** — 그 파일이 당신의 다른 보관함에 속할 때 나옵니다. Obsidian 자신의 URI 처리기에 넘겨 그 보관함의 창을 노트가 열린 채로 띄웁니다. 진짜 편집 가능한 노트로서입니다. 이 창은 있던 그대로 남고, 발밑에서 무엇이 바뀌는 일은 없습니다.
- **Markdown으로 보기** / **텍스트로 편집** — 두 가지 읽기 방식이며, 뒤엣것은 보관함 밖에서 읽기 전용도 풉니다.
- **외부에서 열기** — 이 뷰어가 보여 줄 수 없는 바이너리 형식까지 포함해, 파일을 데스크톱의 기본 애플리케이션에 넘깁니다.

먼저 *텍스트로 편집*을 누르지 않는 한 보관함 밖에는 아무것도 쓰이지 않습니다. 전체 설명은 README의 [보관함 외부](README.ko.md#보관함-외부) 절을 참고하세요.

## 두 가지 경고 색

| | 언제 | 뜻 |
| --- | --- | --- |
| 경로 표시줄의 **빨강** 테두리 | 줄이 보관함 밖을 가리킴 | Obsidian은 거기 있는 것을 노트로 열 수 없고, 자물쇠를 열기 전까지 밖에는 아무것도 쓰이지 않습니다. |
| 경로 표시줄의 **주황** 테두리, 목록의 주황 항목 | Obsidian에 보기가 없는 텍스트 형식의 파일 | 주의 표시입니다. Obsidian이라면 데스크톱 기본 애플리케이션에 넘길 것을 플러그인이 대신 보여 줍니다. |

**둘은 서로 독립적이며 동시에 성립할 수 있습니다** — 외부의 `.json`은 보관함 밖에 있고 *동시에* Obsidian에 편집기가 없는 형식입니다. 뷰어에서는 별개의 줄로 나타나 각자 자기 사실만 말합니다. 경로 표시줄에서는 둘 다 해당할 때 빨강이 이깁니다. 테두리가 둘이면 잡음일 뿐이기 때문입니다.

주황 등급은 일부러 좁게 잡았습니다. 등록된 형식(Markdown, canvas, 이미지, PDF, 오디오, 비디오)은 제대로 처리되므로 아무것도 붙지 않습니다. 바이너리 파일에도 아무것도 붙지 않습니다 — 실수로 `.zip`을 편집해 망가뜨릴 일은 없으니까요. 남는 것은 정확히 위험한 것뿐입니다: **모든 파일 확장명 인식**이 보이게 만든 `.json`, `.css`, `.log`.

둘 다 해당할 곳에서는 빨강이 이깁니다. 테두리가 한꺼번에 둘이면 잡음일 뿐입니다.

## 이름 바꾸기/이동 모드

헤더 맨 오른쪽의 연필 버튼 — 보기 모드 버튼 옆, 기본 버튼들과 같은 크기 — 이 이름 바꾸기/이동 모드를 켜고 끕니다. 그러면 헤더 줄이 강조색으로 둘리는데, 파일 탐색기에서 이름을 바꿀 때와 똑같습니다. 같은 클릭과 키 입력이 이제 Obsidian의 `fileManager.renameFile`을 통해 이동이나 이름 바꾸기를 확정하므로, 그 노트로 가는 링크가 모두 따라옵니다.

이름을 바꾸는 동안:

- 현재 파일 이름이 모든 폴더의 목록에 고정되므로, 이름을 그대로 두고 노트를 옮기는 것은 클릭 한 번입니다.
- 대상 폴더에서 이미 쓰이는 이름은 흐려지지만 그래도 고를 수 있습니다.
- 입력은 Obsidian 자신의 이름 바꾸기 규칙에 대고 실시간으로 검증됩니다 — 같은 문자 집합, 같은 메시지, 파일 트리에서 이름을 바꿀 때 나오는 같은 빨간 툴팁 — 그래서 쓸 수 없거나 충돌하는 이름은 입력하는 동안 표시되고 확정할 수 없습니다.
- 헤더 막대 바깥을 클릭하거나 헤더가 초점을 잃으면 이름 바꾸기 모드가 끝납니다.

## 두 이름 바꾸기를 한 키로

이름 바꾸기 명령(기본 <kbd>F2</kbd>, 다시 지정했다면 그 키)은 Obsidian의 인라인 제목 이름 바꾸기와, 전체 경로가 선택된 이 플러그인의 헤더 경로 표시줄 사이를 **번갈아** 오갑니다. Obsidian의 인라인 제목을 껐다면 헤더 경로 표시줄이 유일한 대상이 되므로, 이 키가 아무 일도 하지 않는 경우는 없습니다.

이는 키를 가로채는 대신 `workspace:edit-file-title` 명령을 감싸서 이루어지므로, 단축키를 다시 지정하는 것도 팔레트에서 명령을 실행하는 것도 그대로 동작합니다.

## 목록 줄의 색 구분

| 색 | 뜻 |
| --- | --- |
| **보라** | 노트(`.md`, `.markdown`) — Obsidian이 노트로 열 것이며, 내용이 섞인 폴더에서 골라내어 보여 줍니다 |
| **주황** | Obsidian에 보기가 없는 텍스트 형식. [경고 색](#두-가지-경고-색)을 보세요 |
| **흐림** | 보관함 밖이라 보관함 자신의 처리가 적용되지 않음 |
| **파랑** | 지금 열려 있는 노트. 탐색 중에는 그 노트 자신의 항목이고, 이름 바꾸기/이동 모드에서는 *이 이름 유지* 항목이 그 자리를 대신합니다 — 어느 쪽이든 같은 노트입니다 |
| **회색** | 이름 바꾸기/이동 모드에만: 그 이름은 이미 쓰입니다. 그래도 고를 수 있습니다 — 고르면 입력란이 채워지고 거기서 검증이 충돌을 표시합니다 |

## 표시 규칙

- 지원하지 않는 확장자의 파일이 목록에 나오는 것은 Obsidian의 **모든 파일 확장명 인식** 설정이 켜져 있을 때뿐입니다.
- 목록에는 최대 100줄이 나옵니다 — Obsidian 자신의 한계입니다. 폴더에 그보다 많으면 마지막 줄이 몇 개가 빠졌는지 알려 줍니다. 계속 입력해 목록을 좁히세요.
- 숨김 파일과 숨김 폴더가 나오는 것은 이 플러그인의 **숨김 파일 표시** 설정이 켜져 있을 때뿐입니다.
- **덮어쓰기 보호는 보이든 안 보이든 똑같이 동작합니다** — 숨겨진 파일도 여전히 덮어쓰지 못하게 막습니다.

## 요약표

| 하고 싶은 일 | 이렇게 |
| --- | --- |
| 폴더 열기(그 노트, 또는 표시) | 그 폴더 **뒤의** 구분자를 클릭 |
| 폴더를 같은 층의 다른 것으로 바꾸기 | 그 폴더 이름을 클릭하고 입력하거나 고르기 |
| 노트의 이름을 바꾸거나 다른 곳을 가리키게 하기 | 노트 이름을 클릭 — 확장자 포함 |
| 폴더의 내용 둘러보기 | 그 폴더 이름을 클릭. 목록은 그 상위를 보여 주므로 원하는 것보다 **한 단계 아래** 폴더를 클릭 |
| 폴더와 그 아래 전부를 다시 치기 | 그 폴더 이름을 **더블클릭**한 뒤 입력 |
| 어떤 폴더 아래로 경로 편집하기 | 그 폴더 이름을 클릭한 뒤 <kbd>End</kbd> 또는 <kbd>→</kbd>로 선택 해제 |
| 경로를 쳐서 파일로 건너뛰기 | 파일 이름이나 빈 공간을 클릭, 입력, <kbd>Enter</kbd> |
| 대신 새 탭에서 열기 | 고를 때 <kbd>Ctrl</kbd>, 또는 <kbd>Ctrl</kbd>+<kbd>Enter</kbd> |
| 옮기는 대신 노트를 어딘가로 복사하기 | 연필, 그리고 대상을 고르거나 확정할 때 <kbd>Ctrl</kbd> |
| 없는 경로에 노트 만들기 | 경로를 입력, <kbd>Enter</kbd>, 확인에 응하기 |
| 입력 중 한 단계 내려가기 | `/` 입력 |
| 입력 중 한 단계 올라가기 | 빈 입력란에서 <kbd>Backspace</kbd> |
| 열린 노트를 옮기거나 이름 바꾸기 | 연필을 클릭한 뒤 위처럼 둘러보거나 입력 |
| 이름은 그대로 두고 옮기기 | 연필 → 대상 폴더로 들어가기 → 고정된 현재 파일 이름 고르기 |
| 그 자리에서 이름 바꾸기 | <kbd>F2</kbd> 두 번(첫 번째는 인라인 제목, 두 번째가 헤더) |
| 다른 보관함·홈·드라이브로 건너뛰기 | 보관함 이름을 클릭 |
| 보관함 밖의 파일 열기 | 보관함 이름 → 위치 고르기 → 둘러보기 → 파일 고르기(*텍스트로 편집* 전까지 읽기 전용) |
| 무엇이든 취소하기 | <kbd>Esc</kbd>, 또는 헤더 막대 바깥 클릭 |

## 설정

| 설정 | 선택지 | 기본값 | 하는 일 |
| --- | --- | --- | --- |
| **정렬** | 왼쪽 / 가운데 / 오른쪽 | 왼쪽 | 헤더 줄에서 경로가 놓이는 자리. *가운데*는 Obsidian의 기본 방식과 맞습니다. |
| **구분 기호** | 아무 문자 | `/` | 항목 사이에 그려지는 구분자. 한 번 클릭으로 쓰는 여섯 가지(`/ > ▸ › \ •`)가 텍스트 칸 앞에 놓입니다. |
| **보관함 이름 표시** | 켬 / 끔 | 켬 | 보관함 자신이 경로의 첫 항목인지 여부. 끄면 그 항목은 사라지는 대신 🏠 아이콘이 되므로 경로는 여전히 클릭할 수 있는 자리에서 시작합니다. |
| **폴더 이름으로 목록 열기** | 켬 / 끔 | 켬 | 폴더 이름과 그 뒤 구분자의 역할을 맞바꿉니다 — [위 표](#경로-표시줄)를 보세요. [Folder notes](obsidian://show-plugin?id=folder-notes)가 있으면 구분자가 폴더 노트를 엽니다. 이름 바꾸기/이동 모드에서는 적용되지 않습니다. |
| **숨김 파일 표시** | 켬 / 끔 | 끔 | 숨김 파일과 숨김 폴더를 목록에 넣을지 여부. 덮어쓰기 보호는 어느 쪽이든 적용됩니다. |
| **외부 파일 접근** | 켬 / 끔 | **끔** | 보관함 이름이 위치 목록을 여는지 여부. 끄면 플러그인의 어느 부분도 이 보관함 너머를 보지 않습니다. |

## 아이콘 바꾸기

Lure는 아이콘 셋을 그립니다: 보관함 루트 아이콘(**보관함 이름 표시**가 꺼져 있을 때), 이름 바꾸기/이동 토글, 그리고 보관함 밖 쓰기를 지키는 자물쇠입니다. 모두 테마나 CSS 스니펫에서 바꿀 수 있습니다 — 대신할 글자를 지정하고 함께 들어 있는 것을 숨기는 일을 규칙 하나로 하세요:

```css
.lure-vault-icon {
	--lure-icon-glyph: "🏠";
	--lure-icon-svg: none;
}

.lure-rename-btn {
	--lure-icon-glyph: "✎";
	--lure-icon-svg: none;
}

/* 자물쇠에는 두 상태가 있고 `.is-active`가 열린 쪽입니다. */
.lure-unlock-btn {
	--lure-icon-glyph: "🔒";
	--lure-icon-svg: none;
}

.lure-unlock-btn.is-active {
	--lure-icon-glyph: "🔓";
}
```

`--lure-icon-glyph`는 CSS `content`에 쓸 수 있는 것이라면 무엇이든 받으므로, 텍스트나 이모지 글자뿐 아니라 `url(...)`로 이미지도 됩니다. Lucide 아이콘을 남기고 그 옆에 자기 글자를 그리려면 `--lure-icon-svg`는 건드리지 마세요.
