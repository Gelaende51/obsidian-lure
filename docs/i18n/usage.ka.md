## ბილიკი სათაურის ზოლში

ჩანაწერის სრული ბილიკი საცავში ცვლის შიშველ ფაილის სახელს ხედის სათაურის ზოლში — იმ ზოლში, რომელიც ჩანართების რიგის ქვემოთაა და უკან/წინ ღილაკებსაც ინახავს.

ამ რიგში ორ რამეზე შეიძლება დაწკაპუნება და **საქაღალდის სახელი ხსნის სიას** განსაზღვრავს, რომელი რას აკეთებს:

| | საქაღალდის სახელი | მის შემდეგ მდგომი გამყოფი |
| --- | --- | --- |
| **ჩართული** (ნაგულისხმევი) | ირჩევს იმ საქაღალდეს რედაქტირებისთვის | ხსნის საქაღალდეს |
| **გამორთული** | ხსნის საქაღალდეს | ჩადის იმ საქაღალდეში |

„ხსნის საქაღალდეს“ ნიშნავს იმას, რასაც ამ მონაკვეთზე დაწკაპუნება აკეთებს სუფთა Obsidian-ში. თუ იქ არცერთი მოდული არ უსმენს, საქაღალდე ჩანს გვერდით ზოლში, ფაილებში — გამოკვეთილი და გაშლილი, რომ შიგთავსი დაინახოთ.

სადაც საქაღალდის ჩანაწერი სწორედ ის ფაილია, რომელსაც უკვე კითხულობთ, დაწკაპუნება საქაღალდეს გამოკვეთს ნაცვლად გახსნისა — არაფერია გასახსნელი, რაც უკვე ეკრანზე არაა, და სწორედ ეს ნიშნავდა ყოველთვის მეორე დაწკაპუნებას.

დაყენებული [Folder notes](obsidian://show-plugin?id=folder-notes)-ით იგივე დაწკაპუნება ამის ნაცვლად ხსნის იმ საქაღალდის ჩანაწერს, **ნებისმიერ სიღრმეზე**: ჩანაწერი აქვე დგინდება იმ მოდულის საკუთარი კონვენციიდან, ვიდრე მას მიენდობა პასუხის გაცემა. ის მოდული ცნობს მხოლოდ იმ საქაღალდეებს, რომლებიც მან თავად მონიშნა, რაც ერთზე მეტ საქაღალდეზე ღრმა ბილიკზე არცერთია, ამიტომ დაწკაპუნება, რომელმაც ზედა დონის საქაღალდის ჩანაწერი გახსნა, უფრო ღრმად აღარაფერს აკეთებდა. დანარჩენი ორი საქაღალდის-ჩანაწერის მოდული არ აქვეყნებს კონვენციას წასაკითხად და არასდროს იჩემებს ამ რიგს, ამიტომ მათთან გამყოფი საქაღალდეს, როგორც ყოველთვის, გამოკვეთს. ეს ერთადერთი საქაღალდის-ჩანაწერის მოდულია, რომელიც სათაურის ბილიკს იჩემებს; [Folder Note](obsidian://show-plugin?id=folder-note-plugin) და [create folder notes with dropdown](obsidian://show-plugin?id=create-folder-notes-with-dropdown) მართავენ საქაღალდის ჩანაწერებს, მაგრამ ბილიკზე დაწკაპუნებას არ უსმენენ, ამიტომ მათთანაც გამყოფი საქაღალდეს ჩვეულებრივად გამოკვეთს. იხილეთ [თავსებადობა](../compatibility.md#verified-against).

გამყოფი **ხაზგასმულია მხოლოდ მაშინ, როცა მის წინ მდგომ საქაღალდეს ნამდვილად აქვს საქაღალდის ჩანაწერი**, ამიტომ ხაზგასმა დაპირებაა, რომ იქ რაღაც გასახსნელია — ნებისმიერ სიღრმეზე, როცა [Folder notes](obsidian://show-plugin?id=folder-notes) გაშვებულია, ვინაიდან ჩანაწერი აქვე დგინდება და არა იმ მოდულს მიენდობა მონიშვნა. სადაც ეს მოდული არაა გაშვებული, არაფერია ხაზგასმული და არაფერი იხსნება: გამყოფი გამოკვეთს, როგორც არცერთი საქაღალდის-ჩანაწერის მოდულის გარეშეც ხდება. ყოველი გამყოფი ორივე შემთხვევაში დაწკაპუნებადი რჩება — ხაზგასმის გარეშეც ის თავის საქაღალდეს გვერდით ზოლში გამოკვეთს და გაშლის, რასაც კურსორის ისარიც კვლავ მიანიშნებს. ხაზგასმა საქაღალდის სახელიდან იმავდროულად ქრება: გადართვის ჩართვისას სახელი სიას ხსნის, ამიტომ მისი, როგორც ჩანაწერზე მიმავალი ბმულის, მონიშვნა სიცრუე იქნებოდა.

**გადარქმევის/გადატანის რეჟიმი ორივეს გადაფარავს**, რასაც უნდა ამბობდეს პარამეტრი: სანამ გადატანა დაუსრულებელია, რიგში არაფერი ხსნის საქაღალდეს, რადგან გახსნა გადატანას მიატოვებდა. საქაღალდის სახელები რედაქტირებისთვის შეირჩევა, გამყოფები კი ჩადიან — ორივე დანიშნულების არჩევის გზაა — და ხაზი ქრება, რომ აჩვენოს: გახსნა შეჩერებულია.

**საცავის ძირი** ერთადერთი მონაკვეთია, რომელიც ბილიკის მონაკვეთი არაა. მას მშობელი არ ჰყავს, საიდანაც დებს გვერდით მდგომებს ჩამოთვლიდა, ამიტომ ის სამაგიეროდ ხსნის [ადგილების სიას](#საცავის-გარეთ-დათვალიერება) — თქვენს სხვა საცავებს, პირად საქაღალდეს, ფაილური სისტემის ძირს და მიერთებულ დისკებს.

## საცავის საკუთარი გამყოფი

გამყოფი, რომელიც პირდაპირ საცავის სახელის შემდეგ დგას, თავად საცავს
წარმოადგენს და არა საქაღალდეს, ამიტომ ის აკეთებს იმას, რასაც სხვა
არცერთი გამყოფი ვერ აკეთებს:

| | პირველი დაწკაპუნება | შემდეგი დაწკაპუნება |
| --- | --- | --- |
| **საწყისი გვერდის მოდულით** (გვერდი, რომელიც Obsidian-ის გახსნისას გხვდებათ) | ხსნის იმ გვერდს ამ პანელში | კეცავს ფაილთა ხეს |
| **მის გარეშე** | კეცავს ფაილთა ხეს | ზუსტად აბრუნებს იმას, რაც ღია იყო |

ჩვეულებრივი დაწკაპუნებებია, არა ორმაგი: როგორც კი გვერდი გახსნილია,
გამყოფს გასახსნელი აღარაფერი აქვს, ამიტომ მომდევნო დაწკაპუნება კეცვაა —
რამდენ ხანსაც არ უნდა დახარჯოთ ამაზე.

ის **ხაზგასმულია**, როცა საწყისი გვერდი გასახსნელად არსებობს, რაც იგივე
დაპირებაა, რასაც საქაღალდის გამყოფი აკეთებს: იქ რაღაც არის. კეცვა
გადამრთველია — მომდევნო დაწკაპუნება აღადგენს ზუსტად იმ საქაღალდეებს,
რომლებიც ღია იყო, და მხოლოდ მათ, ამიტომ თქვენ მიერ მოწყობილი ხე
სხვა რამეზე ერთი გახედვით არ იკარგება.

## პანელი ფაილის გარეშე

ცარიელი ჩანართი, გრაფი და ყველაფერი სხვა, რაც ფაილს არ ასახელებს, თავის
რიგს იღებს: საცავი, შემდეგ ერთი მონაკვეთი, რომელიც ამბობს, რას შეიცავს
პანელი.

```
my-vault / :blank      a new tab
my-vault / :graph      the graph, local or global
my-vault / :<type>     anything else with no file
```

**საცავის ძირის საკუთარი სია** ამ გვერდებსაც სთავაზობს, იმ საქაღალდეებისა
და ჩანაწერების ქვემოთ, რომლებიც ნამდვილად არიან მასში: აირჩიეთ იქ `:graph`
ან `:search` და პანელი ხსნის იმ ხედს, ზუსტად ისე, როგორც ჩანაწერის არჩევა
ხსნის ჩანაწერს. რომელი გვერდები არსებობს, ამოკითხულია Obsidian-იდან და არა
აქ ჩაწერილი — ყოველი ხედი, რომელიც ფაილის საჩვენებლად არ არსებობს, ამიტომ
მოდული, რომელიც თავის ხედს ირეგისტრირებს (საწყისი ჩანართი, კალენდარი),
ჩნდება ისე, რომ ეს მოდული მასზე არაფერს არ იცის. ხედები, რომლებსაც ფაილი
სჭირდება — Markdown, PDF, სურათები, canvas-ები, ბაზები — არ არის
შემოთავაზებული: მათთვის ჩასაჩენი არაფერია.

წერტილ-წერტილი (`:`) სწორედ არსია — არცერთ ფაილს ან საქაღალდეს არ
შეიძლება ერქვას `:graph`, ამიტომ რიგის ისეთ ბილიკად აღქმა შეუძლებელია,
რომელიც შეიძლება გაიხსნას. ჭდე მოდის ხედის ტიპიდან და არა Obsidian-ის
საკუთარი ფორმულირებიდან, ამიტომ ის ერთნაირად იკითხება ინტერფეისის
ნებისმიერ ენაზე, და ბოლო `-view` მოცილებულია: საწყისი ჩანართის მოდული
თავის ხედს რეგისტრირებს, როგორც `home-launcher-view`-ს, და რიგი წერს
`:home-launcher`-ს.

ცარიელ სივრცეზე ან თავად ჭდეზე დაწკაპუნება **ხსნის ველს საცავის ძირზე**:
აკრიფეთ ბილიკი და <kbd>Enter</kbd> ხსნის მას ამავე პანელში, იმავე
დასრულებით, იმავე სიით და იმავე წითელი ველით, რომელიც გვთავაზობს
შექმნას იმისა, რაც ჯერ არ არსებობს. ცარიელი ჩანართი კარგი ადგილია
იმის ასაკრეფად, სად გინდათ წასვლა — სწორედ ამისთვისაა.

ჭდე მხოლოდ ჭდეა და არაფერი მეტი: არც სია, არც გადათრევა, არც
გადარქმევა. გვერდით ზოლების პანელები სულაც უცვლელი რჩება — უკუბმულების
პანელი იმ სათაურს ინარჩუნებს, რომელსაც Obsidian აძლევს.

Canvas-ებს, PDF-ებს, სურათებსა და ბაზებს ეს არაფერი სჭირდებათ. ისინი
ფაილები არიან, ამიტომ იღებენ ჩვეულებრივ ბილიკის ზოლს.

## სიის ჩანაწერები ნამდვილი ფაილმმართველის სტრიქონებია

სიაში ყოველი ფაილი და საქაღალდე იქცევა ისე, როგორც მისი სტრიქონი ფაილებში:

- **მარჯვენა დაწკაპუნება** იმავე კონტექსტურ მენიუსთვის, რომელსაც ფაილები გვთავაზობს, ჩანაწერი ჩანაწერზე — მათ შორის ის, რასაც სხვა მოდულები ამატებენ. საქაღალდე გთავაზობთ *ახალი ჩანაწერს*, *ახალი საქაღალდეს*, *ახალი canvas-ს*, *ახალი ბაზას*, *ასლის გაკეთებას*, *საქაღალდის გადატანას…*, *ძიებას საქაღალდეში*, *ბილიკის კოპირებას*, *ჩვენებას სისტემურ ფაილმმართველში*, *გადარქმევას…* და *წაშლას*; ფაილი გთავაზობთ თავის შესაბამისს, მათ შორის *ნაგულისხმევ აპლიკაციაში გახსნას*.
- **გადათრევა** ჩანაწერისა ნებისმიერ ადგილას, სადაც Obsidian ფაილს იღებს: რედაქტორში — ბმულის ჩასასმელად, საქაღალდეზე ფაილებში — გადასატანად, ჩანართების ზოლზე — გასახსნელად.

მენიუს ფორმულირებები თავად Obsidian-ის თარგმანებიდან მოდის, ამიტომ ისინი ყველა ენაზე ემთხვევა აპლიკაციის დანარჩენ ნაწილს.

## ბილიკის აკრეფა

- **ცარიელ სივრცეზე** დაწკაპუნება ბილიკის წინ ან უკან ხსნის ტექსტურ ველს მთელი ბილიკისთვის *და აჩვენებს ჩანაწერს ფაილმმართველში*, ისე რომ ხე პანელს მოსდევს დამატებითი ჟესტის გარეშე. ის **ითვლის თქვენს დაწკაპუნებებს**: ერთი ირჩევს ბილიკს გაფართოების გარეშე, ორი — მასთან ერთად, სამი — ბილიკს, რომელსაც მანქანა იცნობს. **ფაილის სახელზე** დაწკაპუნება ისევე ითვლება, მაგრამ იწყება ერთი საფეხურით ქვემოთ, სახელზე თავად: ერთი ირჩევს მას გაფართოების გარეშე, ორი — მასთან ერთად, სამი კი ფართოვდება მთელ ბილიკამდე *თქვენი საცავის საქაღალდიდან* — ფორმამდე, რომელსაც ბმული ან ძიება მოითხოვს, და არა მანქანა. მეოთხე დაწკაპუნება სწორედ იქ აღწევს.
- **დათვლა ეკუთვნის სერიას, რომელმაც ველი გახსნა.** როგორც კი ის შეწყდება — შეჩერდით, აკრიფეთ ან დააწკაპუნეთ ერთხელ ტექსტში სადმე — ველი ჩვეულებრივი ტექსტური ველი ხდება, და ორმაგი დაწკაპუნება მასში იმ სიტყვას გამოარჩევს, რაც კურსორის ქვეშაა, ისევე როგორც ნებისმიერ სხვაგან. აკრიფეთ არჩეულის ზემოთ ან ჩაასწორეთ ადგილზე. (თავად ფაილის სახელზე დაწკაპუნება მხოლოდ ფაილის სახელს ირჩევს; იხილეთ ზემოთ.) იმავე სივრცეზე მარჯვენა ღილაკით დაწკაპუნება **კოპირებს** იმავე სამ ვარიანტს ორ, სამ და ოთხ დაწკაპუნებაზე — ერთი ღილაკი აჩვენებს მათ, მეორე იღებს. **ერთი** მარჯვენა დაწკაპუნება ხსნის ბილიკს მთლიანად არჩეულით და გთავაზობთ, რისი გაკეთებაც შეიძლება მასთან: ამოჭრა, კოპირება, ჩასმა, ყველას მონიშვნა — ისე, როგორც Obsidian თავად ეძახის.
- **დააწკაპუნეთ ცარიელ სივრცეზე შუა ღილაკით**, რომ ბილიკის ზემოთ ჩასვათ: ველი იხსნება მთელ ბილიკზე *საცავის ძირიდან*, ასე რომ ბუფერი მთლიანად ანაცვლებს მას, და ის რაც ჩაჯდება — არჩეულია. შემდეგ <kbd>Enter</kbd> იქ მიდის.
- **<kbd>Ctrl</kbd>+დაწკაპუნება ცარიელ სივრცეზე** ხელახლა ხსნის ამ ჩანაწერს საკუთარ ჩანართში, გამოკრთომით ფაილმმართველში, რომ მეორე ჩანართი პირველთან არ აგერიოთ. **საცავის სახელზე** <kbd>Ctrl</kbd>+დაწკაპუნება ან შუა ღილაკით დაწკაპუნება ხსნის ცარიელ ჩანართს, საცავის ძირში მდგომს, სიით რომელიც უკვე ჩანს — ადგილი, სადაც ბილიკი ნულიდან ჩაწეროთ.
- ბილიკის ჯაჭვის ჩვენებისას აკრეფა ბოლო მონაკვეთს გარდაქმნის პატარა ველად, მიმდინარე საქაღალდის ფარგლებში ცოცხალი ავტოშევსებით.
- **ფაილური სისტემის ძირიდან ბილიკის აკრეფაც შეიძლება.** `/` ცარიელი ველის წინ ხსნის ახალს, ვიდრე საფეხურს ავსებს, მისი ყოველი შემდგომი დახრილი ხაზი მას ეკუთვნის, და `~` თქვენი საშინაო საქაღალდეა. სანამ ველში ასეთი ბილიკია, სია საცავის ნაცვლად მანქანას ჩამოთვლის, და სტრიქონის საწყისი მონაკვეთი გვერდზე იხევს — ველში ჩაწერილი ძირიდან იწყება და ეს ისეც ჩანს. როცა *გარე ფაილებზე წვდომა* გამორთულია, სია ცარიელი რჩება, რადგან <kbd>Enter</kbd> ისედაც უარყოფდა ბილიკს.
- **გვერდის აკრეფაც შეიძლება, არა მხოლოდ არჩევა.** `:graph`, `:search` ან რაც არ უნდა თქვენმა დამატებებმა დაარეგისტრირონ — იმ ჭდეები, რასაც [საცავის ძირის სია](#პანელი-ფაილის-გარეშე) გთავაზობთ. ორწერტილის აკრეფა ნებისმიერ ადგილას მათ იძახებს, ვინაიდან სახელი ორწერტილს ვერასდროს შეიცავს, და <kbd>Enter</kbd> ხსნის იმ ხედვას ამ პანელში. `:graph`-ის აკრეფა **საქაღალდის შიგნით** ხსნის იმ საქაღალდის გრაფს — გრაფს, გაფილტრულს `path:"that/folder"`-ით საკუთარ საძიებო ველში, თითქოს იქ ჩაწერილიყო; საცავის ძირში ეს მთელი გრაფია. <kbd>Tab</kbd> ასრულებს სახელს, ისევე როგორც საქაღალდისას — და თან წაიღებს, რაც არ უნდა ველში ეკავა, რადგან გვერდი არცერთ საქაღალდეში არაა და მის ქვეშ არაფერი ცხოვრობს. ასეთ პანელზე ჭდეზე დაწკაპუნება ხსნის ველს, რომელშიც ის უკვე წერია.
- **რასაც <kbd>Tab</kbd> დაწერდა, ის აკრეფისას გთავაზობთ.** სადამდეც ყოველი შვილობილი, რომელიც თქვენ ნაწერით იწყება, ცოტა ხანს კიდევ ეთანხმება ერთმანეთს, ის თანხმობა კურსორის შემდეგ ჩნდება, არჩეული; სადაც ისინი ეთანხმობას წყვეტენ, ნაბიჯი პირველისკენ მათგან — ან იმ სტრიქონისკენ, რომელზეც ისრით მისულხართ, რადგან სწორედ იქითკენ წავიდოდა <kbd>Tab</kbd>. სახელის ზემოთ აკრეფა მის გაფართოებას ადგილზე ტოვებს და მის წინ სთავაზობს, და ახლახან შესული საქაღალდე სთავაზობს თავის პირველ ნაბიჯს, ასე რომ არასდროს ხდება, რომ არაფერი შემოთავაზდეს და <kbd>Tab</kbd>-მა მაინც რამე დაწეროს. აკრიფეთ ის ასოები და ის ერთი-ერთზე ითქვმევა; აკრიფეთ სხვა რამე და ის ქრება. <kbd>Tab</kbd> ან <kbd>End</kbd> მთლიანად იღებს მას, <kbd>→</kbd> — მისი ერთ ასოს, <kbd>Backspace</kbd> — უკან წაიღებს, თქვენ მიერ აკრეფილ არცერთ ასოს შეხების გარეშე, და აღარაფერი შემოთავაზდება, სანამ ისევ არ დაწერთ — ასე რომ ყოველთვის არსებობს გზა იმ სახელიდან გასასვლელად, რაც არ გინდოდათ. <kbd>Tab</kbd>-ზე დაჭერის შემდეგ შემდეგი ნაბიჯი მაშინვე ითავაზება, ისევე როგორც ერთი ასოს აკრეფის შემდეგ. რასაც სია ჩამოთვლის, ის ფილტრდება **თქვენ** მიერ ნაწერით, არასდროს — შემოთავაზებულით.
- **შემოთავაზებები რეგისტრს იგნორირებენ.** `sch` სთავაზობს `Schemes`-ს, ისე დაწერილს, როგორც სახელია; შემოთავაზების უკან წაღება თქვენს ასოებს ისე გიბრუნებთ, როგორც დაწერეთ. სადაც `Test` და `test` ორივე არსებობს, სთავაზობენ იმას, რომელიც ისეა დაწერილი, როგორც თქვენ ჩაწერეთ.
- ველში შემოთავაზებული ნაწილი უბრალოდ **არჩეულია**. სია არის ადგილი, სადაც ის დაშლილია: თითოეული სტრიქონი აჩვენებს იმ ნაწილს, **რომელიც თქვენს ნაწერს დახვედრა, გამუქებულს**, სახელში სადაც არ უნდა ემთხვეოდეს — `kick` პოულობს `Weekly kickoff`-ს და ეს ჩანს კიდეც. **სახელები, რომლებიც თქვენი ნაწერით იწყება, პირველები არიან**, მათზე წინ ვინც მხოლოდ შეიცავს მას, და მონიშნულია ხაზით მათი კიდის გასწვრივ: **ლურჯი**, სადაც მეტს იზიარებენ, ვიდრე თქვენ დაწერეთ, ასე რომ <kbd>Tab</kbd>-ს აქვს რაც დაამატოს ყველასთვის, და **მწვანე** იმ ტოტზე, სადაც შემოთავაზება იხრება, სადაც ისინი იყოფიან — `te`, `test1`, `test2`, `text1` და `text2` არსებობისას სთავაზობს `te`+`st`-ს, ასე რომ ორივე `test` სტრიქონი მწვანეა და ორივე `text` სტრიქონი მარტივ ხაზს ინარჩუნებს. თითოეული მათგანი **ხაზგასმულია იმ ნაბიჯზე, რომელსაც <kbd>Tab</kbd> მისკენ გადადგამდა**, არა მხოლოდ შემოთავაზებულზე, და ხაზგასმა შემოთავაზებას მისდევს, როცა ის იცვლება.
- **აკრეფა უშვებს გამოკვეთილ სტრიქონს.** სია იხსნება იმ ჩანაწერზე, რომელზეც დგახართ, მაგრამ იმ წამს, როცა წერას იწყებთ, საუბარი უკვე სხვაგანაა, და გამოკვეთა, რომელიც არავის დაუდვია, არჩევანად იკითხება, რომელიც უკვე გაკეთდა.
- შემოთავაზება ყოველთვის მხოლოდ თქვენს წინ მდგომი ტექსტია: ასოები, რომლებიც თქვენ დაწერეთ, ისე რჩება, როგორც დაწერეთ, სანამ წერთ, და შემოთავაზების აღება სახელს ისე გადაწერს, როგორც საქაღალდე წერს მას, რადგან ბილიკი დისკს უნდა დაემთხვეს. `sk` + <kbd>Tab</kbd> `Skyline`-მდე მიდის, არა `skyline`-მდე.
- **ველი ატარებს იმის ფერს, რასაც ასახელებს**, იმავე ფერს, რაც მისი სტრიქონია სიაში: იასამნისფერი ჩანაწერისთვის, საქაღალდის საკუთარი ჩანაწერის ჩათვლით, ნარინჯისფერი ყველაფრისთვის, რაც ჩანაწერი არაა, ლურჯი — ჩანაწერისთვის, რომელზეც ახლა ხართ. ის სტრიქონი, საიდანაც ველი ფერს იღებს, არის ის, რომელსაც ზუსტად ის სახელი აქვს, რაც თქვენ დაწერეთ, ან, თუ ასეთი არაა, გამოკვეთილი, ან, თუ ესეც არაა, პირველი, რომელთანაც თქვენი ნაწერი კვლავ მიგყავართ.
- **ველი წითლდება, როგორც კი მასში ჩაწერილს აღარაფერი პასუხობს** — არც ფაილი, არც საქაღალდე, და სიის არცერთი სტრიქონი მისკენ აღარ მიდის. აქედან <kbd>Enter</kbd> ქმნის ველში ჩაწერილს, ვიდრე ხსნის, და წითელი ეს წინასწარ გეუბნებათ, ვიდრე დაადასტურებთ. ის არასდროს ჩნდება ვებ-მისამართისთვის, რომელიც ამ მანქანაზე საძებნი ადგილი არაა. ფერი ერგება **მთელ** ველს და არა მხოლოდ იმ ნაწილს, რაც აკლია: ტექსტური ველი საკუთარი შიგთავსის ნახევარს ვერ დაფერავს. გადატანის/გადარქმევის რეჟიმში ველი საკუთარ წითელს ინარჩუნებს, დაუშვებელი სახელისთვის — იქ სახელი, რომელსაც არაფერი პასუხობს, სწორედ აზრია. რომ სახელი **უკვე დაკავებულია**, ეს დადასტურებისას ჩნდება, დიალოგით, რომელიც კითხულობს, რა მოხდეს ფაილთან, გზაზე მდგომთან — იხილეთ [სახელი, რომელიც დაკავებულია](#დაკავებული-სახელი): ყოველი სახელი, რომელიც `Notes.md`-კენ იწერება, გადის სახელებზე, რომლებიც შესაძლოა თავად ფაილები იყოს, ასე რომ ასო-ასო მონიშვნა აფრთხილებდა სახელზე, რომელსაც ჯერ არავინ ეძებდა.
- `/` ადასტურებს მონაკვეთს, რომელსაც აკრეფთ და მასში ჩადის, ინარჩუნებს რაც მის უკან იყო — იმას აკეთებს, რასაც <kbd>Tab</kbd> აკეთებს, როცა შედის.
- <kbd>Backspace</kbd> ცარიელ ველში საწყის საქაღალდეში აბრუნებს, მის სახელს ისევ ხსნის კურსორით ბოლოში. იგივეს აკეთებს <kbd>Backspace</kbd> გაფართოების წინ, რომელიც მარტოდმარტო დარჩა — ველი, რომელშიც მხოლოდ `.md` წერია, არაფერს ასახელებს — და მარტოხელა გაფართოებაც მასთან ერთად მიდის.
- **საქაღალდეზე დაწკაპუნება ღია ველის დროს მას მთელ ბილიკამდე აფართოებს იმ საქაღალდის შემდეგ**, საქაღალდის საკუთარი სახელით არჩეულით — იმას აკეთებს, რასაც სტრიქონიდან დაწკაპუნება გააკეთებდა, და ველში ყველაფერი, რაც ეკავა, ინარჩუნებს. რაც ველშია, ეს ღია დროს სტრიქონის კუდია, ასე რომ ზემოთ დაწკაპუნებული საქაღალდე იმ ბილიკს გიბრუნებთ, რაც სესიამ გაიარა და არა იმას, საიდანაც ჩანაწერი დაიწყო.
- **ველის თავიდან ისრით გასვლა წინ მდგომ საქაღალდეს შემოაქვს**, თითქოს მთელი ბილიკი ერთი ტექსტის ხაზი იყოს. კურსორის ყველაზე თავში, <kbd>←</kbd> იმ საქაღალდეს ველში შემოაქვს და მისი სახელის ბოლოში ჯდება, <kbd>Ctrl</kbd>+<kbd>←</kbd> მის თავში ჯდება, და <kbd>Home</kbd> ერთბაშად შემოაქვს ყოველი საქაღალდე საცავის ძირამდე — ან იმ ადგილამდე, რომელიც აირჩიეთ, საცავის გარეთ. დააჭირეთ <kbd>Shift</kbd>-ს და არჩევანი შემოსულზე გაიწელება. macOS-ზე სიტყვაზე გადახტომაა <kbd>Option</kbd>+<kbd>←</kbd>, და <kbd>Cmd</kbd>+<kbd>←</kbd> არის <kbd>Home</kbd>. თავის გარდა ნებისმიერ ადგილას ეს ჩვეულებრივი ტექსტური კლავიშებია. **სანამ სია ჩანს, <kbd>Home</kbd>, <kbd>End</kbd>, <kbd>PgUp</kbd> და <kbd>PgDn</kbd> მას ეკუთვნის** — პირველი სტრიქონი, ბოლო სტრიქონი, გვერდი ზემოთ, გვერდი ქვემოთ, სადაც გვერდი ისაა, რასაც სია აჩვენებს, გამოკვეთილი სტრიქონის ეკრანზე თავისი ადგილის შენარჩუნებით — და ტექსტს მხოლოდ მისი დახურვის შემდეგ სწვდება; <kbd>Shift</kbd>+<kbd>Home</kbd> ღია სიის დროსაც შემოაქვს ყოველი საქაღალდე.
- **სია კურსორს მისდევს.** ბილიკის სხვა ნაწილი გამოარჩიეთ — გადაათრიეთ მასზე, დააწკაპუნეთ მასში, ან ისრით მიდით — და სია *იმ* საქაღალდის შვილებს ჩამოთვლის, არა იმისას, რომელზეც ველი გაიხსნა. საქაღალდე ითვლება ჩიპებიდან, პლუს რაც ველიდან კურსორის წინ დევს, ასე რომ `Notes.md`-ში დაწკაპუნება ველში, რომელშიც `2026/Notes.md` წერია, ჩამოთვლის, რაც `2026`-შია. სტრიქონზე მიმართვა მას წერს იმ მონაკვეთში, სადაც კურსორია, და მაჩვენებლის სიიდან მოშორება გიბრუნებთ თქვენს ტექსტსა და არჩევანს, ზუსტად ისე, როგორც იყო.
- **არჩევანის ველიდან გამოტანა** და სხვაგან გაშვება მას არ ხურავს. დაწკაპუნება, რომელიც ველში იწყება, რედაქტირებას ეკუთვნის, რამდენადაც არ უნდა იმოგზაუროს; მხოლოდ დაწკაპუნება, რომელიც გარეთ *იწყება*, დაშორებაა.
- <kbd>Enter</kbd> ადასტურებს — და როცა ველი საერთოდ არაფერს ასახელებს, როგორც ცარიელ საქაღალდეში, სადაც არასდროს ყოფილა რისი შევსებაც, ის ამბობს *ფაილი არ არის არჩეული* და ღია რჩება, ვიდრე დაიხუროს, თითქოს რამე აერჩიათ. <kbd>Esc</kbd> ან დაწკაპუნება სხვაგან აუქმებს, ფაილის ნამდვილ ბილიკზე აბრუნებს. ერთი <kbd>Esc</kbd>-ის დაჭერა საკმარისია: ის ხურავს სიას, ტოვებს ველს და ფოკუსს ჩანაწერს უბრუნებს, ვიდრე თითო ფენაზე თითო დაჭერას მოითხოვდეს.

ველი მორთულობის გარეშეა — არც ყუთი, არც ჩარჩო — ამიტომ ის თავად ბილიკის ტექსტივით იკითხება და აკრეფისას თავისით იზრდება.

ერთი დაჭერა **საცავის სახელზე** ხსნის, რისი გაკეთებაა შესაძლებელი იმაზე, რასაც ეს მონაკვეთი ასახელებს. **საცავისთვის, რომელშიც ხართ**: გახსენით ახალ ფანჯარაში, საცავების მართვა, აკოპირეთ, სად ცხოვრობს, აკოპირეთ მისი ID, აჩვენეთ ფაილმმართველში. **სხვა საცავისთვის**, მდებარეობების სიით მიღწეულისთვის, იგივე, გარდა ახალი ფანჯრისა — რომელიც *ამ* საცავს გახსნიდა და არა იმას — პლუს ერთი, რასაც მხოლოდ საცავი, რომელშიც არ ხართ, გთავაზობთ: **ამ საცავის გახსნა**. ის Obsidian-ისთვის მისი ID-ით არის დასახელებული და არა საქაღალდის სახელით, რადგან ორ საცავს შეიძლება ერთი და იგივე ჰქონდეს. ადგილისთვის, რომელიც საერთოდ არ არის საცავი — თქვენი home საქაღალდე, მიმაგრებული დისკი — არ არის ID დასაკოპირებელი და არაფერია გასახსნელი, და მენიუ ამას იმით ამბობს, რომ არ სთავაზობს მათ.

ნაგულისხმევ (ნავიგაციის) რეჟიმში გახსნილ ჩანაწერს **არასდროს** გადაერქმევა სახელი და არსად გადადის.

- ბილიკი, რომელიც არსებულ ფაილზე მიდის, ხსნის მას.
- ბილიკი, რომელიც ჯერ არ არსებობს, უბრალოდ იქმნება, ნებისმიერ არარსებულ მშობელ საქაღალდესთან ერთად, და იხსნება. თითოეული ასე შექმნილი ფაილი და საქაღალდე ამის შესახებ შეტყობინებაში ამბობს — ახალი საქაღალდე სხვანაირად უხილავია, სანამ არ დაუწყებ ძებნას — და Obsidian-ის საკუთარი ურნა არასასურველის გაუქმებას ერთი კლავიშის დაჭერად აქცევს.
- **საცავის გარეთ ის მაინც ჯერ კითხულობს.** იქ იგივე შეცდომა სისტემურ საქაღალდეში წერს, სადაც არც შეტყობინება და არც Obsidian-ის ურნა დიდად არაფერს ნუგეშობს.

## <kbd>Ctrl</kbd> — ახალი ჩანართი და კოპირება გადატანის ნაცვლად

ჩანაწერი, **რომელიც საცავის შიგნით შეიქმნა, გადავიდა ან დაკოპირდა, ჩანს იქ, სადაც დაჯდა**, ფაილების ხეში, წამით მონიშნული Obsidian-ის აქცენტის ფერით — ხე არის ის ადგილი, სადაც მას შემდეგ დაუწყებ ძებნას, ამიტომ ის შენ წინ ჩნდება და არ რჩება საქაღალდეში, რომელიც შეიძლება ღიაც არ იყოს. დუბლირებაც ამის შესახებ ამბობს: ასლი ორიგინალს ძველ ადგილას ტოვებს და ასლს საკუთარ პანელში ხსნის, რაც სიტყვის გარეშე ადვილად ისე იკითხება, თითქოს არაფერი მომხდარა.

<kbd>Ctrl</kbd>-ის (macOS-ზე <kbd>Cmd</kbd>) დაჭერით სიიდან ფაილის არჩევისას, ან ბილიკზე <kbd>Enter</kbd>-ის დაჭერისას შედეგი ამ ჩანართის ნაცვლად **ახალ ჩანართში** მიდის:

| | ჩვეულებრივ | <kbd>Ctrl</kbd>-ით |
| --- | --- | --- |
| არსებული ფაილის არჩევა ან აკრეფა | იხსნება აქ | იხსნება ახალ ჩანართში |
| არარსებული ბილიკის აკრეფა | კითხულობს, მერე ხსნის აქ | კითხულობს, მერე ხსნის ახალ ჩანართში |
| ბილიკის დამტკიცება გადარქმევის/გადატანის რეჟიმში | ჩანაწერს იქ **გადააქვს** | იქ **აკოპირებს** და ასლს ახალ ჩანართში ხსნის |

მოდიფიკატორი Obsidian-ის საკუთარი წესით იკითხება, ამიტომ ის ზუსტად ისე იქცევა, როგორც ბმულზე ან ფაილების სტრიქონზე — შუა დაწკაპუნებაც „ახალ ჩანართს“ ნიშნავს, <kbd>Ctrl</kbd>+<kbd>Alt</kbd> — გაყოფას, ხოლო <kbd>Ctrl</kbd>+<kbd>Alt</kbd>+<kbd>Shift</kbd> — ახალ ფანჯარას.

კოპირება ზედგადაწერაზე უარს ამბობს, ზუსტად ისე, როგორც გადატანა — მათ შორის ჩანაწერის საკუთარ ბილიკზეც, სადაც კოპირების საგანი არაფერია. საცავის გარეთ ეს უარიც ხმამაღლა ითქმის.

ეს ყველაფერი მუშაობს **გახსნილი სიით** ისევე, როგორც მის გარეშე: გამონიშნულ სტრიქონზე მოდიფიკატორი იმ სტრიქონს ეხება, ხოლო როცა არაფერზე დგახარ — იმას, რაც აკრიფე.

## საცავის გარეთ დათვალიერება

**ეს ნაგულისხმევად გამორთულია.** ჯერ ჩართეთ პარამეტრებში **გარე ფაილებზე წვდომა** — საცავის გარეთ კითხვა და წერა ერთადერთი რამაა, რასაც ეს მოდული აკეთებს და თავად Obsidian არა, ამიტომ მასში შედიან და არა მისგან გამოდიან. გამორთულის დროს საცავის სახელი უბრალოდ თქვენს საცავს აჩვენებს ფაილებში და აქ არაფერი იხედება მის მიღმა.

**საცავის სახელზე** (ან 🏠 ხატულაზე, როცა *საცავის სახელის ჩვენება* გამორთულია) დაწკაპუნება ღულს გახსნის ადგილების და არა შიგთავსის. ველი, რომელიც იხსნება, ინახავს **მთელ ბილიკს, რომელზეც იმყოფებოდით, სრულად ჩაწერილს**, მონიშნული ადგილით, საიდანაც ის იწყება — ამიტომ სხვა ადგილის არჩევა ან მონიშნულის გადაწერა მხოლოდ ამ საწყის ნაწილს ცვლის და ბილიკის დანარჩენი ნაწილი წინ დარჩენილი გაქვთ. **დააჭირეთ სახელს მეორედ** — ორმაგი დაწკაპუნება — და მონიშვნა მთელზე ვრცელდება, ესეც აბსოლუტური ბილიკის ერთი მოძრაობით არჩევის გზაა და არა ხელით გავლისა. გადაიფიქრეთ და <kbd>Esc</kbd> რიგს ისეთივეს დაუბრუნებს, როგორიც იყო.

აქ აკრეფას ისევე სთავაზობენ ადგილის სახელის დანარჩენ ნაწილს, როგორც სხვაგან, და <kbd>Tab</kbd> **სვამს იმ ადგილს** — იმას, რომელზეც მიმართული ხართ, ან იმას, რომელსაც სახელი მხოლოდ ერთადერთი მნიშვნელობით შეიძლება გულისხმობდეს. სადაც რამდენიმე ადგილი კვლავ იმას იზიარებს, რაც აკრიფეთ, დაჭერა გასაყართან ჩერდება, როგორც ყველგან. ადგილზე მიმართვა აჩვენებს **იმ ადგილის საკუთარ ბილიკს**, სრულად მონიშნულს, რასაც მოსდევს თქვენი ჩანაწერის ბილიკი მხოლოდ იმდენად, რამდენადაც ის იქ ნამდვილად ვრცელდება — ეს ზუსტად ისაა, რასაც მისი არჩევა მოგცემდა. ადგილი ეკრანზე ბილიკის შიგნით ნაბიჯი არაა, არამედ ის, საიდანაც მთელი ბილიკი ითვლება, ამიტომ იმისგან, სად იყავით, მის წინ არაფერი რჩება.

შემოთავაზებული ადგილები:

- **თქვენი სხვა საცავები**, წაკითხული Obsidian-ის საკუთარი რეესტრიდან, ბოლოს გახსნილი პირველი, თითოეული Obsidian-ის საკუთარი საცავის ხატულის ქვეშ — იმის, რომელსაც აპლიკაცია საცავის ბრძანებებისთვის იყენებს. საცავს, რომელიც უკვე გახსნილი გაქვთ, სამაგიეროდ სახლი ერგება: ეს ის ადგილია, საიდანაც რიგი ნაგულისხმევად იწყება და არა ადგილი, სადაც უნდა წახვიდეთ.
- **პირადი საქაღალდე**, თქვენი ანგარიშის სახელის ქვეშ, `~`-ით მონიშნული. Lucide-ს ტილდა არ აქვს, ამიტომ ამას თავად მოდული ხატავს Lucide-ის საკუთარ 24×24 ბადეზე იმავე ხაზის სისქით — ხატულა, რომელიც კომპლექტს აკლია და არა ტექსტური სიმბოლო, ხატულებს შორის ჩამჯდარი.
- **ფაილური სისტემის ძირი**, წარწერით `root` — უთარგმნელი, რადგან ყველა სისტემაზე მისი სახელი ესაა — და არა `/`, რომელიც მის შემდეგ მდგომ გამყოფთან ერთად ცარიელ ნაბიჯად წაიკითხებოდა.
- **მიერთებული დისკები**, თითოეული ტიპისთვის ხატულით იქ, სადაც ამის დადგენა იაფია: ქსელური რესურსები, ოპტიკური დისკები, დისკეტები და მოსახსნელი მატარებლები თავიანთს იღებენ; დანარჩენი ზოგად დისკს იღებს. Windows-ზე დისკები ჩანს როგორც `C:` ზოგადი ხატულით — ტომების სახელები და ზუსტი ტიპები WMI-ს საჭიროებს, რაც განზრახ არაა გაკეთებული.

სხვა საცავის არჩევა **Obsidian-ს მასზე არ გადაიყვანს.** ყველაფერი, რაც გახსნილი გაქვთ, გახსნილი რჩება; ბილიკი უბრალოდ იქ იწყებს დათვალიერებას. სწორედ ესაა მთელი აზრი იმისა, რომ ის ბილიკის ზოლზეა და არა გვერდითი ზოლის საცავის გადამრთველისთვისაა მიგდებული.

ის ასევე ჯდება **იმ ჩანაწერს, რომელზეც იმყოფებოდით, რამდენადაც ეს ადგილი ნამდვილად ვრცელდება, ამის ყველაზე ახლოს**.

- თუ არჩეული ადგილი *მოიცავს* ჩანაწერს — პირადი საქაღალდე ან ის, სადაც თქვენი საცავები ცხოვრობს — მისგან იმ ბილიკს იღებთ: აირჩიეთ `~` გახსნილი `takeaways.md`-ით და ველი წაიკითხავს `Vaults/your-vault/takeaways.md`-ს.
- თუ ეს ამის გვერდით მდებარე ადგილია — სხვა საცავი, სხვა დისკი — იმავე შედარებით ბილიკს ცდიან, იმდენად ღრმად, რამდენადაც ის ნამდვილად არსებობს. საცავები ხშირად ერთმანეთის თითქმის-ასლებია და ერთზე გადახტომის მიზეზი ხშირად იმავე ჩანაწერშია იქ.

ორივე შემთხვევაში რიგი არჩეულ ადგილას რჩება და **იმ ბილიკის პირველი საქაღალდე იხსნება მონიშნული**, იმავე ფორმით, რომელსაც საქაღალდეზე დაწკაპუნება იძლევა: ნაბიჯი, რომლის შეცვლაც ყველაზე მოსავალია, როცა სხვაგან გახტებით, ის ზედა ნაწილთან ყველაზე ახლოსაა, და ბილიკის დანარჩენი ნაწილი ხილული რჩება, სანამ მას ცვლით. არასდროს იწერება წინასწარ ის, რაც ნამდვილად დისკზე არაა.

**ჩანაწერის თქვენი საცავიდან *გარეთ* გადატანა ჯერ ეკითხება.** `fileManager`-ს ამ საზღვარზე ფაილის გავყოლა არ შეუძლია: ყოველი ჩანაწერზე მიმართული ბმული ხსნის შეწყვეტს, არაფერი მათ არ განაახლებს, და ჩანაწერი საცავის ინდექსს ტოვებს. ამიტომ გადატანა გადაწყვეტილებად სთავაზობენ და არა უარყოფილად ან ჩუმად შესრულებულად — ფანჯარა აღწერს, რა უჯდება ეს და რამდენი ჩანაწერია დაკავშირებული იმასთან, რომელსაც გადაატანთ. დაადასტურეთ და ის ნამდვილად გადადის: გარეთ კოპირდება, შემდეგ საცავიდან Obsidian-ის საკუთარი წაშლის მეშვეობით იშლება, ამიტომ ის აღდგება ზუსტად ისე, როგორც წაშლილი ჩანაწერი, და ჩავარდნა ერთ-ერთ საფეხურზე ჩანაწერს იქ ტოვებს, სადაც იყო. <kbd>Ctrl</kbd>-ის დაჭერა კვლავ მას გარეთ აკოპირებს ამის ნაცვლად, რასაც ეს პრობლემა არა აქვს. საპირისპირო მიმართულებით — გარე ფაილის საცავში *შემოტანა* — ჯერ არაა მიერთებული.

### გარე ფაილის გახსნა

ფაილური სისტემის დათვალიერება უკან **გახსნილ საცავშიც** დაგაბრუნებთ — ძირიდან, პირადი საქაღალდიდან, საიდანაც არ უნდა ცხოვრობდეს თქვენი საცავები. ასე მიწვდომილი ფაილი ჩვეულებრივი ჩანაწერია, ამიტომ ისეთივედ იხსნება: ნამდვილი რედაქტორი, ბმულები და უკუბმულები, და რიგი საცავის ძირზე დგმულ ბილიკს ბრუნდება. მხოლოდ ის ფაილები, რომლისთვისაც Obsidian-ს ხედი არა აქვს, წინასწარ ხედში რჩება, რადგან იქ წინასწარი ხედი უკეთესი პასუხია. სადაც წინასწარი ხედი ასეთ ჩანაწერს ისედაც აჩვენებს — ხელახლა გახსნილი სამუშაო სივრცის შემთხვევაში, ვთქვათ — მისი ზედა ხაზი გთავაზობთ **გახსნა *(საცავი)*-ში**-ს, რაც იმავე შემოთავაზებას იძლევა, რასაც ხელით გახსნა.

Obsidian-ის რედაქტორი მხოლოდ საცავის შიგნით მდებარე ფაილებზე მუშაობს, ამიტომ გარე ფაილი **ვერ** გაიხსნება ნამდვილ ჩანაწერად ბმულებით, უკუბმულებით და დანარჩენით — ეს აპლიკაციის და არა ამ მოდულის შეზღუდვაა. ერთის არჩევა სამაგიეროდ ხსნის **წინასწარ ხედს**, მხოლოდ წასაკითხად, სანამ სხვას არ იტყვით:

| ტიპი | ჩანს როგორც |
| --- | --- |
| `.md`, `.markdown` | დარენდერებული Markdown |
| `.html`, `.htm`, `.xhtml` | დარენდერებული გვერდი |
| სურათები, ხმა, ვიდეო, PDF | ჩაშენებული დამკვრელი/მაჩვენებელი |
| ნებისმიერი სხვა **ტექსტური** ფაილი (`.json`, `.css`, `.log`, `.txt`, …) | სიტყვასიტყვითი უბრალო ტექსტი |
| ორობითი ფორმატები მაჩვენებლის გარეშე (`.zip`, `.exe`, …) | გადადის *ნაგულისხმევ პროგრამაში გახსნაზე* |

მაჩვენებელს ფაილის ორი წაკითხვა აქვს და რადგან ისინი ერთმანეთს გამორიცხავენ, მხოლოდ ის ჩანს, რომელზეც **გადახვიდოდით**:

| | რას აკეთებს | ნაგულისხმევი |
| --- | --- | --- |
| **ნახვა Markdown-ად** | ფაილს ჩანაწერად რენდერავს, მხოლოდ წასაკითხად | `.md`, `.markdown` |
| **ნახვა როგორც გვერდი** | ფაილს რენდერავს იმ გვერდად, რაც არის, მხოლოდ წასაკითხად | `.html`, `.htm`, `.xhtml` |
| **რედაქტირება ტექსტად** | წყარო, რედაქტირებადი | ყველა დანარჩენი |

საცავის გარეთ **რედაქტირება ტექსტად** იმავდროულად ის დაჭერაა, რომელიც მხოლოდ-წაკითხვას ხსნის — რეჟიმი და ნებართვა ერთი მოძრაობაა და არა ორი ღილაკი, რომლებზეც უნდა იფიქრო. ის წითლდება **ყოველთვის, როცა მისი დაჭერა მოხსნიდა მხოლოდ-წაკითხვას**, ადგილზე რედაქტირებას ამზადებთ თუ პირდაპირ დარენდერებული ხედიდან მოდიხართ; საცავის შიგნით გასახსნელი არაფერია, ამიტომ ის უბრალო რჩება. **ნახვა Markdown-ად** მსუბუქ აქცენტურ ელფერს იღებს — იმავეს, რომელსაც Obsidian შერჩეულ ტექსტს აძლევს — რაც მას მოქმედებისკენ მოწოდების ნაცვლად უკან დასაბრუნებელ გზად მონიშნავს.

რადგან ღილაკი *რედაქტირებას* მიჰყვება და არა უხეშ რეჟიმს, ტექსტურ ხედში მხოლოდ-წაკითხვის მდგომარეობაში მჯდომი ფაილიც კვლავ სთავაზობს **რედაქტირება ტექსტად**-ს: სწორედ ეს დაჭერა ამზადებს მას. ფაილი, რომელშიც ვერასდროს აკრეფ — შემოკლებული ან წაუკითხავი — სამაგიეროდ ამბობს **ნახვა ტექსტად**, რადგან დაჭერას მხოლოდ ამის მოცემა შეუძლია.

ნაგულისხმევები სასარგებლოდაა შერჩეული და არა სიტყვასიტყვით: `#` shell-სკრიპტში კომენტარია და არა სათაური, ამიტომ `.log`-ის Markdown-ად რენდერი მას ჩუმად ჩაყლაპავდა. ორივე ნაგულისხმევი შეიძლება ფაილობრივად გადაიფაროს და არჩევანი ფურცლის ისტორიაში ხვდება, ამიტომ უკან/წინ და ხელახლა გახსნილი სამუშაო სივრცე მას ინახავს — ბევრი ჩანაწერი `.txt` ფაილებში ცხოვრობს და ბევრი `.md` ფაილი წყაროდ უფრო ადვილად იკითხება.

#### რისი გაკეთება შეუძლია HTML გვერდს

არაფრის. გვერდი ჩვენებულია ჩარჩოში **ყოველგვარი ნებართვის გარეშე** — არც სკრიპტები, არც ფორმები, არც ნავიგაცია, არც საკუთარი წყარო — და შიგთავსის პოლიტიკა, რომელიც მას ქსელთან წვდომას სულაც არ ანიჭებს. ეს არაა სიფრთხილე თავისთავად: ჩვეულებრივად ჩატვირთული ადგილობრივი გვერდი ამ ფანჯარას თავის წყაროდ გაუზიარებდა, ეს ფანჯარა კი Obsidian-ია, ამიტომ ჩამოტვირთულ HTML ფაილში სკრიპტი თქვენი აპლიკაციის შიგნით, თქვენი აპლიკაციის მისწვდომობით, გაშვებული აღმოჩნდებოდა.

ეს რასაც ხდის, ის, რასაც გვერდი *აკეთებს*, არის; ის, რასაც ინარჩუნებს — ყველაფერს, რაც გვერდი *არის*. ფაილის გვერდით მდებარე სტილების ფაილები და სურათები იკითხება და ჩარჩოში გადადის, ამიტომ შენახული გვერდი კვლავ თავს ჰგავს. მითვისებები, რომლებიც გვერდის საკუთარი საქაღალდის გარეთ მიმართავს, და მითვისებები ვებში ყველგან, ზუსტად ისე რჩება, როგორც ჩაწერილია, და უბრალოდ არ ჩატვირთდება — ადგილობრივმა ფაილმა ჩუმად სერვერს ვერ ეტყვის, რომ გახსენით.

სკრიპტები **მოცილებულია** და არა უბრალოდ დაბლოკილი, ამიტომ გვერდი, რომელსაც ხედავთ, და წყარო, რომელზეც შეგიძლიათ გადასვლა, ერთი ცხადი გზით განსხვავდება და არა იმით, ჩარჩომ რა ჩუმად არ გაუშვა. გვერდის შიგნით ბმულები არაფერს აკეთებენ. როცა ნამდვილი რამ გინდათ — სკრიპტები, ქსელი და დანარჩენი — *ნაგულისხმევ პროგრამაში გახსნა* მას თქვენს ბრაუზერს გადასცემს, რაც ამისთვის სწორი ხელსაწყოა.

**თქვენი საცავის ფაილები მაშინვე რედაქტირებადია**, ყოველგვარი გახსნის გარეშე: *რედაქტირება ტექსტად* ნამდვილი რედაქტორია და აკრეფისას უკან წერს.

**რედაქტირება გადართვის მიღმაც ახსოვს.** *ნახვა Markdown-ად*-ზე გადასვლა მას აჩერებს — სტატიკურ რენდერში ასაკრეფი არაფერია, ხოლო Live Preview-ს Obsidian-ის საკუთარი რედაქტორი სჭირდება, რომელიც მხოლოდ საცავის შიგნით მდებარე ფაილებისთვის არსებობს — ამიტომ, სანამ იქ ხართ, არაფერი აცხადებს, რომ რედაქტირებთ. *რედაქტირება ტექსტად*-ზე დაბრუნება იქიდან აგრძელებს, სადაც შეჩერდით.

**საცავის გარეთ მდებარე ფაილები მხოლოდ წასაკითხად იხსნება და *რედაქტირება ტექსტად* ამას ხსნის.** ეს დაჭერა მთელი კარიბჭეა: სანამ ის არ მოხდება, იქ არაფერი იწერება. შემდეგ ფაილი აკრეფისას ინახება, ზუსტად ისე, როგორც საცავში მდებარე; სტატუსის ხაზი კი კეტიდან ფანქარზე იცვლება. ეს გახსნა მოიცავს იმ ერთ ფაილს იმ ერთ ჩანართში — სხვა ფაილზე გადასვლა ხელახლა კეტავს და ის განზრახ არ ინახება ჩანართის ისტორიაში, ამიტომ ხელახლა გახსნილი სამუშაო სივრცე არასდროს ბრუნდება უკვე მომზადებული ჩაწერით სისტემურ ფაილზე, რომლის გახსნაც არ გახსოვთ.

**შემოკლებული ფაილები მაინც მხოლოდ წასაკითხად რჩება** — ეკრანზე არსებულის შენახვა ზღვარს მიღმა დარჩენილ ყველაფერს გადააგდებდა, ამიტომ ღილაკი შეთავაზებისა და უარის თქმის ნაცვლად საერთოდ არ სთავაზობს. იგივე ეხება ფაილს, რომლის წაკითხვაც ვერ მოხერხდა: ცარიელი პანელის გარდა უკან ჩასაწერი არაფერია.

თუ ჩაწერა ვერ მოხერხდა — მხოლოდ-წაკითხვის მიმაგრება, ფაილი, რომელიც თქვენი არაა — სისტემის საკუთარი მიზეზი შეტყობინებაში ჩანს.

ძალიან დიდი ფაილები შემოკლებულად ჩანს და სტატუსის ხაზიც ამას ამბობს, ნაცვლად იმისა, რომ თავად აღმოაჩინოთ — სხვა პირობების გვერდით და არა ღილაკებს უკან, რადგან ესეც ფაქტია ფაილის შესახებ, დანარჩენივით. ზღვრები ცოცხალ რენდერერთან ისაზღვრება და არა გამოცნობით — მეგაბაიტი ტექსტის ერთ პანელში განლაგება Obsidian-ის რენდერის პროცესს ადგილზევე კლავს, ხოლო Markdown ბაიტზე რამდენჯერმე მეტი ჯდება, ვიდრე უბრალო ტექსტი, ამიტომ ორივეს ცალკე ზღვრები აქვს და ერთი უზარმაზარი ხაზიც კი მოკლდება მაშინაც, როცა ფაილი მთლიანობაში პატარაა.

**სტატუსის ხაზები წარწერებია, ახსნა კი მინიშნებაა.** ყოველი ხაზი იმდენივე სიტყვით ამბობს, რაც სიმართლეა, რამდენიც საჭიროა — *საცავის გარეთ*, *ამ ტიპის ფაილისთვის რედაქტორი არაა*, *შემოკლებულია — ფაილი ძალიან დიდია* — რადგან მათ გვერდით მდგომი ღილაკები უკვე ამბობენ, რა მდგომარეობაშია ფაილი. ერთზე კურსორის მიტანა წინადადებას იძლევა: რატომ ვერ ხსნის Obsidian მას ჩანაწერად, სხვა შემთხვევაში რა მოუვიდოდა ამ ტიპის ფაილს, რა დაგიჯდებათ შემოკლება.

ეს ეხება თქვენი საცავის **შიგნით** მდებარე ფაილებსაც. Obsidian ნებისმიერ გაფართოებას, რომლისთვისაც ხედი არ აქვს, პირდაპირ სამუშაო მაგიდის ნაგულისხმევ პროგრამას გადასცემს — ამიტომ თქვენს საცავში მდებარე `.txt` ან `.json` Obsidian-ს სულ დატოვებდა. ისინი ახლა იმავე მაჩვენებელში იხსნება, ნარინჯისფერი რგოლით, რადგან „გახსენი ის Obsidian-ში“ სწორედ ესაა, რაც ითხოვეთ — და რადგან საცავის ფაილებია, იქ ისინი ყოველგვარი გახსნის გარეშე რედაქტირებადია. ორობითი ფაილები მაჩვენებლის გარეშე Obsidian-ის ქცევას ინარჩუნებენ; საჩვენებელი არაფერია.

წინასწარი ხედი იხსნება **იმ ჩანართში, სადაც იყავით**, ამიტომ უკან/წინ თქვენ იმ ჩანაწერს დაგიბრუნებთ, საიდანაც მოხვედით; ახალი ჩანართისთვის დააჭირეთ <kbd>Ctrl</kbd>-ს, ისევე როგორც ყველგან. სათაურის ზოლი გარე ფაილის ბილიკს აჩვენებს მანამ, სანამ ის ღიაა, ამიტომ დათვალიერება იქიდან შეგიძლიათ განაგრძოთ.

შიგთავსის ზემოთ მდგომი წყნარი ხაზი გამოსავლებს გთავაზობთ:

- **გახსნა *(საცავი)*-ში** — ჩანს, როცა ფაილი თქვენი სხვა საცავებიდან ერთს ეკუთვნის. მას Obsidian-ის საკუთარ URI-დამმუშავებელს გადასცემს, რომელიც იმ საცავის ფანჯარას იმ ჩანაწერით ხსნის, როგორც ნამდვილ რედაქტირებად ჩანაწერს. ეს ფანჯარა ზუსტად ისე რჩება, როგორც იყო; თქვენ ქვეშ არაფერი გადაერთვება.
- **ნახვა Markdown-ად** / **ნახვა როგორც გვერდი** / **რედაქტირება ტექსტად** — ამ ფაილის ორი წაკითხვა; ბოლო ასევე ხსნის მხოლოდ-წაკითხვას საცავის გარეთ.
- **ნაგულისხმევ პროგრამაში გახსნა** — ფაილს თქვენი სამუშაო მაგიდის ნაგულისხმევ პროგრამას გადასცემს, ორობითი ფორმატების ჩათვლით, რომელთა ჩვენებაც ამ მაჩვენებელს არ შეუძლია. ფორმულირებული ზუსტად ისე, როგორც Obsidian-ის საკუთარი ჩანაწერი იმავე მოქმედებისთვის, რადგან ეს იმავე მოქმედებაა.

მაჩვენებელი **მარჯვენა ღილაკს** ასევე პასუხობს: ტექსტური რედაქტორის შიგნით *ამოკვეთა* / *კოპირება* / *ჩასმა* / *ყველას მონიშვნა*-თ, ხოლო სხვაგან — ფაილის საკუთარი მენიუთ. Obsidian-ის სამწერტილიანი მენიუ სათაურში ამ მენიუსაც ატარებს — საცავის გარეთ ის სხვა შემთხვევაში *გაყოფა მარჯვნივ*-ისა და *გაყოფა ქვემოთ*-ის გარდა არაფერს შემოგთავაზებდა.

თქვენი საცავის გარეთ არაფერი იწერება, თუ ჯერ *რედაქტირება ტექსტად*-ს არ დააჭერთ. სრული განმარტებისთვის იხილეთ README-ის განყოფილება [საცავის გარეთ](README.ka.md#საცავის-გარეთ).

**ორივე რგოლი დამოუკიდებელია, და ორივემ ერთდროულადაც შეიძლება იმოქმედოს** — გარე `.json` საცავის გარეთაცაა *და* ისეთი ტიპისაც, რომლისთვისაც Obsidian-ს რედაქტორი არ აქვს. მაყურებელში ისინი ცალკეულ ხაზებად ჩნდებიან, თითოეული მხოლოდ საკუთარ ფაქტს აღნიშნავს. ბილიკის ზოლზე წითელი იმარჯვებს, სადაც ორივე მოქმედებს, ვინაიდან ორი რგოლი მხოლოდ ხმაური იქნებოდა. წითელი *ტექსტი* სულ სხვა რამაა: ის ეხება იმას, რასაც კრეფთ და არა იმას, სად არის მიმართული მწკრივი, ასე რომ ის შეიძლება გამოჩნდეს ორივე რგოლის შიგნით ან საერთოდაც არცერთის.

ნარინჯისფერი დონე განზრახ ვიწროა. რეგისტრირებული ტიპები (Markdown, canvas, სურათები, PDF, აუდიო, ვიდეო) სათანადოდ განიხილება და არაფერს იღებენ. ბინარულმა ფაილებმაც არაფერი იციან — თქვენ `.zip`-ს შემთხვევით არ აგევსებათ. დარჩენილი ზუსტად საფრთხეა: `.json`, `.css` ან `.log`, რომელიც **Show all file types**-მა ხილულად აქცია. სია განზრახ უფრო ფართოა: იქ ყველაფერი, რაც ჩანაწერი არაა, ნარინჯისფერია — იხილეთ [როგორ ფერდება სიის ჩანაწერები](#როგორ-ფერდება-სიის-ჩანაწერები).

## გადატანის/გადარქმევის რეჟიმი

ფანქრის ღილაკი სათაურის ზოლის ყველაზე შორეულ მარჯვენა კუთხეში — ხედვის-რეჟიმის ღილაკის გვერდით, თავიანთი ღილაკების ტოლი ზომით — რთავს გადატანის/გადარქმევის რეჟიმს. საცავის გარეთ მის ადგილას წითელი საკეტი დგას, სანამ მასზე არ დააჭერთ; იხილეთ [საცავის გარეთ წერა](#საცავის-გარეთ-წერა). ამის შემდეგ სათაურის ზოლი აქცენტის ფერშია ჩარჩოებული, ზუსტად ისე, როგორც File Explorer-ში გადარქმევისას. იგივე დაწკაპუნებები და ღილაკები ახლა Obsidian-ის `fileManager.renameFile`-ის მეშვეობით ადასტურებენ გადატანას ან გადარქმევას, ასე რომ ჩანაწერზე ყველა ბმული მისდევს.

გადარქმევისას:

- მიმდინარე ფაილის სახელი ჩამაგრებულია ყოველი საქაღალდის სიაში, ასე რომ ჩანაწერის გადატანა მისი გადარქმევის გარეშე ერთი დაწკაპუნებაა.
- სამიზნე საქაღალდეში უკვე დაკავებული სახელები **წითელია** — საქაღალდე, რომელსაც უკვე აქვს ეს სახელი, და ფაილიც ამ სახელის — ასე რომ შეჯახება ჩანს, სანამ აირჩევთ. მათი არჩევა მაინც შესაძლებელია: იხილეთ ქვემოთ.
- შენატანი პირდაპირ მოწმდება Obsidian-ის საკუთარი გადარქმევის წესებით — იგივე დასაშვები სიმბოლოები, იგივე შეტყობინებები, იგივე წითელი კარნახი, რასაც ფაილთა ხისში გადარქმევისას იღებთ — ასე რომ დაუშვებელი სახელი აკრეფისთანავე აღინიშნება და ვერ დადასტურდება.
- სათაურის ზოლის გარეთ დაწკაპუნება, ან სათაურის ფოკუსის დაკარგვა, გადარქმევის რეჟიმს ამთავრებს.

### დაკავებული სახელი

გადატანა ან გადარქმევა უკვე არსებულ სახელზე **ერიდება უარის თქმას და კითხულობს
ამის ნაცვლად.** იხსნება დიალოგი ორი ბილიკით, თქვენ მიერ რედაქტირებადით: სად
მიდის თქვენი ფაილი, და სად მიდის ის ფაილი, რომელიც გზაზე დგას — წითელი, სანამ
ეს ჯერაც დაკავებულია. ორივე ბილიკიც ისე იხატება, როგორც ბილიკის ზოლი ხატავს
ერთს, განსხვავებული ნაწილები ფერადადაა, ბოლოს კი მოკლდება, ასე რომ გრძელი
ბილიკიც აჩვენებს, რა იცვლება.

ორივე ველს აქვს სია. მეორე ჩვეულ გამოსავლებს იჭერს:

- **ადგილების გაცვლა** — ის თქვენი ფაილის ძველ საქაღალდეში მიდის, საკუთარი სახელით.
- **სახელების გაცვლა** — ის თავის ადგილას რჩება და თქვენი ფაილის ძველ სახელს იღებს.
- **ორივეს გაცვლა** — ის თქვენი ფაილის ძველ ბილიკს იღებს.
- `-1`, `-bak` და `-old` თავისი სახელის გვერდით.
- ორივე ფაილის ორი სახელი.

პირველი სია სთავაზობს, სად მიდიოდა თქვენი ფაილი, **დარჩენა თავის ადგილას**,
საკუთარ სახელს სამიზნე საქაღალდეში, და `-1`, `-bak` და `-old` მის გვერდით.
გამოსავალი, რომლის ბილიკიც დაკავებულია, ნაცრისფერია და ვერ ირჩევა. ერთის
არჩევა **მხოლოდ ავსებს ველს** — მისი რედაქტირება მაინც შეგიძლიათ — და **გადატანა**
ორივეს გადააქვს, ბმულებთან ერთად; **გაუქმება** არაფერს გადააქვს. სიიდან
დაკავებული სახელის არჩევა იმავეს ითხოვს, ისევე როგორც ჩანაწერის საქაღალდეზე
დაგდება, რომელსაც უკვე აქვს იმავე სახელის ჩანაწერი.

## ერთი კლავიში ორივე გადარქმევისთვის

გადარქმევის ბრძანება (ნაგულისხმევად <kbd>F2</kbd>, ან რაზეც არ უნდა გქონდეთ ხელახლა მიბმული) **მონაცვლეობს** Obsidian-ის inline-title-ის გადარქმევასა და ამ დამატების სათაურის ბილიკის ზოლს შორის. თუ Obsidian-ის inline title გამორთული გაქვთ, სათაურის ბილიკის ზოლი ერთადერთი სამიზნე ხდება, ასე რომ კლავიში არასდროს "არაფერს" აკეთებს.

ბილიკის ზოლში ის იხსნება **სახელზე გაფართოების გარეშე** — ეს თითქმის ყოველთვის ის რედაქტირებაა, რასაც გადარქმევა წარმოადგენს, და იგივეს აკეთებს სახელზე დაწკაპუნებაც. დააჭირეთ ისევ და ის აკეთებს იმას, რასაც იქ <kbd>Tab</kbd> გააკეთებდა: სახელზე ეს არის შემდეგი საფეხური — სახელი გაფართოებით, ბილიკი თქვენი საცავის საქაღალდიდან, ბილიკი სისტემის root-იდან; რაღაცის აკრეფისას ის ავსებს მას, როგორც <kbd>Tab</kbd>-ი აკეთებს.

**ციკლი იკეტება სათაურთან.** ხუთი დაჭერა გატარებთ მთელ წრეზე — inline title, სახელი, სახელი გაფართოებით, ბილიკი თქვენი საცავიდან, ბილიკი სისტემის root-იდან — და მეექვსე ისევ inline title-ია. სწორედ ეს დაჭერაა ერთადერთი, რომელიც <kbd>Tab</kbd>-ისგან განსხვავდება — რომელიც ბილიკის დასაწყისში ბრუნდება; ხოლო მეშვიდე მიდის იქ, სადაც <kbd>Tab</kbd>-ის შემობრუნება მიდის: საცავის root-ში, სადაც მთელი ბილიკია ველში ჩაწერილი და მისი პირველი საქაღალდი მონიშნული. ასე რომ, ყოველ საფეხურზე, სადაც <kbd>Tab</kbd> აღწევს, კლავიშიც აღწევს.

**Focus the path bar** ბრძანება იმავეს აკეთებს ველის შიგნით — რასაც <kbd>Tab</kbd> გააკეთებდა — და იქ, სადაც <kbd>Tab</kbd> შემოტრიალდებოდა, ის კურსორს ნაცვლად ბანკნოტს უბრუნებს. მისი შემდეგი დაჭერა შემოტრიალებაა: საცავის root, პირველი საქაღალდი მონიშნული.

**უკვე გახსნილ ველში** კლავიში მას იმ ადგილას აქცევს გადარქმევად, სადაც დგას — ტექსტის, კურსორისა და მონიშვნის შენარჩუნებით — და **Focus the path bar** იმავე გზით იღებს გადარქმევას მისგან უკან. **ნებისმიერი სხვა რამ**, დაჭერილი თუ დაწკაპუნებული ამ დაჭერებს შორის, თავიდან იწყებს ორივე ციკლს, ასე რომ დაჭერა, თუ რედაქტირებას ეხლახან ასრულებდით, არასდროს ეცემა წინანდელ საფეხურზე.

საცავის გარეთაც კლავიში მუშაობს — იქ inline title არ არსებობს, ასე რომ პირველი დაჭერა პირდაპირ ბილიკის ზოლში მიდის.

ეს მუშაობს `workspace:edit-file-title` ბრძანების შემოხვევით და არა კლავიშის მიტაცებით, ამიტომ მალსახმობის ხელახლა მიბმაც და ბრძანების პალიტრიდან გაშვებაც უცვლელად მუშაობს.

- სია აჩვენებს 1,000-მდე ჩანაწერს — ეს ათჯერ მეტია Obsidian-ის საკუთარ ლიმიტზე. როცა საქაღალდეს მეტი აქვს, ბოლო სტრიქონი ამბობს, რამდენი გამოტოვეს; გააგრძელეთ აკრეფა სიის შესავიწროებლად.
- წერტილით დაწყებული ფაილები და საქაღალდეები ჩნდება მხოლოდ მაშინ, თუ ამ დამატების **Show dot files** პარამეტრი ჩართულია.

## ხატულების შეცვლა

Lure რენდერავს სამ ხატულას: საცავის-root-ის ხატულას (როცა **Show vault name** გამორთულია), გადატანის/გადარქმევის გადამრთველს, და ბოქლომს, რომელიც მის ადგილს იკავებს, სანამ საცავის გარეთ წერა ჩაკეტილია. ყველა შესაცვლელია თემიდან ან CSS ნაწყვეტიდან — დააყენეთ შემცვლელი ნიშანი და დამალეთ ჩაშენებული ერთ წესში:

```css
.lure-vault-icon {
	--lure-icon-glyph: "🏠";
	--lure-icon-svg: none;
}

.lure-rename-btn {
	--lure-icon-glyph: "✎";
	--lure-icon-svg: none;
}

/* ყოველთვის მხოლოდ დახურული ჩანს: მისი გახსნა სლოტს გადარქმევის გადამრთველს გადასცემს. */
.lure-unlock-btn {
	--lure-icon-glyph: "🔒";
	--lure-icon-svg: none;
}
```

`--lure-icon-glyph` იღებს ყველაფერს, რაც CSS-ის `content`-ში დასაშვებია, ამიტომ `url(...)` სურათისთვისაც ისევე მუშაობს, როგორც ტექსტური ნიშნისთვის ან ემოჯისთვის. დატოვეთ `--lure-icon-svg` ხელუხლებელი, თუ გინდათ Lucide-ის ხატულა შეინარჩუნოთ და თქვენი ნიშანი მის გვერდით დახატოთ.
