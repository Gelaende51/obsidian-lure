## ბილიკი სათაურის ზოლში

ჩანაწერის სრული ბილიკი საცავში ცვლის შიშველ ფაილის სახელს ხედის სათაურის ზოლში — იმ ზოლში, რომელიც ჩანართების რიგის ქვემოთაა და უკან/წინ ღილაკებსაც ინახავს.

ამ რიგში ორ რამეზე შეიძლება დაწკაპუნება და **საქაღალდის სახელი ხსნის სიას** განსაზღვრავს, რომელი რას აკეთებს:

| | საქაღალდის სახელი | მის შემდეგ მდგომი გამყოფი |
| --- | --- | --- |
| **ჩართული** (ნაგულისხმევი) | ირჩევს იმ საქაღალდეს რედაქტირებისთვის | ხსნის საქაღალდეს |
| **გამორთული** | ხსნის საქაღალდეს | ჩადის იმ საქაღალდეში |

„ხსნის საქაღალდეს“ ნიშნავს იმას, რასაც ამ მონაკვეთზე დაწკაპუნება აკეთებს სუფთა Obsidian-ში. თუ იქ არცერთი მოდული არ უსმენს, საქაღალდე ჩანს გვერდით ზოლში, ფაილებში — გამოკვეთილი და გაშლილი, რომ შიგთავსი დაინახოთ.

დაყენებული [Folder notes](obsidian://show-plugin?id=folder-notes)-ით იგივე დაწკაპუნება სამაგიეროდ ხსნის იმ საქაღალდის ჩანაწერს. ეს ერთადერთი საქაღალდე-ჩანაწერის მოდულია, რომელიც აღმოჩნდა, რომ სათაურის ბილიკს ითვისებს; [Folder Note](obsidian://show-plugin?id=folder-note-plugin) და [create folder notes with dropdown](obsidian://show-plugin?id=create-folder-notes-with-dropdown) მართავენ საქაღალდის ჩანაწერებს, მაგრამ ბილიკზე დაწკაპუნებას არ უსმენენ, ამიტომ მათთან გამყოფი ჩვეულებრივ აჩვენებს საქაღალდეს. იხილეთ [თავსებადობა](../compatibility.md#verified-against).

გამყოფს **ხაზი მხოლოდ მაშინ ესმება, როცა მის წინ მდგომ საქაღალდეს ნამდვილად აქვს საქაღალდის ჩანაწერი**, ამიტომ ხაზი დაპირებაა, რომ იქ გასახსნელი რაღაც არის. ყოველ გამყოფზე მაინც შეიძლება დაწკაპუნება — ხაზის გარეშე მდგომი აჩვენებს და შლის თავის საქაღალდეს გვერდით ზოლში, რასაც კურსორი მაინც აღნიშნავს. ხაზი იმავე წამს ტოვებს საქაღალდის სახელს: როცა შენაცვლება ჩართულია, სახელი ხსნის სიას, ამიტომ მისი ჩანაწერზე ბმულად მონიშვნა ტყუილი იქნებოდა.

**გადარქმევის/გადატანის რეჟიმი ორივეს გადაფარავს**, რასაც უნდა ამბობდეს პარამეტრი: სანამ გადატანა დაუსრულებელია, რიგში არაფერი ხსნის საქაღალდეს, რადგან გახსნა გადატანას მიატოვებდა. საქაღალდის სახელები რედაქტირებისთვის შეირჩევა, გამყოფები კი ჩადიან — ორივე დანიშნულების არჩევის გზაა — და ხაზი ქრება, რომ აჩვენოს: გახსნა შეჩერებულია.

**საცავის ძირი** ერთადერთი მონაკვეთია, რომელიც ბილიკის მონაკვეთი არაა. მას მშობელი არ ჰყავს, საიდანაც დებს გვერდით მდგომებს ჩამოთვლიდა, ამიტომ ის სამაგიეროდ ხსნის [ადგილების სიას](#საცავის-გარეთ-დათვალიერება) — თქვენს სხვა საცავებს, პირად საქაღალდეს, ფაილური სისტემის ძირს და მიერთებულ დისკებს.

## მონაკვეთზე დაწკაპუნება: მისი გვერდით მდგომით შეცვლა

საქაღალდის სახელზე დაწკაპუნება ტექსტურ ველში ირჩევს **სწორედ იმ საქაღალდის სახელს** და ხსნის **ერთი დონით ზემოთ** მდგომი საქაღალდის — მისი მშობლის — სიას. აკრეფა ან ჩანაწერის არჩევა ამ საქაღალდეს ცვლის გვერდით მდგომით და მის ქვემოთ ყველაფერს ხელუხლებლად ტოვებს, ამიტომ `Projects/2026/Kickoff.md` → დააწკაპუნეთ `2026`-ზე → აირჩიეთ `2025` და მიიღებთ `Projects/2025/Kickoff.md`-ს.

**ჩანაწერის სახელზე** დაწკაპუნება იმავე წესით მუშაობს მისივე საქაღალდის მიმართ და ირჩევს ფაილის სახელს **გაფართოების ჩათვლით** — ჩანაწერის გადარქმევა ან სხვაგან მიმართვა ჩვეულებრივ იმის შეცვლასაც ნიშნავს.

საქაღალდეზე დაწკაპუნებამ უკვე შეარჩია ერთი მონაკვეთი, ამიტომ **კიდევ ერთი დაწკაპუნება** არჩევანს მთელ ხაზზე შლის — იმ საქაღალდეზე *და* ყველაფერზე მის ქვემოთ — და შემდეგ აკრეფა ბილიკის დანარჩენს ერთბაშად ცვლის. ერთნაირად მუშაობს ნავიგაციაშიც და გადარქმევის/გადატანის რეჟიმშიც.

ეს მოქმედებს მხოლოდ როგორც იმ დაწკაპუნების გაგრძელება, რომელმაც ველი გახსნა. როგორც კი ველს გამოიყენებთ, ის სხვა ნებისმიერი ტექსტური ველივით იქცევა: დაწკაპუნება კურსორს სვამს, ორმაგი დაწკაპუნება სიტყვას იღებს, სამმაგი — ხაზს.

ასეა თუ ისე, ბილიკის დანარჩენი ველის გარშემო ხილული რჩება — მის წინ ფირფიტებად, მის შემდეგ კი შეურჩეველ ტექსტად — ამიტომ სრული ბილიკი სათაურიდან არასდროს ქრება. აკრიფეთ არჩევანის შესაცვლელად, ან დააჭირეთ <kbd>End</kbd> / <kbd>→</kbd>, რომ შეინარჩუნოთ და იქიდან განაგრძოთ რედაქტირება. სია მთელ საქაღალდეს აჩვენებს, რაც არ უნდა იყოს წინასწარ ჩასმული; გაფილტვრას მხოლოდ მაშინ იწყებს, როცა ნამდვილად აკრეფთ.

## გამყოფით ჩასვლა

გამყოფზე დაწკაპუნება (როცა **საქაღალდის სახელი ხსნის სიას** გამორთულია) ჩადის მის წინ მდგომ საქაღალდეში: სია აჩვენებს *სწორედ იმ* საქაღალდის შიგთავსს, ბილიკის დანარჩენი კი ველში შერჩეული იხსნება. საქაღალდის არჩევა მას ბილიკის კვალს ამატებს და მაშინვე ხსნის შემდეგ სიას, ამიტომ ხის ჩამოვლა დაწკაპუნებებით შეიძლება სათაურის რიგის დატოვების გარეშე.

## სიის ჩანაწერები ნამდვილი ფაილმმართველის სტრიქონებია

სიაში ყოველი ფაილი და საქაღალდე იქცევა ისე, როგორც მისი სტრიქონი ფაილებში:

- **მარჯვენა დაწკაპუნება** იმავე კონტექსტურ მენიუს იძლევა — საქაღალდეზე *ახალი ჩანაწერი* / *ახალი საქაღალდე*, ფაილზე *ახალ ჩანართში გახსნა* / *გადარქმევა...* / *წაშლა* — მათ შორის იმ ჩანაწერებსაც, რომლებსაც სხვა მოდულები ამატებენ ფაილის მენიუებში.
- **გადაათრიეთ** ჩანაწერი ნებისმიერ ადგილას, სადაც Obsidian ფაილს იღებს: რედაქტორში ბმულის ჩასასმელად, ფაილებში საქაღალდეზე გადასატანად, ჩანართების ზოლზე გასახსნელად.

მენიუს ფორმულირებები თავად Obsidian-ის თარგმანებიდან მოდის, ამიტომ ისინი ყველა ენაზე ემთხვევა აპლიკაციის დანარჩენ ნაწილს.

## ბილიკის აკრეფა

- ფირფიტების წინ ან შემდეგ **ცარიელ ადგილზე** დაწკაპუნება ხსნის ტექსტურ ველს, რომელშიც მთელი ბილიკია ჩასმული და სრულად შერჩეული — აკრიფეთ მასზე, ან ადგილზევე შეასწორეთ. (თავად ფაილის სახელზე დაწკაპუნება მხოლოდ ფაილის სახელს ირჩევს; იხილეთ ზემოთ.)
- აკრეფა მაშინ, როცა ფირფიტების კვალი ჩანს, ბოლო მონაკვეთს აქცევს პატარა ველად, მიმდინარე საქაღალდით შემოსაზღვრული ცოცხალი ავტოშევსებით.
- `/` ამტკიცებს მიმდინარე მონაკვეთს და მასში ჩადის.
- <kbd>Backspace</kbd> ცარიელ ველში ერთი ნაბიჯით უკან, მშობელ საქაღალდეში აბრუნებს და მის სახელს ხელახლა ხსნის კურსორით ბოლოში.
- <kbd>Enter</kbd> ამტკიცებს; <kbd>Esc</kbd> ან სხვაგან დაწკაპუნება აუქმებს და ფაილის ნამდვილ ბილიკს აბრუნებს.

ველი მორთულობის გარეშეა — არც ყუთი, არც ჩარჩო — ამიტომ ის თავად ბილიკის ტექსტივით იკითხება და აკრეფისას თავისით იზრდება.

## ნავიგაცია გახსნილ ფაილს არასდროს ეხება

ნაგულისხმევ (ნავიგაციის) რეჟიმში გახსნილ ჩანაწერს **არასდროს** გადაერქმევა სახელი და არსად გადადის.

- ბილიკი, რომელიც არსებულ ფაილს ემთხვევა, მას ხსნის.
- ბილიკი, რომელიც ჯერ არ არსებობს, ეკითხება *„შეიქმნას ახალი ფაილი?“*. დადასტურება ქმნის დაკლებულ მშობელ საქაღალდეებს და ფაილს; გაუქმება არაფერს არ აკეთებს.

მოდიფიკატორი Obsidian-ის საკუთარი წესით იკითხება, ამიტომ ის ზუსტად ისე იქცევა, როგორც ბმულზე ან ფაილების სტრიქონზე — შუა დაწკაპუნებაც „ახალ ჩანართს“ ნიშნავს, <kbd>Ctrl</kbd>+<kbd>Alt</kbd> — გაყოფას, ხოლო <kbd>Ctrl</kbd>+<kbd>Alt</kbd>+<kbd>Shift</kbd> — ახალ ფანჯარას.

კოპირება უარს ამბობს გადაწერაზე, ზუსტად ისე, როგორც გადატანა — მათ შორის თავად ჩანაწერის ბილიკზეც, სადაც კოპირებისთვის აზრიანი არაფერია.

## საცავის გარეთ დათვალიერება

**ეს ნაგულისხმევად გამორთულია.** ჯერ ჩართეთ პარამეტრებში **გარე ფაილებზე წვდომა** — საცავის გარეთ კითხვა და წერა ერთადერთი რამაა, რასაც ეს მოდული აკეთებს და თავად Obsidian არა, ამიტომ მასში შედიან და არა მისგან გამოდიან. გამორთულის დროს საცავის სახელი უბრალოდ თქვენს საცავს აჩვენებს ფაილებში და აქ არაფერი იხედება მის მიღმა.

**საცავის სახელზე** (ან 🏠 ხატულაზე, როცა *საცავის სახელის ჩვენება* გამორთულია) დაწკაპუნება შიგთავსის ნაცვლად ადგილების სიას ხსნის:

- **თქვენი სხვა საცავები**, წაკითხული Obsidian-ის საკუთარი რეესტრიდან, ბოლოს გახსნილი პირველი, თითოეული Obsidian-ის საკუთარი საცავის ხატულის ქვეშ — იმის, რომელსაც აპლიკაცია საცავის ბრძანებებისთვის იყენებს. საცავს, რომელიც უკვე გახსნილი გაქვთ, სამაგიეროდ სახლი ერგება: ეს ის ადგილია, საიდანაც რიგი ნაგულისხმევად იწყება და არა ადგილი, სადაც უნდა წახვიდეთ.
- **პირადი საქაღალდე**, თქვენი ანგარიშის სახელის ქვეშ, `~`-ით მონიშნული. Lucide-ს ტილდა არ აქვს, ამიტომ ამას თავად მოდული ხატავს Lucide-ის საკუთარ 24×24 ბადეზე იმავე ხაზის სისქით — ხატულა, რომელიც კომპლექტს აკლია და არა ტექსტური სიმბოლო, ხატულებს შორის ჩამჯდარი.
- **ფაილური სისტემის ძირი**, წარწერით `root` — უთარგმნელი, რადგან ყველა სისტემაზე მისი სახელი ესაა — და არა `/`, რომელიც მის შემდეგ მდგომ გამყოფთან ერთად ცარიელ ნაბიჯად წაიკითხებოდა.
- **მიერთებული დისკები**, თითოეული ტიპისთვის ხატულით იქ, სადაც ამის დადგენა იაფია: ქსელური რესურსები, ოპტიკური დისკები, დისკეტები და მოსახსნელი მატარებლები თავიანთს იღებენ; დანარჩენი ზოგად დისკს იღებს. Windows-ზე დისკები ჩანს როგორც `C:` ზოგადი ხატულით — ტომების სახელები და ზუსტი ტიპები WMI-ს საჭიროებს, რაც განზრახ არაა გაკეთებული.

სხვა საცავის არჩევა **Obsidian-ს მასზე არ გადაიყვანს.** ყველაფერი, რაც გახსნილი გაქვთ, გახსნილი რჩება; ბილიკი უბრალოდ იქ იწყებს დათვალიერებას. სწორედ ესაა მთელი აზრი იმისა, რომ ის ბილიკის ზოლზეა და არა გვერდითი ზოლის საცავის გადამრთველისთვისაა მიგდებული.

### სანამ გარეთ ხართ

ბილიკი **იწყება იმ ადგილიდან, რომელიც აირჩიეთ**, და არა მანქანის კატალოგების განლაგებიდან — აირჩიეთ `Archive` და რიგი წაიკითხება როგორც `Archive / notes / …`, და არა `/home/თქვენ/Vaults/Archive/notes/…`. წამყვან მონაკვეთს აქვს ხატულა იმისა, რაცაა (საცავი, პირადი საქაღალდე, დისკი), და <kbd>Backspace</kbd> იქ ჩერდება და აღარ მიდის ზემოთ ფაილური სისტემის დანარჩენ ნაწილში. როცა *საცავის სახელის ჩვენება* გამორთულია, ის მონაკვეთი მხოლოდ ხატულაა — პარამეტრი რიგის საწყის მონაკვეთს ეხება, რომელ საცავსაც უნდა ასახელებდეს, და არა მხოლოდ თქვენსას.

ბილიკის ზოლი **შეცდომის ფერშია ჩარჩოში ჩასმული** — იმავე რგოლით, რომელსაც გადარქმევის რეჟიმი ხატავს — მანამ, სანამ ის თქვენი საცავის გარეთ მიუთითებს. ის აღნიშნავს მდგრად მდგომარეობას და არა წამს: სანამ ის დგას, Obsidian-ის საკუთარი დამუშავებიდან არცერთი არ ვრცელდება იმაზე, რასაც რიგი აჩვენებს, და წერა ჩაკეტილია, სანამ სხვას არ იტყვით.

დანარჩენში დათვალიერება ისე მუშაობს, როგორც შიგნით: ფირფიტები, გამყოფები, აკრეფა, ავტოშევსება, <kbd>Backspace</kbd> ერთი ნაბიჯით გამოსასვლელად. იმავე ხილვადობის წესებიც მოქმედებს, ამიტომ მხარდაუჭერელ გაფართოებებს კვლავ სჭირდება Obsidian-ის *ყველა ფაილის გაფართოების ამოცნობა*, ხოლო წერტილით დაწყებულ ფაილებს — კვლავ ამ მოდულის პარამეტრი.

**მარჯვენა დაწკაპუნება და გადათრევა** სიის ჩანაწერებზე იქ არ მუშაობს — ესენი ფაილების საკუთარი დამმუშავებლებია და მათ სჭირდებათ ფაილი, რომელსაც საცავი იცნობს.

### საცავის გარეთ წერა

ყველაფერი, რაც წერს, **ნაგულისხმევად ჩაკეტილია**. სათაურში გადარქმევის გადამრთველის გვერდით ჩნდება **ბოქლომი** მანამ, სანამ რიგი თქვენი საცავის გარეთ მიუთითებს; მისი დაჭერა კეტს ხსნის და ის წითლდება, რიგის გარშემო რგოლის შესატყვისად.

ნებართვა ეძლევა **ადგილს და არა წამს**: ის გადაურჩება ყველაფერს, რასაც ერთ ადგილას მუშაობისას გააკეთებდით — გადატანის დასრულებას, ველიდან გარეთ დაწკაპუნებას, ფაილის გახსნას — და მთავრდება, როცა სიიდან სხვა საცავს, დისკს ან ძირს აირჩევთ, როცა რიგი საცავის ფაილს დაუბრუნდება, ან როცა ბოქლომს ხელახლა დააჭერთ. ასე რომ, ერთი საქაღალდის შიგნით რიგი გადატანა ერთ დაჭერას მოითხოვს და არა თითო ფაილზე ერთს.

გახსნილი ბოქლომით ბილიკის ზოლი იქაც ისე იქცევა, როგორც შიგნით:

| მოქმედება | შედეგი |
| --- | --- |
| აკრიფეთ არარსებული სახელი, <kbd>Enter</kbd> | იგივე კითხვა „შეიქმნას?“, როგორც შიგნით; დაკლებული მშობელი საქაღალდეებიც იქმნება. გაფართოების გარეშე სახელი `.md` ხდება, ზუსტად ისე, როგორც შიგნით |
| გადარქმევის/გადატანის რეჟიმი, აკრიფეთ ახალი სახელი | არქმევს სახელს იმ ფაილს, რომელსაც რიგი აჩვენებს. გაფართოების გარეშე სახელი ფაილის საკუთარს ინარჩუნებს — აქ, გარეთ, ერთი საქაღალდე ყველანაირ ფაილს ინახავს და გადარქმევამ ჩუმად არ უნდა აქციოს `.png` `.md`-ად |

ჩაკეტილ მდგომარეობაში ყოველივე ეს მოხდენის ნაცვლად აცნობებს, რა უშლის ხელს. არცერთ მდგომარეობაში არაფერი გადაიწერება: უკვე არსებული სამიზნე უარიყოფა და ეს უარი თავად ფაილური სისტემისაა (`COPYFILE_EXCL`, ექსკლუზიური შექმნა) და არა შემოწმებისა, რომელსაც შეეძლო რბოლაში წაგება. ფაილურ სისტემებს შორის გადატანა — USB-დან, ქსელური რესურსიდან — გადადის კოპირება-შემდეგ-წაშლაზე და ორიგინალი მხოლოდ მას შემდეგ იშლება, რაც ასლი ადგილზე დაჯდება.

**ერთი რამ, რასაც ბოქლომი არ ხსნის: ჩანაწერის თქვენი საცავიდან *გარეთ* გადატანა.** `fileManager` ვერ მიჰყვება ფაილს ამ საზღვრის მიღმა, ამიტომ ჩანაწერზე მიმართული ყოველი ბმული ჩუმად გაწყდებოდა და Obsidian უბრალოდ ნახავდა, რომ ის გაქრა. <kbd>Ctrl</kbd>-ის დაჭერა სამაგიეროდ იქ მის ასლს აკეთებს, რასაც ეს პრობლემა არ აქვს, და შეტყობინებაც ამას ამბობს. საპირისპირო მიმართულება — გარე ფაილის საცავში *შემოტანა* — ჯერაც არაა ჩართული.

### გარე ფაილის გახსნა

Obsidian-ის რედაქტორი მხოლოდ საცავის შიგნით მდებარე ფაილებზე მუშაობს, ამიტომ გარე ფაილი **ვერ** გაიხსნება ნამდვილ ჩანაწერად ბმულებით, უკუბმულებით და დანარჩენით — ეს აპლიკაციის და არა ამ მოდულის შეზღუდვაა. ერთის არჩევა სამაგიეროდ ხსნის **წინასწარ ხედს**, მხოლოდ წასაკითხად, სანამ სხვას არ იტყვით:

| ტიპი | როგორ ჩანს |
| --- | --- |
| `.md`, `.markdown` | დარენდერებული Markdown |
| სურათები, აუდიო, ვიდეო, PDF | საკუთარი დამკვრელი/მაჩვენებელი |
| ნებისმიერი სხვა **ტექსტური** ფაილი (`.json`, `.css`, `.log`, `.txt`, …) | სიტყვასიტყვით უბრალო ტექსტი |
| ორობითი ფორმატები მაჩვენებლის გარეშე (`.zip`, `.exe`, …) | გადაეცემა *გარე პროგრამით გახსნა*-ს |

მაჩვენებელს ფაილის ორი წაკითხვა აქვს და რადგან ისინი ერთმანეთს გამორიცხავენ, მხოლოდ ის ჩანს, რომელზეც **გადახვიდოდით**:

| **ნახვა Markdown-ად** | რენდერავს ფაილს ჩანაწერად, მხოლოდ წასაკითხად | `.md`, `.markdown` |
| **რედაქტირება ტექსტად** | წყარო, რედაქტირებადი | ყველაფერი დანარჩენი |

საცავის გარეთ **რედაქტირება ტექსტად** იმავდროულად ის დაჭერაა, რომელიც მხოლოდ-წაკითხვას ხსნის — რეჟიმი და ნებართვა ერთი მოძრაობაა და არა ორი ღილაკი, რომლებზეც უნდა იფიქრო. ის წითლდება **ყოველთვის, როცა მისი დაჭერა მოხსნიდა მხოლოდ-წაკითხვას**, ადგილზე რედაქტირებას ამზადებთ თუ პირდაპირ დარენდერებული ხედიდან მოდიხართ; საცავის შიგნით გასახსნელი არაფერია, ამიტომ ის უბრალო რჩება. **ნახვა Markdown-ად** მსუბუქ აქცენტურ ელფერს იღებს — იმავეს, რომელსაც Obsidian შერჩეულ ტექსტს აძლევს — რაც მას მოქმედებისკენ მოწოდების ნაცვლად უკან დასაბრუნებელ გზად მონიშნავს.

რადგან ღილაკი *რედაქტირებას* მიჰყვება და არა უხეშ რეჟიმს, ტექსტურ ხედში მხოლოდ-წაკითხვის მდგომარეობაში მჯდომი ფაილიც კვლავ სთავაზობს **რედაქტირება ტექსტად**-ს: სწორედ ეს დაჭერა ამზადებს მას. ფაილი, რომელშიც ვერასდროს აკრეფ — შემოკლებული ან წაუკითხავი — სამაგიეროდ ამბობს **ნახვა ტექსტად**, რადგან დაჭერას მხოლოდ ამის მოცემა შეუძლია.

ნაგულისხმევები სასარგებლოდაა შერჩეული და არა სიტყვასიტყვით: `#` shell-სკრიპტში კომენტარია და არა სათაური, ამიტომ `.log`-ის Markdown-ად რენდერი მას ჩუმად ჩაყლაპავდა. ორივე ნაგულისხმევი შეიძლება ფაილობრივად გადაიფაროს და არჩევანი ფურცლის ისტორიაში ხვდება, ამიტომ უკან/წინ და ხელახლა გახსნილი სამუშაო სივრცე მას ინახავს — ბევრი ჩანაწერი `.txt` ფაილებში ცხოვრობს და ბევრი `.md` ფაილი წყაროდ უფრო ადვილად იკითხება.

**თქვენი საცავის ფაილები მაშინვე რედაქტირებადია**, ყოველგვარი გახსნის გარეშე: *რედაქტირება ტექსტად* ნამდვილი რედაქტორია და აკრეფისას უკან წერს.

**რედაქტირება გადართვის მიღმაც ახსოვს.** *ნახვა Markdown-ად*-ზე გადასვლა მას აჩერებს — სტატიკურ რენდერში ასაკრეფი არაფერია, ხოლო Live Preview-ს Obsidian-ის საკუთარი რედაქტორი სჭირდება, რომელიც მხოლოდ საცავის შიგნით მდებარე ფაილებისთვის არსებობს — ამიტომ, სანამ იქ ხართ, არაფერი აცხადებს, რომ რედაქტირებთ. *რედაქტირება ტექსტად*-ზე დაბრუნება იქიდან აგრძელებს, სადაც შეჩერდით.

**საცავის გარეთ მდებარე ფაილები მხოლოდ წასაკითხად იხსნება და *რედაქტირება ტექსტად* ამას ხსნის.** ეს დაჭერა მთელი კარიბჭეა: სანამ ის არ მოხდება, იქ არაფერი იწერება. შემდეგ ფაილი აკრეფისას ინახება, ზუსტად ისე, როგორც საცავში მდებარე; სტატუსის ხაზი კი კეტიდან ფანქარზე იცვლება. ეს გახსნა მოიცავს იმ ერთ ფაილს იმ ერთ ჩანართში — სხვა ფაილზე გადასვლა ხელახლა კეტავს და ის განზრახ არ ინახება ჩანართის ისტორიაში, ამიტომ ხელახლა გახსნილი სამუშაო სივრცე არასდროს ბრუნდება უკვე მომზადებული ჩაწერით სისტემურ ფაილზე, რომლის გახსნაც არ გახსოვთ.

**შემოკლებული ფაილები მაინც მხოლოდ წასაკითხად რჩება** — ეკრანზე არსებულის შენახვა ზღვარს მიღმა დარჩენილ ყველაფერს გადააგდებდა, ამიტომ ღილაკი შეთავაზებისა და უარის თქმის ნაცვლად საერთოდ არ სთავაზობს. იგივე ეხება ფაილს, რომლის წაკითხვაც ვერ მოხერხდა: ცარიელი პანელის გარდა უკან ჩასაწერი არაფერია.

თუ ჩაწერა ვერ მოხერხდა — მხოლოდ-წაკითხვის მიმაგრება, ფაილი, რომელიც თქვენი არაა — სისტემის საკუთარი მიზეზი შეტყობინებაში ჩანს.

ძალიან დიდი ფაილები შემოკლებულად ჩანს და სტატუსის ხაზიც ამას ამბობს, ნაცვლად იმისა, რომ თავად აღმოაჩინოთ — სხვა პირობების გვერდით და არა ღილაკებს უკან, რადგან ესეც ფაქტია ფაილის შესახებ, დანარჩენივით. ზღვრები ცოცხალ რენდერერთან ისაზღვრება და არა გამოცნობით — მეგაბაიტი ტექსტის ერთ პანელში განლაგება Obsidian-ის რენდერის პროცესს ადგილზევე კლავს, ხოლო Markdown ბაიტზე რამდენჯერმე მეტი ჯდება, ვიდრე უბრალო ტექსტი, ამიტომ ორივეს ცალკე ზღვრები აქვს და ერთი უზარმაზარი ხაზიც კი მოკლდება მაშინაც, როცა ფაილი მთლიანობაში პატარაა.

**სტატუსის ხაზები წარწერებია, ახსნა კი მინიშნებაა.** ყოველი ხაზი იმდენივე სიტყვით ამბობს, რაც სიმართლეა, რამდენიც საჭიროა — *საცავის გარეთ*, *ამ ტიპის ფაილისთვის რედაქტორი არაა*, *შემოკლებულია — ფაილი ძალიან დიდია* — რადგან მათ გვერდით მდგომი ღილაკები უკვე ამბობენ, რა მდგომარეობაშია ფაილი. ერთზე კურსორის მიტანა წინადადებას იძლევა: რატომ ვერ ხსნის Obsidian მას ჩანაწერად, სხვა შემთხვევაში რა მოუვიდოდა ამ ტიპის ფაილს, რა დაგიჯდებათ შემოკლება.

ეს ეხება თქვენი საცავის **შიგნით** მდებარე ფაილებსაც. Obsidian ნებისმიერ გაფართოებას, რომლისთვისაც ხედი არ აქვს, პირდაპირ სამუშაო მაგიდის ნაგულისხმევ პროგრამას გადასცემს — ამიტომ თქვენს საცავში მდებარე `.txt` ან `.json` Obsidian-ს სულ დატოვებდა. ისინი ახლა იმავე მაჩვენებელში იხსნება, ნარინჯისფერი რგოლით, რადგან „გახსენი ის Obsidian-ში“ სწორედ ესაა, რაც ითხოვეთ — და რადგან საცავის ფაილებია, იქ ისინი ყოველგვარი გახსნის გარეშე რედაქტირებადია. ორობითი ფაილები მაჩვენებლის გარეშე Obsidian-ის ქცევას ინარჩუნებენ; საჩვენებელი არაფერია.

წინასწარი ხედი იხსნება **იმ ჩანართში, სადაც იყავით**, ამიტომ უკან/წინ თქვენ იმ ჩანაწერს დაგიბრუნებთ, საიდანაც მოხვედით; ახალი ჩანართისთვის დააჭირეთ <kbd>Ctrl</kbd>-ს, ისევე როგორც ყველგან. სათაურის ზოლი გარე ფაილის ბილიკს აჩვენებს მანამ, სანამ ის ღიაა, ამიტომ დათვალიერება იქიდან შეგიძლიათ განაგრძოთ.

შიგთავსის ზემოთ მდგომი წყნარი ხაზი გამოსავლებს გთავაზობთ:

- **გახსნა *(საცავი)*-ში** — ჩანს, როცა ფაილი თქვენს რომელიმე სხვა საცავს ეკუთვნის. გადასცემს მას Obsidian-ის საკუთარ URI-დამმუშავებელს, რომელიც იმ საცავის ფანჯარას ხსნის ჩანაწერით შიგნით, როგორც ნამდვილ რედაქტირებად ჩანაწერს. ეს ფანჯარა ზუსტად ისე რჩება, როგორც იყო; თქვენს ქვეშ არაფერი იცვლება.
- **ნახვა Markdown-ად** / **რედაქტირება ტექსტად** — ორი წაკითხვა; მეორე საცავის გარეთ მხოლოდ-წაკითხვასაც ხსნის.
- **გარე პროგრამით გახსნა** — ფაილს თქვენი სამუშაო მაგიდის ნაგულისხმევ პროგრამას გადასცემს, მათ შორის იმ ორობით ფორმატებსაც, რომელთა ჩვენებაც ამ მაჩვენებელს არ შეუძლია.

თქვენი საცავის გარეთ არაფერი იწერება, თუ ჯერ *რედაქტირება ტექსტად*-ს არ დააჭერთ. სრული განმარტებისთვის იხილეთ README-ის განყოფილება [საცავის გარეთ](README.ka.md#საცავის-გარეთ).

## გადატანის/გადარქმევის რეჟიმი

ფანქრის ღილაკი სათაურის უკიდურეს მარჯვნივ — ხედის რეჟიმის ღილაკის გვერდით, საკუთარი ღილაკების ზომისა — რთავს და თიშავს გადატანის/გადარქმევის რეჟიმს. მაშინ სათაურის რიგი აქცენტის ფერშია ჩარჩოში ჩასმული, ზუსტად ისე, როგორც გადარქმევისას ფაილებში. იგივე დაწკაპუნებები და კლავიშები ახლა ამტკიცებს გადატანას ან გადარქმევას Obsidian-ის `fileManager.renameFile`-ის მეშვეობით, ამიტომ ჩანაწერზე მიმართული ყველა ბმული მას მიჰყვება.

გადარქმევისას:

- ფაილის მიმდინარე სახელი ყოველი საქაღალდის სიაშია მიმაგრებული, ამიტომ ჩანაწერის სახელის შეუცვლელად გადატანა ერთი დაწკაპუნებაა.
- სამიზნე საქაღალდეში უკვე დაკავებული სახელები გამუქებულია, მაგრამ მაინც არჩევადი.
- აკრეფილი Obsidian-ის საკუთარი გადარქმევის წესებით ცოცხლად მოწმდება — იგივე სიმბოლოთა ნაკრები, იგივე შეტყობინებები, იგივე წითელი მინიშნება, რომელსაც ფაილთა ხეში გადარქმევისას იღებთ — ამიტომ დაუშვებელი ან კონფლიქტური სახელი აკრეფისთანავე აღინიშნება და ვერ დამტკიცდება.
- სათაურის ზოლის გარეთ დაწკაპუნება ან სათაურის ფოკუსის დაკარგვა ამთავრებს გადარქმევის რეჟიმს.

## ერთი კლავიში ორივე გადარქმევისთვის

გადარქმევის ბრძანება (ნაგულისხმევად <kbd>F2</kbd>, ან რასაც მიაბამთ) **მონაცვლეობს** Obsidian-ის ჩაშენებული სათაურის გადარქმევასა და ამ მოდულის სათაურის ბილიკის ზოლს (სრული ბილიკი შერჩეული) შორის. თუ Obsidian-ის ჩაშენებული სათაური გამორთული გაქვთ, ბილიკის ზოლი ერთადერთი სამიზნე ხდება, ამიტომ კლავიში არასდროს რჩება უმოქმედო.

ეს მუშაობს `workspace:edit-file-title` ბრძანების შემოხვევით და არა კლავიშის მიტაცებით, ამიტომ მალსახმობის ხელახლა მიბმაც და ბრძანების პალიტრიდან გაშვებაც უცვლელად მუშაობს.

## ხატულების შეცვლა

Lure სამ ხატულას ხატავს: საცავის ძირის ხატულას (როცა **საცავის სახელის ჩვენება** გამორთულია), გადარქმევის/გადატანის გადამრთველს და ბოქლომს, რომელიც საცავის გარეთ ჩაწერას აკონტროლებს. ყველა მათგანი შეიძლება შეიცვალოს თემიდან ან CSS-ნაწყვეტიდან — მიუთითეთ შემცვლელი ნიშანი და დამალეთ თანდართული ერთსა და იმავე წესში:

```css
.lure-vault-icon {
	--lure-icon-glyph: "🏠";
	--lure-icon-svg: none;
}

.lure-rename-btn {
	--lure-icon-glyph: "✎";
	--lure-icon-svg: none;
}

/* ბოქლომს ორი მდგომარეობა აქვს; `.is-active` გახსნილია. */
.lure-unlock-btn {
	--lure-icon-glyph: "🔒";
	--lure-icon-svg: none;
}

.lure-unlock-btn.is-active {
	--lure-icon-glyph: "🔓";
}
```

`--lure-icon-glyph` იღებს ყველაფერს, რაც CSS-ის `content`-ში დასაშვებია, ამიტომ `url(...)` სურათისთვისაც ისევე მუშაობს, როგორც ტექსტური ნიშნისთვის ან ემოჯისთვის. დატოვეთ `--lure-icon-svg` ხელუხლებელი, თუ გინდათ Lucide-ის ხატულა შეინარჩუნოთ და თქვენი ნიშანი მის გვერდით დახატოთ.
