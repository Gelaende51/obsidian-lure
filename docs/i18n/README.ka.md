# Lure

[Obsidian](https://obsidian.md)-ის დამატება, რომელიც ჩანაწერის სათაურის ზოლში მოცემულ ფაილის სახელს აქცევს საცავის მასშტაბით გამავალ სრულ ბილიკად, რომელზეც შეიძლება დაწკაპუნება და რომლის რედაქტირებაც შესაძლებელია — როგორც მისამართის ზოლი ფაილების მმართველ [Dolphin](https://apps.kde.org/dolphin/)-ში.

![დაწკაპუნება საქაღალდის შემდგომ გამყოფზე: მაჩვენებელი მასზეა და ფაილებმა ეს საქაღალდე გამოაჩინა და გახსნა](../images/breadcrumb.png)

Obsidian 1.8.7+ · მხოლოდ კომპიუტერისთვის · AGPL-3.0

## ხელოვნური ინტელექტის შესახებ

- **აგენტი** — **Claude Opus 5** და **Claude Sonnet 5** (Anthropic, Claude Code-ის მეშვეობით): დაწერა TypeScript, CSS, თარგმანების ორმოცდახუთივე ნაკრები და დოკუმენტაცია. თარგმანები მანქანურია და მშობლიური ენის მცოდნეებს არ გადაუმოწმებიათ.
- **ავტორი** — Vault51: განსაზღვრა ყოველი შესაძლებლობა, თითოეული ვერსია რეალურ საცავში გამოსცადა, წარმართა შესწორებები, გადახედა ყველა შედეგს.
- **ხარჯი** — 2026 წლის 3–13 აგვისტო, ცხრა სესია, \~4928 პასუხი: \~7,2 მლნ წარმოქმნილი ტოკენი, \~23,7 მლნ გაგზავნილი, \~1169,6 მლნ ხელახალი წაკითხვა ქეშიდან (სულ \~1200,5 მლნ).

## შესაძლებლობები

- **დააწკაპუნეთ საქაღალდეს** მისი *ზემდგომი* საქაღალდის შიგთავსის სიისთვის — შეცვალეთ ერთი საქაღალდე მეზობლით ისე, რომ ბილიკის დანარჩენს არ შეეხოთ. ჩანაწერის სახელიც ასევე მუშაობს, გაფართოებასთან ერთად.
- **დააწკაპუნეთ გამყოფს** საქაღალდის შემდეგ, რომ ის ფაილებში გამოჩნდეს და გაიხსნას. ერთი პარამეტრი ამ ორ როლს ერთმანეთში ცვლის.
- **დააწკაპუნეთ მარჯვენა ღილაკით ან გადაათრიეთ ნებისმიერი ჩანაწერი** — ფაილების საკუთარი კონტექსტური მენიუ და გადათრევის ქცევა.
- **დააწკაპუნეთ ფაილის სახელს ან ცარიელ ადგილს** ბილიკის ჩასაწერად, ავტომატური შევსებით. `/` ჩადის ქვემოთ, <kbd>Backspace</kbd> ერთი დონით ზემოთ გადის, <kbd>Enter</kbd> ადასტურებს.
- **საქაღალდეზე ფანქრის ღილაკი** ამავე მოქმედებებს გადაიყვანს გადატანის/გადარქმევის რეჟიმში, იმავე შემოწმებებით, რასაც თავად Obsidian აკეთებს.
- **დააჭირეთ <kbd>Ctrl</kbd>-ს** ახალ ჩანართში გასახსნელად — ან, გადატანის/გადარქმევის რეჟიმში, ჩანაწერის იქ დასაკოპირებლად გადატანის ნაცვლად.
- **<kbd>F2</kbd>** ენაცვლება ჩანაწერშივე არსებულ სათაურსა და ბილიკის ზოლს.
- **დააწკაპუნეთ საცავის სახელს**, რომ დაათვალიეროთ თქვენი სხვა საცავები, საშინაო საქაღალდე, ფაილური სისტემის ფესვი და მიერთებული დისკები საცავის შეცვლის გარეშე. მხოლოდ წასაკითხად, სანამ ბოქლომს არ გახსნით, და მთელი ამ ხნის განმავლობაში შეცდომის ფერით ჩარჩოში. ნაგულისხმევად გამორთულია — იხილეთ [საცავის გარეთ](#საცავის-გარეთ).
- **გაფრთხილების ორი დონე** — წითელი საცავის გარეთ, ნარინჯისფერი ტექსტური ფაილებისთვის, რომლებისთვისაც Obsidian-ს რედაქტორი არ აქვს. იხილეთ [გაფრთხილების ორი ფერი](usage.ka.md#გაფრთხილების-ორი-ფერი).
- **თემას აყოლილი ხატულები**, შესაცვლელი CSS-ის ნაწყვეტიდან — და **45 ენა**, ყველა, რასაც Obsidian მოაქვს.
- **პარამეტრები:** სწორება, მზა გამყოფები, რომელი დაწკაპუნება ხსნის სიას, საცავის სახელი, დამალული ფაილები.

## საცავის გარეთ

Obsidian-ის დეველოპერული წესები მოითხოვს, რომ დამატებამ ახსნას საცავის გარეთ ფაილებთან ყოველი წვდომა, ამიტომ პირდაპირ:

**საერთოდ აკეთებს თუ არა რომელიმე მათგანს.** მხოლოდ იმ შემთხვევაში, თუ ჩართავთ **გარე ფაილებზე წვდომას**, რომელიც **ნაგულისხმევად გამორთულია**. გამორთულ მდგომარეობაში დამატებიდან გარე ბილიკამდე მისასვლელი გზა არ არსებობს და ქვემოთ აღწერილი კოდიდან არაფერი სრულდება.

**რას კითხულობს.** მხოლოდ მაშინ, როცა თქვენ სთხოვთ. საცავის სახელზე დაწკაპუნება ჩამოთვლის თქვენს სხვა საცავებს — წაკითხულს თავად Obsidian-ის `obsidian.json`-იდან — ასევე საშინაო საქაღალდეს, ფაილური სისტემის ფესვსა და მიერთებულ დისკებს (Linux-ზე `/proc/mounts`, macOS-ზე `/Volumes`, Windows-ზე დისკის ასოები). იქიდან შემდგომი დათვალიერება ჩამოთვლის საქაღალდეების შიგთავსს, ხოლო ფაილის გახსნა კითხულობს მხოლოდ იმ ერთ ფაილს.

**რას წერს.** არაფერს, სანამ არ დააჭერთ ღილაკს, რომელიც ამას წერს. ასეთი ღილაკი ორია და თითოეული მხოლოდ საკუთარ არეალს ფარავს:

- დამთვალიერებლის ღილაკი **რედაქტირება ტექსტად** განბლოკავს თქვენ წინაშე არსებულ ფაილს — მხოლოდ იმ ერთ ფაილს იმ ერთ ჩანართში. შემდეგ თქვენი ცვლილებები მასში ინახება წერის კვალდაკვალ.
- სათაურის **ბოქლომი**, რომელიც ჩანს მხოლოდ მაშინ, სანამ ბილიკის ზოლი საცავის გარეთ მიუთითებს, განბლოკავს გარე ბილიკებზე შექმნას, გადარქმევასა და გადატანას. ის ისევ იკეტება, როგორც კი შიგნით დაბრუნდებით, ამიტომ ნებართვა არასოდეს ცოცხლობს იმ საქაღალდეზე დიდხანს, რომლისთვისაც გაიცა.

არცერთი განბლოკვა არ ინახება არც სამუშაო სივრცეში და არც პარამეტრებში, ამიტომ ჩაწერა არასოდეს რჩება მზადყოფნაში იმ ფაილზე, რომლის გახსნაც არ გახსოვთ. არცერთ მდგომარეობაში არაფერი გადაეწერება — უკვე არსებული სამიზნე უარიყოფა, ამისთვის გამოიყენება თავად ფაილური სისტემის ექსკლუზიური შექმნა და არა შემოწმება, რომელსაც შეიძლება რბოლა წააგოს — და ჩანაწერი ვერასოდეს *გადავა* საცავის გარეთ, რადგან მასზე მიმავალი ბმულები ჩუმად გაწყდებოდა; <kbd>Ctrl</kbd>-ის დაჭერა მის ნაცვლად გარეთ აკოპირებს მას.

**რატომ.** საჭირო ჩანაწერები ხშირად სხვა საცავშია, სინქრონიზაციის საქაღალდეში ან USB-მეხსიერებაზე, ხოლო თავად Obsidian-ის პასუხი — შეცვალე საცავი — ხურავს ყველაფერს, რაც გახსნილი გქონდათ. ეს კი გაძლევთ საშუალებას მიხვიდეთ და დაათვალიეროთ წასვლის გარეშე, და იქვე შეასწოროთ აკრეფის შეცდომა.

**შეზღუდვა.** Obsidian-ის რედაქტორი მიბმულია საცავის შიგნით არსებულ ფაილებზე, ამიტომ გარე ფაილის გახსნა ნამდვილ ჩანაწერად, ბმულებით, უკუბმულებითა და დანარჩენით, **შეუძლებელია**; ამას ვერცერთი დამატება ვერ შეძლებს. სამაგიეროდ Lure მას საკუთარ დამთვალიერებელში აჩვენებს (Markdown, სურათები, აუდიო, ვიდეო, PDF), დანარჩენ ყველაფერზე კი გთავაზობთ *გარე პროგრამით გახსნას*. ბილიკის ზოლი შეცდომის ფერის ჩარჩოში რჩება ყოველთვის, როცა საცავის გარეთ მიუთითებს, ხოლო კვალი იმ ადგილიდან იწყება, რომელიც თქვენ აირჩიეთ — საცავის სახელიდან, საშინაო საქაღალდიდან, დისკიდან — და არა მანქანის საქაღალდეების განლაგებიდან.

**წყაროდან:** `npm install && npm run build` — იხილეთ [დამუშავება](../development.md).

## თავსებადობა

დამატება არ არის საჭირო. ძირითადი **ფაილები**, თუ ჩართულია, სწორედ ის აჩვენებს საქაღალდეებს გვერდით პანელში; მის გარეშე ის დაწკაპუნებები არაფერს აკეთებს.

გამოცდილია საზოგადოების იმ დამატებებთან, რომლებიც ჩანაწერის სათაურს იზიარებენ ან საქაღალდეზე დაწკაპუნებას პასუხობენ — ორივე ჩატვირთვის თანმიმდევრობით, თითოეული ჩართული და გამორთული:

- [Folder notes](obsidian://show-plugin?id=folder-notes) — გამყოფი ხსნის საქაღალდის ჩანაწერს იმის ნაცვლად, რომ თავად საქაღალდე აჩვენოს, რის გამოც ბილიკის ყოველი მონაკვეთი ადგილად იქცევა, სადაც წასვლა შეიძლება. ერთადერთი საქაღალდე-ჩანაწერების დამატება, რომელიც სათაურის ბილიკს ითვისებს; [Folder Note](obsidian://show-plugin?id=folder-note-plugin) და [create folder notes with dropdown](obsidian://show-plugin?id=create-folder-notes-with-dropdown) იქ არ უსმენენ, ამიტომ გამყოფი ჩვეულებრივად აჩვენებს საქაღალდეს.
- [Quick Explorer](obsidian://show-plugin?id=quick-explorer) და [Front Matter Title](obsidian://show-plugin?id=obsidian-front-matter-title-plugin) — ორივე იმავე სათაურის ელემენტში ხატავს; Lure ინარჩუნებს თავის რიგს, რომელიც არ უნდა ჩაიტვირთოს პირველი, ხოლო რომელიმეს გამორთვა მეორეს ხელუხლებელს ტოვებს.
- [Nav Link Header](obsidian://show-plugin?id=nav-link-header), [Running Head](obsidian://show-plugin?id=running-head), [Crumbs](obsidian://show-plugin?id=crumbs-obsidian), [Breadcrumbs](obsidian://show-plugin?id=breadcrumbs) — საკუთარი ზოლი აქვთ და უპრობლემოდ თანაარსებობენ.

მხოლოდ კომპიუტერისთვის — ურთიერთქმედების მოდელს სჭირდება მაუსის მიტანა, ზუსტი დაწკაპუნებები და კლავიატურა. სრული შედეგები, დარჩენილი შესამოწმებელი და Quick Explorer-სა და Breadcrumbs-თან შედარება მოცემულია [თავსებადობაში](../compatibility.md).
