# Lure

ノートのヘッダーバーにあるファイル名を、保管庫全体をたどるクリック可能で編集可能なパスに変える [Obsidian](https://obsidian.md) プラグインです — ファイルマネージャー [Dolphin](https://apps.kde.org/dolphin/) のアドレスバーのように。

![フォルダーの後ろの区切り文字をクリックしたところ。ポインターがその上にあり、ファイルエクスプローラがそのフォルダーを表示して展開している](../images/breadcrumb.png)

Obsidian 1.8.7+ · デスクトップ専用 · AGPL-3.0

## 機能

- **フォルダーをクリック**すると、その*親*フォルダーの中身が一覧で出ます — パスの残りには触れずに、フォルダーを隣のものへ入れ替えられます。ノートの名前も拡張子を含めて同じように動きます。
- フォルダーの後ろの**区切り文字をクリック**すると、そのフォルダーをファイルエクスプローラで表示して展開します。設定ひとつでこの二つの役割が入れ替わります。
- **どの項目でも右クリックまたはドラッグ**できます — ファイルエクスプローラ自身のコンテキストメニューとドラッグ動作です。
- **ファイル名または空白部分をクリック**するとパスを入力できます。補完付きです。`/` で下に降り、<kbd>Backspace</kbd> で一段上がり、<kbd>Enter</kbd> で確定します。
- **フォルダーに鉛筆のボタン**を押すと、同じ操作が移動／名前の変更に切り替わります。検証は Obsidian 自身と同じ方法で行われます。
- **<kbd>Ctrl</kbd> を押しながら**で新しいタブに開きます — 移動／名前の変更モードでは、ノートを移動する代わりにそこへコピーします。
- **<kbd>F2</kbd>** でインラインタイトルとパスバーが交互に切り替わります。
- **保管庫の名前をクリック**すると、保管庫を切り替えずに他の保管庫、ホームフォルダー、ファイルシステムのルート、マウント済みのドライブを見て回れます。南京錠を開くまでは読み取り専用で、その間ずっとエラー色で囲まれます。既定ではオフです — [保管庫の外](#保管庫の外)を参照してください。
- **二段階の警告** — 保管庫の外では赤、Obsidian にエディタがないテキストファイルにはオレンジ。[二つの警告色](usage.ja.md#二つの警告色)を参照してください。
- **テーマに合わせられるアイコン**は CSS スニペットから差し替えられます — そして **45 言語**、Obsidian が備えるすべての言語に対応します。
- **設定:** 配置、区切り文字のプリセット、どちらのクリックで一覧を開くか、保管庫の名前、ドットファイル。

![移動／名前の変更モードでの同じ一覧。現在のファイル名が最上部に固定され、その下に隣接するフォルダー、既存のノートは灰色になっている](../images/dropdown.png)

*移動／名前の変更モードでは、同じ一覧が別のものを示します。名前を変えずに移動できるようノートの現在の名前が最上部に固定され、その下に移動先となるフォルダーが並び、すでに使われている名前は誤って上書きされないよう灰色になります。*

→ [詳しい使い方](usage.ja.md)

## 保管庫の外

Obsidian の開発者ポリシーは、保管庫の外にあるファイルへのアクセスをプラグインが説明することを求めています。ですので率直に:

**そもそもこれらを行うのか。** **外部ファイルへのアクセス**をオンにした場合のみで、これは**既定でオフ**です。オフのままなら、プラグインから外部のパスに到達する手段はなく、以下に述べるコードは一切実行されません。

**何を読むのか。** あなたが求めたときだけです。保管庫の名前をクリックすると、他の保管庫が一覧されます — Obsidian 自身の `obsidian.json` から読み取ります — 加えてホームフォルダー、ファイルシステムのルート、マウント済みのドライブ（Linux では `/proc/mounts`、macOS では `/Volumes`、Windows ではドライブレター）。そこから先をたどるとディレクトリの中身が一覧され、ファイルを開けばそのファイル一つだけを読みます。

**何を書くのか。** そうと書かれたボタンを押すまで、何も書きません。そのようなボタンは二つあり、それぞれ自分の範囲だけを受け持ちます:

- ビューアの**テキストとして編集**ボタンは、目の前のファイルの施錠を解きます。そのタブのそのファイル一つだけです。以後、入力するそばから変更がそのファイルに保存されます。
- ヘッダーの**南京錠**は、パスバーが保管庫の外を指している間だけ現れ、外部のパスでの作成・名前の変更・移動を許可します。中に戻ると再び施錠されるので、許可が、それを与えたフォルダーより長く残ることはありません。

どちらの解除もワークスペースにも設定にも保存されないため、開いた覚えのないファイルに書き込みが構えられていることはありません。どちらの状態でも上書きは起こりません — 既存の対象は拒否されます。競合に負けうるチェックではなく、ファイルシステム自身の排他的作成を使っています — そしてノートを保管庫の外へ*移動*することは決してできません。そのノートへのリンクが黙って壊れてしまうからです。<kbd>Ctrl</kbd> を押しながらなら、代わりに外へコピーします。

**なぜか。** 必要なノートは別の保管庫、同期フォルダー、USB メモリーにあることが多く、Obsidian 自身の答え — 保管庫を切り替える — は開いていたものをすべて閉じてしまいます。これなら、離れずに見に行けますし、ついでに誤字も直せます。

**限界。** Obsidian のエディタは保管庫の中のファイルに結びついているため、外部のファイルをリンクやバックリンクを備えた本物のノートとして開くことは**できません**。どのプラグインにもできません。代わりに Lure は自前のビューアで表示します（Markdown、画像、音声、動画、PDF）。それ以外はすべて *外部で開く* に回ります。パスバーは保管庫の外を指している間ずっとエラー色で囲まれ、たどった跡はあなたが選んだ場所 — 保管庫の名前、ホームフォルダー、ドライブ — から始まります。マシンのディレクトリ構成からではありません。

## インストール

[community.obsidian.md/plugins/lure](https://community.obsidian.md/plugins/lure) に掲載されていますが、アプリ内のブラウザにはまだ承認されていません。次のいずれかの方法でインストールしてください:

**手動:** [最新のリリース](https://github.com/Gelaende51/obsidian-lure/releases) から `main.js`、`manifest.json`、`styles.css` を `<vault>/.obsidian/plugins/lure/` にダウンロードし、**設定 → コミュニティプラグイン** で有効にします。

**BRAT:** `Gelaende51/obsidian-lure` をベータプラグインとして追加します。

**ソースから:** `npm install && npm run build` — [開発](../development.md)を参照してください。

## 互換性

必要なプラグインはありません。コアの**ファイルエクスプローラ**が有効なら、それがサイドバーでフォルダーを表示する役割を担います。無効な場合、そのクリックは何もしません。

ノートのヘッダーを共有する、またはフォルダーのクリックに応えるコミュニティプラグインとの組み合わせを試しました — 読み込み順を両方とも、それぞれオンとオフで:

- [Folder notes](obsidian://show-plugin?id=folder-notes) — 区切り文字がフォルダーを表示する代わりにそのフォルダーノートを開くので、パスのどの区間も行き先になります。ヘッダーのパスを引き受ける唯一のフォルダーノート系プラグインです。[Folder Note](obsidian://show-plugin?id=folder-note-plugin) と [create folder notes with dropdown](obsidian://show-plugin?id=create-folder-notes-with-dropdown) はそこを見ていないので、区切り文字はいつもどおりフォルダーを表示します。
- [Quick Explorer](obsidian://show-plugin?id=quick-explorer) と [Front Matter Title](obsidian://show-plugin?id=obsidian-front-matter-title-plugin) — どちらも同じヘッダー要素に描き込みます。どちらが先に読み込まれても Lure は自分の行を保ち、どちらかをオフにしてももう一方はそのまま残ります。
- [Nav Link Header](obsidian://show-plugin?id=nav-link-header)、[Running Head](obsidian://show-plugin?id=running-head)、[Crumbs](obsidian://show-plugin?id=crumbs-obsidian)、[Breadcrumbs](obsidian://show-plugin?id=breadcrumbs) — それぞれ自前の帯を持ち、問題なく共存します。

デスクトップ専用です — この操作モデルにはホバー、正確なクリック、キーボードが要ります。すべての結果、まだ確かめていないこと、Quick Explorer や Breadcrumbs との比較は[互換性](../compatibility.md)にあります。
