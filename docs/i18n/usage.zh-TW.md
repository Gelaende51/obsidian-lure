# 使用方式

[← 返回 README](README.zh-TW.md)

## 路徑列

筆記在儲存庫中的完整路徑取代了檢視標題列中光禿禿的檔名 — 標題列就是分頁列下方、同時放著上一頁/下一頁按鈕的那一條。

這一列上有兩處可以點擊，而 **資料夾名稱開啟清單** 決定誰做什麼：

| | 資料夾名稱 | 其後的分隔符 |
| --- | --- | --- |
| **開啟**（預設） | 選取該資料夾以便編輯 | 開啟該資料夾 |
| **關閉** | 開啟該資料夾 | 進入該資料夾 |

「開啟該資料夾」指的是在沒有外掛的 Obsidian 裡點擊該段所做的事。若沒有外掛在那裡監聽，資料夾會在側邊欄的檔案瀏覽器中顯示出來 — 醒目提示，並展開以露出內容。

若該資料夾的筆記正是你已經在讀的那一篇，點擊時會改為顯示該資料夾 — 因為沒有其他東西可開，畫面上已經有了，這正是「再按一次」向來的意義。

安裝了 [Folder notes](obsidian://show-plugin?id=folder-notes) 之後，同樣的點擊會改為開啟該資料夾的筆記，**無論深度為何**：這裡的筆記是依該外掛自己的慣例來解析，而不是交給它去回答。那個外掛只認得它標記過的資料夾，在深度超過一層的路徑上，這些資料夾一個都不是，所以以前點擊頂層資料夾的筆記可以開啟，深一層就什麼也不會發生。另外兩個資料夾筆記外掛沒有公開可讀取的慣例，也從不接管這一列，所以遇到它們時，分隔符一如既往地顯示資料夾。目前發現唯一會接管標題路徑的資料夾筆記外掛就是這一個；[Folder Note](obsidian://show-plugin?id=folder-note-plugin) 和 [create folder notes with dropdown](obsidian://show-plugin?id=create-folder-notes-with-dropdown) 管理資料夾筆記，但不監聽路徑列上的點擊，所以遇到它們時，分隔符照常顯示資料夾。參見[相容性](../compatibility.md#verified-against)。

**只有在其前面的資料夾確實有資料夾筆記時，分隔符才會加底線**，所以底線是一個承諾：那裡有東西可以開啟 — 在執行 [Folder notes](obsidian://show-plugin?id=folder-notes) 時，任何深度都是如此，因為這裡的筆記是自行解析，而不是交給該外掛去標記。若執行的不是這個外掛，就不會有底線，也不會開啟任何東西：分隔符只是顯示資料夾，就像完全沒有資料夾筆記外掛時一樣。無論如何每個分隔符都保持可點擊 — 沒有底線的分隔符會在側邊欄顯示並展開它的資料夾，指標游標仍會提示這一點。底線同時會從資料夾名稱上移開：swap 開啟時，名稱是用來開啟清單的，把它標成通往筆記的連結會是謊言。

**重新命名/移動模式會覆寫兩者**，無論設定為何：有移動待處理時，這一列上的任何東西都不會開啟資料夾，因為開啟就等於放棄這次移動。資料夾名稱被選取以便編輯，分隔符則往下進入 — 兩者都是挑選目的地的方式 — 並且底線消失，以示開啟已暫停。

**儲存庫根目錄**是唯一不屬於路徑分段的一段。它沒有上層可用來列出同層項目，因此改為開啟[位置清單](#瀏覽儲存庫之外) — 你的其他儲存庫、主資料夾、檔案系統根目錄和已掛載的磁碟機。

## 儲存庫自己的分隔符

緊接在儲存庫名稱之後的那個分隔符，代表的是儲存庫本身，而非某個資料夾，所以它做的事是其他分隔符都做不到的：

| | 第一次點擊 | 下一次點擊 |
| --- | --- | --- |
| **有啟動頁外掛時**（Obsidian 開啟時迎接你的頁面） | 在這個分頁中開啟那個頁面 | 收合檔案樹 |
| **沒有時** | 收合檔案樹 | 準確恢復原本開啟的內容 |

是一般的點擊，不是按兩下：頁面一旦開啟，這個分隔符就沒有其他東西可開了，所以下一次按下就是收合 — 不論你隔了多久才按。

當有啟動頁可開啟時，它會**加底線**，這和資料夾分隔符的承諾一樣：那裡有東西。收合是個開關 — 下一次按下會恢復原本展開的資料夾，且只恢復那些，所以你排好的樹狀結構不會因為瞄一眼別的東西而消失。

## 沒有檔案的分頁

空白分頁、圖形檢視，以及任何不對應到檔案的東西，都有自己專屬的一列：先是儲存庫，然後一段說明這個分頁裝的是什麼。

```
my-vault / :blank      一個新分頁
my-vault / :graph      圖形檢視，本機或全域
my-vault / :<type>     任何其他沒有檔案的東西
```

**儲存庫根目錄自己的清單**也會提供這些頁面，就列在它裡面實際存在的資料夾與筆記下方：在那裡選擇 `:graph` 或 `:search`，分頁就會開啟該檢視，就像選擇筆記會開啟筆記一樣。哪些頁面存在是從 Obsidian 讀取的，而不是寫死在這裡 — 每一個不是為了顯示檔案而存在的檢視都算，所以一個註冊了自己檢視的外掛（首頁分頁、行事曆）會出現在清單裡，而本外掛對它一無所知。需要檔案的檢視 — Markdown、PDF、圖片、白板、資料庫 — 不會被提供：因為沒有東西可以顯示。

重點就在那個冒號 — 沒有檔案或資料夾能叫做 `:graph`，所以這一列不會被誤認成可以開啟的路徑。標籤取自檢視類型，而非 Obsidian 自己的措辭，所以無論介面語言是什麼，顯示的內容都一樣，而結尾的 `-view` 會被省略：一個首頁分頁外掛把自己的檢視註冊為 `home-launcher-view`，這一列就顯示成 `:home-launcher`。

點擊空白處，或標籤本身，會**在儲存庫根目錄開啟輸入欄**：輸入路徑並按下 <kbd>Enter</kbd>，就會在這個分頁中開啟它，有著同樣的自動完成、同樣的清單，以及同樣提議建立尚不存在之物的紅色欄位。空白分頁正是輸入你想去的地方的好地方，這也是它存在的目的。

這個標籤就只是個標籤而已：沒有清單、沒有拖曳、沒有重新命名。側邊欄裡的分頁則完全不受影響 — 反向連結分頁保留 Obsidian 給它的標題。

白板、PDF、圖片和資料庫都不需要這些。它們是檔案，所以會得到一般的路徑列。

## 點擊某一段：換成同層的另一個

點擊資料夾名稱會在文字輸入欄中選取**該資料夾的名稱**，並開啟**上一層**資料夾 — 也就是它的上層 — 的清單。輸入或挑選一項即可把這個資料夾換成同層的另一個，而它下面的一切原樣保留，所以 `專案/2026/啟動.md` → 點擊 `2026` → 選擇 `2025`，得到 `專案/2025/啟動.md`。

點擊**筆記的名稱**在它自己的資料夾中運作方式相同，並會選取**不含副檔名**的名稱 — 重新命名是常見的編輯操作，而直接對包含 `.md` 的選取範圍打字，以前會不小心改變檔案類型。副檔名仍然只隔一次按鍵就能看到：<kbd>→</kbd> 能到達它，而擴大到整列的按兩下會連同它一起選取。

點擊資料夾時已經選取了一段，因此**再點一次**會把選取範圍擴大到整列 — 該資料夾*以及*它下面的一切 — 這時輸入就能一次替換路徑的其餘部分。在導覽模式與重新命名/移動模式下表現一致。

這只有作為「開啟輸入欄的那一次點擊」的延續時才成立。一旦你開始使用這個輸入欄，它就和別的文字輸入欄一樣：點擊放置游標，按兩下取一個詞，按三下取整列。

無論哪種情況，路徑的其餘部分都會保留在輸入欄周圍可見 — 前面以標籤形式呈現，後面則是未選取的文字，所以完整路徑永遠不會從標題列消失。輸入即可取代選取範圍，或按 <kbd>→</kbd> 保留它並從那裡繼續編輯。無論預先填入了什麼，清單都會列出整個資料夾；只有在你實際開始輸入後，它才會開始篩選。

## 用分隔符往下進入

在 **資料夾名稱開啟清單** 關閉時點擊分隔符，會進入它前面的那個資料夾：清單列出*那個*資料夾的內容，路徑的其餘部分則以選取狀態在輸入欄中開啟。挑選一個資料夾會把它接到路徑上，並立刻開啟下一個清單，於是你可以一路點著往下走，不必離開標題列。

## 清單會在你所在的位置開啟

清單會在你所在的項目上開啟 — 也就是這個路徑列所屬的筆記，或者，當點擊資料夾列出了它的上層時，就是那個資料夾 — 而不是在第一列。在一個有兩百篇筆記的資料夾裡，第一列離你可遠了。

**在名稱上滾動滾輪會開啟它的清單並在其中移動。** 第一次滾動會開啟與按下名稱相同的清單，之後每一次滾動都會把醒目提示移動一列，把你指到的東西準確地放進輸入欄，就像用方向鍵一樣 — 這樣不用鍵盤也能找到並選取同層的項目。往任一端轉出去，就會把你的文字還給你。當某一列的路徑比分頁還寬時，滾輪會改為橫向捲動作為回應，只要這種情況成立，這個解讀就優先。

清單**盡可能撐到視窗容許的高度**。Obsidian 把自己的建議清單限制在 300 像素，不管下面還有多少空間；這個清單則會一路延伸到視窗底部，只在離邊緣幾個像素處停下，而且只有在資料夾內容超過這個高度時才會捲動。它**不會比路徑列還寬**：放不下的名稱會像這一列縮短名稱那樣被截短，並在你指向它時完整顯示。

在清單中移動會**把你指到的東西放進輸入欄**，無論是用方向鍵還是用滑鼠指向 — 取代你原本在編輯的那一段，其餘路徑則維持不動 — 所以你所在的那一列，也就是你會得到的路徑。

路徑的其餘部分**只顯示到它在你所指之處底下實際存在的程度**。假設你站在某個資料夾中，正在編輯的那一段後面接著 `2026/note.md`，指向一個底下有 `2026`、`2026` 裡又有 `note.md` 的資料夾時，會顯示全部；指向一個有 `2026` 但沒有筆記的資料夾，只會顯示 `2026`；指向一個兩者都沒有的資料夾，名稱後面就什麼都不顯示，指向檔案時同樣如此，因為檔案底下不會有任何東西。**你已經輸入的內容**在輸入過程中會保留完整路徑，不論目前輸入了多少 — 打到一半的名稱還不算數。設定一個名稱進去才算數，而從那裡無法到達的部分就會在那一點被截斷；你正在建立的資料夾，是你在它*之後*輸入的那些，也就是 <kbd>Enter</kbd> 會建立它們的地方。
你輸入過的文字會被保留：移出清單**任一端** — 從第一項往上，或從最後一項往下 — 都會放開它，把你的文字還給你，且不會有任何醒目提示。輸入欄本身也是這個循環中的一站，就像任何一個項目一樣，所以繞一圈會經過它，而不是從最後一列直接跳到第一列，從那裡繼續按下去會繞到另一端。

把**指標移出清單**同樣會把你的文字還給你 — 並把醒目提示交還給滑鼠到來之前擁有它的那個項目：你原本用方向鍵到達的那一項，會重新顯示在輸入欄中，或者是清單一開始開啟時所在的那一項，因為那就是你所在的位置。用滑鼠指向是一種查看的方式，而不是選取的方式，所以指標掃過清單不會讓你付出任何代價。

清單本身在你於其中移動時不會改變 — 它仍然依照你輸入的內容篩選，而不是依照預覽進輸入欄的內容 — 所以你所在的那個項目，不會在下一次按下時從你腳下移開。輸入會取代預覽，並照常篩選。

**它篩選的依據是你正在編輯的那一段**，而不是輸入欄裡的全部內容。點擊資料夾會把路徑的其餘部分留在你正在修改的名稱後面，所以如果依照整個內容篩選，就會去找一個叫做 `2026/啟動.md` 的子項目，結果什麼也找不到 — 不管你輸入什麼，清單都會在你打第一個字時就關閉。**副檔名也被排除在篩選之外**，只要游標還在句點前面：點擊筆記名稱會選取主檔名，把 `.md` 留在後面，所以打一個字母，輸入欄就會變成 `a.md`，而那不是你要找的東西。把游標移到句點之後，副檔名就會和其他東西一樣列入計算。一個真的什麼都配不到的名稱，仍然會關閉清單，因為空清單就是誠實的答案。

預覽**只會交換那一段，其餘路徑不受影響**：指向一個資料夾，是在問「如果這一步換成那個會怎樣」，而不是把整條路徑丟掉。移出清單會恢復你原本的文字*以及*你原本的選取範圍，所以下一次按鍵取代的，是你在查看之前本來就要取代的東西。

## 清單中的每一列都是真正的檔案管理員項目

清單裡的每個檔案和資料夾，表現都與它在檔案瀏覽器中的那一列一致：

- **右鍵點擊**會叫出與檔案瀏覽器完全相同的操作選單，項目對項目一致 — 包括其他外掛加進去的項目。資料夾提供「*新增筆記*」、「*新增資料夾*」、「*新增白板*」、「*新增資料庫*」、「*製作副本*」、「*將資料夾移動到…*」、「*在資料夾中搜尋*」、「*複製路徑*」、「*在系統檔案總管中顯示*」、「*重新命名…*」和「*刪除*」；檔案則提供對應的選項，包括「*用預設應用程式開啟*」。
- **拖曳**一個項目到任何 Obsidian 接受檔案的地方：拖進編輯器以插入連結，拖到檔案瀏覽器中的資料夾上以移動它，拖到分頁列上以開啟它。

功能表文字來自 Obsidian 自己的譯文，因此在任何語言下都與應用程式其餘部分保持一致。

## 輸入路徑

- 點擊路徑列**前後的空白處**會開啟針對整條路徑的文字輸入欄，*並且在檔案總管中顯示這則筆記*，讓樹狀結構跟著窗格走，不用再多一個動作。它會**計算你按了幾次**：一次選取不含副檔名的路徑，兩次連副檔名一起選，三次選取電腦所認得的路徑。點擊**檔案名稱**的計算方式相同，但從低一階開始，也就是名稱本身：一次選取不含副檔名的名稱，兩次連副檔名一起選，三次則擴大到*從你的儲存庫資料夾起算*的整條路徑 — 這是連結或搜尋所需要的形式，而不是電腦所需要的。第四次按才會到達那個形式。
- **計數屬於開啟該欄位的那一連串按壓。** 一旦中斷 — 你停頓了、打字了、或在文字中某處單擊了一下 — 該欄位就變成和其他文字欄位一樣普通，在裡面雙擊會選取指標下的那個字，跟其他地方一樣。直接在選取的內容上打字即可覆寫，或就地編輯。（點擊檔名本身只會選取檔名；見上文。）在同一空白處按右鍵會**複製**同樣的三種選取，分別對應第二、三、四次按壓 — 一個按鈕負責顯示，另一個負責取用。**單次**右鍵按壓會開啟路徑並選取全部內容，並提供可對它做的動作：剪下、複製、貼上、全選，都用 Obsidian 自己的措辭。
- **在空白處按滑鼠中鍵**可貼上覆寫路徑：欄位會以*從儲存庫根目錄起算*的整條路徑開啟，因此剪貼簿內容會取代全部，貼上的內容會被選取。接著按 <kbd>Enter</kbd> 即可前往該處。
- **<kbd>Ctrl</kbd>+點擊空白處**會在自己的分頁中再次開啟這則筆記，並在檔案總管中閃爍提示，讓第二個分頁不會被誤認成第一個。在**儲存庫名稱**上，<kbd>Ctrl</kbd>+點擊或中鍵點擊會開啟一個空白分頁，停在儲存庫根目錄，並已顯示清單 — 方便你從頭輸入路徑。
- 在顯示路徑列時打字，會把最尾端那一段轉換成一個小型輸入欄，並提供限定在目前資料夾範圍內的即時自動完成。
- **可以輸入從檔案系統根目錄起算的路徑。** 在空白欄位前面加上 `/` 會開啟一個這樣的欄位，而不是完成某一階，之後的每個斜線都屬於它，而 `~` 則代表你的家目錄。當欄位中是這樣的路徑時，清單顯示的是電腦而非儲存庫，該列開頭那一段會讓開 — 欄位中的內容從根目錄開始，並會如實標示。若*存取外部檔案*關閉，清單則會維持空白，因為 <kbd>Enter</kbd> 反正也會拒絕該路徑。
- **可以直接輸入頁面，不只是點選它。** `:graph`、`:search`，或任何你的外掛程式所註冊的項目 — 也就是[儲存庫根目錄清單](#沒有檔案的分頁)所提供的標籤。在任何地方輸入冒號都會叫出它們，因為沒有任何名稱可以含有冒號，而 <kbd>Enter</kbd> 會在此窗格中開啟該檢視。在**資料夾內**輸入 `:graph` 會開啟該資料夾的圖表 — 也就是在其自己的搜尋欄中以 `path:"that/folder"` 篩選的圖表，如同直接輸入的一樣；在儲存庫根目錄則是整個圖表。<kbd>Tab</kbd> 會補完名稱，就像補完資料夾名稱一樣 — 並會一併帶走欄位中的其他內容，因為頁面不屬於任何資料夾，也沒有東西存在於其下。點擊這樣頁面上的標籤會開啟已含有該內容的欄位。
- **打字時會即時提供 <kbd>Tab</kbd> 會寫入的內容。** 只要每個以你所輸入內容開頭的子項目還持續一致，這份一致的部分就會出現在插入點之後，並被選取；一旦它們不再一致，該步驟就會朝向其中第一個 — 或朝向你用方向鍵移到的那一列，因為那正是 <kbd>Tab</kbd> 會前往之處。覆寫某個名稱時會保留其副檔名，並在其前方提供內容；剛進入的資料夾則會提供它的第一步，因此不存在什麼都沒提供、而 <kbd>Tab</kbd> 卻仍寫入內容的情況。輸入那些字母，它們就會被逐一吃掉；輸入其他任何內容，它就會消失。<kbd>Tab</kbd> 或 <kbd>End</kbd> 會整段取用，<kbd>→</kbd> 會取用其中一個字母，<kbd>Backspace</kbd> 會收回它而不動到你所輸入的字母，且在你再次打字之前不會再提供內容 — 因此永遠有辦法脫離一個你不想要的名稱。按下 <kbd>Tab</kbd> 之後，下一步會立即被提供，就像打了一個字之後一樣。清單所顯示的內容，篩選依據永遠是**你**輸入的內容，而不是曾被提供過的內容。
- **提供的內容不分大小寫。** `sch` 會提供 `Schemes`，拼法照該名稱本身；收回這項提供會把你輸入的字母原樣還給你。當 `Test` 和 `test` 都存在時，會提供拼法與你輸入相符的那一個。
- 在欄位中，被提供的部分只是單純**被選取**。清單則是拼出詳情的地方：每一列都會以**粗體**顯示與你所輸入內容相符的部分，不論匹配發生在名稱中的哪個位置 — `kick` 會找到 `Weekly kickoff` 並標示出來。**以你所輸入內容開頭的名稱會排在前面**，優先於只是包含它的名稱，並在邊緣以一條線標示：**藍色**代表它們與其他項目共享的部分比你輸入的還多，因此 <kbd>Tab</kbd> 對它們全部都還有東西可補；**綠色**則標示提供內容在分岔處所走的分支 — 以 `test1`、`test2`、`text1`、`text2` 為例，`te` 會提供 `te`+`st`，因此兩列 `test` 是綠色，兩列 `text` 則維持普通的線。每一列都會**畫底線標出 <kbd>Tab</kbd> 朝它會走的那一步**，不只是被提供的那一列，且底線會隨提供內容改變而跟著變動。
- **打字會放開目前反白的那一列。** 清單開啟時停在你目前所在的項目上，但一旦你打字，重點就轉移到別處了，而一個沒人主動選取的反白，讀起來卻像是已經做出的選擇。
- 提供的內容永遠只是你面前的文字：打字期間，你所輸入的字母會維持你輸入時的拼法，而採用該提供內容時會依資料夾的拼法重寫該名稱，因為路徑必須符合磁碟上的實際狀況。`sk` + <kbd>Tab</kbd> 會到達 `Skyline`，而不是 `skyline`。
- **欄位會呈現它所命名對象的顏色**，與其在清單中那一列相同的顏色：紫色代表筆記，包括資料夾自己的筆記；橘色代表非筆記的任何東西；藍色代表你目前所在的筆記。欄位取色的那一列，是名稱與你輸入內容完全相符的那一列，若沒有則是反白的那一列，再沒有則是你輸入內容仍指向的第一列。
- **一旦欄位中的內容找不到對應項目，欄位就會變紅** — 沒有檔案、沒有資料夾，清單中也沒有任何一列仍指向它。此時 <kbd>Enter</kbd> 會建立欄位中的內容，而不是開啟它，紅色會在你確認之前先行提示。它從不會在網址上出現，因為網址本來就不是這台電腦上要去尋找的地方。是**整個**欄位變色，而不只是缺漏的那部分 — 文字欄位無法只為自己內容的一半上色。在重新命名/移動模式中，欄位對於不合法的名稱會維持自己的紅色 — 在那裡，找不到對應項目的名稱正是重點。名稱**已被使用**的情況，會在你確認時才處理，並跳出對話框詢問該如何處理擋路的檔案 — 見[已被使用的名稱](#已被使用的名稱)：每個朝 `Notes.md`輸入的名稱，過程中都會經過一些可能本身就是檔案的名稱，因此逐字元標示會對根本還沒人要求過的名稱發出警告。
- `/` 會確認你正在輸入的這一段並進入其中，同時保留其後的內容 — 與 <kbd>Tab</kbd> 進入資料夾時的效果相同。
- 在空白輸入欄中按 <kbd>Backspace</kbd> 會退回上一層的父資料夾，重新開啟其名稱並將游標放在結尾。若前方只剩下一個副檔名獨自留著，按 <kbd>Backspace</kbd> 也會這麼做 — 一個只剩 `.md` 的欄位並未命名任何東西 — 於是那個孤立的副檔名也會一併消失。
- **欄位開啟時點擊某個資料夾，會將其擴大為該資料夾之後的整條路徑**，並選取該資料夾自己的名稱 — 效果與從清單中點擊它相同，且欄位原本保留的所有內容都會保留。欄位開啟時，其中內容就是該列的尾端，因此點擊更上層的資料夾，會交還這個作業階段所走過的路徑，而不是筆記一開始所在的路徑。
- **在欄位最前端按方向鍵，會把前面的資料夾帶進來**，彷彿整條路徑是同一行文字。當插入點位於最前端時，<kbd>←</kbd> 會把該資料夾帶進欄位並停在其名稱結尾，<kbd>Ctrl</kbd>+<kbd>←</kbd> 會停在其開頭，而 <kbd>Home</kbd> 會一次帶入直到儲存庫根目錄 — 或直到你所選的位置，若在儲存庫之外 — 的每個資料夾。按住 <kbd>Shift</kbd> 選取範圍會隨之延伸涵蓋帶進來的內容。在 macOS 上，跳字是 <kbd>Option</kbd>+<kbd>←</kbd>，<kbd>Cmd</kbd>+<kbd>←</kbd> 則等同於 <kbd>Home</kbd>。除了最前端之外，這些都是普通的文字編輯鍵。**清單顯示期間，<kbd>Home</kbd>、<kbd>End</kbd>、<kbd>PgUp</kbd> 和 <kbd>PgDn</kbd> 屬於清單所有** — 分別是第一列、最後一列、上一頁、下一頁，「一頁」指的是清單目前所顯示的內容，反白的那一列會維持在畫面上的相對位置 — 只有在清單關閉後才會作用於文字；清單開啟時，<kbd>Shift</kbd>+<kbd>Home</kbd> 一樣會帶入每個資料夾。
- **清單會跟著插入點走。** 選取路徑中不同的部分 — 拖曳選取、點入其中，或用方向鍵移動 — 清單就會顯示*那個*資料夾的子項目，而不是欄位一開始開啟時所在的那個。資料夾的認定方式是以各區塊加上插入點前方欄位中的內容為準，因此在內容為 `2026/Notes.md` 的欄位中點入 `Notes.md`，會顯示 `2026` 中的內容。指向某一列會把它寫入插入點所在的那一段，而把指標移開清單則會把你的文字和選取內容原封不動還給你。
- **把選取範圍拖出欄位**後在別處放開，並不會關閉它。在欄位內開始的按壓，不論拖到多遠都屬於這次編輯；只有*開始*於欄位外的按壓，才算是點擊到別處。
- <kbd>Enter</kbd> 會確認 — 而當欄位完全沒有命名任何東西時，例如在一個空資料夾中，根本沒東西可以補完，它會顯示*未選取任何檔案*並維持開啟，而不是像已經選了什麼一樣關閉。<kbd>Esc</kbd> 或點擊別處會取消並還原成檔案的真實路徑。按一次 <kbd>Esc</kbd> 就夠了：它會關閉清單、離開欄位並把焦點交還給筆記，而不是每一層都要按一次。

輸入欄毫無修飾 — 沒有方框，沒有邊框 — 因此讀起來就是路徑文字本身，並且會隨輸入自動伸長。

**第二下按鍵跟隨第一下。** 建立資料夾筆記的位置，落在該列中*開啟*該資料夾的那個部分——預設是分隔符，關掉互換後則是資料夾名稱——與底線標記的目標相同，也是單擊已經要求資料夾筆記的同一個目標。只有在資料夾筆記外掛程式正在執行時才會提供這個選項，因為資料夾筆記是一種慣例，而非檔案系統的事實，而且只在該資料夾還沒有資料夾筆記時才會提供。它存放在哪裡、叫什麼名字，是從**資料夾筆記**自己的設定讀取的，所以把資料夾筆記放在資料夾旁邊、或叫它 `_index` 的儲存庫，會得到相應的那一種；檔案本身永遠是 Markdown，這正是該外掛程式自己的預設建立指令所產生的內容，也是它在儲存庫設定為任何類型時所能找到的內容。重新命名/移動模式完全不在此列——當有移動待處理時，這一列上沒有東西會開啟資料夾。

**點擊名稱會持續進行下去。** 這四個階段和重新命名鍵所走的四個階段相同，順序也相同：名稱、帶副檔名的名稱、從儲存庫算起的路徑、從系統根目錄算起的路徑。所以第三次點擊會到達儲存庫路徑，第四次會到達機器的路徑——這與 <kbd>Tab</kbd> 越過欄位結尾所給你的四樣東西相同，也與右鍵按鈕*複製*而非選取的四樣東西相同。

**懸停**是它自己的答案，而且從不改變任何東西：只要你指著一個縮短的名稱，它就會完整顯示出來，而列開頭的圖示則說明儲存庫位於何處。

| 按在哪裡 | 一下 | 兩下 | 三下 |
| --- | --- | --- | --- |
| **儲存庫名稱** | 儲存庫的右鍵選單：對這個段落名稱所指的儲存庫可以做的事——包括*開啟此儲存庫*，若那個儲存庫不是你目前所在的那個 | 複製儲存庫的名稱 | 複製儲存庫的所在位置——第四下則複製開啟中檔案的所在位置 |
| **分隔符** | 該資料夾的選單——若有資料夾筆記外掛程式在執行且該資料夾有資料夾筆記，則是該筆記的選單 | | |
| **資料夾名稱** | 該資料夾的選單 | 複製資料夾的名稱 | 複製它以及它右邊的一切 |
| **筆記名稱** | 檔案的選單——與檔案總管該列所給的相同 | 複製名稱 | 連同副檔名一起複製 |
| **空白處** | | 複製從你的儲存庫資料夾算起的路徑，不含副檔名 | 相同，但包含副檔名 |

在**儲存庫名稱**上按一下，會開啟該段落所命名的對象可以做的事。對於**你目前所在的儲存庫**：在新視窗中開啟它、管理儲存庫、複製它的所在位置、複製它的 ID、在你的檔案管理員中顯示它。對於透過位置清單所到達的**另一個儲存庫**，則是同樣的選項扣掉新視窗——那會開啟*這個*儲存庫，而不是那個——再加上唯一一項只有非你所在儲存庫才能提供的東西：**開啟此儲存庫**。它是以其 ID（而非資料夾名稱）向 Obsidian 命名的，因為兩個儲存庫可能共用同一個資料夾名稱。對於根本不是儲存庫的地方——你的家目錄、一個掛載的磁碟機——沒有 ID 可以複製，也沒有東西可以開啟，選單會以不提供這些選項來表明這一點。

這不是 Obsidian 自己的三點選單，那個屬於啟動視窗，無法從正在執行的儲存庫內部開啟——這些是同樣的項目重新建立而成，用 Obsidian 自己的措辭，取自它的指令，所以會以你的語言出現。該選單的三個項目刻意**沒有**出現在這裡：*重新命名儲存庫*、*移動儲存庫*和*從清單中移除*都是作用在儲存庫自己的資料夾或 Obsidian 的儲存庫登錄上，而對你正站在其中的儲存庫——其檔案已開啟、監看程式正在執行——做這些事，正是儲存庫損壞的原因。請開啟儲存庫管理員（*開啟其他儲存庫*）並在那裡進行，那時儲存庫是關閉的。

**空白處**上的兩種複製，是這一列如實寫出的樣子——連結或搜尋所需要的東西——而**儲存庫名稱**上的則是檔案系統所知道的路徑，這是 Obsidian 之外的任何東西所需要的。那裡每按一下，都會擴大複製結果的用途：兩下給出儲存庫的名稱，三下給出儲存庫的所在位置，四下給出開啟中檔案的所在位置。Obsidian 自己的兩個指令，*從儲存庫資料夾*和*從系統根目錄*，也做出同樣的區分；這裡對外的那些選項，落在路徑本身之外的那個段落上。

以上這些在儲存庫之外也同樣適用，作用在相同的目標上。

每次複製都會以通知的方式告知，因為複製不會在畫面上留下任何痕跡來顯示它發生過，而按錯次數的按鍵不應該看起來像成功的一次。

## 修飾鍵：在別處開啟它

筆記名稱和資料夾段落的行為，與它們在檔案總管中的列相同。

| | 在筆記名稱上 | 在資料夾段落上 |
| --- | --- | --- |
| 一般點擊 | 編輯名稱 | 瀏覽該資料夾 |
| <kbd>Ctrl</kbd> / 中鍵點擊 | 在新分頁中開啟筆記 | 將資料夾送到新分頁 |
| <kbd>Ctrl</kbd>+<kbd>Alt</kbd> | 分割視窗 | 分割視窗 |
| 拖曳 | 筆記，可拖到 Obsidian 能接受檔案的任何地方 | 資料夾，同樣如此——包括分頁列 |

資料夾不是 Obsidian 能開啟的東西，所以把它送到分頁會做以下兩件事之一：若有資料夾筆記外掛程式在執行且已有資料夾筆記，就開啟其資料夾筆記；否則開啟一個空白分頁，其路徑列已經停在該資料夾——只留下名稱讓你輸入。把資料夾段落拖放到**分頁列**上會做同樣的事，在你放開的地方開啟新分頁——Obsidian 的分頁列本身只接受檔案，所以從檔案總管拖出來的資料夾在那裡仍然會被拒絕。

## Tab：先補完名稱，再補完路徑，最後擴大選取範圍

<kbd>Tab</kbd> 的補完方式和 shell 一樣：**按一下會把你打的字延伸到那個資料夾裡各個名稱一致的地方為止，遇到分歧就停下。** 打 `Sk`，如果只有 `Sketches` 是這樣開頭，這個字就補完了；打 `Al`，如果 `Alpha-one`、`Alpha-two` 和 `Alpine` 都是這樣開頭，你會得到 `Alp`，因為下一個字元是只有你才能回答的問題。

不打字直接再按一次，就會朝某一個名稱前進 — 清單中被反白的那一列，或第一列 — 並在那個名稱的下一個分歧處停下：先是 `Alpha-`，然後是 `Alpha-one`。清單會依你目前所在的位置開啟，所以在你自己的資料夾裡，第一次按下會朝你正打開的筆記前進，而不是排序上排在最前面的那個。

**按一下絕不會替你在名稱之間做選擇。** 一旦你打的字只剩下一個候選項，或你已經打出資料夾的完整名稱，且沒有*別的資料夾*能再延伸它，<kbd>Tab</kbd> 才會進入那個資料夾。若還有別的能延伸 — 例如 `Schemes` 旁邊有 `Schemes2026` — <kbd>Tab</kbd> 會繼續朝較長的名稱補完；<kbd>Enter</kbd> 和清單才是表示「就是這個」的動作。

**檔案**絕不會這樣擋住資料夾。與自己同名的資料夾旁邊放著一則筆記，那是資料夾筆記，不是路徑上的分岔，而 <kbd>Tab</kbd> 走的是資料夾 — 所以 `Projects` 旁邊即使有 `Projects.md`，也會像其他資料夾一樣被進入。

由此衍生出兩件較小的事：填入欄位的拼法，會照該資料夾本身的拼法來寫，所以 `sk` 會變成 `Sketches`；而且只有正在輸入的那個名稱會被取代，所以路徑右邊若還有其他內容，會被保留下來。

當輸入時已經有名稱可供選用，<kbd>Tab</kbd> **會精確寫下那個候選項**：候選項一律就是按下時會寫入的內容，清單中的底線和綠線說的是同一件事，所以插入點之後看到的就是你會得到的結果。名稱不再一致的地方，就是朝其中第一個名稱邁進的那一步 — 或是朝你用方向鍵移到的那一列邁進，<kbd>Tab</kbd> 會採用那一列而非旁邊那一列 — 所以在按下之前，用方向鍵移到你要的那個，或把分岔點打過去。只有當候選項只剩下*一個*名稱時，同樣的按下才會進入它。

抵達檔案名稱本身**就是**第一階 — 不會多花一次按下把插入點移到即將標記的名稱末端。從那裡開始，按下就不再沿路徑移動，而是開始擴大選取範圍：

1. 名稱
2. 含副檔名的名稱
3. 從你的儲存庫資料夾起算的路徑
4. 從系統根目錄起算的路徑
5. 回到路徑的最前端，**以目前的樣貌**呈現 — 停在走動開始的地方，第一段被標記，準備再走一輪

第四次點擊會直接抵達同樣的第四階。

擴大範圍就只會**擴大**。已經在欄位中完整存在的名稱 — 不論是被同一個鍵補完的，還是從清單中選出的 — 會被整個標記，而不是先把副檔名拿掉再標記：第一階是給剛*抵達*的名稱用的，此時副檔名還不是討論的重點。

這個階梯是走動**抵達之處**，不是起點。點擊路徑中間的某個資料夾，欄位會開啟顯示其下的所有內容，並標記該資料夾的名稱；接下來每按一次 <kbd>Tab</kbd> 就會進入**一個**資料夾 — 標記下一個，並保留其後的路徑 — 直到只剩下檔案名稱時，擴大選取才會開始：

| 按下 | 分段標籤 | 欄位內容 | 被標記 |
| --- | --- | --- | --- |
| 點擊了 `a` | | `a/b/c/leaf.md` | `a` |
| <kbd>Tab</kbd> | `a` | `b/c/leaf.md` | `b` |
| <kbd>Tab</kbd> | `a › b` | `c/leaf.md` | `c` |
| <kbd>Tab</kbd> | `a › b › c` | `leaf.md` | `leaf` — 第一階 |
| <kbd>Tab</kbd> | `a › b › c` | `leaf.md` | `leaf.md` |

**一個名稱一旦被定下來，不論你用什麼方式定下，都是定下了。** 用 <kbd>Tab</kbd> 補完它、用 `/` 送出它、從清單中挑選它，這三種方式最後都會讓這一列停在同一個位置，持有同一個路徑，所以動作之後的下一次按下，不論你是怎麼走過來的，意義都相同。以前從清單中挑選資料夾會清空欄位，把原本用 <kbd>Tab</kbd> 抵達同一個資料夾時會保留的路徑給丟掉。

**還在輸入中的路徑會整段一起跟過來。** 進入路徑其餘部分所掛靠的那個資料夾，並不代表其餘部分已經存在 — 這正是路徑在完成之前就先被打出來的方式，而它所命名的那些資料夾，正是 <kbd>Enter</kbd> 即將建立的資料夾。所以從 `Dokumente/plans/untitled.md` 走進 `Dokumente`，`plans/untitled.md` 仍會留在你面前，不論 `plans` 現在是否存在。從無到有打出來的路徑也是同樣道理：沒有任何一段是從別處繼承來的，所以也沒有任何一段會被拿掉。

**把某一步換成別的步，情況就不同了，這時路徑只會跟到真正存在的地方為止。** 把路徑中間的某個資料夾換成同層的另一個 — 點擊 `a`，打入另一個名稱，按下 <kbd>Tab</kbd> — 其下的一切都會跟著你，因為你原本所在的路徑，通常就是你想要的路徑的大部分。不過，只有在那邊真正存在的東西才能撐過這次轉換，所以欄位和旁邊的清單永遠不會互相矛盾：留在你面前的，會是一條你真的能走下去的路徑。從 `a/b/c/leaf.md` 開始，點擊 `a` 並標記其名稱：

| 你定下的內容 | 分段標籤 | 欄位內容 | 被標記 |
| --- | --- | --- | --- |
| `x`，完全沒有 `b` | `x` | | 沒有任何東西跟過來 |
| `y`，有 `b` 但裡面沒有 `c` | `y` | `b` | `b` |
| `z`，從頭到尾都是 `a` 的雙胞胎 | `z` | `b/c/leaf.md` | `b` |

這樣單獨留下來的資料夾，仍然是一個可以走進去的資料夾：接下來的按下會進入它，而不是開始在它的名稱上擴大選取範圍。

資料夾裡**沒有任何東西**能對上的名稱，處理方式不同，因為沒有東西因它而被定下：按下會標記你打的字，讓你可以直接打字覆蓋，而不是回答成別的地方。

整套機制是一個**迴圈，繞一圈不花任何成本**：最後一階之後再按一次，會把這一列交回路徑的最前端，連同各個資料夾一起，準備再繞一輪。唯一會離開這一列的，是絕對路徑前綴，在停止顯示它的那次按下時。

回來的是**你走出來的路徑**，不是你出發時的那條。中途分岔走動 — 從清單中挑選另一個同層項目、朝另一個名稱補完 — 這一圈就會收束在你實際所在的位置；在它之前的四階描述的正是同一條路徑，而這一階以前才是那個描述過去的例外階。

<kbd>Shift</kbd>+<kbd>Tab</kbd> 是往反方向合上同一個環：在路徑最前端，已經沒有東西可以再交還，也沒有更上層可去時，下一次按下會跳到**最遠**那一階 — 從系統根目錄起算的路徑 — 然後從那裡繼續縮小範圍。兩個方向都不會走到死路。

它也不會在已經顯示過的那一階上多花一次按下。在最後一階之下 — 不含副檔名的名稱 — 階梯就結束了，*同一次按下*就會離開資料夾：從系統根目錄起算的路徑、從你的儲存庫起算的路徑、名稱、不含副檔名的名稱，接著是資料夾，每一步各一次。

同樣地，若某一階不會改變任何東西，也不會多花一次按下：點擊一則筆記的名稱時，本來就已經顯示不含副檔名的樣子，那正是第一階要顯示的內容，所以從那裡開始，<kbd>Tab</kbd> 會從第二階起算。

每一階改變的是欄位**裡**的內容，而不只是反白顯示的部分 — 選取範圍必須涵蓋它所指稱的文字，否則 <kbd>Enter</kbd> 送出的東西就會和你看到被選取的內容不一致。這個階梯屬於單一次編輯過程：只要點到別處，或打了任何字，下一次 <kbd>Tab</kbd> 就會重新開始補完名稱。

### <kbd>Shift</kbd>+<kbd>Tab</kbd>：同一條路倒著走

<kbd>Shift</kbd>+<kbd>Tab</kbd> 會按照原本按下的順序，每次收回一步：選取範圍每次縮小一階，每一次補完都會被交還，每一個資料夾都會被退出 — 它的名稱回到欄位中，讓你可以編輯而不必重新打過。

**回程途中不會刪除任何東西。** 一次補完會被*標記*它所新增的字元交還回來，就跟前進時標記它所擴大的部分一樣 — 名稱依然留在你面前，接下來每按一次，就會多標記一步：

| | 欄位內容 | 被標記 |
| --- | --- | --- |
| 走進來的結果 | `Alpha-one` | |
| <kbd>Shift</kbd>+<kbd>Tab</kbd> | `Alpha-one` | `one` |
| <kbd>Shift</kbd>+<kbd>Tab</kbd> | `Alpha-one` | `ha-one` |
| <kbd>Shift</kbd>+<kbd>Tab</kbd> | `Alpha-one` | `Alpha-one` |

打字會取代被標記的部分，跟其他地方一樣。<kbd>Tab</kbd> 會準確地放回標記交還的內容，所以往外走兩步、再往內走兩步，會回到原本所在的位置。

一旦整個名稱都被標記，就沒有任何一次按下留下的東西可再收回，下一次按下就會*沿路徑往上走*：它會離開你目前所在的資料夾，就跟在空白欄位上按 <kbd>Backspace</kbd> 一樣。這同樣不花任何成本 — 資料夾的名稱會回到欄位中，出現在原本內容的**前面**，並被標記，這和點擊那個資料夾所得到的文字完全一樣。往回走是一種方向，而不是復原歷史 — 但先標記名稱，就能確保不會有一次按下同時收回你打的字，又把你帶出你原本打字的那個資料夾。

一開始就**已經被選取**的文字 — 也就是點擊資料夾後留下的內容 — 正是 <kbd>Tab</kbd> 接下來會處理的名稱：它會像其他名稱一樣被補完並被進入，打字也會取代它。只有聚焦指令會直接開啟在階梯本身的某一階上，因為它顯示給你的是整條路徑，而不是一個可以走進去的資料夾。

## 打字打出不是路徑的東西

| 你打的內容 | 會發生什麼事 |
| --- | --- |
| `https://…` | 若你已啟用 Obsidian 的**網頁檢視器**核心外掛，就會在新分頁中開啟；否則會用你電腦上的瀏覽器開啟 |
| `obsidian://…` | 交給 Obsidian 自己的 URI 處理器處理 |
| `file:///…` | 解碼並開啟：如果在你的儲存庫內，就當作真正的筆記；否則就在檢視器中開啟 |
| `/home/you/a%20b.md` | 效果相同，適用於從瀏覽器或檔案管理員貼上的路徑 |

只有明確的通訊協定會被視為協定 — 一則名為 `100%20` 的筆記依然是一則筆記。屬於某個協定的 `/` 會保持原樣，而不會往下進入資料夾，這樣一個網址就能用手打出來，而不只是貼上。

## 給鍵盤使用的指令

**聚焦路徑列**會在筆記名稱上開啟欄位，並像 <kbd>F2</kbd> 一樣走過各階 — 名稱、含副檔名的名稱、從你的儲存庫起算的路徑、從系統根目錄起算的路徑 — 之後再按一次會關閉欄位，把游標放回筆記裡。它不會重新命名：<kbd>Enter</kbd> 是導覽，就跟其他欄位一樣。它預設沒有自己的按鍵，因為 Obsidian 的方針不鼓勵外掛預先佔用按鍵；本外掛設定最後的「快速鍵」一列，會開啟只顯示本外掛指令的*設定 → 快速鍵*，讓你可以在那裡設定。

## 導覽從不碰觸開啟中的檔案

在預設的（導覽）模式下，目前開啟的筆記**絕不會**被重新命名或移動。

- 若路徑指向一個既有檔案，就會開啟它。
- 若路徑尚不存在，就直接建立，連同任何缺少的上層資料夾，並開啟它。以這種方式建立的每個檔案和資料夾都會在通知中告知你 — 新資料夾原本不會有任何提示，直到你去找它才會發現 — 而 Obsidian 自己的垃圾桶讓你只需一個按鍵就能復原不想要的結果。
- **在儲存庫之外，仍然會先詢問。** 在那裡，同樣的打字錯誤會寫進系統資料夾，而通知和 Obsidian 的垃圾桶都幫不上什麼忙。

## <kbd>Ctrl</kbd> — 新分頁，以及複製而非移動

在儲存庫內**建立、移動或複製**的筆記，會在檔案瀏覽器中顯示它落腳的位置，並短暫以 Obsidian 的強調色標記出來 — 你事後會到樹狀結構裡找它，所以會直接呈現在你面前，而不是留在一個可能根本沒展開的資料夾裡。複製也是如此：複製會讓原本的檔案留在原處，並在自己的窗格中開啟副本，若不加說明，很容易讓人誤以為什麼都沒發生。

在從清單中挑選檔案時，或在某個路徑上按 <kbd>Enter</kbd> 時按住 <kbd>Ctrl</kbd>（macOS 上是 <kbd>Cmd</kbd>），會把結果送到**新分頁**而不是目前這個：

| | 直接操作 | 按住 <kbd>Ctrl</kbd> |
| --- | --- | --- |
| 挑選或輸入一個既有檔案 | 在此處開啟 | 在新分頁開啟 |
| 輸入一個不存在的路徑 | 先詢問，然後在此處開啟 | 先詢問，然後在新分頁開啟 |
| 在重新命名/移動模式下送出路徑 | 把筆記**移動**到那裡 | 把它**複製**到那裡，並在新分頁開啟副本 |

輔助鍵按 Obsidian 自己的規則讀取，因此其行為與在連結或檔案瀏覽器項目上完全一致 — 按中鍵同樣表示「新分頁」，<kbd>Ctrl</kbd>+<kbd>Alt</kbd> 表示分割，<kbd>Ctrl</kbd>+<kbd>Alt</kbd>+<kbd>Shift</kbd> 表示新視窗。

複製時會拒絕覆寫，跟移動一樣 — 包括複製到筆記自己的路徑上，那樣做沒有任何意義。在儲存庫之外，這個拒絕動作同樣會明確告知你。

**清單開啟時**這一切也同樣適用：在被反白的那一列上，輔助鍵會套用到那一列；若沒有停在任何一列上，就會套用到你打的內容。

## 瀏覽儲存庫之外

**此項預設關閉。** 請先在設定中開啟 **存取外部檔案** — 在儲存庫之外讀寫是這個外掛所做的、而 Obsidian 自己不做的唯一一件事，所以它被設計成需要主動開啟，而不是主動關閉。關閉時，儲存庫名稱只是在檔案瀏覽器中顯示你的儲存庫，這裡的任何東西都不會望向它之外。

點擊**儲存庫名稱**（或在 *顯示儲存庫名稱* 關閉時點擊 🏠 圖示）會開啟一個地點清單，而不是內容清單。它打開的欄位會裝著**你原本所在的整條路徑，完整寫出**，並選取它開始的那個地點 — 所以挑選別的地方，或蓋掉選取的部分打字，都只換掉開頭那一段，其餘路徑仍留在你面前。**再按一次名稱** — 也就是雙擊 — 選取範圍就會擴展到整個名稱，這就是一整個絕對路徑能一次動作就選取、而不必手動掃過去的方式。改變主意的話，<kbd>Esc</kbd> 會把這一列還原成原樣。

在這裡打字，和別處一樣會補完地點名稱的其餘部分，而 <kbd>Tab</kbd> 會**帶入那個地點** — 你正指著的那一個，或名稱唯一能指的那一個。當還有好幾個地點共用你已輸入的內容時，按鍵會停在分岔處，就像在別處一樣。指向某個地點時會顯示**那個地點自己的路徑**，全部選取，後面接著你的筆記路徑，但只延伸到它在那邊真正存在的程度 — 這正是挑選它會把你帶到的位置。地點不是畫面上路徑裡的一段，而是計算整條路徑的起點，所以你原本所在之處不會留在它前面。

可選擇的地點有：

- **你的其他儲存庫**，讀自 Obsidian 自己的紀錄，最近開啟的排在前面，各自帶著 Obsidian 自己的儲存庫圖示 — 也就是應用程式在儲存庫相關指令裡用的那一個。已經開啟的那個儲存庫改用一棟房子：預設情況下這一列就從那裡開始，它不是一個要去的地方。
- **主資料夾**，在自己的帳號名稱下，以一個 `~` 標示。Lucide 沒有波浪號，所以這一個由外掛按 Lucide 自己的 24×24 格線、用同樣的線寬繪製 — 它是這套圖示缺少的一枚圖示，而不是混在圖示當中的一個文字字元。
- **檔案系統根目錄**，標為 `root` — 不作翻譯，因為在任何系統上它都叫這個名字 — 而不用 `/`，那樣在緊接其後的分隔符旁邊會讀成空空的一段。
- **已掛載的磁碟機**，在判斷成本低廉之處按類型配圖示：網路共用、光碟、軟碟和可攜式媒體各有其圖示；其餘一律用通用磁碟機圖示。在 Windows 上磁碟機顯示為 `C:` 並配通用圖示 — 磁碟區名稱與精確類型需要 WMI，這是刻意不去做的。

挑選另一個儲存庫**不會把 Obsidian 切換過去。** 你開啟的一切照舊開著，只是路徑列開始在那邊瀏覽。把它放在路徑列上、而不是交給側邊欄的儲存庫切換器，意義正在於此。

它落地的位置也會**盡可能貼近你正在看的筆記，直到那個地點實際能延伸到的程度**。

- 如果你挑的地點*包含*這則筆記 — 主資料夾，或你儲存庫所在之處 — 你會得到從那裡算起的路徑：在開著 `takeaways.md` 時挑選 `~`，欄位會讀作 `Vaults/your-vault/takeaways.md`。
- 如果它是與目前這個並列的地點 — 另一個儲存庫、另一個磁碟機 — 系統會嘗試同樣的相對路徑，能存在多深就到多深。儲存庫之間常常近乎彼此的複本，而跳過去的理由通常就是那邊的同一則筆記。

無論哪種情況，這一列都停在你挑選的地點，並且**那條路徑的第一個資料夾會以選取狀態開啟**，與點擊某個資料夾所呈現的形狀相同：跳到別處時你最有可能改動的那一段就是最靠近開頭的那一段，而你更動它的同時其餘路徑仍然可見。任何預先填入的內容都是磁碟上真實存在的東西。

### 在外面時

路徑**從你挑選的地點開始**，而不是從這台機器的目錄結構開始 — 點擊空白處或按下聚焦鍵所得到的欄位也是如此：它裝著從那個地點算起的路徑，而不是這台機器的絕對路徑，路徑軌跡收合到那個地點本身，正如它在儲存庫內收合到儲存庫根目錄一樣 — 選擇 `Archive`，這一列會讀作 `Archive / notes / …`，而不是 `/home/you/Vaults/Archive/notes/…`。開頭那一段帶著代表其身分（儲存庫、主資料夾、磁碟機）的圖示，而 <kbd>Backspace</kbd> 會停在那裡，不會繼續往上走進檔案系統的其餘部分。在 *顯示儲存庫名稱* 關閉時，那一段就只剩圖示 — 這項設定管的是這一列的起始段，無論它指的是哪個儲存庫，不只是你自己的那個。

只要路徑列指向儲存庫之外，它就一直**以錯誤色描邊** — 與重新命名模式所畫的是同一個框。它標記的是一種持續狀態，而非某個瞬間：只要它還在，Obsidian 自己的那套處理就都不適用於這一列所顯示的內容，並且在你另行表態之前寫入始終是鎖定的。

除此之外，瀏覽與在儲存庫內一樣：小方塊、分隔符、輸入、自動完成、用 <kbd>Backspace</kbd> 退出。可見性規則同樣適用，所以不受支援的副檔名仍需要 Obsidian 的 *偵測所有的副檔名*，點檔案仍需要本外掛的設定。

**在外面右鍵也能用**，不過是不同的選單：檔案瀏覽器自己的處理程式需要一個儲存庫認得的檔案，所以外面的項目改由路徑建構而來。它們提供開啟（在此處、在右側、在新視窗中，或用桌面的預設應用程式開啟）、*複製路徑*、*在系統檔案總管中顯示*，以及 — 一旦鎖頭打開後 — *新增筆記*、*新增資料夾*、*製作副本*、*重新命名…* 和 *刪除*。**拖曳**仍然需要儲存庫檔案，因此依舊無法使用。

同樣的選單也出現在檢視器中開啟的檔案上，透過右鍵或該窗格自己的三點選單皆可，而它會詢問那個檢視標題列裡的鎖頭。它不會問別的：檔案是以呈現方式還是原始碼方式顯示，都不影響它能不能被刪除，圖片或 PDF — 這些根本沒有原始碼檢視 — 和筆記一樣可以刪除。*刪除* 指的是移到桌面的資源回收桶，因此可以從那裡復原；沒有資源回收桶的系統會回報這一點，而不是直接銷毀檔案。

在儲存庫之外刪除，會把檔案移到你的**系統資源回收桶** — Windows 上是資源回收筒，macOS 上是垃圾桶 — 絕不會是直接解除連結。在外面沒有 Obsidian 自己的垃圾桶可以復原，所以一個無法復原的刪除根本不會提供：在沒有資源回收桶的平台上，嘗試操作會回報失敗，而不是直接銷毀檔案。

### 寫入儲存庫之外

任何寫入動作**預設都是鎖定的**。只要這一列指向儲存庫之外，標題列中重新命名切換鍵的位置就會被一把**紅色鎖頭**取代 — 顏色與這一列周圍的框相同，理由也相同：它標記的是一種拒絕。兩者是同一個位置上的同一個控制項，所以永遠不會有「哪一個管哪一件事」的疑問。

三次按下，循環一輪：

| 按下 | 得到什麼 |
| --- | --- |
| 紅色鎖頭 | 允許在此寫入。鎖頭被重新命名/移動切換鍵取代 |
| 切換鍵 | 重新命名/移動模式，與儲存庫內完全一樣 |
| 再次按切換鍵 | 模式結束，鎖頭再度關上 — 這項授權不會活得比它為之開啟的那件事更久 |

**重新命名鍵也會詢問鎖頭。** 在儲存庫之外按下它，會讓鎖頭一開一關地閃一下，而不是打開一個每次提交都會被拒絕的模式：拒絕發生在動作之前，而不是之後。按下鎖頭，或在半秒內再按一次重新命名鍵 — 第二次按下所授予的正是那個按鈕所授予的，只是限於這個地點，並隨之開啟重新命名模式。

在儲存庫內沒有鎖頭：沒有什麼需要解鎖，切換鍵直接佔著那個位置。

這項授權是**授予某個地點，而不是某個瞬間**：在同一個地點工作時你會做的所有事 — 完成一次移動、點掉輸入框、開啟一個檔案 — 都不會讓它失效，直到你從清單中挑選另一個儲存庫、磁碟機或根目錄，或這一列回到某個儲存庫檔案，或第三次按下為止，它才會結束。所以在同一個資料夾裡連續進行多次移動只需要按一次，不必每個檔案都按一次。

鎖頭打開後，路徑列在外面的表現與在裡面一樣：

| 操作 | 結果 |
| --- | --- |
| 輸入一個不存在的名稱，按 <kbd>Enter</kbd> | 與在儲存庫內相同的「要建立嗎？」詢問；缺少的上層資料夾也會被建立。不帶副檔名的名稱會變成 `.md`，與在儲存庫內完全一樣 |
| 重新命名/移動模式，輸入新名稱 | 重新命名這一列所顯示的檔案。不帶副檔名的名稱會保留該檔案原有的副檔名 — 在外面，一個資料夾裡什麼類型的檔案都有，重新命名不該悄悄把 `.png` 變成 `.md` |
| 重新命名/移動模式，瀏覽到別處，選擇**保留此名稱** | 以它現有的名稱移動過去 |
| 在以上任一操作中按住 <kbd>Ctrl</kbd> | 改為複製而非移動，並在新分頁開啟副本 |

處於鎖定狀態時，以上各項都不會發生，而是回報是什麼擋住了它們。兩種狀態下都絕不會覆寫任何東西：已存在的目標會被拒絕，而這個拒絕來自檔案系統本身（`COPYFILE_EXCL`，一次獨占式建立），而不是某個可能輸掉競爭條件的檢查。跨檔案系統的移動 — 從 USB 隨身碟、從網路共用 — 會退回到「先複製後刪除」，並且只有在副本落地之後才會刪除原檔。

**把筆記移*出*你的儲存庫會先詢問。** `fileManager` 無法跨越那道邊界追蹤一個檔案：每個指向這則筆記的連結都會失效，沒有任何東西會更新它們，而這則筆記也會從儲存庫的索引中消失。所以這次移動會以一個決定的形式提出，而不是直接拒絕或悄悄完成 — 一個對話方塊會說明代價，以及有多少筆記連結到你正在移動的這一則。確認後它就真的移動：先複製出去，再透過 Obsidian 自己的刪除功能從儲存庫移除，因此它和一則被刪除的筆記一樣可以復原，而其中任一步失敗都會讓筆記留在原處。按住 <kbd>Ctrl</kbd> 仍然是改為複製出去，這樣就完全沒有上述問題。反方向 — 把外部檔案帶*進*儲存庫 — 目前還沒有實作。

### 開啟外部檔案

瀏覽檔案系統可以一路走回**你正開著的儲存庫**內 — 從根目錄、從主資料夾、從你儲存庫所在的任何地方。以這種方式抵達的檔案是一則普通筆記，所以會以筆記的樣子開啟：真正的編輯器、連結與反向連結，而這一列也會彈回以儲存庫為根的路徑列。只有 Obsidian 沒有檢視可用的檔案才會留在預覽中，因為在外面，預覽才是比較好的答案。若某個預覽正這樣顯示著這樣一則筆記 — 比方說一個重新開啟的工作區 — 它的頂端那一列會提供**在*（儲存庫）*中開啟**，這與你手動做出的選擇是一樣的。

Obsidian 的編輯器只對儲存庫內的檔案作用，因此外部檔案**無法**作為帶連結、反向連結等等的真正筆記開啟 — 這是應用程式的限制，不是本外掛的限制。挑選一個外部檔案會改為開啟**預覽**，在你另行表態之前是唯讀的：

| 類型 | 顯示為 |
| --- | --- |
| `.md`、`.markdown` | 呈現後的 Markdown |
| `.html`、`.htm`、`.xhtml` | 呈現後的網頁 |
| 圖片、音訊、影片、PDF | 原生播放器／檢視器 |
| 其他任何**文字**檔案（`.json`、`.css`、`.log`、`.txt` 等） | 逐字的純文字 |
| 沒有檢視器的二進位格式（`.zip`、`.exe` 等） | 交給 *以預設應用程式開啟* |

檢視器對一個檔案有兩種讀法，而由於兩者互斥，只會顯示你將要**切換到**的那一種：

| | 作用 | 預設用於 |
| --- | --- | --- |
| **以 Markdown 檢視** | 將檔案當作筆記呈現，唯讀 | `.md`、`.markdown` |
| **以頁面顯示** | 將檔案按其本身的頁面呈現，唯讀 | `.html`、`.htm`、`.xhtml` |
| **以文字編輯** | 原始內容，可編輯 | 其他所有情況 |

在儲存庫之外，**以文字編輯** 同時也是解除唯讀的那一次按下 — 模式與授權是一個動作，而不是兩個需要分別琢磨的按鈕。**只要按下會解除唯讀**，它就帶紅色調，無論你是在原地準備編輯，還是逕自從呈現檢視過來；在儲存庫內沒有什麼可解鎖的，所以它保持素淨。**以 Markdown 檢視** 覆著一層淡淡的強調色 — 與 Obsidian 給選取文字的色調相同 — 標明它是回去的路，而不是號召你行動。

由於按鈕跟隨的是*編輯*而非原始模式，一個在文字檢視中處於唯讀的檔案仍會給出 **以文字編輯**：正是這一按使其備妥。而永遠無法寫入的檔案 — 被截斷的，或讀取失敗的 — 則改為寫著 **以文字檢視**，因為按下所能給的就只有這些。

預設值取的是有用的那一面，而非字面的那一面：shell 指令碼裡的 `#` 是註解而不是標題，所以把 `.log` 當作 Markdown 呈現會把它悄悄吞掉。兩種預設都可以逐檔覆寫，而這個選擇會進入該窗格的歷程，因此上一頁/下一頁以及重新開啟的工作區都會保留它 — 有大量筆記住在 `.txt` 檔裡，也有大量 `.md` 檔讀原始內容更省事。

#### HTML 頁面被允許做什麼

什麼都不能。這個頁面會顯示在一個**所有權限都被剝奪**的框架裡 — 沒有指令碼、沒有表單、沒有導覽、沒有屬於自己的來源 — 而且內容政策完全不允許它連上網路。這不是為謹慎而謹慎：以一般方式載入的本機頁面會與這個視窗共享來源，而這個視窗就是 Obsidian，所以一個下載下來的 HTML 檔案裡的指令碼，會在你的應用程式裡以你的應用程式的權限運行。

這樣做的代價是這個頁面能*做*的任何事；保留下來的則是這個頁面*是*什麼。位於檔案旁邊的樣式表和圖片會被讀入並帶進這個框架中，所以一個儲存下來的頁面看起來仍然像它自己。指向頁面自身資料夾之外的參照，以及指向網路上某處的參照，都會原封不動地保留，只是不會載入 — 一個本機檔案不能悄悄告訴伺服器你開啟了它。

指令碼是被**移除**，而不僅僅是被封鎖，這樣一來，你看到的頁面與你可以切換過去的原始碼之間，差異就只有一個明確說明的地方，而不是框架默默拒絕執行的種種未知之處。頁面內的連結沒有作用。當你想要真正的東西 — 指令碼、網路，一應俱全 — *以預設應用程式開啟* 會把它交給你的瀏覽器，那才是做這件事的合適工具。

**儲存庫內的檔案可以直接編輯**，無需解鎖：*以文字編輯* 是一個真正的編輯器，你輸入它就寫回。

**編輯狀態會跨切換保留。** 切到 *以 Markdown 檢視* 會將其暫停 — 靜態呈現沒有可輸入之處，而即時預覽需要 Obsidian 自己的編輯器，那只對儲存庫內的檔案存在 — 因此在那邊不會有任何東西聲稱你正在編輯。切回 *以文字編輯* 會從你停下的地方繼續。

**儲存庫之外的檔案以唯讀方式開啟，而 *以文字編輯* 解除這一點。** 這一按就是整道門：在它發生之前，外面什麼也不會被寫入。之後檔案會隨你輸入而儲存，與儲存庫內的檔案完全一樣；狀態列也從一把鎖變成一支筆。這次解鎖只涵蓋那一個分頁裡的那一個檔案 — 轉到另一個檔案就重新上鎖 — 而且它被刻意不存入分頁的歷程，因此重新開啟的工作區絕不會帶著「已備妥的寫入權限」回到某個你根本不記得開啟過的系統檔案上。

**被截斷的檔案無論如何都保持唯讀** — 儲存畫面上的內容會丟棄上限之外的一切，所以那個按鈕根本不提供，而不是提供了再拒絕。讀取失敗的檔案同理：除了一個空窗格，沒有什麼可寫回。

如果寫入失敗 — 唯讀掛載點、並非你所有的檔案 — 系統自己的原因會以通知的形式顯示出來。

超大檔案會被截斷顯示，而狀態列會直說，而不是留給你自己去發現 — 它與其他條件並列，而不是跟在按鈕後面，因為它和其餘各項一樣是關於這個檔案的事實。上限是對著真實呈現引擎量出來的，而不是猜的 — 把一 MB 的文字排布在一個窗格裡會直接搞垮 Obsidian 的呈現程序，而 Markdown 每位元組的開銷是純文字的數倍，所以兩者有各自的上限；即便整個檔案很小，單獨一列過長時那一列也會被截短。

**狀態列是標籤，解釋則是提示。** 每一列都用盡可能少的字說明當下為真的事 — *儲存庫之外*、*沒有適用於此檔案類型的編輯器*、*已截斷 — 檔案過大* — 因為旁邊的按鈕已經說明了檔案處於什麼狀態。把游標停上去就能得到那句話：為什麼 Obsidian 無法把它當作筆記開啟，這種檔案類型本來會遭遇什麼，截斷讓你失去了什麼。

這同樣適用於儲存庫**內**的檔案。凡是 Obsidian 沒有檢視可用的副檔名，它都會逕自交給桌面的預設應用程式 — 所以儲存庫裡的一個 `.txt` 或 `.json` 會把你整個帶出 Obsidian。現在這些也在同一個檢視器中開啟，帶橘色描邊，因為「在 Obsidian 裡開啟它」正是你的訴求 — 而作為儲存庫檔案，它們在那裡無需任何解鎖即可編輯。沒有檢視器的二進位檔案保持 Obsidian 原有的行為；那裡沒有什麼可顯示的。

預覽**在你原本所在的分頁中**開啟，因此上一頁/下一頁會把你帶回原來的筆記；和別處一樣，按住 <kbd>Ctrl</kbd> 可用新分頁。只要它開著，標題列就繼續顯示這個外部檔案的路徑，你可以從那裡繼續瀏覽。

內容上方有一列低調的出口：

- **在*（儲存庫）*中開啟** — 當檔案屬於你其中一個其他儲存庫時顯示。把它交給 Obsidian 自己的 URI 處理器，後者會開啟該儲存庫的視窗並帶著這則筆記，作為一則真正可編輯的筆記。這個視窗完全保持原樣；不會有任何東西在你腳下切換。
- **以 Markdown 檢視** / **以頁面顯示** / **以文字編輯** — 這個檔案擁有的兩種讀法；最後一項在儲存庫之外還會解除唯讀。
- **以預設應用程式開啟** — 把檔案交給你桌面的預設應用程式，包括這個檢視器無法顯示的二進位格式。措辭與 Obsidian 自己對同一動作的項目一模一樣，因為那正是同一個動作。

檢視器也能回應**右鍵**：在文字編輯器內是 *剪下* / *複製* / *貼上* / *全選*，在其他任何地方則是檔案自己的選單。Obsidian 標題列的三點選單也帶著那個選單 — 否則在儲存庫之外，它原本只會提供 *向右分割* 和 *向下分割*。

除非你先按下 *以文字編輯*，否則儲存庫之外不會被寫入任何東西。完整的說明見 README 的 [儲存庫之外](README.zh-TW.md#儲存庫之外) 一節。

## 把檔案拖到路徑中的資料夾上

列裡的每個資料夾都是拖放目標，所以**把筆記拖到某個資料夾上，就會把它移到那裡**——最短的路徑，就是從筆記到它上方任何一個資料夾，因為目的地已經顯示在畫面上了。無論是從檔案總管拖曳、從下拉清單拖曳、從標題列裡筆記自己的名稱拖曳，還是從 Obsidian 中任何會產生檔案的地方拖曳，都可以——這是應用程式自己的拖曳動作，所以懸停標籤、游標和高亮顯示，都是檔案總管畫出來的那一套。

**儲存庫的名稱也接受拖放**，因為它就是這一列最上方的資料夾——這是唯一能從這裡把筆記放進儲存庫根目錄的手勢。

**整批選取的項目可以一次拖曳**，而且會整批一起移動：只要其中任何一個無法被接受，這次拖放就會被拒絕，而不是移動一部分、悄悄跳過其餘的。

連結會跟著筆記走，就跟從檔案總管移動，或是用輸入路徑的方式移動時一樣。

**無法接受拖放的資料夾，什麼都不會提供**——不會出現「*移入*」標籤，資料夾也不會高亮——而不是提供一個之後會失敗的動作；取而代之的，是 Obsidian 對標題列原本的回應：「*在此分頁中開啟*」。有三種情況：

- 檔案**目前已經在**的那個資料夾，因為它已經在那裡了；
- 被拖放到**自己或自己的子孫項目裡**的資料夾，因為這樣會讓它找不到原本的位置；
- 選取項目裡同時包含**一個資料夾和它裡面的東西**，因為移動資料夾會連同子項目一起帶走。

已經有**同名檔案**的資料夾，會接受拖放，並詢問該如何處理那個擋路的檔案，用的對話框跟輸入或選取一個已被使用的名稱時一樣——見[已被使用的名稱](#已被使用的名稱)。這裡的任何動作都不會覆寫檔案。

只有**儲存庫內部**的資料夾接受拖放。當這一列指向儲存庫外部時，它的各段都會拒絕拖放，因為把筆記移出儲存庫，會破壞所有指向它的連結——這是個值得先問一聲、而非隨手一拖就做的決定。要刻意這麼做，還是得用輸入路徑的方式，它會先問過你，並告訴你會影響多少筆記。

## 拖放文字或檔案來寫入內容

同樣的目標也接受**內容**，不只是檔案，而區分這兩者的依據是你正在拖曳什麼，而不是你放在哪裡。

**拖到這一列已經命名的筆記上**——筆記自己的名稱，或是某個資料夾筆記的分隔符——你拖放的內容，會被加到它的結尾，前面隔一個空行。它會先詢問你，因為這是寫入一個已經存在的檔案，而拖曳這個動作，手一抖也可能不小心做出來。從編輯器拖出來的文字、從桌面拖來的檔案、從這個儲存庫拖出來的筆記，都可以；檔案會被當作文字讀取，二進位檔案則會被拒絕，而不是貼成滿滿一螢幕的亂碼。

**拖到一個位置上——儲存庫名稱或某個資料夾**——這時還不會寫入任何東西，因為還沒有名稱。輸入框會在那裡打開，裡面裝著你拖放的內容，你輸入的名稱，就是提交動作的關鍵：一個新筆記會被*建立*，裡面裝著這段文字；一個已存在的筆記，則會像上面一樣被詢問。按 <kbd>Esc</kbd>，或點擊別處，就會放開整個動作。

**當一次會落地為內容的拖曳懸停在這一列上方時，這一列會發出藍色光環**，而當輸入框正裝著這樣的內容時，也會維持藍色——同樣的藍色，說的是同一件事：接下來發生的事，跟你手上的文字有關。從你自己的儲存庫拖出來的檔案，拖到資料夾上仍然代表「*把它移到那裡*」，會保留 Obsidian 自己的高亮，絕不會發出藍色光環；那個手勢原本就存在，內容的處理方式要讓路給它。

## 當路徑比面板還長

名稱會被**縮短，而不是硬擠**，順序依照你最不可能需要的部分開始：

1. **先是儲存庫名稱**，最後只剩下圖示。你知道自己在哪個儲存庫；這個圖示會一直說明路徑從哪裡開始。
2. **接著是檔案的副檔名**，如果你有開啟這個選項的話——這是儲存庫裡幾乎每個檔案都有的同樣三個字元。它要不整個保留，要不就不縮短：半個副檔名什麼都說不出來，跟沒有副檔名沒兩樣。
3. **接著是資料夾，最長的先來。** 最長的資料夾名稱會先縮到跟第二長的一樣長，接著兩者一起再縮，依此類推，各自在自己的下限停下——所以一個非常長的資料夾，會先犧牲掉自己比其他資料夾多出來的部分，然後旁邊一個短名稱才會少掉一個字母。
4. **檔案自己的名稱放到最後**，並且會保留大約六個字元。畢竟標題列就是為它存在的。

空間是**連續**釋放出來的，以像素的分數為單位，而不是一次讓出一個字母：正在讓路的名稱，會在像素邊界被裁切，並在它的 `…` 底下淡出，所以慢慢拖動面板時，這一列會平滑地變窄，後面的東西不會一格一格地跳動。在任何字母被犧牲之前，會先用掉分隔符周圍的空間——那是這一列唯一的留白，而且完全不用犧牲任何資訊——被縮短的名稱，會在分隔符開始的地方結束，兩者之間不會留下一段空白的縫隙。

**輸入框會取用它需要的空間。** 打開一個輸入框來輸入路徑，並不會把旁邊的資料夾硬擠開：它會跟裡面的文字一樣寬，並隨著你輸入而變長，所以路徑列會保留輸入框不需要的所有空間。只有在空間不足以同時容納兩者時，這一列才會捲動，而輸入框永遠是唯一不會讓步的東西——因為它是正在編輯的文字，不是正在被塞進去的名稱。

裁切的程度，絕不會超過區分相鄰項目所需要的最少字元：同一個資料夾裡的 `Projects2025` 和 `Projects2026`，會被縮成 `…025` 和 `…026`，而不是縮成一個會讓兩者變成同一個詞的字首；而 `Reports` 旁邊有 `Receipts` 時，可以縮成 `Rep…`。除此之外，每個名稱都會保留一個**可讀的寬度**——資料夾大約留四個字母的份量，檔案名稱留六個字母的份量，這是用這一列實際繪製所用的字體去量測，而不是用字元數去計算。四個窄字母和四個寬字母，代表的名稱份量並不相同，所以 `lilliliillil` 可以保留比 `WWMMWWMMWWMM` 更多的內容，而顯示在畫面上的，兩者最終的寬度是一樣的。短名稱則完全不會被動它——一個被磨到只剩 `A…` 的名稱，雖然還是獨一無二，卻已經無法閱讀。**空格不計入這個寬度。** 用六個字元來說明這是哪個檔案，這六個字元都值得被讀到，所以字元之間的空白會一起被免費保留下來，而且絕不會有一個空格孤零零地緊貼著 `…`，因為那樣反正也看不出來。

**名稱會在相鄰項目一致的地方被裁切，如果哪裡都不一致，就從中間裁切。** 兩個資料夾叫做 `aaaa-common-one` 和 `aaaa-common-two`，除了最後三個字元以外全部相同，所以裁掉尾巴，保留的正是那不含任何資訊的一半：它們會被縮成 `…one` 和 `…two`，這樣既更短，*又*能區分兩者。如果一致的部分在結尾——像 `alpha-draft` 和 `beta-draft`——那麼被裁掉的就是結尾；如果兩端都一致，保留下來的就是中間部分。一個沒有相近鄰居的名稱，會失去中間的部分，因為一個名稱是以「它是什麼」開頭，以「它是哪一個」結尾——對檔案來說，就是它的副檔名：`annual…2026.md`。

一小段共同的部分不算數。`parallel structures` 恰好跟旁邊的 `Schemes` 結尾兩個字母相同，但這不是把兩者都完整保留的理由——光是開頭三個字元，就已經足以分辨它們了。

沒有東西會換到第二行。當即使是最短、最誠實的名稱也放不下時，這一列會**橫向捲動**，停在檔案所在的那一端——到了這個地步，已經沒有東西可以再壓縮，繼續裁切只會是遮住內容，而不是縮短它。滾輪會依照指標所在的位置，捲動這一列，而且兩端都能夠到達：捲動時，這一列會對齊到它的起點，不論對齊設定是什麼，因為在一個已經容不下它的方框裡置中的內容，會同時往左、往右溢出——而左邊那一半，是完全無法用捲動到達的。

**指向一個被縮短的名稱，它就會完整地顯示出來**，只要你的指標還停在它上面，並且會捲動到最左邊，讓還原後的全部內容都在畫面上。**點擊它，它就會保持不動**：輸入框會打開，顯示你點擊的資料夾、它之後可以選取的內容，以及你輸入的任何東西，而在指標移開之後，這些內容仍然會繼續顯示。當你正在捲動這一列，或是正在輸入文字時，名稱都不會自己彈開——如果一個名稱在你想閱讀這一列的手勢下突然彈開，會把你後面的一切都推到你抓不到的地方。

**開頭的那一段，永遠會帶有一個工具提示，內容就是絕對路徑**——像 `/home/you/Vaults/Notes`，或是這一列開始的任何地方。這是唯一一件畫面上其他任何東西都說不出來的事：名稱只會告訴你*是哪個*儲存庫，從來不會告訴你它在哪裡。不論有沒有東西被縮短過，這個工具提示都會存在。

當**顯示儲存庫名稱**關閉時，名稱並不是被移除，只是被壓縮到寬度為零而已——所以指向這個圖示，會像指向一個被這一列縮短過的名稱一樣，把它還原回來。

**顯示副檔名**會把副檔名加回這一列的檔案名稱上。關閉時——這是預設值——這一列會用 Obsidian 為筆記命名的方式來命名，不含儲存庫裡幾乎每個檔案都有的 `.md`；開啟時，它會用檔案系統的方式來命名，這在儲存庫裡不只有筆記的時候會很有用。這也是這一列在空間不足時，第二個會犧牲的東西，緊接在儲存庫名稱之後。
工具提示會告訴你剩下的部分：不只是名稱，還有這一列在它底下顯示的一切，格式是 `…/名稱/資料夾/note.md`，所以懸停一次，就能同時回答「這是什麼」和「它底下是什麼」兩個問題。當名稱被關閉或已經被壓縮掉時，儲存庫的圖示也會用同樣的方式，顯示它的儲存庫名稱。

| --- | --- | --- |
| 路徑列上的**紅色**光環 | 這一列指向儲存庫外部 | Obsidian 無法把那裡的東西當成筆記開啟，而且在你打開掛鎖之前，外面的任何東西都不會被寫入。 |
| 路徑列上的**橙色**光環 | 這個檔案是 Obsidian 沒有檢視方式的文字類型 | 一個提醒。Obsidian 原本會把它交給你桌面環境的預設應用程式；這個外掛會改為顯示它。 |
| 輸入框中的**紅色**文字 | 那個路徑上目前還沒有東西 | 按下 <kbd>Enter</kbd> 會建立它，而不是開啟它。與其說是警告，不如說是在說明下一次按鍵會做什麼——見[輸入路徑](#輸入路徑)。 |
| 用來取代重新命名切換鈕的**紅色**掛鎖 | 這一列指向儲存庫外部，而在那裡寫入的功能仍被鎖住 | 跟光環一樣的紅色，也是同樣的理由：標示著一次拒絕。按下它，就能允許在這裡寫入，並把這個位置交還給切換鈕——見[寫入儲存庫之外](#寫入儲存庫之外)。 |

**這兩種光環各自獨立，也可能同時出現**——一個外部的 `.json` 檔案，既在儲存庫外部，又是 Obsidian 沒有編輯器可用的類型。在檢視器裡，它們會分成獨立的兩行顯示，各自只陳述自己的事實。但在路徑列上，只要有其中一項成立，紅色就會勝出，因為兩個光環同時出現只會是雜訊。紅色的*文字*則完全是另一回事：它說的是你正在輸入什麼，而不是這一列指向哪裡，所以不論哪一種光環之下，或是兩者都沒有的情況下，它都可能出現。

橙色這一層，範圍是刻意收得很窄的。已註冊的類型（Markdown、白板、圖片、PDF、音訊、影片）都能被正確處理，不會顯示任何提示。二進位檔案也不會顯示——你不會不小心把一個 `.zip` 編輯成一團亂。剩下的，正好就是真正的風險所在：像 `.json`、`.css` 或 `.log` 這類因為開啟了**顯示所有檔案類型**而變得可見的檔案。下拉清單的判定範圍則刻意放得更寬：在那裡，所有不是筆記的東西都是橙色——見[清單項目的著色](#清單項目的著色)。

## 重新命名/移動模式

標題列最右邊的鉛筆按鈕——就在檢視模式按鈕旁邊，大小跟原生按鈕一樣——用來切換重新命名/移動模式。在儲存庫外部，這個位置會顯示一個紅色掛鎖，直到你按下它為止；見[寫入儲存庫之外](#寫入儲存庫之外)。這時候，標題列會用強調色框起來，就跟在檔案總管裡重新命名時一模一樣。同樣的點擊和按鍵，現在會透過 Obsidian 的 `fileManager.renameFile` 來提交一次移動或重新命名，所以所有指向這個筆記的連結都會跟著更新。

重新命名期間：

- 目前的檔案名稱會被固定顯示在每個資料夾的下拉清單裡，所以要移動一個筆記而不改名，只需要點擊一下。
- 目標資料夾裡已經被使用的名稱會顯示成**紅色**——包括已經存在同名資料夾，以及已經存在同名檔案的情況——所以在你選擇之前，就能看到會發生衝突。它們仍然可以被選取：見下文。
- 輸入內容會即時依照 Obsidian 本身的重新命名規則來驗證——同樣的字元集、同樣的訊息、同樣的紅色工具提示，就跟在檔案樹裡重新命名時一樣——所以不合法的名稱在你輸入的當下就會被標示出來，並且無法被提交。
- 點擊標題列以外的地方，或是標題列失去焦點，都會結束重新命名模式。

### 已被使用的名稱

移動或重新命名到一個已經存在的名稱時，會**詢問你，而不是直接拒絕。** 系統會打開一個對話框，裡面有兩條可以編輯的路徑：你的檔案要去哪裡，以及擋路的那個檔案要去哪裡——只要那個名稱仍然被佔用，就會顯示紅色。每條路徑的繪製方式，也跟路徑列一樣，不同的部分會被上色，而且最後才會被縮短，所以就算路徑很長，仍然看得出改變的地方。

兩個欄位都有一份清單。第二個欄位裡，是常見的幾種解決方式：

- **互換位置**——它會移到你檔案原本所在的資料夾，維持自己的名稱。
- **互換名稱**——它留在原地，改用你檔案原本的名稱。
- **互換兩者**——它會取用你檔案原本的完整路徑。
- 在它自己的名稱旁邊加上 `-1`、`-bak` 或 `-old`。
- 兩個檔案原本各自的名稱。

第一份清單提供的選項是：你的檔案原本要去的地方、**留在原地**、在目標資料夾裡用它自己的名稱，以及在旁邊加上 `-1`、`-bak` 或 `-old`。如果某個選項的路徑已經被佔用，就會變成灰色，無法選取。選取其中一個，**只會填入那個欄位**——你仍然可以編輯它——按下**套用**會把兩者都移動，連結也會一起跟著移動；按下**取消**則什麼都不會移動。從下拉清單裡選取一個已被使用的名稱，也會問同樣的問題；把一個筆記拖放到已經有同名檔案的資料夾上時，也是一樣。

## 一個鍵管兩種重新命名

重新命名指令（預設是 <kbd>F2</kbd>，或你重新指定的任何按鍵）會在 Obsidian 的內嵌標題重新命名與本外掛的標題路徑列之間**交替切換**。如果你已關閉 Obsidian 的內嵌標題，標題路徑列就成為唯一的目標，所以這個鍵永遠不會沒有反應。

在路徑列中，它開啟的是**不含副檔名的名稱**——這幾乎就是重新命名時該編輯的部分，點擊名稱選取的也是同一段。再按一次，它會做<kbd>Tab</kbd>在那裡會做的事：在名稱上，那是下一級——含副檔名的名稱、從你的儲存庫資料夾算起的路徑、從系統根目錄算起的路徑；如果已輸入了什麼，它就補完，就跟<kbd>Tab</kbd>一樣。

**循環在標題處收尾。** 按五次會繞完一圈——內嵌標題、名稱、含副檔名的名稱、從儲存庫算起的路徑、從系統根目錄算起的路徑——第六次又回到內嵌標題。這一按是唯一與<kbd>Tab</kbd>不同的地方，<kbd>Tab</kbd>會繞回路徑的最前面；而第七按會走到<kbd>Tab</kbd>繞圈之後去的地方：儲存庫根目錄，整條路徑都在欄位中，且第一個資料夾被標記選取。所以<kbd>Tab</kbd>能到達的每一級，這個鍵也都能到達。

**聚焦路徑列**指令在欄位內部做的是同一件事——凡是<kbd>Tab</kbd>會做的都做；而在<kbd>Tab</kbd>會繞圈的地方，它反而把游標交還給筆記。它的下一次按下就是那個繞圈：儲存庫根目錄，第一個資料夾被標記選取。

**在已經開啟的欄位中**，這個鍵會就地把它轉為重新命名——保留文字、插入點與選取範圍——而**聚焦路徑列**則以同樣的方式把重新命名狀態撤掉。**在兩次按下之間**按了或點了**其他任何東西**，都會讓其中一個循環重新開始，所以你編輯完之後再按一次，絕不會停在之前留下的某一級上。

在儲存庫之外這個鍵同樣有效——那裡沒有內嵌標題，所以第一次按下會直接進入路徑列。

這是透過包裝 `workspace:edit-file-title` 指令實現的，而不是去搶按鍵，因此重新指定快速鍵和從指令面板執行指令都照常有效。

## 清單項目的著色

| 顏色 | 意義 |
| --- | --- |
| **紫色** | 筆記（`.md`、`.markdown`）——Obsidian 會以筆記開啟的東西，從混雜內容的資料夾中挑出來 |
| **橘色** | 不是筆記——任何 Obsidian 不會以筆記開啟的東西，從 PDF 到 `.txt`，以及和它們一起出現的 `:page` 項目。混雜內容的資料夾會被讀取以找出其中的筆記，而其他一切都用同一種顏色標示，比只警示其中少數幾項更快說明狀況；見[警示顏色](#警示顏色) |
| **淡色** | 儲存庫之外，所以儲存庫本身的處理方式不適用 |
| **藍色**（粗體） | 你目前所在的位置：這個路徑列自己的筆記，以及路徑列停留的資料夾。在重新命名/移動模式中，*保留此名稱*項目會代替筆記的位置——不論哪種情況都是同一份筆記 |
| **紅色** | 僅限重新命名/移動模式：該名稱已被使用。仍可選取——選取後會詢問該如何處理擋路的檔案；見[已被使用的名稱](#已被使用的名稱) |

**資料夾以粗體顯示**，所以資料夾自己的筆記不需要另外的顏色來與其資料夾區分：它和其他筆記一樣是紫色。**列邊上的一條直線**標示出以你所輸入內容為開頭的名稱——若進一步吻合則為藍色，若走向所提供的分支則為綠色；見[輸入路徑](#輸入路徑)。

欄位對其所指的對象採用相同的顏色——見[輸入路徑](#輸入路徑)。

## 可見性規則

- 副檔名不受支援的檔案，只有在 Obsidian 的**偵測所有檔案副檔名**設定開啟時才會出現在清單中——**僅限儲存庫內**。在儲存庫之外，該設定不適用：它管理的是儲存庫索引的內容，而外面的一切都不在儲存庫中，所以你筆記旁的 `.txt` 無論如何都會列出。
- 清單最多顯示 1,000 個項目，是 Obsidian 本身限制的十倍。當資料夾中的項目更多時，最後一列會說明省略了多少個；持續輸入以縮小清單範圍。
- 點檔案和點資料夾只有在本外掛的**顯示點檔案**設定開啟時才會出現。
- **覆寫保護不論可見性如何都同樣有效**——隱藏的檔案仍會阻止你覆寫它。

## 速查表

**用引號包起來**的路徑會自動被解開。Windows 的*複製為路徑*會給出 `"C:\Users\you\note.md"`，連引號一起，而任何含有空格的路徑，殼層也會這樣處理；貼上或直接輸入都一樣有效。只有雙引號，且只有在整段的頭尾成對出現時才會被解開——它不可能出現在真正的名稱中，而單引號則很可能出現。

## 設定

| 設定 | 選項 | 預設值 | 作用 |
| --- | --- | --- | --- |
| **語言** | Obsidian 預設，或 46 種語言之一 | Obsidian 預設 | 本外掛自身文字所使用的語言。*Obsidian 預設*會依循外觀設定中設定的語言，這是幾乎每個人想要的結果。這一列本身——它的名稱、說明，以及*Obsidian 預設*這個選項——無論選了什麼都會保持英文，因為這是你在看不懂某種語言時回頭的路。希臘語和梵語在這裡有翻譯，而 Obsidian 自己的清單中沒有，所以這個設定是唯一能選到它們的方式。 |
| **對齊方式** | 靠左／居中／靠右 | 靠左 | 路徑列在標題列中的位置。*居中*符合 Obsidian 經典的外觀。 |
| **分隔符號** | 任意字元 | `/` | 段落之間繪製的分隔符。文字欄位前方有六個一鍵選取的預設值（`/ > ▸ › \ •`）。 |
| **顯示儲存庫名稱** | 開／關 | 開 | 儲存庫本身是否作為第一個路徑段。關閉時，該段會變成一個 🏠 圖示而非消失，所以路徑仍會從某個可點擊的地方開始。 |
| **資料夾名稱開啟清單** | 開／關 | 開 | 交換資料夾名稱與其後方分隔符號的作用——見[上表](#路徑列)。搭配[資料夾筆記](obsidian://show-plugin?id=folder-notes)時，分隔符號會開啟資料夾筆記。在重新命名/移動模式中永不適用。 |
| **顯示點檔案** | 開／關 | 關 | 點檔案和點資料夾是否列在清單中。覆寫保護無論如何都適用。 |
| **顯示所有檔案類型** | — | — | 不是本外掛的設定，而是 Obsidian 的設定，之所以在這裡提及，是因為它回答的是同一個問題：你的儲存庫只會索引它被告知要索引的檔案類型，而只有被索引的內容才能被列出。到 Obsidian 的設定中尋找它並開啟以查看所有檔案；這一列旁的按鈕會開啟該頁面，並將該設定捲動到可見範圍並閃爍提示，就像在設定本身的搜尋中點擊它一樣。在儲存庫之外它不適用，因為外面的東西反正都不會被索引。 |
| **顯示副檔名** | 開／關 | 關 | 該列上的檔名是否帶有副檔名。關閉時會省略——就像 Obsidian 省略筆記標題的副檔名一樣。開啟時，該列會以檔案系統的方式命名檔案。無論哪種情況，副檔名都是該列空間不足時第二個被捨棄的東西，緊接在儲存庫名稱之後。 |
| **存取外部檔案** | 開／關 | **關** | 儲存庫名稱是否會開啟位置清單。關閉時，本外掛絕不會看到這個儲存庫之外的內容。 |
| **快速鍵** | 按鈕 | — | 開啟已篩選為本外掛項目的 Obsidian *快速鍵*頁面，在那裡可為*聚焦路徑列*指定按鍵。 |

## 更換圖示

Lure 會繪製三個圖示：儲存庫根目錄圖示（當**顯示儲存庫名稱**關閉時）、重新命名/移動切換鈕，以及在儲存庫之外寫入被鎖定時代替它位置的鎖頭。這些都可以透過主題或 CSS 片段替換——在一條規則中設定替換用的字元並隱藏內建的圖示：

```css
.lure-vault-icon {
	--lure-icon-glyph: "🏠";
	--lure-icon-svg: none;
}

.lure-rename-btn {
	--lure-icon-glyph: "✎";
	--lure-icon-svg: none;
}

/* Only ever shown shut: opening it hands the slot to the rename toggle. */
.lure-unlock-btn {
	--lure-icon-glyph: "🔒";
	--lure-icon-svg: none;
}
```

`--lure-icon-glyph` 接受任何在 CSS `content` 中合法的值，因此 `url(...)` 可用於圖片，正如文字或表情符號字元一樣。若想保留 Lucide 圖示並把你的字元畫在它旁邊，就別動 `--lure-icon-svg`。
