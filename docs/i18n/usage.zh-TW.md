# 使用方式

[← 返回 README](README.zh-TW.md)

## 路徑列

筆記在儲存庫中的完整路徑取代了檢視標題列中光禿禿的檔名 — 標題列就是分頁列下方、同時放著上一頁/下一頁按鈕的那一條。

這一列上有兩處可以點擊，而 **資料夾名稱開啟清單** 決定誰做什麼：

| | 資料夾名稱 | 其後的分隔符 |
| --- | --- | --- |
| **開啟**（預設） | 選取該資料夾以便編輯 | 開啟該資料夾 |
| **關閉** | 開啟該資料夾 | 進入該資料夾 |

「開啟該資料夾」指的是在沒有外掛的 Obsidian 裡點擊該段所做的事。若沒有外掛在那裡監聽，資料夾會在側邊欄的檔案瀏覽器中顯示出來 — 醒目提示，並展開以露出內容。

裝有 [Folder notes](obsidian://show-plugin?id=folder-notes) 時，同樣的點擊會改為開啟該資料夾的筆記。這是目前確認會接管標題列路徑的唯一一款資料夾筆記外掛；[Folder Note](obsidian://show-plugin?id=folder-note-plugin) 與 [create folder notes with dropdown](obsidian://show-plugin?id=create-folder-notes-with-dropdown) 管理資料夾筆記，但並不監聽路徑上的點擊，所以與它們並用時分隔符照常顯示資料夾。參見[相容性](../compatibility.md#verified-against)。

分隔符**只有在它前面的資料夾確實有資料夾筆記時**才帶底線，因此底線是一個承諾：那裡確實有東西可開啟。無論有沒有底線，每個分隔符都可點擊 — 沒有底線的那一個會在側邊欄中顯示並展開它的資料夾，游標形狀仍會提示這一點。底線同時從資料夾名稱上移開：開啟互換後，資料夾名稱開啟的是清單，把它標成通往筆記的連結就成了謊言。

**重新命名/移動模式會覆寫兩者**，無論設定為何：有移動待處理時，這一列上的任何東西都不會開啟資料夾，因為開啟就等於放棄這次移動。資料夾名稱被選取以便編輯，分隔符則往下進入 — 兩者都是挑選目的地的方式 — 並且底線消失，以示開啟已暫停。

**儲存庫根目錄**是唯一不屬於路徑分段的一段。它沒有上層可用來列出同層項目，因此改為開啟[位置清單](#瀏覽儲存庫之外) — 你的其他儲存庫、主資料夾、檔案系統根目錄和已掛載的磁碟機。

## 點擊某一段：換成同層的另一個

點擊資料夾名稱會在文字輸入欄中選取**該資料夾的名稱**，並開啟**上一層**資料夾 — 也就是它的上層 — 的清單。輸入或挑選一項即可把這個資料夾換成同層的另一個，而它下面的一切原樣保留，所以 `專案/2026/啟動.md` → 點擊 `2026` → 選擇 `2025`，得到 `專案/2025/啟動.md`。

點擊**筆記的名稱**對它自己的資料夾以同樣方式作用，並且選取的檔名**包含副檔名** — 重新命名或改指一篇筆記通常也意味著要改副檔名。

點擊資料夾時已經選取了一段，因此**再點一次**會把選取範圍擴大到整列 — 該資料夾*以及*它下面的一切 — 這時輸入就能一次替換路徑的其餘部分。在導覽模式與重新命名/移動模式下表現一致。

這只有作為「開啟輸入欄的那一次點擊」的延續時才成立。一旦你開始使用這個輸入欄，它就和別的文字輸入欄一樣：點擊放置游標，按兩下取一個詞，按三下取整列。

無論哪種情況，路徑的其餘部分都留在輸入欄周圍可見 — 前面是小方塊，後面是未選取的文字 — 所以完整路徑不會從標題列消失。輸入以替換選取範圍，或按 <kbd>End</kbd> / <kbd>→</kbd> 保留它並從那裡繼續編輯。無論預先填了什麼，清單都會列出整個資料夾；只有你真正開始輸入時它才開始篩選。

## 用分隔符往下進入

在 **資料夾名稱開啟清單** 關閉時點擊分隔符，會進入它前面的那個資料夾：清單列出*那個*資料夾的內容，路徑的其餘部分則以選取狀態在輸入欄中開啟。挑選一個資料夾會把它接到路徑上，並立刻開啟下一個清單，於是你可以一路點著往下走，不必離開標題列。

## 清單中的每一列都是真正的檔案管理員項目

清單裡的每個檔案和資料夾，表現都與它在檔案瀏覽器中的那一列一致：

- **按右鍵**可得同一個快顯功能表 — 資料夾上是 *新增筆記* / *新增資料夾*，檔案上是 *在新分頁開啟* / *重新命名…* / *刪除* — 也包括其他外掛加進檔案功能表的項目。
- 把項目**拖曳**到任何 Obsidian 接受檔案的地方：拖進編輯器以插入連結，拖到檔案瀏覽器的某個資料夾上以移動它，拖到分頁列上以開啟它。

功能表文字來自 Obsidian 自己的譯文，因此在任何語言下都與應用程式其餘部分保持一致。

## 輸入路徑

- 點擊路徑前後的**空白處**會開啟一個文字輸入欄，其中預先填入完整路徑並已全選 — 直接覆寫，或就地編輯。（點擊檔名本身只會選取檔名；見上文。）
- 在路徑顯示著的時候開始輸入，會把末尾一段變成一個小輸入欄，帶有限定於目前資料夾的即時自動完成。
- `/` 送出目前這一段並進入其中。
- 在空的輸入欄中按 <kbd>Backspace</kbd> 會退回上層資料夾，並把它的名稱重新開啟、游標置於末尾。
- <kbd>Enter</kbd> 送出；<kbd>Esc</kbd> 或點擊別處則取消，回到檔案真正的路徑。

輸入欄毫無修飾 — 沒有方框，沒有邊框 — 因此讀起來就是路徑文字本身，並且會隨輸入自動伸長。

## 導覽從不碰觸開啟中的檔案

在預設的（導覽）模式下，目前開啟的筆記**絕不會**被重新命名或移動。

- 指向既有檔案的路徑會開啟該檔案。
- 尚不存在的路徑會詢問 *「建立新檔案？」*。確認會建立缺少的上層資料夾與該檔案；取消則什麼也不做。

## <kbd>Ctrl</kbd> — 新分頁，以及複製而非移動

在從清單中挑選檔案時，或在某個路徑上按 <kbd>Enter</kbd> 時按住 <kbd>Ctrl</kbd>（macOS 上是 <kbd>Cmd</kbd>），會把結果送到**新分頁**而不是目前這個：

| | 直接操作 | 按住 <kbd>Ctrl</kbd> |
| --- | --- | --- |
| 挑選或輸入一個既有檔案 | 在此處開啟 | 在新分頁開啟 |
| 輸入一個不存在的路徑 | 先詢問，然後在此處開啟 | 先詢問，然後在新分頁開啟 |
| 在重新命名/移動模式下送出路徑 | 把筆記**移動**到那裡 | 把它**複製**到那裡，並在新分頁開啟副本 |

輔助鍵按 Obsidian 自己的規則讀取，因此其行為與在連結或檔案瀏覽器項目上完全一致 — 按中鍵同樣表示「新分頁」，<kbd>Ctrl</kbd>+<kbd>Alt</kbd> 表示分割，<kbd>Ctrl</kbd>+<kbd>Alt</kbd>+<kbd>Shift</kbd> 表示新視窗。

複製與移動一樣拒絕覆寫 — 包括覆寫到筆記自身的路徑，那裡本就沒有什麼值得複製的。

## 瀏覽儲存庫之外

**此項預設關閉。** 請先在設定中開啟 **存取外部檔案** — 在儲存庫之外讀寫是這個外掛所做的、而 Obsidian 自己不做的唯一一件事，所以它被設計成需要主動開啟，而不是主動關閉。關閉時，儲存庫名稱只是在檔案瀏覽器中顯示你的儲存庫，這裡的任何東西都不會望向它之外。

點擊**儲存庫名稱**（當 *顯示儲存庫名稱* 關閉時是 🏠 圖示）開啟的是位置清單，而不是內容：

- **你的其他儲存庫**，讀自 Obsidian 自己的紀錄，最近開啟的排在前面，各自帶著 Obsidian 自己的儲存庫圖示 — 也就是應用程式在儲存庫相關指令裡用的那一個。已經開啟的那個儲存庫改用一棟房子：預設情況下這一列就從那裡開始，它不是一個要去的地方。
- **主資料夾**，在自己的帳號名稱下，以一個 `~` 標示。Lucide 沒有波浪號，所以這一個由外掛按 Lucide 自己的 24×24 格線、用同樣的線寬繪製 — 它是這套圖示缺少的一枚圖示，而不是混在圖示當中的一個文字字元。
- **檔案系統根目錄**，標為 `root` — 不作翻譯，因為在任何系統上它都叫這個名字 — 而不用 `/`，那樣在緊接其後的分隔符旁邊會讀成空空的一段。
- **已掛載的磁碟機**，在判斷成本低廉之處按類型配圖示：網路共用、光碟、軟碟和可攜式媒體各有其圖示；其餘一律用通用磁碟機圖示。在 Windows 上磁碟機顯示為 `C:` 並配通用圖示 — 磁碟區名稱與精確類型需要 WMI，這是刻意不去做的。

挑選另一個儲存庫**不會把 Obsidian 切換過去。** 你開啟的一切照舊開著，只是路徑列開始在那邊瀏覽。把它放在路徑列上、而不是交給側邊欄的儲存庫切換器，意義正在於此。

### 在外面時

路徑**從你挑選的位置開始**，而不是從機器的目錄結構開始 — 選了 `封存`，這一列讀作 `封存 / 筆記 / …`，而不是 `/home/you/Vaults/封存/筆記/…`。起首那一段帶著表明其身分的圖示（儲存庫、主資料夾、磁碟機），並且 <kbd>Backspace</kbd> 到此為止，不會繼續往上走進檔案系統的其餘部分。當 *顯示儲存庫名稱* 關閉時，那一段就只剩圖示 — 這項設定針對的是這一列的起首段，無論它指的是哪個儲存庫，而不只是你自己的那個。

只要路徑列指向儲存庫之外，它就一直**以錯誤色描邊** — 與重新命名模式所畫的是同一個框。它標記的是一種持續狀態，而非某個瞬間：只要它還在，Obsidian 自己的那套處理就都不適用於這一列所顯示的內容，並且在你另行表態之前寫入始終是鎖定的。

除此之外，瀏覽與在儲存庫內一樣：小方塊、分隔符、輸入、自動完成、用 <kbd>Backspace</kbd> 退出。可見性規則同樣適用，所以不受支援的副檔名仍需要 Obsidian 的 *偵測所有的副檔名*，點檔案仍需要本外掛的設定。

**按右鍵與拖曳**在外面不起作用 — 那是檔案瀏覽器自己的處理邏輯，它們需要一個儲存庫認識的檔案。

### 寫入儲存庫之外

一切寫入操作**預設都是鎖定的。** 只要這一列指向儲存庫之外，標題列中重新命名按鈕旁就會出現一把**鎖頭**；按下它會開鎖並變紅，與這一列周圍的描邊相呼應。

授權給的是**一個位置，而不是一個瞬間**：你在一個地方工作時會做的事，它都能撐過去 — 完成一次移動、點開輸入欄、開啟一個檔案 — 而當你從清單中挑選了另一個儲存庫、磁碟機或根目錄，當這一列回到儲存庫內的檔案，或當你再次按下鎖頭時，它就結束。因此在同一個資料夾裡連著移動多次，只需按一次，而不是每個檔案按一次。

鎖頭打開後，路徑列在外面的表現與在裡面一樣：

| 操作 | 結果 |
| --- | --- |
| 輸入一個不存在的名稱，按 <kbd>Enter</kbd> | 與在儲存庫內相同的「要建立嗎？」詢問；缺少的上層資料夾也會被建立。不帶副檔名的名稱會變成 `.md`，與在儲存庫內完全一樣 |
| 重新命名/移動模式，輸入新名稱 | 重新命名這一列所顯示的檔案。不帶副檔名的名稱會保留該檔案原有的副檔名 — 在外面，一個資料夾裡什麼類型的檔案都有，重新命名不該悄悄把 `.png` 變成 `.md` |
| 重新命名/移動模式，瀏覽到別處，選擇**保留此名稱** | 以它現有的名稱移動過去 |
| 在以上任一操作中按住 <kbd>Ctrl</kbd> | 改為複製而非移動，並在新分頁開啟副本 |

處於鎖定狀態時，以上各項都不會發生，而是回報是什麼擋住了它們。兩種狀態下都絕不會覆寫任何東西：已存在的目標會被拒絕，而這個拒絕來自檔案系統本身（`COPYFILE_EXCL`，一次獨占式建立），而不是某個可能輸掉競爭條件的檢查。跨檔案系統的移動 — 從 USB 隨身碟、從網路共用 — 會退回到「先複製後刪除」，並且只有在副本落地之後才會刪除原檔。

**有一件事鎖頭並不解鎖：把筆記移動到儲存庫*之外*。** `fileManager` 無法跨過那道邊界追蹤檔案，因此指向該筆記的每一個連結都會悄無聲息地失效，而 Obsidian 只會看到它憑空消失。按住 <kbd>Ctrl</kbd> 會改為把它複製出去，這就完全沒有那個問題，通知裡也是這麼說的。反方向 — 把外面的檔案帶*進*儲存庫 — 目前同樣尚未接通。

### 開啟外部檔案

Obsidian 的編輯器只對儲存庫內的檔案作用，因此外部檔案**無法**作為帶連結、反向連結等等的真正筆記開啟 — 這是應用程式的限制，不是本外掛的限制。挑選一個外部檔案會改為開啟**預覽**，在你另行表態之前是唯讀的：

| 類型 | 呈現方式 |
| --- | --- |
| `.md`、`.markdown` | 呈現後的 Markdown |
| 圖片、音訊、視訊、PDF | 原生播放器/檢視器 |
| 其他任何**文字**檔（`.json`、`.css`、`.log`、`.txt` …） | 原樣的純文字 |
| 沒有檢視器的二進位格式 | 交給 *在外部開啟* |

檢視器對一個檔案有兩種讀法，而由於兩者互斥，只會顯示你將要**切換到**的那一種：

| | 作用 | 預設適用於 |
| --- | --- | --- |
| **以 Markdown 檢視** | 把檔案當作筆記呈現，唯讀 | `.md`、`.markdown` |
| **以文字編輯** | 原始內容，可編輯 | 其餘一切 |

在儲存庫之外，**以文字編輯** 同時也是解除唯讀的那一次按下 — 模式與授權是一個動作，而不是兩個需要分別琢磨的按鈕。**只要按下會解除唯讀**，它就帶紅色調，無論你是在原地準備編輯，還是逕自從呈現檢視過來；在儲存庫內沒有什麼可解鎖的，所以它保持素淨。**以 Markdown 檢視** 覆著一層淡淡的強調色 — 與 Obsidian 給選取文字的色調相同 — 標明它是回去的路，而不是號召你行動。

由於按鈕跟隨的是*編輯*而非原始模式，一個在文字檢視中處於唯讀的檔案仍會給出 **以文字編輯**：正是這一按使其備妥。而永遠無法寫入的檔案 — 被截斷的，或讀取失敗的 — 則改為寫著 **以文字檢視**，因為按下所能給的就只有這些。

預設值取的是有用的那一面，而非字面的那一面：shell 指令碼裡的 `#` 是註解而不是標題，所以把 `.log` 當作 Markdown 呈現會把它悄悄吞掉。兩種預設都可以逐檔覆寫，而這個選擇會進入該窗格的歷程，因此上一頁/下一頁以及重新開啟的工作區都會保留它 — 有大量筆記住在 `.txt` 檔裡，也有大量 `.md` 檔讀原始內容更省事。

**儲存庫內的檔案可以直接編輯**，無需解鎖：*以文字編輯* 是一個真正的編輯器，你輸入它就寫回。

**編輯狀態會跨切換保留。** 切到 *以 Markdown 檢視* 會將其暫停 — 靜態呈現沒有可輸入之處，而即時預覽需要 Obsidian 自己的編輯器，那只對儲存庫內的檔案存在 — 因此在那邊不會有任何東西聲稱你正在編輯。切回 *以文字編輯* 會從你停下的地方繼續。

**儲存庫之外的檔案以唯讀方式開啟，而 *以文字編輯* 解除這一點。** 這一按就是整道門：在它發生之前，外面什麼也不會被寫入。之後檔案會隨你輸入而儲存，與儲存庫內的檔案完全一樣；狀態列也從一把鎖變成一支筆。這次解鎖只涵蓋那一個分頁裡的那一個檔案 — 轉到另一個檔案就重新上鎖 — 而且它被刻意不存入分頁的歷程，因此重新開啟的工作區絕不會帶著「已備妥的寫入權限」回到某個你根本不記得開啟過的系統檔案上。

**被截斷的檔案無論如何都保持唯讀** — 儲存畫面上的內容會丟棄上限之外的一切，所以那個按鈕根本不提供，而不是提供了再拒絕。讀取失敗的檔案同理：除了一個空窗格，沒有什麼可寫回。

如果寫入失敗 — 唯讀掛載點、並非你所有的檔案 — 系統自己的原因會以通知的形式顯示出來。

超大檔案會被截斷顯示，而狀態列會直說，而不是留給你自己去發現 — 它與其他條件並列，而不是跟在按鈕後面，因為它和其餘各項一樣是關於這個檔案的事實。上限是對著真實呈現引擎量出來的，而不是猜的 — 把一 MB 的文字排布在一個窗格裡會直接搞垮 Obsidian 的呈現程序，而 Markdown 每位元組的開銷是純文字的數倍，所以兩者有各自的上限；即便整個檔案很小，單獨一列過長時那一列也會被截短。

**狀態列是標籤，解釋則是提示。** 每一列都用盡可能少的字說明當下為真的事 — *儲存庫之外*、*沒有適用於此檔案類型的編輯器*、*已截斷 — 檔案過大* — 因為旁邊的按鈕已經說明了檔案處於什麼狀態。把游標停上去就能得到那句話：為什麼 Obsidian 無法把它當作筆記開啟，這種檔案類型本來會遭遇什麼，截斷讓你失去了什麼。

這同樣適用於儲存庫**內**的檔案。凡是 Obsidian 沒有檢視可用的副檔名，它都會逕自交給桌面的預設應用程式 — 所以儲存庫裡的一個 `.txt` 或 `.json` 會把你整個帶出 Obsidian。現在這些也在同一個檢視器中開啟，帶橘色描邊，因為「在 Obsidian 裡開啟它」正是你的訴求 — 而作為儲存庫檔案，它們在那裡無需任何解鎖即可編輯。沒有檢視器的二進位檔案保持 Obsidian 原有的行為；那裡沒有什麼可顯示的。

預覽**在你原本所在的分頁中**開啟，因此上一頁/下一頁會把你帶回原來的筆記；和別處一樣，按住 <kbd>Ctrl</kbd> 可用新分頁。只要它開著，標題列就繼續顯示這個外部檔案的路徑，你可以從那裡繼續瀏覽。

內容上方有一列低調的出口：

- **在「{vault}」中開啟** — 當該檔案屬於你的另一個儲存庫時出現。把它交給 Obsidian 自己的 URI 處理器，由後者開啟那個儲存庫的視窗並載入該筆記，作為一篇真正可編輯的筆記。目前這個視窗原封不動，不會在你腳下發生切換。
- **以 Markdown 檢視** / **以文字編輯** — 兩種讀法；後者在儲存庫之外還會解除唯讀。
- **在外部開啟** — 把檔案交給桌面的預設應用程式，包括這個檢視器無法顯示的那些二進位格式。

除非你先按下 *以文字編輯*，否則儲存庫之外不會被寫入任何東西。完整的說明見 README 的 [儲存庫之外](README.zh-TW.md#儲存庫之外) 一節。

## 兩種警示顏色

| | 何時 | 含義 |
| --- | --- | --- |
| 路徑列上的**紅色**描邊 | 這一列指向儲存庫之外 | Obsidian 無法把那裡的東西當作筆記開啟，並且在你打開鎖頭之前，外面不會被寫入任何東西。 |
| 路徑列上的**橘色**描邊、清單中的橘色項目 | 該檔案是 Obsidian 沒有檢視可用的文字類型 | 一個提醒。Obsidian 會把它交給桌面的預設應用程式；外掛則改為顯示它。 |

**兩者相互獨立，且可以同時成立** — 一個外部的 `.json` 既在儲存庫之外，*又*是 Obsidian 沒有編輯器的類型。在檢視器裡它們呈現為各自獨立的列，各自只陳述自己的那件事。而在路徑列上，兩者都成立時紅色勝出，因為兩圈描邊只會變成雜訊。

橘色這一級是刻意收窄的。已註冊的類型（Markdown、canvas、圖片、PDF、音訊、視訊）會被妥善處理，什麼也不加。二進位檔案同樣什麼也不加 — 你不會不小心把一個 `.zip` 編輯成一團亂。剩下的恰好就是危險所在：被 **偵測所有的副檔名** 變得可見的 `.json`、`.css` 或 `.log`。

兩者都會成立時紅色勝出；同時出現兩圈描邊只會是雜訊。

## 重新命名/移動模式

標題列最右側的鉛筆按鈕 — 緊鄰檢視模式按鈕，與原生按鈕同樣大小 — 切換重新命名/移動模式。此時標題列會以強調色描邊，與在檔案瀏覽器中重新命名時一模一樣。同樣的點擊與按鍵，如今會經由 Obsidian 的 `fileManager.renameFile` 送出一次移動或重新命名，因此指向該筆記的所有連結都會隨之更新。

重新命名期間：

- 目前的檔名會被釘在每個資料夾的清單裡，所以「移動筆記但不改名」只需點一下。
- 目標資料夾中已被占用的名稱會變灰，但仍可選取。
- 輸入會即時按 Obsidian 自己的重新命名規則驗證 — 同樣的字元集、同樣的訊息、與在檔案樹中重新命名時相同的紅色提示 — 因此不合法或衝突的名稱會在你輸入時被標出，並且無法送出。
- 點擊標題列之外，或標題列失去焦點，都會結束重新命名模式。

## 一個鍵管兩種重新命名

重新命名指令（預設 <kbd>F2</kbd>，或你重新指定的按鍵）會在 Obsidian 的行內標題重新命名與本外掛「全路徑已選取的標題路徑列」之間**交替**。若你關閉了 Obsidian 的行內標題，標題路徑列便成為唯一目標，於是這個鍵永遠不會毫無作用。

這是透過包裝 `workspace:edit-file-title` 指令實現的，而不是去搶按鍵，因此重新指定快速鍵和從指令面板執行指令都照常有效。

## 清單項目的著色

| 顏色 | 含義 |
| --- | --- |
| **紫色** | 一篇筆記（`.md`、`.markdown`）— Obsidian 會作為筆記開啟的東西，從內容混雜的資料夾中挑出來 |
| **橘色** | Obsidian 沒有檢視可用的文字類型；參見[警示顏色](#兩種警示顏色) |
| **暗淡** | 位於儲存庫之外，因此儲存庫自己的那套處理不適用 |
| **藍色** | 你目前所在的筆記。瀏覽時是它自己的那一項；在重新命名/移動模式下，*保留此名稱* 這一項站在它的位置上 — 兩者都是同一則筆記 |
| **灰階** | 僅限重新命名/移動模式：該名稱已被占用。仍可選取 — 選取會填入輸入欄，驗證會在那裡標出衝突 |

## 可見性規則

- 只有在 Obsidian 的 **偵測所有的副檔名** 設定開啟時，副檔名不受支援的檔案才會出現在清單中。
- 清單最多顯示 100 項 — 這是 Obsidian 自己的上限。當某個資料夾超過此數時，最後一列會說明省略了多少項；繼續輸入以縮小範圍。
- 只有在本外掛的 **顯示點檔案** 設定開啟時，點檔案和點資料夾才會出現。
- **覆寫保護與是否可見無關，行為完全一致** — 隱藏的檔案同樣會阻止你覆寫它。

| --- | --- |

| 把一個資料夾換成同層的另一個 | 點擊該資料夾名稱，然後輸入或挑選 |

| 重打某個資料夾及其下的一切 | **按兩下**該資料夾名稱，然後輸入 |
| 從某個資料夾起往下編輯路徑 | 點擊該資料夾名稱，再按 <kbd>End</kbd> 或 <kbd>→</kbd> 取消選取 |
| 輸入路徑跳到某個檔案 | 點擊檔名或空白處，輸入，按 <kbd>Enter</kbd> |
| 改為在新分頁開啟檔案 | 挑選時按 <kbd>Ctrl</kbd>，或按 <kbd>Ctrl</kbd>+<kbd>Enter</kbd> |
| 把筆記複製到某處而不是移動 | 鉛筆，然後在挑選或送出目標時按 <kbd>Ctrl</kbd> |
| 在不存在的路徑上建立筆記 | 輸入路徑，按 <kbd>Enter</kbd>，確認詢問 |
| 輸入時往下一層 | 輸入 `/` |
| 輸入時往上一層 | 在空的輸入欄中按 <kbd>Backspace</kbd> |
| 移動或重新命名目前開啟的筆記 | 點擊鉛筆，然後照上面瀏覽或輸入 |

| 取消任何操作 | 按 <kbd>Esc</kbd>，或點擊標題列之外 |

## 設定

| 設定 | 選項 | 預設 | 作用 |
| --- | --- | --- | --- |
| **對齊方式** | 靠左 / 置中 / 靠右 | 靠左 | 路徑在標題列中的位置。*置中* 與 Obsidian 的經典樣式一致。 |
| **分隔符號** | 任意字元 | `/` | 繪製在各段之間的分隔符。文字方塊前面擺著六個一鍵預設（`/ > ▸ › \ •`）。 |
| **顯示儲存庫名稱** | 開 / 關 | 開 | 儲存庫本身是否作為路徑的第一段。關閉後那一段會變成 🏠 圖示而不是消失，因此路徑起點仍是可點擊的。 |
| **資料夾名稱開啟清單** | 開 / 關 | 開 | 互換資料夾名稱與其後分隔符的作用 — 參見[上面的表](#路徑列)。裝有 [Folder notes](obsidian://show-plugin?id=folder-notes) 時，分隔符開啟資料夾筆記。在重新命名/移動模式下永不適用。 |
| **顯示點檔案** | 開 / 關 | 關 | 點檔案和點資料夾是否列入清單。覆寫保護無論如何都適用。 |
| **存取外部檔案** | 開 / 關 | **關** | 儲存庫名稱是否開啟位置清單。關閉時，外掛中沒有任何部分會望向本儲存庫之外。 |

## 更換圖示

Lure 繪製三枚圖示：儲存庫根目錄圖示（當 **顯示儲存庫名稱** 關閉時）、重新命名/移動開關，以及守著「寫入儲存庫之外」的鎖頭。它們都可以從佈景主題或 CSS 片段中更換 — 在同一條規則裡設定替代字元並隱藏內建的那個：

```css
.lure-vault-icon {
	--lure-icon-glyph: "🏠";
	--lure-icon-svg: none;
}

.lure-rename-btn {
	--lure-icon-glyph: "✎";
	--lure-icon-svg: none;
}

/* 鎖頭有兩種狀態；`.is-active` 是打開的那一種。 */
.lure-unlock-btn {
	--lure-icon-glyph: "🔒";
	--lure-icon-svg: none;
}

.lure-unlock-btn.is-active {
	--lure-icon-glyph: "🔓";
}
```

`--lure-icon-glyph` 接受任何在 CSS `content` 中合法的值，因此 `url(...)` 可用於圖片，正如文字或表情符號字元一樣。若想保留 Lucide 圖示並把你的字元畫在它旁邊，就別動 `--lure-icon-svg`。
