# Lure

一個 [Obsidian](https://obsidian.md) 外掛程式，把筆記標題列中的檔名變成可點擊、可編輯的麵包屑導覽，顯示它在儲存庫中的完整路徑——就像 [Dolphin](https://apps.kde.org/dolphin/) 檔案管理員的網址列。

![點擊資料夾後面的分隔符號：游標停在上面，檔案瀏覽器已顯示並展開該資料夾](../images/breadcrumb.png)

Obsidian 1.8.7+ · 僅限桌面版 · AGPL-3.0

## AI 揭露

- **代理** — **Claude Opus 5** 與 **Claude Sonnet 5**（Anthropic，透過 Claude Code）：撰寫了 TypeScript、CSS、全部 45 套翻譯與文件。翻譯為機器生成，未經母語者校訂。
- **用量** — 2026 年 8 月 3 日至 9 月 19 日，20 個工作階段，約 16,460 次回應：生成約 1,990 萬個 token，傳送約 8,700 萬個，快取重讀約 54.510 億個（合計約 55.580 億個）。
- **上游** — 模型是從他人發表的開放原始碼、文件與社群文章中學習的。大部分功勞應歸於他們。
- **作者** — Vault51：規劃每一項功能，在實際使用的儲存庫中測試每一次迭代，主導修正方向，並審閱所有產出。

## 功能

- **點擊資料夾**會開啟其*上層資料夾*內容的下拉清單——把某個資料夾換成同層的另一個，路徑的其餘部分保持不變。筆記名稱也以同樣方式運作，並會選取不含副檔名的名稱。
- **點擊資料夾後面的分隔符號**，即可在檔案瀏覽器中顯示並展開該資料夾。一項設定可以互換這兩種角色。
- **對任一項目按右鍵或拖曳**——出現的就是檔案瀏覽器本身的右鍵選單，項目一一對應，拖曳行為也相同。儲存庫以外的路徑則有專為它們打造的對等選單，連*刪除*都有，透過系統資源回收筒進行。
- **點擊檔名或空白處**即可輸入路徑，並有自動補全。`/` 往下進入，<kbd>Backspace</kbd> 往上退出，<kbd>Enter</kbd> 確認——尚不存在的路徑會直接建立，並跳出通知告訴你建在哪裡。
- **清單會在你所在的項目上開啟**，用方向鍵或滑鼠移過項目時，欄位會填入你所指的內容。指向的一列會顯示為它將給出的提示；移出清單的任一端，會還原你原本輸入的文字；游標離開清單時，醒目標示會回到你原來的位置。清單會跟隨游標：顯示游標所在的資料夾，並依其前面的字母篩選。
- **資料夾上的鉛筆按鈕**會把同樣的互動切換成移動／重新命名，並以與 Obsidian 相同的方式驗證。已經使用的名稱會在清單中顯示為紅色，選擇它會詢問要重新命名擋路的那個，還是與它互換位置或名稱。
- **按住 <kbd>Ctrl</kbd>** 可在新分頁中開啟——在移動／重新命名模式下，則改為把筆記複製過去。筆記名稱與各個資料夾段落接受的修飾鍵和拖曳，都與它們在檔案瀏覽器中的列相同。
- **名稱會隨著輸入自動補全**——<kbd>Tab</kbd> 將會寫入的內容會以選取狀態出現在游標後方，依名稱本身的拼寫顯示，無論你輸入的是大寫還是小寫——也就是資料夾內的名稱有共同部分之處，或在一致中斷時，朝其中第一個名稱邁出的一步；繼續輸入會逐字吃掉它，<kbd>→</kbd> 只接受一個字母，<kbd>Tab</kbd> 或 <kbd>End</kbd> 整段接受，<kbd>Backspace</kbd> 則把它收回。清單會持續依你實際輸入的內容篩選，而不是依建議的內容。
- **<kbd>Tab</kbd> 像 shell 一樣補全**：它會把你輸入的內容延伸到該資料夾中各名稱一致之處為止；名稱不一致時，一次一步朝其中一個前進；只有剩下唯一一個名稱時才進入資料夾。超過路徑末端後，它改為擴大選取範圍：名稱、含副檔名的名稱、從儲存庫起算的路徑、從系統根目錄起算的路徑。<kbd>Shift</kbd>+<kbd>Tab</kbd> 沿同一條路倒著走——把退回的部分標示出來，而不是刪除——越過起點後會繼續沿路徑往上，然後繞回系統路徑。無論往哪個方向，繞一圈都會回到你建立的路徑。
- **右鍵複製**——按兩下複製名稱，按三下複製它右邊的全部內容；在空白處則複製整個路徑或系統路徑。
- **把一則筆記拖到路徑列的某個資料夾上**即可移動過去，連結也會一併更新——目的地已經在畫面上，所以只要拖一次，不必在檔案樹裡繞一大圈。儲存庫名稱也可以，代表根目錄。整批選取的項目會一起移動；無法接受拖入內容的資料夾則不會有任何反應，而不是事後才失敗。
- **把文字拖放到路徑列上即可記下來**——放到資料夾或儲存庫名稱上，會以它為名建立一則新筆記；放到筆記本身的名稱上，則附加到你正在閱讀的內容末尾。從桌面拖來的檔案也一樣，而在可以放下時，該列會亮起藍色外框。
- **欄位會帶上它所指名稱的顏色**——與該列在清單中的顏色相同，資料夾筆記為灰色——一旦沒有任何東西與之對應就會**變成紅色**，讓你在按下 <kbd>Enter</kbd> 之前就知道它會開啟筆記還是建立筆記。
- **HTML 檔案會以網頁呈現**，放在一個收回所有權限的框架中——沒有指令碼、沒有網路、沒有自己的來源（origin）——並會帶入檔案旁邊的樣式表與圖片，讓儲存下來的網頁看起來依然是原本的樣子。原始碼只要按一下就能檢視。
- **輸入網址**——`https://`、`obsidian://`，或 `file://` 與百分比編碼的路徑——就會直接開啟，而不會被當成筆記名稱。若你已啟用 Obsidian 內建的網頁檢視器，網址會在它的分頁中開啟。
- **長路徑會從字母冗餘之處縮短**——絕不縮到無法和隔壁資料夾區分的程度，而且是平順地縮短，不是一次跳一個字母——只有在沒有任何東西可再壓縮時才會捲動。將游標指向縮短的名稱即可看到完整名稱。
- **<kbd>F2</kbd>** 在行內標題與路徑列之間切換，開啟時選取不含副檔名的名稱，再按則逐步擴大到完整路徑。當標題已捲出畫面時，它也能順利穿過 Obsidian 的重新命名對話框。另有*聚焦路徑列*指令，可走同樣的階段而不重新命名；設定中的*快速鍵*列可直接帶你前往綁定。
- **點擊儲存庫名稱**即可瀏覽你的其他儲存庫、家目錄、檔案系統根目錄與已掛載的磁碟，而不必切換儲存庫。在你打開於該處取代重新命名切換鈕的紅色掛鎖之前，一律為唯讀，且全程以錯誤色框起。預設關閉——請參閱[儲存庫之外](#儲存庫之外)。
- **儲存庫根目錄會列出窗格可以容納的頁面**——`:graph`、`:search`，以及你的外掛註冊的各種檢視。選一個，或直接輸入：冒號不會出現在任何檔名開頭，因此這些標籤同時也是位址。在資料夾內輸入 `:graph` 會開啟該資料夾的關係圖。安裝起始頁面外掛後，儲存庫自己的分隔符第一次點擊會開啟該頁面，下一次點擊則收合檔案樹。
- **不含檔案的窗格上的一列**——空白分頁顯示為 `vault / :blank`，關係圖為 `vault / :graph`，旁邊的欄位是網址列：輸入路徑後按 <kbd>Enter</kbd>，即在該窗格中開啟，或建立它。側邊欄窗格保留 Obsidian 自己的標題。
- **兩級警示**——儲存庫之外為紅色，Obsidian 沒有對應編輯器的文字檔為橘色。請參閱[警示顏色](usage.zh-TW.md#兩種警示顏色)。
- **可隨佈景主題更換的圖示**，透過 CSS 程式碼片段替換——以及 **46 種語言**：Obsidian 內建的每一種，外加它沒有提供設定的希臘文與梵文。可以只為本外掛選擇一種語言，或跟隨 Obsidian 本身的語言。
- **設定：** 語言、對齊方式、分隔符號預設組合、哪一種點擊會開啟清單、儲存庫名稱、點檔案（dot files）、副檔名。

![移動／重新命名模式下的同一個清單：目前的檔名固定在最上方，下方是同層資料夾，已存在的筆記呈灰色](../images/dropdown.png)

*在移動／重新命名模式下，同一個清單提供的選項會有所不同：筆記目前的名稱固定在最上方，可用來移動而不改名；接著是可以移入的資料夾；已被使用的名稱則呈紅色；選擇它會詢問該如何處理擋路的檔案。*

## 儲存庫之外

Obsidian 的開發者政策要求外掛說明任何對儲存庫以外檔案的存取，因此在此直說：

**它究竟做不做這些事。** 只有在你開啟**存取外部檔案**時才會，而這個選項**預設關閉**。關閉時，外掛完全無法觸及任何外部路徑，下面描述的程式碼也一概不會執行。

**它讀什麼。** 只在你要求時才讀。點擊儲存庫名稱會列出你的其他儲存庫——讀取自 Obsidian 自己的 `obsidian.json`——以及你的家目錄、檔案系統根目錄與已掛載的磁碟（Linux 上為 `/proc/mounts`，macOS 上為 `/Volumes`，Windows 上為磁碟機代號）。從那裡瀏覽會列出目錄內容，開啟檔案則只讀取那一個檔案。

**它寫什麼。** 什麼都不寫，直到你按下明確表示要寫入的按鈕。這樣的按鈕有兩個，各自只涵蓋自己的範圍：

- 檢視器的**以文字編輯**按鈕會解鎖你眼前的檔案，僅限該分頁中的那一個檔案。之後你的編輯會隨著輸入存回該檔案。
- 標題列的**紅色掛鎖**會在路徑列指向儲存庫之外時佔據重新命名切換鈕的位置，它會解鎖在外部路徑上建立、重新命名、移動與刪除的權限——打開後便把位置交還給切換鈕。當你回到儲存庫內，或按下離開重新命名模式的那一下時，它會重新上鎖，因此權限絕不會比你授權的那個資料夾活得更久。

兩種解鎖都不會儲存在工作區或設定中，所以寫入權限絕不會在你不記得開過的檔案上悄悄待命。無論在哪種狀態下，都不會覆寫任何東西——目標已存在時一律拒絕，採用的是檔案系統本身的獨占建立（exclusive create），而不是可能輸掉競態條件的事先檢查。

把筆記移*出*儲存庫，是唯一一種代價無從挽回的寫入：Obsidian 只會更新儲存庫內的連結，所以每個指向該筆記的連結都會失效。這項操作會先跳出對話框說明這一點，並計算受影響的筆記數量；實際執行時則是先複製、再透過 Obsidian 自己的垃圾桶刪除，因此和刪除筆記一樣可以復原。按住 <kbd>Ctrl</kbd> 則改為複製出去。

**為什麼。** 你想找的筆記常常在另一個儲存庫、同步資料夾或 USB 隨身碟裡，而 Obsidian 本身的解法——切換儲存庫——會關掉你開著的所有東西。這讓你不必離開就能過去看看，順手修正錯字。

**限制。** Obsidian 的編輯器只綁定儲存庫內的檔案，所以外部檔案**無法**以具備連結、反向連結等功能的真正筆記開啟；任何外掛都做不到。Lure 改以自己的檢視器顯示它（Markdown、圖片、音訊、影片、PDF），其他類型則提供*以外部程式開啟*。只要路徑列指向儲存庫之外，就會一直以錯誤色框起；路徑軌跡從你選擇的位置開始——儲存庫名稱、家目錄、磁碟——而不是從電腦的目錄結構開始。

## 安裝

**在 Obsidian 中：** 開啟 **設定 → 第三方外掛程式 → 瀏覽**，搜尋 *Lure*，然後按 *安裝* 與 *啟用*——或在 [community.obsidian.md/plugins/lure](https://community.obsidian.md/plugins/lure) 上按 *Add to Obsidian*。

**手動：** 從[最新版本](https://github.com/Gelaende51/obsidian-lure/releases)下載 `main.js`、`manifest.json` 與 `styles.css` 到 `<vault>/.obsidian/plugins/lure/`，然後在**設定 → 第三方外掛程式**中啟用。

**BRAT：** 將 `Gelaende51/obsidian-lure` 新增為 beta 外掛。

**從原始碼：** `npm install && npm run build`——請參閱[開發](../development.md)。

## 相容性

不需要任何其他外掛。核心外掛**檔案瀏覽器**若已啟用，就由它在側邊欄中顯示資料夾；沒有它的話，這些點擊不會有任何作用。

已針對共用筆記標題列或會回應資料夾點擊的第三方外掛進行測試——兩種載入順序，各自開啟與關閉：

- [Folder notes](obsidian://show-plugin?id=folder-notes)——分隔符號會開啟資料夾的筆記，而不是顯示資料夾，讓路徑的每一段無論多深都成為可以前往的地方：筆記是依照該外掛本身的慣例解析出來的，而不是交給它去回應。它也是唯一公開這種慣例的外掛；[Folder Note](obsidian://show-plugin?id=folder-note-plugin) 與 [create folder notes with dropdown](obsidian://show-plugin?id=create-folder-notes-with-dropdown) 沒有公開任何慣例，也從不接管標題列的路徑，所以搭配它們時，分隔符號照常顯示資料夾。
- [Quick Explorer](obsidian://show-plugin?id=quick-explorer) 與 [Front Matter Title](obsidian://show-plugin?id=obsidian-front-matter-title-plugin)——兩者都繪製到同一個標題元素中；無論誰先載入，Lure 都會保住這一列，關閉其中任何一個也不會影響另一個。
- [Nav Link Header](obsidian://show-plugin?id=nav-link-header)、[Running Head](obsidian://show-plugin?id=running-head)、[Crumbs](obsidian://show-plugin?id=crumbs-obsidian)、[Breadcrumbs](obsidian://show-plugin?id=breadcrumbs)——各自擁有自己的區塊，可以共存。

僅限桌面版——這種互動模式需要滑鼠懸停、精確點擊與鍵盤。完整結果、尚待驗證的預期，以及與 Quick Explorer 和 Breadcrumbs 的比較，請參閱[相容性](../compatibility.md)。
