# Lure

一个 [Obsidian](https://obsidian.md) 插件，把笔记标题栏中的文件名变成一条可点击、可编辑的面包屑导航，显示它在仓库中的完整路径——就像 [Dolphin](https://apps.kde.org/dolphin/) 文件管理器的地址栏。

![点击某个文件夹后面的分隔符：指针停在分隔符上，文件列表已定位并展开了该文件夹](../images/breadcrumb.png)

Obsidian 1.8.7+ · 仅限桌面端 · AGPL-3.0

## AI 披露

- **代理** — **Claude Opus 5 / 5.5** 和 **Claude Sonnet 5**（Anthropic，通过 Claude Code）：编写了 TypeScript、CSS、全部 45 套翻译以及文档。翻译均为机器生成，未经母语者校订。
- **用量** — 2026 年 8 月 3 日至 9 月 23 日，25 个会话，约 17973 次回复：生成约 2110 万 token，发送约 9120 万，缓存重读约 58.170 亿（合计约 59.293 亿）。
- **上游** — 模型学习自他人发布的开源代码、文档和社区文章。大部分功劳归于他们。
- **作者** — Vault51：提出了每一项功能，在真实仓库中测试了每一次迭代，指导修复，并审阅了全部产出。

## 功能

- **点击文件夹**，弹出其*父文件夹*内容的列表——把一个文件夹换成同级的另一个，路径的其余部分保持不变。笔记名称的用法相同，选中时不含扩展名。
- **点击文件夹后面的分隔符**，在文件列表中定位并展开该文件夹。一个设置即可互换这两种作用。
- **对任意条目右键或拖拽**——得到的是文件列表自己的右键菜单，条目一一对应，拖拽行为也相同。仓库之外的路径会得到专门为其构建的同等菜单，连*删除*都有，经由系统回收站完成。
- **点击文件名或空白处**即可输入路径，并带自动补全。`/` 进入下一级，<kbd>Backspace</kbd> 退回上一级，<kbd>Enter</kbd> 确认——如果路径尚不存在，就直接创建，并弹出通知告诉你建在了哪里。
- **列表在你所处的条目上打开**，用方向键或鼠标悬停浏览时，输入框会填入你所指向的内容。指向的一行会显示为它将给出的提示；移出列表的任一端会还原你输入的内容，指针离开列表时，高亮会回到你原来的位置。列表跟随光标：显示光标所在的文件夹，并按其前面的字母过滤。
- **文件夹上的铅笔按钮**把同样的交互切换为移动/重命名，校验方式与 Obsidian 一致。已被占用的名称会在列表中显示为红色，选择它会打开两个可并排编辑的路径，只需一次选择即可互换位置、名称或整体。
- **按住 <kbd>Ctrl</kbd>** 在新标签页中打开——在移动/重命名模式下，则改为把笔记复制过去。笔记名称和各文件夹段接受与文件列表中对应行相同的修饰键，也同样可以拖拽。
- **名称会随着输入自动补全**——<kbd>Tab</kbd> 将会写入的内容会以选中状态出现在光标之后，按名称本身的拼写显示，无论你输入的是大写还是小写——即文件夹中各名称一致的部分，或者在一致中断处，朝其中第一个名称迈出的一步；继续输入会逐字吞掉它，<kbd>→</kbd> 只采纳一个字母，<kbd>Tab</kbd> 或 <kbd>End</kbd> 整体采纳，<kbd>Backspace</kbd> 撤回。列表始终按你输入的内容筛选，而不是按补全提示的内容。
- **<kbd>Tab</kbd> 像 shell 一样补全**：它把你输入的内容延伸到该文件夹中各名称一致为止；名称不一致时，一步一步向其中一个靠近；只有剩下唯一一个名称时才进入文件夹。越过路径末尾后，它改为扩大选区：名称、带扩展名的名称、从仓库起的路径、从系统根目录起的路径。<kbd>Shift</kbd>+<kbd>Tab</kbd> 沿同一路线反向走——把退回的部分标记出来而不是删除——越过起点后继续沿路径向上，然后绕回到系统路径。无论朝哪个方向，走完一圈都会回到你构建的路径。
- **右键复制**——在名称上按两次复制该名称，按三次复制从它往右的全部内容；在空白处则复制整个路径或系统路径。
- **把一篇笔记拖到路径栏的某个文件夹上**即可移动过去，链接一并更新——目标已经显示在屏幕上，所以只需拖一次，不必在文件树里来回寻找。仓库名同样可用，对应根目录。整批选中的内容会作为一个整体移动；无法接收所拖内容的文件夹不会有任何反应，而不是事后才报错。
- **把文本拖到路径栏上即可记下来**——拖到文件夹或仓库名上，为它新建一篇笔记并命名；拖到笔记自己的名称上，追加到你正在阅读的内容末尾。从桌面拖来的文件也一样；在可以放下的位置，该行会亮起蓝色边框。
- **输入框带上它所指内容的颜色**——与该行在列表中的颜色相同，文件夹笔记为灰色——一旦没有对应的内容就**变红**，这样在按下 <kbd>Enter</kbd> 之前，你就能看出它会打开一篇笔记还是新建一篇。
- **HTML 文件以网页形式显示**，放在一个收回了全部权限的框架中——没有脚本、没有网络、没有自己的源（origin）——同时把文件旁边的样式表和图片一并载入，让保存下来的网页仍保持原貌。源代码只需按一下即可查看。
- **输入网址**——`https://`、`obsidian://`，或 `file://` 及百分号编码的路径——它会被直接打开，而不是当作笔记名称。如果你启用了 Obsidian 自带的网页浏览器，网页地址会在它的标签页中打开。
- **长路径会从字母冗余之处缩短**——绝不缩到无法与相邻文件夹区分的程度，而且是平滑过渡，而不是一次一个字母——只有在无可再压缩时才滚动。指向缩短的名称即可看到完整名称。
- **<kbd>F2</kbd>** 在内联标题和路径栏之间切换，打开时选中不含扩展名的名称，继续按则逐步扩展到完整路径。当标题滚出视野时，它会顺畅地穿过 Obsidian 的重命名对话框。*聚焦路径栏*命令按同样的层级逐步切换而不重命名；设置中的*快捷键*行可带你前往绑定它。
- **点击仓库名**即可浏览你的其他仓库、主目录、文件系统根目录和已挂载的驱动器，无需切换仓库。在那里默认只读，直到你打开取代重命名开关位置的红色挂锁，并且全程以错误色框出。默认关闭——参见[仓库之外](#仓库之外)。
- **仓库根目录会列出窗格可以容纳的页面** — `:graph`、`:search`，以及你的插件注册的任何视图。可以选择，也可以输入：冒号不会出现在任何文件名的开头，因此这些标签同时也是地址。在文件夹内输入 `:graph` 会打开该文件夹的关系图。安装了起始页插件后，点击仓库自己的分隔符，第一次会打开该页面，下一次会收起文件树。
- **不含文件的窗格上的一行** — 空标签页显示为 `vault / :blank`，图谱显示为 `vault / :graph`，旁边的字段是地址栏：输入路径后按 <kbd>Enter</kbd>，即可在该窗格中打开它，或创建它。侧边栏窗格保留 Obsidian 自带的标题。
- **两级警示**——仓库之外为红色，Obsidian 没有对应编辑器的文本文件为橙色。参见[警示颜色](usage.zh.md#两种警示颜色)。
- **可随主题更换的图标**，通过 CSS 片段替换——以及 **46 种语言**：Obsidian 自带的每一种，外加 Obsidian 没有提供设置项的希腊语和梵语。可以单独为插件选择语言，也可以跟随 Obsidian 的语言。
- **设置：** 语言、对齐方式、分隔符预设、由哪种点击打开列表、仓库名、点文件、文件扩展名。

## 仓库之外

Obsidian 的开发者政策要求插件说明任何对仓库之外文件的访问，所以在此直说：

**它究竟做不做这些事。** 只有当你打开**访问外部文件**时才会，而它**默认关闭**。关闭时，插件没有任何途径访问外部路径，下面所述的代码也从不运行。

**它读什么。** 只在你要求时才读。点击仓库名会列出你的其他仓库——读取自 Obsidian 自己的 `obsidian.json`——以及你的主目录、文件系统根目录和已挂载的驱动器（Linux 上为 `/proc/mounts`，macOS 上为 `/Volumes`，Windows 上为盘符）。从那里浏览会列出目录内容，打开文件则只读取那一个文件。

**它写什么。** 什么都不写，直到你按下明确表示要写入的按钮。这样的按钮有两个，各自只管自己的范围：

- 查看器的**以文本编辑**按钮会解锁你眼前的文件，仅限这一个标签页中的这一个文件。之后你的编辑会随输入保存回该文件。
- 标题栏的**红色挂锁**在路径栏指向仓库之外时占据重命名开关的位置，它会解锁在外部路径上的创建、重命名、移动和删除——打开后便把这个位置交还给开关。当你回到仓库内，或者按下退出重命名模式的那一下时，它会重新上锁，因此权限绝不会比你授权时所在的文件夹存续得更久。

两种解锁都不会保存在工作区或设置中，所以写入绝不会在你不记得打开过的文件上处于待命状态。无论哪种状态都不会覆盖任何内容——已存在的目标会被拒绝，靠的是文件系统自身的独占创建，而不是可能在竞态中落败的事先检查。

把笔记*移出*仓库是唯一一种代价无法挽回的写入：Obsidian 只更新仓库内的链接，因此所有指向该笔记的链接都会失效。这项操作会先弹出对话框说明这一点，并统计受影响的笔记数量；执行方式是先复制、再通过 Obsidian 自己的回收站删除，所以它和删除一篇笔记一样可以恢复。按住 <kbd>Ctrl</kbd> 则改为复制出去。

**为什么。** 你想要的笔记常常在另一个仓库、同步文件夹或 U 盘里，而 Obsidian 自己的办法——切换仓库——会关闭你打开的所有内容。这个插件让你无需离开就能去看一看，顺手改个错字。

**局限。** Obsidian 的编辑器绑定于仓库内的文件，所以外部文件**无法**作为带有链接、反向链接等功能的真正笔记打开；任何插件都做不到。Lure 改为在自己的查看器中显示它（Markdown、图片、音频、视频、PDF），其他类型则提供*在外部打开*。只要路径栏指向仓库之外，就始终以错误色框出；路径从你选择的位置开始——某个仓库名、你的主目录、某个驱动器——而不是从机器的目录结构开始。

## 安装

**在 Obsidian 中：** 打开 **设置 → 第三方插件 → 浏览**，搜索 *Lure*，然后点击 *安装* 和 *启用*——或在 [community.obsidian.md/plugins/lure](https://community.obsidian.md/plugins/lure) 上点击 *Add to Obsidian*。

**手动：** 从[最新发布](https://github.com/Gelaende51/obsidian-lure/releases)下载 `main.js`、`manifest.json` 和 `styles.css`，放入 `<vault>/.obsidian/plugins/lure/`，然后在**设置 → 第三方插件**中启用。

**BRAT：** 将 `Gelaende51/obsidian-lure` 添加为 beta 插件。

**从源码：** `npm install && npm run build`——参见[开发](../development.md)。

## 兼容性

不需要任何其他插件。核心插件**文件列表**如果已启用，负责在侧边栏中定位文件夹；没有它，这些点击不会产生任何效果。

已针对与本插件共用笔记标题栏或响应文件夹点击的第三方插件进行测试——两种加载顺序，每个插件分别开启和关闭：

- [Folder notes](obsidian://show-plugin?id=folder-notes)——分隔符会打开文件夹的文件夹笔记，而不是定位该文件夹，使路径中的每一段无论多深都成为可以前往的地方：笔记按照该插件自己的约定解析，而不是交给它去响应。它也是唯一公开此类约定的插件；[Folder Note](obsidian://show-plugin?id=folder-note-plugin) 和 [create folder notes with dropdown](obsidian://show-plugin?id=create-folder-notes-with-dropdown) 没有公开任何约定，也从不接管标题栏路径，所以与它们搭配时，分隔符照常定位文件夹。
- [Quick Explorer](obsidian://show-plugin?id=quick-explorer) 和 [Front Matter Title](obsidian://show-plugin?id=obsidian-front-matter-title-plugin)——两者都在同一个标题元素中绘制；无论谁先加载，Lure 都保有这一行，关闭其中任何一个都不会影响另一个。
- [Nav Link Header](obsidian://show-plugin?id=nav-link-header)、[Running Head](obsidian://show-plugin?id=running-head)、[Crumbs](obsidian://show-plugin?id=crumbs-obsidian)、[Breadcrumbs](obsidian://show-plugin?id=breadcrumbs)——各自拥有自己的栏，可以共存。

仅限桌面端——这种交互方式需要悬停、精确点击和键盘。完整测试结果、尚待验证的预期，以及与 Quick Explorer 和 Breadcrumbs 的比较，见[兼容性](../compatibility.md)。
