# Використання

[← назад до README](README.uk.md)

## Рядок шляху

Повний шлях нотатки всередині сховища замінює саме лише ім'я файлу в шапці подання — на смузі під рядом вкладок, тій самій, де є кнопки «назад» і «вперед».

У рядку клікабельні дві речі, і **Назва теки відкриває список** вирішує, що з них що робить:

| | Назва теки | Роздільник після неї |
| --- | --- | --- |
| **Увімкнено** (типово) | Виділяє цю теку для редагування | Відкриває теку |
| **Вимкнено** | Відкриває теку | Спускається в цю теку |

«Відкриває теку» означає те, що робить цей клік у чистому Obsidian. Якщо там ніхто не слухає, тека показується в бічній панелі Файлового менеджера — підсвічена й розгорнута, щоб було видно вміст.

Якщо тека належить нотатці, яку ви саме читаєте, клік замість цього просто показує теку — немає нічого, що можна було б відкрити, чого й так немає на екрані, і саме це завжди означало друге натискання.

Зі встановленим [Folder notes](obsidian://show-plugin?id=folder-notes) той самий клік натомість відкриває нотатку цієї теки, **на будь-якій глибині**: нотатка визначається тут за власним правилом цього плагіна, а не полишається на його розсуд. Той плагін розпізнає лише позначені ним теки, яких на шляху глибшому за одну теку немає жодної, тож натискання, що раніше відкривало нотатку теки верхнього рівня, глибше вже нічого не робило. Два інші плагіни для нотаток тек не публікують жодного правила для читання й ніколи не перехоплюють рядок, тож із ними роздільник, як і завжди, показує теку. Це єдиний знайдений плагін для нотаток тек, що перехоплює шлях у шапці; [Folder Note](obsidian://show-plugin?id=folder-note-plugin) та [create folder notes with dropdown](obsidian://show-plugin?id=create-folder-notes-with-dropdown) керують нотатками тек, але не слухають клік по рядку шляху, тож із ними роздільник, як завжди, показує теку. Див. [сумісність](../compatibility.md#verified-against).

Роздільник **підкреслений лише тоді, коли в теки перед ним справді є нотатка теки**, тож підкреслення — це обіцянка, що там є що відкрити — на будь-якій глибині, якщо працює [Folder notes](obsidian://show-plugin?id=folder-notes), бо нотатка визначається тут, а не полишається тому плагіну для позначення. Якщо працює не цей плагін, нічого не підкреслюється й нічого не відкривається: роздільник просто показує теку, як і за повної відсутності плагінів для нотаток тек. Кожен роздільник лишається клікабельним у будь-якому разі — той, що без підкреслення, показує й розгортає свою теку в бічній панелі, про що й далі свідчить курсор-покажчик. Підкреслення водночас зникає з назви теки: коли заміна ввімкнена, назва відкриває список, тож позначати її як посилання на нотатку було б неправдою.

**Режим перейменування/переміщення головніший за обидва**, хай там що каже налаштування: доки переміщення не завершено, ніщо в рядку не відкриває теку, бо відкриття покинуло б переміщення. Назви тек виділяються для правки, а роздільники спускаються вниз — і те, й те способи вибрати ціль — а підкреслення зникає, показуючи, що відкриття призупинено.

**Корінь сховища** — єдиний сегмент, який не є сегментом шляху. У нього немає батьківської теки, з якої можна перелічити сусідів, тож він відкриває натомість [список розташувань](#перегляд-поза-сховищем) — ваші інші сховища, домашню теку, корінь файлової системи та підключені диски.

## Власний роздільник сховища

Роздільник одразу після назви сховища позначає саме сховище, а не теку,
тож він робить те, чого не може жоден інший роздільник:

| | Перший клік | Наступний клік |
| --- | --- | --- |
| **З плагіном стартової сторінки** (сторінкою, яка зустрічає вас при відкритті Obsidian) | Відкриває цю сторінку в цій панелі | Згортає дерево файлів |
| **Без нього** | Згортає дерево файлів | Повертає точно те, що було відкрито |

Це звичайні кліки, а не подвійний клік: щойно сторінка відкрита, роздільнику
більше нічого відкривати, тож наступне натискання — це згортання, скільки б
часу між ними не минуло.

Він **підкреслений**, коли є стартова сторінка для відкриття — та сама
обіцянка, що дає роздільник теки: там щось є. Згортання перемикається туди-сюди —
наступне натискання відновлює саме ті теки, що були відкриті, і лише їх, тож
дерево, яке ви впорядкували, не втрачається через погляд на щось інше.

## Панель без файлу

Порожня вкладка, граф і будь-що інше, що не називає файл, отримують власний
рядок: сховище, а тоді один сегмент, що каже, що саме утримує панель.

```
my-vault / :blank      нова вкладка
my-vault / :graph      граф, локальний або глобальний
my-vault / :<type>     будь-що інше без файлу
```

**Власний список кореня сховища** теж пропонує ці сторінки — під теками й
нотатками, які в ньому справді є: виберіть там `:graph` чи `:search`, і панель
відкриє цей вигляд точно так, як вибір нотатки відкриває нотатку. Які сторінки
існують — зчитується з Obsidian, а не записано тут — кожен вигляд, що існує не
для показу файлу, тож плагін, який реєструє свій (домашня вкладка, календар),
з'являється без того, щоб цей плагін узагалі щось про нього знав. Вигляди, яким
потрібен файл — Markdown, PDF, зображення, канви, бази — не пропонуються: їм
просто нема чого показати.

Двокрапка — це і є суть: жоден файл чи теку не можна назвати `:graph`, тож
рядок не можна сплутати зі шляхом, який можна було б відкрити. Підпис береться
з типу вигляду, а не з власних формулювань Obsidian, тож він читається однаково
незалежно від мови інтерфейсу, а кінцеве `-view` відкидається: плагін домашньої
вкладки реєструє свій вигляд як `home-launcher-view`, і рядок каже
`:home-launcher`.

Клік по порожньому місцю або по самому підпису **відкриває поле в корені
сховища**: наберіть шлях, і <kbd>Enter</kbd> відкриє його в цій самій панелі, з
тим самим автодоповненням, тим самим списком і тим самим червоним полем, що
пропонує створити те, чого ще немає. Порожня вкладка — гарне місце, щоб набрати,
куди ви хочете піти, для цього вона й існує.

Підпис — це лише підпис і нічого більше: жодного списку, перетягування чи
перейменування. Панелі в бічних панелях лишаються повністю недоторканими —
панель зворотних посилань зберігає назву, яку дає їй Obsidian.

Канви, PDF, зображення та бази не потребують нічого з цього. Це файли, тож
вони отримують звичайний рядок шляху.

## Клік по сегменту: замініть його на сусідній

Клік по назві теки виділяє **назву цієї теки** в текстовому полі й відкриває список теки **на рівень вище** — її батьківської. Введення або вибір запису змінює цю теку на сусідню й лишає недоторканим усе, що нижче, тож `Проєкти/2026/Старт.md` → клік по `2026` → вибрати `2025` дає `Проєкти/2025/Старт.md`.

Клік по **назві нотатки** працює так само щодо її власної теки й виділяє назву **без розширення** — перейменування є звичайною правкою, а набір поверх виділення, що включало `.md`, раніше випадково змінював тип файлу. Розширення лишається видимим за одне натискання: <kbd>→</kbd> дістає до нього, а подвійний клік, що розширює на весь рядок, бере все.

Клік по теці вже виділив один сегмент, тож **ще один клік** розширює виділення на весь рядок — цю теку *і* все, що нижче, — і те, що ви наберете, замінить тоді решту шляху за раз. Працює однаково в навігації та в режимі перейменування/переміщення.

Це діє лише як продовження кліку, що відкрив поле. Щойно ви попрацювали з полем, воно поводиться як будь-яке інше текстове поле: клік ставить курсор, подвійний бере слово, потрійний бере рядок.

У будь-якому разі решта шляху лишається видимою навколо поля — фішками перед ним і невиділеним текстом після нього, тож повний шлях ніколи не зникає з шапки. Наберіть, щоб замінити виділення, або натисніть <kbd>→</kbd>, щоб лишити його й редагувати далі. Список показує всю теку незалежно від того, що вже вписано наперед; фільтрувати він починає, лише коли ви справді почнете набирати.

## Спуск роздільником

Клік по роздільнику (при вимкненому **Назва теки відкриває список**) спускає в теку перед ним: список показує вміст *тієї* теки, а решта шляху відкривається виділеною в полі. Вибір теки додає її до ланцюжка шляху й одразу відкриває наступний список, тож можна спускатися деревом кліками, не полишаючи рядка шапки.

## Список відкривається там, де ви є

Список відкривається на записі, у якому ви стоїте — на нотатці, якій належить
цей рядок, або, коли клік по теці показав її батьківську, на цій теці — а не
на першому рядку. У теці з двомастами нотатками перший рядок був би зовсім не
поруч із вами.

**Прокрутка коліщатком над назвою відкриває її список і проходить по ньому.**
Перший поворот відкриває той самий список, що й натискання на назву, а кожен
наступний поворот пересуває підсвітку на рядок, ставлячи те, на що ви
вказуєте, у поле точно так, як це робить стрілка — тож сусідню теку можна
знайти й вибрати без клавіатури. Прокрутка за будь-який край повертає вам ваш
текст. Рядок, у якого шляху більше, ніж уміщує панель, відповідає на
коліщатко натомість бічною прокруткою, і цей варіант читання перемагає, поки
він застосовний.

Список **завввишки настільки, наскільки дозволяє вікно**. Obsidian обмежує
свої списки підказок 300 пікселями, хай там що нижче; цей же тягнеться до
низу вікна, зупиняючись за кілька пікселів до краю, і прокручується лише
тоді, коли в теці більше записів, ніж влазить. Він **не ширший за рядок
шляху**: назва, що не влазить, скорочується так само, як скорочує її рядок, і
показується повністю, коли ви на неї вказуєте.

Рух списком **ставить те, на що ви вказуєте, у поле** — стрілкою чи наведенням
— замість сегмента, який ви редагували, лишаючи решту шляху незмінною — тож
рядок, на якому ви стоїте, і є той шлях, який ви отримаєте.

Решта шляху показується **лише настільки, наскільки вона існує під тим, на що
ви вказуєте**. Стоячи в одній теці з `2026/note.md` за сегментом, який ви
редагуєте, наведення на теку, у якій є `2026` із `note.md` всередині, показує
все; та, у якій є `2026` без нотатки, показує `2026`; та, у якій немає ні
того, ні того, не показує нічого після назви взагалі, як і файл, бо під ним
нічого не живе. **Те, що набрали ви самі**, зберігає свій повний шлях, поки ви
його набираєте, хоч би скільки там уже було — напівнабрана назва ще не є
рішенням. Вписати назву — це рішення, і те, до чого від неї не дістатися,
відрізається саме в цій точці; теки, які ви створюєте, — це ті, що ви набираєте
*після* неї, і саме там <kbd>Enter</kbd> їх створює.
Набраний вами текст зберігається: вихід **за будь-який край списку** — вгору
за перший запис або вниз за останній — відпускає його й повертає ваш текст,
без жодної підсвітки. Поле — це така сама зупинка на колі, як і будь-який
запис, тож коло проходить крізь нього, а не стрибає з останнього рядка на
перший, і натискання далі звідти переносить на інший край.

Забирання **курсора зі списку** теж повертає ваш текст — і віддає підсвітку
тому, у кого вона була до появи миші: запису, до якого ви дійшли стрілками,
знову показаному в полі, або тому, на якому список відкрився, бо саме там ви
стоїте. Наведення — це спосіб дивитися, а не обирати, тож проведення курсором
по списку нічого вам не коштує.

Сам список не змінюється, поки ви ним рухаєтеся — він і далі фільтрує за тим,
що ви набрали, а не за тим, що попередньо показано в полі — тож запис під вами
ніколи не зсувається перед наступним натисканням. Набір тексту замінює
попередній перегляд і фільтрує, як зазвичай.

**Фільтрує він за сегментом, який ви редагуєте**, а не за всім полем. Клік по
теці лишає решту шляху в полі позаду назви, яку ви змінюєте, тож фільтрація за
всім полем шукала б дочірній елемент під назвою `2026/Старт.md` і не знайшла б
нічого — список закрився б на першому ж натисканні, хай би що ви набрали.
**Розширення теж не враховується**, доки курсор перед крапкою: клік по назві
нотатки виділяє основу й лишає `.md` позаду, тож набір однієї літери робить
поле `a.md`, а це не те, що ви шукаєте. Поставте курсор за крапку — і
розширення рахується, як і все інше. Назва, що справді не збігається ні з
чим, усе одно закриває список, бо порожній список — чесна відповідь.

Попередній перегляд **замінює лише цей один сегмент і лишає решту шляху без
змін**: наведення на теку запитує «що, якби цим кроком була вона», а не
викидає шлях геть. Вихід зі списку відновлює і текст, і виділення, які були в
вас, тож наступне натискання замінить те саме, що замінило б до того, як ви
почали дивитися.

## Записи списку — справжні рядки файлового менеджера

Кожен файл і тека в списку поводяться як свій рядок у Файловому менеджері:

- **Клік правою кнопкою** відкриває те саме контекстне меню, що й Файловий менеджер, пункт у пункт — включно з тими, що додають інші плагіни. Тека пропонує *Нова нотатка*, *Нова тека*, *Нова канва*, *Нова база*, *Зробити копію*, *Перемістити теку до…*, *Пошук у теці*, *Копіювати шлях*, *Показати в системному провіднику*, *Перейменувати…* та *Видалити*; файл пропонує свій відповідник, включно з *Відкрити в застосунку за замовчуванням*.
- **Перетягніть** запис куди завгодно, куди Obsidian приймає файл: у редактор, щоб вставити посилання, на теку у Файловому менеджері, щоб перемістити його, на смугу вкладок, щоб його відкрити.

Текст меню береться з власних перекладів Obsidian, тож він збігається з рештою застосунку будь-якою мовою.

## Введення шляху

- Клік по **порожньому простору** до або після рядка шляху відкриває текстове поле для всього шляху *й показує нотатку у файловому менеджері*, тож дерево слідує за панеллю без другого жесту. Поле **рахує ваші натискання**: одне виділяє шлях без розширення, два — з ним, три — виділяють шлях, який знає машина. Клік по **назві файлу** рахується так само, але починається на одну сходинку нижче, з самої назви: одне натискання виділяє її без розширення, два — з ним, а три розширюють виділення до всього шляху *від папки вашого сховища* — форма, якої потребує посилання чи пошук, а не машина. Четверте натискання досягає саме цього.
- **Рахунок належить сесії, що відкрила поле.** Щойно вона минула — ви зробили паузу, ввели текст або клікнули один раз десь у тексті, — поле стає звичайним текстовим полем, і подвійний клік у ньому виділяє слово під курсором, як і будь-де ще. Друкуйте поверх виділеного або редагуйте на місці. (Клік по самій назві файлу виділяє лише назву файлу; див. вище.) Клік правою кнопкою по тому самому простору **копіює** ті самі три варіанти при двох, трьох і чотирьох натисканнях — одна кнопка їх показує, інша забирає. **Одне** натискання правою відкриває шлях із повністю виділеним текстом і пропонує те, що з ним можна зробити: вирізати, копіювати, вставити, виділити все — власними словами Obsidian.
- **Клік середньою кнопкою по порожньому простору**, щоб вставити поверх шляху: поле відкривається з усім шляхом *від кореня сховища*, тож буфер обміну замінює його повністю, а те, що потрапляє в поле, виділяється. <kbd>Enter</kbd> тоді переходить туди.
- **<kbd>Ctrl</kbd>+клік по порожньому простору**, щоб відкрити цю нотатку знову в окремій вкладці, підсвіченій у файловому менеджері, щоб другу вкладку не сплутати з першою. На **назві сховища** <kbd>Ctrl</kbd>+клік або клік середньою кнопкою відкриває порожню вкладку, що стоїть у корені сховища зі списком, який уже показано, — місце, звідки можна ввести шлях із нуля.
- Введення тексту, поки показано рядок шляху, перетворює кінцевий сегмент на маленьке поле з живим автодоповненням, обмеженим поточною папкою.
- **Можна ввести шлях від кореня файлової системи.** `/` перед порожнім полем відкриває його замість завершення сходинки, кожна коса риска після неї належить їй, а `~` — це ваша домашня папка. Поки поле містить такий шлях, список показує машину, а не сховище, а початковий сегмент рядка відступає — те, що в полі, починається з кореня і про це свідчить. При вимкненому *Доступ до зовнішніх файлів* список натомість стоїть порожнім, бо <kbd>Enter</kbd> все одно відмовиться прийняти такий шлях.
- **Сторінку можна ввести, а не лише обрати.** `:graph`, `:search` або що завгодно, що реєструють ваші плагіни — назви, які пропонує [список кореня сховища](#панель-без-файлу). Введення двокрапки будь-де викликає їх, бо жодна назва не може її містити, і <kbd>Enter</kbd> відкриває цей вигляд у поточній панелі. `:graph`, введене **всередині папки**, відкриває граф цієї папки — граф, відфільтрований за `path:"that/folder"` у власному полі пошуку, ніби введеним там; у корені сховища це весь граф. <kbd>Tab</kbd> завершує назву так само, як завершує назву папки, — і забирає з собою все інше, що містило поле, бо сторінка не в жодній папці і нічого не живе під нею. Клік по назві на такій панелі відкриває поле, що вже її містить.
- **Те, що написав би <kbd>Tab</kbd>, пропонується під час набору.** Там, де кожен нащадок, що починається з уже введеного, ще якийсь час погоджується, ця згода з'являється після курсора, виділена; там, де вони перестають погоджуватися, крок до першого з них з'являється так само — або до рядка, до якого ви перейшли стрілками, бо саме до нього прямував би <kbd>Tab</kbd>. Введення поверх назви залишає її розширення на місці й пропонує варіант перед ним, а щойно відкрита папка пропонує свій перший крок, тож немає стану, в якому нічого не пропонується, а <kbd>Tab</kbd> все одно щось пише. Введіть ці літери, і вони поглинаються по одній; введіть щось інше, і пропозиція зникає. <kbd>Tab</kbd> або <kbd>End</kbd> забирає її цілком, <kbd>→</kbd> забирає одну її літеру, <kbd>Backspace</kbd> повертає її назад, не торкаючись літери, яку ви ввели, і нічого не пропонується знову, доки ви не введете текст — тож завжди є вихід із назви, яка вам не потрібна. Після натискання <kbd>Tab</kbd> наступний крок пропонується одразу, як і після введеної літери. Те, що показує список, фільтрується тим, що ввели **ви**, а не тим, що було запропоновано.
- **Пропозиції ігнорують регістр.** `sch` пропонує `Schemes`, написане так, як і сама назва; скасування пропозиції повертає ваші літери такими, як ви їх ввели. Там, де існують і `Test`, і `test`, пропонується той варіант, що написаний так, як ви ввели.
- У полі запропонована частина просто **виділена**. Список — те місце, де вона розписана: кожен рядок показує ту свою частину, що **збіглася з уведеним вами, жирним шрифтом**, де б у назві не сталося збігу — `kick` знаходить `Weekly kickoff` і показує це. **Назви, що починаються з уведеного вами, йдуть першими**, попереду тих, що лише містять його, і позначені лінією вздовж краю: **синьою**, де вони мають спільного більше, ніж ви ввели, тож <kbd>Tab</kbd> є що додати для всіх них, і **зеленою** на тій гілці, куди пропозиція веде там, де вони розходяться — `te` з `test1`, `test2`, `text1` і `text2` пропонує `te`+`st`, тож два рядки `test` зелені, а два рядки `text` зберігають просту лінію. Кожен із них **підкреслює крок, який <kbd>Tab</kbd> зробив би до нього**, а не лише той, що запропоновано, і підкреслення слідує за пропозицією, коли та змінюється.
- **Введення тексту відпускає підсвічений рядок.** Список відкривається на елементі, на якому ви стоїте, але щойно ви починаєте вводити текст, мова йде вже про щось інше, і підсвічування, яке ніхто туди не ставив, читається як уже зроблений вибір.
- Пропозиція — завжди лише текст перед вами: літери, які ви ввели, залишаються написаними так, як ви їх ввели, поки ви друкуєте, а прийняття пропозиції переписує назву так, як її пише папка, бо шлях має відповідати диску. `sk` + <kbd>Tab</kbd> веде до `Skyline`, а не до `skyline`.
- **Поле набуває кольору того, що воно називає**, того самого кольору, що й відповідний рядок у списку: фіолетовий для нотатки, включно з власною нотаткою папки, помаранчевий для всього, що не є нотаткою, синій для нотатки, на якій ви перебуваєте. Рядок, з якого поле бере колір, — той, що названий точно так, як ви ввели, або, за відсутності такого, підсвічений, або, за відсутності й такого, перший, до якого ще веде ваше введення.
- **Поле стає червоним, щойно нічого не відповідає тому, що в ньому написано** — немає ні файлу, ні папки, і жоден рядок списку до цього більше не веде. Звідти <kbd>Enter</kbd> створює те, що написано в полі, замість того, щоб відкрити це, і червоний колір повідомляє про це ще до підтвердження. Він ніколи не з'являється для веб-адреси, яка не є місцем на цій машині, де варто щось шукати. Забарвлюється **все** поле, а не лише та частина, якої бракує: текстове поле не може забарвити половину власного вмісту. У режимі переміщення/перейменування поле зберігає власний червоний колір для назви, яка є недопустимою — там саме те, що ніщо не відповідає назві, і є суттю. Те, що назва вже **зайнята**, розглядається під час підтвердження, з діалоговим вікном, що запитує, що робити з файлом на шляху — див. [Назва, яка вже зайнята](#назва-яка-вже-зайнята): кожна назва, введена в напрямку `Notes.md`, проходить через назви, які можуть бути окремими файлами, тож позначання цього по літері попереджало б про назву, про яку ще ніхто не питав.
- `/` підтверджує сегмент, який ви вводите, і спускається в нього, зберігаючи все, що було до нього, — те саме, що робить <kbd>Tab</kbd>, коли заходить усередину.
- <kbd>Backspace</kbd> у порожньому полі повертає на крок назад, до батьківської папки, знову відкриваючи її назву з курсором у кінці. Те саме робить <kbd>Backspace</kbd> перед розширенням, що лишилося саме по собі — поле, що містить лише `.md`, не називає нічого, — і самотнє розширення йде разом із поверненням.
- **Клік по папці, поки поле відкрите, розширює його до всього шляху після цієї папки**, з виділеною власною назвою папки — те саме, що зробив би клік по ній у рядку, і все, що поле містило, зберігається. Те, що в полі, є хвостом рядка, поки він відкритий, тож папка, по якій клікнули вище, повертає шлях, яким пройшла сесія, а не той, з якого нотатка починалася.
- **Перехід стрілкою за початок поля вводить у нього папку перед ним**, ніби весь шлях був одним рядком тексту. З курсором у самому початку <kbd>←</kbd> вводить цю папку в поле й опиняється в кінці її назви, <kbd>Ctrl</kbd>+<kbd>←</kbd> опиняється на її початку, а <kbd>Home</kbd> вводить одразу кожну папку аж до кореня сховища — або до місця, яке ви обрали, поза сховищем. Утримуйте <kbd>Shift</kbd>, і виділення розтягується на те, що ввійшло. У macOS перехід словами — це <kbd>Option</kbd>+<kbd>←</kbd>, а <kbd>Cmd</kbd>+<kbd>←</kbd> діє як <kbd>Home</kbd>. Будь-де, крім початку, це звичайні клавіші тексту. **Поки список показано, <kbd>Home</kbd>, <kbd>End</kbd>, <kbd>PgUp</kbd> і <kbd>PgDn</kbd> належать йому** — перший рядок, останній рядок, сторінка вгору, сторінка вниз, де сторінка — це те, що показує список, а підсвічений рядок зберігає своє місце на екрані, — і сягають тексту лише після того, як список закрито; <kbd>Shift</kbd>+<kbd>Home</kbd> вводить кожну папку так само, поки список відкритий.
- **Список слідує за курсором.** Оберіть іншу частину шляху — перетягніть виділення над нею, клацніть у ній або перейдіть стрілками — і список покаже нащадків *тієї* папки, а не тієї, на якій поле було відкрито. Папка обчислюється з міток плюс того, що в полі стоїть перед курсором, тож клік у `Notes.md` в полі, що містить `2026/Notes.md`, покаже вміст `2026`. Наведення на рядок записує його в той сегмент, де стоїть курсор, а забирання вказівника зі списку повертає ваш текст і ваше виділення такими, якими вони й були.
- **Витягування виділення за межі поля** й відпускання десь-інде не закриває його. Натискання, що почалося в полі, належить редагуванню незалежно від того, як далеко воно зайшло; лише натискання, що *почалося* зовні, є кліком убік.
- <kbd>Enter</kbd> підтверджує — а коли поле не називає взагалі нічого, як у порожній папці, де завершувати було нічого, воно каже *Файл не вибрано* і залишається відкритим, а не закривається, ніби щось було обрано. <kbd>Esc</kbd> або клік деінде скасовує повернення до справжнього шляху файлу. Одного натискання <kbd>Esc</kbd> достатньо: воно закриває список, залишає поле й повертає фокус нотатці, а не забирає по натисканню на кожен шар.

Поле не має обрамлення — ані рамки, ані межі, — тож читається як сам текст шляху й саме росте в міру набору.

## Кожна частина рядка, кнопка за кнопкою

Весь рядок одним поглядом. Стовпчик правого кліка показує, що дає **одне**
натискання; та сама кнопка ще й рахує натискання, і [її власна
таблиця](#правий-клік-одне-натискання-два-три) нижче містить друге, третє й
четверте. Ця таблиця припускає, що **Назва теки відкриває список** увімкнено —
це типове налаштування; якщо його вимкнено, назва теки й роздільник міняються
місцями в першому стовпчику, як сказано в [таблиці на початку](#рядок-шляху).

| Де натискаєте | Клік | Подвійний клік | <kbd>Ctrl</kbd>+клік або клік середньою кнопкою | Правий клік | Перетягнути щось на це |
| --- | --- | --- | --- | --- | --- |
| **Назва сховища** | Відкриває список місць — інші сховища, домівка, корінь файлової системи, підключені диски. Типово вимкнено; якщо вимкнено, натомість показує сховище у File Explorer | Позначає **весь абсолютний шлях**. Цей список відкривається з уже заповненим полем шляху, позначена лише частина самого сховища; друге натискання розширює позначення на решту. Якщо список вимкнено — розширювати нічого | Вкладка без нічого, розташована в корені сховища, зі списком, що вже показується — місце, звідки можна ввести шлях з нуля | Власне контекстне меню сховища: що можна зробити зі сховищем, яке іменує цей сегмент | **Файл** переміщується в корінь сховища. **Текст** відкриває поле в корені, щоб назвати нотатку, якою він має стати |
| **Назва теки** | Обирає цю теку для редагування, вміст її батьківської теки показується нижче | Перевводить цю теку і все, що під нею | Відкриває цю теку в новій вкладці | Контекстне меню цієї теки — те саме, що й у File Explorer | **Файл** переміщується в цю теку. **Текст** відкриває там поле, щоб назвати нотатку, якою він має стати |
| **Роздільник** | Відкриває теку перед ним — її нотатку теки, якщо працює плагін нотаток тек і вона існує, інакше показує та розгортає її у File Explorer | **Створює нотатку цієї теки** і переходить до неї, якщо працює плагін нотаток тек, а тека ще не має жодної. Якщо вона вже має, це просто те саме одиничне натискання знову | Нотатка теки в новій вкладці, якщо вона є; інакше вкладка, розташована в цій теці, зі списком, що показується | Те саме контекстне меню теки, що дає назва — меню її нотатки теки, якщо вона є | На кінець нотатки цієї теки, якщо вона є, після підтвердження |
| **Назва нотатки** | Відкриває назву для редагування — теки лишаються поряд у вигляді чіпів — усе, крім розширення, позначено | Додає розширення до позначення | Відкриває нотатку в новій вкладці | Контекстне меню файлу — те саме, що й у рядку File Explorer | На кінець цієї нотатки, після підтвердження |
| **Порожнє місце** | Відкриває **весь шлях** для редагування, позначений аж до розширення. Теки потрапляють у поле разом з ним, що й робить цей жест призначеним для перевведення шляху, а не назви | Додає розширення до позначення | <kbd>Ctrl</kbd> знову відкриває цю нотатку в окремій вкладці, підсвіченій у File Explorer, щоб копію не сплутали з першою. Клік середньою кнопкою — це *не* той жест: він вставляє поверх шляху | Позначає весь шлях і пропонує, що можна зробити з позначеним текстом | |

**Друге натискання йде за першим.** Створення нотатки теки прив'язане до тієї
частини рядка, яка *відкриває* цю теку — це роздільник за замовчуванням і назва
теки, якщо заміну вимкнено — та сама ціль, яку позначає підкреслення, і та сама,
яку вже запитує одиничне натискання для нотатки теки. Це пропонується лише поки
працює плагін нотаток тек, оскільки нотатка теки — це домовленість, а не факт
файлової системи, і лише там, де тека ще не має жодної. Де вона лежить і як
називається — читається з власних налаштувань **Folder notes**, тож сховище,
яке тримає нотатки тек поряд із текою або називає їх `_index`, отримає саме
таку; сам файл завжди Markdown, оскільки саме це створює власна типова команда
створення того плагіна і саме це він знаходить, який би тип не був встановлений
для сховища. Режим переміщення/перейменування тут узагалі ні до чого — жодна
частина рядка не відкриває теку, поки переміщення очікує на підтвердження.

**Кліки на назві продовжуються.** Чотири щаблі — ті самі чотири, якими проходить
клавіша перейменування, у тому самому порядку: назва, назва з розширенням,
шлях від сховища, шлях від кореня системи. Тож третій клік досягає шляху
сховища, а четвертий — шляху машини — ті самі чотири речі, які дає
<kbd>Tab</kbd> за кінцем поля, і ті самі чотири, які права кнопка *копіює*
замість того, щоб позначати.

**Наведення** — це своя окрема відповідь, і воно ніколи нічого не змінює:
скорочена назва повертається повністю, поки ви на неї вказуєте, а значок на
початку рядка показує, де живе сховище.

## Правий клік: одне натискання, два, три

Кожна ціль у рядку відповідає на правий клік, і скільки разів ви натиснете —
вирішує, що ви отримаєте. Оскільки друге натискання ще може надійти, перше
чекає близько третини секунди, перш ніж діяти — така ціна розміщення трьох
жестів на одній кнопці.

| Де натискаєте | Один раз | Двічі | Тричі |
| --- | --- | --- | --- |
| **Назва сховища** | Контекстне меню сховища: що можна зробити зі сховищем, яке іменує цей сегмент — включно з *Open this vault*, якщо це сховище не те, в якому ви зараз | Копіює назву сховища | Копіює, де лежить сховище — а четверте натискання, де лежить відкритий файл |
| **Роздільник** | Меню цієї теки — її нотатки теки, якщо працює плагін нотаток тек і тека її має | | |
| **Назва теки** | Меню цієї теки | Копіює назву теки | Копіює її та все, що праворуч від неї |
| **Назва нотатки** | Меню файлу — те саме, що й у рядку File Explorer | Копіює назву | Копіює її з розширенням |
| **Порожнє місце** | | Копіює шлях від теки вашого сховища, без розширення | Те саме, але з ним |

Одне натискання на **назві сховища** відкриває, що можна зробити з тим, що
іменує цей сегмент. Для **сховища, в якому ви перебуваєте**: відкрити його в
новому вікні, керувати сховищами, скопіювати, де воно лежить, скопіювати його
ID, показати у вашому файловому менеджері. Для **іншого сховища**, до якого
дістались через список місць, — те саме, мінус нове вікно, яке відкрило б *це*
сховище, а не те, — плюс єдина річ, яку може запропонувати лише сховище, в
якому ви не перебуваєте: **Open this vault**. Воно назване для Obsidian за
своїм ID, а не за назвою теки, оскільки два сховища можуть мати однакову назву.
Для місця, яке взагалі не є сховищем — вашої домашньої теки, підключеного
диска — немає ID для копіювання і нічого відкривати, і меню про це говорить,
не пропонуючи ці пункти.

Це не власне триточкове меню Obsidian, яке належить стартовому вікну і не може
бути відкрите зсередини запущеного сховища — це ті самі пункти, відтворені
власними формулюваннями Obsidian, взяті з його команд, щоб вони приходили
вашою мовою. Три пункти того меню навмисно **відсутні** тут: *rename vault*,
*move vault* і *remove from list* усі діють на власну теку сховища або на
реєстр сховищ Obsidian, а робити це зі сховищем, у якому ви зараз стоїте — з
відкритими файлами й запущеними спостерігачами — це спосіб зламати сховище.
Відкрийте менеджер сховищ (*Open another vault*) і робіть це там, де сховище
закрите.

Дві копії на **порожньому місці** — це рядок таким, яким він записаний — те,
що потрібно посиланню чи пошуку — а ті, що на **назві сховища**, — це шляхи,
які знає файлова система, тобто те, що потрібно всьому поза Obsidian. Кожне
натискання там розширює, для чого годиться копія: два дають назву сховища,
три — де лежить сховище, чотири — де лежить відкритий файл. Obsidian проводить
те саме розрізнення у своїх двох командах, *from vault folder* та *from system
root*; тут ті, що звернені назовні, лежать на сегменті, який сам перебуває
поза шляхом.

Усе це працює й поза сховищем, на тих самих цілях.

Кожна копія повідомляє про це сповіщенням, оскільки копіювання не лишає нічого
на екрані, що показало б, що воно сталося, а неправильно пораховане натискання
не повинно виглядати як успішне.

## Модифікатори: відкрити деінде

Назва нотатки та сегменти тек поводяться так само, як їхні рядки у File Explorer.

| | На назві нотатки | На сегменті теки |
| --- | --- | --- |
| Звичайний клік | Редагувати назву | Переглянути цю теку |
| <kbd>Ctrl</kbd> / клік середньою кнопкою | Відкрити нотатку в новій вкладці | Надіслати теку в нову вкладку |
| <kbd>Ctrl</kbd>+<kbd>Alt</kbd> | Розділення | Розділення |
| Перетягування | Нотатка, будь-куди, куди Obsidian приймає файл | Тека, так само — включно з панеллю вкладок |

Тека — це не те, що Obsidian може відкрити, тож надсилання її у вкладку робить
одне з двох: відкриває її нотатку теки, якщо працює плагін нотаток тек і вона
є, або відкриває порожню вкладку, чий рядок шляху вже стоїть у цій теці —
лишаючи вам тільки ввести назву. Перетягування сегмента теки на **панель
вкладок** робить те саме, у новій вкладці там, де ви відпустите — власна
панель вкладок Obsidian сама по собі приймає лише файли, тож тека, витягнута
з File Explorer, там так само буде відхилена.

## Tab: спершу завершує ім'я, потім шлях, потім розширює вибір

<kbd>Tab</kbd> доповнює так само, як це робить оболонка: **натискання розширює введене настільки, наскільки збігаються імена в цій папці, і зупиняється там, де вони розходяться.** Введіть `Sk`, коли лише `Sketches` починається так, і слово завершене; введіть `Al`, коли з нього починаються і `Alpha-one`, і `Alpha-two`, і `Alpine`, і ви отримаєте `Alp`, бо наступний символ — це питання, на яке можете відповісти лише ви.

Натисніть ще раз, нічого не вводячи, і курсор рухається до одного імені — рядка, підсвіченого у списку, або першого — зупиняючись на наступній неоднозначності цього імені: `Alpha-`, потім `Alpha-one`. Список відкривається там, де ви вже перебуваєте, тож у власній папці перше натискання веде до відкритої нотатки, а не до того, що сортується першим.

**Натискання ніколи не вибирає між іменами за вас.** <kbd>Tab</kbd> заходить у папку, щойно введене залишає єдиного кандидата, або щойно ви ввели повну назву папки і жодна *інша папка* не продовжує її. Там, де продовжує — `Schemes` поряд із `Schemes2026` — <kbd>Tab</kbd> продовжує доповнювати до довшої назви; <kbd>Enter</kbd> і список — це жести, що означають *саме цю*.

**Файл** ніколи так не затримує папку. Папка поряд із нотаткою власної назви — це нотатка-папка, а не розгалуження шляху, і <kbd>Tab</kbd> обходить папки — тож у `Projects` із `Projects.md` поряд заходять, як і в будь-яку іншу.

Звідси випливають дві менші речі: те, що потрапляє в поле, пишеться так, як пише папка, тож `sk` стає `Sketches`; і замінюється лише те ім'я, що вводиться, тож шлях із чимось праворуч зберігає це.

Коли під час введення пропонується ім'я, <kbd>Tab</kbd> **пише саме пропозицію**: пропозиція завжди дорівнює тому, що напише натискання, а підкреслення та зелена лінія у списку кажуть те саме, тож те, що ви бачите після курсора, ви й отримаєте. Там, де імена перестають збігатися, це крок до першого з них — або до рядка, до якого ви перейшли стрілками, і саме його бере <kbd>Tab</kbd>, а не сусідній — тож перейдіть стрілками до потрібного, або допишіть повз розгалуження, перш ніж натискати. Лише там, де пропозиція залишає *одне* ім'я, те саме натискання заходить у нього.

Прибуття до імені файлу **і є** першим щаблем — жодне натискання не витрачається на те, щоб просто поставити курсор у кінець імені, яке ось-ось буде позначене. Звідти натискання перестають рухатись уздовж шляху й починають розширювати позначене:

1. ім'я
2. ім'я з розширенням
3. шлях від папки вашого сховища
4. шлях від кореня системи
5. назад до початку шляху **у його теперішньому вигляді** — там, де почалась подорож, з позначеним першим сегментом, готовим пройти знову

Четвертий клік досягає того самого четвертого щабля напряму.

Розширення завжди лише **розширює**. Ім'я, що вже цілком у полі — завершене тією ж клавішею або обране зі списку — позначається цілком, а не спершу звільняється від розширення: перший щабель — для імені, до якого подорож щойно *прибула*, де розширення ще не є темою.

Драбина — це те, куди подорож **прибуває**, а не звідки вона починається. Клацніть по папці посередині шляху, і поле відкриється на всьому, що нижче неї, з позначеною назвою цієї папки; кожен <kbd>Tab</kbd> тоді бере **одну** папку — позначаючи наступну, зберігаючи решту шляху позаду — і лише коли не залишиться нічого, крім імені файлу, розширення починається:

| натискання | чіпи | поле | позначено |
| --- | --- | --- | --- |
| клікнуто `a` | | `a/b/c/leaf.md` | `a` |
| <kbd>Tab</kbd> | `a` | `b/c/leaf.md` | `b` |
| <kbd>Tab</kbd> | `a › b` | `c/leaf.md` | `c` |
| <kbd>Tab</kbd> | `a › b › c` | `leaf.md` | `leaf` — перший щабель |
| <kbd>Tab</kbd> | `a › b › c` | `leaf.md` | `leaf.md` |

**Ім'я, що встановлене, — встановлене, хоч би як ви його встановили.** Завершення його клавішею
<kbd>Tab</kbd>, підтвердження знаком `/` і вибір його зі списку —
все це залишає рядок у тому самому місці з тим самим шляхом, тож натискання після
жесту означає те саме, яким би шляхом ви не прийшли. Вибір папки зі
списку раніше очищав поле натомість, відкидаючи шлях, який досягнення
тієї самої папки через <kbd>Tab</kbd> зберегло б.

**Шлях, який ви ще пишете, приходить цілим.** Крок у саму папку, на якій тримається решта шляху, — це не твердження, що решта існує — так шлях друкується наперед самого себе, і папки, названі в ньому, — це ті, які ось-ось створить <kbd>Enter</kbd>. Тож спуск шляхом `Dokumente/plans/untitled.md` у `Dokumente` зберігає `plans/untitled.md` перед вами, незалежно від того, чи існує вже `plans`. Те саме стосується шляху, введеного з нуля: жодна його частина не була успадкована звідкись, тож жодна не забирається.

**Заміна одного кроку на інший — інша історія, і тоді шлях приходить лише настільки, наскільки він справді існує.** Заміните папку посередині шляху на сусідню — клацніть `a`, введіть іншу назву, натисніть <kbd>Tab</kbd> — і все, що нижче неї, піде з вами, бо шлях, на якому ви були, зазвичай складає більшу частину бажаного шляху. Проте вцілі лише те, що справді існує там, тож поле й список поряд з ним ніколи не розходяться: те, що залишається перед вами, — це шлях, яким справді можна пройти. Починаючи з `a/b/c/leaf.md`, з клікнутим `a` і позначеною його назвою:

| що ви встановили | чіпи | поле | позначено |
| --- | --- | --- | --- |
| `x`, у якому взагалі немає `b` | `x` | | нічого не прийшло з ним |
| `y`, у якому є `b`, але немає `c` в ньому | `y` | `b` | `b` |
| `z`, двійник `a` аж до самого низу | `z` | `b/c/leaf.md` | `b` |

Папка, що залишилась стояти сама так, — усе ще папка, в яку можна зайти: натискання після неї заходить у неї, а не починає розширювати вибір над її назвою.

На ім'я, якому **ніщо** в папці не відповідає, реагують інакше, бо ним нічого не встановлено: натискання позначає введене вами, готове до перезапису, а не відповідає чимось іншим.

Уся ця конструкція — **петля, і пройти нею коло нічого не коштує**: натискання після останнього щабля повертає рядок до початку шляху, з усіма папками, готовий пройти коло знову. Єдине, що коли-небудь залишає рядок, — це абсолютний префікс, на натисканні, що перестає його показувати.

Те, що повертається, — це **шлях, який ви побудували**, а не той, з якого ви вирушили. Розгалузьте подорож на півшляху — оберіть іншого сусіда зі списку, доповніть до іншої назви — і коло замикається там, де ви справді перебуваєте; чотири щаблі перед цим описують той самий шлях, а цей раніше був зайвим щаблем, що описував минуле.

<kbd>Shift</kbd>+<kbd>Tab</kbd> замикає те саме кільце в інший бік: на початку шляху, коли нічого більше не можна повернути й нікуди далі вгору, наступне натискання переходить до **дальнього** щабля — шляху від кореня системи — і продовжує звужувати звідти. Жоден напрямок не веде в глухий кут.

Воно так само не витрачає натискання на щабель, який уже показувало. Нижче останнього щабля — імені без розширення — драбина закінчується, і *те саме натискання* виходить із папки: шлях від кореня системи, шлях від вашого сховища, ім'я, ім'я без розширення, потім папка — по одному кроку.

Так само жодне натискання не витрачається на щабель, що нічого не змінює: клік по назві нотатки вже показує її без розширення, що й показує перший щабель, тож звідти <kbd>Tab</kbd> починає з другого.

Кожен щабель змінює те, що *в* полі, а не лише те, що підсвічене — вибір має бути над текстом, який він називає, інакше <kbd>Enter</kbd> підтвердив би щось інше, ніж те, що видно вибраним. Драбина належить одному сеансу редагування: клацніть кудись убік, або введіть будь-що, і наступний <kbd>Tab</kbd> знову завершує ім'я.

### <kbd>Shift</kbd>+<kbd>Tab</kbd>: той самий шлях назад

<kbd>Shift</kbd>+<kbd>Tab</kbd> забирає назад по одному кроку за натискання, у тому порядку, в якому натискання були зроблені: вибір звужується по щаблю за раз, кожне завершення повертається, і з кожної папки виходять — її назва повертається в поле, щоб ви могли її редагувати, а не вводити наново.

**Нічого не видаляється на зворотному шляху.** Завершення повертається *позначенням* символів, які воно додало, точно як рух уперед позначає те, над чим він розширився — назва залишається перед вами, і кожне наступне натискання позначає ще один крок цього.

| | поле | позначено |
| --- | --- | --- |
| прийшли сюди | `Alpha-one` | |
| <kbd>Shift</kbd>+<kbd>Tab</kbd> | `Alpha-one` | `one` |
| <kbd>Shift</kbd>+<kbd>Tab</kbd> | `Alpha-one` | `ha-one` |
| <kbd>Shift</kbd>+<kbd>Tab</kbd> | `Alpha-one` | `Alpha-one` |

Введення замінює позначену частину, як і будь-де ще. <kbd>Tab</kbd> повертає точно те, що віддала позначка, тож два кроки назовні й два кроки назад повертають вас туди, де ви були.

Щойно позначене все ім'я, не лишається нічого, що поклало туди натискання, і наступне натискання йде *вгору шляхом*: воно виходить із папки, в якій ви стоїте, точно як <kbd>Backspace</kbd> у порожньому полі. Це теж нічого не коштує — назва папки повертається в поле **перед** усім, що в ньому було, позначена, що є тим самим текстом, який дав би клік по цій папці. Назад — це напрям, а не історія скасувань — але позначення назви спершу означає, що жодне натискання ніколи одночасно не забирає написане вами і не виводить вас із папки, в якій ви це написали.

Текст, що відкривається **вже вибраним** — те, що залишає по собі клік по папці — це ім'я, з яким <kbd>Tab</kbd> працює далі: воно завершується й у нього заходять, як і в будь-що інше, а введення замінює його. Лише команда фокусу відкривається на щаблі самої драбини, бо вона показує вам увесь шлях, а не папку для входу.

## Введення чогось, що не є шляхом

| Що ви вводите | Що відбувається |
| --- | --- |
| `https://…` | Відкривається в новій вкладці в **переглядачі вебу** Obsidian, якщо у вас увімкнено цей вбудований плагін; інакше — у вашому браузері на комп'ютері |
| `obsidian://…` | Передається власному обробнику URI в Obsidian |
| `file:///…` | Розшифровується й відкривається: як справжня нотатка, якщо вона всередині вашого сховища, у переглядачі — якщо ні |
| `/home/you/a%20b.md` | Те саме, для шляху, вставленого з браузера чи файлового менеджера |

Рахуються лише явні схеми — нотатка з назвою `100%20` усе ще нотатка. `/`, що належить схемі, лишається буквальним, а не спускається в папку, тож URL можна ввести вручну, а не лише вставити.

## Команда для клавіатури

**Фокус на рядку шляху** відкриває поле на назві нотатки й обходить його так само, як це робить <kbd>F2</kbd> — ім'я, ім'я з розширенням, шлях від вашого сховища, шлях від кореня системи — і натискання після цього закриває поле й повертає курсор у нотатку. Це не перейменування: Enter переходить, як і в будь-якому іншому полі. Спочатку вона не має власної клавіші, бо настанови Obsidian не рекомендують плагінам займати клавіші самостійно; рядок **«Гарячі клавіші»** наприкінці налаштувань цього плагіна відкриває *Налаштування → Гарячі клавіші*, показуючи лише його команди, тож ви можете прив'язати клавішу там.

## Навігація ніколи не чіпає відкритий файл

У типовому режимі (навігації) відкрита нотатка **ніколи** не перейменовується й не переміщується.

- Шлях, що вказує на наявний файл, відкриває його.
- Шлях, якого ще не існує, просто створюється, разом із будь-якими відсутніми батьківськими папками, і відкривається. Кожен файл і папка, створені так, повідомляють про це у сповіщенні — інакше нова папка невидима, доки ви її не шукатимете спеціально — а власне смітник Obsidian робить скасування небажаної справою одного натискання.
- **Поза сховищем це все одно спершу запитує.** Там та сама одруківка записує у системну папку, де ні сповіщення, ні смітник Obsidian не дуже допоможуть.

## <kbd>Ctrl</kbd> — нова вкладка й копіювання замість переміщення

Нотатка, **створена, переміщена чи скопійована всередині сховища, показується там, де вона опинилась**, у Файловому менеджері, на мить позначена акцентним кольором Obsidian — саме в дереві ви шукатимете її потім, тож вона показується вам, а не залишається в папці, яка, можливо, навіть не відкрита. Дублювання так само повідомляє про себе: копія залишає оригінал на місці й відкриває копію в окремій панелі, бо без жодного слова це легко сприйняти так, ніби нічого не сталося.

Утримання <kbd>Ctrl</kbd> (<kbd>Cmd</kbd> у macOS) під час вибору файлу зі списку або натискання <kbd>Enter</kbd> на шляху надсилає результат у **нову вкладку**, а не в цю:

| | Просто | З <kbd>Ctrl</kbd> |
| --- | --- | --- |
| Вибрати або ввести наявний файл | Відкривається тут | Відкривається в новій вкладці |
| Ввести неіснуючий шлях | Запитує, потім відкриває тут | Запитує, потім відкриває в новій вкладці |
| Підтвердити шлях у режимі перейменування/переміщення | **Переміщує** нотатку туди | **Копіює** її туди й відкриває копію в новій вкладці |

Модифікатор зчитується за правилом самого Obsidian, тож поводиться точно як на посиланні чи на рядку Файлового менеджера — середній клік теж означає «нова вкладка», <kbd>Ctrl</kbd>+<kbd>Alt</kbd> означає поділ, а <kbd>Ctrl</kbd>+<kbd>Alt</kbd>+<kbd>Shift</kbd> — нове вікно.

Копіювання відмовляється перезаписувати, точно як і переміщення — включно з власним шляхом нотатки, куди немає сенсу копіювати. Поза сховищем ця відмова також озвучується.

Усе це працює **як зі відкритим списком**, так і без нього: на підсвіченому рядку модифікатор застосовується до цього рядка, а якщо нічого не вибрано — до введеного вами.

## Перегляд поза сховищем

**Типово це вимкнено.** Спершу увімкніть **Доступ до зовнішніх файлів** у налаштуваннях — читання й запис поза сховищем єдине, що робить цей плагін і чого сам Obsidian не зробить, тож у це заходять навмисно, а не виходять. При вимкненому налаштуванні назва сховища просто показує ваше сховище у Файловому менеджері, і ніщо тут ніколи не зазирає далі.

Клік по **назві сховища** (або значку 🏠, коли **Показувати назву сховища** вимкнено) відкриває список місць, а не вмісту. Поле, яке при цьому відкривається, тримає **весь шлях, на якому ви були, записаний повністю**, з виділеним місцем, звідки він починається — тож вибір іншого місця або введення поверх виділеного змінює лише цю провідну частину, лишаючи решту шляху перед вами. **Натисніть на назву вдруге** — подвійний клік — і виділення розширюється на всю неї цілком: так абсолютний шлях береться одним жестом, а не виділяється вручну. Передумали — <kbd>Esc</kbd> повертає рядок таким, яким він був.

Введення тут пропонує решту назви місця, як і всюди, а <kbd>Tab</kbd> **закладає це місце** — те, на яке ви вказуєте, або те, яким назва може бути лише. Там, де кілька місць досі поділяють введене, натискання зупиняється на розгалуженні, як і всюди. Наведення на місце показує **власний шлях цього місця**, весь виділений, а за ним — шлях вашої нотатки, але лише настільки, наскільки він справді існує там — саме те, на що вивів би вибір цього місця. Місце — це не крок усередині шляху на екрані, а точка, звідки рахується весь шлях, тож ніщо з того, де ви були, перед ним не лишається.

Пропоновані місця:

- **Ваші інші сховища**, прочитані з власного реєстру Obsidian, спершу відкрите останнім, кожне під власним значком сховища Obsidian — тим самим, який застосунок використовує для команд, пов'язаних зі сховищами. У сховища, яке вже відкрите, натомість будиночок: це те, звідки рядок починається типово, а не місце, куди можна піти.
- **Домашня тека**, під іменем вашого облікового запису, позначена `~`. У Lucide немає тильди, тож цей значок малює сам плагін на тій самій сітці 24×24 Lucide і з тією ж товщиною штриха — значок, якого набору бракує, а не текстовий символ, що затесався серед значків.
- **Корінь файлової системи**, підписаний `root` — без перекладу, бо так він зветься в будь-якій системі, — а не `/`, який поруч із наступним роздільником читався б як порожній крок.
- **Підключені диски**, зі значком за типом там, де це дешево визначити: мережеві ресурси, оптичні диски, дискети та змінні носії отримують свій; усе інше отримує узагальнений диск. У Windows диски показуються як `C:` з узагальненим значком — назви томів і точні типи потребують WMI, який навмисно не використовується.

Вибір іншого сховища **не перемикає на нього Obsidian.** Усе, що у вас відкрито, лишається відкритим; рядок шляху просто починає перегляд там. У цьому весь сенс того, що воно на смузі шляху, а не віддане перемикачу сховищ у бічній панелі.

Він також приземляється **якнайближче до нотатки, на якій ви є, наскільки це місце туди сягає**.

- Якщо вибране вами місце *містить* нотатку — домашня тека або де б там не жили ваші сховища — ви отримуєте її шлях звідти: виберіть `~` при відкритому `takeaways.md`, і поле покаже `Vaults/your-vault/takeaways.md`.
- Якщо це місце поруч із поточним — інше сховище, інший диск — пробується той самий відносний шлях, настільки глибоко, наскільки він справді існує. Сховища часто майже копіюють одне одного, і причина переходу до іншого зазвичай та сама нотатка там.

У будь-якому разі рядок лишається на вибраному місці, і **перша тека цього шляху відкривається виділеною** — та сама форма, яку дає клік по теці: крок, який ви найімовірніше зміните, перестрибнувши кудись іще, найближчий до початку, а решта шляху лишається видимою, поки ви його змінюєте. Ніщо ніколи не заповнюється наперед, якщо цього насправді немає на диску.

### Поки ви ззовні

Шлях **починається з обраного вами місця**, а не з розкладки директорій машини — так само й поле, яке ви отримуєте, клікнувши по порожньому простору або натиснувши клавішу фокусу: воно тримає шлях від цього місця, а не абсолютний шлях машини, зі слідом, згорнутим до самого місця точно так, як він згортається до кореня сховища всередині — оберіть `Archive`, і рядок покаже `Archive / notes / …`, а не `/home/you/Vaults/Archive/notes/…`. Провідний сегмент несе значок того, чим він є (сховище, домашня тека, диск), і <kbd>Backspace</kbd> зупиняється саме там, а не йде далі в решту файлової системи. При вимкненому **Показувати назву сховища** цей сегмент — самий лише значок: налаштування стосується початкового сегмента рядка, яке б сховище він не називав, а не тільки вашого власного.

Рядок шляху лишається **в рамці кольору помилки** — тому самому кільці, яке малює режим перейменування, — увесь час, поки вказує поза ваше сховище. Він позначає тривкий стан, а не мить: доки він є, ніщо з власної обробки Obsidian не стосується того, що показує рядок, а запис заблоковано, доки ви не скажете інакше.

Решта перегляду працює як усередині: фішки, роздільники, введення, автодоповнення, <kbd>Backspace</kbd> для виходу. Діють і ті самі правила видимості, тож непідтримуваним розширенням і далі потрібне **Виявлення всіх розширень файлів** Obsidian, а прихованим файлам — налаштування цього плагіна.

**Клік правою кнопкою працює й там**, хоча меню інше: власні обробники Файлового менеджера потребують файлу, про який знає сховище, тож записи ззовні будуються натомість зі шляху. Вони пропонують відкриття (тут, праворуч, у новому вікні або в типовому застосунку вашої стільниці), *Скопіювати шлях*, *Показати в системному провіднику*, а після відкриття замка — *Нова нотатка*, *Нова тека*, *Зробити копію*, *Перейменувати…* і *Видалити*. **Перетягування** досі потребує файлу сховища й лишається недоступним.

Те саме меню є і на відкритому файлі в переглядачі — клавішею правою миші або з власних трьох крапок панелі, — і воно звертається до замка в шапці цього подання. Більше ні до чого воно не звертається: чи файл відрисовується, чи показується як вихідний текст — не впливає на те, чи можна його видалити, а зображення чи PDF — у яких взагалі немає подання джерела — так само видаленні, як і нотатка. *Видалити* означає кошик стільниці, тож звідти дію можна скасувати; система без кошика повідомляє про це замість того, щоб знищити файл.

Видалення поза сховищем переміщує файл у ваш **системний кошик** — Кошик у Windows, Смітник у macOS — ніколи не пряме видалення. Тут немає кошика Obsidian, з якого можна відновити, тож видалення, яке не можна скасувати, взагалі не пропонується: там, де платформа не має кошика, спроба повідомляє про невдачу замість того.

### Запис поза сховищем

Усе, що записує, **типово заблоковано**. Увесь час, поки рядок вказує поза ваше сховище, місце перемикача перейменування в шапці займає **червоний замок** — той самий колір, що й кільце навколо рядка, і з тієї самої причини: він позначає відмову. Ці два — один елемент керування в одному слоті, тож ніколи не виникає питання, котрий із них що обмежує.

Три натискання по колу:

| Натискання | Що отримуєте |
| --- | --- |
| Червоний замок | Запис тут дозволено. Замок заміняється перемикачем перейменування/переміщення |
| Перемикач | Режим перейменування/переміщення, точно як усередині сховища |
| Перемикач знову | Режим завершується, і замок знову зачиняється — дозвіл не переживає те, заради чого його відкрили |

**Клавіша перейменування також звертається до замка.** Поза вашим сховищем її натискання лише блимає замком — відкриває й одразу зачиняє, — а не відкриває режим, який кожен коміт однаково відхилив би: відмова приходить до роботи, а не після неї. Натисніть замок або натисніть клавішу перейменування ще раз протягом половини секунди — друге натискання надає рівно те, що надає кнопка, для цього місця, і разом з тим відкриває режим перейменування.

Усередині вашого сховища замка немає: розблоковувати нічого, і слот просто займає перемикач.

Дозвіл надається **місцю, а не миті**: він переживає все, що ви робили б, працюючи в одному місці — завершення переміщення, клік повз поле вводу, відкриття файлу, — і закінчується, коли ви обираєте інше сховище, диск чи корінь зі списку, коли рядок повертається до файлу сховища або на те третє натискання. Тож серія переміщень усередині однієї теки коштує одного натискання, а не по одному на файл.

З відкритим замком рядок шляху поводиться там так само, як усередині:

| Дія | Результат |
| --- | --- |
| Ввести неіснуючу назву, <kbd>Enter</kbd> | Те саме питання «створити?», що й усередині; відсутні теки теж створюються. Назва без розширення стає `.md`, точно як усередині |
| Режим перейменування/переміщення, ввести нову назву | Перейменовує файл, який показує рядок. Назва без розширення зберігає розширення файлу — тут зовні тека тримає файли будь-якого штибу, і перейменування не має мовчки перетворювати `.png` на `.md` |
| Режим перейменування/переміщення, перейти в інше місце, вибрати **лишити цю назву** | Переміщує туди під назвою, яку вже має |
| Утримати <kbd>Ctrl</kbd> на будь-якому з двох | Копіює замість переміщення й відкриває копію в новій вкладці |

Із закритим замком усе це замість дії повідомляє, що його блокує. У жодному зі станів нічого не перезаписується: наявна вже ціль відхиляється, і відмова походить від самої файлової системи (`COPYFILE_EXCL`, виняткове створення), а не від перевірки, яка могла б програти перегони. Переміщення між файловими системами — з флешки, з мережевого ресурсу — переходить на «скопіювати, потім видалити», і оригінал прибирається лише після того, як копія лягла на місце.

**Переміщення нотатки *за межі* вашого сховища спершу питає.** `fileManager` не може простежити файл через цю межу: кожне посилання, що вказує на нотатку, перестає розпізнаватися, ніщо їх не оновлює, і нотатка залишає індекс сховища. Тож переміщення пропонується як рішення, а не відхиляється чи виконується мовчки — діалог повідомляє, чого це коштуватиме і скільки нотаток посилаються на ту, яку ви переміщуєте. Підтвердьте — і воно справді переміщується: копіюється назовні, потім видаляється зі сховища через власне видалення Obsidian, тож його можна відновити точно як видалену нотатку, а невдача на будь-якому з кроків лишає нотатку там, де вона й була. Утримання <kbd>Ctrl</kbd> усе одно натомість копіює її назовні, у чому такої проблеми немає. Зворотний шлях — внесення зовнішнього файлу *в* сховище — поки що не налаштований.

### Відкриття зовнішнього файлу

Перегляд файлової системи може повернутися назад **у сховище, яке у вас відкрите** — з кореня, з домашньої теки, звідки б не жили ваші сховища. Файл, досягнутий так, — звичайна нотатка, тож він і відкривається як така: справжній редактор, посилання й зворотні посилання, а рядок повертається до рядка шляху, закоріненого в сховище. Лише файли, для яких в Obsidian немає подання, лишаються в перегляді, бо там перегляд — кращий варіант. Там, де перегляд усе одно показує таку нотатку — скажімо, заново відкритий робочий простір, — верхній рядок пропонує **Відкрити в *(сховище)***, ту саму пропозицію, яку дає ручний вибір.

Редактор Obsidian працює лише з файлами всередині сховища, тож зовнішній файл **не можна** відкрити як справжню нотатку з посиланнями, зворотними посиланнями й усім іншим — це обмеження застосунку, а не плагіна. Вибір такого файлу відкриває натомість **перегляд**, лише для читання, доки ви не скажете інакше:

| Тип | Показується як |
| --- | --- |
| `.md`, `.markdown` | Відрисований Markdown |
| `.html`, `.htm`, `.xhtml` | Відрисована сторінка |
| Зображення, аудіо, відео, PDF | Рідний програвач/переглядач |
| Будь-який інший **текстовий** файл (`.json`, `.css`, `.log`, `.txt`, …) | Дослівний простий текст |
| Двійкові формати без переглядача (`.zip`, `.exe`, …) | Передається у *Відкрити в типовому застосунку* |

У переглядача два прочитання файлу, і, оскільки вони виключають одне одного, показується лише те, **на яке** ви б перемкнулися:

| | Що робить | Типово для |
| --- | --- | --- |
| **Показати як Markdown** | Відрисовує файл як нотатку, лише для читання | `.md`, `.markdown` |
| **Показати як сторінку** | Відрисовує файл як сторінку, якою він і є, лише для читання | `.html`, `.htm`, `.xhtml` |
| **Редагувати як текст** | Вихідний текст, редагований | усе інше |

Поза сховищем **Редагувати як текст** — це ще й те натискання, яке знімає «лише читання»: режим і дозвіл виявляються одним жестом, а не двома кнопками, про які треба міркувати. Кнопка забарвлюється червоним **щоразу, коли натискання зняло б «лише читання»**, чи то ви зводите правку на місці, чи прийшли прямо з відрисованого вигляду; всередині сховища розблоковувати нічого, тож вона лишається звичайною. **Показати як Markdown** отримує легку заливку кольором акценту — той самий відтінок, яким Obsidian позначає виділений текст, — позначаючи її як шлях назад, а не як заклик до дії.

Оскільки кнопка стежить за *правкою*, а не за сирим режимом, файл, що лежить у текстовому вигляді лише для читання, усе одно пропонує **Редагувати як текст**: це і є те натискання, яке її зводить. Файл, у який ніколи не можна буде писати — обрізаний або нечитаний, — каже натомість **Показати як текст**, бо це все, що натискання може дати.

Типові значення обрано корисні, а не буквальні: `#` у сценарії оболонки — це коментар, а не заголовок, тож відрисовка `.log` як Markdown мовчки б його проковтнула. Будь-яке з типових значень можна перевизначити для окремого файлу, і вибір іде в історію вкладки, тож «назад/вперед» і заново відкритий робочий простір його зберігають — безліч нотаток живе у файлах `.txt`, і безліч файлів `.md` читається легше як вихідний текст.

#### Що дозволено робити HTML-сторінці

Нічого. Сторінка показується у фреймі з **усіма забраними дозволами** — жодних скриптів, жодних форм, жодної навігації, жодного власного походження — і з політикою вмісту, яка взагалі не дозволяє мережі. Це не обережність заради обережності: локальна сторінка, завантажена звичайним шляхом, поділяла б походження цього вікна, а це вікно — Obsidian, тож скрипт у завантаженому HTML-файлі виконувався б усередині вашого застосунку з можливостями вашого застосунку.

Ціна цього — усе, що сторінка *робить*; те, що зберігається, — усе, чим сторінка *є*. Таблиці стилів і зображення, що лежать поруч із файлом, зчитуються й переносяться у фрейм, тож збережена сторінка й далі виглядає собою. Посилання, що вказують за межі власної теки сторінки, і посилання кудись у мережу лишаються точно такими, як написані, і просто не завантажуються — локальний файл не може мовчки повідомити серверу, що ви його відкрили.

Скрипти **прибираються**, а не просто блокуються, тож сторінка, яку ви бачите, і вихідний текст, на який можна перемкнутися, різняться одним заявленим способом, а не тим, що фрейм мовчки відмовився виконувати. Посилання всередині сторінки нічого не роблять. Коли вам потрібне справжнє — скрипти, мережа і все інше — *Відкрити в типовому застосунку* передає це вашому браузеру, який для цього і є правильним інструментом.

**Файли у вашому сховищі редаговані одразу**, без жодного розблокування: *Редагувати як текст* — справжній редактор, і він пише в міру набору.

**Правка запам'ятовується при перемиканні.** Перехід у *Показати як Markdown* її призупиняє — у статичній відрисовці ніде друкувати, а «Живий перегляд» потребує власного редактора Obsidian, який існує лише для файлів усередині сховища, — тож ніщо не стверджує, ніби ви правите, поки ви там. Повернення до *Редагувати як текст* підхоплює з того місця, де ви спинилися.

**Файли поза сховищем відкриваються лише для читання, і *Редагувати як текст* це знімає.** Це натискання і є весь заслін: доки його немає, зовні нічого не пишеться. Далі файл зберігається в міру набору, точно як файл зі сховища; а рядок стану міняє замок на олівець. Розблокування поширюється на цей один файл у цій одній вкладці — перехід до іншого файлу знову блокує, і воно навмисно не зберігається в історії вкладки, щоб заново відкритий робочий простір ніколи не повернувся зі зведеним записом на системному файлі, про відкриття якого ви не пам'ятаєте.

**Обрізані файли в будь-якому разі лишаються лише для читання** — збереження того, що на екрані, викинуло б усе за межею, тож кнопка взагалі не пропонується замість того, щоб пропонуватися й відмовляти. Те саме й із файлом, який не вдалося прочитати: записувати назад нічого, крім порожньої панелі.

Якщо запис не вдався — розділ, змонтований лише для читання, чужий файл, — причина, названа самою системою, показується в сповіщенні.

Дуже великі файли показуються обрізаними, і рядок стану так і каже, а не лишає вам це з'ясовувати — поруч з іншими умовами, а не хвостом за кнопками, бо це такий самий факт про файл, як і решта. Межі виміряно на справжньому відрисовувачі, а не вгадано: розкласти мегабайт тексту в одній панелі наповал убиває процес відрисовки Obsidian, а Markdown коштує в кілька разів дорожче на байт, ніж простий текст, тож у них окремі межі, і один величезний рядок скорочується, навіть коли файл цілком невеликий.

**Рядки стану — це підписи, а пояснення живе у спливаючій підказці.** Кожен рядок каже, що є правдою, стількома словами, скільки треба — *Поза сховищем*, *Немає редактора для цього типу файлів*, *Обрізано — файл завеликий*, — бо кнопки поруч уже кажуть, у якому стані файл. Наведення дає фразу: чому Obsidian не може відкрити його як нотатку, що інакше сталося б із цим типом файлу, чого коштує обрізання.

Це стосується й файлів **усередині** вашого сховища. Будь-яке розширення, для якого в Obsidian немає подання, він передає просто в типовий застосунок стільниці — тож `.txt` чи `.json` у вашому сховищі вивів би вас з Obsidian цілком. Тепер такі відкриваються в тому самому переглядачі, з помаранчевим кільцем, бо «відкрий це в Obsidian» і є те, про що ви просили, — а будучи файлами сховища, вони там редаговані без жодного розблокування. Двійкові файли без переглядача зберігають поведінку Obsidian; показувати нічого.

Перегляд відкривається **в тій вкладці, де ви були**, тож «назад/вперед» повертають до нотатки, звідки ви прийшли; утримуйте <kbd>Ctrl</kbd> для нової вкладки, як і скрізь. Панель шапки далі показує шлях зовнішнього файлу, доки він відкритий, тож звідти можна продовжувати перегляд.

Неголосний рядок над вмістом пропонує виходи:

- **Відкрити в *(сховище)*** — показується, коли файл належить одному з ваших інших сховищ. Передає його власному обробнику URI Obsidian, який відкриває вікно того сховища з нотаткою всередині, як справжню редаговану нотатку. Це вікно лишається точно таким, яким було; ніщо не перемикається під вами.
- **Показати як Markdown** / **Показати як сторінку** / **Редагувати як текст** — два прочитання, які має цей файл; останнє також знімає «лише читання» поза сховищем.
- **Відкрити в типовому застосунку** — передає файл типовому застосунку вашої стільниці, зокрема двійкові формати, яких цей переглядач не показує. Сформульовано точно як власний запис Obsidian для тієї самої дії, бо це та сама дія.

Переглядач також відповідає на **клік правою кнопкою**: усередині текстового редактора — *Вирізати* / *Копіювати* / *Вставити* / *Виділити все*, а будь-де ще — власним меню файлу. Меню з трьох крапок Obsidian у шапці теж несе це меню — поза сховищем воно інакше не пропонувало б нічого, крім *Розділити праворуч* і *Розділити вниз*.

Ніщо поза вашим сховищем не записується, доки ви не натиснете *Редагувати як текст*. Повне розкриття — у розділі [Поза сховищем](README.uk.md#поза-сховищем) README.

## Перетягування файлу на теку в шляху

Кожна тека в рядку — ціль для перетягування, тож **нотатка, перетягнута на неї,
переміщується туди** — найкоротший шлях між нотаткою й будь-якою текою над нею,
адже пункт призначення вже на екрані. Перетягуйте з файлового менеджера, зі
списку, з власної назви нотатки в заголовку чи з будь-якого іншого місця в
Obsidian, що видає файл: це власне перетягування застосунку, тому підказка
під курсором, сам курсор і підсвічування — ті самі, що малює файловий менеджер.

**Назва сховища теж приймає перетягування**, адже це тека на самому верху
рядка — єдиний жест, що переносить нотатку в корінь сховища прямо звідси.

**Цілий вибір можна перетягнути одразу**, і він переміщується як одне ціле:
якщо хоча б один з елементів не вдалося б перенести, перетягування
відхиляється цілком, а не переносить частину, мовчки пропускаючи решту.

Посилання йдуть за нотаткою так само, як і коли її переміщують з файлового
менеджера чи вводом шляху.

Тека, яка **не може прийняти перетягування, не пропонує нічого власного** —
жодного напису *Перемістити в*, жодного підсвічування теки — замість того, щоб
пропонувати щось, що потім провалиться; натомість там стоїть власна відповідь
Obsidian для заголовка — *Відкрити в цій вкладці*. Три випадки:

- тека, в якій файл **вже перебуває**, адже він уже там;
- тека, кинута **сама в себе чи у власного нащадка**, бо тоді їй не було б
  куди повертатися;
- вибір, що містить **теку й щось усередині неї**, адже переміщення теки
  захоплює й нащадка.

Тека, яка вже містить **файл з такою самою назвою**, приймає перетягування й
питає, що робити з тим, що заважає, — тим самим діалогом, що й для введеної
чи обраної зайнятої назви — див. [Назва, яка вже зайнята](#назва-яка-вже-зайнята).
Ніщо тут нічого не перезаписує.

Перетягування приймають лише теки **всередині вашого сховища**. Поки рядок
вказує поза сховище, його сегменти відмовляються, адже винесення нотатки за
межі сховища руйнує кожне посилання на неї — рішення, що заслуговує на
запитання, а не на жест. Свідомий спосіб зробити це — все ще ввести шлях, який
спершу запитає й скаже, скільки нотаток це зачепить.

## Перетягування тексту чи файлу, щоб його записати

Ті самі цілі приймають і **вміст**, і файли, і одне від іншого відрізняється
за тим, що саме ви перетягуєте, а не за тим, куди ви це кидаєте.

**На нотатку, яку рядок уже називає** — власну назву нотатки, або роздільник,
чия тека має нотатку теки — те, що ви кинули, додається в кінець, після
порожнього рядка. Спершу питається підтвердження, адже це записує у файл, що
вже існує, а перетягування — жест, який непевна рука може зробити випадково.
Працює текст з редактора, файл з робочого столу і нотатка, перетягнута з
цього ж сховища; файл читається як текст, а бінарний — відхиляється замість
того, щоб вставитися екраном нісенітниці.

**На місце — назву сховища чи теку** — нічого ще не записується, бо нічого ще
не назване. Поле відкривається там, тримаючи те, що ви кинули, і назва, яку
ви вводите, підтверджує це: нова нотатка *створюється* з цим текстом, а про
наявну запитується точно так само, як вище. <kbd>Esc</kbd> або клік деінде
відпускає все це.

**Рядок дзвенить синім**, поки над ним триває перетягування, що приземлиться
як вміст, і лишається синім, поки поле тримає його — той самий синій, що каже
те саме: далі йдеться про текст, який ви несете. Файл, перетягнутий з вашого
власного сховища на теку, все одно означає *перемістити його туди*, зберігає
власне підсвічування Obsidian і ніколи не дзвенить синім — цей жест був тут
першим, і вміст перед ним відступає.

## Коли шлях довший за панель

Назви **скорочуються, а не стискаються**, у порядку того, що вам найменш
імовірно знадобиться:

1. **Спершу назва сховища**, аж до самого значка. Ви знаєте, в якому ви
   сховищі; значок і далі каже, звідки починається шлях.
2. **Потім розширення файлу**, якщо воно у вас увімкнене — ті самі три
   символи майже в кожному файлі сховища. Воно зникає цілком, а не
   скорочується: половина розширення не каже нічого, чого не каже його
   відсутність.
3. **Потім теки, найдовші першими.** Найдовша назва теки скорочується до
   довжини наступної найдовшої, тоді обидві разом і так далі, кожна
   зупиняючись на своїй межі — тож одна дуже довга тека віддає все, що має
   понад інші, перш ніж коротка назва поруч втрачає хоч одну літеру.
4. **Власна назва файлу — остання**, і вона зберігає близько шести символів.
   Саме для цього й існує заголовок.

Простір звільняється **безперервно**, частками пікселя, а не літерою за раз:
назва, що поступається, обрізається по пікселю й гасне під своїм `…`, тож
панель, яку повільно звужують, плавно звужує рядок, і ніщо після неї не
рухається стрибками. Перш ніж піде хоч одна літера, витрачається повітря
навколо роздільників — це єдиний інтервал рядка, і він не коштує жодної
інформації, — а скорочена назва закінчується там, де починається роздільник,
без смужки порожнього простору між ними.

**Поле бере те, що воно тримає.** Відкриття його для введення шляху не
витісняє теки поруч: воно рівно таке широке, як текст у ньому, і росте, поки
ви друкуєте, тож слід зберігає все, чого поле не потребує. Лише коли не
вистачає місця на обидва, рядок прокручується, і тоді поле — єдина річ, що
ніколи не поступається: це текст, який редагують, а не назва, яку підганяють.

Нічого не обрізається за межі того, що відрізняє назву від сусідніх:
`Projects2025` і `Projects2026` в одній теці скорочуються до `…025` і `…026`,
а не до префіксу, що зробив би їх однаковим словом, тоді як `Reports` поруч
із `Receipts` може скоротитися до `Rep…`. Понад це кожна назва зберігає
**читабельну ширину** — приблизно чотири літери для теки й шість для назви
файлу, виміряні шрифтом, яким рядок насправді намальовано, а не порахованих.
Чотири вузькі літери й чотири широкі — не однакова кількість назви, тож
`lilliliillil` дозволено зберегти більше себе, ніж `WWMMWWMMWWMM`, і те, що
залишається на екрані, однакового розміру в обох випадках. Короткі назви
залишають незайманими цілком — назва, стерта до `A…`, унікальна й усе одно
нечитабельна. **Пробіли в цей рахунок не входять.** Шість символів, щоб
сказати, який це файл, — це шість символів, вартих прочитання, тож пробіли
між ними їдуть безкоштовно, і жоден з них ніколи не лишається впритул до
`…`, де він однаково був би непомітним.

**Назву обрізають там, де сусіди з нею згодні, і посередині, коли вони
не згодні ніде.** Дві теки з назвами `aaaa-common-one` і `aaaa-common-two`
поділяють усе, крім останніх трьох символів, тож обрізання хвоста зберігає
саме ту половину, що щось каже: вони скорочуються до `…one` і `…two`, що
коротше *і* розрізняє їх. Там, де збіг наприкінці — `alpha-draft` поруч із
`beta-draft` — саме кінець і зникає; там, де збіг з обох кінців, лишається
середина. Назва без близьких сусідів втрачає середину, адже назва
відкривається тим, чим вона є, а закривається тим, яка саме вона — для
файлу це розширення: `annual…2026.md`.

Короткий спільний відрізок не рахується. `parallel structures` випадково
закінчується тими самими двома літерами, що й `Schemes` поруч, і це не
причина зберігати обидві назви цілком — трьох символів спереду вже досить,
щоб їх розрізнити.

Ніщо не переноситься на другий рядок. Коли навіть найкоротші чесні назви не
влазять, рядок **прокручується вбік**, зупиняючись у кінці, де знаходиться
файл — на цьому етапі стискати вже нічого, а подальше обрізання радше
приховало б, ніж скоротило. Коліщатко прокручує рядок незалежно від того, де
над рядком перебуває вказівник, і дістатися можна обох кінців: під час
прокрутки рядок вирівнюється за своїм початком, хоч би що казало налаштування
вирівнювання, адже вміст, центрований у рамці, з якої він виріс, виходить за
межі як зліва, так і справа — і до тієї половини прокрутитися взагалі не
можна.

**Наведіть на скорочену назву — і вона повертається повністю**, доки ви на
неї наведені, прокручена до лівого краю, щоб усе повернене було видно на
екрані. **Клацніть по ній — і вона лишається**: поле відкривається, показуючи
теку, по якій ви клацнули, те, що пропонується після неї, і все, що ви
вводите, і продовжує це показувати, коли вказівник відведено. Назви лишаються
на місці, поки ви прокручуєте рядок або друкуєте в ньому — якщо назва
розкривалася б під час жесту, призначеного для читання рядка, це зсунуло б
усе, що йде після неї, з-під вас.

**Початковий сегмент завжди має підказку, і це абсолютний шлях** —
`/home/you/Vaults/Notes`, чи звідки б рядок не починався. Це єдине, чого
ніщо на екрані сказати не може: назва повідомляє, *яке* це сховище, але
ніколи — де воно. Вона з'являється незалежно від того, чи довелося щось
скорочувати.

З вимкненим параметром **Показувати назву сховища** назва не видаляється, а
лише зводиться до нуля — тож наведення на значок повертає її точно так само,
як наведення на назву, яку рядку довелося скоротити.

**Показувати розширення файлів** повертає розширення на назву файлу в рядку.
Вимкнено — за замовчуванням — рядок називає нотатку так, як її називає
Obsidian, без `.md`, яке поділяє майже кожен файл у сховищі; увімкнено —
називає її так, як це робить файлова система, що корисно, коли сховище
містить не лише нотатки. Це також друга річ, якою рядок жертвує, коли
бракує місця, одразу після назви сховища.
Підказка дає решту: не лише назву, а й усе, що рядок показує під нею, у
вигляді `…/назва/тека/нотатка.md`, тож одне наведення відповідає і "що це",
і "що під цим". Значок сховища називає своє сховище так само, коли назва
вимкнена або була стиснута геть.

## Кольори попереджень

| | Коли | Що це означає |
| --- | --- | --- |
| **Червоне** кільце на рядку шляху | Рядок вказує поза ваше сховище | Obsidian не може відкрити те, що там, як нотатку, і нічого там не записується, доки ви не відкриєте замок. |
| **Оранжеве** кільце на рядку шляху | Файл — текстовий тип, для якого в Obsidian немає перегляду | Застереження. Obsidian передав би його типовому застосунку вашої системи; замість цього його показує плагін. |
| **Червоний** текст у відкритому полі | За цим шляхом ще нічого немає | <kbd>Enter</kbd> створить це, а не відкриє. Це радше не попередження, а твердження про те, що зробить наступне натискання клавіші — див. [Введення шляху](#введення-шляху). |
| **Червоний** замок замість перемикача перейменування | Рядок вказує поза ваше сховище, і запис туди все ще заблоковано | Той самий червоний, що й кільце, і з тієї самої причини: він позначає відмову. Натискання дозволяє запис сюди й повертає слот перемикачу — див. [Запис поза сховищем](#запис-поза-сховищем). |

**Обидва кільця незалежні, і обидва можуть діяти одночасно** — зовнішній
`.json` перебуває і поза вашим сховищем, *і* є типом, для якого в Obsidian
немає редактора. У переглядачі вони з'являються як окремі рядки, кожен з
яких констатує лише власний факт. На рядку шляху, коли застосовні обидва,
перемагає червоний, адже два кільця були б лише шумом. Червоний *текст* —
це третя, зовсім окрема річ: він стосується того, що вводиться, а не того,
куди вказує рядок, тож може з'являтися всередині будь-якого з кілець або
жодного.

Оранжевий рівень навмисно вузький. Зареєстровані типи (Markdown, canvas,
зображення, PDF, аудіо, відео) обробляються належним чином і не отримують
нічого. Бінарні файли теж не отримують нічого — ви не перетворите `.zip` на
хаос випадково. Що лишається — це саме небезпека: `.json`, `.css` чи `.log`,
які зробив видимими параметр **Показати всі типи файлів**. Список навмисно
ширший: там усе, що не є нотаткою, оранжеве — див.
[як забарвлюються записи списку](#як-забарвлюються-записи-списку).

## Режим переміщення/перейменування

Кнопка-олівець у крайньому правому куті заголовка — поруч із кнопкою режиму
перегляду, того самого розміру, що й рідні кнопки — перемикає режим
переміщення/перейменування. Поза вашим сховищем на її місці стоїть червоний
замок, доки ви його не натиснете; див. [Запис поза сховищем](#запис-поза-сховищем).
Тоді рядок заголовка обрамляється кольором акценту, точно як перейменування
у файловому менеджері. Ті самі кліки й натискання клавіш тепер підтверджують
переміщення чи перейменування через `fileManager.renameFile` в Obsidian, тож
усі посилання на нотатку йдуть слідом.

Поки триває перейменування:

- Поточна назва файлу закріплена в списку кожної теки, тож перемістити
  нотатку без перейменування — це один клік.
- Назви, вже зайняті в цільовій теці, — **червоні** — тека, що вже містить
  таку назву, і файл з такою назвою — тож конфлікт видно ще до вибору. Їх
  усе одно можна обрати: див. нижче.
- Введення перевіряється наживо за власними правилами перейменування
  Obsidian — ті самі набори символів, ті самі повідомлення, та сама червона
  підказка, яку ви отримуєте при перейменуванні в дереві файлів — тож
  заборонена назва позначається під час введення й не може бути підтверджена.
- Клік поза рядком заголовка або втрата фокусу заголовком завершує режим
  перейменування.

### Назва, яка вже зайнята

Переміщення чи перейменування на назву, що вже існує, **запитує, а не
відмовляє.** Відкривається діалог з двома шляхами, які можна редагувати: куди
йде ваш файл і куди йде файл, що заважає, — червоний, доки він усе ще
зайнятий. Кожен шлях також намальовано так само, як його малює рядок шляху:
частини, що відрізняються, забарвлені, а скорочуються останніми, тож навіть
довгий шлях усе одно показує, що змінюється.

Обидва поля мають список. Другий містить звичні виходи:

- **Поміняти місцями** — він переходить у стару теку вашого файлу, під
  власною назвою.
- **Поміняти імена** — він лишається на місці й бере стару назву вашого
  файлу.
- **Поміняти обидва** — він бере старий шлях вашого файлу.
- `-1`, `-bak` і `-old` поруч із власною назвою.
- Дві назви, які мали файли.

Перший список пропонує те, куди прямував ваш файл, **Лишити як є**, власну
назву в цільовій теці, а також `-1`, `-bak` і `-old` поруч з нею. Вихід, чий
шлях зайнятий, сірий і не може бути обраний. Вибір лише **заповнює поле** —
ви все ще можете його редагувати — і **Застосувати** переміщує обидва, разом
з усіма посиланнями; **Скасувати** не переміщує нічого. Вибір зайнятої назви
зі списку запитує те саме, як і перетягування нотатки на теку, що вже
містить цю назву.

## Одна клавіша для обох перейменувань

Команда перейменування (<kbd>F2</kbd> за замовчуванням, або те, на що ви її перепризначили) **чергує** між перейменуванням inline title в Obsidian і рядком шляху цього плагіна в заголовку. Якщо ви вимкнули inline title в Obsidian, рядок шляху в заголовку стає єдиною ціллю, тож клавіша ніколи не робить нічого даремно.

У рядку шляху вона відкриває **ім'я без розширення** — саме таке редагування зазвичай і є перейменуванням, і те саме робить клік по імені, виділяючи його. Натисніть ще раз — і вона робить те саме, що там зробив би <kbd>Tab</kbd>: на імені це наступний щабель — ім'я з розширенням, шлях від теки вашого сховища, шлях від кореня системи; якщо щось вже введено, вона доповнює його, як це робить <kbd>Tab</kbd>.

**Цикл замикається на заголовку.** П'ять натискань проведуть вас по колу — inline title, ім'я, ім'я з розширенням, шлях від сховища, шлях від кореня системи — а шосте знову дає inline title. Це натискання — єдине, що відрізняється від <kbd>Tab</kbd>, яке натомість повертається на початок шляху — а сьоме йде туди, куди веде коло <kbd>Tab</kbd>: корінь сховища, з усім шляхом у полі та виділеною першою текою. Тож кожен щабель, до якого дістається <kbd>Tab</kbd>, дістається і ця клавіша.

Команда **Фокус на рядку шляху** робить те саме всередині поля — усе, що зробив би <kbd>Tab</kbd> — а там, де <kbd>Tab</kbd> замкнув би коло, вона натомість повертає курсор нотатці. Наступне її натискання — те саме коло: корінь сховища, виділена перша тека.

**У полі, яке вже відкрите**, клавіша перетворює його на перейменування там, де воно є — зберігаючи текст, курсор і виділення — а **Фокус на рядку шляху** знімає з нього перейменування так само. **Будь-що інше**, натиснуте чи клікнуте між натисканнями, починає будь-яке з циклів заново, тож натискання після редагування ніколи не потрапляє на щабель, що лишився з минулого разу.

Поза сховищем клавіша теж працює — там немає inline title, тож перше натискання одразу веде до рядка шляху.

Це працює через обгортку команди `workspace:edit-file-title`, а не перехоплення клавіші, тож перепризначення сполучення й запуск команди з палітри працюють без змін.

## Як забарвлюються записи списку

| Колір | Означає |
| --- | --- |
| **Фіолетовий** | Нотатка (`.md`, `.markdown`) — те, що Obsidian відкриє як нотатку, вибрана з теки зі змішаним вмістом |
| **Помаранчевий** | Не нотатка — усе, що Obsidian не відкриє як таку, від PDF до `.txt`, і разом з ними записи `:page`. Тека зі змішаним вмістом читається заради нотаток у ній, і один колір для всього іншого показує це швидше, ніж застереження над кількома з них; див. [кольори попереджень](#кольори-попереджень) |
| **Приглушений** | Поза вашим сховищем, тож власна обробка сховища не застосовується |
| **Синій**, жирний | Там, де ви вже перебуваєте: власна нотатка цього рядка й тека, на якій стоїть рядок шляху. У режимі перейменування/переміщення на місці нотатки стоїть запис *залишити цю назву* — в обох випадках це та сама нотатка |
| **Червоний** | Лише в режимі перейменування/переміщення: назва вже зайнята. Все ще можна вибрати — вибір запитає, що робити з файлом, що стоїть на заваді; див. [Назва, яка вже зайнята](#назва-яка-вже-зайнята) |

**Теки — жирним**, тож власній нотатці теки не потрібен окремий колір, щоб виділятися серед вмісту теки: вона фіолетова, як і будь-яка інша нотатка. **Лінія вздовж краю рядка** позначає назви, що починаються з того, що ви ввели — синя там, де вони збігаються далі, зелена на гілці, яку пропонує варіант; див. [Введення шляху](#введення-шляху).

Поле набуває тих самих кольорів для того, що воно називає — див. [Введення шляху](#введення-шляху).

## Правила видимості

- Файли з непідтримуваними розширеннями з'являються у списках, лише якщо в Obsidian увімкнено налаштування **Detect all file extensions** — **всередині сховища**. Поза ним це налаштування не діє: воно керує тим, що індексує сховище, а поза сховищем немає нічого проіндексованого, тож `.txt` поруч із вашими нотатками показується в будь-якому разі.
- Список показує до 1000 записів — у десять разів більше за власне обмеження Obsidian. Якщо в теці більше, останній рядок повідомляє, скільки залишилося поза списком; продовжуйте вводити текст, щоб звузити список.
- Файли й теки, чиї назви починаються з крапки, з'являються, лише якщо увімкнено налаштування цього плагіна **Показувати приховані файли**.
- **Захист від перезапису працює однаково незалежно від видимості** — прихований файл усе одно не дасть вам перезаписати себе.

Шлях **у лапках** автоматично звільняється від них. Функція Windows *Copy as path* видає `"C:\Users\you\note.md"`, разом із лапками, і оболонка робить те саме для будь-якого шляху з пробілом; вставте такий шлях чи введіть його — працює в обох випадках. ## Заміна значків

Lure малює три значки: значок кореня сховища (коли **Показувати назву сховища** вимкнено), перемикач перейменування/переміщення й замок, що стоїть на його місці, поки запис поза сховищем заблокований. Усі можна замінити з теми чи CSS-фрагмента — задайте гліф заміни й приховайте вбудований одним правилом:

```css
.lure-vault-icon {
	--lure-icon-glyph: "🏠";
	--lure-icon-svg: none;
}

.lure-rename-btn {
	--lure-icon-glyph: "✎";
	--lure-icon-svg: none;
}

/* Показується лише закритим: відкриття передає слот перемикачу перейменування. */
.lure-unlock-btn {
	--lure-icon-glyph: "🔒";
	--lure-icon-svg: none;
}
```

`--lure-icon-glyph` приймає все, що припустиме у CSS-властивості `content`, тож `url(...)` годиться для картинки не гірше, ніж текстовий гліф чи емодзі. Лишіть `--lure-icon-svg` у спокої, щоб зберегти значок Lucide і намалювати свій гліф поруч.
